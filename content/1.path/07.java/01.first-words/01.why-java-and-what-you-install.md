The gap closes here. One language, taken all the way, and this lesson defends
which one before installing anything, because "learn Java" with no argument
behind it is how people end up learning four languages badly.

## Why this matters in a job

Because you will be asked why you chose it, and "it was in the syllabus" is a
weak answer. It also matters because the honest case for Java is not that it is
the best language. It is that it is the best *first* language for this market and
for this purpose.

## The argument

::pros-cons
---
title: Java as a first language
pros:
  - The largest number of entry-level roles in the Indian market, by a wide margin
  - Verbose enough that the machine model stays visible — types, memory, objects
  - Strictly typed and compiled, so a large class of mistakes is caught before the program runs
  - The standard library is enormous and the documentation is genuinely good
  - Almost every enterprise system, and Android, and most of banking
cons:
  - Slower to a first running program than Python, and the ceremony is real
  - The build tooling is genuinely unpleasant until it is familiar
  - Not the language anybody would pick for a quick script
---
::

::compare{caption="The same task, and the reason verbosity is a feature while you are learning."}
  :::compare-side{label="Python" verdict="neutral"}
  ```python
  score = 78
  ```
  Shorter, and it tells you nothing about what a variable is, how much space it
  takes, or what happens when you put text in it later.
  :::
  :::compare-side{label="Java" verdict="right"}
  ```java
  int score = 78;
  ```
  Four extra characters, and they say: this holds a whole number, it is 32 bits,
  and the compiler will refuse to put text in it. That visibility is exactly what
  you need for a year and can gladly give up afterwards.
  :::
::

::note
If you already know Python or C++ well, use it. The course is written in Java
because one language has to be chosen, and every concept here transfers directly.
What this course will not endorse is learning three at once, which is the most
common way a year is wasted.
::

## JDK, JRE, JVM

Three acronyms that are asked about in interviews and confuse everybody.

The sequence, which is the actual answer to "how does Java work":

::flow{numbered direction="vertical" caption="Compiled once, run anywhere. That is not marketing; it is this diagram."}
  :::flow-step{label="You write .java" icon="i-lucide-file-code"}
  Text. Readable by humans, meaningless to the machine.
  :::
  :::flow-step{label="javac compiles it to .class" icon="i-lucide-cog"}
  Not machine code. **Bytecode**: instructions for a machine that does not
  physically exist.
  :::
  :::flow-step{label="The JVM executes the bytecode" icon="i-lucide-play" highlight}
  There is a different JVM for Windows, macOS, Linux and your phone, and each
  turns the same bytecode into that machine's instructions. The `.class` file is
  identical everywhere.
  :::
  :::flow-step{label="The JIT compiles the hot parts" icon="i-lucide-zap"}
  Code that runs often is compiled to real machine code while the program runs,
  which is why a long-running Java service reaches roughly C-like speed after
  warming up, and why your first timing measurement is always misleading.
  :::
::

## Install it

::tabs
  :::tabs-item{label="macOS" icon="i-lucide-command"}
  ```bash [Terminal]
  brew install openjdk@21
  # Homebrew does not link it by default; this makes `java` findable.
  sudo ln -sfn $(brew --prefix)/opt/openjdk@21/libexec/openjdk.jdk \
               /Library/Java/JavaVirtualMachines/openjdk-21.jdk
  ```
  :::

  :::tabs-item{label="Linux" icon="i-simple-icons-linux"}
  ```bash [Terminal]
  sudo apt update && sudo apt install openjdk-21-jdk
  ```
  :::

  :::tabs-item{label="Windows" icon="i-lucide-monitor"}
  Inside WSL, use the Linux instructions. That is the recommendation from the
  terminal track and it still holds: every instruction you will be given for the
  rest of your career assumes a Unix shell.
  :::
::

```bash [Terminal]
java -version
javac -version
```

```text [Output]
openjdk version "21.0.5" 2026-10-15
javac 21.0.5
```

::warning{icon="i-lucide-alert-triangle"}
If `java` works and `javac` does not, you have a JRE and not a JDK. It is the
most common installation problem there is, and the error it produces —
`javac: command not found` — does not say so. Install the JDK.
::

## Your first program, compiled by hand

Do it this way once. Every IDE hides these two steps, and people who have never
seen them cannot debug a build.

```java [Admissions.java]
public class Admissions {
  public static void main(String[] args) {
    System.out.println("University admissions, 2026 intake");
  }
}
```

```bash [Terminal]
javac Admissions.java     # produces Admissions.class
ls
java Admissions           # note: no .class, no .java. The class NAME.
```

```text [Output]
Admissions.class  Admissions.java
University admissions, 2026 intake
```

::code-trace{caption="Four things in that file, and every one of them is asked about."}
```java [Admissions.java]
public class Admissions {
  public static void main(String[] args) {
    System.out.println("University admissions, 2026 intake");
  }
}
```

  :::code-trace-step{lines="1" caption="`public class Admissions` — and the file MUST be called Admissions.java. A public class and its file share a name; this is enforced by the compiler and catches everybody once."}
  :::
  :::code-trace-step{lines="2" caption="`static` means this method belongs to the class rather than to an object. It has to be, because the JVM calls it before any object exists."}
  :::
  :::code-trace-step{lines="2" caption="`void` returns nothing. `String[] args` receives anything typed after the class name on the command line."}
  :::
  :::code-trace-step{lines="3" caption="`System.out` is a PrintStream object; `println` is a method on it. Even printing is an object calling a method, which is a hint about the rest of this language."}
  :::
::

## Meet your first four errors deliberately

Every one of these will happen to you. Cause them now, on purpose, while nothing
is at stake.

```bash [Terminal]
# 1. Rename the file and watch the compiler refuse.
mv Admissions.java Wrong.java && javac Wrong.java
```

```text [Output]
Wrong.java:1: error: class Admissions is public, should be declared
in a file named Admissions.java
```

```bash [Terminal]
# 2. Run the file name rather than the class name.
javac Admissions.java && java Admissions.java
```

```text [Output]
error: class found on application class path: Admissions
```

```bash [Terminal]
# 3. Delete a semicolon, then compile.
# 4. Rename main to start, compile successfully, then run.
```

```text [Output]
Error: Main method not found in class Admissions, please define the main
method as: public static void main(String[] args)
```

::tip
Number four is the one worth dwelling on. It **compiled fine**. Compiling and
running are separate steps with separate failures, and knowing which step failed
is half of debugging a build. `javac` errors are about your code; `java` errors
are about how you are starting it.
::

## What you can do now

You can install a JDK, compile and run a program from a terminal, and explain
what bytecode is and why it exists. That last one is a standard interview
question and you have now watched it happen.

## Your turn

1. Make the programme name come from the command line rather than being fixed.
2. Print the number of arguments given.
3. Run it with no arguments and read the exception carefully.

::accordion
  :::accordion-item{label="One answer, and what the exception teaches" icon="i-lucide-check"}
  ```java [Admissions.java]
  public class Admissions {
    public static void main(String[] args) {
      System.out.println("Arguments given: " + args.length);
      System.out.println("Programme: " + args[0]);
    }
  }
  ```

  ```bash
  java Admissions "B.Tech CSE"
  ```

  With no arguments you get
  `ArrayIndexOutOfBoundsException: Index 0 out of bounds for length 0`.

  Read it as the English sentence it is: you asked for position 0 of something
  that has nothing in it. Java arrays start at 0, so position 0 of an empty array
  does not exist. The fix is to check `args.length` before reading, and
  **checking before reading is the shape of most defensive code you will ever
  write.**
  :::
::

## Check yourself

1. What is the difference between the JDK, the JRE and the JVM?
2. **An interviewer asks: "what does 'write once, run anywhere' actually mean?"**

## The interview question this answers

**"Explain JDK, JRE and JVM"** and **"is Java compiled or interpreted?"**

The second is the better question and the answer is *both*, which is what makes
it a good filter. `javac` compiles source to bytecode ahead of time; the JVM
interprets that bytecode; and the JIT compiler then compiles the frequently-run
parts to native machine code while the program runs. Saying all three, in that
order, answers it properly. Then the consequence: the same `.class` file runs on
any machine with a JVM, which is what portability actually means.
