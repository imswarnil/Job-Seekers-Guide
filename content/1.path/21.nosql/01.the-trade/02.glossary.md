| Term | In one line |
| --- | --- |
| **Document store** | Stores JSON-shaped documents. MongoDB, DynamoDB. One read gives you a whole nested thing. |
| **Key-value store** | A key, a value, in memory. Redis. Microsecond reads. **You will use one.** |
| **Search engine** | Full-text search with ranking, stemming and fuzziness. `LIKE '%rao%'` is not search. |
| **Graph database** | Relationships are the data. Three degrees of separation is one traversal rather than three joins. |
| **Collection / document** | A table and a row, roughly. |
| **Embedding** | Nesting related data inside a document. Fast to read, and the fee is now copied 40,000 times. |
| **Referencing** | Storing an id instead. A join you perform yourself, in application code. |
| **"Schema-less"** | ⚠️ The schema still exists. It moved into your application, where it is a convention the next application will not know about. |
| **Sharding** | Splitting data across machines by a key. The genuine scaling argument, and far rarer than it is invoked. |
| **Eventual consistency** | A write may not be visible everywhere immediately. Fine for a like count, not for a seat allotment. |
| **CAP theorem** | ⚠️ Under a network partition you choose availability or consistency. Quoted constantly, and it only says anything *during* a partition. |
| **BASE** | The contrast drawn with ACID: basically available, soft state, eventually consistent. A slogan more than a specification. |
| **TTL** | A key that expires. What makes Redis right for sessions and rate limits. |
| **JSONB** | A Postgres column holding JSON, indexable and queryable. Usually the correct answer to "we need flexibility". |

## The three sentences to keep

::pull-quote
The trade is joins, cross-document transactions and enforced constraints, in
exchange for one read and easier sharding. "Schema-less" means unenforced. And
for most real cases, relational plus a JSONB column is the better answer.
::
