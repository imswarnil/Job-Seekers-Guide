Every word this track introduced, one line each. Read it on the morning of an
interview. Any line you cannot say in your own words, with a university example,
is the one to revise.

## The idea

| Word | Means |
| --- | --- |
| **OOP** | Organising a program around objects that hold their own data and the methods allowed to change it |
| **Procedural programming** | Data and functions kept separate; functions act on data from outside (C) |
| **Class** | A blueprint that declares fields and methods; written once |
| **Object / instance** | One thing built from a class at runtime with `new`, with its own copy of the fields |
| **Instantiation** | Creating an object from a class |
| **Field / state** | A variable that belongs to an object (or, if `static`, to the class) |
| **Method / behaviour** | A function that belongs to a class |
| **Reference** | A variable holding an object's address, not the object |
| **Heap** | The memory area where objects live |
| **Constructor** | The block that runs inside `new`, same name as the class, no return type |
| **Default constructor** | The no-argument constructor the compiler adds only if you wrote none |
| **Constructor chaining** | One constructor calling another with `this(...)` or `super(...)` |
| **Copy constructor** | A constructor that takes another object of the same class and copies it |

## The four pillars

| Word | Means |
| --- | --- |
| **Encapsulation** | Bundling data with the methods that guard it, and restricting direct access |
| **Data hiding** | Making fields `private`; the mechanism encapsulation uses |
| **Invariant** | A rule that must always hold for an object (marks between 0 and 100) |
| **Abstraction** | Exposing what something does and hiding how |
| **Inheritance** | A child class acquiring a parent's fields and methods with `extends`; an is-a relationship |
| **Single / multilevel / hierarchical** | One parent one child / a chain / many children one parent |
| **Multiple inheritance** | One class with two parents; Java allows it only through interfaces |
| **Diamond problem** | The ambiguity when two parents provide the same method to one child |
| **Polymorphism** | One call behaving differently depending on the object or the arguments |
| **Compile-time polymorphism** | Overloading, resolved by the compiler; static or early binding |
| **Runtime polymorphism** | Overriding, resolved by the JVM from the real object; dynamic or late binding |
| **Dynamic method dispatch** | The JVM choosing the overriding method from the actual object at runtime |
| **Upcasting / downcasting** | Child object as parent type (implicit, safe) / parent reference cast to child (explicit, can fail) |
| **Overloading** | Same method name, different parameter list |
| **Overriding** | A subclass replacing an inherited method with the same signature |
| **Signature** | A method's name plus its parameter types; not the return type |
| **Covariant return type** | An overriding method returning a subtype of the parent's return type |
| **`@Override`** | An annotation that makes the compiler check you really are overriding |

## Relationships

| Word | Means |
| --- | --- |
| **Abstract class** | A class that cannot be instantiated, may have state, constructors and abstract methods |
| **Abstract method** | A method declared with no body, which a concrete child must implement |
| **Interface** | A contract of methods, with constants only; a class can implement many |
| **Default method** | An interface method with a body (Java 8+) |
| **Functional interface** | An interface with exactly one abstract method; what a lambda implements |
| **Marker interface** | An interface with no methods, used as a tag (`Serializable`) |
| **Association** | Two objects that know or use each other, no ownership |
| **Aggregation** | Has-a where the part can outlive the whole (department and professors) |
| **Composition** | Has-a where the part dies with the whole (student and ID card) |
| **Composition over inheritance** | Prefer holding and delegating to extending |
| **Fragile base class** | A child broken by a change inside its parent |

## The keywords

| Word | Means |
| --- | --- |
| **Access modifier** | `private`, default, `protected`, `public`: where something can be used from |
| **Package-private (default)** | No keyword: visible only inside the same package |
| **`static`** | Belongs to the class, one shared copy, usable without an object |
| **Static block** | Code that runs once, when the class loads |
| **`final`** | Assigned once (variable), not overridable (method), not extendable (class) |
| **Immutable** | An object whose state cannot change after construction (`String`, `List.of`) |
| **`this`** | A reference to the current object |
| **`super`** | A reference to the parent's part of the current object |
| **`equals`** | Whether two objects mean the same thing, as the class defines |
| **`hashCode`** | An `int` that picks a bucket in hash-based collections |
| **equals/hashCode contract** | Equal objects must have equal hash codes |
| **Record** | A compact class that generates constructor, accessors, `equals`, `hashCode` and `toString` |

## Design

| Word | Means |
| --- | --- |
| **SOLID** | Single responsibility, open/closed, Liskov substitution, interface segregation, dependency inversion |
| **Single responsibility** | One reason to change per class |
| **Open/closed** | Extend by adding code, not by editing working code |
| **Liskov substitution** | A child must work anywhere its parent does, without surprises |
| **Interface segregation** | Several small interfaces rather than one large one |
| **Dependency inversion** | Depend on abstractions, not on concrete classes |
| **Dependency injection** | Handing a class its dependencies, usually through the constructor |
| **Design pattern** | A named, reusable solution to a recurring design problem |
| **Gang of Four (GoF)** | The 1994 book that catalogued 23 patterns in three groups |
| **Singleton** | Exactly one instance, with a global access point |
| **Factory** | A method that decides which concrete class to create |
| **Builder** | Step-by-step, named construction of an object with many optional fields |
| **Observer** | A subject notifies every registered listener when it changes |
| **Strategy** | Interchangeable algorithms behind one interface, chosen at runtime |
| **Coupling** | How much one class depends on others; aim low |
| **Cohesion** | How related the responsibilities inside one class are; aim high |

## The pairs people confuse

::feature-list{columns="2"}
  :::feature{icon="i-lucide-git-compare" title="Encapsulation and abstraction"}
  Encapsulation hides **data** (who may change it). Abstraction hides
  **complexity** (what the caller needs to know).
  :::
  :::feature{icon="i-lucide-git-compare" title="Overloading and overriding"}
  Overloading: same name, different parameters, compile time. Overriding: same
  signature in a child, runtime.
  :::
  :::feature{icon="i-lucide-git-compare" title="Abstract class and interface"}
  Abstract class: shared state and code, extend one. Interface: a capability,
  implement many.
  :::
  :::feature{icon="i-lucide-git-compare" title="Aggregation and composition"}
  Both has-a. Aggregation: the part survives the whole. Composition: it does not.
  :::
  :::feature{icon="i-lucide-git-compare" title="== and equals"}
  `==`: same object. `equals`: same meaning.
  :::
  :::feature{icon="i-lucide-git-compare" title="final, finally, finalize"}
  A restriction keyword; a block that always runs; a deprecated GC hook.
  :::
::
