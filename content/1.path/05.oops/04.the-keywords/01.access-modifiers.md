Four levels: `private`, **default** (no keyword at all), `protected` and
`public`. The one with no keyword is called **package-private**, and it is the
one freshers forget exists.

## Why this matters in a job

Access modifiers are how a team says "this part is safe to use, and this part may
change tomorrow". When you make something `public`, other teams start depending
on it and you can never change it freely again. Getting this wrong is how a
"small refactor" breaks three other services.

In interviews, you will be asked to draw the table below. Written tests ask it
as a multiple-choice question with a `protected` trap.

## The idea: rooms in a college

- **private**: your own locker. Only you.
- **default**: the department staff room. Anyone in the same department (package).
- **protected**: the department staff room, plus family: subclasses in other
  departments can come in, but only for their own things.
- **public**: the college notice board. Everyone.

An **access modifier** is a keyword that sets where a class, field, method or
constructor can be used from. A **package** is a folder-level group of related
classes, declared at the top of a file with `package`.

| Modifier | Same class | Same package | Subclass, other package | Anywhere |
| --- | :---: | :---: | :---: | :---: |
| `private` | Yes | No | No | No |
| *(default)* | Yes | Yes | No | No |
| `protected` | Yes | Yes | Yes, through inheritance | No |
| `public` | Yes | Yes | Yes | Yes |

Each row adds one column to the one above it. Learn it as "each level opens one
more door".

## How it works

Two packages, one parent and one child.

```java [edu/exam/Result.java]
package edu.exam;

public class Result {
    private   int internalMarks = 18;   // only Result
              int externalMarks = 54;   // default: only edu.exam
    protected int graceMarks    = 3;    // edu.exam, plus subclasses anywhere
    public    String subject    = "Operating Systems";

    public int total() {
        return internalMarks + externalMarks + graceMarks;
    }
}
```

```java [edu/hostel/HostelResult.java]
package edu.hostel;

import edu.exam.Result;

public class HostelResult extends Result {
    public String show() {
        // internalMarks  -> error: internalMarks has private access in Result
        // externalMarks  -> error: externalMarks is not public in Result; cannot be accessed from outside package
        return subject + ": total " + total() + ", grace " + graceMarks;   // public and protected: fine
    }

    public static void main(String[] args) {
        System.out.println(new HostelResult().show());
    }
}
```

```text [Output]
Operating Systems: total 75, grace 3
```

## The protected trap

`protected` does not mean "any subclass can read it on any object". Outside the
package, a subclass can use it **only through its own inheritance**, meaning on
`this` or on objects of its own type.

```java [edu/hostel/Trap.java]
package edu.hostel;

import edu.exam.Result;

public class Trap extends Result {
    void check(Result other, Trap mine) {
        System.out.println(this.graceMarks);   // fine: inherited
        System.out.println(mine.graceMarks);   // fine: a Trap
        // System.out.println(other.graceMarks);
        //   error: graceMarks has protected access in Result
    }
}
```

That commented line is the trick question. Most people guess it compiles.

## Real use case

The rule of thumb every team I have worked in follows:

::steps
### Start private
Every field `private`. Every helper method `private`.

### Widen only on purpose
Make a method `public` when another class genuinely needs it, and treat that as a
promise you will keep.

### Use default for tests and package helpers
A package-private method can be called by a test in the same package without
becoming part of the public API.

### Use protected for designed extension points
Only when you actually expect subclasses to override it, as in a framework's
`protected void onSave()` hook.
::

For **top-level classes** (not nested), only `public` and default are allowed. A
file can have at most one `public` top-level class, and it must match the
filename.

## What confuses people here

- **Default is not `public`.** Leaving the keyword out restricts to the package.
- **Interface methods are `public` by default**, the opposite of classes. That is
  why an implementing method must be declared `public`, or you get
  `attempting to assign weaker access privileges; was public`.
- **Overriding cannot narrow access.** A `public` method cannot become
  `protected` in a child (the overriding lesson's table).

## Interview questions

::accordion
  :::accordion-item{label="What are the access modifiers in Java?" icon="i-lucide-message-circle"}
  `private` (class only), default or package-private (same package), `protected`
  (same package plus subclasses), `public` (everywhere). Draw the table: each
  level opens one more column.
  :::
  :::accordion-item{label="Difference between default and protected?" icon="i-lucide-message-circle"}
  Both allow the same package. `protected` additionally allows subclasses in
  other packages, through inheritance. Default does not.
  :::
  :::accordion-item{label="Can a top-level class be private or protected?" icon="i-lucide-message-circle"}
  No. Only `public` or default. A nested class can be any of the four.
  :::
  :::accordion-item{label="Can a subclass in another package access a protected member through a parent reference?" icon="i-lucide-message-circle"}
  No. Only through `this` or references of its own type. `other.graceMarks` where
  `other` is a `Result` fails with `graceMarks has protected access in Result`.
  :::
  :::accordion-item{label="Why make fields private and not public?" icon="i-lucide-message-circle"}
  Encapsulation: every change goes through a method that can check it, and you
  can change the internal representation later without breaking anyone.
  :::
::
