`this` is a reference to **the current object**, the one the method was called
on. `super` is a way to reach **the parent's part** of that same object. Neither
exists in a static method, because there is no current object there.

## Why this matters in a job

You will type `this.` hundreds of times a week in constructors and setters, and
`super(...)` every time you write a subclass or a custom exception. Reading them
correctly is what lets you follow an inheritance chain in someone else's code
without getting lost.

## The idea

When Anita fills in a form that says "Your name", the word "your" means Anita.
When Rahul fills in the same form, "your" means Rahul. `this` is that word: the
same code, meaning whichever object is running it.

`super` is "the version my parent had". A hosteller asked for their charges can
say "the student charges, plus the mess".

## How it works

The four uses of `this`:

```java [ThisUses.java]
public class ThisUses {
    private final String name;
    private final int year;

    ThisUses(String name, int year) {
        this.name = name;                  // 1. field vs parameter with the same name
        this.year = year;
    }

    ThisUses(String name) {
        this(name, 1);                     // 2. call another constructor of this class
    }

    ThisUses printed() {
        System.out.println(name + ", year " + year);
        return this;                       // 3. return the current object (method chaining)
    }

    void register(Registry r) {
        r.add(this);                       // 4. pass the current object as an argument
    }

    static class Registry {
        int count;
        void add(ThisUses s) { count++; }
    }

    public static void main(String[] args) {
        Registry registry = new Registry();
        ThisUses anita = new ThisUses("Anita Rao", 2).printed();
        new ThisUses("Farhan Ali").printed().register(registry);
        anita.register(registry);
        System.out.println("Registered: " + registry.count);
    }
}
```

```text [Output]
Anita Rao, year 2
Farhan Ali, year 1
Registered: 2
```

Without `this.` in use 1, `name = name;` assigns the parameter to itself. It
compiles, the field stays `null`, and nothing warns you. That is the most common
constructor bug in a fresher's first week.

The uses of `super`:

```java [SuperUses.java]
public class SuperUses {
    static class Student {
        protected String status = "enrolled";
        protected final String name;

        Student(String name) { this.name = name; }

        int monthlyCharges() { return 900; }             // bus
    }

    static class Hosteller extends Student {
        protected String status = "in hostel";           // hides the parent's field

        Hosteller(String name) {
            super(name);                                  // 1. call the parent constructor
        }

        @Override
        int monthlyCharges() {
            return super.monthlyCharges() + 6500;         // 2. call the parent's version of a method
        }

        String statuses() {
            return status + " / " + super.status;         // 3. reach a hidden parent field
        }
    }

    public static void main(String[] args) {
        Hosteller h = new Hosteller("Anita Rao");
        System.out.println(h.name + ": " + h.monthlyCharges() + ", " + h.statuses());
    }
}
```

```text [Output]
Anita Rao: 7400, in hostel / enrolled
```

`super.monthlyCharges()` is the useful one: extend the parent's behaviour instead
of copying it.

## Real use case: first line or nothing

::compare{caption="this() and super() must be the first statement in a constructor."}
  :::compare-side{label="Does not compile" verdict="wrong"}
  ```java [Bad.java]
  Hosteller(String name) {
      System.out.println("Creating");
      super(name);
  }
  ```
  `error: call to super must be first statement in constructor`. The parent's
  part of the object must exist before the child's code touches anything.
  :::
  :::compare-side{label="Compiles" verdict="right"}
  ```java [Good.java]
  Hosteller(String name) {
      super(name);
      System.out.println("Creating " + name);
  }
  ```
  Parent first, then the child. The same order as construction itself.
  :::
::

It follows that one constructor cannot call **both** `this(...)` and `super(...)`.
If it calls `this(...)`, the other constructor it calls will eventually call
`super(...)`.

::note
Java 25 finalised "flexible constructor bodies", which allow statements before
`super(...)` as long as they do not touch `this` (validating an argument, for
example). Most codebases you will join run on Java 17 or 21, and written tests
still expect the classic rule. Answer with the classic rule, and mention Java 25
only if they ask about recent versions.
::

## What confuses people here

- **If you write no `super(...)`, the compiler inserts `super()`**, with no
  arguments. If the parent has no no-argument constructor, the child fails to
  compile with `constructor Student in class Student cannot be applied to given types`.
- **`this` in a static method** does not compile: there is no current object.
- **`super.super.method()`** is not allowed. You can only reach one level up.

## Interview questions

::accordion
  :::accordion-item{label="What is the this keyword? Where is it used?" icon="i-lucide-message-circle"}
  A reference to the current object. Used to separate fields from same-named
  parameters, to call another constructor (`this(...)`), to return the current
  object for chaining, and to pass the current object to another method.
  :::
  :::accordion-item{label="What is the super keyword?" icon="i-lucide-message-circle"}
  A reference to the parent's part of the current object. Used to call the parent
  constructor (`super(name)`), the parent's version of an overridden method
  (`super.monthlyCharges()`), and a parent field hidden by the child.
  :::
  :::accordion-item{label="Can this() and super() both be used in one constructor?" icon="i-lucide-message-circle"}
  No. Each must be the first statement, so only one can be. A constructor that
  calls `this(...)` delegates, and the target constructor calls `super(...)`.
  :::
  :::accordion-item{label="What happens if a parent has only a parameterised constructor and the child does not call super?" icon="i-lucide-message-circle"}
  Compile error. The compiler inserts `super()`, which does not exist. The child
  must call `super(someArgs)` explicitly.
  :::
::
