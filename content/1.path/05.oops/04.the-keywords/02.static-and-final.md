On the class itself. A field marked `static` exists **once**, shared by every
object, and it exists even before the first object is created. The keyword that
often travels with it, `final`, answers a different question: not "whose is it"
but "can it change".

## Why this matters in a job

`static` is where a lot of real bugs hide. A static counter shared by every
request in a web server, updated by two threads at once, is a classic. `final`
is the opposite: it is one of the cheapest ways to make code safer, and reviewers
at every company I have worked at ask "can this be final?".

In interviews: "why is `main` static?", "can a static method use `this`?", "what
is a static block?", "final against finally against finalize". All quick, all
common.

## The idea

The admission office has a board: "Seats filled: 312 of 600". There is one board
for the whole university, not one per student. When a student is admitted, the
one board changes. That board is `static`.

A **static** member belongs to the **class**, not to any object. There is one
copy, it is loaded when the class is first used, and you access it through the
class name: `Admission.seatsFilled`.

**final** means "assigned once". A final variable cannot be reassigned, a final
method cannot be overridden, and a final class cannot be extended.

## How it works: static

```java [Admission.java]
public class Admission {
    static final int TOTAL_SEATS = 600;     // a constant: static AND final
    static int seatsFilled;                  // one copy, shared
    static String university;

    final int roll;                          // one copy per object, set once
    final String name;

    static {                                 // static block: runs once, when the class loads
        university = "LNCT Bhopal";
        System.out.println("Class loaded for " + university);
    }

    Admission(String name) {
        seatsFilled++;
        this.roll = 2100 + seatsFilled;
        this.name = name;
    }

    static int seatsLeft() {                 // static method: no object needed
        // return name;                      // error: non-static variable name cannot be referenced from a static context
        return TOTAL_SEATS - seatsFilled;
    }

    public static void main(String[] args) {
        System.out.println("Before anyone: " + seatsLeft());
        Admission a = new Admission("Anita Rao");
        Admission b = new Admission("Rahul Menon");
        System.out.println(a.name + " " + a.roll + ", " + b.name + " " + b.roll);
        System.out.println("Left: " + Admission.seatsLeft());
    }
}
```

```text [Output]
Class loaded for LNCT Bhopal
Before anyone: 600
Anita Rao 2101, Rahul Menon 2102
Left: 598
```

The static block ran first, before `main`, because the JVM loads the class before
it can call anything on it.

  :::feature{icon="i-lucide-variable" title="Static variable"}
  One copy per class. Counters, constants, caches.
  :::
  :::feature{icon="i-lucide-function-square" title="Static method"}
  Called without an object. Cannot use `this`, `super`, or instance fields

  :::feature{icon="i-lucide-play" title="Static block"}

  than one line.
  :::
  :::feature{icon="i-lucide-box" title="Static nested class"}
  A class inside a class that does not need an instance of the outer one. Every
  example in this track uses them.

## How it works: final

```java [Finals.java]
import java.util.ArrayList;
import java.util.List;

public class Finals {
    static class Subject {
        final String code;
        Subject(String code) { this.code = code; }

        final int credits() { return 4; }         // cannot be overridden
    }

    static final class Grade { }                  // cannot be extended, like String

    public static void main(String[] args) {
        final int passMark = 40;
        // passMark = 35;                         // error: cannot assign a value to final variable passMark

        final List<String> toppers = new ArrayList<>();
        toppers.add("Rahul");                     // allowed: the LIST changed, not the reference
        toppers.add("Anita");
        // toppers = new ArrayList<>();           // error: cannot assign a value to final variable toppers

        System.out.println(passMark + " " + toppers);
    }
}
```

```text [Output]
40 [Rahul, Anita]
```

::warning{icon="i-lucide-alert-triangle"}
`final` on a reference freezes the **reference**, not the **object**. A
`final List` can still be added to. If you need the contents fixed, use
`List.of(...)` or `List.copyOf(...)`, which are **immutable**: any change throws
`UnsupportedOperationException`.
::

## Real use case

The pattern you will write most: constants and utility methods.

```java [Rules.java]
public final class Rules {
    public static final int MIN_ATTENDANCE_PCT = 75;
    public static final int MAX_CREDITS_PER_SEMESTER = 26;

    private Rules() { }                             // no objects of a rules holder

    public static boolean canSitExam(int attendancePct) {
        return attendancePct >= MIN_ATTENDANCE_PCT;
    }

    public static void main(String[] args) {
        System.out.println(Rules.canSitExam(72) + " " + Rules.canSitExam(81));
    }
}
```

```text [Output]
false true
```

Constants are `UPPER_SNAKE_CASE` by convention. The class is `final` and its
constructor `private`, because nobody should extend or instantiate it.

## What confuses people here

- **"Why is `main` static?"** So the JVM can call it without creating an object
  first. There is no object yet when a program starts.
- **"Can a static method be overridden?"** No, it is hidden (the polymorphism
  lesson). Can it be overloaded? Yes.
- **`final`, `finally`, `finalize` are unrelated.** `final` is the keyword here.
  `finally` is the block after `try` that always runs. `finalize()` was a method
  the garbage collector could call before reclaiming an object; it is deprecated
  since Java 9 and you should never rely on it.
- **A static mutable field is shared by every thread.** Fine in a console
  program; a real bug in a web server. That is a topic in the operating systems
  track.

## Interview questions

::accordion
  :::accordion-item{label="What is the static keyword? Where can it be used?" icon="i-lucide-message-circle"}
  It makes a member belong to the class rather than to objects: one shared copy,
  usable without an object. Used on variables, methods, blocks and nested
  classes. Show `seatsFilled` counting across every `Admission`.
  :::
  :::accordion-item{label="Can a static method access instance variables? Can it use this?" icon="i-lucide-message-circle"}
  Not directly. There is no object, so no `this`. It can use instance members only
  through an object reference it is given. The compiler says
  `non-static variable name cannot be referenced from a static context`.
  :::
  :::accordion-item{label="When does a static block run?" icon="i-lucide-message-circle"}
  Once, when the class is loaded into the JVM, before `main` and before any
  object is created. Multiple static blocks run in the order written.
  :::
  :::accordion-item{label="What does final mean on a variable, a method and a class?" icon="i-lucide-message-circle"}
  Variable: assigned once. Method: cannot be overridden. Class: cannot be extended
  (`String`, `Integer` and every wrapper class are final).
  :::
  :::accordion-item{label="Difference between final, finally and finalize?" icon="i-lucide-message-circle"}
  `final` restricts change. `finally` is a block that always runs after
  `try`/`catch`, for cleanup. `finalize()` was a garbage-collection hook,
  deprecated since Java 9.
  :::
  :::accordion-item{label="Is a final variable immutable?" icon="i-lucide-message-circle"}
  For a primitive, yes. For a reference, only the reference is fixed; the object
  can still change. `final List<String> toppers` can still be `add`ed to.
  :::
::
