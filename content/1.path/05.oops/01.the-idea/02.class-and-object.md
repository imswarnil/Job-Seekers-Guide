The class is the plan and the object is what gets built from it. One class, as
many objects as you like, each with its own copy of the data. The Java track
showed you the syntax; this lesson is about saying it precisely.

## Why this matters in a job

Because every bug report you will read at work is about an **object**, not a
class. "Student 2104's attendance shows 104%" is one object in a bad state. If you
cannot keep "the kind of thing" and "this particular thing" apart in your head,
you will look for the bug in the wrong place.

In the interview, "what is the difference between a class and an object?" is
asked in almost every fresher round. It is easy, which is exactly why a vague
answer costs you.

## The blueprint and the building

A **class** is a blueprint. The university's admission form is a class: it says
every student has a name, a roll number, a course and a year. The form itself is
not a student.

An **object** is one filled-in copy of that form. Anita's form is one object.
Rahul's is another. Same fields, different values, and changing Rahul's year does
nothing to Anita's.

::feature-list{columns="2"}
  :::feature{icon="i-lucide-file-text" title="Class"}
  A type you define. Declares **fields** (what each object knows) and
  **methods** (what each object can do). Exists once, in your code. Takes no
  memory per student.
  :::
  :::feature{icon="i-lucide-user" title="Object"}
  An **instance** of a class, created at runtime with `new`. Lives on the
  **heap** (the area of memory for objects). Has its own copy of every
  non-static field.
  :::
::

"Instance" is the word interviewers use. An object is an instance of a class, and
creating one is called **instantiation**.

## How it works

```java [Student.java]
public class Student {
    String name;
    int rollNumber;
    int year;

    void promote() {
        year++;
    }

    public static void main(String[] args) {
        Student anita = new Student();
        anita.name = "Anita Rao";
        anita.rollNumber = 2104;
        anita.year = 2;

        Student rahul = new Student();
        rahul.name = "Rahul Menon";
        rahul.rollNumber = 2105;
        rahul.year = 2;

        rahul.promote();

        System.out.println(anita.name + " is in year " + anita.year);
        System.out.println(rahul.name + " is in year " + rahul.year);
    }
}
```

```text [Output]
Anita Rao is in year 2
Rahul Menon is in year 3
```

`promote()` changed Rahul's `year` and not Anita's, because each object carries
its own fields.

::code-trace{caption="What happens on the line with new"}
```java [Trace.java]
Student anita = new Student();
```

  :::code-trace-step{lines="1" caption="Right-hand side first. new asks the JVM for enough heap memory for one Student: a name reference, two ints."}
  :::
  :::code-trace-step{lines="1" caption="Every field gets its default: null for name, 0 for rollNumber and year. Then the constructor runs (next lesson)."}
  :::
  :::code-trace-step{lines="1" caption="new hands back a reference, the address of that memory. The variable anita, on the stack, stores the address, not the object."}
  :::
::

That last step is the one people forget. `anita` is not the student. It is a
**reference** pointing at the student, which you met in the Java track's lesson
on the stack and the heap.

## Real use case

When a Java service reads students from the database, every row becomes one
object of one class.

```java [Roster.java]
import java.util.List;

public class Roster {
    record Student(int rollNumber, String name, int year) {}

    public static void main(String[] args) {
        // In real code this list comes from a database query.
        List<Student> secondYear = List.of(
            new Student(2104, "Anita Rao", 2),
            new Student(2105, "Rahul Menon", 2),
            new Student(2106, "Farhan Ali", 2)
        );

        System.out.println("Class: Student, objects: " + secondYear.size());
        for (Student s : secondYear) {
            System.out.println(s.rollNumber() + " " + s.name());
        }
    }
}
```

```text [Output]
Class: Student, objects: 3
2104 Anita Rao
2105 Rahul Menon
2106 Farhan Ali
```

One class, three hundred rows, three hundred objects. The class is written once.

## What confuses people here

- **"Declaring a variable creates an object."** `Student s;` creates nothing. It
  makes a reference that points nowhere. Only `new` creates an object, and using
  `s` before that is the `NullPointerException` you met in the Java track.
- **"Two objects with the same values are the same object."** No. Two `new`
  calls make two objects, even with identical fields, and `==` compares the
  references, so it says `false`. The `equals` lesson later in this track is
  about exactly this.
- **"Assigning one variable to another copies the object."**
  `Student copy = anita;` copies the reference. There is still one object with
  two names pointing at it. Change `copy.year` and `anita.year` changes too.

```java [SameObject.java]
public class SameObject {
    static class Student { int year = 2; }

    public static void main(String[] args) {
        Student anita = new Student();
        Student copy = anita;
        copy.year = 4;
        System.out.println(anita.year);
        System.out.println(anita == copy);
        System.out.println(anita == new Student());
    }
}
```

```text [Output]
4
true
false
```

## Interview questions

::accordion
  :::accordion-item{label="What is the difference between a class and an object?" icon="i-lucide-message-circle"}
  A class is a blueprint: it declares the fields and methods. An object is one
  instance of that class, created at runtime with `new`, living on the heap with
  its own copy of the fields. One `Student` class, many student objects.
  :::
  :::accordion-item{label="How many ways can you create an object in Java?" icon="i-lucide-message-circle"}
  The common answer interviewers want: `new`, reflection
  (`Class.getDeclaredConstructor().newInstance()`), `clone()`, and
  deserialisation. For a fresher, knowing `new` well and naming the other three is
  enough. Every one of them still ends with memory on the heap.
  :::
  :::accordion-item{label="Where are objects stored, and where are references stored?" icon="i-lucide-message-circle"}
  Objects on the heap. A local reference variable lives on the stack of the
  method that declared it and holds the object's address. When no reference
  points at an object any more, the garbage collector may reclaim it.
  :::
  :::accordion-item{label="Does a class take memory?" icon="i-lucide-message-circle"}
  The class's code and its static fields are loaded once, into an area of the
  JVM called the metaspace. The per-object fields take no memory until an object
  is created. That is why a class with a thousand-element array field costs
  nothing until you call `new`.
  :::
::
