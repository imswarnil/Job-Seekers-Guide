A constructor. It is the code that runs inside `new`, before anybody gets a
reference to the object, and if it refuses, the object never exists at all. That
is how you make a half-built student impossible rather than unlikely.

## Why this matters in a job

Most of the bad data I have fixed at work came from objects that were allowed to
exist in a state that made no sense: an enquiry with no phone number, an exam
result with no subject. Every one of those could have been stopped in the
constructor.

In interviews, constructors are a favourite for quick-fire questions: can a
constructor be private, can it be inherited, can it return a value, what happens
if you do not write one. Five questions, thirty seconds each, and they add up.

## The idea

Think of the college's admission counter. You cannot walk away with a roll
number until the clerk has your name, your course and your fee receipt. The
counter is the constructor: nothing leaves it half-filled.

A **constructor** is a special block that runs once, when an object is created
with `new`. It has **the same name as the class** and **no return type**, not
even `void`. Its job is to put the object into a valid starting state.

::feature-list{columns="2"}
  :::feature{icon="i-lucide-circle-dashed" title="Default constructor"}
  If you write **no** constructor, the compiler adds an empty one with no
  parameters. Write any constructor and it stops adding it.
  :::
  :::feature{icon="i-lucide-list-checks" title="Parameterised constructor"}
  Takes the values the object needs and checks them. The one you should be
  writing almost every time.
  :::
  :::feature{icon="i-lucide-copy" title="Copy constructor"}
  Takes another object of the same class and copies its values. Java does not
  generate one; you write it if you want it.
  :::
  :::feature{icon="i-lucide-lock" title="Private constructor"}
  Nobody outside the class can call `new`. Used by Singleton and by utility
  classes. You will meet it again in the patterns lesson.
  :::
::

## How it works

```java [Course.java]
public class Course {
    private final String code;
    private final String title;
    private final int credits;

    // Parameterised: every Course starts complete and checked.
    public Course(String code, String title, int credits) {
        if (code == null || code.isBlank()) {
            throw new IllegalArgumentException("A course needs a code");
        }
        if (credits < 1 || credits > 6) {
            throw new IllegalArgumentException("Credits must be 1 to 6, got " + credits);
        }
        this.code = code;
        this.title = title;
        this.credits = credits;
    }

    // Overloaded: a lab course defaults to 2 credits.
    // this(...) calls the constructor above, so the checks run once, in one place.
    public Course(String code, String title) {
        this(code, title, 2);
    }

    // Copy constructor.
    public Course(Course other) {
        this(other.code, other.title, other.credits);
    }

    @Override
    public String toString() {
        return code + " " + title + " (" + credits + " credits)";
    }

    public static void main(String[] args) {
        Course dbms = new Course("CS301", "Database Systems", 4);
        Course lab = new Course("CS391", "DBMS Lab");
        Course copy = new Course(dbms);

        System.out.println(dbms);
        System.out.println(lab);
        System.out.println(copy + ", same object? " + (copy == dbms));

        new Course("CS999", "Everything", 12);
    }
}
```

```text [Output]
CS301 Database Systems (4 credits)
CS391 DBMS Lab (2 credits)
CS301 Database Systems (4 credits), same object? false
Exception in thread "main" java.lang.IllegalArgumentException: Credits must be 1 to 6, got 12
	at Course.<init>(Course.java:12)
	at Course.main(Course.java:44)
```

Look at `Course.<init>` in the stack trace. That is what the JVM calls a
constructor internally, and seeing it tells you the failure happened while the
object was being built, so no half-made `Course` ever escaped.

::code-trace{caption="Constructor chaining with this(...)"}
```java [Chain.java]
public Course(String code, String title) {
    this(code, title, 2);
}
```

  :::
  :::code-trace-step{lines="2" caption="this(...) jumps to the three-argument constructor with credits = 2. It must be the first statement, or the code does not compile."}
  :::

## Real use case

The order of construction matters once inheritance arrives. The parent's
constructor always runs **before** the child's, because the child may depend on
the parent's fields being ready.

```java [Order.java]
public class Order {
    static class Person {
        Person() { System.out.println("1. Person built"); }
    }

    static class Faculty extends Person {
        Faculty() {
            // the compiler inserts super(); here
            System.out.println("2. Faculty built");
        }
    }

    public static void main(String[] args) {
        new Faculty();
    }
}
```

```text [Output]
1. Person built
2. Faculty built
```

`super()` is inserted for you if you do not write it. That detail comes back in
the `this` and `super` lesson.

## What confuses people here

::compare{caption="The default constructor disappears the moment you write your own."}
  :::compare-side{label="Compiles" verdict="right"}
  ```java [A.java]
  class Hostel { }
  Hostel h = new Hostel();
  ```
  No constructor written, so the compiler supplies `Hostel()`.
  :::
  :::compare-side{label="Does not compile" verdict="wrong"}
  ```java [B.java]
  class Hostel {
      Hostel(String block) { }
  }
  Hostel h = new Hostel();
  ```
  `constructor Hostel in class Hostel cannot be applied to given types`. You
  wrote one, so the free one is gone.
  :::
::

- **A method with the class's name and a return type is not a constructor.**
  `public void Course() {}` compiles, and it is an ordinary method that never
  runs on `new`. A nasty one to spot.
- **Constructors are not inherited.** A child class gets the parent's methods,
  not its constructors. It must declare its own and call `super(...)`.
- **Constructors cannot be `static`, `final` or `abstract`.** They belong to
  object creation, so none of those words make sense on them.

## Interview questions

::accordion
  :::accordion-item{label="What is a constructor, and how is it different from a method?" icon="i-lucide-message-circle"}
  It runs once, automatically, when `new` creates the object. It has the class's
  name and no return type. A method has a return type (or `void`), any name, and
  runs only when called. A constructor sets up state; a method does work.
  :::
  :::accordion-item{label="What is the default constructor? When does Java provide it?" icon="i-lucide-message-circle"}
  A no-argument constructor the compiler adds **only if the class declares no
  constructor at all**. It sets fields to their defaults and calls `super()`.
  Declare any constructor and it is not added, which is why `new Hostel()` stops
  compiling in the example above.
  :::
  :::accordion-item{label="Can a constructor be private? Why would you do that?" icon="i-lucide-message-circle"}
  Yes. It stops outside code calling `new`. Used for a Singleton (the class makes
  its one instance itself) and for utility classes like `java.lang.Math`, which
  only have static methods and should never be instantiated.

  ```java [Grades.java]
  public final class Grades {
      private Grades() { }                        // nobody may create one
      public static char of(int marks) { return marks >= 90 ? 'A' : marks >= 75 ? 'B' : 'C'; }
  }
  ```
  :::
  :::accordion-item{label="What is constructor chaining?" icon="i-lucide-message-circle"}
  One constructor calling another: `this(...)` for another in the same class,
  `super(...)` for the parent's. Either must be the **first** statement, and you
  cannot have both in one constructor. It keeps validation in one place.
  :::
  :::accordion-item{label="Can a constructor return a value? Can it be inherited?" icon="i-lucide-message-circle"}
  No to both. It has no return type (it implicitly produces the new object), and
  it is not inherited: a subclass must write its own and chain to the parent's
  with `super(...)`.
  :::
::
