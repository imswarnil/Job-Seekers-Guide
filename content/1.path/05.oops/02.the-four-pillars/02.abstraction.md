Hiding **how** something works while showing **what** it does is abstraction.
Encapsulation protected the data; abstraction protects the caller from
complexity it has no business knowing about.

## Why this matters in a job

At Twilio, the reports I built read from a data layer that other engineers
owned. I called `getPipelineByRegion()` and got numbers. Whether it hit a cache,
a warehouse or three APIs was not my problem, and when they rewrote the insides
my code did not change. That is abstraction paying for itself: two teams working
on the same system without waiting for each other.

In interviews the question is nearly always paired: "what is abstraction, and
how is it different from encapsulation?"

## The idea: the ATM

You walk up to an ATM near BTM Layout, put in a card, type a PIN and an amount,
and cash comes out. You do not know which bank server it spoke to, how the PIN
was encrypted, or how the note counter works. The screen shows you **what** you
can do. **How** it happens is hidden.

**Abstraction** is exposing only the essential operations of something and
hiding the implementation details behind them. In Java it is achieved with
**interfaces** and **abstract classes**: a type that says what can be done,
with the how left to the classes that implement it.

::compare{caption="The one-line difference, worth learning word for word."}
  :::compare-side{label="Encapsulation" verdict="neutral"}
  Hides the **data**. Answers "who may change this?". Achieved with `private`
  fields and guarded methods.
  :::
  :::compare-side{label="Abstraction" verdict="neutral"}
  Hides the **complexity**. Answers "what does the caller need to know?".
  Achieved with interfaces and abstract classes.
  :::
::

## How it works

The university sends results to students. Today by email, tomorrow by SMS too.
The code that publishes results should not care which.

```java [ResultPublisher.java]
import java.util.List;

public class ResultPublisher {

    // The abstraction: WHAT a notifier can do. No HOW at all.
    interface Notifier {
        void send(String rollNumber, String message);
    }

    // Two implementations: the HOW, hidden from the publisher.
    static class EmailNotifier implements Notifier {
        public void send(String rollNumber, String message) {
            // real code: SMTP connection, templates, retries...
            System.out.println("EMAIL to " + rollNumber + "@univ.edu: " + message);
        }
    }

    static class SmsNotifier implements Notifier {
        public void send(String rollNumber, String message) {
            // real code: SMS gateway API, character limits, DLT template ids...
            System.out.println("SMS to phone of " + rollNumber + ": " + message);
        }
    }

    // The publisher depends only on the abstraction.
    static void publish(List<Notifier> channels, String roll, int marks) {
        String message = "Your semester result is out: " + marks + "/100";
        for (Notifier n : channels) {
            n.send(roll, message);
        }
    }

    public static void main(String[] args) {
        publish(List.of(new EmailNotifier(), new SmsNotifier()), "2104", 72);
    }
}
```

```text [Output]
EMAIL to 2104@univ.edu: Your semester result is out: 72/100
SMS to phone of 2104: Your semester result is out: 72/100
```

`publish` never mentions email or SMS. Add a `WhatsAppNotifier` next year and
`publish` does not change by one character.

## Real use case

You have used abstraction every day in the Java track without calling it that.

```java [JdkAbstraction.java]
import java.util.ArrayList;
import java.util.LinkedList;
import java.util.List;

public class JdkAbstraction {
    static int countDetained(List<Integer> attendance) {
        int count = 0;
        for (int pct : attendance) if (pct < 75) count++;
        return count;
    }

    public static void main(String[] args) {
        List<Integer> a = new ArrayList<>(List.of(80, 62, 91, 70));
        List<Integer> b = new LinkedList<>(List.of(80, 62, 91, 70));
        System.out.println(countDetained(a) + " " + countDetained(b));
    }
}
```

```text [Output]
2 2
```

`List` is the abstraction. `ArrayList` is backed by an array, `LinkedList` by
nodes and pointers, and `countDetained` neither knows nor cares. JDBC is the same
idea at a larger scale: your code talks to `Connection` and `ResultSet`, and the
driver underneath can be MySQL, PostgreSQL or Oracle.

::real-life{title="A question I was asked at more than one walk-in" source="Technical rounds, 2018"}
"Give me an example of abstraction from real life that is not a car." Everybody
says the car: steering wheel, you do not know how the engine works. It is fine
and it is what every other candidate says. The ATM, a TV remote, or the `List`
interface in Java all stand out more, and the `List` one shows you have written
code.
::

## What confuses people here

- **"Abstraction means the `abstract` keyword."** The keyword is one tool. An
  interface with no `abstract` word in sight is still abstraction, and so is a
  plain method with a good name that hides forty lines.
- **"Abstraction and encapsulation are the same thing, described twice."** They
  often appear together, which is why they blur. The distinction: encapsulation
  is about **access to data**, abstraction is about **exposing only what matters**.
- **"You can create an object of an abstract type."** You cannot. `new Notifier()`
  does not compile. You create an object of a concrete class and refer to it by
  the abstract type: `Notifier n = new EmailNotifier();`.

## Interview questions

::accordion
  :::accordion-item{label="What is abstraction?" icon="i-lucide-message-circle"}
  Showing what an object does and hiding how it does it. In Java, through
  interfaces and abstract classes. Example: `publish` calls `Notifier.send` and
  works with email, SMS or anything added later, because it only knows the
  interface.
  :::
  :::accordion-item{label="Difference between abstraction and encapsulation?" icon="i-lucide-message-circle"}
  Abstraction hides complexity (design level: what to expose). Encapsulation hides
  data (implementation level: who may change it). Abstraction is achieved with
  interfaces and abstract classes; encapsulation with access modifiers.
  :::
  :::accordion-item{label="How do you achieve abstraction in Java?" icon="i-lucide-message-circle"}
  Two ways: abstract classes (0 to 100% abstraction, can hold state and
  concrete methods) and interfaces (a contract of methods; traditionally 100%
  abstract, since Java 8 they can have `default` and `static` methods too). The
  difference between the two is its own lesson in the next chapter.
  :::
  :::accordion-item{label="Give a real-world example of abstraction from Java itself." icon="i-lucide-message-circle"}
  `List` with `ArrayList` and `LinkedList`; JDBC's `Connection` over any
  database driver. Code written against the interface keeps working when the
  implementation is swapped.
  :::
::
