One request, traced through four layers, and about forty new words arrived with
it. Here they are, each in one line, because a term you can use and cannot
define is a term that will catch you out across a table.

## The layers

::field-group
  :::field{name="Protocol" type="concept"}
  An agreement about the shape of a message. Nothing more mysterious than that.
  :::
  :::field{name="Encapsulation" type="concept"}
  Each layer wraps the one above it in its own header. Your HTTP request is
  inside a TCP segment, inside an IP packet, inside an Ethernet frame.
  :::
  :::field{name="Link layer" type="layer"}
  One hop, machine to machine, over one physical medium. Ethernet, wifi.
  :::
  :::field{name="Internet layer" type="layer"}
  Getting a packet across many hops, using IP addresses. Makes no promises about
  arrival.
  :::
  :::field{name="Transport layer" type="layer"}
  TCP or UDP. Turns "a packet might arrive" into "this stream arrives in order",
  or deliberately does not.
  :::
  :::field{name="Application layer" type="layer"}
  HTTP, DNS, SMTP. What the message actually means.
  :::
::

## Finding and reaching

::field-group
  :::field{name="IP address" type="addressing"}
  Which machine. `10.0.4.12` or an IPv6 equivalent.
  :::
  :::field{name="Port" type="addressing"}
  Which program on that machine. 80 for HTTP, 443 for HTTPS, 5432 for
  PostgreSQL, 3000 for whatever you are running right now.
  :::
  :::field{name="Socket" type="addressing"}
  The pair: address plus port. A connection is two sockets.
  :::
  :::field{name="DNS" type="naming"}
  The system that turns a name into an address. Not part of HTTP, and it happens
  before any request is sent.
  :::
  :::field{name="A record" type="dns"}
  A name pointing directly at an IPv4 address. `AAAA` is the IPv6 version.
  :::
  :::field{name="CNAME" type="dns"}
  A name pointing at another name. Cannot exist at the root of a domain, which
  is the single most common DNS confusion.
  :::
  :::field{name="TTL" type="dns"}
  How long a resolver may cache an answer. The reason a DNS change does not take
  effect instantly, and the reason you lower it *before* a migration.
  :::
  :::field{name="NAT" type="addressing"}
  Many private addresses sharing one public one. Why everyone on a campus wifi
  appears to come from a single address, and why rate limiting by address alone
  punishes a whole university.
  :::
::

## TCP and what it costs

::field-group
  :::field{name="Three-way handshake" type="tcp"}
  SYN, SYN-ACK, ACK. One full round trip before any data moves, which is why
  connection reuse matters so much.
  :::
  :::field{name="Sequence number" type="tcp"}
  Where a byte sits in the stream. What makes reassembly in order possible.
  :::
  :::field{name="Acknowledgement" type="tcp"}
  The receiver saying which bytes arrived. Missing acknowledgements trigger
  retransmission.
  :::
  :::field{name="Head-of-line blocking" type="tcp"}
  One lost segment stalls everything behind it, because order is guaranteed.
  The price of reliability, and the reason HTTP/3 moved to UDP.
  :::
  :::field{name="UDP" type="transport"}
  Send and hope. No handshake, no ordering, no retransmission. Correct for
  video, voice and DNS, where a late packet is worse than a missing one.
  :::
  :::field{name="MTU" type="transport"}
  The largest frame a link will carry, typically 1500 bytes. Larger messages are
  split, which is why one HTTP response is many packets.
  :::
::

## HTTP

::field-group
  :::field{name="Idempotent" type="http"}
  Repeating the request has the same effect as making it once. `GET`, `PUT` and
  `DELETE` are; `POST` is not. This is why a browser will re-send a `GET` on
  refresh and warn you about a `POST`.
  :::
  :::field{name="Safe" type="http"}
  Changes nothing on the server. `GET` and `HEAD`. A `GET` that deletes
  something is a real and dangerous bug, because crawlers follow links.
  :::
  :::field{name="Stateless" type="http"}
  The server remembers nothing between requests. Sessions and cookies exist
  entirely to work around this.
  :::
  :::field{name="Header" type="http"}
  Metadata about the request or response. `Content-Type`, `Authorization`,
  `Cache-Control`.
  :::
  :::field{name="Status code" type="http"}
  `2xx` worked, `3xx` look elsewhere, `4xx` you got it wrong, `5xx` we got it
  wrong. The class matters more than the number.
  :::
  :::field{name="429" type="http"}
  Too Many Requests, with `Retry-After`. Knowing this number specifically marks
  somebody who has read the specification.
  :::
  :::field{name="Keep-alive" type="http"}
  Reusing one TCP connection for several requests, so the handshake is paid once
  rather than per file.
  :::
::

## TLS

::field-group
  :::field{name="TLS" type="security"}
  What the `s` in `https` is. The successor to SSL, which is the name people
  still use.
  :::
  :::field{name="Certificate" type="security"}
  A document binding a public key to a domain name, signed by an authority the
  browser already trusts.
  :::
  :::field{name="What the padlock proves" type="critical"}
  That the connection is encrypted and the server controls that domain name.
  **Not** that the site is honest, safe, or who you assume. A phishing site can
  have a valid certificate, and most do.
  :::
  :::field{name="Certificate authority" type="security"}
  An organisation browsers trust to vouch for domains. The whole model rests on
  that list, which is why a compromised authority is a serious event.
  :::
::

## When it breaks

::field-group
  :::field{name="Timeout" type="reliability"}
  Giving up on a reply. A missing reply and a slow reply are indistinguishable,
  which is the fundamental problem of distributed systems.
  :::
  :::field{name="Retry storm" type="reliability"}
  A struggling service is retried by everybody at once and is finished off by
  the retries rather than the original load.
  :::
  :::field{name="Exponential backoff" type="reliability"}
  Waiting longer after each failure. 1s, 2s, 4s, 8s.
  :::
  :::field{name="Jitter" type="reliability"}
  Randomising the wait, so a thousand clients that failed together do not retry
  together. Backoff without jitter still produces a synchronised stampede.
  :::
  :::field{name="Circuit breaker" type="reliability"}
  Stop calling a failing service for a while, so it can recover and you fail
  fast instead of waiting.
  :::
::

## The three pairs people confuse

::compare{caption="Used interchangeably, and they are not the same."}
  :::compare-side{label="Latency" verdict="neutral"}
  How long one message takes. Limited by distance and the speed of light, and it
  is why a server in Frankfurt feels slow from Bangalore no matter how fast it
  is.
  :::
  :::compare-side{label="Bandwidth" verdict="neutral"}
  How much can flow per second. A fat pipe with high latency is still slow to
  first byte.
  :::
::

**TCP against HTTP.** TCP delivers bytes in order. HTTP is the meaning of those
bytes. "The API is down" is usually HTTP; "connection refused" is TCP.

**Authentication against encryption.** TLS proves who the server is and hides
the contents. It says nothing about who *you* are, which is what your session
cookie is for.
