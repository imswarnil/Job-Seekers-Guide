Every element on a page is a rectangle, and the 44 extra pixels come from how
that rectangle is measured. By default `width` sets only the innermost part of
the box, and everything else is added on top.

## Why this matters in a job

"Explain the box model" is asked in almost every fresher web interview, and the
follow-up is always a number: "a 300px element with 20px padding and a 2px
border, how wide is it?" At work, the box model explains columns that overflow,
cards that do not line up, and gaps that are smaller than you wrote.

## Four layers, like a framed certificate

Picture your degree certificate framed on a wall. The printed text is the
**content**. The white mount around it is the **padding**. The wooden frame is
the **border**. The empty wall between it and the next frame is the **margin**.

- **Content:** the text or image. `width` and `height` size this, by default.
- **Padding:** space inside the border. Takes the element's background colour.
- **Border:** the line around the padding.
- **Margin:** space outside the border, pushing other elements away. Always
  transparent.

## How it works

```css [student-card.css]
.student-card {
  width: 300px;
  padding: 20px;
  border: 2px solid #334155;
  margin: 16px;
}
```

```text [Output]
Width on screen, content-box (the default):
  2 + 20 + 300 + 20 + 2 = 344px
Space it occupies in the row, including margin:
  16 + 344 + 16 = 376px
```

The default value of `box-sizing` is `content-box`, which means `width` is the
content only. Change one line:

```css [student-card.css]
.student-card {
  box-sizing: border-box;
  width: 300px;
  padding: 20px;
  border: 2px solid #334155;
}
```

```text [Output]
Width on screen, border-box:   300px
Content area left inside:      300 - 20 - 20 - 2 - 2 = 256px
```

Now `width` means the whole visible box, padding and border included. That is
what everybody expects `width` to mean, so nearly every stylesheet starts with
this reset:

```css [reset.css]
*, *::before, *::after { box-sizing: border-box; }
```

Press Run and compare the two cards. Then delete the `box-sizing` line and run
it again.

::runner{lang="css"}
```css
.card { width: 300px; padding: 20px; border: 2px solid #334155; margin-bottom: 8px; }
.b { box-sizing: border-box; }
.ruler { width: 300px; height: 6px; background: #f59e0b; }

/* --- html --- */
<div class="ruler"></div>
<div class="card">content-box: 344px wide</div>
<div class="card b">border-box: 300px wide</div>
```
::

### Margin collapse

```html [collapse.html]
<p style="margin-bottom: 20px">Hall ticket issued.</p>
<p style="margin-top: 30px">Exam on Monday.</p>
```

```text [Output]
Gap between the two paragraphs: 30px (not 50px)
```

When two **vertical** margins touch, they collapse into the larger of the two.
Horizontal margins never collapse, and margins inside a flex or grid container
never collapse. Padding or a border between them also stops it.

## Real use case

Two equal columns for a course page, each with padding, inside a 1000px
container:

::compare{caption="Two 50% columns with 20px of padding, in a 1000px row."}
  :::compare-side{label="content-box, the default" verdict="wrong"}
  Each column is 500 + 40 = 540px. Two of them need 1080. They overflow and the
  second one drops below the first.
  :::
  :::compare-side{label="border-box" verdict="right"}
  Each column is 500px in total, padding included. Two fit exactly.
  :::
::

In a real codebase you will find the `border-box` reset in the first ten lines
of the base stylesheet, and spacing between siblings done with `gap` on a flex
or grid parent rather than margins on the children, which sidesteps margin
collapse entirely.

## What confuses people here

**`height: 100%` does nothing.** A percentage height needs a parent with a
definite height. If the parent's height depends on its content, the percentage
has nothing to be a percentage of.

**Margin is outside the element.** A click on the margin is not a click on the
element, and a background colour does not fill it.

**Padding cannot be negative, margin can.** `margin-top: -10px` pulls an element
upward. It is legal and occasionally useful, and usually a sign of a layout that
should have been a flex container.

## Interview questions

::accordion
  :::accordion-item{label="Explain the CSS box model." icon="i-lucide-message-circle"}
  Every element is content, then padding, then border, then margin, outward. By
  default `width` sets the content box only, so padding and border are added on
  top. `box-sizing: border-box` makes `width` include padding and border.
  :::
  :::accordion-item{label="A div has width 200px, padding 10px, border 5px, margin 20px. How wide is it?" icon="i-lucide-message-circle"}
  With `content-box`: 200 + 10 + 10 + 5 + 5 = 230px visible, and 270px of space
  including margins. With `border-box`: 200px visible (content 170px), and 240px
  including margins.
  :::
  :::accordion-item{label="What is margin collapse?" icon="i-lucide-message-circle"}
  Adjacent vertical margins of block elements combine into the larger one
  rather than the sum. A 20px bottom margin meeting a 30px top margin gives a
  30px gap. It does not happen horizontally, or inside flex and grid containers.
  :::
  :::accordion-item{label="Padding or margin: which one takes the background colour?" icon="i-lucide-message-circle"}
  Padding. The background covers content and padding (and sits under the
  border). Margin is always transparent.
  :::
  :::accordion-item{label="Why do people set box-sizing: border-box on everything?" icon="i-lucide-message-circle"}
  So that `width` means what it says. Adding padding no longer changes an
  element's size, and percentage columns add up to 100% instead of overflowing.
  :::
::
