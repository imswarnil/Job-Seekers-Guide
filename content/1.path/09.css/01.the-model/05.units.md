A pixel is fixed. Everything else in CSS is relative to something: the parent,
the root of the page, or the size of the screen. The skill is knowing what each
unit is relative to, because the wrong choice looks fine on your laptop and
breaks for the reader who zoomed in.

## Why this matters in a job

"What is the difference between em and rem?" is one of the five most asked CSS
questions for freshers. At work, units decide whether a page respects a user's
font-size setting, which matters for accessibility and, for government and
education sites, is often a legal requirement.

## Absolute and relative

A pixel is like saying "the notice is 20 centimetres wide". A relative unit is
like saying "the notice is half the width of the board", which stays right when
the board changes.

| Unit | Relative to | Example |
| --- | --- | --- |
| `px` | Nothing. A fixed CSS pixel. | `border: 1px solid` |
| `%` | The parent (for `width`, the parent's width) | `width: 50%` |
| `em` | The element's own font size (for `font-size`, the parent's) | `padding: 0.5em 1em` |
| `rem` | The root (`<html>`) font size, 16px by default | `font-size: 1.125rem` = 18px |
| `vw` | 1% of the viewport width | `width: 100vw` |
| `vh` | 1% of the viewport height | `min-height: 100vh` |

Two newer ones worth recognising: `ch` is the width of the "0" character, so
`max-width: 65ch` gives a comfortable reading line; `dvh` is like `vh` but
accounts for the phone's address bar sliding in and out.

## How it works

The trap with `em` is that it **compounds**. Nested lists of course modules:

```html [modules.html]
<ul class="modules">
  <li>Semester 5
    <ul class="modules">
      <li>Operating Systems
        <ul class="modules">
          <li>Paging</li>
        </ul>
      </li>
    </ul>
  </li>
</ul>
```

```css [modules.css]
html     { font-size: 16px; }
.modules { font-size: 1.2em; }
```

```text [Output]
Level 1 "Semester 5":         16 × 1.2 = 19.2px
Level 2 "Operating Systems":  19.2 × 1.2 = 23.04px
Level 3 "Paging":             23.04 × 1.2 = 27.65px
```

Each list is 1.2 times its **parent**, and the parent was already enlarged. Now
switch to `rem`:

```css [modules.css]
.modules { font-size: 1.2rem; }
```

```text [Output]
Level 1: 16 × 1.2 = 19.2px
Level 2: 16 × 1.2 = 19.2px
Level 3: 16 × 1.2 = 19.2px
```

`rem` always looks at the root, so nesting changes nothing.

::runner{lang="css"}
```css
.em  { font-size: 1.2em; }
.rem { font-size: 1.2rem; }

/* --- html --- */
<ul class="em"><li>em: Semester 5<ul class="em"><li>Operating Systems<ul class="em"><li>Paging</li></ul></li></ul></li></ul>
<ul class="rem"><li>rem: Semester 5<ul class="rem"><li>Operating Systems<ul class="rem"><li>Paging</li></ul></li></ul></li></ul>
```
::

## Real use case

A typical base stylesheet for a college site chooses like this:

```css [base.css]
html   { font-size: 100%; }           /* respect the user's setting, usually 16px */
body   { font-size: 1rem; line-height: 1.5; }
h1     { font-size: 2rem; }
main   { max-width: 70rem; margin-inline: auto; padding: 0 1rem; }
p      { max-width: 65ch; }
.btn   { padding: 0.5em 1em; }        /* em: grows with the button's own text */
.hero  { min-height: 60vh; }
hr     { border-top: 1px solid #ddd; }
```

The reasoning: `rem` for font sizes and most spacing, so a reader who sets their
browser to 20px gets a page that scales with them. `em` for padding that should
grow with its own text, like a button that gets bigger when its label does.
`px` for thin things that should stay thin, like borders. `%` and `vw` for
widths.

## What confuses people here

**`100vw` causes a horizontal scrollbar** on desktops, because `vw` includes the
width of the vertical scrollbar. Use `width: 100%` for full-width blocks.

**`em` on `font-size` looks at the parent**, but `em` on everything else looks
at the element's own font size. `h2 { font-size: 2em; margin-bottom: 1em; }`
gives a 32px heading with a 32px margin, not 16px.

**Setting `html { font-size: 62.5%; }`** so that 1rem = 10px was a popular trick.
It works, and it overrides the user's setting to a smaller base that you then
have to scale back up everywhere. Prefer leaving the root alone.

## Interview questions

::accordion
  :::accordion-item{label="What is the difference between em and rem?" icon="i-lucide-message-circle"}
  `em` is relative to the element's font size (the parent's, when used on
  `font-size`), so it compounds when nested. `rem` is relative to the root
  `<html>` font size, so `1.5rem` is the same everywhere. Nested lists at
  `1.2em` grow 19.2, 23.04, 27.65px; at `1.2rem` they stay 19.2px.
  :::
  :::accordion-item{label="Which unit would you use for font sizes, and why?" icon="i-lucide-message-circle"}
  `rem`. It scales with the user's browser font setting, which `px` does not,
  and it does not compound like `em`.
  :::
  :::accordion-item{label="What are vw and vh?" icon="i-lucide-message-circle"}
  Viewport units: 1vw is 1% of the viewport's width, 1vh is 1% of its height.
  `min-height: 100vh` makes a section at least one screen tall. On phones, `dvh`
  handles the address bar better.
  :::
  :::accordion-item{label="What is 50% relative to?" icon="i-lucide-message-circle"}
  It depends on the property. For `width`, and surprisingly for `padding` and
  `margin` too, it is the parent's width. For `height` it is the parent's
  height, which must be definite. For `font-size` it is the parent's font size.
  :::
::
