Flexbox is the answer for putting things in a row or a column. You turn it on
for a parent with one line, `display: flex`, and its children stop stacking and
line up, with rules for how the spare space is shared out.

## Why this matters in a job

Because most of front-end layout is rows and columns of things: a navigation
bar, a row of buttons, a card with a name on the left and a status on the right.
In interviews, "how do you centre a div?" and "what is the difference between
`justify-content` and `align-items`?" are both Flexbox questions, and the second
one catches people who have only copied snippets.

## One line of seats

Think of one row of chairs on a stage for a college function. The row has a
direction (left to right), and there is a question of how to spread the chairs
along it (bunched at one end, spaced evenly) and another of how to line them up
across it (all at the front edge, or centred). Flexbox is that.

- The **container** is the parent with `display: flex`. Its direct children are
  **flex items**.
- The **main axis** runs in the `flex-direction`: horizontal for `row` (the
  default), vertical for `column`.
- The **cross axis** is at right angles to it.

::compare{caption="The properties, split by where they go."}
  :::compare-side{label="On the container" verdict="neutral"}
  `display: flex` · `flex-direction: row | column` · `justify-content` (main
  axis: `flex-start`, `center`, `space-between`, `space-around`,
  `space-evenly`) · `align-items` (cross axis: `stretch`, `center`,
  `flex-start`, `flex-end`) · `flex-wrap: wrap` · `gap`.
  :::
  :::compare-side{label="On the items" verdict="neutral"}
  `flex-grow` (share of spare space) · `flex-shrink` (share of the squeeze when
  there is not enough) · `flex-basis` (starting size before growing or
  shrinking) · the shorthand `flex` · `align-self` (override `align-items` for
  one item) · `order`.
  :::
::

## How it works

::code-trace{caption="The two properties that get confused, and the rule that fixes it."}
```css [toolbar.css]
.toolbar {
  display: flex;
  justify-content: space-between;
  align-items: center;
}
```

  :::code-trace-step{lines="2" caption="flex-direction defaults to row, so the MAIN axis is horizontal and the CROSS axis is vertical."}
  :::
  :::code-trace-step{lines="3" caption="justify-content always works on the MAIN axis. In a row that means horizontally."}
  :::
  :::code-trace-step{lines="4" caption="align-items always works on the CROSS axis. In a row that means vertically. Set flex-direction: column and both swap meaning, which is the entire source of the confusion."}
  :::
::

Now `flex-grow`, `flex-shrink` and `flex-basis` with numbers. A 600px row, no
gap, three items:

```css [grow.css]
.row        { display: flex; width: 600px; }
.name       { flex: 1 1 100px; }   /* grow 1, shrink 1, basis 100px */
.department { flex: 2 1 100px; }   /* grow 2 */
.status     { flex: 0 0 100px; }   /* fixed at 100px */
```

```text [Output]
Starting sizes (flex-basis): 100 + 100 + 100 = 300px
Spare space:                 600 - 300 = 300px
Shared by grow ratio 1 : 2 : 0 → 100px, 200px, 0px
Final widths: name 200px, department 300px, status 100px
```

`flex: 1` on its own, the form you will see most, means `1 1 0%`: start from
zero and take an equal share of everything.

Centring, which used to be a famous problem:

```css [centre.css]
.hero {
  display: flex;
  justify-content: center;   /* horizontally, in a row */
  align-items: center;       /* vertically */
  min-height: 60vh;
}
```

::runner{lang="css"}
```css
.toolbar { display: flex; justify-content: space-between; align-items: center; gap: 1rem; flex-wrap: wrap; padding: 0.5rem; border: 1px solid #cbd5e1; }
.toolbar h2 { margin: 0; font-size: 1.1rem; }
.hero { display: flex; justify-content: center; align-items: center; height: 120px; background: #f1f5f9; margin-top: 1rem; }

/* --- html --- */
<div class="toolbar">
  <h2>Applications, 2026 intake</h2>
  <div><button>Filter</button> <button>Export</button></div>
</div>
<div class="hero"><strong>Centred in both directions</strong></div>
```
::

## Real use case

The header of a college portal: logo on the left, links in the middle, a login
button pushed to the far right, wrapping on a phone.

```css [header.css]
.site-header {
  display: flex;
  align-items: center;
  gap: 1rem;
  flex-wrap: wrap;
}
.site-header .login { margin-left: auto; }   /* absorb all free space before it */
```

`margin-left: auto` on one item is the idiom worth knowing: an auto margin in a
flex container swallows all the free space on that side, so the item is pushed
to the end. It keeps working when somebody adds another link, which
`justify-content: space-between` does not.

A student card list that wraps:

```css [cards.css]
.card-list { display: flex; flex-wrap: wrap; gap: 1rem; }
.card-list > * { flex: 1 1 16rem; }   /* at least 16rem, grow to fill the row */
```

## What confuses people here

**Flex properties go on the parent, the effect shows on the children.** Putting
`display: flex` on the item you want to move does nothing to it.

**`align-items` "does nothing".** In a row, it aligns vertically within the row's
height. If the container is only as tall as its content, there is no room to
move. Give it a height, or `min-height`.

**Items overflow instead of shrinking.** A flex item will not shrink below its
content's minimum width, so a long email address with no spaces pushes the row
wide. `min-width: 0` on the item fixes it.

**`gap`, not margins.** `gap: 1rem` puts space only between items, never at the
edges, and needs no `:last-child` exception.

## Interview questions

::accordion
  :::accordion-item{label="How do you centre a div horizontally and vertically?" icon="i-lucide-message-circle"}
  On the parent: `display: flex; justify-content: center; align-items: center;`
  plus a height. Or `display: grid; place-items: center;`. For horizontal only,
  a block with a width takes `margin-inline: auto`.
  :::
  :::accordion-item{label="justify-content against align-items?" icon="i-lucide-message-circle"}
  `justify-content` distributes items along the main axis; `align-items` aligns
  them on the cross axis. In the default `row`, that is horizontal and vertical.
  With `flex-direction: column` they swap.
  :::
  :::accordion-item{label="What does flex: 1 mean?" icon="i-lucide-message-circle"}
  `flex-grow: 1; flex-shrink: 1; flex-basis: 0%`. Every item with `flex: 1`
  gets an equal share of the space regardless of its content.
  :::
  :::accordion-item{label="Explain flex-grow, flex-shrink and flex-basis." icon="i-lucide-message-circle"}
  `flex-basis` is the starting size. If there is spare space, it is shared in
  the ratio of `flex-grow`. If there is not enough, the overflow is taken away in
  the ratio of `flex-shrink` (weighted by basis). A 600px row of three 100px
  items with grow 1, 2, 0 ends at 200, 300 and 100px.
  :::
  :::accordion-item{label="What does flex-wrap do?" icon="i-lucide-message-circle"}
  By default items stay on one line and shrink. `flex-wrap: wrap` lets them move
  to a new line when they do not fit, which is what makes a row of cards work on
  a phone.
  :::
::
