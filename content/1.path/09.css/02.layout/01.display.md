Some elements start a new line and stretch across the page. Others sit inside a
line of text like a word. That difference is not decided by the tag. It is
decided by the `display` property, which every element has a default for and
which you can change.

## Why this matters in a job

Because "why does `width` do nothing on my `<span>`?" is a `display` question,
and because "what is the difference between `display: none` and
`visibility: hidden`?" is asked in nearly every fresher CSS round.

## Paragraphs and words

A block element behaves like a paragraph in a notebook: it starts on a new line
and takes the whole width of the page. An inline element behaves like a word: it
sits in the line, as wide as its text, and wraps with the sentence.

::compare{caption="The three values you need to know first."}
  :::compare-side{label="block" verdict="neutral"}
  New line, full width of the parent. Respects `width`, `height`, and all
  margins and padding. Default for `div`, `p`, `h1` to `h6`, `ul`, `section`,
  `form`.
  :::
  :::compare-side{label="inline" verdict="neutral"}
  Sits in the line of text. **Ignores `width` and `height`.** Vertical margin
  does not push other lines away. Default for `span`, `a`, `strong`, `em`,
  `label`.
  :::
::

`inline-block` is the middle: it sits in the line like a word, but respects
`width`, `height` and vertical margins like a block. `img`, `input` and `button`
behave this way by default.

Two ways to hide:

- `display: none` removes the element completely. It takes no space, and screen
  readers skip it.
- `visibility: hidden` makes it invisible but **keeps its space**, as if a
  seat in the exam hall were empty but still reserved.
- `opacity: 0` is also invisible and keeps its space, and it can still be
  clicked.

## How it works

```html [badges.html]
<p>
  Asha Rao
  <span class="badge">Topper</span>
  <span class="badge badge--block">Scholarship</span>
</p>
<p class="gone">Hidden with display: none</p>
<p class="ghost">Hidden with visibility: hidden</p>
<p>Last line</p>
```

```css [badges.css]
.badge        { width: 200px; padding: 4px 8px; background: #fef3c7; }
.badge--block { display: inline-block; }
.gone         { display: none; }
.ghost        { visibility: hidden; }
```

```text [Output]
"Topper" is only as wide as its text: width is ignored on an inline span.
"Scholarship" is 200px wide and still on the same line: inline-block.
The display: none paragraph leaves no gap.
The visibility: hidden paragraph leaves one empty line of space above "Last line".
```

::runner{lang="css"}
```css
.badge        { width: 200px; padding: 4px 8px; background: #fef3c7; }
.badge--block { display: inline-block; }
.gone         { display: none; }
.ghost        { visibility: hidden; }

/* --- html --- */
<p>Asha Rao <span class="badge">Topper</span> <span class="badge badge--block">Scholarship</span></p>
<p class="gone">Hidden with display: none</p>
<p class="ghost">Hidden with visibility: hidden</p>
<p>Last line</p>
```
::

`display` has two more values you will use constantly: `flex` and `grid`. They
make the element itself behave like a block, and change how its **children**
are laid out. Those are the next lessons but one.

## Real use case

Navigation links are `<a>` elements, which are inline, so padding on them does
not make the clickable area taller in the way you expect. The standard fix:

```css [nav.css]
.nav a {
  display: inline-block;   /* now padding and height count */
  padding: 0.75rem 1rem;
}
```

And a mobile menu is hidden and shown by toggling a class that sets
`display: none`, because a closed menu should take no space and should not be
read out by a screen reader:

```css [menu.css]
.menu            { display: none; }
.menu.is-open    { display: block; }
```

## What confuses people here

**`display: none` and accessibility.** It hides content from screen readers too.
To hide something visually but keep it readable (a "Skip to results" link, a
label for an icon button), use a visually-hidden class that shrinks the element
to one pixel instead.

**The gap between inline-block elements.** Two `inline-block` buttons show a
small gap even with zero margin. It is the space character between the tags in
your HTML, rendered like a space between words. Flexbox with `gap` avoids it.

## Interview questions

::accordion
  :::accordion-item{label="Block, inline and inline-block: what is the difference?" icon="i-lucide-message-circle"}
  Block starts on a new line, takes full width, and respects width, height and
  all margins. Inline flows with text and ignores width and height. Inline-block
  flows with text but respects width, height and vertical margins.
  :::
  :::accordion-item{label="display: none against visibility: hidden?" icon="i-lucide-message-circle"}
  `display: none` removes the element from layout: no space, not read by screen
  readers. `visibility: hidden` hides it but keeps its space. `opacity: 0` keeps
  its space and it still receives clicks.
  :::
  :::accordion-item{label="Why does width not work on a span?" icon="i-lucide-message-circle"}
  A `span` is inline by default, and inline boxes are sized by their content.
  Set `display: inline-block` or `block` and `width` applies.
  :::
  :::accordion-item{label="Name five block and five inline elements." icon="i-lucide-message-circle"}
  Block: `div`, `p`, `h1`, `ul`, `section`. Inline: `span`, `a`, `strong`,
  `em`, `label`. (`img`, `input` and `button` are inline-level but sized like
  inline-block.)
  :::
::
