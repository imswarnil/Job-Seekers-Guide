CSS has had variables since about 2017. You name a value once, `--brand: #1d4ed8`,
use it everywhere with `var(--brand)`, and change it in one place. Because they
can be redefined inside a media query or a class, they are also how dark mode is
built.

## Why this matters in a job

Because every real design system is a list of custom properties: colours,
spacing, font sizes. When you join a team, the first file you read is the one
that defines them. In interviews, "what are CSS variables and how are they
different from Sass variables?" and "transition against animation?" are common
follow-ups once the layout questions are done.

## The college's colour sheet

A college prints a brand sheet: this blue, this maroon, this font. Every
department uses those names instead of guessing the shade. Custom properties are
that sheet, inside the stylesheet.

- Define on a selector, usually `:root` (the `<html>` element) so every element
  can see it: `:root { --brand: #1d4ed8; }`.
- Use with `var(--brand)`, with an optional fallback: `var(--brand, blue)`.
- They **inherit** and **cascade** like any property, so a class or a media
  query can redefine them for part of the page.

Colours can be written as `#1d4ed8` (hex), `rgb(29 78 216)`, `hsl(224 76% 48%)`,
or a named colour such as `maroon`. `hsl` (hue, saturation, lightness) is the
easiest to adjust by hand: a darker shade is the same hue with a lower
lightness.

## How it works

```css [theme.css]
:root {
  --bg: #ffffff;
  --text: #1e293b;
  --brand: #1d4ed8;
  --radius: 0.5rem;
}

@media (prefers-color-scheme: dark) {
  :root {
    --bg: #0f172a;
    --text: #e2e8f0;
    --brand: #60a5fa;
  }
}

body  { background: var(--bg); color: var(--text); }
.btn  {
  background: var(--brand);
  color: var(--bg);
  border-radius: var(--radius);
  padding: 0.5em 1em;
  transition: transform 150ms ease, background-color 150ms ease;
}
.btn:hover { transform: translateY(-2px); }

@media (prefers-reduced-motion: reduce) {
  .btn { transition: none; }
}
```

```text [Output]
Light system setting: white page, dark text, a dark blue "Apply" button.
Dark system setting:  dark navy page, light text, a light blue button.
Hovering the button lifts it 2px over 150 milliseconds.
With "reduce motion" switched on in the operating system, it moves instantly.
```

No rule for `.btn` or `body` changed between the themes. Only the variables did.

::runner{lang="css"}
```css
:root { --brand: #1d4ed8; --bg: #fff; }
.dark { --brand: #60a5fa; --bg: #0f172a; }
.box { background: var(--bg); padding: 1rem; margin-bottom: 0.5rem; }
.btn { background: var(--brand); color: var(--bg); border: 0; padding: 0.5em 1em; border-radius: 0.5rem; transition: transform 150ms ease; }
.btn:hover { transform: translateY(-2px); }

/* --- html --- */
<div class="box"><button class="btn">Apply now</button></div>
<div class="box dark"><button class="btn">Apply now</button></div>
```
::

### Transition against animation

- A **transition** animates a change between two states when a property changes,
  such as on `:hover` or when a class is added. It needs a trigger.
- An **animation** uses `@keyframes` to run a sequence on its own, can loop, and
  needs no trigger.

```css [loading.css]
@keyframes pulse {
  0%, 100% { opacity: 1; }
  50%      { opacity: 0.4; }
}
.result-loading { animation: pulse 1.2s ease-in-out infinite; }
```

```text [Output]
"Loading results" fades to 40% and back every 1.2 seconds, forever.
```

Animate `transform` and `opacity` where you can. The browser can move and fade
an element without recalculating the layout of the page, so they stay smooth.
Animating `width`, `top` or `margin` forces layout on every frame and stutters
on a cheap phone.

## Real use case

A college results portal lets each department brand its pages. The components
are written once against variables; each department only overrides a few:

```css [departments.css]
.dept-cse { --brand: #1d4ed8; }
.dept-ece { --brand: #b91c1c; }
.dept-mech { --brand: #15803d; }
```

```html [page.html]
<body class="dept-ece">  <!-- every button, link and heading bar is now red -->
```

Because variables cascade, one class on `<body>` rethemes everything under it.
JavaScript can change them at runtime too:
`document.documentElement.style.setProperty('--brand', '#7c3aed')`.

## What confuses people here

**CSS variables against Sass variables.** A Sass variable (`$brand`) is replaced
by its value when the stylesheet is compiled, before it reaches the browser; it
cannot change at runtime or per element. A CSS custom property lives in the
browser, cascades, and can change in a media query or from JavaScript.

**Variables do not work in media query conditions.** `@media (min-width:
var(--bp))` is ignored.

**`transition: all`** looks convenient and animates properties you did not
intend, including layout ones. List the properties.

## Interview questions

::accordion
  :::accordion-item{label="What are CSS custom properties?" icon="i-lucide-message-circle"}
  Variables defined with a `--name` and read with `var(--name, fallback)`. They
  cascade and inherit, so they can be redefined for part of the page or inside
  a media query, and changed from JavaScript.
  :::
  :::accordion-item{label="How would you implement dark mode?" icon="i-lucide-message-circle"}
  Define colours as custom properties on `:root`, redefine them inside
  `@media (prefers-color-scheme: dark)` or under a `.dark` class toggled by the
  user, and write every component against the variables.
  :::
  :::accordion-item{label="Transition against animation?" icon="i-lucide-message-circle"}
  A transition interpolates between two states when a property changes and
  needs a trigger. An animation runs a `@keyframes` sequence on its own, with
  control over iterations, direction and delay.
  :::
  :::accordion-item{label="Which properties are cheap to animate, and why?" icon="i-lucide-message-circle"}
  `transform` and `opacity`, because the browser can apply them without
  recalculating layout or repainting other elements. Animating `width`, `left`
  or `margin` triggers layout on every frame.
  :::
  :::accordion-item{label="What is prefers-reduced-motion?" icon="i-lucide-message-circle"}
  A media feature that is true when the user has asked their operating system
  to reduce motion, often because movement makes them unwell. Respect it by
  removing or shortening transitions and animations inside
  `@media (prefers-reduced-motion: reduce)`.
  :::
::
