A phone browser, left to itself, assumes every page was written for a desktop.
It lays the page out 980 pixels wide and shrinks the result to fit the screen,
so the text is unreadable until you pinch. Responsive design is the set of
techniques that makes one page right at 360 pixels and at 1400.

## Why this matters in a job

Because most students and job seekers open college and job portals on a phone,
and a page that needs pinching is a page they leave. In interviews you will be
asked what a media query is, what "mobile-first" means, and what the viewport
meta tag does. Those three answers cover most of it.

## One notice, three notice boards

The same notice is pinned on a small board outside the lab and a wide one in the
main corridor. On the small board it is one column, large type. On the wide
board it can be two columns. The words are the same; the arrangement changes
with the space. That is responsive design.

The tools:

::feature-list{columns="2"}
  :::feature{icon="i-lucide-smartphone" title="The viewport meta tag"}
  `<meta name="viewport" content="width=device-width, initial-scale=1">` tells
  the phone to lay out at its real width instead of pretending to be 980px.
  Without it, nothing else in this lesson works on a phone.
  :::
  :::feature{icon="i-lucide-ruler" title="Media queries"}
  `@media (min-width: 48rem) { ... }` applies rules only when the condition is
  true. The width where the layout changes is a **breakpoint**.
  :::
  :::feature{icon="i-lucide-arrow-up-right" title="Mobile-first"}
  Write the phone layout as the default, then add `min-width` queries for wider
  screens. The small screen gets the simplest CSS.
  :::
  :::feature{icon="i-lucide-image" title="Fluid sizes"}
  `max-width: 100%` on images, `%` and `fr` widths, `max-width` on content, and
  `clamp()` for type that scales between a minimum and a maximum.
  :::
::

## How it works

A course page, mobile-first:

```html [course.html]
<head>
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <link rel="stylesheet" href="course.css">
</head>
<body>
  <div class="layout">
    <nav class="sidebar">Semester 5 subjects</nav>
    <main>
      <h1>Operating Systems</h1>
      <img src="scheduler.png" alt="A Gantt chart of three processes">
    </main>
  </div>
</body>
```

```css [course.css]
/* Default: phones. One column. */
.layout  { display: grid; gap: 1rem; padding: 1rem; }
img      { max-width: 100%; height: auto; }
h1       { font-size: clamp(1.5rem, 4vw + 1rem, 2.5rem); }
main     { max-width: 70ch; }

/* 768px and wider: sidebar beside the content. */
@media (min-width: 48rem) {
  .layout { grid-template-columns: 14rem 1fr; }
}

/* 1200px and wider: more breathing room. */
@media (min-width: 75rem) {
  .layout { max-width: 72rem; margin-inline: auto; padding: 2rem; }
}
```

```text [Output]
360px phone:   sidebar above content, one column; image scales to 328px wide;
               h1 is 4vw + 1rem = 14.4 + 16 = 30.4px, inside the 24–40px range.
1024px laptop: sidebar 224px on the left, content beside it;
               h1 is 4vw + 1rem = 40.96 + 16 = 56.96px, capped at 2.5rem (40px).
1440px screen: the whole layout is centred and no wider than 1152px.
```

The `clamp(min, preferred, max)` function picks the preferred value but never
below the minimum or above the maximum, so headings grow with the screen and
cannot get silly at either end.

Run it, then drag the preview narrower if your screen allows, or read the
widths from developer tools' device toolbar.

::runner{lang="css"}
```css
.layout { display: grid; gap: 1rem; }
.layout > * { background: #f1f5f9; padding: 1rem; }
@media (min-width: 30rem) {
  .layout { grid-template-columns: 10rem 1fr; }
}

/* --- html --- */
<div class="layout">
  <nav>Semester 5 subjects</nav>
  <main>Operating Systems. Narrower than 480px, the sidebar sits above this.</main>
</div>
```
::

### Common breakpoints

Choose breakpoints where **your content** breaks, not by device names. As a
starting point many teams use about 40rem (640px), 48rem (768px), 64rem (1024px)
and 80rem (1280px). Media queries can also test other things:
`(orientation: landscape)`, `(hover: hover)`, `(prefers-color-scheme: dark)`,
`(prefers-reduced-motion: reduce)`, and `print`.

## Real use case

The hardest ordinary layout problem: a results table with six columns on a 360px
phone. There are three honest answers.

::pros-cons
---
title: Horizontal scroll inside a wrapper
pros:
  - The table stays a table, so it stays accessible and comparable
  - One wrapper with overflow-x, and a sticky first column
cons:
  - Users often do not realise they can scroll sideways
---
::

::pros-cons
---
title: Rows become cards below a breakpoint
pros:
  - Readable on a phone, each student becomes one block
cons:
  - Comparing students becomes hard, which was the point of the table
  - display block on rows can lose table meaning for screen readers
---
::

```css [results-table.css]
.table-wrap { overflow-x: auto; }
.table-wrap th[scope="row"] { position: sticky; left: 0; background: white; }

@media (max-width: 40rem) {
  .results.as-cards thead { display: none; }
  .results.as-cards tr { display: block; border: 1px solid #ddd; margin-bottom: 0.75rem; }
  .results.as-cards td { display: flex; justify-content: space-between; }
  .results.as-cards td::before { content: attr(data-label); font-weight: 600; }
}
```

```html [results-row.html]
<td data-label="Score">78</td>
```

The `data-label` attribute is the part people forget: on a card, a bare "78"
means nothing without "Score:" beside it.

## What confuses people here

**`max-width` against `min-width` queries.** `(min-width: 48rem)` means "48rem
and wider": use it for mobile-first. `(max-width: 48rem)` means "48rem and
narrower": desktop-first. Mixing both in one stylesheet produces widths where
two rules apply, or none.

**Forgetting the viewport tag.** Your media queries will appear not to work on a
real phone, while they work in the desktop browser resized narrow.

**Testing only at device widths.** Layouts break between them. Drag the window
slowly from 1400px to 320px and watch for the width where something overlaps.

## Interview questions

::accordion
  :::accordion-item{label="What is responsive design?" icon="i-lucide-message-circle"}
  One page, one codebase, whose layout adapts to the screen: fluid widths,
  flexible images, and media queries that change the layout at breakpoints.
  :::
  :::accordion-item{label="What does the viewport meta tag do?" icon="i-lucide-message-circle"}
  `width=device-width, initial-scale=1` tells a mobile browser to use the
  device's real width for layout instead of a virtual 980px desktop, and not to
  zoom out. Without it, media queries do not fire as expected on phones.
  :::
  :::accordion-item{label="What is mobile-first?" icon="i-lucide-message-circle"}
  Writing the base CSS for the smallest screen and adding `min-width` media
  queries to enhance for larger ones. Small devices download and apply the
  least CSS, and it forces you to decide what matters most.
  :::
  :::accordion-item{label="Write a media query for screens 768px and wider." icon="i-lucide-message-circle"}
  ```css
  @media (min-width: 768px) {
    .layout { grid-template-columns: 14rem 1fr; }
  }
  ```
  :::
  :::accordion-item{label="How do you make an image responsive?" icon="i-lucide-message-circle"}
  `img { max-width: 100%; height: auto; }` so it never exceeds its container
  and keeps its proportions. For different image files per screen, `srcset` and
  `sizes` on the `<img>`, or the `<picture>` element.
  :::
  :::accordion-item{label="What does clamp() do?" icon="i-lucide-message-circle"}
  `clamp(min, preferred, max)` returns the preferred value limited to the range.
  `font-size: clamp(1.5rem, 4vw + 1rem, 2.5rem)` scales with the viewport but
  stays between 24px and 40px.
  :::
::
