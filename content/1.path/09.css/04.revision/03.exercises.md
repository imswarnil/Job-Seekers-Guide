The interview bank was thirty answers from a chair. These are the problems
themselves: two sets of calculations interviewers put on paper, then six layout
bugs, all of which look correct on the machine they were built on.

::tip
Open developer tools, switch on the device toolbar and set the width to 360px
before the layout section. That is a real phone, and four of the six bugs break
there.
::

## Real use case

Every one of these is a bug from ordinary college software: an admissions list,
a results page, a department dashboard. Fixing them in a practice file now is
cheaper than meeting them in a code review in your first month.

## Set A: specificity

Work out the score of each selector, then say which colour the text ends up.

```html [set-a.html]
<main id="results" class="page">
  <section class="semester current">
    <p class="score topper" data-status="pass">78</p>
  </section>
</main>
```

```css [set-a.css]
/* A1 */ .score                          { color: black; }
/* A2 */ p.score                         { color: grey; }
/* A3 */ .semester .score                { color: blue; }
/* A4 */ .semester.current p             { color: teal; }
/* A5 */ [data-status="pass"].topper     { color: green; }
/* A6 */ #results p                      { color: red; }
/* A7 */ main#results .semester .score   { color: purple; }
/* A8 */ .page .semester .score.topper   { color: orange; }
```

::accordion
  :::accordion-item{label="Answers" icon="i-lucide-check"}
  ```text
  A1 .score                        → 0, 1, 0
  A2 p.score                       → 0, 1, 1
  A3 .semester .score              → 0, 2, 0
  A4 .semester.current p           → 0, 2, 1
  A5 [data-status="pass"].topper   → 0, 2, 0
  A6 #results p                    → 1, 0, 1
  A7 main#results .semester .score → 1, 2, 1   ← wins: purple
  A8 .page .semester .score.topper → 0, 4, 0
  ```

  Two ids tie on the first column (A6 and A7 both have one), so the second
  column decides, and A7 has two classes to A6's none. A8 has four classes and
  still loses to both, because it has no id.

  **Follow-up:** delete A6 and A7. Which wins now? A8 at (0, 4, 0). Delete A8
  too? A4 at (0, 2, 1) beats A3 and A5 at (0, 2, 0).
  :::
::

## Set B: the box model

For each, give the visible width (border edge to border edge) and the total
horizontal space including margins.

| # | CSS |
| --- | --- |
| B1 | `width: 300px; padding: 20px; border: 2px solid; margin: 10px;` |
| B2 | Same as B1 plus `box-sizing: border-box;` |
| B3 | `width: 50%; padding: 0 16px; border: 1px solid;` inside a 600px parent |
| B4 | `display: inline; width: 200px; padding: 8px;` on a span whose text is 90px wide |

::accordion
  :::accordion-item{label="Answers" icon="i-lucide-check"}
  ```text
  B1 content-box: 2 + 20 + 300 + 20 + 2 = 344px visible, 364px with margins
  B2 border-box:  300px visible (content 300 - 44 = 256px), 320px with margins
  B3 50% of 600 = 300px content + 32 padding + 2 border = 334px visible
     (two of these side by side need 668px in a 600px row: they wrap)
  B4 width is ignored on an inline element: 90 + 8 + 8 = 106px
  ```

  B3 is the classic interview trap: two "50%" columns that do not fit. The fix is
  `box-sizing: border-box`, after which each is exactly 300px.
  :::
::

## Set C: six layout bugs

### C1. The status that will not turn red

```css [c1.css]
.student-row .status { color: red; }
#admissions .status  { color: grey; }
```

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  The id rule scores (1, 1, 0) against (0, 2, 0) and wins on the first column.
  The fix is not `!important` and not another id. Lower the winning rule to a
  class:

  ```css
  .admissions .status  { color: grey; }
  .student-row .status { color: red; }
  ```
  :::
::

### C2. The results table that scrolls the whole page

Six columns and a 360px phone. The whole page scrolls sideways.

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  Scroll the table, not the page, and pin the name column:

  ```css
  .table-wrap { overflow-x: auto; }
  .table-wrap th[scope="row"] { position: sticky; left: 0; background: white; }
  ```

  Or restyle rows as cards below 40rem with `data-label` headings (see the
  responsive design lesson). Shrinking the font until it fits is the wrong
  answer: the table becomes unreadable instead of unusable.
  :::
::

### C3. The gap that is not there

```css [c3.css]
.notice  { margin-bottom: 2rem; }
.circular { margin-top: 3rem; }
```

You expected 5rem between them and got 3rem.

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  Margin collapse: adjacent vertical margins merge into the larger. Stop
  fighting it by putting both in a flex column with `gap`:

  ```css
  .notices { display: flex; flex-direction: column; gap: 2rem; }
  ```

  `gap` never collapses and lives in one place.
  :::
::

### C4. Flexbox or Grid

You need the filter bar above a list of placement drives (a row of controls, a
Reset button pushed to the right), and a dashboard of four cards that is 2×2 on
a laptop and one column on a phone.

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  Filter bar: Flexbox, one dimension, one item pushed away.

  ```css
  .filters { display: flex; gap: 1rem; align-items: center; flex-wrap: wrap; }
  .filters .reset { margin-left: auto; }
  ```

  Dashboard: Grid, two dimensions, and no media query needed.

  ```css
  .dashboard { display: grid; gap: 1.5rem; grid-template-columns: repeat(auto-fit, minmax(18rem, 1fr)); }
  ```
  :::
::

### C5. The box that will not centre

A 200px "Hall ticket" box inside a 600px-tall container sits at the top left.

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  ```css
  .container { display: grid; place-items: center; min-height: 600px; }
  ```

  The old answer, `position: absolute; top: 50%; left: 50%;
  transform: translate(-50%, -50%)`, works but takes the box out of the flow,
  so the container stops growing with it and a different bug appears later.
  :::
::

### C6. The layout that breaks at one width

Fine on a laptop, but at about 768px the content slides under the sidebar.

```css [c6.css]
.sidebar { float: left; width: 260px; }
.content { float: left; width: 70%; }
```

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  260px plus 70% exceeds 100% once the container is narrower than about 867px
  (260 is 30% of 867). Fixed and percentage widths in one row always break at
  some width. Let Grid do the arithmetic:

  ```css
  .layout { display: grid; grid-template-columns: 260px minmax(0, 1fr); gap: 2rem; }
  @media (max-width: 48rem) { .layout { grid-template-columns: 1fr; } }
  ```
  :::
::

## Interview questions

::accordion
  :::accordion-item{label="Which of these exercises is most likely to be asked on paper?" icon="i-lucide-message-circle"}
  Set A and Set B. Specificity and box-model width are the two CSS questions
  with a single correct number, which is why interviewers like them. Practise
  until each takes under thirty seconds.
  :::
  :::accordion-item{label="How do you test a layout for mobile without a phone?" icon="i-lucide-message-circle"}
  Developer tools' device toolbar at 360px, 768px and 1400px, then drag the width
  slowly between them to find the width where something breaks. Then check on a
  real phone before shipping, because touch targets and the address bar behave
  differently.
  :::
  :::accordion-item{label="What three habits prevent most of these bugs?" icon="i-lucide-message-circle"}
  Build the 360px layout first. Keep selectors to single classes, with no ids and
  no `!important`. Use `gap`, `fr` and `minmax` instead of margins and mixed
  fixed and percentage widths.
  :::
::
