The glossary gave you the words. These are the questions those words get used
in. CSS questions in a fresher interview are narrow and predictable, and almost
all of them are really checking whether you can debug rather than whether you
can decorate.

::tip
Answer every one out loud before opening it. A CSS answer that includes a
number ("344 pixels") or a line of code sounds like experience. One that
includes only adjectives ("it is more flexible") sounds like a summary you read.
::

## Real use case

In the web round of a walk-in, the CSS part is usually five to ten minutes:
two or three definitions, one specificity or box-model puzzle on paper, and
"how would you centre this" or "how would you make this work on mobile". Every
one of those is below.

## Interview questions

### Applying style and the cascade

::accordion
  :::accordion-item{label="1. What are the ways to add CSS to a page, and which is preferred?" icon="i-lucide-message-circle"}
  External (`<link rel="stylesheet">`), internal (`<style>`), inline (`style`
  attribute). External is preferred: one cached file for every page, and
  content kept separate from presentation.
  :::
  :::accordion-item{label="2. What does 'cascading' mean in CSS?" icon="i-lucide-message-circle"}
  Several rules can apply to one element, and the browser resolves conflicts in
  order: importance (`!important`), then inline against stylesheet, then
  specificity, then source order (later wins).
  :::
  :::accordion-item{label="3. My style is not applying. What do you check?" icon="i-lucide-message-circle"}
  A sequence, and giving a sequence is the answer. Is the rule reaching the
  element (Styles panel in developer tools; if absent, the selector is wrong or
  the file 404s)? Is it struck through (something more specific won)? Is the box
  the size you think (`box-sizing`)? Is the property applicable (`width` on an
  inline element, `z-index` with no `position`)? And not `!important`.
  :::
  :::accordion-item{label="4. Which CSS properties are inherited?" icon="i-lucide-message-circle"}
  Text properties: `color`, `font-*`, `line-height`, `text-align`,
  `visibility`. Not box properties: `margin`, `padding`, `border`,
  `background`, `width`. Force it with `inherit`.
  :::
::

### Selectors and specificity

::accordion
  :::accordion-item{label="5. How is specificity calculated?" icon="i-lucide-message-circle"}
  Three counts: ids; classes, attributes and pseudo-classes; types and
  pseudo-elements. Compared left to right. Inline beats all three; `!important`
  beats inline; a tie goes to the later rule.

  ```text
  #nav .link:hover a  → 1, 2, 1
  ```
  :::
  :::accordion-item{label="6. Which wins: .card .note .text or #panel p?" icon="i-lucide-message-circle"}
  `#panel p` at (1, 0, 1) beats (0, 3, 0). The first column decides, however
  many classes the other has.
  :::
  :::accordion-item{label="7. Why avoid ids in stylesheets?" icon="i-lucide-message-circle"}
  An id rule can only be overridden by another id rule or `!important`, so it
  starts a specificity war. Classes keep every rule at (0, 1, 0) and the cascade
  predictable.
  :::
  :::accordion-item{label="8. div p against div > p?" icon="i-lucide-message-circle"}
  Descendant (any depth) against child (direct children only).
  :::
  :::accordion-item{label="9. Pseudo-class against pseudo-element, with examples." icon="i-lucide-message-circle"}
  `:hover`, `:focus`, `:nth-child(2)` select an element in a state or position.
  `::before`, `::after`, `::first-line` create or style a part of one.
  `::before` needs `content: ""` to appear.
  :::
  :::accordion-item{label="10. How do you select every other row of a table?" icon="i-lucide-message-circle"}
  `tr:nth-child(even)` or `tr:nth-child(2n)`. Odd rows: `odd` or `2n+1`.
  :::
::

### The box model and units

::accordion
  :::accordion-item{label="11. Explain the box model." icon="i-lucide-message-circle"}
  Content, padding, border, margin, outward. By default `width` sets the content
  box, so a 300px element with 20px padding and a 2px border is 344px wide.
  `border-box` makes `width` the whole box, which is why codebases set it
  globally.
  :::
  :::accordion-item{label="12. Width 250px, padding 15px, border 5px, margin 10px, content-box. Total space taken horizontally?" icon="i-lucide-message-circle"}
  Visible box: 250 + 30 + 10 = 290px. Including margins: 310px. With
  `border-box`, visible 250px (content 210px), with margins 270px.
  :::
  :::accordion-item{label="13. What is margin collapse?" icon="i-lucide-message-circle"}
  Adjacent vertical margins of blocks merge into the larger one: 20px and 30px
  give a 30px gap. Never horizontal, never inside flex or grid, and a border or
  padding between them prevents it.
  :::
  :::accordion-item{label="14. em against rem?" icon="i-lucide-message-circle"}
  `em` is relative to the element's font size (the parent's, for
  `font-size`), so it compounds: nested at 1.2em gives 19.2, 23.04, 27.65px.
  `rem` is relative to the root, so 1.2rem is 19.2px at every level.
  :::
  :::accordion-item{label="15. px, %, vw: when do you use each?" icon="i-lucide-message-circle"}
  `px` for borders and hairlines. `%` for widths relative to a parent. `vw` and
  `vh` for sizes relative to the screen, such as a hero at `min-height: 60vh`.
  `rem` for type and most spacing.
  :::
::

### Display and position

::accordion
  :::accordion-item{label="16. Block, inline, inline-block?" icon="i-lucide-message-circle"}
  Block: new line, full width, respects width and height. Inline: flows in text,
  ignores width and height. Inline-block: flows in text but respects width,
  height and vertical margins.
  :::
  :::accordion-item{label="17. display: none against visibility: hidden?" icon="i-lucide-message-circle"}
  `none` removes it from layout and from screen readers. `hidden` keeps its
  space and hides it. `opacity: 0` keeps its space and still takes clicks.
  :::
  :::accordion-item{label="18. relative, absolute, fixed, sticky?" icon="i-lucide-message-circle"}
  Relative: offset from its own spot, space kept. Absolute: out of flow, against
  the nearest positioned ancestor. Fixed: against the viewport, does not scroll.
  Sticky: scrolls until an offset, then sticks while its parent is visible.
  :::
  :::accordion-item{label="19. Why is my z-index not working?" icon="i-lucide-message-circle"}
  The element is not positioned, or it sits inside a stacking context (an
  ancestor with `z-index`, `opacity` below 1 or `transform`) that is below the
  other element. Raise the ancestor, not the child.
  :::
::

### Flexbox and Grid

::accordion
  :::accordion-item{label="20. How do you centre a div?" icon="i-lucide-message-circle"}
  `display: flex; justify-content: center; align-items: center;` on the parent,
  with a height, or `display: grid; place-items: center;`. Horizontal only, for
  a block with a width: `margin-inline: auto`.
  :::
  :::accordion-item{label="21. justify-content against align-items?" icon="i-lucide-message-circle"}
  Main axis against cross axis. In a row: horizontal against vertical. With
  `flex-direction: column` they swap.
  :::
  :::accordion-item{label="22. What does flex: 1 mean, and flex: 0 0 200px?" icon="i-lucide-message-circle"}
  `flex: 1` is grow 1, shrink 1, basis 0%: an equal share of the space.
  `flex: 0 0 200px` is fixed at 200px, never growing or shrinking.
  :::
  :::accordion-item{label="23. Flexbox or Grid?" icon="i-lucide-message-circle"}
  One dimension against two. Flex for a row or column where the content decides
  sizes; Grid when you define rows and columns together. Usually both: Grid for
  the page, Flex inside each part.
  :::
  :::accordion-item{label="24. What is the fr unit, and how do you make a grid responsive without media queries?" icon="i-lucide-message-circle"}
  A fraction of the free space. `repeat(auto-fill, minmax(16rem, 1fr))` gives as
  many columns as fit at 16rem minimum.
  :::
::

### Responsive design and theming

::accordion
  :::accordion-item{label="25. What is a media query? Write one." icon="i-lucide-message-circle"}
  A condition under which rules apply.

  ```css
  @media (min-width: 768px) {
    .layout { grid-template-columns: 14rem 1fr; }
  }
  ```
  :::
  :::accordion-item{label="26. What is mobile-first, and why?" icon="i-lucide-message-circle"}
  Base CSS for the smallest screen, `min-width` queries to add for larger ones.
  Phones apply the least CSS, and it forces a decision about what matters.
  :::
  :::accordion-item{label="27. What does the viewport meta tag do?" icon="i-lucide-message-circle"}
  `<meta name="viewport" content="width=device-width, initial-scale=1">` makes a
  phone lay out at its real width instead of a virtual 980px, so media queries
  work.
  :::
  :::accordion-item{label="28. How would you make a six-column table work on a phone?" icon="i-lucide-message-circle"}
  No single answer, which is why it is asked. Scroll the table inside a wrapper
  with `overflow-x: auto` and a sticky first column; or restyle rows as cards
  below a breakpoint, repeating headings with `data-label` and `::before`; or
  show fewer columns with a details view. Name each one's cost, and that the card
  version needs testing with a screen reader.
  :::
  :::accordion-item{label="29. CSS variables against Sass variables?" icon="i-lucide-message-circle"}
  Sass variables are replaced at compile time and cannot change in the browser.
  CSS custom properties live in the browser, cascade, can change inside a media
  query or class, and can be set from JavaScript. That is what makes dark mode
  with one set of component rules possible.
  :::
  :::accordion-item{label="30. Transition against animation?" icon="i-lucide-message-circle"}
  A transition runs between two states when a property changes. An animation
  runs a `@keyframes` sequence on its own and can loop. Prefer animating
  `transform` and `opacity`, and respect `prefers-reduced-motion`.
  :::
::
