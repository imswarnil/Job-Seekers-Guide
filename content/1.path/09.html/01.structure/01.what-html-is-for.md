Everything you have built lives in a terminal and the registrar is not going to
learn one. This is the first of four tracks about the part a person can actually
open, and it starts with the thing most people get wrong about HTML.

## Why this matters in a job

Because HTML is treated as the trivial part and is the layer that decides whether
your application works for somebody using a screen reader, whether Google can
read it, and whether your JavaScript can find anything. Getting it wrong is
invisible to you and total for somebody else.

## HTML describes meaning, not appearance

```html [wrong.html]
<div class="title">Applications</div>
<div class="row">
  <div class="cell">Anita Rao</div>
  <div class="cell">78</div>
</div>
<div class="button" onclick="shortlist()">Shortlist</div>
```

```html [right.html]
<h1>Applications</h1>
<table>
  <caption>2026 intake, computer science</caption>
  <thead>
    <tr><th scope="col">Applicant</th><th scope="col">Score</th></tr>
  </thead>
  <tbody>
    <tr><td>Anita Rao</td><td>78</td></tr>
  </tbody>
</table>
<button type="button">Shortlist</button>
```

Both can be made to look identical. Everything else about them differs.

::feature-list{columns="2"}
  :::feature{icon="i-lucide-accessibility" title="A screen reader"}
  Announces "table, 2 columns, 412 rows" and lets the user jump between rows and
  hear the column heading with each cell. The `div` version is read as a
  continuous stream of words with no structure at all.
  :::
  :::feature{icon="i-lucide-keyboard" title="A keyboard"}
  `<button>` is focusable, reachable with Tab, and activates on Enter **and**
  Space. `<div class="button">` is none of those, so the feature simply does not
  exist for somebody who cannot use a mouse.
  :::
  :::feature{icon="i-lucide-search" title="A search engine"}
  Reads `<h1>` as the page's subject. A `div` with a class called `title` means
  nothing to it, because a class name is your private vocabulary.
  :::
  :::feature{icon="i-lucide-code" title="Your own code"}
  `document.querySelectorAll('tbody tr')` works on any correct table forever.
  `.row` works until somebody renames the class.
  :::
::

::pull-quote
The right element is not a style choice. It is the difference between a feature
existing and not existing for a person using a keyboard or a screen reader.
::

## The elements that carry meaning

```html [page.html]
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Applications · University Admissions</title>
  </head>
  <body>
    <header>          <!-- the site header: logo, nav -->
      <nav aria-label="Main">…</nav>
    </header>

    <main>            <!-- the unique content. Exactly ONE per page. -->
      <h1>Applications</h1>

      <section aria-labelledby="filters-heading">
        <h2 id="filters-heading">Filters</h2>
        …
      </section>

      <article>       <!-- something that would make sense on its own -->
        <h2>Anita Rao</h2>
        …
      </article>
    </main>

    <aside>…</aside>  <!-- related, but not the point of the page -->
    <footer>…</footer>
  </body>
</html>
```

Those landmarks are how a screen reader user navigates: "skip to main content",
"next landmark". A page built of `div`s has no landmarks, so they read it top to
bottom, every time, including the navigation.

::warning{icon="i-lucide-alert-triangle"}
`lang="en"` on `<html>` is one attribute and it decides which voice a screen
reader uses. Without it, an English page can be read with Hindi pronunciation
rules, which is unintelligible. It is the cheapest accessibility fix in
existence and it is missing from most pages.
::

## Headings are an outline, not sizes

```html [wrong.html]
<h1>Applications</h1>
<h4>Filters</h4>          <!-- chosen because h4 looked the right size -->
<h2>Results</h2>
```

```html [right.html]
<h1>Applications</h1>
<h2>Filters</h2>
<h2>Results</h2>
<h3>Computer science</h3>
```

A screen reader user can list every heading on the page and jump between them,
which is how they skim. Skipping a level breaks the outline, and choosing a level
for its font size is what causes it. **Size is CSS. Level is meaning.**

## Images, links and buttons

```html [details.html]
<!-- alt describes the PURPOSE, not the picture -->
<img src="/logo.svg" alt="University of Bhopal">
<img src="/divider.svg" alt="">          <!-- decorative: EMPTY alt, not missing -->

<!-- A link GOES somewhere. A button DOES something. -->
<a href="/applications/9001">View application</a>
<button type="button">Shortlist</button>

<!-- Never this. It is a link that goes nowhere pretending to be a button. -->
<a href="#" onclick="shortlist()">Shortlist</a>
```

::tip
`alt=""` on a decorative image is correct and different from omitting `alt`
entirely. Empty means "skip this, it carries no information". Missing means the
screen reader reads the file name, so a user hears "divider dash final dash two
dot s v g".
::

The link-or-button distinction has a practical test: if middle-clicking it to
open in a new tab would make sense, it is a link. If not, it is a button.

## Watch the difference

```html [table.html]
<table>
  <caption>2026 applications, computer science</caption>
  <thead>
    <tr>
      <th scope="col">Applicant</th>
      <th scope="col">Score</th>
      <th scope="col">Status</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Anita Rao</th>
      <td>78</td>
      <td>Shortlisted</td>
    </tr>
  </tbody>
</table>
```

```text [What a screen reader announces on the middle cell]
"2026 applications, computer science, table, 3 columns, 412 rows.
 Row 1, Anita Rao. Score, 78."
```

It says **"Score"** before "78", because `scope="col"` told it which heading
governs that cell. In a `div` table the user hears "78" with no idea what it is,
and that is the whole of why semantic HTML matters.

## What you can do now

You can build a page whose structure carries meaning, which makes it work for a
keyboard, a screen reader and a search engine without any extra work.

## Your turn

Rewrite this. There are six problems.

```html [fix-me.html]
<div class="page">
  <div class="header">University Admissions</div>
  <div class="nav">
    <span onclick="go('/applications')">Applications</span>
  </div>
  <div class="content">
    <div class="h1">2026 Intake</div>
    <div class="h3">Shortlisted</div>
    <img src="/chart.png">
    <div class="list">
      <div>Anita Rao - 78</div>
      <div>Vikram Shah - 64</div>
    </div>
    <div class="btn" onclick="exportCsv()">Export</div>
  </div>
</div>
```

::accordion
  :::accordion-item{label="The six, and the rewrite" icon="i-lucide-check"}
  1. No landmarks: `header`, `nav`, `main` are all `div`s, so there is nothing
     to navigate by.
  2. The nav item is a `span` with a click handler: not focusable, not
     keyboard-operable, not a link.
  3. Headings are classes, so the outline does not exist. And `h1` to `h3` skips
     a level.
  4. The image has no `alt`, so its file name is read aloud.
  5. A list of items is a set of `div`s rather than a list, so the count is not
     announced.
  6. The button is a `div`, so it cannot be reached or activated by keyboard.

  ```html
  <body>
    <header>
      <p>University Admissions</p>
      <nav aria-label="Main">
        <a href="/applications">Applications</a>
      </nav>
    </header>

    <main>
      <h1>2026 Intake</h1>
      <h2>Shortlisted</h2>

      <img src="/chart.png"
           alt="Applications per programme: CSE 412, ECE 288, Mechanical 201">

      <ul>
        <li>Anita Rao: 78</li>
        <li>Vikram Shah: 64</li>
      </ul>

      <button type="button">Export</button>
    </main>
  </body>
  ```

  **The `alt` is the interesting one.** "Chart of applications" describes the
  picture and is useless. The alt text has to carry the **information** the image
  carries, which for a chart means the numbers. If the numbers are also in a
  table on the page, then `alt=""` is correct and the table is the accessible
  version.
  :::
::

## The interview question this answers

**"Why use semantic HTML?"**

Four audiences, and naming all four is the answer: a screen reader gets structure
and landmarks to navigate by, a keyboard gets focus and activation for free, a
search engine gets meaning, and your own code gets selectors that do not break
when somebody renames a class.

Then one concrete example. `<div class="button">` cannot be reached with Tab and
does not activate on Enter, so the feature does not exist for somebody who cannot
use a mouse. That is a sentence about a person rather than about standards, and
it is what makes the answer land.
