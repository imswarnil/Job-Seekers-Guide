A String can never change, so every `+` in a loop builds a brand-new String and
copies everything written so far into it. Building a report of forty thousand
lines that way is quadratic without looking like it, and the fix is a class
built for exactly this job: `StringBuilder`.

## Why this matters in a job

Text is most of what business code produces: CSV exports, emails, log lines,
SQL, report rows. Building it the wrong way inside a loop is one of the
performance bugs code reviewers look for first, because it is invisible at 100
rows and takes seconds at 40,000.

In interviews, "String, StringBuilder or StringBuffer?" is asked in almost every
fresher Java round, usually followed by "reverse a string", "check a
palindrome" or "count the vowels", which are all one or two String methods
once you know them. The second half of this lesson is that toolkit.

## A mutable buffer instead of a new String each time

Imagine writing a merit list by hand. The String way: every time you add a name,
you take a fresh sheet of paper, copy out every name so far, then add the new
one. The StringBuilder way: one notebook, and you keep writing on the next
line. At the end you photocopy the notebook once (`toString()`).

`StringBuilder` is a **mutable** sequence of characters: its methods change the
object itself instead of returning a new one. Inside it is a character array
with spare room (the **capacity**, 16 characters by default). When it fills up,
it grows to about double, so appending is cheap on average.

## Measure the quadratic

```java [BuildReport.java]
public class BuildReport {
  public static void main(String[] args) {
    for (int n : new int[] {1_000, 10_000, 40_000}) {
      long start = System.nanoTime();
      String report = "";
      for (int i = 0; i < n; i++) {
        report += "2026CSE" + i + "," + (i % 100) + "\n";
      }
      long concatMs = (System.nanoTime() - start) / 1_000_000;

      start = System.nanoTime();
      StringBuilder sb = new StringBuilder();
      for (int i = 0; i < n; i++) {
        sb.append("2026CSE").append(i).append(',').append(i % 100).append('\n');
      }
      String built = sb.toString();
      long builderMs = (System.nanoTime() - start) / 1_000_000;

      System.out.printf("%,7d results: concat %,6d ms | builder %3d ms | same text: %b%n",
          n, concatMs, builderMs, report.equals(built));
    }
  }
}
```

```text [Output (my laptop; your timings will differ)]
  1,000 results: concat     14 ms | builder   0 ms | same text: true
 10,000 results: concat     67 ms | builder   0 ms | same text: true
 40,000 results: concat  1,297 ms | builder   0 ms | same text: true
```

Four times the rows (10,000 to 40,000), nearly twenty times the time for the
`+` version, and the builder does not register. Both produce identical text.
**Quadratic** means the work grows with the square of the input: each `+=`
copies everything so far, so the total copying is 1 + 2 + 3 + … + n.

::note
A single `+` outside a loop is fine. The compiler turns
`"Roll " + roll + ": " + marks` into efficient code for you. What it cannot do is
carry one builder **across loop iterations**, because each iteration is a
separate statement. The rule is narrow: building text in a loop means
`StringBuilder`.
::

## Syntax: the StringBuilder methods

```java [BuilderMethods.java]
public class BuilderMethods {
  public static void main(String[] args) {
    StringBuilder sb = new StringBuilder("Anita Rao");
    sb.append(", CSE");
    System.out.println("append:  " + sb);
    sb.insert(0, "Ms ");
    System.out.println("insert:  " + sb);
    sb.replace(3, 8, "ANITA");
    System.out.println("replace: " + sb);
    sb.delete(0, 3);
    System.out.println("delete:  " + sb);
    sb.setCharAt(0, 'a');
    System.out.println("setChar: " + sb);
    System.out.println("reverse: " + new StringBuilder("MALAYALAM").reverse());
    System.out.println("length " + sb.length() + ", capacity " + new StringBuilder().capacity());

    StringBuilder a = new StringBuilder("CSE");
    StringBuilder b = new StringBuilder("CSE");
    System.out.println("a.equals(b): " + a.equals(b));
    System.out.println("a.toString().equals(b.toString()): " + a.toString().equals(b.toString()));
    System.out.println("a.compareTo(b): " + a.compareTo(b));
  }
}
```

```text [Output]
append:  Anita Rao, CSE
insert:  Ms Anita Rao, CSE
replace: Ms ANITA Rao, CSE
delete:  ANITA Rao, CSE
setChar: aNITA Rao, CSE
reverse: MALAYALAM
length 14, capacity 16
a.equals(b): false
a.toString().equals(b.toString()): true
a.compareTo(b): 0
```

Every method changed `sb` itself; nothing had to be reassigned. `append`
returns the same builder, which is why calls can be chained:
`sb.append(roll).append(',').append(marks)`. Ranges such as `replace(3, 8, …)`
and `delete(0, 3)` include the start index and exclude the end.

::warning{icon="i-lucide-alert-triangle"}
`StringBuilder` does **not** override `equals`. Two builders with the same text
are not `equals` (the output above says `false`), because `equals` falls back to
comparing addresses. Compare `toString()` results, or use `compareTo`, which
returns 0 for equal contents (Java 11 and later).
::

## StringBuilder against StringBuffer

`StringBuffer` is the original, from Java 1.0. It has the same methods, and
every one of them is **synchronised**: only one thread (one independent path of
execution in a program) can be inside it at a time, which makes it safe to share
between threads. `StringBuilder` arrived in Java 5 as the same class without the
locking.

::compare{caption="Three types for text. Choose by whether it changes and who shares it."}
  :::compare-side{label="String" verdict="neutral"}
  Immutable, pooled, thread-safe because nobody can change it. Use for any
  value you store, compare or pass around.
  :::
  :::compare-side{label="StringBuilder" verdict="right"}
  Mutable, not synchronised. Use for building text, inside one method. This is
  the one you want almost every time.
  :::
::

| | `String` | `StringBuilder` | `StringBuffer` |
| --- | --- | --- | --- |
| Mutable | No | Yes | Yes |
| Thread-safe | Yes (immutable) | No | Yes (synchronised) |
| Speed for building | Slow in loops | Fastest | Close to StringBuilder in one thread |
| Since | 1.0 | 5 | 1.0 |
| `equals` compares content | Yes | No | No |

The textbook says StringBuffer is "slower because of synchronisation". Measured
honestly, in one thread, the difference is small:

```java [BufferVsBuilder.java]
public class BufferVsBuilder {
  public static void main(String[] args) {
    int n = 5_000_000;
    for (int round = 1; round <= 3; round++) {
      long start = System.nanoTime();
      StringBuilder builder = new StringBuilder();
      for (int i = 0; i < n; i++) builder.append('x');
      long builderMs = (System.nanoTime() - start) / 1_000_000;

      start = System.nanoTime();
      StringBuffer buffer = new StringBuffer();
      for (int i = 0; i < n; i++) buffer.append('x');
      long bufferMs = (System.nanoTime() - start) / 1_000_000;

      System.out.printf("round %d: StringBuilder %3d ms | StringBuffer %3d ms%n", round, builderMs, bufferMs);
    }
  }
}
```

```text [Output (my laptop; your timings will differ)]
round 1: StringBuilder  10 ms | StringBuffer  17 ms
round 2: StringBuilder  12 ms | StringBuffer   5 ms
round 3: StringBuilder   6 ms | StringBuffer   6 ms
```

The JVM notices the lock is never contested and largely removes its cost once
the code warms up. So the honest answer is: use `StringBuilder` because nothing
shares it, not because `StringBuffer` is dramatically slow. And a builder being
appended to by several threads at once is a design problem; locking each
`append` does not make the resulting order meaningful.

## The String methods you will use every day

```java [StringMethods.java]
import java.util.Arrays;

public class StringMethods {
  public static void main(String[] args) {
    String roll = "  2026CSE0184  ";
    String clean = roll.strip();

    System.out.println("length()          " + clean.length());
    System.out.println("charAt(4)         " + clean.charAt(4));
    System.out.println("substring(0, 4)   " + clean.substring(0, 4));
    System.out.println("substring(7)      " + clean.substring(7));
    System.out.println("indexOf(\"CSE\")    " + clean.indexOf("CSE"));
    System.out.println("indexOf(\"ECE\")    " + clean.indexOf("ECE"));
    System.out.println("lastIndexOf('0')  " + clean.lastIndexOf('0'));
    System.out.println("contains(\"CSE\")   " + clean.contains("CSE"));
    System.out.println("startsWith(\"2026\")" + " " + clean.startsWith("2026"));
    System.out.println("endsWith(\"0184\")  " + clean.endsWith("0184"));
    System.out.println("replace           " + clean.replace("CSE", "ECE"));
    System.out.println("toLowerCase()     " + clean.toLowerCase());
    System.out.println("[" + roll.trim() + "] [" + roll.strip() + "]");
    System.out.println("isEmpty(\"   \")    " + "   ".isEmpty());
    System.out.println("isBlank(\"   \")    " + "   ".isBlank());

    String csvRow = "2026CSE0184,Anita Rao,CSE,78";
    String[] cells = csvRow.split(",");
    System.out.println("split             " + Arrays.toString(cells) + " (" + cells.length + " cells)");
    System.out.println("split(\"\\\\.\")      " + Arrays.toString("8.4.2".split("\\.")));
    System.out.println("split(\".\")        " + Arrays.toString("8.4.2".split(".")));
    System.out.println("join              " + String.join(" | ", "CSE", "ECE", "MECH"));
    System.out.println("format            " + String.format("%-12s|%5d|%6.2f", "Anita Rao", 78, 81.666));
    System.out.println("formatted         " + "%s scored %d".formatted("Vikram", 64));
    System.out.println("repeat            " + "-".repeat(10));
    System.out.println("equalsIgnoreCase  " + "cse".equalsIgnoreCase("CSE"));
    System.out.println("compareTo         " + "Anita".compareTo("Vikram") + " " + "Vikram".compareTo("Anita") + " " + "Anita".compareTo("Anita"));
    System.out.println("compareTo case    " + "anita".compareTo("Anita"));
    System.out.println("vowels            " + "Anita Rao".toLowerCase().chars().filter(ch -> "aeiou".indexOf(ch) >= 0).count());
    System.out.println("toCharArray       " + Arrays.toString("CSE".toCharArray()));
    System.out.println("valueOf           " + (String.valueOf(78) + 1));
  }
}
```


The ones that need a sentence each:

- **`substring(begin, end)`** includes `begin` and excludes `end`, so its length
  is `end - begin`. `substring(7)` runs to the end.
- **`indexOf`** returns `-1` when the text is not there. Always check for `-1`
  before using the result as a position.
- **`trim` against `strip`**: both remove surrounding whitespace. `trim()` only
  knows characters up to the ordinary space; `strip()` (Java 11) understands
  Unicode whitespace too, such as the non-breaking space pasted from a
  spreadsheet. Prefer `strip()` in new code.
- **`isEmpty` against `isBlank`**: `isEmpty` is true only for `""`. `isBlank`
  (Java 11) is also true for text that is all whitespace. A form field with three
  spaces is blank, not empty.
- **`split` takes a regular expression** (a pattern language), not plain text.
  `.` means "any character", so `split(".")` splits on everything and returns an
  empty array. Escape it: `split("\\.")`.
- **`compareTo`** returns a negative number, zero or a positive number: less,
  equal or greater in dictionary order. `'A'` (65) minus `'V'` (86) is -21.
  Lowercase letters sort after uppercase ones (`'a' - 'A'` is 32), so use
  `compareToIgnoreCase` for names.
- **`chars()`** gives the characters as a stream of `int`s; the Java 8 chapter
  explains streams properly. `String.valueOf` turns any value into a String.

## Real use case

A marks report with aligned columns, built with one StringBuilder and
`String.format`. This is the shape of every console report and plain-text email
a back-office job produces:

```java [Report.java]
public class Report {
  public static void main(String[] args) {
    String[] names = {"Anita Rao", "Vikram Shah", "Farhan Qureshi"};
    int[] marks = {78, 64, 91};

    StringBuilder report = new StringBuilder();
    report.append(String.format("%-16s %5s %7s%n", "Student", "Marks", "Result"));
    report.append("-".repeat(30)).append('\n');
    for (int i = 0; i < names.length; i++) {
      String result = marks[i] >= 75 ? "First" : "Second";
      report.append(String.format("%-16s %5d %7s%n", names[i], marks[i], result));
    }
    System.out.print(report);
  }
}
```

```text [Output]
Student          Marks  Result
------------------------------
Anita Rao           78   First
Vikram Shah         64  Second
Farhan Qureshi      91   First
```

`%-16s` is left-aligned in 16 characters, `%5d` right-aligned in 5, and `%n` a
line break that is correct on every operating system.

And the interview classic, a palindrome check (a word that reads the same
backwards), in one line using `reverse()`:

```java [Palindrome.java]
public class Palindrome {
  public static void main(String[] args) {
    String[] names = {"Malayalam", "Anita", "Nitin"};
    for (String name : names) {
      String lower = name.toLowerCase();
      boolean palindrome = new StringBuilder(lower).reverse().toString().equals(lower);
      System.out.println(name + " -> " + palindrome);
    }
  }
}
```

```text [Output]
Malayalam -> true
Anita -> false
Nitin -> true
```

::tip
In a written test they may say "without using library methods". Then compare
characters from both ends moving inwards, with `charAt(i)` and
`charAt(length - 1 - i)`, stopping in the middle. Know both versions.
::

## What confuses people here

**Indexes past the end throw.** `substring`, `charAt` and `deleteCharAt` all
check their bounds:

```java [SubstringTrap.java]
public class SubstringTrap {
  public static void main(String[] args) {
    String roll = "2026CSE0184";
    System.out.println(roll.substring(4, 7));
    System.out.println(roll.substring(4, 20));
  }
}
```

```text [Output]
CSE
Exception in thread "main" java.lang.StringIndexOutOfBoundsException: Range [4, 20) out of bounds for length 11
	at java.base/jdk.internal.util.Preconditions$1.apply(Preconditions.java:55)
	...
	at java.base/java.lang.String.substring(String.java:2823)
	at SubstringTrap.main(SubstringTrap.java:5)
```

(The `...` stands for eight more lines inside the JDK, trimmed here.) The
message says it plainly: `[4, 20)` is "from 4, up to but not including 20", and
the String has 11 characters.

- **Forgetting that String methods return a new String.** `clean.replace("CSE",
  "ECE");` on its own line changes nothing. StringBuilder methods are the
  opposite: they change the builder.
- **`split` with a dot or a pipe.** Both are special in regular expressions:
  `split("\\.")`, `split("\\|")`.
- **`+` inside `append`.** `sb.append(roll + "," + marks)` builds a temporary
  String first. Chain `append` calls instead.
- **Comparing builders with `equals`.** It is address comparison. Use
  `toString().equals(...)`.

## Interview questions

::accordion
  :::accordion-item{label="String, StringBuilder or StringBuffer: which and why?"}
  `String` for values, because it is immutable. `StringBuilder` for building text,
  because it is mutable and not synchronised. `StringBuffer` only if one builder
  must be shared across threads, which is rare. Building 40,000 lines with `+=`
  took 1,297 ms against 0 ms for StringBuilder in the measurement above.
  :::

  :::accordion-item{label="Why is concatenation in a loop slow?"}
  Each `+=` creates a new String and copies everything so far into it, so n
  appends copy about n²/2 characters in total. `StringBuilder` appends into a
  growing internal array and copies only when it resizes.
  :::

  :::accordion-item{label="Reverse a String."}
  `new StringBuilder("MALAYALAM").reverse().toString()`. `String` has no
  `reverse()` of its own because it is immutable. Without library help, swap
  characters from both ends of a `char[]` from `toCharArray()`.
  :::

  :::accordion-item{label="Difference between isEmpty() and isBlank(), and trim() and strip()?"}
  `"   ".isEmpty()` is `false`; `"   ".isBlank()` is `true`. `trim()` removes
  characters up to the ordinary space; `strip()` removes all Unicode whitespace.
  `isBlank` and `strip` arrived in Java 11.
  :::

  :::accordion-item{label="Why does splitting on a dot return an empty array?"}
  `split` takes a regular expression, and `.` matches any character, so every
  character is a separator and the trailing empty pieces are removed, leaving
  `[]`. `"8.4.2".split("\\.")` gives `[8, 4, 2]`.
  :::
::
