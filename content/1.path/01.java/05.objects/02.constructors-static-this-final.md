You have written a constructor and used `this.code = code` without a full
explanation, and `main` has been `static` since your first program. These four
keywords (`static`, `this`, `final`, and the constructor itself) produce half
the questions in a core Java round, so this lesson takes them one at a time.

## Why this matters in a job

In a real codebase, `static final` is how every constant is declared,
constructors are where validation lives, and a mutable `static` field is one of
the first things a senior reviewer flags. In interviews: "why is main static?",
"what is a static block?", "difference between final, finally and finalize?",
"can a constructor be final?", and "what is constructor chaining?" come up at
almost every walk-in I sat.

## One per class, or one per object

Go back to the admissions form. Some things are printed on the form itself and
are the same on every copy: the college name at the top. Other things are
filled in by each applicant: their own name. In Java:

- a **static** member (field or method) belongs to the **class**. There is one
  copy, shared by every object, and it exists even when there are no objects.
- an **instance** member belongs to **each object**. Every object has its own
  copy.

## How it works

### static fields and methods

```java [Enrolment.java]
public class Enrolment {
  public static void main(String[] args) {
    System.out.println("Before any student: " + Student.count);
    Student a = new Student("Anita Rao");
    Student b = new Student("Vikram Shah");
    Student c = new Student("Priya Nair");
    System.out.println(a.rollNumber + " " + a.name);
    System.out.println(c.rollNumber + " " + c.name);
    System.out.println("Total: " + Student.count);
    System.out.println("College: " + Student.COLLEGE);
    System.out.println(Student.nextRollPreview());
  }
}

class Student {
  static final String COLLEGE = "LNCT Bhopal";  // one constant, shared
  static int count = 0;                         // one counter, shared

  final String rollNumber;                      // one per object
  final String name;

  Student(String name) {
    count++;
    this.rollNumber = "CSE" + (1800 + count);
    this.name = name;
  }

  static String nextRollPreview() {             // belongs to the class
    return "Next roll number: CSE" + (1800 + count + 1);
  }
}
```

```bash [Terminal]
javac Enrolment.java && java Enrolment
```

```text [Output]
Before any student: 0
CSE1801 Anita Rao
CSE1803 Priya Nair
Total: 3
College: LNCT Bhopal
Next roll number: CSE1804
```

`Student.count` was readable before any student existed, because it belongs to
the class. Call static members on the class name (`Student.count`), not on an
object, so the reader can see they are shared.

A static method has no object, so it has no `this` and cannot touch instance
fields directly:

```java [StaticContext.java]
public class StaticContext {
  String batch = "2018";

  public static void main(String[] args) {
    System.out.println(batch);
  }
}
```

```text [Output]
StaticContext.java:5: error: non-static variable batch cannot be referenced from a static context
    System.out.println(batch);
                       ^
1 error
```

Every beginner meets this error in their first week of objects. The fix is to
create an object and go through it: `new StaticContext().batch`.

That is also **why `main` is static**. The JVM has to call `main` before any
object of your class exists. If `main` were an instance method, the JVM would
need an object first, and would not know which constructor to call or with what.

### The order Java builds things in

A **static block** (`static { ... }`) runs once, when the class is first loaded.
An **instance initialiser block** (`{ ... }` with no keyword) runs before the
constructor body every time an object is made.

```java [InitOrder.java]
public class InitOrder {
  public static void main(String[] args) {
    System.out.println("main starts");
    new Department("CSE");
    new Department("ECE");
  }
}

class Department {
  static int created;
  String code;

  static {
    System.out.println("1. static block: runs once, when the class is loaded");
  }

  {
    System.out.println("2. instance block: runs before every constructor");
  }

  Department(String code) {
    this.code = code;
    created++;
    System.out.println("3. constructor: " + code + " (department #" + created + ")");
  }
}
```

```text [Output]
main starts
1. static block: runs once, when the class is loaded
2. instance block: runs before every constructor
3. constructor: CSE (department #1)
2. instance block: runs before every constructor
3. constructor: ECE (department #2)
```

`Department` was loaded lazily, the first time the program used it, which is
why "main starts" printed first. Static blocks are used for one-time set-up,
such as loading a configuration file or a database driver.

### this, and constructor chaining

`this` is a reference to the current object. It has three everyday uses:

- `this.code = code`: tell a field apart from a parameter with the same name;
- `this(...)`: call another constructor of the same class (**constructor
  chaining**);
- `return this`: hand back the same object so calls can be chained.

```java [Chaining.java]
public class Chaining {
  public static void main(String[] args) {
    Course a = new Course("CS-201", "Core Java", 4);
    Course b = new Course("CS-110", "Communication Skills");
    System.out.println(a);
    System.out.println(b);
  }
}

class Course {
  final String code;
  final String title;
  final int credits;

  Course(String code, String title) {
    this(code, title, 3);                  // default 3 credits; must be the first line
  }

  Course(String code, String title, int credits) {
    if (credits < 1 || credits > 6) {
      throw new IllegalArgumentException("Credits must be 1 to 6, got " + credits);
    }
    this.code = code;
    this.title = title;
    this.credits = credits;
  }

  public String toString() {
    return code + " " + title + " (" + credits + ")";
  }
}
```

```text [Output]
CS-201 Core Java (4)
CS-110 Communication Skills (3)
```

One constructor does the real work and validation; the others delegate to it.
With two copies of the validation, they always drift apart. `this(...)` must be
the **first statement**; anything before it is `error: call to this must be
first statement in constructor`.

### final, three meanings

`final` means "cannot be changed after it is set", and what "changed" means
depends on what it is attached to.

::feature-list{columns="3"}
  :::feature{icon="i-lucide-lock" title="final variable"}
  Assigned once. A `final` field with no value (a **blank final**) must be
  assigned in every constructor.
  :::
  :::feature{icon="i-lucide-shield" title="final method"}
  Cannot be overridden by a subclass (overriding is two lessons away).
  :::
  :::feature{icon="i-lucide-ban" title="final class"}
  Cannot be extended at all. `String` is a final class.
  :::
::

```java [FinalErrors.java]
public class FinalErrors {
  public static void main(String[] args) {
    final int maxMarks = 100;
    maxMarks = 120;
    final int[] marks = {78, 64};
    marks = new int[] {1, 2};
  }
}

final class Grade { }
class SpecialGrade extends Grade { }

class Exam {
  final int passMark() { return 40; }
}
class ReExam extends Exam {
  int passMark() { return 35; }
}
```

```text [Output]
FinalErrors.java:11: error: cannot inherit from final Grade
class SpecialGrade extends Grade { }
                           ^
FinalErrors.java:4: error: cannot assign a value to final variable maxMarks
    maxMarks = 120;
    ^
FinalErrors.java:6: error: cannot assign a value to final variable marks
    marks = new int[] {1, 2};
    ^
FinalErrors.java:17: error: passMark() in ReExam cannot override passMark() in Exam
  int passMark() { return 35; }
      ^
  overridden method is final
4 errors
```

## Real use case

Two patterns you will see in every codebase. First, constants:
`static final` plus UPPER_SNAKE_CASE.

```java
public class FeeRules {
  public static final long LATE_FINE_PAISE = 10_000;    // ₹100
  public static final int  MIN_ATTENDANCE_PCT = 75;
  private FeeRules() { }        // private constructor: nobody creates a FeeRules
}
```

Second, `return this` for readable set-up code, often called a **fluent**
style. Builders in libraries you will use at work (HTTP clients, test data
builders) look like this:

```java [FluentThis.java]
public class FluentThis {
  public static void main(String[] args) {
    Timetable t = new Timetable("CSE 3rd sem")
        .add("Mon", "Java")
        .add("Mon", "DBMS")
        .add("Tue", "OS");
    t.print();
  }
}

class Timetable {
  private final String batch;
  private final StringBuilder slots = new StringBuilder();

  Timetable(String batch) { this.batch = batch; }

  Timetable add(String day, String subject) {
    slots.append(day).append(": ").append(subject).append('\n');
    return this;                 // hand back the same object, so calls can chain
  }

  void print() {
    System.out.print(batch + "\n" + slots);
  }
}
```

```text [Output]
CSE 3rd sem
Mon: Java
Mon: DBMS
Tue: OS
```

::warning{icon="i-lucide-alert-triangle"}
A `static` field that changes is shared state. In a web application every
request in flight sees the same one, and two requests changing it at once is a
bug that only appears under load. `static final` constants are good; mutable
`static` fields are a code smell. The multithreading chapter shows exactly what
goes wrong.
::

## What confuses people here

### A final reference is not a frozen object

```java [FinalDemo.java]
import java.util.Arrays;

public class FinalDemo {
  public static void main(String[] args) {
    final int maxMarks = 100;
    final int[] marks = {78, 64, 81};

    marks[0] = 92;                      // allowed: the array's contents change
    System.out.println(Arrays.toString(marks));

    Hostel h = new Hostel("Block B", 120);
    System.out.println(h.name + " holds " + h.capacity);
  }
}

class Hostel {
  final String name;        // a "blank final": no value here...
  final int capacity;

  Hostel(String name, int capacity) {
    this.name = name;       // ...assigned exactly once, in the constructor
    this.capacity = capacity;
  }
}
```

```text [Output]
[92, 64, 81]
Block B holds 120
```

::compare{caption="final freezes the variable, not the object it points at."}
  :::compare-side{label="What people expect" verdict="wrong"}
  `final int[] marks` means the marks can never change.
  :::
  :::compare-side{label="What final guarantees" verdict="right"}
  `marks` will always point at **the same array**. The contents of that array
  can still change. An immutable object (like `String`) is a different, stronger
  property, designed into the class.
  :::
::

- **`final`, `finally`, `finalize`** sound alike and are unrelated. `final` is
  this keyword. `finally` is the block after `try` that always runs (exceptions
  chapter). `finalize()` was a method the garbage collector could call before
  destroying an object; it is deprecated since Java 9 and you should never rely
  on it.
- **A constructor cannot be `final`, `static` or `abstract`.** It is not
  inherited, so there is nothing to override, and it always belongs to an
  object being created.
- **Static methods cannot be overridden**; a subclass method with the same
  signature *hides* it instead. The polymorphism lesson shows the difference.

## Interview questions

::accordion
  :::accordion-item{label="Why is the main method static?" icon="i-lucide-message-circle"}
  Because the JVM calls it before any object of the class exists. A static
  method belongs to the class, so it can be called as `Admissions.main(args)`
  without creating an `Admissions` object and without the JVM having to guess
  which constructor to use.
  :::
  :::accordion-item{label="What is a static block and when does it run?" icon="i-lucide-message-circle"}
  A block marked `static { }` that runs once, when the class is loaded, before
  any object is created and before any static method runs. In `InitOrder.java`
  it printed once even though two departments were created. Used for one-time
  set-up of static fields.
  :::
  :::accordion-item{label="Can we access an instance variable from a static method?" icon="i-lucide-message-circle"}
  Not directly: the compiler reports `non-static variable batch cannot be
  referenced from a static context`. A static method has no `this`. Create or
  receive an object and go through it: `new StaticContext().batch`.
  :::
  :::accordion-item{label="What is constructor chaining?" icon="i-lucide-message-circle"}
  One constructor calling another. `this(...)` calls another constructor of the
  same class; `super(...)` calls the parent class's constructor. Either must be
  the first statement, and a constructor can have only one of them.
  :::
  :::accordion-item{label="What is the difference between final, finally and finalize?" icon="i-lucide-message-circle"}
  `final` is a modifier: a final variable cannot be reassigned, a final method
  cannot be overridden, a final class cannot be extended. `finally` is the block
  after `try`/`catch` that runs whether or not an exception was thrown.
  `finalize()` is a deprecated `Object` method the garbage collector might call
  before reclaiming an object; there is no guarantee it ever runs.
  :::
  :::accordion-item{label="Can a constructor be private? Why would you do it?" icon="i-lucide-message-circle"}
  Yes. It stops code outside the class from calling `new`. Used for utility
  classes that should never be instantiated (`FeeRules` above, `Math`,
  `Collections`), and for the **singleton** pattern, where the class creates its
  one instance itself and hands it out through a static method.
  :::
::
