Names in one array, marks in another, matched by position. Sort one and forget
the other, and every student gets somebody else's marks. A **class** is Java's
answer: one thing that holds a student's name and marks together, so nothing
can separate them.

::warning{icon="i-lucide-alert-triangle"}
**This is the hardest conceptual jump so far, and it took me weeks.** At
JSpiders I could write the syntax in my second week and did not really
understand what I was doing for about a month after that. If it does not click
immediately, that is the normal experience, not a signal about you. Read it
twice, type the examples, and it arrives.
::

## Why this matters in a job

Every Java system you will ever read is made of classes. The "OOPs round" is a
fixed part of fresher interviews in Bangalore: what is a class, what is an
object, what are the four pillars, and "explain with a real example". The
next nine lessons are that round, and this one is its foundation.

It also removes a whole category of bug. Data scattered across parallel arrays
is related only by a convention nobody enforces. Bundle it into an object and
the convention becomes impossible to break.

## The problem, made concrete

```java [Parallel.java]
import java.util.Arrays;

public class Parallel {
  public static void main(String[] args) {
    String[] names     = {"Anita Rao", "Vikram Shah", "Priya Nair"};
    int[] scores       = {78, 64, 81};
    boolean[] withdrawn = {false, false, true};

    Arrays.sort(scores);     // sort by score... only the scores move

    for (int i = 0; i < names.length; i++) {
      System.out.println(names[i] + " " + scores[i] + (withdrawn[i] ? " (withdrawn)" : ""));
    }
  }
}
```

```text [Output]
Anita Rao 64
Vikram Shah 78
Priya Nair 81 (withdrawn)
```

Anita scored 78 and now has 64. Nothing crashed. Nothing looks wrong unless
you already know the right answer. The three arrays were only ever related by
position.

## A class is a form; an object is one filled-in copy

The admissions office has a blank form: name, date of birth, marks, category.
That printed template is written once. Every applicant fills in their own copy,
and each copy is a separate piece of paper with its own answers.

- The **class** is the blank form: a description of what every student has
  (**fields**) and what every student can do (**methods**).
- An **object** is one filled-in copy, created at run time with `new`. It is
  also called an **instance** of the class.

The class `Student` is written once. There may be four thousand `Student`
objects, each with its own name and its own marks.

::pull-quote
A class is written once, by you, at compile time. Objects are made from it, as
many as you need, while the program runs.
::

## Syntax

```java
class Student {
  String name;            // a field: data every Student has
  int[] marks;

  double average() {      // a method: behaviour that uses this Student's fields
    ...
  }
}

Student anita = new Student();   // create an object
anita.name = "Anita Rao";        // reach a field with a dot
anita.average();                 // call a method with a dot
```

A complete program. Two classes can live in one file as long as only one is
`public`, and the file is named after that one.

```java [Admissions.java]
public class Admissions {
  public static void main(String[] args) {
    Student anita = new Student();          // one object
    anita.name = "Anita Rao";
    anita.marks = new int[] {78, 64, 81, 90};

    Student vikram = new Student();         // another, with its own fields
    vikram.name = "Vikram Shah";
    vikram.marks = new int[] {55, 72, 48, 61};

    Student priya = new Student();
    priya.name = "Priya Nair";
    priya.marks = new int[] {92, 88, 79, 85};

    Student[] students = {anita, vikram, priya};

    // Sort by average, highest first. Swapping whole objects keeps
    // each name with its own marks.
    for (int i = 0; i < students.length; i++) {
      for (int j = i + 1; j < students.length; j++) {
        if (students[j].average() > students[i].average()) {
          Student t = students[i]; students[i] = students[j]; students[j] = t;
        }
      }
    }

    for (Student s : students) {
      System.out.printf("%-12s %.2f %s%n", s.name, s.average(), s.isEligible() ? "eligible" : "not eligible");
    }
  }
}

class Student {
  // fields: what every Student knows
  String name;
  int[] marks;

  // methods: what every Student can do, using its OWN fields
  double average() {
    int total = 0;
    for (int m : marks) total += m;
    return (double) total / marks.length;
  }

  boolean isEligible() {
    return average() >= 60;
  }
}
```

```bash [Terminal]
javac Admissions.java      # produces Admissions.class AND Student.class
java Admissions
```

```text [Output]
Priya Nair   86.00 eligible
Anita Rao    78.25 eligible
Vikram Shah  59.00 not eligible
```

The sort swapped **whole students**, so each name travelled with its own marks.
The bug from `Parallel.java` cannot happen, because there is nothing to keep in
step. And `average()` has no parameters: when you call `priya.average()`, the
method works on Priya's `marks`, because it runs "on" that object.

### What `new` really does

::flow{numbered direction="vertical" caption="new Student(): only the address lands on the stack."}
  :::flow-step{label="Allocate space on the heap" icon="i-lucide-box"}
  Enough room for every field in the class.
  :::
  :::flow-step{label="Fill the fields with defaults" icon="i-lucide-circle-dot"}
  Numbers 0, booleans `false`, references `null`. Never leftover memory.
  :::
  :::flow-step{label="Run the constructor" icon="i-lucide-hammer" highlight}
  Your chance to make the object valid before anybody can use it.
  :::
  :::flow-step{label="Return the address" icon="i-lucide-link"}
  Which is what the variable on the stack holds, exactly as with arrays.
  :::
::

Look at what the defaults give you when there is no constructor:

```java [Defaults.java]
public class Defaults {
  public static void main(String[] args) {
    Course c = new Course();
    System.out.println(c.code);
    System.out.println(c.credits);
    System.out.println(c.elective);
    System.out.println(c);
    System.out.println(c.code.length());
  }
}

class Course {
  String code;
  int credits;
  boolean elective;
}
```

```text [Output]
null
0
false
Course@80ec1f8
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "String.length()" because "<local1>.code" is null
	at Defaults.main(Defaults.java:8)
```

A course with no code and zero credits is not a valid course. And printing the
object gives `Course@80ec1f8`, the class name and a hash code, the same as
printing an array. The `equals, hashCode and records` lesson shows how to make
it print something useful with `toString()`.

### Constructors: born valid

A **constructor** is a special block that runs when the object is created. It
has the class's name and no return type, not even `void`.

```java [Born.java]
public class Born {
  public static void main(String[] args) {
    Course java = new Course("CS-201", "Core Java", 4);
    System.out.println(java.describe());

    Course broken = new Course("CS-305", "Operating Systems", 9);
    System.out.println(broken.describe());
  }
}

class Course {
  String code;
  String title;
  int credits;

  // A constructor: same name as the class, no return type.
  Course(String code, String title, int credits) {
    if (credits < 1 || credits > 6) {
      throw new IllegalArgumentException("Credits must be 1 to 6, got " + credits);
    }
    this.code = code;          // this.code is the field; code is the parameter
    this.title = title;
    this.credits = credits;
  }

  String describe() {
    return code + " " + title + " (" + credits + " credits)";
  }
}
```

```text [Output]
CS-201 Core Java (4 credits)
Exception in thread "main" java.lang.IllegalArgumentException: Credits must be 1 to 6, got 9
	at Course.<init>(Born.java:19)
	at Born.main(Born.java:6)
```

`throw new IllegalArgumentException(...)` stops the program with a message;
the exceptions chapter covers it properly. `<init>` in the stack trace is the
JVM's name for a constructor. The point: a nine-credit course **never came into
existence**. Every `Course` anywhere in the program has passed that check.

`this.code = code` is needed because the parameter `code` hides the field
`code`. `this` means "the object being built", so `this.code` is the field. The
next lesson looks at `this` properly.

## Real use case

Look at any Java codebase and the classes are nouns from the business:
`Student`, `Course`, `FeePayment`, `Attendance`, `Placement`. Each holds the
data that belongs together and the behaviour that uses it.

```java
class FeePayment {
  String rollNumber;
  long amountPaise;            // money in paise, never double
  String paidOn;

  boolean isLate(String dueDate) {
    return paidOn.compareTo(dueDate) > 0;   // ISO dates compare as text
  }
}
```

::real-life{title="What a class replaces at work" source="Every CRUD service in Bangalore"}
A fee record fetched from the database becomes a `FeePayment` object, is
checked by its own methods, is turned into JSON for the website, and is saved
back. Nobody passes six loose variables around. When an interviewer says
"design the classes for a college fee system", they want this: nouns become
classes, their facts become fields, their rules become methods.
::

## What confuses people here

::compare{caption="The object and the variable are two different things."}
  :::compare-side{label="What people think" verdict="wrong"}
  `Faculty a = new Faculty("Dr. Menon");` means `a` **is** the faculty
  member, so `Faculty c = a;` makes a second faculty member.
  :::
  :::compare-side{label="What happens" verdict="right"}
  `a` holds an **address**. `c = a` copies the address. One object, two
  names: change `c.name` and `a.name` shows the change.
  :::
::

```java [Identity.java]
public class Identity {
  public static void main(String[] args) {
    Faculty a = new Faculty("Dr. Menon");
    Faculty b = new Faculty("Dr. Menon");
    Faculty c = a;
    System.out.println(a == b);
    System.out.println(a == c);
    c.name = "Dr. K. Menon";
    System.out.println(a.name);
  }
}

class Faculty {
  String name;
  Faculty(String name) { this.name = name; }
}
```

```text [Output]
false
true
Dr. K. Menon
```

`a == b` is `false` even though both say "Dr. Menon": `==` on objects compares
addresses. Two separate objects with the same contents are not `==`. The
`equals` lesson fixes that.

- **Write any constructor and the free one disappears.** If a class has no
  constructor, Java gives it an empty no-argument one (the **default
  constructor**). Write `Course(String code)` and `new Course()` stops
  compiling: `constructor Course in class Course cannot be applied to given
  types`.
- **Fields get defaults; local variables do not.** A field `int fieldCount;`
  starts at 0. A local `int localCount;` used before assignment is a compile
  error: `variable localCount might not have been initialized`.
- **A constructor is not a method.** It has no return type. Write
  `void Course(...)` by mistake and it becomes an ordinary method that happens
  to share the class name, and your "constructor" silently never runs.

## Interview questions

::accordion
  :::accordion-item{label="What is the difference between a class and an object?" icon="i-lucide-message-circle"}
  A class is a description written once in code: the fields every instance has
  and the methods it can run. An object is one instance created at run time with
  `new`, living on the heap, with its own copy of the fields. Then the reason it
  matters: bundling the data means it cannot be separated (the parallel arrays
  bug), and a validating constructor means an invalid object cannot exist.
  :::
  :::accordion-item{label="What happens when you write new Student()?" icon="i-lucide-message-circle"}
  The JVM allocates memory on the heap for the fields, sets them to default
  values (0, `false`, `null`), runs the constructor, and returns a reference
  that is stored in the variable. The variable itself is on the stack.
  :::
  :::accordion-item{label="What is a default constructor?" icon="i-lucide-message-circle"}
  A no-argument constructor the compiler adds when a class declares none. It
  sets nothing beyond the defaults. As soon as you write any constructor, the
  compiler stops adding it, and `new Course()` fails to compile unless you
  write a no-argument one yourself.
  :::
  :::accordion-item{label="How many ways are there to create an object in Java?" icon="i-lucide-message-circle"}
  The usual answer is five: `new`; `clone()`; reflection
  (`Course.class.getDeclaredConstructor().newInstance()`); deserialisation
  (reading an object back from bytes); and factory methods such as
  `Integer.valueOf(5)` or `List.of()`, which call `new` for you inside.
  In everyday code it is almost always `new` or a factory method.
  :::
  :::accordion-item{label="Do local variables get default values?" icon="i-lucide-message-circle"}
  No. Fields and array elements do; local variables must be assigned before
  use, or the compiler reports `variable localCount might not have been
  initialized`. The difference exists because the compiler can see every path
  through a method, but not every path through an object's life.
  :::
::
