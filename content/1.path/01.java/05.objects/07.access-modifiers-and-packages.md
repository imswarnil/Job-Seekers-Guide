Every program so far has lived in one file. A real project has hundreds or
thousands of classes, split into folders called **packages**, and four
**access modifiers** decide which class can see which field and method.

## Why this matters in a job

The first time you open a company codebase, the folder tree you see is the
package structure: `com.company.admissions.service`,
`com.company.fees.repository`. You need to know how that maps to files, why an
import fails, and why a method you can see in the editor is "not visible" from
where you are calling it. The access table below is a guaranteed interview
question ("what is the difference between protected and default?"), and
`protected` across packages trips up even people with a year of experience.

## Packages are departments; modifiers are door signs

A college campus is split into departments: Computer Science, Accounts,
Admissions. Each has its own building (a **package**). The doors have signs:

- **public**: anyone on campus may enter;
- **protected**: the department's own staff, plus people trained by it who now
  work elsewhere (subclasses in other packages);
- **(no sign)**, called **default** or **package-private**: this department's
  staff only;
- **private**: this one office only.

A **package** is a named group of related classes, and on disk it is a folder.
The name is written in reverse domain order so it is unique worldwide: a
college at `lnct.in` would use `in.lnct.admissions`, and that class's file
lives in the folder `in/lnct/admissions/`.

## Syntax

```java
package in.lnct.admissions;          // first line of the file: which package

import in.lnct.fees.FeeAccount;       // use a class from another package
import java.util.*;                   // every class in java.util (not sub-packages)
import static java.lang.Math.max;     // a static member, used without the class name

public class Applicant { ... }
```

The four levels, from most open to most closed:

| Modifier | Same class | Same package | Subclass in another package | Anywhere |
| --- | --- | --- | --- | --- |
| `public` | Yes | Yes | Yes | Yes |
| `protected` | Yes | Yes | Yes (through inheritance) | No |
| *(none)*, default | Yes | Yes | No | No |
| `private` | Yes | No | No | No |

A top-level class may only be `public` or default. `private class Hidden { }`
fails with `modifier private not allowed here`. Nested classes can use all four.

## How it works

A small project with three packages, as it would sit on disk:

```text [Project layout]
src/
└── in/lnct/
    ├── admissions/
    │   ├── Applicant.java
    │   └── Registrar.java
    ├── fees/
    │   └── ScholarshipApplicant.java
    └── app/
        └── Main.java
```

```java [src/in/lnct/admissions/Applicant.java]
package in.lnct.admissions;

public class Applicant {
  public final String name;          // everyone
  protected int score;               // this package + subclasses anywhere
  String category;                   // (no modifier) this package only
  private String aadhaarLast4;       // this class only

  public Applicant(String name, int score, String category, String aadhaarLast4) {
    this.name = name;
    this.score = score;
    this.category = category;
    this.aadhaarLast4 = aadhaarLast4;
  }

  public String maskedId() {
    return "XXXX-XXXX-" + aadhaarLast4;   // private is fine inside the class
  }
}
```

```java [src/in/lnct/admissions/Registrar.java]
package in.lnct.admissions;

public class Registrar {
  public static final int CUTOFF = 60;

  public static boolean shortlist(Applicant a) {
    // Same package: can read protected and package-private members.
    int cutoff = a.category.equals("GEN") ? CUTOFF : CUTOFF - 5;
    return a.score >= cutoff;
  }
}
```

```java [src/in/lnct/fees/ScholarshipApplicant.java]
package in.lnct.fees;

import in.lnct.admissions.Applicant;

public class ScholarshipApplicant extends Applicant {
  public ScholarshipApplicant(String name, int score) {
    super(name, score, "GEN", "0000");
  }

  public int waiverPercent() {
    return score >= 90 ? 50 : 0;     // protected: visible in a subclass, any package
  }
}
```

```java [src/in/lnct/app/Main.java]
package in.lnct.app;

import in.lnct.admissions.Applicant;
import in.lnct.admissions.Registrar;
import in.lnct.fees.ScholarshipApplicant;
import static in.lnct.admissions.Registrar.CUTOFF;   // a static import

public class Main {
  public static void main(String[] args) {
    Applicant meera = new Applicant("Meera Iyer", 57, "OBC", "4821");
    System.out.println(meera.name + " " + meera.maskedId());
    System.out.println("Shortlisted: " + Registrar.shortlist(meera));
    System.out.println("General cutoff: " + CUTOFF);

    ScholarshipApplicant farah = new ScholarshipApplicant("Farah Khan", 93);
    System.out.println(farah.name + " waiver " + farah.waiverPercent() + "%");
  }
}
```

Compile everything into a separate `out` folder with `-d`, then run the class by
its **fully qualified name** (package plus class) with `-cp` (the **classpath**:
where Java should look for `.class` files):

```bash [Terminal]
javac -d out $(find src -name "*.java")
find out -type f
java -cp out in.lnct.app.Main
```

```text [Output]
out/in/lnct/admissions/Applicant.class
out/in/lnct/admissions/Registrar.class
out/in/lnct/app/Main.class
out/in/lnct/fees/ScholarshipApplicant.class
Meera Iyer XXXX-XXXX-4821
Shortlisted: true
General cutoff: 60
Farah Khan waiver 50%
```

`javac -d out` rebuilt the package folders under `out` for you. Now try to read
the three hidden fields from a class in `in.lnct.app`:

```java [bad/Peek.java]
package in.lnct.app;

import in.lnct.admissions.Applicant;

public class Peek {
  public static void main(String[] args) {
    Applicant a = new Applicant("Rohit Das", 64, "GEN", "1234");
    System.out.println(a.score);
    System.out.println(a.category);
    System.out.println(a.aadhaarLast4);
  }
}
```

```text [Output]
bad/Peek.java:8: error: score has protected access in Applicant
    System.out.println(a.score);
                        ^
bad/Peek.java:9: error: category is not public in Applicant; cannot be accessed from outside package
    System.out.println(a.category);
                        ^
bad/Peek.java:10: error: aadhaarLast4 has private access in Applicant
    System.out.println(a.aadhaarLast4);
                        ^
3 errors
```

Three different messages for three different levels. Read the wording: each
one tells you which modifier stopped you.

## Real use case

A typical Spring Boot service at a Bangalore company is laid out by feature
and layer:

```text [A real package layout]
com.company.admissions
├── controller    AdmissionController      public: the web layer calls it
├── service       AdmissionService         public methods, private helpers
├── repository    ApplicantRepository      an interface
└── model         Applicant                private fields, public getters
```

The habits that go with it:

::feature-list{columns="2"}
  :::feature{icon="i-lucide-lock" title="Start private"}
  Every field private, every helper method private. Widen only when something
  outside genuinely needs it.
  :::
  :::feature{icon="i-lucide-door-open" title="Public is a promise"}
  Once six teams call a public method, changing it is a negotiation. Narrowing
  later is hard; widening later is easy.
  :::
  :::feature{icon="i-lucide-package" title="Default for internals"}
  A helper class used only inside its package can be package-private, which
  hides it from the rest of the codebase.
  :::
  :::feature{icon="i-lucide-shield" title="Protected sparingly"}
  It exposes internals to every future subclass, in any package, forever.
  :::
::

::real-life{title="The error you will see in week one" source="Any new codebase"}
You copy a class into a new folder and everything breaks with `cannot find
symbol`. Nine times out of ten the `package` line at the top no longer matches
the folder, or the import still points at the old package. The IDE will offer
to fix it; knowing why it broke is what lets you fix it when the IDE cannot.
::

## What confuses people here

::compare{caption="Protected across packages works through inheritance, not through any object."}
  :::compare-side{label="What people expect" verdict="wrong"}
  "`ScholarshipApplicant` is a subclass, so inside it I can read `score` on any
  `Applicant`." In another package, `new Applicant(...).score` from inside the
  subclass is still an error.
  :::
  :::compare-side{label="What protected allows" verdict="right"}
  The subclass can use the `score` it **inherited**: `this.score`, or `score`
  on its own objects. `waiverPercent()` above reads its own `score`, which is
  why it compiles.
  :::
::

- **`import java.util.*` does not import sub-packages.** `java.util.function`
  needs its own import.
- **`java.lang` is imported automatically**, which is why `String`, `Math` and
  `System` never needed an import.
- **Running by file path fails.** From inside `out`, `java Main` gives `Error:
  Could not find or load main class Main`, because the class's real name is
  `in.lnct.app.Main` and Java looks for it under `in/lnct/app/`.
- **Two classes with the same simple name** (`java.util.Date` and
  `java.sql.Date`) cannot both be imported; use the fully qualified name for
  one of them.
- **The default package** (no `package` line, as in every earlier lesson) is
  fine for learning and never used in real projects: classes in it cannot be
  imported from a named package.

## Interview questions

::accordion
  :::accordion-item{label="Explain the four access modifiers." icon="i-lucide-message-circle"}
  `private`: the same class only. Default (no keyword): the same package.
  `protected`: the same package, plus subclasses in other packages through
  inheritance. `public`: everywhere. Then prove it: `Peek.java` got three
  different errors for `score`, `category` and `aadhaarLast4`.
  :::
  :::accordion-item{label="What is the difference between protected and default access?" icon="i-lucide-message-circle"}
  Both allow access within the same package. `protected` also allows access
  from a subclass in a different package, through the inherited member.
  Default does not: `ScholarshipApplicant` in `in.lnct.fees` could read its
  inherited `score` (protected) but could not read `category` (default).
  :::
  :::accordion-item{label="What is a package and why use one?" icon="i-lucide-message-circle"}
  A named group of related classes that maps to a folder. It prevents name
  clashes (two `Date` classes can exist in different packages), organises a
  large codebase, and together with default access lets a package hide its
  internal classes from everyone else.
  :::
  :::accordion-item{label="What is a static import?" icon="i-lucide-message-circle"}
  `import static in.lnct.admissions.Registrar.CUTOFF;` lets you write `CUTOFF`
  without the class name. Useful for constants and for test assertions
  (`import static org.junit.jupiter.api.Assertions.*`); overused, it makes it
  unclear where a name comes from.
  :::
  :::accordion-item{label="Can a top-level class be private or protected?" icon="i-lucide-message-circle"}
  No. A top-level class is either `public` or default. `private class Hidden`
  fails with `modifier private not allowed here`. Nested classes (a class
  inside a class) can use all four.
  :::
::
