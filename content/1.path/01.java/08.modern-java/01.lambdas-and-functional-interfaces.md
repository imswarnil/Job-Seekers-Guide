The anonymous `Comparator` class at the end of the generics lesson was eight
lines for one comparison, and only one of those lines said anything. Java 8
(2014) added **lambdas** so that one line can say it, and nearly every piece of
modern Java you will read is built on them.

## Why this matters in a job

Open any Java codebase written after about 2016 and you will see lambdas and
streams on most screens: `list.sort(...)`, `map.forEach(...)`,
`students.stream().filter(...)`. You cannot read that code without this lesson.

In interviews, "what is new in Java 8?" is close to guaranteed, and it leads
straight to "what is a functional interface?", "name some built-in ones",
"what is a method reference?" and "why must a variable used in a lambda be
effectively final?". All five are answered below with code.

## A lambda is an instruction slip

Before Java 8, if you wanted to hand the exam cell a rule ("sort these by
CGPA, highest first"), you had to hire a whole clerk to carry it: declare a
class, name it, implement its method, create an object of it. That is the
anonymous class. A **lambda** is the instruction slip on its own: the rule,
without the clerk.

Technically, a lambda is a short way to write an object that implements an
interface with **exactly one abstract method**. That kind of interface is
called a **functional interface**. `Comparator` is one: its only abstract
method is `compare(a, b)`. Because there is only one method, Java knows which
method your lambda is the body of, so you do not have to name it.

::compare{caption="The same comparator, before and after Java 8."}
  :::compare-side{label="Anonymous class" verdict="wrong"}
  ```java
  new Comparator<Student>() {
    @Override
    public int compare(Student a, Student b) {
      return Double.compare(b.cgpa(), a.cgpa());
    }
  }
  ```
  Five lines of ceremony around one line of meaning.
  :::
  :::compare-side{label="Lambda" verdict="right"}
  ```java
  (a, b) -> Double.compare(b.cgpa(), a.cgpa())
  ```
  Parameters, an arrow, the body. The types are inferred from `Comparator<Student>`.
  :::
::

## Syntax

```java
(a, b) -> Double.compare(a.cgpa(), b.cgpa())   // two parameters, expression body
marks -> marks >= 40                           // one parameter: brackets optional
() -> 1801                                      // no parameters: empty brackets
(String name) -> name.toUpperCase()             // explicit type, if you want it
m -> {                                          // block body: braces and return
  int withBonus = m + 5;
  return withBonus >= 40;
}
```

```java [SortStudents.java]
import java.util.*;

public class SortStudents {
  record Student(String name, String department, double cgpa) {}

  public static void main(String[] args) {
    List<Student> students = new ArrayList<>(List.of(
        new Student("Anita", "CSE", 8.4),
        new Student("Vikram", "ECE", 7.1),
        new Student("Farah", "CSE", 9.2)));

    // Before Java 8: an anonymous class, eight lines for one comparison.
    Collections.sort(students, new Comparator<Student>() {
      @Override
      public int compare(Student a, Student b) {
        return Double.compare(b.cgpa(), a.cgpa());
      }
    });
    System.out.println("Anonymous class: " + students.get(0).name());

    // Java 8: a lambda. The same comparison, one line.
    students.sort((a, b) -> Double.compare(a.cgpa(), b.cgpa()));
    System.out.println("Lambda:          " + students.get(0).name());

    // A method reference, when the lambda only calls one method.
    students.sort(Comparator.comparing(Student::name));
    students.forEach(s -> System.out.println("  " + s.name()));
  }
}
```

```bash [Terminal]
javac SortStudents.java && java SortStudents
```

```text [Output]
Anonymous class: Farah
Lambda:          Vikram
  Anita
  Farah
  Vikram
```

### The built-in functional interfaces

You rarely declare your own. The package `java.util.function` has about forty,
and seven cover almost everything:

| Interface | Method | Takes, returns | University example |
| --- | --- | --- | --- |
| `Predicate<T>` | `test` | T, `boolean` | Has this student passed? |
| `Function<T, R>` | `apply` | T, R | Marks to grade |
| `Consumer<T>` | `accept` | T, nothing | Send an email to this student |
| `Supplier<T>` | `get` | nothing, T | Give me the next roll number |
| `BiFunction<T, U, R>` | `apply` | T and U, R | Marks and maximum to percentage |
| `UnaryOperator<T>` | `apply` | T, T | Name to upper case |
| `BinaryOperator<T>` | `apply` | T and T, T | Add two marks |

```java [BuiltIns.java]
import java.util.function.*;

public class BuiltIns {
  public static void main(String[] args) {
    Predicate<Integer> passed = marks -> marks >= 40;           // T -> boolean
    Function<Integer, String> grade = marks -> marks >= 75 ? "A" : "B"; // T -> R
    Consumer<String> notify = name -> System.out.println("Email sent to " + name); // T -> nothing
    Supplier<Integer> nextRoll = () -> 1801;                    // nothing -> T
    BiFunction<Integer, Integer, Double> pct = (got, max) -> got * 100.0 / max;
    UnaryOperator<String> shout = s -> s.toUpperCase();         // T -> T
    BinaryOperator<Integer> add = (a, b) -> a + b;              // (T, T) -> T

    System.out.println(passed.test(38));
    System.out.println(grade.apply(81));
    notify.accept("Farah");
    System.out.println(nextRoll.get());
    System.out.println(pct.apply(45, 60));
    System.out.println(shout.apply("cse"));
    System.out.println(add.apply(78, 5));

    Predicate<Integer> distinction = marks -> marks >= 75;
    System.out.println(passed.and(distinction.negate()).test(60));
    Function<Integer, Integer> bonus = m -> m + 5;
    System.out.println(bonus.andThen(grade).apply(72));
  }
}
```

```text [Output]
false
A
Email sent to Farah
1801
75.0
CSE
83
true
A
```

The last two lines show why these are interfaces and not only syntax: they have
**default methods** for combining. `passed.and(distinction.negate())` is "passed
but without distinction". `bonus.andThen(grade)` adds 5 marks and then grades,
so 72 becomes 77 and an A.

### Writing your own

Declare an interface with one abstract method and, ideally, mark it
`@FunctionalInterface`. The annotation is optional; what it buys you is a
compile error if somebody later adds a second abstract method and breaks every
lambda that uses it. Default and static methods do not count against the one.

```java [OwnInterface.java]
public class OwnInterface {
  @FunctionalInterface
  interface FeeRule {
    long feeFor(int credits);          // exactly one abstract method
    default String currency() { return "INR"; }   // defaults are allowed
  }

  public static void main(String[] args) {
    FeeRule regular = credits -> credits * 2_500L;
    FeeRule scholarship = credits -> credits * 2_500L / 2;
    System.out.println(regular.feeFor(20) + " " + regular.currency());
    System.out.println(scholarship.feeFor(20) + " " + scholarship.currency());
  }
}
```

```text [Output]
50000 INR
25000 INR
```

### Method references

When a lambda does nothing except call one existing method, you can name the
method instead. `s -> s.toUpperCase()` becomes `String::toUpperCase`. There are
four kinds, and interviewers like you to list them:

::feature-list{columns="2"}
  :::feature{icon="i-lucide-box" title="Static method"}
  `Integer::parseInt` means `s -> Integer.parseInt(s)`.
  :::
  :::feature{icon="i-lucide-user" title="Method of a particular object"}
  `System.out::println` means `x -> System.out.println(x)`.
  :::
  :::feature{icon="i-lucide-users" title="Method of any object of a type"}
  `String::toUpperCase` means `s -> s.toUpperCase()`: the object is the first
  argument.
  :::
  :::feature{icon="i-lucide-plus" title="Constructor"}
  `ArrayList::new` means `() -> new ArrayList<>()`.
  :::
::

```java [MethodRefs.java]
import java.util.*;
import java.util.function.*;

public class MethodRefs {
  static boolean isTopper(int marks) { return marks >= 90; }

  public static void main(String[] args) {
    List<String> names = List.of("anita", "vikram", "farah");

    // 1. Static method:              ClassName::staticMethod
    Predicate<Integer> topper = MethodRefs::isTopper;
    Function<String, Integer> parse = Integer::parseInt;

    // 2. Instance method of a particular object:  object::method
    Consumer<String> print = System.out::println;

    // 3. Instance method of an arbitrary object of a type:  ClassName::instanceMethod
    Function<String, String> upper = String::toUpperCase;

    // 4. Constructor:                ClassName::new
    Supplier<List<String>> newList = ArrayList::new;

    System.out.println(topper.test(92));
    System.out.println(parse.apply("78") + 2);
    names.forEach(print);
    System.out.println(upper.apply("cse"));
    List<String> waitlist = newList.get();
    waitlist.add("Rohit");
    System.out.println(waitlist);
  }
}
```

```text [Output]
true
80
anita
vikram
farah
CSE
[Rohit]
```

## Real use case

The place you will write lambdas most at work is where a library method asks
"what should I do?" and you answer with behaviour: sorting, filtering,
iterating a map, running a task on another thread, handling a click.

```java
students.sort(Comparator.comparing(Student::department)
                        .thenComparing(Student::cgpa, Comparator.reverseOrder()));
feeDues.forEach((roll, amount) -> reminders.send(roll, amount));
executor.submit(() -> resultService.publish(semester));
students.removeIf(s -> s.cgpa() < 5.0);
```

Four lines, four different interfaces (`Comparator`, `BiConsumer`, `Runnable`
or `Callable`, `Predicate`), and none of them named. That is what Java 8 bought.
The streams lesson next builds whole data pipelines out of the same pieces.

::real-life{title="What a reviewer looks for" source="Java code review, any team"}
A lambda longer than three or four lines is usually a method that has not been
named yet. Move the body into a private method with an honest name and pass
`this::isEligibleForScholarship` instead. The call site reads like English and
the logic can be tested on its own.
::

## What confuses people here

### Effectively final

A lambda can read local variables from the method around it, but only if they
are **final** or **effectively final**: never reassigned after they are set.

```java [EffectivelyFinal.java]
import java.util.*;

public class EffectivelyFinal {
  public static void main(String[] args) {
    List<Integer> marks = List.of(78, 64, 92);
    int cutoff = 70;
    marks.forEach(m -> { if (m >= cutoff) System.out.println(m); });
    cutoff = 75;
  }
}
```

```text [Output]
EffectivelyFinal.java:7: error: local variables referenced from a lambda expression must be final or effectively final
    marks.forEach(m -> { if (m >= cutoff) System.out.println(m); });
                                  ^
1 error
```

The error points at the lambda, but the cause is the last line. Why the rule?
The lambda may run later, or on another thread, after the method has returned
and its stack frame is gone. So Java **copies** the value into the lambda. If
the variable could still change, the copy and the original would disagree.
Forbidding the change removes the question.

::compare{caption="Counting inside a lambda: the hack and the right tool."}
  :::compare-side{label="Mutating from inside" verdict="wrong"}
  ```java
  int[] above = {0};
  marks.forEach(m -> { if (m >= 70) above[0]++; });
  ```
  Compiles, because the array reference never changes. It is also not
  thread-safe and fights the style. You will see it in real code.
  :::
  :::compare-side{label="Ask a question, get an answer" verdict="right"}
  ```java
  long above = marks.stream().filter(m -> m >= 70).count();
  ```
  Both print 2. The stream version has no shared state at all.
  :::
::

- **`this` inside a lambda** means the enclosing object. Inside an anonymous
  class it means the anonymous object. That is one of the real differences
  between the two.
- **A lambda has no type of its own.** `var f = x -> x + 1;` does not compile:
  Java needs a target interface to know what the lambda is.
- **Checked exceptions do not fit.** `Function.apply` declares no exceptions, so
  a lambda that calls a method throwing `IOException` must catch it inside.

## Interview questions

::accordion
  :::accordion-item{label="What is a functional interface? Name some." icon="i-lucide-message-circle"}
  An interface with exactly one abstract method, so a lambda can implement it.
  Default and static methods do not count. Examples: `Runnable` (`run`),
  `Callable` (`call`), `Comparator` (`compare`), and in `java.util.function`
  `Predicate`, `Function`, `Consumer`, `Supplier`. `@FunctionalInterface`
  makes the compiler enforce the one-method rule.
  :::
  :::accordion-item{label="What are the main features of Java 8?" icon="i-lucide-message-circle"}
  Lambdas, functional interfaces, method references, the Stream API, default
  and static methods in interfaces, `Optional`, and the new `java.time`
  date-time API. Then pick one and show it: `list.sort(Comparator.comparing(Student::cgpa))`
  replacing an eight-line anonymous class is the easiest to demonstrate.
  :::
  :::accordion-item{label="Lambda against anonymous class: what is the difference?" icon="i-lucide-message-circle"}
  A lambda can only implement a functional interface; an anonymous class can
  extend a class or implement an interface with many methods. Inside a lambda,
  `this` is the enclosing object; inside an anonymous class it is the anonymous
  object. An anonymous class can hold its own fields; a lambda cannot. Both can
  only capture effectively final locals.
  :::
  :::accordion-item{label="What are the four kinds of method reference?" icon="i-lucide-message-circle"}
  Static (`Integer::parseInt`), instance method of a particular object
  (`System.out::println`), instance method of an arbitrary object of a type
  (`String::toUpperCase`), and constructor (`ArrayList::new`). All four are in
  `MethodRefs.java` above.
  :::
  :::accordion-item{label="Why must variables used in a lambda be effectively final?" icon="i-lucide-message-circle"}
  The lambda captures a copy of the value, and may run after the method has
  returned or on another thread. If the variable could change, the copy would be
  stale. Reassigning `cutoff` after the lambda gives `local variables referenced
  from a lambda expression must be final or effectively final`.
  :::
  :::accordion-item{label="Predicate against Function: when would you use each?" icon="i-lucide-message-circle"}
  `Predicate<T>` answers yes or no (`test` returns `boolean`) and is what
  `filter` and `removeIf` take. `Function<T, R>` turns a T into an R and is what
  `map` takes. `marks -> marks >= 40` is a predicate; `marks -> grade(marks)`
  is a function.
  :::
::
