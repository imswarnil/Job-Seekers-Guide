A lambda hands Java one rule. A **stream** chains several rules into a
pipeline: take every student, keep the ones in CSE, keep the ones who passed,
turn each into a name, collect the names. One statement, no loop, and each step
reads as what it does.

## Why this matters in a job

Streams are the most visible part of modern Java. In a service company code
review, a twelve-line loop that builds a list is often sent back with "use a
stream". In interviews, Java 8 questions reach streams within a minute:
"difference between map and flatMap", "intermediate against terminal
operations", "is a stream lazy?", "can you reuse a stream?", and the live coding
favourite, "use streams to find the second highest mark" or "count students by
department".

## A stream is an assembly line

Picture the exam cell processing answer sheets on a long table. At one end,
the pile (the **source**). Along the table, clerks who each do one thing: one
removes sheets from other departments (**filter**), one writes the total on the
cover (**map**), one sorts. At the far end, somebody who produces the result:
a count, a list, a sum (the **terminal operation**).

Two facts about this table matter more than any method name:

1. **Nothing moves until someone stands at the end.** The clerks wait. Build a
   pipeline with no terminal operation and no work is done. That is
   **laziness**.
2. **The sheets pass through once.** When the line has run, it is finished. A
   stream cannot be reused.

A stream is **not** a collection. It holds no data of its own; it describes a
computation over data that lives somewhere else, and the source is never
changed.

::flow{direction="horizontal" caption="Every stream has the same three-part shape."}
  :::flow-step{label="Source" icon="i-lucide-database"}
  `students.stream()`, `Arrays.stream(marks)`, `IntStream.range(1, 6)`.
  :::
  :::flow-step{label="Intermediate operations" icon="i-lucide-filter" highlight}
  `filter`, `map`, `sorted`, `distinct`, `limit`, `skip`. Each returns a new
  stream. Zero or more of them. Lazy.
  :::
  :::flow-step{label="Terminal operation" icon="i-lucide-flag"}
  `toList`, `count`, `reduce`, `forEach`, `anyMatch`, `findFirst`,
  `collect`. Exactly one. It triggers the work and closes the stream.
  :::
::

## Syntax

```java
List<String> result = students.stream()        // source
    .filter(s -> s.marks() >= 40)              // keep matching elements (Predicate)
    .map(Student::name)                        // transform each element (Function)
    .toList();                                 // terminal: gather into a List
```

```java [StreamBasics.java]
import java.util.*;

public class StreamBasics {
  record Student(String name, String department, int marks) {}

  public static void main(String[] args) {
    List<Student> students = List.of(
        new Student("Anita", "CSE", 78),
        new Student("Vikram", "ECE", 55),
        new Student("Farah", "CSE", 92),
        new Student("Rohit", "MECH", 38),
        new Student("Meera", "CSE", 64));

    // The loop way
    List<String> passedCse = new ArrayList<>();
    for (Student s : students) {
      if (s.department().equals("CSE") && s.marks() >= 40) {
        passedCse.add(s.name().toUpperCase());
      }
    }
    System.out.println("Loop:   " + passedCse);

    // The stream way: source -> intermediate operations -> terminal operation
    List<String> viaStream = students.stream()
        .filter(s -> s.department().equals("CSE"))
        .filter(s -> s.marks() >= 40)
        .map(s -> s.name().toUpperCase())
        .toList();
    System.out.println("Stream: " + viaStream);

    int total = students.stream().map(Student::marks).reduce(0, Integer::sum);
    System.out.println("Total marks: " + total);

    double average = students.stream().mapToInt(Student::marks).average().orElse(0);
    System.out.println("Average: " + average);

    System.out.println("Top 3: " + students.stream()
        .sorted(Comparator.comparingInt(Student::marks).reversed())
        .limit(3)
        .map(Student::name)
        .toList());

    System.out.println("Anyone failed? " + students.stream().anyMatch(s -> s.marks() < 40));
    System.out.println("All above 30? " + students.stream().allMatch(s -> s.marks() > 30));
    System.out.println("Departments: " + students.stream().map(Student::department).distinct().toList());
    System.out.println("CSE count: " + students.stream().filter(s -> s.department().equals("CSE")).count());
    System.out.println("Highest: " + students.stream().mapToInt(Student::marks).max().getAsInt());
  }
}
```

```bash [Terminal]
javac StreamBasics.java && java StreamBasics
```

```text [Output]
Loop:   [ANITA, FARAH, MEERA]
Stream: [ANITA, FARAH, MEERA]
Total marks: 327
Average: 65.4
Top 3: [Farah, Anita, Meera]
Anyone failed? true
All above 30? true
Departments: [CSE, ECE, MECH]
CSE count: 3
Highest: 92
```

The operations you will use nine times out of ten:

| Operation | Kind | What it does |
| --- | --- | --- |
| `filter(Predicate)` | intermediate | Keeps elements for which the predicate is true |
| `map(Function)` | intermediate | Turns each element into something else |
| `sorted()` / `sorted(Comparator)` | intermediate | Sorts (natural order, or by the comparator) |
| `distinct()` | intermediate | Removes duplicates, using `equals` |
| `limit(n)` / `skip(n)` | intermediate | First n / all but the first n |
| `toList()` | terminal | An unmodifiable `List` (Java 16+) |
| `count()` | terminal | How many, as a `long` |
| `reduce(identity, BinaryOperator)` | terminal | Folds everything into one value |
| `anyMatch` / `allMatch` / `noneMatch` | terminal | `boolean`, and stop early once the answer is known |
| `findFirst()` / `max` / `min` | terminal | An `Optional`, because there may be nothing |
| `forEach(Consumer)` | terminal | Does something with each element |

### reduce

`reduce(0, Integer::sum)` starts with 0 (the **identity**) and combines it with
each element in turn: `0 + 78`, then `78 + 55`, and so on. The identity must be
the value that changes nothing: 0 for addition, 1 for multiplication. With no
identity, `reduce(Integer::sum)` returns an `Optional<Integer>`, because an empty
stream has no sum to give.

### Laziness and single use, proved

```java [Lazy.java]
import java.util.*;
import java.util.stream.*;

public class Lazy {
  public static void main(String[] args) {
    List<Integer> marks = List.of(78, 55, 92, 38, 64);

    Stream<Integer> pipeline = marks.stream()
        .filter(m -> { System.out.println("  filter " + m); return m >= 60; })
        .map(m -> { System.out.println("  map " + m); return m + 5; });
    System.out.println("Pipeline built. Nothing has run yet.");

    Optional<Integer> first = pipeline.findFirst();
    System.out.println("First: " + first.get());

    try {
      pipeline.count();
    } catch (IllegalStateException e) {
      System.out.println(e.getMessage());
    }
  }
}
```

```text [Output]
Pipeline built. Nothing has run yet.
  filter 78
  map 78
First: 83
stream has already been operated upon or closed
```

Three things in six lines of output. The filter and map printed nothing until
`findFirst` ran. Each element goes through the **whole** pipeline before the
next starts (filter 78, map 78), rather than all filters and then all maps. And
because `findFirst` had its answer after one element, 55, 92, 38 and 64 were
never looked at. Using the stream a second time threw `IllegalStateException`.

### Primitive streams

`Stream<Integer>` boxes every number into an `Integer` object. `IntStream`,
`LongStream` and `DoubleStream` hold primitives and add `sum`, `average` and
`summaryStatistics`. `mapToInt` converts; `mapToObj` and `boxed` go back.

```java [IntStreams.java]
import java.util.IntSummaryStatistics;
import java.util.stream.*;

public class IntStreams {
  public static void main(String[] args) {
    System.out.println(IntStream.rangeClosed(1, 5).sum());
    System.out.println(IntStream.range(1801, 1806).mapToObj(r -> "CSE" + r).collect(Collectors.joining(", ")));
    IntSummaryStatistics stats = IntStream.of(78, 55, 92, 38, 64).summaryStatistics();
    System.out.println(stats);
    System.out.println(Stream.iterate(1, n -> n * 2).limit(6).toList());
  }
}
```

```text [Output]
15
CSE1801, CSE1802, CSE1803, CSE1804, CSE1805
IntSummaryStatistics{count=5, sum=327, min=38, average=65.400000, max=92}
[1, 2, 4, 8, 16, 32]
```

`range(1801, 1806)` stops before 1806; `rangeClosed` includes the end.
`Stream.iterate` makes an infinite stream, which is fine only because `limit(6)`
cuts it off. Leave out the `limit` and it runs until memory runs out.

## Real use case

Result processing is the classic fit: many small questions asked of one list.
A results service in a real codebase is full of lines like these:

```java
double cseAverage = students.stream()
    .filter(s -> s.department().equals("CSE"))
    .mapToInt(Student::marks)
    .average()
    .orElse(0);

List<String> backlogList = students.stream()
    .filter(s -> s.marks() < 40)
    .map(Student::name)
    .sorted()
    .toList();

boolean anyAbsent = attendance.stream().anyMatch(a -> a.percentage() < 75);
```

Each one is a sentence. The loop versions of the same three would be about
twenty lines with three accumulator variables, and each accumulator is a place
for an off-by-one or a forgotten reset. Grouping ("average marks **per**
department") is the next lesson.

::real-life{title="When a loop is still the right answer" source="Code review"}
Streams are not always better. If you need to stop early on a complex
condition, update several things at once, throw a checked exception, or debug
step by step, a plain `for` loop is often clearer. A fair rule: if the stream
needs a comment to explain it, write the loop.
::

## What confuses people here

::compare{caption="Using a stream as a fancy for-each."}
  :::compare-side{label="Side effects in forEach" verdict="wrong"}
  ```java
  List<Integer> withBonus = new ArrayList<>();
  marks.stream()
       .map(m -> m + 5)
       .forEach(withBonus::add);
  ```
  It works, prints `[83, 60, 97]`, and breaks the moment somebody adds
  `.parallel()`, because `ArrayList` is not safe for several threads.
  :::
  :::compare-side{label="Let the terminal operation build it" verdict="right"}
  ```java
  List<Integer> withBonus = marks.stream()
       .map(m -> m + 5)
       .toList();
  ```
  Same output, no shared state, and the source list stays `[78, 55, 92]`.
  :::
::

- **`toList()` is unmodifiable.** Calling `add` on its result throws
  `UnsupportedOperationException`. If you need to add to it, use
  `.collect(Collectors.toCollection(ArrayList::new))`.
- **A stream does not change its source.** `map(m -> m + 5)` produces new
  values; the original list is untouched.
- **`peek` is for debugging only.** It is an intermediate operation and, like
  every one, does nothing without a terminal.
- **`count()` returns a `long`,** not an `int`.
- **Parallel streams** (`parallelStream()`) split work across cores. They help
  on large CPU-heavy work and hurt on small lists or anything with shared state.
  Do not add them for speed without measuring.

## Interview questions

::accordion
  :::accordion-item{label="What is the difference between intermediate and terminal operations?" icon="i-lucide-message-circle"}
  Intermediate operations (`filter`, `map`, `sorted`, `distinct`, `limit`)
  return a new stream and are lazy: they do nothing on their own. A terminal
  operation (`toList`, `count`, `reduce`, `forEach`, `findFirst`) produces a
  result or side effect, runs the pipeline, and closes the stream. In
  `Lazy.java` nothing printed until `findFirst` was called.
  :::
  :::accordion-item{label="Can a stream be reused?" icon="i-lucide-message-circle"}
  No. After a terminal operation the stream is consumed. A second terminal
  operation throws `IllegalStateException: stream has already been operated
  upon or closed`. Create a new stream from the source instead:
  `students.stream()` again.
  :::
  :::accordion-item{label="What is the difference between a Collection and a Stream?" icon="i-lucide-message-circle"}
  A collection stores data and can be read many times. A stream stores nothing;
  it is a one-time pipeline of operations over a source, evaluated lazily, and
  never modifies that source. A collection is a noun; a stream is a verb.
  :::
  :::accordion-item{label="Find the second highest mark using streams." icon="i-lucide-message-circle"}
  ```java
  int second = marks.stream()
      .distinct()
      .sorted(Comparator.reverseOrder())
      .skip(1)
      .findFirst()
      .orElseThrow();
  ```
  `distinct` so that two students on 92 do not make 92 the second highest.
  `findFirst` returns an `Optional` because there may be no second value.
  :::
  :::accordion-item{label="What does reduce do? What is the identity?" icon="i-lucide-message-circle"}
  It combines all elements into one value with a `BinaryOperator`.
  `reduce(0, Integer::sum)` computes `((0 + 78) + 55) + ...`. The identity is
  the starting value that leaves any element unchanged when combined: 0 for
  sum, 1 for product. Without it, `reduce` returns an `Optional`.
  :::
  :::accordion-item{label="map against mapToInt: why does it matter?" icon="i-lucide-message-circle"}
  `map(Student::marks)` gives a `Stream<Integer>`, a stream of boxed objects.
  `mapToInt(Student::marks)` gives an `IntStream` of primitives, which avoids
  boxing and adds `sum()`, `average()` and `summaryStatistics()`.
  :::
::
