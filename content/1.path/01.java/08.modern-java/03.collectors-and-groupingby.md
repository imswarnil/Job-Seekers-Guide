`toList()` and `count()` answer one question about the whole list. The exam
cell's real questions are per group: how many students in each department,
the average per department, who passed and who did not. A **collector** is the
recipe `collect` uses to build the answer, and `groupingBy` is the one you will
use most.

## Why this matters in a job

"Group these by X and count them" is the most common live-coding stream
question in Java interviews, because it replaces fifteen lines of map-handling
loop with one statement and shows at once whether you know the API. At work,
every report and dashboard endpoint is some version of it: orders per day,
students per branch, fees due per semester.

The `toMap` duplicate-key exception is also a real production failure. It works
in testing with clean data and throws the first time two rows share a key.

## A collector is the last clerk on the line

In the assembly line from the last lesson, the terminal operation is the clerk
at the end. `collect` is a clerk who can be told **how** to pack the results:
into a box (`toList`), into a box with no repeats (`toSet`), into labelled
folders by key (`toMap`), into one line of text (`joining`), or into a filing
cabinet with one drawer per department (`groupingBy`), where each drawer can
itself be counted, averaged or listed.

All of these live as static methods on the class `java.util.stream.Collectors`.

## Syntax

```java
stream.collect(Collectors.toSet())
stream.collect(Collectors.toMap(keyFunction, valueFunction))
stream.collect(Collectors.joining(", "))
stream.collect(Collectors.groupingBy(classifier))                    // Map<K, List<T>>
stream.collect(Collectors.groupingBy(classifier, downstream))        // Map<K, whatever downstream makes>
stream.collect(Collectors.partitioningBy(predicate))                 // Map<Boolean, List<T>>
```

The second argument to `groupingBy` is a **downstream collector**: what to do
with each group once it is formed. Without one, each group is a `List`.

```java [Collect.java]
import java.util.*;
import java.util.stream.*;

public class Collect {
  record Student(String roll, String name, String department, int marks) {}

  public static void main(String[] args) {
    List<Student> students = List.of(
        new Student("1801", "Anita", "CSE", 78),
        new Student("1802", "Vikram", "ECE", 55),
        new Student("1803", "Farah", "CSE", 92),
        new Student("1804", "Rohit", "MECH", 38),
        new Student("1805", "Meera", "CSE", 64),
        new Student("1806", "Imran", "ECE", 81));

    Set<String> departments = students.stream()
        .map(Student::department).collect(Collectors.toSet());
    System.out.println("toSet:     " + new TreeSet<>(departments));

    Map<String, String> byRoll = students.stream()
        .collect(Collectors.toMap(Student::roll, Student::name));
    System.out.println("toMap:     " + new TreeMap<>(byRoll));

    String names = students.stream().map(Student::name)
        .collect(Collectors.joining(", ", "[", "]"));
    System.out.println("joining:   " + names);

    Map<String, List<Student>> byDept = students.stream()
        .collect(Collectors.groupingBy(Student::department));
    byDept.forEach((dept, list) ->
        System.out.println("  " + dept + " -> " + list.stream().map(Student::name).toList()));

    Map<String, Long> countByDept = students.stream()
        .collect(Collectors.groupingBy(Student::department, TreeMap::new, Collectors.counting()));
    System.out.println("counting:  " + countByDept);

    Map<String, Double> avgByDept = students.stream()
        .collect(Collectors.groupingBy(Student::department, TreeMap::new,
                 Collectors.averagingInt(Student::marks)));
    System.out.println("averaging: " + avgByDept);

    Map<String, Optional<Student>> topperByDept = students.stream()
        .collect(Collectors.groupingBy(Student::department, TreeMap::new,
                 Collectors.maxBy(Comparator.comparingInt(Student::marks))));
    topperByDept.forEach((d, s) -> System.out.println("  topper " + d + ": " + s.get().name()));

    Map<String, List<String>> namesByDept = students.stream()
        .collect(Collectors.groupingBy(Student::department, TreeMap::new,
                 Collectors.mapping(Student::name, Collectors.toList())));
    System.out.println("mapping:   " + namesByDept);

    Map<Boolean, List<String>> passFail = students.stream()
        .collect(Collectors.partitioningBy(s -> s.marks() >= 40,
                 Collectors.mapping(Student::name, Collectors.toList())));
    System.out.println("partition: " + passFail);

    int second = students.stream().map(Student::marks).distinct()
        .sorted(Comparator.reverseOrder()).skip(1).findFirst().orElseThrow();
    System.out.println("second highest: " + second);
  }
}
```

The downstream collectors worth knowing: `counting()`, `summingInt`,
`averagingInt`/`averagingDouble`, `maxBy`/`minBy` (which return an `Optional`,
because a group could in principle be empty), `mapping(f, toList())` to keep
only one field, and `toSet()`.

### partitioningBy

`partitioningBy` is `groupingBy` with a yes-or-no classifier. The map always
has exactly two keys, `false` and `true`, even if one of the lists is empty.
Use it for pass against fail, eligible against not eligible.

### flatMap: one level of lists removed

`map` turns each element into exactly one thing. If each student has a list of
electives, `map` gives you a list of lists. `flatMap` turns each element into a
**stream** and joins all those streams into one.

```java [FlatMap.java]
import java.util.*;
import java.util.stream.*;

public class FlatMap {
  record Student(String name, List<String> electives) {}

  public static void main(String[] args) {
    List<Student> students = List.of(
        new Student("Anita", List.of("Cloud", "ML")),
        new Student("Farah", List.of("ML", "IoT")),
        new Student("Rohit", List.of()));

    List<List<String>> nested = students.stream().map(Student::electives).toList();
    System.out.println("map:     " + nested);

    List<String> flat = students.stream()
        .flatMap(s -> s.electives().stream())
        .distinct()
        .sorted()
        .toList();
    System.out.println("flatMap: " + flat);
  }
}
```

```text [Output]
map:     [[Cloud, ML], [ML, IoT], []]
flatMap: [Cloud, IoT, ML]
```

## Real use case

A placement cell dashboard: offers per company, average package per
department, the students not yet placed. Before streams this was a
`HashMap<String, List<...>>`, a loop, and a `if (!map.containsKey(k)) map.put(k, new ArrayList<>())`
dance for every report. Now each report is one statement:

```java
Map<String, Long> offersPerCompany = placements.stream()
    .collect(Collectors.groupingBy(Placement::company, Collectors.counting()));

Map<String, Double> avgPackageByDept = placements.stream()
    .collect(Collectors.groupingBy(p -> p.student().department(),
             Collectors.averagingDouble(Placement::packageLpa)));

Map<Boolean, List<Student>> placedOrNot = students.stream()
    .collect(Collectors.partitioningBy(s -> placedRolls.contains(s.roll())));
```

::real-life{title="The loop it replaces" source="Every reporting endpoint"}
The pre-Java 8 version of "count per department" is a map, a loop, a
`containsKey` check, a `get`, an increment and a `put`. It is about eight lines
and a classic place to forget the first-time case. `groupingBy(..., counting())`
cannot forget it. (`Map.merge(dept, 1L, Long::sum)` is the loop-based
equivalent, and worth knowing too.)
::

## What confuses people here

### The toMap duplicate key

```java [DuplicateKey.java]
import java.util.*;
import java.util.stream.*;

public class DuplicateKey {
  record Student(String name, String department, int marks) {}

  public static void main(String[] args) {
    List<Student> students = List.of(
        new Student("Anita", "CSE", 78),
        new Student("Farah", "CSE", 92),
        new Student("Vikram", "ECE", 55));

    // Keep the higher mark when two students share a department
    Map<String, Integer> best = students.stream()
        .collect(Collectors.toMap(Student::department, Student::marks, Math::max));
    System.out.println(best);

    Map<String, String> byDept = students.stream()
        .collect(Collectors.toMap(Student::department, Student::name));
    System.out.println(byDept);
  }
}
```

```text [Output]
{CSE=92, ECE=55}
Exception in thread "main" java.lang.IllegalStateException: Duplicate key CSE (attempted merging values Anita and Farah)
	at java.base/java.util.stream.Collectors.duplicateKeyException(Collectors.java:135)
	...
	at DuplicateKey.main(DuplicateKey.java:19)
```

::compare{caption="Two-argument toMap assumes keys are unique. Real data disagrees."}
  :::compare-side{label="No merge function" verdict="wrong"}
  ```java
  Collectors.toMap(Student::department, Student::name)
  ```
  Works until two students share a department, then throws
  `IllegalStateException: Duplicate key`.
  :::
  :::compare-side{label="Say what happens on a clash" verdict="right"}
  ```java
  Collectors.toMap(Student::department, Student::marks, Math::max)
  ```
  The third argument decides: keep the higher mark. If you wanted all of them,
  you wanted `groupingBy`.
  :::
::

- **`groupingBy` gives a `HashMap`** by default. Its iteration order is not
  guaranteed, so tests that compare printed output can pass on one machine and
  fail on another. Pass `TreeMap::new` when order matters.
- **`toMap` rejects `null` values** with a `NullPointerException`, even though
  `HashMap` itself allows them.
- **`Collectors.toList()` against `Stream.toList()`**: the collector gives a
  modifiable `ArrayList` in practice; `toList()` (Java 16) gives an unmodifiable
  list. Both are fine for reading.
- **`counting()` returns `Long`**, so the map is `Map<String, Long>`, not
  `Map<String, Integer>`.

## Interview questions

::accordion
  :::accordion-item{label="Count students in each department using streams." icon="i-lucide-message-circle"}
  ```java
  Map<String, Long> countByDept = students.stream()
      .collect(Collectors.groupingBy(Student::department, Collectors.counting()));
  ```
  On the data above: `{CSE=3, ECE=2, MECH=1}`. Mention that the value type is
  `Long`, and that you would pass `TreeMap::new` if the order mattered.
  :::
  :::accordion-item{label="What is the difference between map and flatMap?" icon="i-lucide-message-circle"}
  `map` turns each element into exactly one element. `flatMap` turns each
  element into a stream and flattens all of them into one stream. With a list
  of electives per student, `map` gave `[[Cloud, ML], [ML, IoT], []]` and
  `flatMap` gave the electives themselves.
  :::
  :::accordion-item{label="What happens when toMap meets a duplicate key?" icon="i-lucide-message-circle"}
  The two-argument form throws `IllegalStateException: Duplicate key CSE`. The
  three-argument form takes a merge function that decides which value to keep,
  such as `Math::max` or `(a, b) -> a`.
  :::
  :::accordion-item{label="groupingBy against partitioningBy?" icon="i-lucide-message-circle"}
  `groupingBy` takes a function and makes one group per distinct key.
  `partitioningBy` takes a predicate and always makes exactly two groups,
  keyed `false` and `true`, even if one is empty.
  :::
  :::accordion-item{label="Find the highest scorer in each department." icon="i-lucide-message-circle"}
  ```java
  Map<String, Optional<Student>> topper = students.stream()
      .collect(Collectors.groupingBy(Student::department,
               Collectors.maxBy(Comparator.comparingInt(Student::marks))));
  ```
  `maxBy` returns an `Optional` per group. The output above was Farah for CSE,
  Imran for ECE and Rohit for MECH.
  :::
  :::accordion-item{label="Join all student names into one comma-separated string." icon="i-lucide-message-circle"}
  `students.stream().map(Student::name).collect(Collectors.joining(", "))`.
  The three-argument form adds a prefix and suffix:
  `joining(", ", "[", "]")` gave `[Anita, Vikram, Farah, Rohit, Meera, Imran]`.
  :::
::
