`ArrayList` was the default in every example of the last lesson. It is worth
knowing exactly what it is, because "ArrayList or LinkedList?" is asked in
nearly every Java interview, and the textbook answer most people give is only
half true.

## Why this matters in a job

A **List** is an ordered collection that allows duplicates and lets you reach
any element by its position (its **index**, from 0). Most data you touch at
work arrives as one: rows from a database query, lines of an uploaded file,
the students in a batch.

Two bugs in this lesson reach real code often. `remove(2)` on a list of
numbers removes the wrong thing. And `add` on a list built with `List.of` or
`Arrays.asList` throws at run time, usually in a method far from where the list
was made.

## Two ways to keep a register

Picture two ways of keeping the attendance register.

- **ArrayList** is a printed register with numbered lines. Finding line 37 is
  instant: you turn to it. But writing a new name at line 1 means rewriting
  every name below it one line down. And when the pages run out, the office
  buys a bigger register and copies everything across.
- **LinkedList** is a chain of index cards, where each card says who comes
  before and after it. Adding a card at the front is instant: change two
  pointers. But finding the 37th card means counting from the start, one card
  at a time.

## Syntax

The methods you will use daily, which both classes share because both
implement `List`:

```java [ListBasics.java]
import java.util.*;

public class ListBasics {
  public static void main(String[] args) {
    List<String> students = new ArrayList<>();
    students.add("Anita");                 // append
    students.add("Vikram");
    students.add("Rohit");
    students.add(1, "Farah");              // insert at index 1, others shift right
    System.out.println(students);

    System.out.println("get(2):        " + students.get(2));
    students.set(0, "Anita Rao");          // replace
    System.out.println("indexOf Rohit: " + students.indexOf("Rohit"));
    System.out.println("contains Meera: " + students.contains("Meera"));

    students.remove("Vikram");             // by value
    students.remove(0);                    // by index
    System.out.println("after removes: " + students + " size " + students.size());

    List<String> more = List.of("Meera", "Arjun");
    students.addAll(more);
    System.out.println("subList(1,3):  " + students.subList(1, 3));

    for (int i = 0; i < students.size(); i++) {
      System.out.println((i + 1) + ". " + students.get(i));
    }
  }
}
```

```bash [Terminal]
javac ListBasics.java && java ListBasics
```

### How an ArrayList grows

Inside, an `ArrayList` is an ordinary `Object[]` array plus a count of how many
slots are used. The array's length is the **capacity**; the count is the
**size**. When you add to a full array, it creates a new one **1.5 times** as
large and copies everything across. You can watch it happen:

```java [Growth.java]
import java.lang.reflect.Field;
import java.util.*;

public class Growth {
  public static void main(String[] args) throws Exception {
    ArrayList<Integer> rolls = new ArrayList<>();
    Field f = ArrayList.class.getDeclaredField("elementData");
    f.setAccessible(true);
    int lastCapacity = -1;
    for (int i = 1; i <= 50; i++) {
      rolls.add(i);
      int capacity = ((Object[]) f.get(rolls)).length;
      if (capacity != lastCapacity) {
        System.out.println("size " + rolls.size() + " -> capacity " + capacity);
        lastCapacity = capacity;
      }
    }
  }
}
```

```bash [Terminal]
java --add-opens java.base/java.util=ALL-UNNAMED Growth.java
```

```text [Output]
size 1 -> capacity 10
size 11 -> capacity 15
size 16 -> capacity 22
size 23 -> capacity 33
size 34 -> capacity 49
size 50 -> capacity 73
```

The code reads a private field with **reflection**, which Java blocks unless
you pass `--add-opens`; never do this in real code, it is only for looking
inside. The numbers are the point: an empty `ArrayList` starts with no array,
gets 10 slots on the first `add`, then 15, 22, 33, 49, 73. Each step is the old
capacity plus half of it.

Copying sounds expensive, and each copy is. But copies get rarer as the list
grows, so averaged over all the adds, `add` at the end costs a constant amount
of work. That is called **amortised O(1)**, and it is the phrase the
interviewer wants. If you know you will add 40,000 items, `new
ArrayList<>(40_000)` skips all the copying.

### The costs, side by side

| Operation | ArrayList | LinkedList |
| --- | --- | --- |
| `get(i)`, `set(i, x)` | O(1): jump to the slot | O(n): walk from the nearer end |
| `add(x)` at the end | amortised O(1) | O(1) |
| `add(0, x)` or `remove(0)` | O(n): shift everything | O(1) |
| `add` or `remove` in the middle | O(n): shift | O(n) to walk there, then O(1) |
| `contains(x)` | O(n) | O(n) |
| Memory per element | one reference | a node with three references |

**O(1)** means the time does not grow with the size of the list; **O(n)**
means it grows in proportion. The DSA track makes this precise. Here is what it
means in milliseconds on my machine with 100,000 items (your numbers will
differ; the gap will not):

```java [ListRace.java]
import java.util.*;

public class ListRace {
  static long time(Runnable r) {
    long start = System.nanoTime();
    r.run();
    return (System.nanoTime() - start) / 1_000_000;
  }

  public static void main(String[] args) {
    int n = 100_000;
    List<Integer> array = new ArrayList<>();
    List<Integer> linked = new LinkedList<>();
    for (int i = 0; i < n; i++) { array.add(i); linked.add(i); }

    System.out.println("get(i) for every i:");
    System.out.println("  ArrayList  " + time(() -> { long s = 0; for (int i = 0; i < n; i++) s += array.get(i); }) + " ms");
    System.out.println("  LinkedList " + time(() -> { long s = 0; for (int i = 0; i < n; i++) s += linked.get(i); }) + " ms");

    System.out.println("add(0, x) 50,000 times at the front:");
    System.out.println("  ArrayList  " + time(() -> { for (int i = 0; i < 50_000; i++) array.add(0, i); }) + " ms");
    System.out.println("  LinkedList " + time(() -> { for (int i = 0; i < 50_000; i++) linked.add(0, i); }) + " ms");
  }
}
```

```text [Output]
get(i) for every i:
  ArrayList  1 ms
  LinkedList 4497 ms
add(0, x) 50,000 times at the front:
  ArrayList  509 ms
  LinkedList 2 ms
```

A `for` loop with `get(i)` over a `LinkedList` took four and a half seconds
for something an `ArrayList` does in a millisecond, because each `get(i)` walks
the chain from the start. Adding at the front is the reverse. That is the
honest trade-off, and in practice reading by position is far more common than
inserting at the front, which is why `ArrayList` is the default.

::side-note{kind="performance"}
If you need fast adds and removes at both ends (a queue or a stack), use
`ArrayDeque`, not `LinkedList`. It is an array used as a ring, with no node per
element, and it is faster than `LinkedList` at the very thing `LinkedList` is
supposed to be good at.
::

## Real use case

The exam results for a batch arrive as a list. Remove the absentees, rank the
rest by marks, and take the top three for the notice board.

```java [ResultsList.java]
import java.util.*;

public class ResultsList {
  record Result(String rollNumber, String name, int marks) { }

  public static void main(String[] args) {
    List<Result> results = new ArrayList<>(List.of(
        new Result("CS1801", "Anita",  78),
        new Result("CS1802", "Vikram", -1),     // -1: absent
        new Result("CS1803", "Farah",  92),
        new Result("CS1804", "Rohit",  35),
        new Result("CS1805", "Meera",  88),
        new Result("CS1806", "Arjun",  -1)));

    results.removeIf(r -> r.marks() < 0);                  // drop absentees
    results.sort(Comparator.comparingInt(Result::marks).reversed());

    List<Result> topThree = results.subList(0, Math.min(3, results.size()));
    System.out.println("Present: " + results.size());
    for (int i = 0; i < topThree.size(); i++) {
      Result r = topThree.get(i);
      System.out.println("Rank " + (i + 1) + ": " + r.name() + " " + r.marks());
    }
  }
}
```

```text [Output]
Present: 4
Rank 1: Farah 92
Rank 2: Meera 88
Rank 3: Anita 78
```

`removeIf` removes every element matching a condition, safely, in one pass
(removing inside a `for` loop is the subject of the iterator lesson).
`Comparator.comparingInt(...).reversed()` sorts highest first; comparators get
their own lesson. `Math.min(3, results.size())` guards the day only two
students turn up, where `subList(0, 3)` would throw.

## What confuses people here

### remove(2) on a list of numbers

```java [RemoveTrap.java]
import java.util.*;

public class RemoveTrap {
  public static void main(String[] args) {
    List<Integer> marks = new ArrayList<>(List.of(78, 2, 64, 91));

    marks.remove(2);                        // remove(int index): removes 64
    System.out.println(marks);

    marks.remove(Integer.valueOf(2));       // remove(Object): removes the value 2
    System.out.println(marks);
  }
}
```

```text [Output]
[78, 2, 91]
[78, 91]
```

`List` has two overloads, `remove(int index)` and `remove(Object o)`. The
literal `2` is an `int`, and an exact match beats boxing, so Java removes
**index** 2. To remove the value, pass an `Integer`.

### Lists you cannot change

```java [Immutable.java]
import java.util.*;

public class Immutable {
  public static void main(String[] args) {
    List<String> fixed = Arrays.asList("Java", "DBMS", "OS");
    fixed.set(0, "Core Java");             // allowed: same size
    System.out.println(fixed);

    List<String> subjects = List.of("Java", "DBMS", "OS");
    try {
      subjects.add("Networks");
    } catch (UnsupportedOperationException e) {
      System.out.println("List.of add: " + e);
    }
    try {
      fixed.add("Networks");
    } catch (UnsupportedOperationException e) {
      System.out.println("Arrays.asList add: " + e);
    }

    List<String> editable = new ArrayList<>(subjects);   // a real, changeable copy
    editable.add("Networks");
    System.out.println(editable);
  }
}
```

```text [Output]
[Core Java, DBMS, OS]
List.of add: java.lang.UnsupportedOperationException
Arrays.asList add: java.lang.UnsupportedOperationException
[Java, DBMS, OS, Networks]
```

::compare{caption="Three ways to make a list from values, and what each allows."}
  :::compare-side{label="List.of / Arrays.asList" verdict="wrong"}
  `List.of` allows nothing: no add, remove or set, and no `null` elements.
  `Arrays.asList` is a fixed-size view of an array: `set` works, `add` and
  `remove` throw. Both compile fine and fail at run time.
  :::
  :::compare-side{label="new ArrayList<>(...)" verdict="right"}
  When you need to change it, copy into a real `ArrayList`. When you want it
  unchangeable, `List.of` is exactly right, and it says so to every reader.
  :::
::

- **`subList` is a view, not a copy.** Changes through it change the original
  list, and changing the original's size afterwards makes the view throw.
- **`size()` is not capacity.** There is no public method for capacity; you
  only control it with the constructor or `ensureCapacity`.

## Interview questions

::accordion
  :::accordion-item{label="ArrayList or LinkedList: which would you use?" icon="i-lucide-message-circle"}
  `ArrayList` almost always. It gives O(1) `get(i)`, uses less memory and is
  friendly to the CPU cache because its elements sit together. `LinkedList`
  wins only at adding and removing at the ends or through an iterator, and for
  that `ArrayDeque` is usually better still. `ListRace.java` shows `get(i)` in a
  loop: 1 ms against about 4,500 ms.
  :::
  :::accordion-item{label="How does an ArrayList grow?" icon="i-lucide-message-circle"}
  It is backed by an `Object[]`. The first `add` creates 10 slots; when full,
  it allocates a new array 1.5 times the size and copies the elements across
  (10, 15, 22, 33, 49...). Because copies become rarer, adding at the end is
  amortised O(1).
  :::
  :::accordion-item{label="What does list.remove(2) do on a List<Integer>?" icon="i-lucide-message-circle"}
  It removes the element at **index** 2, because `remove(int)` is an exact
  match for the `int` literal. To remove the value 2, call
  `list.remove(Integer.valueOf(2))`.
  :::
  :::accordion-item{label="What is the difference between Arrays.asList and List.of?" icon="i-lucide-message-circle"}
  `Arrays.asList` returns a fixed-size list backed by the array: `set` works
  and writes through to the array, `add` and `remove` throw, and nulls are
  allowed. `List.of` (Java 9) is fully immutable and rejects nulls with a
  `NullPointerException`.
  :::
  :::accordion-item{label="ArrayList or Vector?" icon="i-lucide-message-circle"}
  `ArrayList`. `Vector` is the 1996 version with every method synchronised,
  and it doubles in size instead of growing by half. The locking costs time
  and rarely gives real thread safety, because most bugs are in sequences of
  calls, not single ones.
  :::
