A list happily holds Anita twice when she clicks "enrol" twice. A **Set** is a
collection that refuses duplicates: add something that is already there and
nothing happens. Java gives you three, and the only real difference between
them is the order you get back.

## Why this matters in a job

"Remove the duplicates" and "is this already in there?" are two of the most
common things business code asks. A roll-number upload with repeated rows, a
list of departments built from thousands of students, the set of students who
have already paid: all sets.

In interviews the questions are predictable: the difference between HashSet,
LinkedHashSet and TreeSet; how a HashSet knows two objects are duplicates;
whether a set allows `null`; and "find the duplicates in this array", which is
a set in three lines.

## A set is the guest list at the gate

At a college fest, the security guard has a guest list. When a name arrives,
he checks whether it is already ticked. If it is, the person is not let in
again. He does not care about the order people arrived in, only about whether
a name is there. That is a **HashSet**.

Now two variations. The registration desk wants the names **in the order
people arrived**: a **LinkedHashSet**. The certificate printer wants them **in
alphabetical order**: a **TreeSet**.

::feature-list{columns="3"}
  :::feature{icon="i-lucide-shuffle" title="HashSet"}
  No order promised. Fastest: `add`, `remove` and `contains` are O(1) on
  average. Allows one `null`.
  :::
  :::feature{icon="i-lucide-list-ordered" title="LinkedHashSet"}
  Keeps insertion order. Almost as fast; a little more memory for the links
  that remember the order.
  :::
  :::feature{icon="i-lucide-arrow-down-a-z" title="TreeSet"}
  Always sorted. O(log n) per operation. No `null`. Adds `first`, `floor`,
  `ceiling` and ranges.
  :::
::

**O(log n)** means the work grows very slowly: for a million items, about
twenty steps. The DSA track explains why a sorted tree gives that.

## Syntax

```java
Set<String> a = new HashSet<>();
Set<String> b = new LinkedHashSet<>();
Set<String> c = new TreeSet<>();
boolean added = a.add("CSE");      // false if it was already there
a.contains("CSE");  a.remove("CSE");  a.size();
```

The same six inserts into each:

```java [ThreeSets.java]
import java.util.*;

public class ThreeSets {
  public static void main(String[] args) {
    String[] departments = {"Mechanical", "CSE", "Civil", "ECE", "CSE", "Aero"};

    Set<String> hash = new HashSet<>();
    Set<String> linked = new LinkedHashSet<>();
    Set<String> tree = new TreeSet<>();
    for (String d : departments) {
      hash.add(d);
      linked.add(d);
      tree.add(d);
    }
    System.out.println("HashSet:       " + hash);
    System.out.println("LinkedHashSet: " + linked);
    System.out.println("TreeSet:       " + tree);

    boolean added = hash.add("CSE");
    System.out.println("add(CSE) again returned " + added + ", size " + hash.size());
    System.out.println("contains ECE? " + hash.contains("ECE"));
  }
}
```

```bash [Terminal]
javac ThreeSets.java && java ThreeSets
```

```text [Output]
HashSet:       [Civil, CSE, ECE, Mechanical, Aero]
LinkedHashSet: [Mechanical, CSE, Civil, ECE, Aero]
TreeSet:       [Aero, CSE, Civil, ECE, Mechanical]
add(CSE) again returned false, size 5
contains ECE? true
```

Look at the TreeSet line: `CSE` comes before `Civil`. Strings sort by
character code, and every capital letter comes before every lowercase one, so
`CS` beats `Ci`. Sorting "properly" needs a Comparator, which is two lessons
away.

### How a HashSet decides two things are the same

A `HashSet` is a `HashMap` underneath, using your elements as keys. To check
whether an element is already there it calls two methods on it:
`hashCode()`, to find the right bucket fast, then `equals()`, to compare within
that bucket. You met both in the equals and hashCode lesson. Here is what
happens when a class has neither:

```java [DuplicateStudents.java]
import java.util.*;

public class DuplicateStudents {
  static class Student {                       // no equals, no hashCode
    final String rollNumber;
    final String name;
    Student(String rollNumber, String name) { this.rollNumber = rollNumber; this.name = name; }
    public String toString() { return rollNumber; }
  }

  record StudentRecord(String rollNumber, String name) { }   // equals + hashCode generated

  public static void main(String[] args) {
    Set<Student> plain = new HashSet<>();
    plain.add(new Student("CS1801", "Anita"));
    plain.add(new Student("CS1801", "Anita"));
    System.out.println("class:  " + plain.size() + " " + plain);

    Set<StudentRecord> records = new HashSet<>();
    records.add(new StudentRecord("CS1801", "Anita"));
    records.add(new StudentRecord("CS1801", "Anita"));
    System.out.println("record: " + records.size() + " " + records);
  }
}
```

```text [Output]
class:  2 [CS1801, CS1801]
record: 1 [StudentRecord[rollNumber=CS1801, name=Anita]]
```

The set "of unique students" holds the same student twice. Without overrides,
`equals` and `hashCode` come from `Object` and compare **identity** (are these
the same object in memory?), and two `new` calls make two objects. A record
generates both from its fields, so the second add is refused. How the hashing
actually works inside is the next lesson.

### TreeSet: sorted, and it can answer "nearest"

Because a `TreeSet` keeps its elements sorted, it can answer questions a hash
set cannot: the smallest, the largest, the nearest below or above a value, and
everything in a range. These come from the `NavigableSet` interface, so declare
the variable as `TreeSet` (or `NavigableSet`) to use them.

```java [MarksBands.java]
import java.util.*;

public class MarksBands {
  public static void main(String[] args) {
    TreeSet<Integer> cutoffs = new TreeSet<>(List.of(40, 60, 75, 90));
    int marks = 68;

    System.out.println("first / last:  " + cutoffs.first() + " / " + cutoffs.last());
    System.out.println("floor(68):     " + cutoffs.floor(marks));    // highest <= 68
    System.out.println("ceiling(68):   " + cutoffs.ceiling(marks));  // lowest >= 68
    System.out.println("higher(75):    " + cutoffs.higher(75));      // strictly above
    System.out.println("headSet(75):   " + cutoffs.headSet(75));     // below 75
    System.out.println("tailSet(75):   " + cutoffs.tailSet(75));     // 75 and above
    System.out.println("descending:    " + cutoffs.descendingSet());
    System.out.println("floor(30):     " + cutoffs.floor(30));
  }
}
```

```text [Output]
first / last:  40 / 90
floor(68):     60
ceiling(68):   75
higher(75):    90
headSet(75):   [40, 60]
tailSet(75):   [75, 90]
descending:    [90, 75, 60, 40]
floor(30):     null
```

`floor(68)` is 60: a student with 68 has cleared the 60 band and not the 75
one. That one call replaces an `if` chain. `floor(30)` returns `null`, because
nothing is at or below 30, so check before unboxing it into an `int`.

### Set arithmetic

```java [SetOps.java]
import java.util.*;

public class SetOps {
  public static void main(String[] args) {
    Set<String> java = Set.of("Anita", "Farah", "Rohit", "Meera");
    Set<String> dbms = Set.of("Anita", "Vikram", "Meera");

    Set<String> union = new TreeSet<>(java);
    union.addAll(dbms);
    Set<String> both = new TreeSet<>(java);
    both.retainAll(dbms);
    Set<String> javaOnly = new TreeSet<>(java);
    javaOnly.removeAll(dbms);

    System.out.println("either: " + union);
    System.out.println("both:   " + both);
    System.out.println("Java only: " + javaOnly);
  }
}
```

```text [Output]
either: [Anita, Farah, Meera, Rohit, Vikram]
both:   [Anita, Meera]
Java only: [Farah, Rohit]
```

`addAll` is union, `retainAll` is intersection, `removeAll` is difference. All
three **change** the set they are called on, which is why each starts from a
fresh copy. `Set.of` sets are immutable, like `List.of` lists.

## Real use case

A spreadsheet of roll numbers is uploaded for hall tickets. Two students with
the same roll number means one of them gets the wrong ticket, so the upload
must report every duplicate before anything is printed.

```java [DuplicateRolls.java]
import java.util.*;

public class DuplicateRolls {
  public static void main(String[] args) {
    // Roll numbers from a spreadsheet upload
    String[] upload = {"CS1801", "CS1802", "CS1803", "CS1802", "CS1805", "CS1801", "CS1806"};

    Set<String> seen = new HashSet<>();
    Set<String> duplicates = new TreeSet<>();
    for (String roll : upload) {
      if (!seen.add(roll)) {          // add returns false if it was already there
        duplicates.add(roll);
      }
    }
    System.out.println(upload.length + " rows, " + seen.size() + " unique");
    System.out.println("Duplicated: " + duplicates);
  }
}
```

```text [Output]
7 rows, 5 unique
Duplicated: [CS1801, CS1802]
```

The trick is using the return value of `add`. There is no need to call
`contains` first and then `add`, which would search twice. The duplicates go
into a `TreeSet` so the report is sorted for whoever has to fix the
spreadsheet. This exact problem, "find the duplicates in an array", is a
written-round and first-round coding favourite.

::real-life{title="Sets at work" source="Validation, permissions, deduplication"}
Sets turn up wherever the question is membership: which roles a user has,
which students have already been emailed today (so a retry does not email them
twice), which ids arrived in both of two reports. A `contains` on a `HashSet`
of 40,000 roll numbers is as fast as on a set of 40; on a `List` it checks
every one.
::

## What confuses people here

```java [TreeTraps.java]
import java.util.*;

public class TreeTraps {
  static class Course {
    final String code;
    Course(String code) { this.code = code; }
  }

  public static void main(String[] args) {
    Set<String> hash = new HashSet<>();
    hash.add(null);
    System.out.println("HashSet with null: " + hash);

    try {
      new TreeSet<String>().add(null);
    } catch (NullPointerException e) {
      System.out.println("TreeSet.add(null): NullPointerException");
    }

    Set<Course> courses = new TreeSet<>();
    courses.add(new Course("CS201"));
  }
}
```

```text [Output]
HashSet with null: [null]
TreeSet.add(null): NullPointerException
Exception in thread "main" java.lang.ClassCastException: class TreeTraps$Course cannot be cast to class java.lang.Comparable (TreeTraps$Course is in unnamed module of loader 'app'; java.lang.Comparable is in module java.base of loader 'bootstrap')
	at java.base/java.util.TreeMap.compare(TreeMap.java:1604)
	at java.base/java.util.TreeMap.addEntryToEmptyMap(TreeMap.java:811)
	at java.base/java.util.TreeMap.put(TreeMap.java:820)
	at java.base/java.util.TreeMap.put(TreeMap.java:569)
	at java.base/java.util.TreeSet.add(TreeSet.java:259)
	at TreeTraps.main(TreeTraps.java:21)
```

::compare{caption="Two sets, two completely different ideas of what 'the same' means."}
  :::compare-side{label="HashSet" verdict="neutral"}
  Uses `hashCode()` then `equals()`. Elements do not need to be comparable,
  and one `null` is allowed.
  :::
  :::compare-side{label="TreeSet" verdict="neutral"}
  Uses `compareTo()` (or a Comparator) and nothing else. Elements must be
  comparable, or you get the `ClassCastException` above on the **first** add.
  It cannot compare `null`, so it throws. Two elements that compare as 0 count
  as duplicates, even if `equals` says otherwise.
  :::
::

- **The stack trace mentions `TreeMap`.** `TreeSet` is a `TreeMap` underneath,
  in the same way that `HashSet` is a `HashMap`. Knowing that answers half the questions in
  this lesson.
- **Changing an element after adding it** breaks a `HashSet`: its hash code
  changes, it sits in the wrong bucket, and `contains` stops finding it. The
  next lesson shows this with a map key. Use immutable elements, such as
  Strings and records.
- **Sets have no `get(index)`.** There is no position. Loop over it, or copy it
  into a list.

## Interview questions

::accordion
  :::accordion-item{label="HashSet, LinkedHashSet and TreeSet: what is the difference?" icon="i-lucide-message-circle"}
  Order and cost. HashSet: no order, O(1) average, one null allowed.
  LinkedHashSet: insertion order, O(1), slightly more memory. TreeSet: sorted,
  O(log n), no null, elements must be comparable. `ThreeSets.java` shows all
  three orders from the same inserts.
  :::
  :::accordion-item{label="How does a HashSet detect duplicates?" icon="i-lucide-message-circle"}
  It stores elements as keys of an internal `HashMap`. It uses `hashCode()` to
  pick a bucket, then `equals()` to compare with what is in that bucket. If a
  class overrides neither, two objects with equal fields are both kept, as
  `DuplicateStudents.java` shows (size 2).
  :::
  :::accordion-item{label="Find the duplicate elements in an array." icon="i-lucide-message-circle"}
  One pass with a set, using the boolean that `add` returns:

  ```java
  Set<String> seen = new HashSet<>();
  for (String roll : upload) {
    if (!seen.add(roll)) System.out.println("duplicate: " + roll);
  }
  ```

  O(n) time, against O(n²) for comparing every pair.
  :::
  :::accordion-item{label="Can a Set contain null?" icon="i-lucide-message-circle"}
  `HashSet` and `LinkedHashSet` allow one `null`. `TreeSet` throws
  `NullPointerException`, because it has to compare the element with others.
  `Set.of(...)` rejects `null` too.
  :::
  :::accordion-item{label="Why is contains faster on a HashSet than on an ArrayList?" icon="i-lucide-message-circle"}
  An `ArrayList` checks every element with `equals`: O(n). A `HashSet`
  computes the hash code, jumps to one bucket and checks the few elements
  there: O(1) on average.
  :::
::
