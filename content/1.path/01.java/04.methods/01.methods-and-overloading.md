The mark sheet program had the same "total a row" loop written twice. A
**method** is a named block of code you write once and call from anywhere, and
it is the first real tool for keeping a program you can still change next month.

## Why this matters in a job

Every code review you receive is partly about methods: this one does two
things, this name lies, this has seven parameters. In a real codebase nobody
writes a 300-line `main`; they write small methods with honest names and
call them.

In interviews, methods produce a steady set of questions: what a method
signature is, whether you can overload on return type, whether `main` can be
overloaded, and which overload Java picks when more than one fits. All of them
are answered below with code.

## A method is a recipe card

In a college canteen, the cook does not reinvent masala dosa for every order.
There is one recipe. You hand over the inputs (batter, filling), the recipe
runs, and a dosa comes back. In Java:

- the **inputs** are **parameters**, the variables in the brackets of the
  method's definition;
- the values you actually hand over when calling are **arguments**;
- what comes back is the **return value**, and its type is written before the
  name. `void` means nothing comes back.

## Syntax

```java
static returnType methodName(Type parameter1, Type parameter2) {
  // body
  return value;          // leave out for void
}
```

For now every method is `static`, which means you can call it straight from
`main` without creating an object first. What `static` really means gets its own
lesson in the objects chapter.

```java [GradeCalculator.java]
public class GradeCalculator {
  public static void main(String[] args) {
    int[] anita  = {78, 64, 81, 90};
    int[] vikram = {55, 72, 48, 61};

    printReport("Anita", anita);
    printReport("Vikram", vikram);
  }

  // parameters: a name and the marks. returns nothing: it prints.
  static void printReport(String name, int[] marks) {
    double avg = average(marks);
    System.out.printf("%-7s average %.2f grade %s%n", name, avg, grade(avg));
  }

  // returns a double; the caller decides what to do with it
  static double average(int[] marks) {
    if (marks.length == 0) {
      return 0;                      // leave early for the edge case
    }
    int total = 0;
    for (int m : marks) {
      total += m;
    }
    return (double) total / marks.length;
  }

  static String grade(double average) {
    if (average >= 75) return "A";
    if (average >= 60) return "B";
    if (average >= 40) return "C";
    return "F";
  }
}
```

```bash [Terminal]
javac GradeCalculator.java && java GradeCalculator
```

```text [Output]
Anita   average 78.25 grade A
Vikram  average 59.00 grade C
```

`return` does two things: it hands back a value and it **ends the method
immediately**. That is why `average` can check the empty case first and
`return 0` without an `else`. Returning early for edge cases keeps the main path
un-indented and readable.

### Scope: a parameter is a new variable

```java [Scope.java]
public class Scope {
  public static void main(String[] args) {
    int total = 0;
    addBonus(total);
    System.out.println("total in main: " + total);
  }

  static void addBonus(int total) {
    total += 5;
    System.out.println("total in addBonus: " + total);
  }
}
```

```text [Output]
total in addBonus: 5
total in main: 0
```

Two variables called `total`, in two methods, with nothing to do with each
other. The method got a **copy** of the value. Why that stays true even for
arrays and objects (and why it sometimes looks as if it does not) is the whole of
the next lesson.

### Overloading

**Overloading** is writing several methods with the same name and different
parameter lists. The compiler picks one at compile time by looking at the
arguments.

```java [Overloads.java]
public class Overloads {
  static double average(int a, int b)        { return (a + b) / 2.0; }
  static double average(int a, int b, int c) { return (a + b + c) / 3.0; }
  static double average(double[] marks) {
    double sum = 0;
    for (double m : marks) sum += m;
    return sum / marks.length;
  }

  static void record(int marks)     { System.out.println("int: " + marks); }
  static void record(long marks)    { System.out.println("long: " + marks); }
  static void record(Integer marks) { System.out.println("Integer: " + marks); }
  static void record(Object marks)  { System.out.println("Object: " + marks); }

  public static void main(String[] args) {
    System.out.println(average(70, 81));
    System.out.println(average(70, 81, 90));
    System.out.println(average(new double[] {72.5, 88.0}));

    byte b = 10;
    record(b);            // byte widens to int: the closest match
    record(5L);           // exact match: long
    record(Integer.valueOf(7));
    record("seventy");    // only Object fits a String
  }
}
```

```text [Output]
75.5
80.33333333333333
80.25
int: 10
long: 5
Integer: 7
Object: seventy
```

When no overload matches exactly, Java tries three things in a fixed order and
stops at the first that works:

::flow{numbered direction="horizontal" caption="Overload resolution. The earliest step that finds a match wins."}
  :::flow-step{label="Widening" icon="i-lucide-arrow-up-right" highlight}
  `int` to `long`, `float` to `double`: the primitive gets bigger.
  :::
  :::flow-step{label="Boxing" icon="i-lucide-package"}
  `int` to `Integer`: the primitive is wrapped in an object.
  :::
  :::flow-step{label="Varargs" icon="i-lucide-list"}
  `int` to `int...`: the last resort.
  :::
::

```java [WideningWins.java]
public class WideningWins {
  static void record(long marks)      { System.out.println("long (widening)"); }
  static void record(Integer marks)   { System.out.println("Integer (boxing)"); }
  static void record(int... marks)    { System.out.println("varargs"); }

  public static void main(String[] args) {
    record(78);          // an int literal: which one wins?
  }
}
```

```text [Output]
long (widening)
```

Most people guess `Integer`. Widening was the rule before boxing existed (Java
5), and it kept priority so old code would not change meaning.

## Real use case

The same pattern runs through every codebase you will join: a public method
that reads like a sentence, and small private helpers that each do one job. The
review comment that sends back a 90-line method is nearly always some version
of "what does this do? Answer in the method names." This is the shape a
reviewer wants.

```java
static String report(int[] marks) {
  return "Average: %.2f, highest: %d, passed: %d"
      .formatted(average(marks), highest(marks), countAtLeast(marks, 40));
}
```

::feature-list{columns="2"}
  :::feature{icon="i-lucide-tag" title="The name is a verb phrase"}
  `average`, `calculateAttendance`, `isEligible`. If you need "and" in the name,
  it is two methods.
  :::
  :::feature{icon="i-lucide-eye-off" title="No surprises"}
  It does what the name says and nothing else: no hidden printing, no changing
  its arguments.
  :::
  :::feature{icon="i-lucide-minimize-2" title="Few parameters"}
  Past three or four, you are usually missing an object. Classes, in chapter 5,
  are the fix.
  :::
  :::feature{icon="i-lucide-undo" title="Same input, same output"}
  A method that depends only on its parameters can be tested in one line.
  :::
::

Splitting a long method also finds bugs. Split a one-block report method into
`average`, `highest` and `countAtLeast`, and the empty-array case becomes
obvious in `average`: it divides by `marks.length` without checking it. In one
tangled block, nobody notices.

## What confuses people here

::compare{caption="Overloading on return type alone does not compile."}
  :::compare-side{label="Only the return type differs" verdict="wrong"}
  ```java
  static int parseMarks(String s)    { ... }
  static double parseMarks(String s) { ... }
  ```
  ```text
  error: method parseMarks(String) is already defined in class ReturnOnly
  ```
  At a call such as `parseMarks("78");` whose result is ignored, the compiler
  could not tell which you meant.
  :::
  :::compare-side{label="The parameter lists differ" verdict="right"}
  ```java
  static int parseMarks(String s)          { ... }
  static int parseMarks(String s, int max) { ... }
  ```
  Different number, types or order of parameters. That is overloading.
  :::
::

- **A missing `return`.** If any path through a non-`void` method can reach
  the end without returning, the compiler refuses with `error: missing return
  statement`. An `if (marks >= 40) return "PASS";` with no `else` does it.
- **An ambiguous call.** With `find(String)` and `find(StringBuilder)`,
  `find(null)` fails: `error: reference to find is ambiguous`, because `null`
  fits both equally.
- **Parameters and arguments** are different words. Parameters are in the
  definition; arguments are in the call. Interviewers sometimes check.
- **Overloading is not overriding.** Overloading is same name, different
  parameters, chosen at compile time. Overriding is a subclass replacing a
  parent's method, chosen at run time. The polymorphism lesson sets them side
  by side.

## Interview questions

::accordion
  :::accordion-item{label="What is a method signature?" icon="i-lucide-message-circle"}
  The method's name plus the number, types and order of its parameters. The
  return type, the parameter names and the modifiers are not part of it. Two
  methods in one class cannot share a signature, which is why overloading on
  return type alone fails with "already defined".
  :::
  :::accordion-item{label="Can we overload the main method?" icon="i-lucide-message-circle"}
  Yes. The JVM only calls `public static void main(String[] args)`; any other
  `main` is an ordinary method you can call yourself.

  ```java [MainOverload.java]
  public class MainOverload {
    public static void main(String[] args) {
      System.out.println("The JVM calls this one");
      main(42);
    }
    public static void main(int batch) {
      System.out.println("Overloaded main, batch " + batch);
    }
  }
  ```

  ```text [Output]
  The JVM calls this one
  Overloaded main, batch 42
  ```
  :::
  :::accordion-item{label="Which overload is chosen for record(78) with record(long), record(Integer) and record(int...)?" icon="i-lucide-message-circle"}
  `record(long)`. Java tries widening first, then boxing, then varargs, and
  takes the first stage that finds a match. `WideningWins.java` above prints
  `long (widening)`.
  :::
  :::accordion-item{label="Can a void method use return?" icon="i-lucide-message-circle"}
  Yes, a bare `return;` with no value ends it early. It is common as a guard:
  `if (marks == null) return;` at the top of the method.
  :::
  :::accordion-item{label="What is the difference between a parameter and an argument?" icon="i-lucide-message-circle"}
  A parameter is the variable in the method definition (`int[] marks`). An
  argument is the value passed at the call (`anita`). The argument's value is
  copied into the parameter.
  :::
::
