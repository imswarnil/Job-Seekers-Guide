Every loop in the last lesson leaned on a row of numbered boxes. That row is an
**array**: a fixed number of values of one type, stored side by side under a
single name, each reached by its position.

## Why this matters in a job

Arrays sit underneath almost everything. An `ArrayList` is an array that
copies itself into a bigger one when it fills up; a `String` keeps its
characters in one; `main` receives its arguments in one. At work you will
mostly use collections instead, but you cannot explain how they behave without
arrays.

In interviews arrays are the single most common coding topic. Second highest
mark, reverse in place, find the duplicate, rotate by k: the DSA track is
largely arrays. This lesson makes sure the basics are not what trips you.

## An array is a row of lockers

Picture the lockers outside a college lab: one long row, numbered from 0, all
the same size, bolted to the wall. You can change what is inside any locker.
You cannot add a locker to the row, and you cannot put a bag in a locker built
for books. That is an array: **fixed size**, **one type**, **numbered from 0**.

::memory{kind="array" caption="int[] scores = {78, 64, 81, 55, 92}. Five elements, indices 0 to 4."}
---
cells:
  - { value: "78", label: "[0]" }
  - { value: "64", label: "[1]" }
  - { value: "81", label: "[2]" }
  - { value: "55", label: "[3]" }
  - { value: "92", label: "[4] last = length - 1", state: "active" }
---
::

Why from 0? Because the index is really an **offset**: how many boxes past the
start. The first box is zero boxes past the start. Java reaches `scores[3]` by
jumping straight to "start plus 3 boxes", which is why reading any element takes
the same time however long the array is.

## Syntax

```java
int[] marks = new int[5];               // five ints, each set to 0
int[] scores = {78, 64, 81, 55, 92};    // declared and filled in one go
scores[0]                               // read the first element
scores[2] = 85;                         // write the third
scores.length                           // how many: a field, no brackets
```

```java [MarksArray.java]
import java.util.Arrays;

public class MarksArray {
  public static void main(String[] args) {
    int[] marks = new int[5];                  // five ints, all 0
    int[] scores = {78, 64, 81, 55, 92};       // declared and filled
    String[] names = new String[3];            // three references, all null

    System.out.println(scores[0]);             // first
    System.out.println(scores[scores.length - 1]);  // last
    System.out.println(scores.length);         // a field, no brackets
    System.out.println(Arrays.toString(marks));
    System.out.println(Arrays.toString(names));
    System.out.println(scores);                // not what you wanted

    int[] copy = scores;                       // NOT a copy: same array
    copy[0] = 10;
    System.out.println("scores[0] is now " + scores[0]);
  }
}
```

```bash [Terminal]
javac MarksArray.java && java MarksArray
```

```text [Output]
78
92
5
[0, 0, 0, 0, 0]
[null, null, null]
[I@29f69090
scores[0] is now 10
```

Four facts are in that output, and together they cause most array bugs.

::feature-list{columns="2"}
  :::feature{icon="i-lucide-circle-dot" title="Defaults are not empty"}
  `int[]` fills with 0, `double[]` with 0.0, `boolean[]` with `false`, `char[]`
  with the character `'\u0000'`, and any object array with `null`.
  :::
  :::feature{icon="i-lucide-printer" title="Printing prints the address"}
  `[I@29f69090` means "an array of int" plus a hash code. Use
  `Arrays.toString`, and `Arrays.deepToString` for a grid.
  :::
  :::feature{icon="i-lucide-copy" title="An array is an object"}
  `int[] copy = scores` copies the **reference**, so both names point at one
  array. Change one and the other changes. The next chapter explains why.
  :::
  :::feature{icon="i-lucide-lock" title="The size is fixed forever"}
  `new int[5]` is five, permanently. More room means a new array and a copy.
  :::
::

### The Arrays class

`java.util.Arrays` is a class full of helpers for arrays. These are the ones
worth knowing by heart:

```java [ArrayTools.java]
import java.util.Arrays;

public class ArrayTools {
  public static void main(String[] args) {
    int[] scores = {78, 64, 81, 55, 92};

    int[] longer = Arrays.copyOf(scores, 7);          // padded with 0
    int[] middle = Arrays.copyOfRange(scores, 1, 4);  // index 1 to 3
    int[] cloned = scores.clone();                    // a real, separate copy

    Arrays.sort(scores);                              // sorts in place
    System.out.println("sorted:   " + Arrays.toString(scores));
    System.out.println("longer:   " + Arrays.toString(longer));
    System.out.println("middle:   " + Arrays.toString(middle));
    System.out.println("cloned:   " + Arrays.toString(cloned));
    System.out.println("index of 81: " + Arrays.binarySearch(scores, 81));

    int[] pending = new int[4];
    Arrays.fill(pending, -1);                         // "not marked yet"
    System.out.println("pending:  " + Arrays.toString(pending));

    int[] a = {1, 2, 3};
    int[] b = {1, 2, 3};
    System.out.println("a == b:          " + (a == b));
    System.out.println("a.equals(b):     " + a.equals(b));
    System.out.println("Arrays.equals:   " + Arrays.equals(a, b));
  }
}
```

```text [Output]
sorted:   [55, 64, 78, 81, 92]
longer:   [78, 64, 81, 55, 92, 0, 0]
middle:   [64, 81, 55]
cloned:   [78, 64, 81, 55, 92]
index of 81: 3
pending:  [-1, -1, -1, -1]
a == b:          false
a.equals(b):     false
Arrays.equals:   true
```

Three details to notice. `copyOfRange(scores, 1, 4)` includes index 1 and
**excludes** index 4, the same "start inclusive, end exclusive" rule as
`substring`. `binarySearch` only gives a correct answer on a **sorted** array;
on an unsorted one it returns garbage without complaining. And `equals` on an
array compares references, the same as `==`, so it is useless: use
`Arrays.equals`.

::tip
`Arrays.fill(pending, -1)` is a small habit worth copying. A mark of 0 is a
real mark. Filling with -1 means "not entered yet", so you can tell a student
who scored nothing from a paper nobody has marked.
::

### 2D arrays

A two-dimensional array is an array of arrays. `int[][] marks = new int[3][4]`
is three rows, each a row of four ints. `marks[r][c]` is row `r`, column `c`.

Because each row is its own array, rows can be different lengths. That is
called a **jagged array**, and it is why a loop should read `marks[r].length`
rather than assume every row is as long as the first.

```java [Jagged.java]
import java.util.Arrays;

public class Jagged {
  public static void main(String[] args) {
    // Each department has a different number of electives.
    String[][] electives = new String[3][];
    electives[0] = new String[] {"Cloud", "ML"};
    electives[1] = new String[] {"VLSI"};
    electives[2] = new String[] {"Robotics", "IoT", "Drones"};

    for (int d = 0; d < electives.length; d++) {
      System.out.println("Dept " + d + " has " + electives[d].length + ": "
          + Arrays.toString(electives[d]));
    }

    int[][] grid = new int[2][3];
    System.out.println(grid.length + " rows, " + grid[0].length + " columns");
  }
}
```

```text [Output]
Dept 0 has 2: [Cloud, ML]
Dept 1 has 1: [VLSI]
Dept 2 has 3: [Robotics, IoT, Drones]
2 rows, 3 columns
```

`new String[3][]` gives three rows that are each `null` until you assign
them. The column count can be left out; the row count cannot.

## Real use case

The exam cell's mark sheet: students down the side, subjects across the top,
a total per student and an average per subject. Row totals loop across a row;
column averages loop down a column. That swap of the inner and outer loop is
the whole trick.

```java [MarkSheet.java]
import java.util.Arrays;

public class MarkSheet {
  public static void main(String[] args) {
    String[] students = {"Anita", "Vikram", "Farah"};
    String[] subjects = {"Java", "DBMS", "OS", "Maths"};

    // rows = students, columns = subjects
    int[][] marks = {
      {78, 64, 81, 90},
      {55, 72, 48, 61},
      {92, 88, 79, 85}
    };

    System.out.printf("%-8s", "");
    for (String s : subjects) System.out.printf("%6s", s);
    System.out.printf("%7s%n", "Total");

    for (int r = 0; r < marks.length; r++) {
      int total = 0;
      System.out.printf("%-8s", students[r]);
      for (int c = 0; c < marks[r].length; c++) {
        System.out.printf("%6d", marks[r][c]);
        total += marks[r][c];
      }
      System.out.printf("%7d%n", total);
    }

    System.out.printf("%-8s", "Average");
    for (int c = 0; c < subjects.length; c++) {
      int sum = 0;
      for (int r = 0; r < marks.length; r++) sum += marks[r][c];
      System.out.printf("%6.1f", (double) sum / marks.length);
    }
    System.out.println();

    System.out.println(Arrays.deepToString(marks));
  }
}
```

```text [Output]
          Java  DBMS    OS Maths  Total
Anita       78    64    81    90    313
Vikram      55    72    48    61    236
Farah       92    88    79    85    344
Average   75.0  74.7  69.3  78.7
[[78, 64, 81, 90], [55, 72, 48, 61], [92, 88, 79, 85]]
```

::real-life{title="Where you meet this at work" source="Reports, spreadsheets and image data"}
Any time data arrives as rows and columns (an Excel upload, a CSV export, a
seating plan, pixels in an image) you are one step from a 2D array. In real
code it usually becomes a list of objects soon after, but the loops that read
it in look exactly like the ones above.
::

## What confuses people here

::compare{caption="Copying an array: the version that looks right and is not."}
  :::compare-side{label="Shares one array" verdict="wrong"}
  ```java
  int[] backup = scores;
  Arrays.sort(scores);
  // backup is sorted too
  ```
  Only the reference was copied. Two names, one row of lockers.
  :::
  :::compare-side{label="A real copy" verdict="right"}
  ```java
  int[] backup = scores.clone();
  // or Arrays.copyOf(scores, scores.length)
  Arrays.sort(scores);
  // backup keeps the original order
  ```
  A new array with the same values. For a 2D array, `clone()` copies only the
  outer array; the rows are still shared. That is a **shallow copy**.
  :::
::

- **`length`, `length()`, `size()`.** Arrays have a field, `arr.length`.
  Strings have a method, `s.length()`. Collections have `list.size()`. Mixing
  them up is a compile error and a classic written-round question.
- **A negative size compiles and then fails:** `new int[-1]` throws
  `NegativeArraySizeException: -1` at run time.
- **`int[] a, b;` and `int a[], b;` are different.** The first makes two arrays.
  The second makes one array `a` and one plain `int` `b`. Put the brackets on
  the type.
- **Reading past the end** throws `ArrayIndexOutOfBoundsException: Index 5 out
  of bounds for length 5`, the off-by-one from the loops lesson.

## Interview questions

::accordion
  :::accordion-item{label="What are the default values of an array?" icon="i-lucide-message-circle"}
  0 for the integer types, 0.0 for `float` and `double`, `false` for
  `boolean`, `'\u0000'` for `char`, and `null` for any object type, including
  `String`. `Arrays.toString(new String[3])` prints `[null, null, null]`.
  :::
  :::accordion-item{label="Can you change the size of an array?" icon="i-lucide-message-circle"}
  No. The size is fixed when it is created. To grow it you create a bigger
  array and copy across, which is what `Arrays.copyOf(scores, 7)` does and
  what `ArrayList` does internally when it fills up.
  :::
  :::accordion-item{label="Find the second highest mark in one pass." icon="i-lucide-message-circle"}
  Keep two variables and update both as you go. The `m != highest` check
  stops a repeated top mark from counting as second.

  ```java [SecondHighest.java]
  public class SecondHighest {
    public static void main(String[] args) {
      int[] marks = {78, 92, 64, 92, 81};
      int highest = Integer.MIN_VALUE, second = Integer.MIN_VALUE;
      for (int m : marks) {
        if (m > highest) {
          second = highest;
          highest = m;
        } else if (m > second && m != highest) {
          second = m;
        }
      }
      System.out.println("Highest: " + highest + ", second: " + second);

      // Reverse in place with two pointers
      int[] roll = {1, 2, 3, 4, 5};
      for (int i = 0, j = roll.length - 1; i < j; i++, j--) {
        int t = roll[i]; roll[i] = roll[j]; roll[j] = t;
      }
      System.out.println(java.util.Arrays.toString(roll));
    }
  }
  ```

  ```text [Output]
  Highest: 92, second: 81
  [5, 4, 3, 2, 1]
  ```

  Sorting first also works, and costs more (sorting is slower than one pass).
  Say both, and say why you chose the loop.
  :::
  :::accordion-item{label="What is the difference between an array and an ArrayList?" icon="i-lucide-message-circle"}
  An array has a fixed size, can hold primitives (`int[]`), and uses
  `length`. An `ArrayList` grows by itself, holds only objects (`Integer`, not
  `int`), uses `size()`, and has methods such as `add` and `remove`. Inside,
  an `ArrayList` is an array plus a count.
  :::
  :::accordion-item{label="What does clone() do on a 2D array?" icon="i-lucide-message-circle"}
  A shallow copy. It creates a new outer array whose slots point at the
  **same** rows. Changing `copy[0][0]` changes the original too. A deep copy
  needs each row cloned: `for (int r = 0; r < m.length; r++) copy[r] = m[r].clone();`.
  :::
::
