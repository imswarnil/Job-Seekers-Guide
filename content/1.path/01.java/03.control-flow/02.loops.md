A decision runs once, and the fee office has four thousand students. A loop is
how you run the same block of code once per student, or until a condition
changes, without writing it four thousand times.

## Why this matters in a job

Almost every report, batch job and import you will touch at work is a loop:
read every row, check every student, total every payment. And almost every
loop bug is at the edge: the first item, the last item, or the item exactly on
a cutoff. Interviewers know this, which is why "print this pattern" and "what
does this loop print" are staples of the written round and the first
technical round at most Bangalore walk-ins.

## A loop is a register being called

Picture a lecturer taking attendance. She starts at the first name, reads it,
marks it, moves to the next, and stops after the last one. There is a
**start** (the first name), a **condition** to keep going (there are names
left), a **step** (move down one line) and a **body** (read and mark). Every
loop in Java has those four parts. The different loops only differ in where
you write them.

::flow{direction="horizontal" caption="The four parts of every loop. The bug is almost always in the second."}
  :::flow-step{label="Start" icon="i-lucide-play"}
  `int i = 0`: runs once, before anything else.
  :::
  :::flow-step{label="Condition" icon="i-lucide-help-circle" highlight}
  `i < marks.length`: checked before every pass. False means stop.
  :::
  :::flow-step{label="Body" icon="i-lucide-box"}
  The work, once per pass.
  :::
  :::flow-step{label="Step" icon="i-lucide-arrow-right"}
  `i++`: runs after the body, then back to the condition.
  :::
::

The examples below use **arrays**, which are the subject of the next lesson.
For now, read `String[] students = {"Anita", "Vikram"}` as a row of numbered
boxes, numbered from 0, and `students.length` as how many boxes there are.

## Syntax

```java
for (start; condition; step) { body }           // a counted loop
for (Type item : collection) { body }          // the enhanced for, "for each"
while (condition) { body }                     // checks first, may run zero times
do { body } while (condition);                 // runs once, then checks
```

All four in one program:

```java [FourLoops.java]
public class FourLoops {
  public static void main(String[] args) {
    String[] students = {"Anita", "Vikram", "Farah"};

    // 1. for: when you need the index or know the count
    for (int i = 0; i < students.length; i++) {
      System.out.println((i + 1) + ". " + students[i]);
    }

    // 2. enhanced for: when you need each element, not its position
    for (String name : students) {
      System.out.print(name + " ");
    }
    System.out.println();

    // 3. while: when the end is a condition, not a count
    int seatsLeft = 5;
    int day = 0;
    while (seatsLeft > 0) {
      day++;
      seatsLeft -= 2;            // two admissions a day
    }
    System.out.println("Seats filled on day " + day);

    // 4. do-while: the body runs at least once
    int attempts = 0;
    do {
      attempts++;
      System.out.println("Attempt " + attempts);
    } while (attempts < 0);      // false straight away, but the body already ran
  }
}
```

```bash [Terminal]
javac FourLoops.java && java FourLoops
```

```text [Output]
1. Anita
2. Vikram
3. Farah
Anita Vikram Farah 
Seats filled on day 3
Attempt 1
```

---
title: Which loop to reach for
pros:
  - "Enhanced for: the default. It cannot go out of bounds and says \"every element\""
  - "for: when you need the index, or you are counting (1 to 100, every third item)"
  - "while: when you do not know how many passes (read until the file ends, retry until it works)"
cons:
  - "do-while: rare. Use it only when the body must run once before the check, such as showing a menu"
  - "Enhanced for cannot give you the index, and cannot safely remove items from a list while looping"
---

### break and continue

`break` leaves the loop immediately. `continue` skips the rest of this pass
and goes to the next one.

```java [FindTopper.java]
public class FindTopper {
  public static void main(String[] args) {
    String[] names = {"Anita", "Vikram", "Farah", "Rohit"};
    int[] marks    = {78, -1, 96, 88};    // -1 means not yet marked

    int total = 0;
    int counted = 0;
    for (int i = 0; i < marks.length; i++) {
      if (marks[i] < 0) {
        continue;                          // skip this one, carry on
      }
      total += marks[i];
      counted++;
    }
    System.out.println("Average of marked papers: " + (double) total / counted);

    for (int i = 0; i < marks.length; i++) {
      if (marks[i] > 95) {
        System.out.println("First above 95: " + names[i]);
        break;                             // found it, stop looking
      }
    }
  }
}
```

```text [Output]
Average of marked papers: 87.33333333333333
First above 95: Farah
```

### Nested loops, and the labelled break

A loop inside a loop runs the inner loop completely for **every** pass of the
outer one. Three days times four periods is twelve passes of the inner body.

```java [Timetable.java]
public class Timetable {
  public static void main(String[] args) {
    String[] days = {"Mon", "Tue", "Wed"};
    int periods = 4;

    for (String day : days) {                      // outer loop: 3 times
      System.out.print(day + ":");
      for (int p = 1; p <= periods; p++) {         // inner loop: 4 times per day
        System.out.print(" P" + p);
      }
      System.out.println();
    }

    // Find the first free slot in a grid, and stop BOTH loops.
    boolean[][] booked = {
      {true, true, true, true},
      {true, true, false, true},
      {false, true, true, true}
    };
    search:
    for (int d = 0; d < booked.length; d++) {
      for (int p = 0; p < booked[d].length; p++) {
        if (!booked[d][p]) {
          System.out.println("First free: " + days[d] + " period " + (p + 1));
          break search;                            // leaves the outer loop too
        }
      }
    }
  }
}
```

```text [Output]
Mon: P1 P2 P3 P4
Tue: P1 P2 P3 P4
Wed: P1 P2 P3 P4
First free: Tue period 3
```

A plain `break` inside the inner loop only leaves the **inner** loop; the outer
one carries on to Wednesday and prints a second free slot. `search:` is a
**label**, a name for the outer loop, and `break search;` leaves that one.
Labels work, and they are rare in real code, because the cleaner fix is to put
the search in a method and `return` from it. You will see both in interviews.

## Real use case

Every term, a college office produces the attendance shortfall list: who is
below 75% and cannot sit the exam. It is a `for` loop over students, and then
a `while` loop to answer the question every student on that list asks next:
"how many classes do I need?"

```java [AttendanceReport.java]
public class AttendanceReport {
  public static void main(String[] args) {
    String[] names   = {"Anita Rao", "Vikram Shah", "Farah Khan", "Rohit Das"};
    int[] attended   = {36, 28, 30, 40};
    int classesHeld  = 40;
    int minimumPct   = 75;

    int belowCount = 0;
    for (int i = 0; i < names.length; i++) {
      double pct = attended[i] * 100.0 / classesHeld;
      String flag = pct < minimumPct ? "  <- below 75%" : "";
      System.out.printf("%-12s %3d/%d %6.1f%%%s%n", names[i], attended[i], classesHeld, pct, flag);
      if (pct < minimumPct) belowCount++;
    }
    System.out.println(belowCount + " student(s) cannot sit the exam");

    // How many more classes must Vikram attend in a row to reach 75%?
    int a = attended[1], held = classesHeld, extra = 0;
    while (a * 100 < minimumPct * held) {
      a++; held++; extra++;
    }
    System.out.println("Vikram needs " + extra + " consecutive classes");
  }
}
```

```text [Output]
Anita Rao     36/40   90.0%
Vikram Shah   28/40   70.0%  <- below 75%
Farah Khan    30/40   75.0%
Rohit Das     40/40  100.0%
1 student(s) cannot sit the exam
Vikram needs 8 consecutive classes
```

Farah is on exactly 75.0%. The rule says "below 75%", so `pct < minimumPct` is
right and she sits the exam. Write `<=` and she does not, and her parents ring
the principal. The `while` loop compares integers (`a * 100 < 75 * held`)
rather than doubles on purpose: it avoids the floating-point surprises from the
primitives lesson.

::code-trace{caption="Why the counter is declared outside the loop."}

## What confuses people here

### The off-by-one error

```java [OffByOne.java]
public class OffByOne {
  public static void main(String[] args) {
    int[] marks = {78, 64, 81, 55, 92};   // valid indices: 0 to 4
    for (int i = 0; i <= marks.length; i++) {
      System.out.println(marks[i]);
    }
  }
}
```

```text [Output]
78
64
81
55
92
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 5
	at OffByOne.main(OffByOne.java:5)
```

::compare{caption="Two characters, and they are the difference between correct and crashing."}
  :::compare-side{label="i <= length" verdict="wrong"}
  Five elements, indices 0 to 4, and the loop reaches 5. The last valid index
  is always `length - 1`.
  :::
  :::compare-side{label="i < length" verdict="right"}
  Stops at 4. That is why `<` is the default in a counted loop and `<=` should
  make you look twice.
  :::
::

The mirror-image bug is `i < marks.length - 1`, which silently skips the last
element and never crashes. That one is worse, because nothing tells you.

### Infinite loops

A loop whose condition never becomes false runs until you press `Ctrl+C`.
The usual cause is forgetting the step: `while (i < 3) { ... }` with no `i++`.
`for (;;)` and `while (true)` are deliberate infinite loops, and they are fine
as long as there is a `break` inside.

### The semicolon after the loop

```java
for (int i = 0; i < 3; i++);      // the ; is an empty body
{
  System.out.println("Hello");     // runs once, not three times
}
```

It compiles, it runs, and the block below is not part of the loop. Braces on
the same line as the `for` make it impossible.

::warning{icon="i-lucide-alert-triangle"}
A variable declared in the `for` header (`int i`) exists only inside the loop.
Using `i` after the loop is a compile error, `cannot find symbol`. If you need
the final value, declare it before the loop.
::

## Interview questions

::accordion
  :::accordion-item{label="What is the difference between while and do-while?" icon="i-lucide-message-circle"}
  `while` checks the condition first, so its body may run zero times.
  `do-while` runs the body once and then checks, so it always runs at least
  once. In `FourLoops.java` the condition `attempts < 0` was false from the
  start and "Attempt 1" still printed.
  :::
  :::accordion-item{label="What is the difference between break and continue?" icon="i-lucide-message-circle"}
  `break` leaves the loop entirely. `continue` skips the rest of the current
  pass and moves to the next one. In a nested loop both act on the innermost
  loop unless you give a label: `break outer;`.
  :::
  :::accordion-item{label="Print the digit sum and the reverse of a number." icon="i-lucide-message-circle"}
  A written-round favourite. `% 10` gives the last digit, `/ 10` removes it.

  ```java [Sum.java]
  public class Sum {
    public static void main(String[] args) {
      int n = 12345, sum = 0, reversed = 0;
      while (n > 0) {
        int digit = n % 10;
        sum += digit;
        reversed = reversed * 10 + digit;
        n /= 10;
      }
      System.out.println("Digit sum: " + sum + ", reversed: " + reversed);
    }
  }
  ```

  ```text [Output]
  Digit sum: 15, reversed: 54321
  ```
  :::
  :::accordion-item{label="Can you write a for loop with no parts?" icon="i-lucide-message-circle"}
  Yes. `for (;;)` has no start, no condition and no step, and is an infinite
  loop, the same as `while (true)`. All three parts of a `for` are optional;
  the two semicolons are not.
  :::
  :::accordion-item{label="When would you not use the enhanced for loop?" icon="i-lucide-message-circle"}
  When you need the index, when you need to go backwards or skip items, when
  you need to walk two arrays side by side, and when you need to remove items
  from a collection while looping (that throws a
  `ConcurrentModificationException`, which has its own lesson in the
  collections chapter).
  :::
::
