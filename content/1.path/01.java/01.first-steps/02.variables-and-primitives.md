A program that remembers nothing prints the same line forever. To remember a
mark or a roll number it needs a **variable**: a named piece of memory with a
declared type, and in Java the compiler checks that type before the program
ever runs.

## Why this matters in a job

Every line of Java you write at work declares, reads or changes a variable, so
this is the most-used idea in the language. It is also where two of the most
expensive beginner mistakes live. Integer division gives a student 81 instead of
81.67. Using `double` for money leaves a fee account out by fractions of a paisa
that an auditor will eventually find. Both reach production regularly.

In interviews: "what are the primitive types and their sizes", "what is the
default value of an int", "why not use double for money" and "what happens when
an int overflows" come up at almost every fresher round.

## A variable is a labelled box of a fixed size

Picture the pigeonholes in a college staff room. Each one has a name on it
("Dr Iyer, Physics"), and each is sized for what it holds: a slot for letters is
no use for a parcel. A Java variable is the same: a **name**, a **type** that
fixes what shape of value fits in it, and the **value** inside.

```java
int marks = 78;
```

- `int` is the type: a whole number, stored in 32 bits.
- `marks` is the name.
- `78` is the value.
- `=` is **assignment**: put the value on the right into the box on the left.
  It is not "equals" in the maths sense. `marks = marks + 5` makes perfect sense
  in Java.

Java is **statically typed**: the type is fixed when you declare the variable
and the compiler refuses anything that does not fit. `marks = "seventy-eight";`
does not compile, and that refusal is a feature.

## The eight primitives

A **primitive** type holds its value directly in the box. It is not an object.
Java has exactly eight, and everything else (`String`, arrays, your own classes)
is a **reference type**, which the methods chapter explains.

| Type | Size | Range or meaning | Default (as a field) | Use it for |
| --- | --- | --- | --- | --- |
| `byte` | 8 bits | −128 to 127 | `0` | Raw file or network data |
| `short` | 16 bits | −32,768 to 32,767 | `0` | Almost never |
| **`int`** | 32 bits | about ±2.1 billion | `0` | **The default for whole numbers** |
| **`long`** | 64 bits | about ±9.2 × 10¹⁸ | `0L` | Ids, timestamps, money in paise |
| `float` | 32 bits | about 7 significant digits | `0.0f` | Almost never |
| **`double`** | 64 bits | about 15 significant digits | `0.0` | Averages, percentages. **Never money.** |
| `char` | 16 bits | one UTF-16 character, `'A'` | `'\u0000'` | Single letters, grades |
| **`boolean`** | JVM-dependent | `true` or `false` | `false` | Conditions |

Four of them do nearly all the work: `int`, `long`, `double`, `boolean`.

## Syntax

```java [StudentRecord.java]
public class StudentRecord {
  public static void main(String[] args) {
    byte semester = 5;
    short batchYear = 2026;
    int marks = 412;
    long rollNumber = 2026_0001_0184L;   // L: this literal is a long
    float cgpaApprox = 8.4f;             // f: this literal is a float
    double attendancePct = 87.5;
    char section = 'B';                  // single quotes for char
    boolean feePaid = true;

    System.out.println("Semester: " + semester);
    System.out.println("Batch: " + batchYear);
    System.out.println("Marks: " + marks);
    System.out.println("Roll number: " + rollNumber);
    System.out.println("CGPA: " + cgpaApprox);
    System.out.println("Attendance: " + attendancePct + "%");
    System.out.println("Section: " + section);
    System.out.println("Fee paid: " + feePaid);
    System.out.println("int range: " + Integer.MIN_VALUE + " to " + Integer.MAX_VALUE);
    System.out.println("long max: " + Long.MAX_VALUE);
  }
}
```

```text [Output]
Semester: 5
Batch: 2026
Marks: 412
Roll number: 202600010184
CGPA: 8.4
Attendance: 87.5%
Section: B
Fee paid: true
int range: -2147483648 to 2147483647
long max: 9223372036854775807
```

Three small rules sit in that file:

- Underscores in a number (`2026_0001_0184L`) are ignored by the compiler and
  make long numbers readable.
- A whole-number literal is an `int` unless it ends in `L`. A decimal literal is
  a `double` unless it ends in `f`. `float cgpa = 8.4;` does not compile.
- `char` uses single quotes, `String` uses double quotes. `'B'` and `"B"` are
  different types.

### final: a value that cannot change

```java [Constants.java]
public class Constants {
  public static void main(String[] args) {
    final int MAXIMUM_MARKS = 100;
    MAXIMUM_MARKS = 120;
  }
}
```

```text [Output of javac Constants.java]
Constants.java:4: error: cannot assign a value to final variable MAXIMUM_MARKS
    MAXIMUM_MARKS = 120;
    ^
1 error
```

`final` means "assigned once, never again". A value that cannot change is one
fewer thing to reason about, and it is how every constant in a real codebase is
declared, by convention in `UPPER_SNAKE_CASE`.

### Local variables have no default

The "default" column in the table applies to **fields** (variables declared in a
class, which you meet in the objects chapter). A **local variable**, declared
inside a method, has no default at all:

```java [Uninit.java]
public class Uninit {
  public static void main(String[] args) {
    int cutoff;
    System.out.println(cutoff);
  }
}
```

```text [Output of javac Uninit.java]
Uninit.java:4: error: variable cutoff might not have been initialized
    System.out.println(cutoff);
                       ^
1 error
```

### var

```java [VarDemo.java]
import java.util.ArrayList;

public class VarDemo {
  public static void main(String[] args) {
    var marks = 78;                         // inferred as int
    var names = new ArrayList<String>();    // saves writing the type twice
    names.add("Anita Rao");
    var ratio = 18 / 24.0;                  // inferred as double
    System.out.println(marks + " " + names + " " + ratio);
  }
}
```

```text [Output]
78 [Anita Rao] 0.75
```

`var` (Java 10 and later) lets the compiler infer the type of a **local**
variable. It is still strictly typed; you did not write the type, but it is
fixed. Use it where the type is obvious from the right-hand side. It cannot be
used for fields, method parameters, or without an initial value.

## Real use case

Fee and marks systems in real colleges hit the same three decisions every day:
which type holds this, what happens at the edges, and how is money stored. Here
is the pattern almost every financial system in the world uses: store an
**integer count of the smallest unit**.

```java [Money.java]
public class Money {
  public static void main(String[] args) {
    long feePaise = 4_500_000L;   // Rs 45,000.00
    long paidPaise = 1_500_050L;  // Rs 15,000.50
    long balance = feePaise - paidPaise;
    System.out.printf("Balance: Rs %d.%02d%n", balance / 100, balance % 100);
  }
}
```

```text [Output]
Balance: Rs 29999.50
```

Exact, always. The other correct answer is `BigDecimal`, a class for exact
decimal arithmetic, which you will meet in any payments codebase.

::real-life{title="The fee ledger" source="Any university accounts office"}
The accounts office reconciles every payment against the bank statement at the
end of the month. A system that stores fees as `double` produces balances like
29999.499999999996, and somebody spends a Saturday explaining why the college is
short by a fraction of a paisa. Store paise in a `long`, or use `BigDecimal`.
::

## What confuses people here

### Trap one: integer division

```java [Average.java]
public class Average {
  public static void main(String[] args) {
    int totalMarks = 245;
    int subjects = 3;

    int average = totalMarks / subjects;
    double stillWrong = totalMarks / subjects;
    double right = (double) totalMarks / subjects;

    System.out.println("int average:  " + average);
    System.out.println("still wrong:  " + stillWrong);
    System.out.println("right:        " + right);
  }
}
```

```text [Output]
int average:  81
still wrong:  81.0
right:        81.66666666666667
```

::compare{caption="The fix is not what most people try first."}
  :::compare-side{label="Still wrong" verdict="wrong"}
  ```java
  double stillWrong = totalMarks / subjects;   // 81.0
  ```
  The division still happens between two `int`s and throws the fraction away.
  The `double` only receives the already-broken answer.
  :::
  :::compare-side{label="Right" verdict="right"}
  ```java
  double right = (double) totalMarks / subjects;   // 81.666…
  ```
  One operand is now a `double`, so the division itself is done in floating
  point. **The types of the operands decide the arithmetic**, not the type you
  assign into.
  :::
::

The same bug in an attendance calculation gives every student 0%:

```java [Attendance.java]
public class Attendance {
  public static void main(String[] args) {
    int classesHeld = 24;
    int classesAttended = 18;
    double wrong = classesAttended / classesHeld * 100;
    double right = classesAttended * 100.0 / classesHeld;
    System.out.println("Wrong: " + wrong + "%");
    System.out.println("Right: " + right + "%");
  }
}
```

```text [Output]
Wrong: 0.0%
Right: 75.0%
```

18 / 24 in integer arithmetic is 0, and 0 × 100 is 0. Multiplying by `100.0`
first avoids the integer division entirely.

### Trap two: floating point is not exact

```java [Fees.java]
import java.math.BigDecimal;

public class Fees {
  public static void main(String[] args) {
    double paid = 0.1 + 0.2;
    System.out.println(paid);
    System.out.println(paid == 0.3);

    // A late fine of Rs 0.10 a day, for 30 days
    double fine = 0;
    for (int day = 1; day <= 30; day++) fine += 0.10;
    System.out.println("Fine: " + fine);
    System.out.println("Is it 3.00? " + (fine == 3.0));

    System.out.println(new BigDecimal(0.1));
    System.out.println(new BigDecimal("0.1"));
  }
}
```

```text [Output]
0.30000000000000004
false
Fine: 3.0000000000000013
Is it 3.00? false
0.1000000000000000055511151231257827021181583404541015625
0.1
```

This is not a Java bug. A `double` stores numbers in binary, and 0.1 has no
exact binary form, in the same way 1/3 has no exact decimal form. The error is
tiny and it accumulates. Never compare doubles with `==`, and never store money
in one. Note the last two lines: `new BigDecimal(0.1)` is already wrong because
the `double` was wrong before `BigDecimal` saw it. Build it from a `String`.

### Trap three: overflow is silent

```java [Overflow.java]
public class Overflow {
  public static void main(String[] args) {
    int applications = 2_147_483_647;   // Integer.MAX_VALUE
    applications = applications + 1;
    System.out.println(applications);

    long safe = 2_147_483_647L;
    safe = safe + 1;
    System.out.println(safe);

    System.out.println(Math.addExact(2_147_483_647, 0));
    System.out.println(Math.addExact(2_147_483_647, 1));
  }
}
```

```text [Output]
-2147483648
2147483648
2147483647
Exception in thread "main" java.lang.ArithmeticException: integer overflow
	at java.base/java.lang.Math.addExact(Math.java:911)
	at Overflow.main(Overflow.java:12)
```

No error, no warning: the `int` wrapped around to the most negative value.
That is why ids and timestamps are `long`. When a wrong total would be worse
than a crash, `Math.addExact` throws instead of wrapping.

## Interview questions

::accordion
  :::accordion-item{label="What are the eight primitive types, and their sizes?"}
  `byte` 8 bits, `short` 16, `int` 32, `long` 64, `float` 32, `double` 64, `char`
  16 (unsigned, UTF-16), and `boolean`, whose size the specification leaves to
  the JVM. `Integer.MAX_VALUE` prints `2147483647`, which is 2³¹ − 1.
  :::

  :::accordion-item{label="Why should you not use float or double for money?"}
  Binary floating point cannot represent most decimal fractions exactly, so
  `0.1 + 0.2` prints `0.30000000000000004` and errors accumulate. Store an
  integer count of paise in a `long`, or use `BigDecimal` constructed from a
  `String`. `new BigDecimal(0.1)` prints
  `0.1000000000000000055511151231257827021181583404541015625`, which is why the
  String matters.
  :::

  :::accordion-item{label="What is the default value of a local int?"}
  There is none. A field of type `int` defaults to `0`, but a local variable must
  be assigned before it is read, or `javac` reports `variable cutoff might not
  have been initialized`.
  :::

  :::accordion-item{label="What happens when an int overflows?"}
  It wraps around silently: `Integer.MAX_VALUE + 1` is `-2147483648`. No
  exception. Use `long`, or `Math.addExact`, which throws `ArithmeticException:
  integer overflow`.
  :::

  :::accordion-item{label="Is Java a statically typed language? What does var change?"}
  Yes. Every variable's type is fixed at compile time. `var marks = 78;` only
  asks the compiler to infer the type; `marks` is still an `int` and
  `marks = "A";` still fails to compile.
  :::
::
