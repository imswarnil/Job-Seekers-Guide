`(double) totalMarks` turned a wrong average into a right one, and it deserves
an explanation. It is a **cast**: an instruction to convert a value from one
type to another. This lesson covers when Java does that on its own, when you
have to ask, and the operators that do arithmetic, comparison and logic on the
values you now know how to store.

## Why this matters in a job

The written round of almost every service company I sat in 2018 had a "what is
the output of this code" section, and most of those questions are about this
lesson: `i++` against `++i`, `1 + 2 + "marks"`, `(int) 8.97`, a `byte` that
overflows. They are quick marks if you know the rules and a guessing game if you
do not.

At work the same rules decide whether a percentage is 75.0 or 0.0, and whether a
null check protects your code or crashes it. Short-circuit evaluation (`&&`)
is how half the null checks in any Java codebase are written.

## Casting: pouring between containers

Picture three measuring jugs in a hostel mess: a small one (`byte`), a medium one
(`int`) and a large one (`long`). Pouring from small into large is always safe;
it fits. Pouring from large into small is only safe if there was not much in it.
Otherwise it spills, and you lose what spilled.

- **Widening** (small into large) is automatic. Java does it for you because
  nothing can be lost: `byte → short → int → long → float → double`, and
  `char → int`.
- **Narrowing** (large into small) needs an explicit cast, written as the target
  type in brackets: `(int) 8.97`. You are telling the compiler "I know this might
  lose information, do it anyway".

## Syntax

```java [Casting.java]
public class Casting {
  public static void main(String[] args) {
    // Widening: small into big, automatic, never loses the value
    int marks = 412;
    long total = marks;
    double asDouble = marks;
    System.out.println("long: " + total + ", double: " + asDouble);

    // Narrowing: big into small, needs a cast, may lose information
    double cgpa = 8.97;
    int truncated = (int) cgpa;
    long rounded = Math.round(cgpa);
    System.out.println("(int) 8.97 = " + truncated + ", Math.round = " + rounded);

    int seats = 300;
    byte squeezed = (byte) seats;
    System.out.println("(byte) 300 = " + squeezed);

    // char and int are both numbers underneath
    char grade = 'A';
    int code = grade;
    char next = (char) (grade + 1);
    System.out.println("'A' as int = " + code + ", next grade = " + next);

    // Casting too late
    int totalMarks = 245, subjects = 3;
    System.out.println((double) (totalMarks / subjects));
    System.out.println((double) totalMarks / subjects);
  }
}
```

```text [Output]
long: 412, double: 412.0
(int) 8.97 = 8, Math.round = 9
(byte) 300 = 44
'A' as int = 65, next grade = B
81.0
81.66666666666667
```

Four results worth saying out loud:

- `(int) 8.97` is **8**. A cast to an integer type **truncates** towards zero; it
  never rounds. Use `Math.round` to round.
- `(byte) 300` is **44**. A `byte` holds −128 to 127, so the cast keeps only the
  lowest 8 bits of 300 (300 − 256 = 44). No error, no warning.
- `char` is a number. `'A'` is 65, so `'A' + 1` is 66, and casting back to
  `char` gives `B`.
- The position of the cast matters. `(double) (totalMarks / subjects)` divides
  first, as integers, and then converts 81 to 81.0.

## The promotions Java does behind your back

Before any arithmetic, Java **promotes** small types: `byte`, `short` and `char`
become `int`. If either operand is a `long`, `float` or `double`, the other is
promoted to match. That rule causes two classic surprises.

```java [Promotion.java]
public class Promotion {
  public static void main(String[] args) {
    byte lab = 40;
    byte theory = 50;
    // byte sum = lab + theory;   // does not compile: lab + theory is an int
    int sum = lab + theory;
    System.out.println("sum: " + sum);

    byte bonus = 10;
    bonus += 5;          // compiles: += hides a cast
    System.out.println("bonus: " + bonus);

    byte risky = 120;
    risky += 10;         // also compiles, and silently overflows
    System.out.println("risky: " + risky);

    long perSecond = 24 * 60 * 60 * 1000 * 1000;      // int overflow first
    long correct   = 24L * 60 * 60 * 1000 * 1000;
    System.out.println("microseconds in a day, wrong: " + perSecond);
    System.out.println("microseconds in a day, right: " + correct);

    System.out.println("1 + 2 + \"marks\" = " + (1 + 2 + "marks"));
    System.out.println("\"marks\" + 1 + 2 = " + ("marks" + 1 + 2));
    System.out.println('A' + 'B');
    System.out.println("" + 'A' + 'B');
  }
}
```

```text [Output]
sum: 90
bonus: 15
risky: -126
microseconds in a day, wrong: 500654080
microseconds in a day, right: 86400000000
1 + 2 + "marks" = 3marks
"marks" + 1 + 2 = marks12
131
AB
```

Uncomment the `byte sum` line and the compiler says:

```text [Output of javac]
BadByte.java:4: error: incompatible types: possible lossy conversion from int to byte
    byte sum = lab + theory;
                   ^
1 error
```

## The operators

```java [Operators.java]
public class Operators {
  public static void main(String[] args) {
    int totalMarks = 413;
    int subjects = 5;
    System.out.println("413 / 5 = " + totalMarks / subjects);
    System.out.println("413 % 5 = " + totalMarks % subjects);
    System.out.println("-7 / 2 = " + (-7 / 2) + ", -7 % 2 = " + (-7 % 2));
    System.out.println("7.5 % 2 = " + (7.5 % 2));

    int rollNumber = 184;
    System.out.println(rollNumber % 2 == 0 ? "even roll number" : "odd roll number");

    int present = 10;
    int a = present++;   // use, then add
    int b = ++present;   // add, then use
    System.out.println("a = " + a + ", b = " + b + ", present = " + present);

    int attempts = 5;
    attempts = attempts++;
    System.out.println("attempts = " + attempts);

    int marks = 72;
    boolean passedAll = marks >= 40 && marks <= 100;
    boolean distinctionOrSports = marks >= 75 || true;
    System.out.println(passedAll + " " + distinctionOrSports + " " + !passedAll);

    System.out.println(2 + 3 * 4);
    System.out.println((2 + 3) * 4);
    System.out.println(10 - 4 - 3);

    int x = 6, y = 3;
    System.out.println("6 & 3 = " + (x & y) + ", 6 | 3 = " + (x | y) + ", 6 ^ 3 = " + (x ^ y));
    System.out.println("1 << 4 = " + (1 << 4) + ", 64 >> 2 = " + (64 >> 2) + ", -64 >>> 28 = " + (-64 >>> 28));

    System.out.println(10 / 0.0);
    System.out.println(0.0 / 0.0);
    System.out.println(10 / 0);
  }
}
```

```text [Output]
413 / 5 = 82
413 % 5 = 3
-7 / 2 = -3, -7 % 2 = -1
7.5 % 2 = 1.5
even roll number
a = 10, b = 12, present = 12
attempts = 5
true true false
14
20
3
6 & 3 = 2, 6 | 3 = 7, 6 ^ 3 = 5
1 << 4 = 16, 64 >> 2 = 16, -64 >>> 28 = 15
Infinity
NaN
Exception in thread "main" java.lang.ArithmeticException: / by zero
	at Operators.main(Operators.java:37)
```

| Group | Operators | What to remember |
| --- | --- | --- |
| Arithmetic | `+ - * / %` | `%` is the remainder. Its sign follows the left operand: `-7 % 2` is `-1`. |
| Increment | `++ --` | `x++` gives the old value, then adds. `++x` adds, then gives the new value. |
| Assignment | `= += -= *= /= %=` | Compound forms hide a cast back to the left type. |
| Comparison | `== != < > <= >=` | Always produce a `boolean`. `==` on objects compares addresses (next chapter). |
| Logical | `&& \|\| !` | `&&` and `\|\|` short-circuit: they skip the right side when the left decides it. |
| Ternary | `cond ? a : b` | An `if` that produces a value. Keep it to one line. |
| Bitwise | `& \| ^ ~ << >> >>>` | Rare in business code; asked in written tests. `>>>` fills with zeros. |

**Precedence**, highest first, in the order you will actually meet it:
`++ --` and `!`, then `* / %`, then `+ -`, then `< > <= >=`, then `== !=`, then
`&&`, then `||`, then `?:`, then `=` and friends. Operators of the same level
run left to right (`10 - 4 - 3` is 3), except assignment, which runs right to
left. When in doubt, add brackets. A reviewer never complains about clear
brackets.

Dividing an integer by zero throws `ArithmeticException`. Dividing a `double` by
zero does not: it gives `Infinity`, and `0.0 / 0.0` gives `NaN` (not a
number), which then quietly poisons every calculation it touches.

## Real use case

Short-circuit `&&` is how a real codebase avoids crashing on missing data. An
applicant who skipped the name field has a `null` name (no object at all), and
calling a method on `null` crashes:

```java [ShortCircuit.java]
public class ShortCircuit {
  public static void main(String[] args) {
    String applicantName = null;

    if (applicantName != null && applicantName.length() > 3) {
      System.out.println("long name");
    } else {
      System.out.println("no name, and no crash");
    }

    int checks = 0;
    boolean r1 = false && (++checks > 0);
    boolean r2 = false & (++checks > 0);
    System.out.println("checks after && and & : " + checks);

    if (applicantName != null & applicantName.length() > 3) {
      System.out.println("unreachable");
    }
  }
}
```

```text [Output]
no name, and no crash
checks after && and & : 1
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "String.length()" because "<local1>" is null
	at ShortCircuit.main(ShortCircuit.java:16)
```

`&&` stopped as soon as `applicantName != null` was false, so `length()` never
ran. The single `&` on `boolean`s evaluates **both** sides every time, which is
why `checks` went up once and why the last `if` crashed.

::side-note{kind="go-deeper"}
`<local1>` appears because `javac` does not record local variable names by
default. Compile with `javac -g ShortCircuit.java` and the message names the
variable: `because "applicantName" is null`. Build tools usually pass `-g` for
you.
::

## What confuses people here

::compare{caption="The two increments. Written tests love this."}
  :::compare-side{label="x++ (post-increment)" verdict="neutral"}
  ```java
  int present = 10;
  int a = present++;   // a = 10, present = 11
  ```
  Hands over the **old** value, then adds one.
  :::
  :::compare-side{label="++x (pre-increment)" verdict="neutral"}
  ```java
  int present = 11;
  int b = ++present;   // b = 12, present = 12
  ```
  Adds one first, then hands over the **new** value.
  :::
::

::warning{icon="i-lucide-alert-triangle"}
`attempts = attempts++;` leaves `attempts` **unchanged** (5 in the output above).
The right side saves the old value 5, increments `attempts` to 6, and then the
assignment writes the saved 5 back. Never write this. At work, use `++` on a
line of its own, where pre and post behave identically.
::

- **A cast truncates, it does not round.** `(int) 8.97` is 8, and `(int) -8.97`
  is -8.
- **Narrowing casts overflow silently.** `(byte) 300` is 44. A cast is you
  promising the compiler the value fits; the compiler believes you.
- **Integer division by zero throws, double division does not.**
- **`==` on doubles is unreliable** for the reason in the previous lesson.
  Compare the difference against a small tolerance instead.

## Interview questions

::accordion
  :::accordion-item{label="What is the difference between widening and narrowing casting?"}
  Widening converts to a larger type and is automatic and safe: `long total = marks;`.
  Narrowing converts to a smaller type, needs an explicit cast and can lose data:
  `(byte) 300` is `44`, and `(int) 8.97` is `8`.
  :::

  :::accordion-item{label="Why does byte b = b1 + b2 fail, but b += 5 compile?"}
  Arithmetic promotes `byte` to `int`, so `b1 + b2` is an `int` and cannot be
  assigned to a `byte` without a cast. Compound assignment includes an implicit
  cast back to the left-hand type, so `b += 5` compiles, and `byte risky = 120;
  risky += 10;` gives `-126`.
  :::

  :::accordion-item{label="What does int x = 5; x = x++; leave in x?"}
  5. The old value is saved, `x` becomes 6, then the saved 5 is assigned back
  over it. `x = ++x;` would give 6.
  :::

  :::accordion-item{label="What is the difference between & and &&?"}
  Both are logical AND on booleans. `&&` short-circuits and skips the right side
  when the left is `false`; `&` always evaluates both. That is why
  `name != null && name.length() > 3` is safe and the `&` version throws a
  `NullPointerException`. On integers, `&` is bitwise AND: `6 & 3` is `2`.
  :::

  :::accordion-item{label="Predict the output of a mixed number and String sum"}
  `System.out.println(1 + 2 + "3" + 4 + 5);` prints `3345`. Left to right: `1 + 2` is the number 3, then `3 + "3"` is the string
  `"33"`, and every `+` after a String joins text, giving `"3345"`.
  :::
::
