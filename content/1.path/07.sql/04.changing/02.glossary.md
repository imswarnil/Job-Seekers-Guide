Ten weeks in one page.

## The clause order, which explains most errors

```text
Written:    SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT
Evaluated:  FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
```

That single difference explains why an alias fails in `WHERE` and works in
`ORDER BY`, why an aggregate condition belongs in `HAVING`, and why a window
function cannot appear in `WHERE`.

## Reading

| Term | In one line |
| --- | --- |
| **`SELECT`** | Which columns. Name them; `SELECT *` breaks silently when a column is added. |
| **`WHERE`** | Removes **rows**, before grouping. Cannot see an aggregate. |
| **`ORDER BY`** | Sorts. Always end with something unique or the order is not reproducible. |
| **`LIMIT` / `TOP`** | First n, after everything else. |
| **`DISTINCT`** | Removes duplicate rows. Often a symptom of a join producing them. |
| **`BETWEEN`** | Inclusive at **both** ends. Write the comparison out when the boundary matters. |
| **`LIKE`** | `%` any run, `_` one character. A **leading** `%` cannot use an index. |
| **`IN` / `NOT IN`** | Any of these. `NOT IN` with a null in the list returns **nothing**. |
| **`EXISTS` / `NOT EXISTS`** | Is there at least one matching row. Immune to the null trap. Prefer it. |

## NULL

| Term | In one line |
| --- | --- |
| **`NULL`** | Not a value: the absence of one. "We do not know." |
| **Three-valued logic** | `TRUE`, `FALSE`, `UNKNOWN`. Only `TRUE` returns a row. |
| **`= NULL`** | Always `UNKNOWN`, so never matches. Use `IS NULL`. |
| **`COALESCE(a,b)`** | First non-null. Substituting a default is a decision, not formatting. |
| **`NULLIF(a,b)`** | `NULL` when equal. `NULLIF(held, 0)` turns a division by zero into "cannot be calculated". |
| **Aggregates and NULL** | Every aggregate except `COUNT(*)` skips nulls. Usually correct, and the label must say so. |

## Joining

| Term | In one line |
| --- | --- |
| **`INNER JOIN`** | Only rows with a partner on both sides. Silently drops the rest. |
| **`LEFT JOIN`** | Every left row; nulls where there was no match. |
| **`RIGHT JOIN`** | The same with the tables swapped. Rare in real code. |
| **`FULL OUTER JOIN`** | Everything from both sides. |
| **`CROSS JOIN`** | Every combination. Deliberate against a one-row table; otherwise an accident. |
| **Self-join** | A table joined to itself with two aliases. Remember the `<>` or every row matches itself. |
| **`ON` against `WHERE`** | On a `LEFT JOIN`, a right-table condition in `WHERE` turns it back into an inner join. |
| **Fan-out** | Joining to a table with several matching rows multiplies your aggregates. The most common cause of a wrong dashboard. |
| **Find what is missing** | `LEFT JOIN` then `WHERE right.id IS NULL`. |

## Grouping

| Term | In one line |
| --- | --- |
| **`GROUP BY`** | Collapses rows into one row per group. |
| **The rule** | Every `SELECT` column must be grouped or aggregated. A group of 412 has no single name. |
| **`HAVING`** | Removes **groups**, after grouping. Where aggregate conditions go. |
| **`COUNT(*)` vs `COUNT(col)`** | Rows against non-null values. The difference is the bug in half of all `LEFT JOIN` counts. |
| **Conditional aggregation** | `COUNT(*) FILTER (WHERE ...)`, or `SUM(CASE WHEN ... THEN 1 ELSE 0 END)`. Turns long output wide. |
| **`WITH` / CTE** | Names an intermediate result. The best readability tool in the language. |

## Windows

| Term | In one line |
| --- | --- |
| **`OVER (PARTITION BY ...)`** | `GROUP BY` that keeps every row. |
| **`ROW_NUMBER`** | 1, 2, 3, 4. Ties broken **arbitrarily** unless you add a tie-break. |
| **`RANK`** | 1, 2, 2, 4. Skips after a tie. |
| **`DENSE_RANK`** | 1, 2, 2, 3. No gap. |
| **`LAG` / `LEAD`** | The previous or next row's value. Compare with last month. |
| **Top n per group** | Rank in a `WITH`, filter outside it. A window cannot go in `WHERE`. |
| **Frame clause** | `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`: a running total. Be explicit; the default uses `RANGE` and includes ties. |

## Writing

| Term | In one line |
| --- | --- |
| **`INSERT`** | Always name the columns. Several rows in one statement. |
| **`RETURNING`** | Get back what the database generated, without a second query. |
| **Upsert** | `ON CONFLICT ... DO UPDATE`. What makes an import safe to re-run. |
| **`UPDATE` / `DELETE`** | **Read the affected-row count.** It is the only warning you get. |
| **Soft delete** | Mark rather than remove, so history and reports survive. Costs a filter on every query. |
| **`TRUNCATE`** | Empties a table instantly, no `WHERE`, no triggers, and **not rollbackable in MySQL**. |
| **`BEGIN` / `COMMIT` / `ROLLBACK`** | All of it or none. Turn off autocommit against real data. |
| **SQL injection** | String concatenation into SQL. Fixed by a placeholder, which sends query and data on separate paths. Never by escaping. |

## Performance, from the DBMS track

| Term | In one line |
| --- | --- |
| **`EXPLAIN ANALYZE`** | What the database will actually do, and what it did. |
| **`Seq Scan`** | Reading every row. The two words to look for. |
| **Index Scan** | Using the index. What you wanted. |
| **An index will not help** | A function on the column, a leading `%`, skipping the leading column of a composite, a value that is not selective, or a type mismatch. |

## The seven sentences to keep

::pull-quote
`WHERE` filters rows and `HAVING` filters groups. `NULL` is never equal to
anything, including itself. Every aggregate but `COUNT(*)` skips nulls. A
right-table condition in `WHERE` cancels a `LEFT JOIN`. Joining to many rows
multiplies your sums. Read the affected-row count. And there is no acceptable
reason to concatenate a value into SQL.
::
