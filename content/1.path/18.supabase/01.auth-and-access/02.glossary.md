| Term | In one line |
| --- | --- |
| **Authentication** | Who are you. Once per session. Fails with **401**, which is badly named: it means unauthenticated. |
| **Authorisation** | May you. Every request, every row. Fails with **403**. |
| **Hash** | A one-way function. You store the hash and compare, never the password. |
| **bcrypt / argon2** | Deliberately **slow** hashes, which is the point. Never SHA-256 or MD5 for a password; they are fast. |
| **Salt** | Random data mixed in so identical passwords hash differently. bcrypt includes it in the output. |
| **Session** | Server-side state keyed by a token the browser holds. |
| **JWT** | A signed token carrying claims. No lookup needed, and it cannot be revoked before it expires, which is the trade. |
| **HttpOnly** | JavaScript cannot read the cookie, so an XSS bug cannot steal the session. |
| **SameSite** | The cookie is not sent on cross-site requests. The main defence against CSRF. |
| **CSRF** | Another site causing the browser to make an authenticated request on your behalf. |
| **IDOR** | ⚠️ Insecure direct object reference. Changing `/results/4182` to `4183` and reading somebody else's marks. The most common serious flaw in a portal. |
| **RBAC** | Permissions by role. Necessary and rarely sufficient: "is a lecturer" is not "teaches this subject". |
| **Scope** | Role plus a boundary. A registrar **for this department**. |
| **Row-level security** | The permission enforced by the **database**, so a forgotten `WHERE` leaks nothing. |
| **Least privilege** | The least access that works. A read-only database user for anything that only reads. |

## The three sentences to keep

::pull-quote
Authentication is once per session and authorisation is every row. A permission
in your code protects you from your code; a permission in the database protects
you from everything. And the screen only links to your own record, which is
exactly why nobody tests changing the id.
::
