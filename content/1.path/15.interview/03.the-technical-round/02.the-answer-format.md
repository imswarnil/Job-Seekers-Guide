Every technical question gets the same five steps: **definition, how it works,
an example, where it is used or the trade-off, and then stop.** It takes about
one to two minutes, and it works for Java, SQL, DBMS, OS, networks and anything
else you are asked.

## Why it matters

Freshers lose marks on questions they know, in two ways. The one-line answer
("a HashMap stores key-value pairs") sounds like something memorised the night
before, and leaves the interviewer to drag the rest out of you. The ten-minute
answer, everything you know in no order, loses them halfway and hides the parts
that were right.

::real-life{title="Why I started using a format" source="Bangalore, 2018"}
At my early walk-ins I gave one-line answers and then waited, because I did not
know whether they wanted more. The interviewer took the silence as the edge of
what I knew. Some of those were questions I could have talked about for five
minutes. Once I used the same five steps every time, the silence went, and so
did the feeling of guessing how much to say.
::

## The five steps

::flow{numbered direction="vertical" caption="About 15 to 30 seconds each. Then stop and let them choose where to go."}
  :::flow-step{label="Definition" icon="i-lucide-book"}
  One or two sentences, in plain words. What it is. If you only got this far,
  it would still be a correct answer.
  :::
  :::flow-step{label="How it works" icon="i-lucide-cog" highlight}
  The mechanism underneath. This is the part that separates understanding from
  memorising, and it is where interviewers push.
  :::
  :::flow-step{label="Example" icon="i-lucide-code"}
  A few lines of code, a small table, or a real-life comparison. Something they
  can see. Use the college: students, marks, courses, fees.
  :::
  :::flow-step{label="Where it is used, or the trade-off" icon="i-lucide-scale"}
  When you would use it, and when you would not. One sentence of trade-off is
  the most senior-sounding sentence available to a fresher.
  :::
  :::flow-step{label="Stop" icon="i-lucide-hand"}
  Stop talking. Do not add "and also…". If they want more, they will ask, and
  the question they ask tells you what they care about.
  :::
::

```text [answer-format.txt]
1. DEFINITION     "A ___ is ___."
2. HOW IT WORKS   "Internally, ___. When you ___, it ___."
3. EXAMPLE        "For example, ___." (code, a table, or real life)
4. USED / TRADE-  "It's used for ___. The trade-off is ___, so when ___
   OFF             I'd use ___ instead."
5. STOP.
```

::compare{caption="The same question, the same knowledge, two answers."}
  :::compare-side{label="The one-liner" verdict="wrong"}
  **Q:** What is a HashMap?

  "It is a class in Java which stores key-value pairs."

  Correct, and it could have come from anybody who read a list of questions on
  the bus. The interviewer now has to decide whether to dig or move on, and
  usually moves on with a note.
  :::
  :::compare-side{label="The five steps" verdict="right"}
  **Q:** What is a HashMap?

  Definition, then the buckets and hashing, then four lines of code with
  student roll numbers, then "not thread-safe, not ordered, so
  ConcurrentHashMap or LinkedHashMap when that matters". Then stop.

  About ninety seconds, and every sentence is a place they could follow up.
  :::
::

## A worked example: Java, how does a HashMap work?

**1. Definition.** "A HashMap is a Java collection that stores key-value pairs
and finds a value by its key in constant time on average. Keys are unique."

**2. How it works.** "Inside, it is an array of buckets, 16 by default. When you
put a key, Java calls the key's `hashCode()`, mixes the bits, and uses that to
pick a bucket index. If two keys land in the same bucket, that is a collision,
and they are stored together in that bucket, as a linked list, and from Java 8
as a balanced tree once a bucket grows past eight entries and the
table has at least 64 buckets. When you `get`, it
goes to the bucket by hash code and then uses `equals()` to find the exact key.
When the map is 75% full, which is the load factor, it doubles the array and
redistributes the entries."

**3. Example.**

```java [StudentLookup.java]
import java.util.HashMap;
import java.util.Map;

public class StudentLookup {
    public static void main(String[] args) {
        Map<Integer, String> students = new HashMap<>();
        students.put(101, "Anita");
        students.put(102, "Vikram");
        students.put(101, "Anita Rao");   // same key: the value is replaced

        System.out.println(students.get(101));
        System.out.println(students.get(103));   // no such key
        System.out.println(students.size());
    }
}
```

```text [Output]
Anita Rao
null
2
```

"Putting roll number 101 twice replaces the value instead of adding a second
entry, because keys are unique, and a missing key returns `null` rather than
throwing."

**4. Where it is used, and the trade-off.** "Anywhere you look things up by an
ID: students by roll number, a cache, counting how often each value appears. The
trade-offs are that it does not keep order, so I'd use `LinkedHashMap` for
insertion order or `TreeMap` for sorted keys, it is not thread-safe, so
`ConcurrentHashMap` across threads, and a custom key class must override both
`equals()` and `hashCode()` or lookups fail."

**5. Stop.**

::tip
The interviewer's most common follow-up here is "what happens if I override
`equals()` but not `hashCode()`?" Two equal objects can land in different
buckets, so `get` with an equal key returns `null`. If you said the last sentence
of step 4, you have already half-answered it.
::

## A worked example: OOPs, abstract class against interface

**1. Definition.** "Both are ways to achieve abstraction, which means exposing
what something does and hiding how. An abstract class is a class that cannot be
instantiated and can have fields, constructors, and both abstract and concrete
methods. An interface is a contract of methods that any class can implement,
whatever it extends."

**2. How it works.** "A class can extend only one abstract class, because Java
has single inheritance of classes, but it can implement many interfaces. An
abstract class can hold state, like a name field, and a constructor to set it.
An interface cannot hold instance state; since Java 8 it can have `default` and
`static` methods with a body, so the difference today is mostly state and single
inheritance, not 'interfaces have no code'."

**3. Example.**

```java [CampusDemo.java]
interface Notifiable {
    String email();
    default String alert(String message) {
        return "To " + email() + ": " + message;
    }
}

abstract class Staff implements Notifiable {
    private final String name;
    Staff(String name) { this.name = name; }
    String getName() { return name; }
    public String email() { return name.toLowerCase() + "@college.edu"; }
    abstract int monthlyPay();
}

class Faculty extends Staff {
    Faculty(String name) { super(name); }
    int monthlyPay() { return 60000; }
}

class LabAssistant extends Staff {
    LabAssistant(String name) { super(name); }
    int monthlyPay() { return 25000; }
}

class Student implements Notifiable {
    private final String rollNo;
    Student(String rollNo) { this.rollNo = rollNo; }
    public String email() { return rollNo + "@students.college.edu"; }
}

public class CampusDemo {
    public static void main(String[] args) {
        Staff[] staff = { new Faculty("Rao"), new LabAssistant("Meena") };
        for (Staff s : staff) {
            System.out.println(s.getName() + ": " + s.monthlyPay());
        }

        Notifiable[] everyone = { staff[0], new Student("CS2018-042") };
        for (Notifiable n : everyone) {
            System.out.println(n.alert("College closed on Monday"));
        }
    }
}
```

```text [Output]
Rao: 60000
Meena: 25000
To rao@college.edu: College closed on Monday
To CS2018-042@students.college.edu: College closed on Monday
```

"`Staff` is abstract because every staff member has a name and a pay, but there
is no such thing as plain staff, only faculty and lab assistants. `Notifiable` is
an interface because students and staff are unrelated classes that both need to
receive alerts."

**4. Where it is used, and the trade-off.** "I use an abstract class when
related classes share state and code, an 'is-a' family. I use an interface when
unrelated classes need the same ability, a 'can-do'. The trade-off is that
extending an abstract class uses up your one superclass, so if in doubt I start
with an interface."

**5. Stop.**

## A worked example: DBMS, what is normalisation?

**1. Definition.** "Normalisation is organising tables so that each fact is
stored once, which removes duplicate data and the update problems that come with
it."

**2. How it works.** "You apply normal forms in order. First normal form: every
column holds one atomic value, no lists in a cell. Second normal form: every
non-key column depends on the whole primary key, not part of it. Third normal
form: non-key columns depend only on the key, not on another non-key column."

**3. Example.** "Take one table of exam results."

```text [exam_result, before]
student_id | student_name | department | dept_head  | course_id | course_name | marks
-----------+--------------+------------+------------+-----------+-------------+------
101        | Anita        | CSE        | Dr. Rao    | C1        | DBMS        | 78
101        | Anita        | CSE        | Dr. Rao    | C2        | OS          | 64
102        | Vikram       | ECE        | Dr. Iyer   | C1        | DBMS        | 71
```

"The key is `(student_id, course_id)`. `student_name` depends only on
`student_id`, which is part of the key, so it breaks second normal form. And
`dept_head` depends on `department`, not on the student, which breaks third. If
the CSE head changes, I have to update every CSE row, and if I miss one the data
contradicts itself. That is an update anomaly. Split it:"

```sql [normalised.sql]
CREATE TABLE department (
  name      VARCHAR(10) PRIMARY KEY,
  head      VARCHAR(50)
);
CREATE TABLE student (
  id         INT PRIMARY KEY,
  name       VARCHAR(50),
  department VARCHAR(10) REFERENCES department(name)
);
CREATE TABLE course (
  id   VARCHAR(5) PRIMARY KEY,
  name VARCHAR(50)
);
CREATE TABLE exam_result (
  student_id INT        REFERENCES student(id),
  course_id  VARCHAR(5) REFERENCES course(id),
  marks      INT,
  PRIMARY KEY (student_id, course_id)
);
```

"Now the head of CSE is stored in one row, and changing it is one update."

**4. Where it is used, and the trade-off.** "Any transactional system, like
admissions or fees, is normalised to about third normal form, because writes
must be correct. The trade-off is joins: a report now needs four tables. So
reporting databases are often deliberately denormalised for speed, with the
normalised tables as the source of truth."

**5. Stop.**

## Common mistakes

- **Skipping step 2.** The definition alone sounds memorised. How it works is
  where the marks are.
- **An example with `foo` and `bar`.** Use students, marks and courses. It is
  easier for you to reason about and easier for them to follow.
- **Not stopping.** After step 4, stop. Filling silence with more facts is how
  a right answer picks up a wrong sentence at the end.
- **Using the format as a script.** Nobody says "step three, example". The steps
  are the order in your head, not words you say.

## How to practise

Pick three questions a day from the [fifty most-asked
questions](/interview/the-technical-round/the-fifty-questions). Answer each out
loud in the five steps, timed. Aim for 60 to 120 seconds. Record one a day.
