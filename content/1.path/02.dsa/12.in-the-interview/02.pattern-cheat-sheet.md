Here is the table. Most interview problems are one of about sixteen patterns
in disguise, and the disguise is thin: the question nearly always contains a
phrase that gives the pattern away. Read the middle column until you notice those
phrases without trying.

I kept a version of this on a sheet of paper stuck above my desk in the months
before the switch from Accenture. Writing your own copy by hand, in your own
words, is worth more than reading mine.

## Pattern → signal → problems

| Pattern | The signal in the question | Classic problems | Typical cost |
| --- | --- | --- | --- |
| **Hashing** | "find a pair", "seen before", "count", "duplicate", "first unique" | Two sum, first non-repeating character, contains duplicate, group anagrams | O(n) time, O(n) space |
| **Prefix sums** | "sum of range", "many queries", "subarray sum equals k" | Range sum query, subarray sum equals k, equilibrium index | O(n) build, O(1) per query |
| **Kadane** | "maximum sum contiguous subarray", "best stretch" | Maximum subarray, maximum circular subarray | O(n), O(1) |
| **Two pointers** | "sorted array", "pair", "in place", "palindrome", "remove duplicates" | Pair with target sum, move zeros, container with most water, three sum | O(n) after sorting |
| **Sliding window** | "contiguous", "substring", "at most k", "longest / smallest window" | Max sum of k days, longest substring without repeats, minimum window substring | O(n) |
| **Binary search** | "sorted", "find position", "minimum possible maximum", "rotated" | First and last occurrence, search in rotated array, allocate minimum pages | O(log n) |
| **Sorting first** | "overlapping", "intervals", "meetings", "closest" | Merge intervals, meeting rooms, minimum difference pair | O(n log n) |
| **Stack** | "brackets", "next greater", "previous smaller", "undo", "evaluate" | Balanced brackets, next greater element, min stack, stock span | O(n) |
| **Queue / BFS** | "level by level", "shortest steps", "minimum moves", "nearest" | Level order traversal, rotting oranges, shortest path in a grid | O(V + E) |
| **Linked list pointers** | "in place", "middle", "cycle", "kth from end", "merge" | Reverse list, middle node, detect cycle, merge two sorted lists | O(n), O(1) |
| **Tree recursion (DFS)** | "height", "depth", "path", "subtree", "ancestor" | Height of tree, diameter, lowest common ancestor, path sum | O(n) |
| **Heap** | "top k", "kth largest", "k closest", "merge k sorted", "running median" | Kth largest element, top k frequent, merge k sorted lists | O(n log k) |
| **Graph DFS / BFS** | "connected", "islands", "regions", "friends of friends" | Number of islands, connected components, clone graph | O(V + E) |
| **Topological sort** | "prerequisites", "order of tasks", "dependencies" | Course schedule, course order | O(V + E) |
| **Backtracking** | "all combinations", "all permutations", "every possible", "generate" | Subsets, permutations, combination sum, N-Queens | O(2ⁿ) or O(n!) |
| **Dynamic programming** | "number of ways", "minimum cost", "maximum profit", "can you reach", "longest ... subsequence" | Climbing stairs, coin change, 0/1 knapsack, LCS, house robber | O(states × choices) |
| **Greedy** | "maximum number of non-overlapping", "minimum number of", "schedule" | Activity selection, jump game, minimum platforms | O(n log n) |

::tip
When two patterns fit, the constraint line decides. n up to 10⁵ rules out O(n²),
so "pair with target sum" on an unsorted array with n = 10⁵ is hashing, not the
brute force. n up to 20 invites backtracking. Always read the constraints before
choosing.
::

## Signals by input type

::feature-list{columns="2"}
  :::feature{icon="i-lucide-rows-3" title="Array or string"}
  Sorted? Binary search or two pointers. Contiguous? Window or prefix sums.
  Pairs or counts? Hashing. None of those? Sort it first and look again.
  :::
  :::feature{icon="i-lucide-link" title="Linked list"}
  Slow and fast pointers for middle and cycles. A dummy head node for anything
  that might change the first node.
  :::
  :::feature{icon="i-lucide-git-branch" title="Tree"}
  Recursion for anything about depth, height or paths. A queue for anything "by
  level". In-order for anything "sorted" on a BST.
  :::
  :::feature{icon="i-lucide-network" title="Graph or grid"}
  BFS for shortest steps without weights, DFS for "is it connected", topological
  sort for ordering, Dijkstra when edges have weights.
  :::
::

## Java API under pressure

The methods I reach for in almost every round. Knowing them cold saves minutes
that you need for thinking.

| Need | Java | Cost |
| --- | --- | --- |
| Stack | `Deque<Integer> st = new ArrayDeque<>();` `push`, `pop`, `peek` | O(1) |
| Queue | `Queue<Integer> q = new ArrayDeque<>();` `offer`, `poll`, `peek` | O(1) |
| Min-heap | `new PriorityQueue<>()` | offer/poll O(log n), peek O(1) |
| Max-heap | `new PriorityQueue<>(Comparator.reverseOrder())` | same |
| Count things | `map.merge(key, 1, Integer::sum)` | O(1) average |
| Read with default | `map.getOrDefault(key, 0)` | O(1) average |
| Seen before? | `if (!set.add(x))` means x was already present | O(1) average |
| Sorted map | `TreeMap`: `floorKey`, `ceilingKey`, `firstKey`, `headMap` | O(log n) |
| Sort array | `Arrays.sort(a)`; objects: `Arrays.sort(a, comparator)` | O(n log n) |
| Sort 2D by first column | `Arrays.sort(rows, (x, y) -> Integer.compare(x[0], y[0]))` | O(n log n) |
| Sort a list | `list.sort(Comparator.comparing(Student::marks).reversed())` | O(n log n) |
| Fill | `Arrays.fill(dp, -1)` | O(n) |
| Print an array | `Arrays.toString(a)`, 2D: `Arrays.deepToString(grid)` | O(n) |
| Build a string | `StringBuilder sb`; `append`, `reverse`, `insert(0, c)`, `toString` | append O(1) amortised |
| Character tricks | `c - 'a'` for index 0–25, `Character.isLetterOrDigit(c)`, `Character.toLowerCase(c)` | O(1) |
| Integer limits | `Integer.MAX_VALUE`, `Integer.MIN_VALUE`; use `long` for sums past 2.1 billion | |

::warning{icon="i-lucide-alert-triangle"}
`Integer` objects compared with `==` are only equal by value between -128 and
127 (Java caches those). `map.get(a) == map.get(b)` works in your test with small
counts and fails in the interviewer's test with counts of 200. Use `.equals` or
unbox to `int` first.
::

## The same checklist, as questions

::flow{numbered direction="vertical" caption="Ask these in order when a problem gives nothing away"}
  :::flow-step{label="What does n allow?" icon="i-lucide-ruler"}
  Read the constraints and write the target complexity down.
  :::
  :::flow-step{label="What does brute force repeat?" icon="i-lucide-repeat"}
  Repeated search → hashing. Repeated sums → prefix sums. Repeated subproblems → DP.
  :::
  :::flow-step{label="Would sorting help?" icon="i-lucide-arrow-down-wide-narrow" highlight}
  The single most useful question. Sorting unlocks binary search, two pointers and greedy.
  :::
  :::flow-step{label="Is it really a graph?" icon="i-lucide-network"}
  Things with connections, dependencies or moves on a grid usually are.
  :::
::
