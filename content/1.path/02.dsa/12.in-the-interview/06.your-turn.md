Here are the problems. Ten of them, one or two from each part of the track, each
with a trap built in. Every solution shows two versions: the one most people
write first (it often runs, and is sometimes quietly wrong), and the one an
experienced developer writes, with the reason in plain words.

::note
The rule for this page: 25 minutes on each problem before opening its solution,
with a pen and paper next to you. If you are stuck at 25 minutes, open the hint
line in the solution, close it, and try for ten more. Reading a solution you
have not fought with teaches you almost nothing. I learned that the slow way.
::

## 1. The second topper

The results notice needs the second-highest mark in a class of 60. Two students
share the top mark of 91. Find the second-highest **distinct** mark, in one pass,
without sorting.

::accordion
  :::accordion-item{label="Solution" icon="i-lucide-check"}
  **Hint:** keep two variables, and think about what an equal mark should do.

  **Beginner version.** Sort and take the second from the end:

  ```java
  Arrays.sort(marks);
  return marks[marks.length - 2];   // 91 again when two students share 91
  ```

  It runs and prints 91, which is wrong: that is the top mark a second time. It is
  also O(n log n) for an O(n) job, and it reorders the caller's array.

  **Better version.**

  ```java [SecondTopper.java]
  public class SecondTopper {
    public static void main(String[] args) {
      int[] marks = {78, 91, 64, 91, 85};
      int highest = Integer.MIN_VALUE, second = Integer.MIN_VALUE;
      for (int m : marks) {
        if (m > highest) {
          second = highest;
          highest = m;
        } else if (m > second && m != highest) {
          second = m;
        }
      }
      System.out.println(second == Integer.MIN_VALUE
          ? "No second highest"
          : "Second highest: " + second);
    }
  }
  ```

  ```text [Output]
  Second highest: 85
  ```

  One pass, O(1) space, and the `m != highest` check is what handles the tie.
  The "No second highest" branch is for a class where everyone scored the same.
  :::
::

## 2. A hundred thousand fee questions

The accounts office stores fees collected per day for a semester. The principal's
dashboard asks, a hundred thousand times a day, "how much was collected between
day l and day r?" Answer each question in O(1).

::accordion
  :::accordion-item{label="Solution" icon="i-lucide-check"}
  **Hint:** one extra array, built once.

  **Beginner version.** Loop from l to r for each question. O(n) per question, so
  O(n × q) overall: 180 days times 100,000 questions is 18 million additions per
  day, repeated forever.

  **Better version.** Prefix sums, with `long` because totals pass 2.1 billion
  quickly:

  ```java [FeeQueries.java]
  public class FeeQueries {
    public static void main(String[] args) {
      int[] fees = {12000, 0, 45000, 8000, 30000, 15000, 0};
      long[] prefix = new long[fees.length + 1];     // prefix[i] = first i days
      for (int i = 0; i < fees.length; i++) {
        prefix[i + 1] = prefix[i] + fees[i];
      }
      int[][] questions = {{0, 2}, {2, 5}, {6, 6}};
      for (int[] q : questions) {
        long total = prefix[q[1] + 1] - prefix[q[0]];
        System.out.println("Days " + q[0] + " to " + q[1] + ": Rs " + total);
      }
    }
  }
  ```

  ```text [Output]
  Days 0 to 2: Rs 57000
  Days 2 to 5: Rs 98000
  Days 6 to 6: Rs 0
  ```

  O(n) to build, O(1) per question. The `+ 1` in `prefix[q[1] + 1]` is where
  every off-by-one in this problem lives.
  :::
::

## 3. A merit list you can defend

Rank students by marks, highest first. Two students on the same mark must always
come out in roll-number order, so that running the list twice never swaps who is
on the cutoff.

::accordion
  :::accordion-item{label="Solution" icon="i-lucide-check"}
  **Hint:** say the tie-break in code, do not rely on the input order.

  **Beginner version.** `list.sort((a, b) -> b.marks() - a.marks());`. It sorts by
  marks, and ties come out in whatever order they arrived. Today that happens to
  be roll order; next month somebody loads the data differently and a parent
  calls to ask why their child moved below the line.

  **Better version.**

  ```java [MeritList.java]
  import java.util.*;

  public class MeritList {
    record Student(String roll, int marks) { }

    public static void main(String[] args) {
      List<Student> students = new ArrayList<>(List.of(
          new Student("CSE07", 82), new Student("CSE03", 91),
          new Student("CSE12", 82), new Student("CSE01", 75),
          new Student("CSE05", 91)));

      students.sort(Comparator.comparingInt(Student::marks).reversed()
          .thenComparing(Student::roll));

      int rank = 1;
      for (Student s : students) {
        System.out.println(rank++ + ". " + s.roll() + " " + s.marks());
      }
    }
  }
  ```

  ```text [Output]
  1. CSE03 91
  2. CSE05 91
  3. CSE07 82
  4. CSE12 82
  5. CSE01 75
  ```

  `comparingInt` also avoids the subtraction comparator, which overflows when the
  values are large (it is safe for marks, and a habit that bites later with
  amounts in paise or timestamps).
  :::
::

## 4. The first roll number to repeat

The admission list has duplicates from students who submitted twice. The office
wants the **first roll number to appear a second time**, reading top to bottom.

::accordion
  :::accordion-item{label="Solution" icon="i-lucide-check"}
  **Hint:** "first to repeat" and "first that has a duplicate somewhere" are
  different questions. Ask which one is meant.

  **Beginner version.** Two loops, return the first `i` that has a match at any
  `j > i`. For `{104, 211, 87, 390, 211, 104}` that returns 104, because 104 has
  a duplicate at the end. But 211 is the first roll to *appear again*. O(n²) and
  answering a different question.

  **Better version.** A set of rolls already seen; the first `add` that fails is
  the answer.

  ```java [FirstRepeat.java]
  import java.util.*;

  public class FirstRepeat {
    public static void main(String[] args) {
      int[] rolls = {104, 211, 87, 390, 211, 104};
      Set<Integer> seen = new HashSet<>();
      Integer firstRepeat = null;
      for (int roll : rolls) {
        if (!seen.add(roll)) {
          firstRepeat = roll;
          break;
        }
      }
      System.out.println("First roll to repeat: " + firstRepeat);
    }
  }
  ```

  ```text [Output]
  First roll to repeat: 211
  ```

  O(n) time, O(n) space. The `add` returning `false` for "already there" is one
  of the most useful single facts in the Java collections.
  :::
::

## 5. The longest stretch without a repeat

A timetable is a string of subject codes, one letter per period: `M` for Maths,
`P` for Physics and so on. Find the longest run of consecutive periods with no
subject repeated.

::accordion
  :::accordion-item{label="Solution" icon="i-lucide-check"}
  **Hint:** a window that grows on the right and jumps its left edge past the
  earlier copy of a repeated letter.

  **Beginner version.** From every starting period, walk right with a fresh
  `HashSet` until a repeat. Correct, and O(n²).

  **Better version.** Remember the last period each subject was seen.

  ```java [DistinctPeriods.java]
  import java.util.*;

  public class DistinctPeriods {
    public static void main(String[] args) {
      String timetable = "MPCMBPCDE";
      int[] lastSeen = new int[128];
      Arrays.fill(lastSeen, -1);
      int left = 0, best = 0, bestStart = 0;
      for (int right = 0; right < timetable.length(); right++) {
        char subject = timetable.charAt(right);
        if (lastSeen[subject] >= left) {
          left = lastSeen[subject] + 1;       // jump past the earlier copy
        }
        lastSeen[subject] = right;
        if (right - left + 1 > best) {
          best = right - left + 1;
          bestStart = left;
        }
      }
      System.out.println(best + " periods: " + timetable.substring(bestStart, bestStart + best));
    }
  }
  ```

  ```text [Output]
  6 periods: MBPCDE
  ```

  O(n), and the `>= left` check matters: a letter seen before the window started
  is not a repeat inside it.
  :::
::

## 6. Find a roll in a rotated list

The roll list was sorted, then the printer started the page halfway through:
`{40, 50, 60, 10, 20, 30}`. Find a roll number in O(log n).

::accordion
  :::accordion-item{label="Solution" icon="i-lucide-check"}
  **Hint:** at every middle, one of the two halves is still sorted. Check whether
  the target lies inside that half.

  **Beginner version.** A linear scan, O(n). Correct, and the interviewer will
  say "can you do better?" because the word *sorted* is in the question.

  **Better version.**

  ```java [RotatedRolls.java]
  public class RotatedRolls {
    static int find(int[] rolls, int target) {
      int low = 0, high = rolls.length - 1;
      while (low <= high) {
        int mid = low + (high - low) / 2;
        if (rolls[mid] == target) return mid;
        if (rolls[low] <= rolls[mid]) {                 // left half is sorted
          if (target >= rolls[low] && target < rolls[mid]) high = mid - 1;
          else low = mid + 1;
        } else {                                        // right half is sorted
          if (target > rolls[mid] && target <= rolls[high]) low = mid + 1;
          else high = mid - 1;
        }
      }
      return -1;
    }

    public static void main(String[] args) {
      int[] rolls = {40, 50, 60, 10, 20, 30};
      System.out.println("20 at index " + find(rolls, 20));
      System.out.println("50 at index " + find(rolls, 50));
      System.out.println("55 at index " + find(rolls, 55));
    }
  }
  ```

  ```text [Output]
  20 at index 4
  50 at index 1
  55 at index -1
  ```

  The `<=` in `rolls[low] <= rolls[mid]` handles a two-element range where low
  and mid are the same index.
  :::

## 7. Merging two sections' merit lists

Section A and section B each have a list of marks sorted from low to high. Build
one sorted list for the whole year, in a single pass.

::accordion
  :::accordion-item{label="Solution" icon="i-lucide-check"}
  **Hint:** this is the merge step of merge sort.

  **Beginner version.** Copy both into one array and call `Arrays.sort`. It works,
  in O((n + m) log(n + m)), and throws away the fact that both halves were
  already sorted. In an interview this answer is followed by "and without
  sorting?"

  **Better version.**

  ```java [MergeSections.java]
  import java.util.*;

  public class MergeSections {
    public static void main(String[] args) {
      int[] a = {45, 62, 78, 91};
      int[] b = {50, 62, 70};
      int[] merged = new int[a.length + b.length];
      int i = 0, j = 0, k = 0;
      while (i < a.length && j < b.length) {
        merged[k++] = (a[i] <= b[j]) ? a[i++] : b[j++];   // <= keeps it stable
      }
      while (i < a.length) merged[k++] = a[i++];          // leftovers
      while (j < b.length) merged[k++] = b[j++];
      System.out.println(Arrays.toString(merged));
    }
  }
  ```

  ```text [Output]
  [45, 50, 62, 62, 70, 78, 91]
  ```

  O(n + m). The two leftover loops are the part people forget; without them the
  91 is silently lost.
  :::
::

## 8. Top three in every department

The placement cell wants the three highest marks in each department, from one
list of (department, marks) rows. Tens of thousands of rows, a dozen departments.

::accordion
  :::accordion-item{label="Solution" icon="i-lucide-check"}
  **Hint:** a map from department to something that keeps only three.

  **Beginner version.** Group into lists, sort each list, take the first three.
  O(n log n), and it holds every mark in memory to throw most of them away.

  **Better version.** One min-heap of size three per department. O(n log 3),
  which is O(n).

  ```java [TopThree.java]
  import java.util.*;

  public class TopThree {
    public static void main(String[] args) {
      String[][] rows = {
          {"CSE", "91"}, {"ECE", "72"}, {"CSE", "78"}, {"ME", "70"},
          {"ECE", "88"}, {"CSE", "85"}, {"ECE", "95"}, {"CSE", "66"},
          {"ECE", "81"}, {"ME", "64"}, {"ECE", "59"}};

      Map<String, PriorityQueue<Integer>> top = new TreeMap<>();
      for (String[] row : rows) {
        PriorityQueue<Integer> heap = top.computeIfAbsent(row[0], d -> new PriorityQueue<>());
        heap.offer(Integer.parseInt(row[1]));
        if (heap.size() > 3) heap.poll();                  // drop the smallest
      }

      for (var entry : top.entrySet()) {
        List<Integer> marks = new ArrayList<>(entry.getValue());
        marks.sort(Comparator.reverseOrder());
        System.out.println(entry.getKey() + " " + marks);
      }
    }
  }
  ```

  ```text [Output]
  CSE [91, 85, 78]
  ECE [95, 88, 81]
  ME [70, 64]
  ```

  `TreeMap` only so the departments print in order. Iterating a `PriorityQueue`
  does not give sorted order, which is why the three are copied and sorted
  before printing.
  :::
::

## 9. Can anyone finish this degree?

Courses have prerequisites: Programming before DSA, DSA before DBMS and OS, OS
before Networks, Programming before Web. Print an order in which a student can
take every course, or say it is impossible because the prerequisites loop.

::accordion
  :::accordion-item{label="Solution" icon="i-lucide-check"}
  **Hint:** repeatedly take any course with no remaining prerequisites.

  **Beginner version.** DFS from each course, printing when it finishes, with no
  check for a loop. It produces an order even when the prerequisites form a
  cycle, which is the one case the registrar needed to catch.

  **Better version.** Kahn's algorithm: count incoming edges, queue the courses
  with none, and if fewer than all courses come out, there is a cycle.

  ```java [CourseOrder.java]
  import java.util.*;

  public class CourseOrder {
    static String[] names = {"Programming", "DSA", "DBMS", "OS", "Networks", "Web"};

    static List<String> order(int[][] edges) {
      int n = names.length;
      List<List<Integer>> next = new ArrayList<>();
      for (int i = 0; i < n; i++) next.add(new ArrayList<>());
      int[] waitingOn = new int[n];
      for (int[] e : edges) {                  // e[0] must come before e[1]
        next.get(e[0]).add(e[1]);
        waitingOn[e[1]]++;
      }
      Queue<Integer> ready = new ArrayDeque<>();
      for (int c = 0; c < n; c++) if (waitingOn[c] == 0) ready.offer(c);

      List<String> result = new ArrayList<>();
      while (!ready.isEmpty()) {
        int course = ready.poll();
        result.add(names[course]);
        for (int after : next.get(course)) {
          if (--waitingOn[after] == 0) ready.offer(after);
        }
      }
      return result.size() == n ? result : null;   // null means a cycle
    }

    public static void main(String[] args) {
      int[][] plan = {{0, 1}, {0, 5}, {1, 2}, {1, 3}, {3, 4}};
      System.out.println(order(plan));
      int[][] broken = {{0, 1}, {0, 5}, {1, 2}, {1, 3}, {3, 4}, {4, 0}};
      System.out.println(order(broken));
    }
  }
  ```

  ```text [Output]
  [Programming, DSA, Web, DBMS, OS, Networks]
  null
  ```

  O(V + E). In real code return an empty `Optional` or throw a clear exception
  rather than `null`; `null` keeps the example short.
  :::
::

## 10. Ways to score exactly seven

A quiz has questions worth 1, 2 and 5 marks, and any number of each can be
answered. In how many different **combinations** can a student score exactly 7?
(1 + 2 + 2 + 2 and 2 + 1 + 2 + 2 are the same combination.)

::accordion
  :::accordion-item{label="Solution" icon="i-lucide-check"}
  **Hint:** the order of the two loops decides whether you count combinations or
  orderings.

  **Beginner version.** Amount in the outer loop, question values in the inner
  loop:

  ```java
  for (int a = 1; a <= 7; a++)
    for (int q : values)
      if (q <= a) ways[a] += ways[a - q];   // counts ORDERINGS: 26
  ```

  It runs and prints 26, which counts 1 + 2 and 2 + 1 separately. The question
  asked for combinations.

  **Better version.** Values in the outer loop, so each combination is built in
  one fixed order:

  ```java [QuizScores.java]
  public class QuizScores {
    public static void main(String[] args) {
      int[] values = {1, 2, 5};
      int target = 7;
      long[] ways = new long[target + 1];
      ways[0] = 1;                                 // one way to score zero
      for (int q : values) {
        for (int a = q; a <= target; a++) {
          ways[a] += ways[a - q];
        }
      }
      System.out.println("Combinations for " + target + ": " + ways[target]);
    }
  }
  ```

  ```text [Output]
  Combinations for 7: 6
  ```

  The six: 5+2, 5+1+1, 2+2+2+1, 2+2+1+1+1, 2+1+1+1+1+1 and seven 1s. O(target ×
  values). Swapping two loops changed the question being answered, and nothing
  crashed. That is the difference between code that runs and code that is right.
  :::

## The cheat-sheet

Everything the track used, one line each. Keep this next to you while you
practise the fifty.

| When the problem says | Reach for | Java | Cost |
| --- | --- | --- | --- |
| Look up by roll number | Hash map | `HashMap<Integer, Student>` | O(1) average |
| Seen before? / duplicates | Hash set | `if (!set.add(x))` | O(1) average |
| Count occurrences | Map or `int[26]` | `map.merge(k, 1, Integer::sum)` | O(n) |
| Many range sums | Prefix sums | `long[] prefix = new long[n + 1]` | O(1) per query |
| Best contiguous sum | Kadane | two variables | O(n) |
| Sorted, find a value | Binary search | `Arrays.binarySearch(a, x)` or your own | O(log n) |
| Sorted, find a pair | Two pointers | `left`, `right` | O(n) |
| Longest / shortest stretch | Sliding window | `left`, `right`, counts | O(n) |
| Order by a rule | Sort | `list.sort(comparing(...).thenComparing(...))` | O(n log n) |
| Newest first / matching brackets | Stack | `ArrayDeque`: `push`, `pop`, `peek` | O(1) |
| Oldest first / level by level | Queue | `ArrayDeque`: `offer`, `poll`, `peek` | O(1) |
| Top k / kth largest | Min-heap of size k | `PriorityQueue<Integer>` | O(n log k) |
| Sorted keys, ranges | Tree map | `TreeMap`: `floorKey`, `subMap` | O(log n) |
| Every combination | Backtracking | choose, recurse, un-choose | O(2ⁿ) |
| Connected / islands | DFS or BFS | `boolean[] visited` | O(V + E) |
| Fewest steps, no weights | BFS | `Queue<int[]>` | O(V + E) |
| Prerequisite order | Topological sort | in-degree array + queue | O(V + E) |
| Count ways / min cost | DP | `long[] dp`, state and transition | O(states × choices) |
| Most non-overlapping | Greedy | sort by end time | O(n log n) |
