Here are the questions, word for word the way they are asked in rounds for
fresher and early-career Java roles. Try each one out loud before opening it. An
answer you can only recognise is not one you can give.

::tip
The pattern that wins almost every one of these: the short answer first, then the
reason, then the cost or the trap. Three sentences, then stop and let them ask
more.
::

## Complexity and basics

::accordion
  :::accordion-item{label="1. What is the time complexity of this code?" icon="i-lucide-message-circle"}
  Walk it loop by loop, and name hidden costs inside library calls:

  ```java
  for (int roll : rollNumbers)          // n
    if (shortlisted.contains(roll))     // ArrayList: n more. HashSet: O(1).
      notifyStudent(roll);
  ```

  O(n × m) with an `ArrayList`, O(n) with a `HashSet`. By convention an
  unqualified answer is the worst case.
  :::

  :::accordion-item{label="2. Why do we drop constants in Big-O?" icon="i-lucide-message-circle"}
  Big-O describes the shape of growth, not speed today. 3n and n both grow
  linearly, and any linear algorithm beats a quadratic one once n is large
  enough. The honest caveat: at small n the constant can win, so an O(n²) loop
  over six departments is fine.
  :::

  :::accordion-item{label="3. What is the space complexity of a recursive function?" icon="i-lucide-message-circle"}
  At least the maximum recursion depth, because each call keeps a frame on the
  stack. A recursive sum of n marks is O(n) space even with no arrays:

  ```java
  static int sum(int[] marks, int i) {
    if (i == marks.length) return 0;
    return marks[i] + sum(marks, i + 1);   // n frames deep at the bottom
  }
  ```
  :::

  :::accordion-item{label="4. Array or ArrayList or LinkedList?" icon="i-lucide-message-circle"}
  Array for a fixed size and primitives. `ArrayList` for almost every list: O(1)
  index, contiguous, cache-friendly. `LinkedList` rarely: its O(1) insert needs
  you to already hold the node, and walking it is slow in practice. For a queue
  or stack use `ArrayDeque`.
  :::
::

## Arrays, strings and hashing

::accordion
  :::accordion-item{label="5. Why is string concatenation in a loop slow?" icon="i-lucide-message-circle"}
  `String` is immutable, so each `+=` builds a new string and copies everything
  so far: O(n²) total. `StringBuilder` appends in amortised O(1).

  ```java [Concat.java]
  public class Concat {
    public static void main(String[] args) {
      StringBuilder roll = new StringBuilder();
      for (int i = 1; i <= 5; i++) roll.append("CSE").append(i).append(' ');
      System.out.println(roll.toString().trim());
    }
  }
  ```

  ```text [Output]
  CSE1 CSE2 CSE3 CSE4 CSE5
  ```
  :::

  :::accordion-item{label="6. Find the maximum sum of a contiguous subarray" icon="i-lucide-message-circle"}
  Kadane: keep the best sum ending here; restart when it goes negative.

  ```java [BestStretch.java]
  public class BestStretch {
    public static void main(String[] args) {
      int[] change = {-2, 1, -3, 4, -1, 2, 1, -5, 4};   // daily attendance change
      int endingHere = change[0], best = change[0];
      for (int i = 1; i < change.length; i++) {
        endingHere = Math.max(change[i], endingHere + change[i]);
        best = Math.max(best, endingHere);
      }
      System.out.println(best);
    }
  }
  ```

  ```text [Output]
  6
  ```

  Initialise with the first element, not 0, or an all-negative array returns 0.
  :::

  :::accordion-item{label="7. Check whether two names are anagrams" icon="i-lucide-message-circle"}
  Count letters up for one, down for the other; every count must end at 0.
  O(n) time, O(1) space (26 counters).

  ```java
  static boolean isAnagram(String a, String b) {
    if (a.length() != b.length()) return false;
    int[] count = new int[26];
    for (int i = 0; i < a.length(); i++) {
      count[a.charAt(i) - 'a']++;
      count[b.charAt(i) - 'a']--;
    }
    for (int c : count) if (c != 0) return false;
    return true;
  }
  // isAnagram("listen", "silent") → true
  ```
  :::

  :::accordion-item{label="8. How does HashMap work internally?" icon="i-lucide-message-circle"}
  `hashCode()` of the key, spread and reduced to a bucket index; the bucket holds
  entries; within it keys are compared with `equals`. Collisions are normal; a
  bucket past eight entries becomes a red-black tree (when the table has at least
  64 buckets). Past a 0.75 load factor the table doubles and every entry is
  rehashed. Average O(1), worst case O(n) with a bad hash.
  :::

  :::accordion-item{label="9. What happens if you override equals but not hashCode?" icon="i-lucide-message-circle"}
  Two equal objects land in different buckets, so the map never finds the second
  one:

  ```java [BrokenKey.java]
  import java.util.*;

  public class BrokenKey {
    static class Student {
      final String roll;
      Student(String roll) { this.roll = roll; }
      @Override public boolean equals(Object o) {
        return o instanceof Student s && roll.equals(s.roll);
      }
      // no hashCode
    }

    public static void main(String[] args) {
      Set<Student> present = new HashSet<>();
      present.add(new Student("CSE042"));
      System.out.println(present.contains(new Student("CSE042")));
      present.add(new Student("CSE042"));
      System.out.println(present.size());
    }
  }
  ```

  ```text [Output]
  false
  2
  ```

  A set with the same student twice. Add `hashCode` returning `roll.hashCode()`
  and both lines become `true` and `1`.
  :::

  :::accordion-item{label="10. Two sum: return the indices of two marks that add to a target" icon="i-lucide-message-circle"}
  Brute force is O(n²). One pass with a map from mark to index is O(n):

  ```java
  static int[] twoSum(int[] marks, int target) {
    Map<Integer, Integer> seenAt = new HashMap<>();
    for (int i = 0; i < marks.length; i++) {
      Integer j = seenAt.get(target - marks[i]);
      if (j != null) return new int[]{j, i};
      seenAt.put(marks[i], i);
    }
    return new int[]{-1, -1};
  }
  // twoSum(new int[]{45, 72, 31, 55}, 100) → [0, 3]
  ```
  :::

  :::accordion-item{label="11. Why does comparing two Integer counts with == sometimes fail?" icon="i-lucide-message-circle"}
  Java caches `Integer` objects from -128 to 127. Outside that, `==` compares
  references.

  ```java [IntegerCache.java]
  import java.util.*;

  public class IntegerCache {
    public static void main(String[] args) {
      Map<String, Integer> count = new HashMap<>();
      count.put("CSE", 100); count.put("ECE", 100);
      System.out.println(count.get("CSE") == count.get("ECE"));
      count.put("CSE", 300); count.put("ECE", 300);
      System.out.println(count.get("CSE") == count.get("ECE"));
      System.out.println(count.get("CSE").equals(count.get("ECE")));
    }
  }
  ```

  ```text [Output]
  true
  false
  true
  ```
  :::

## Searching, sorting and recursion

::accordion
  :::accordion-item{label="12. Write binary search. What are the traps?" icon="i-lucide-message-circle"}
  `low <= high`, `mid = low + (high - low) / 2` (the sum can overflow `int`),
  and `low = mid + 1` / `high = mid - 1` (or a two-element range never shrinks).
  The data must be sorted.

  ```java
  static int search(int[] sorted, int target) {
    int low = 0, high = sorted.length - 1;
    while (low <= high) {
      int mid = low + (high - low) / 2;
      if (sorted[mid] == target) return mid;
      if (sorted[mid] < target) low = mid + 1; else high = mid - 1;
    }
    return -1;
  }
  ```
  :::

  :::accordion-item{label="13. Find the first occurrence of a mark in a sorted array" icon="i-lucide-message-circle"}
  On a match, record it and keep searching left:

  ```java
  static int first(int[] sorted, int target) {
    int low = 0, high = sorted.length - 1, answer = -1;
    while (low <= high) {
      int mid = low + (high - low) / 2;
      if (sorted[mid] == target) { answer = mid; high = mid - 1; }
      else if (sorted[mid] < target) low = mid + 1;
      else high = mid - 1;
    }
    return answer;
  }
  // first(new int[]{40, 55, 55, 55, 78}, 55) → 1
  ```

  For the last occurrence, move `low = mid + 1` on a match instead.
  :::

  :::accordion-item{label="14. Merge sort or quick sort?" icon="i-lucide-message-circle"}
  Merge sort: O(n log n) always, stable, O(n) extra space. Quick sort: O(n log n)
  on average, O(n²) worst case (a bad pivot on sorted data), in place, not
  stable, and usually faster in practice because it is cache-friendly. Java uses
  a dual-pivot quicksort for primitives and Timsort (a merge sort) for objects.
  :::

  :::accordion-item{label="15. What is a stable sort and why does it matter?" icon="i-lucide-message-circle"}
  Equal elements keep their input order. Sort students by name, then stably by
  marks, and students with equal marks stay alphabetical:

  ```java [StableSort.java]
  import java.util.*;

  public class StableSort {
    record Student(String name, int marks) { }

    public static void main(String[] args) {
      List<Student> list = new ArrayList<>(List.of(
          new Student("Rahul", 72), new Student("Anita", 88),
          new Student("Kiran", 72), new Student("Divya", 88)));
      list.sort(Comparator.comparing(Student::name));
      list.sort(Comparator.comparingInt(Student::marks).reversed());
      list.forEach(s -> System.out.println(s.marks() + " " + s.name()));
    }
  }
  ```

  ```text [Output]
  88 Anita
  88 Divya
  72 Kiran
  72 Rahul
  ```
  :::

  :::accordion-item{label="16. What is the difference between recursion and iteration?" icon="i-lucide-message-circle"}
  Anything recursive can be written with a loop and an explicit stack. Recursion
  is clearer for trees, backtracking and divide and conquer; it costs a stack
  frame per call and throws `StackOverflowError` once the default thread stack
  fills, typically somewhere in the thousands to tens of thousands of calls
  depending on how big each frame is. Iteration is safer for long linear work.
  :::

  :::accordion-item{label="17. Generate all subsets of a set of electives" icon="i-lucide-message-circle"}
  Backtracking: include or exclude each item. 2ⁿ subsets.

  ```java
  static void subsets(String[] electives, int i, List<String> chosen, List<List<String>> out) {
    if (i == electives.length) { out.add(new ArrayList<>(chosen)); return; }
    chosen.add(electives[i]);                     // choose
    subsets(electives, i + 1, chosen, out);       // explore
    chosen.remove(chosen.size() - 1);             // un-choose
    subsets(electives, i + 1, chosen, out);
  }
  // three electives → 8 subsets
  ```

  The trap: adding `chosen` itself instead of a copy leaves eight references to
  one empty list.
  :::
::

## Linked lists, stacks, queues

::accordion
  :::accordion-item{label="18. Reverse a linked list" icon="i-lucide-message-circle"}
  Three pointers, O(n) time, O(1) space:

  ```java
  static Node reverse(Node head) {
    Node previous = null, current = head;
    while (current != null) {
      Node next = current.next;    // save before breaking the link
      current.next = previous;
      previous = current;
      current = next;
    }
    return previous;               // the old tail is the new head
  }
  ```
  :::

  :::accordion-item{label="19. Detect a cycle in a linked list" icon="i-lucide-message-circle"}
  Floyd's slow and fast pointers. If there is a loop, the fast one laps the slow
  one; if not, fast reaches `null`. O(n) time, O(1) space, versus a `HashSet` of
  visited nodes at O(n) space.

  ```java
  static boolean hasCycle(Node head) {
    Node slow = head, fast = head;
    while (fast != null && fast.next != null) {
      slow = slow.next;
      fast = fast.next.next;
      if (slow == fast) return true;
    }
    return false;
  }
  ```
  :::

  :::accordion-item{label="20. Why ArrayDeque instead of Stack?" icon="i-lucide-message-circle"}
  `Stack` extends `Vector`: every method is synchronised (a cost you rarely need)
  and it exposes indexed access, which breaks the idea of a stack. `ArrayDeque`
  is faster and is what the Java documentation itself recommends.
  :::

  :::accordion-item{label="21. Next greater element for each day's attendance" icon="i-lucide-message-circle"}
  A monotonic stack of indices still waiting for an answer. Each index is pushed
  and popped once: O(n).

  ```java [NextGreater.java]
  import java.util.*;

  public class NextGreater {
    public static void main(String[] args) {
      int[] present = {42, 38, 45, 40, 50};
      int[] answer = new int[present.length];
      Arrays.fill(answer, -1);
      Deque<Integer> waiting = new ArrayDeque<>();
      for (int i = 0; i < present.length; i++) {
        while (!waiting.isEmpty() && present[waiting.peek()] < present[i]) {
          answer[waiting.pop()] = present[i];
        }
        waiting.push(i);
      }
      System.out.println(Arrays.toString(answer));
    }
  }
  ```

  ```text [Output]
  [45, 45, 50, 50, -1]
  ```
  :::
::

## Trees, graphs, DP

::accordion
  :::accordion-item{label="22. Height of a binary tree" icon="i-lucide-message-circle"}
  One plus the taller subtree; an empty tree is 0 (or -1 if the interviewer
  counts edges, so ask).

  ```java
  static int height(TreeNode node) {
    if (node == null) return 0;
    return 1 + Math.max(height(node.left), height(node.right));
  }
  ```

  O(n) time, O(h) stack space, where h is the height.
  :::

  :::accordion-item{label="23. Kth largest mark among n students" icon="i-lucide-message-circle"}
  A min-heap of size k: the smallest of the top k sits at the top. O(n log k),
  better than sorting when k is small.

  ```java [KthLargest.java]
  import java.util.*;

  public class KthLargest {
    public static void main(String[] args) {
      int[] marks = {67, 91, 45, 88, 73, 95, 58};
      int k = 3;
      PriorityQueue<Integer> top = new PriorityQueue<>();
      for (int m : marks) {
        top.offer(m);
        if (top.size() > k) top.poll();
      }
      System.out.println(k + "rd highest: " + top.peek());
    }
  }
  ```

  ```text [Output]
  3rd highest: 88
  ```
  :::

  :::accordion-item{label="24. BFS or DFS?" icon="i-lucide-message-circle"}
  BFS (a queue) visits by distance, so it finds the shortest path when edges have
  no weights. DFS (recursion or a stack) goes deep first and suits
  connectivity, cycle detection and topological sort. Both are O(V + E) with an
  adjacency list and both need a visited set.
  :::

  :::accordion-item{label="25. How do you know a problem needs dynamic programming?" icon="i-lucide-message-circle"}
  It asks for a count of ways, a minimum, a maximum or "is it possible", and the
  brute-force recursion solves the same subproblem repeatedly. Then say the
  recipe: state, transition, base case, order. Climbing stairs:

  ```java
  static long ways(int n) {
    long before = 1, last = 1;            // ways(0), ways(1)
    for (int i = 2; i <= n; i++) {
      long now = before + last;           // came from i-1 or i-2
      before = last; last = now;
    }
    return last;
  }
  // ways(5) → 8
  ```
  :::
