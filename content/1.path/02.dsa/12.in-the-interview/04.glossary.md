Here is every word from this track, on one page. This is the page to read on
the morning of an interview. The first table is the one to know by heart.

## The cost table

| Structure | Access | Search | Insert | Delete | Notes |
| --- | --- | --- | --- | --- | --- |
| Array / `ArrayList` | **O(1)** by index | O(n) | O(1) amortised at end, O(n) middle | O(n) | Contiguous, cache-friendly. The default. |
| Sorted array | O(1) | **O(log n)** binary search | O(n) | O(n) | Fast to search, slow to change |
| Linked list | O(n) | O(n) | O(1) **once you hold the node** | O(1) once you hold the node | Extra memory per node for the pointer |
| Stack (`ArrayDeque`) | top only | O(n) | O(1) push | O(1) pop | Last in, first out |
| Queue (`ArrayDeque`) | ends only | O(n) | O(1) offer | O(1) poll | First in, first out |
| `HashMap` / `HashSet` | by key **O(1)** average | O(1) average | O(1) average | O(1) average | No order. Worst case O(n) with a bad hash. |
| `TreeMap` / `TreeSet` | O(log n) | O(log n) | O(log n) | O(log n) | Sorted keys, ranges, floor and ceiling |
| Binary search tree | O(log n) if balanced | O(log n) | O(log n) | O(log n) | **O(n) when skewed** |
| Heap (`PriorityQueue`) | top O(1) | O(n) | O(log n) | O(log n) remove top | Min at the top by default |
| Graph (adjacency list) | | BFS / DFS O(V + E) | add edge O(1) | | Space O(V + E) |

## The algorithms

| Algorithm | Time | Extra space | Stable? |
| --- | --- | --- | --- |
| Linear search | O(n) | O(1) | |
| Binary search | O(log n) | O(1) iterative | |
| Bubble, selection, insertion sort | O(n²) | O(1) | Bubble and insertion yes, selection no |
| Merge sort | O(n log n) always | O(n) | **Yes** |
| Quick sort | O(n log n) average, O(n²) worst | O(log n) stack | No |
| Counting sort | O(n + k), k = range of values | O(k) | Yes (the prefix-sum version) |
| Heap sort | O(n log n) | O(1) | No |
| `Arrays.sort(int[])` | O(n log n) | dual-pivot quicksort | No (does not matter for primitives) |
| `Arrays.sort(Object[])`, `List.sort` | O(n log n) | Timsort, O(n) | **Yes** |
| BFS / DFS | O(V + E) | O(V) | |
| Dijkstra with a heap | O((V + E) log V) | O(V) | |
| Kadane | O(n) | O(1) | |

## Complexity

| Term | In one line |
| --- | --- |
| **Big-O** | How the work grows when the input grows. Ten times the input: how much more work? |
| **O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ), O(n!)** | Constant, logarithmic, linear, linearithmic, quadratic, exponential, factorial. In order from best to worst. |
| **Worst / best / average case** | An unqualified complexity means the worst case. |
| **Amortised** | Averaged over many operations. `ArrayList.add` is usually O(1), occasionally a full copy, O(1) on average. |
| **Space complexity** | Extra memory used, including the recursion call stack. |
| **Auxiliary space** | Memory beyond the input itself. What interviewers usually mean by "space". |
| **Constraints** | The limits on n under a problem. They tell you the complexity the setter expects: about 10⁸ simple steps a second. |

## Arrays, strings and hashing

| Term | In one line |
| --- | --- |
| **Contiguous** | Stored side by side in memory. Why array access is arithmetic. |
| **Prefix sum** | `prefix[i]` = total of the first i elements, so any range sum is one subtraction. |
| **Subarray / substring** | A continuous stretch of an array / string. |
| **Subsequence** | Elements in their original order, not necessarily continuous. |
| **Immutable** | Cannot change after creation. Java `String` is, so `+=` in a loop copies every time. |
| **Anagram** | Same letters, same counts, different order. |
| **Frequency array** | `int[26]` counting letters, index `c - 'a'`. |
| **Hash function / `hashCode`** | Turns a key into a number used to pick a bucket. |
| **Bucket / collision** | A slot in the hash table / two keys in the same slot. Normal. |
| **Load factor** | Entries divided by buckets. Java resizes past 0.75 and rehashes everything. |
| **`equals` / `hashCode` contract** | Equal objects must have equal hash codes, or a map cannot find its own entries. |

## Recursion, searching and sorting

| Term | In one line |
| --- | --- |
| **Base case** | The input small enough to answer directly. Without one, `StackOverflowError`. |
| **Call stack** | Where each method call's variables live until it returns. |
| **Backtracking** | Choose, explore, undo, try the next choice. Generates every possibility. |
| **Divide and conquer** | Split into halves, solve each, combine. Merge sort and quick sort. |
| **Lower bound** | The first index whose value is at least the target. |
| **Rotated sorted array** | A sorted array cut at some point and swapped: `[40, 50, 10, 20, 30]`. One half is always sorted. |
| **Pivot / partition** | The element quick sort splits around / the step that puts smaller left and larger right. |
| **Stable sort** | Equal elements keep their original order. |
| **In-place** | Uses O(1) extra memory (apart from a few variables). |
| **Comparator / Comparable** | An external ordering rule / the natural order a class defines for itself. |

## Patterns

| Term | In one line |
| --- | --- |
| **Two pointers** | Two indices moving through the data, from both ends or in the same direction. |
| **Sliding window** | A contiguous range that grows on the right and shrinks on the left. |
| **Slow and fast pointers** | One moves one step, the other two. Finds the middle and detects cycles (Floyd). |
| **Monotonic stack** | A stack kept increasing or decreasing. Answers "next greater" in O(n). |
| **Dummy node** | A fake head before the real one, so changing the first node needs no special case. |

## Trees, heaps and graphs

| Term | In one line |
| --- | --- |
| **Root / leaf / height** | The top node / a node with no children / edges on the longest root-to-leaf path. |
| **Pre-, in-, post-order** | Self first / self between the children / self last. |
| **Level order** | Row by row, with a queue. BFS on a tree. |
| **BST** | Every left descendant smaller, every right descendant larger. In-order is sorted. |
| **Balanced** | Height stays about log n. Red-black trees in `TreeMap`. |
| **Heap** | A complete tree in an array where each parent beats its children. Children of i at 2i+1 and 2i+2. |
| **Vertex / edge** | A thing / a connection between two things. |
| **Directed / weighted** | Edges have a direction / a cost. |
| **Adjacency list / matrix** | Each vertex's neighbours in a list / a V × V grid of true and false. |
| **Visited set** | What stops a graph walk from going round forever. |
| **Topological sort** | An order where every prerequisite comes before what needs it. Only for graphs with no cycle. |
| **Dijkstra** | Shortest paths with non-negative weights, using a priority queue. |

## Dynamic programming and greedy

| Term | In one line |
| --- | --- |
| **Overlapping subproblems** | The same smaller question comes up again and again. |
| **Optimal substructure** | The best answer is built from best answers to smaller parts. |
| **Memoisation** | Top-down: recursion plus a memo of answers. |
| **Tabulation** | Bottom-up: fill a table from the base cases. |
| **State / transition** | What `dp[i]` means / how it is built from smaller states. |
| **0/1 knapsack** | Take each item whole or not at all, under a limit. |
| **Greedy** | Take the best-looking choice now and never undo it. |
| **Exchange argument** | Proof that swapping in the greedy choice never makes an answer worse. |

## The pairs people confuse

::feature-list{columns="2"}
  :::feature{icon="i-lucide-split" title="Subarray and subsequence"}
  A subarray is continuous. A subsequence only keeps the order. "Longest common
  substring" and "longest common subsequence" are different problems.
  :::
  :::feature{icon="i-lucide-split" title="Heap (structure) and heap (memory)"}
  The priority queue's tree has nothing to do with the JVM heap where objects
  live. Same word, two meanings.
  :::
  :::feature{icon="i-lucide-split" title="Memoisation and tabulation"}
  Same answers, opposite order. Top-down recursion with a cache, or bottom-up
  loops over a table.
  :::
  :::feature{icon="i-lucide-split" title="Greedy and DP"}
  Greedy commits to one choice per step. DP keeps the best answer for every state.
  :::
  :::feature{icon="i-lucide-split" title="Binary tree and BST"}
  Every BST is a binary tree. Most binary trees are not BSTs.
  :::
  :::feature{icon="i-lucide-split" title="Stable and in-place"}
  Stable is about equal elements' order. In-place is about extra memory. Merge
  sort is stable, not in-place; quick sort is in-place, not stable.
  :::
::
