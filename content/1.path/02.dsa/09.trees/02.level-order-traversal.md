To read a tree row by row you need to remember, while reading one row, who is
waiting on the next row. The people waiting should be served in the order they
were discovered, first discovered, first served. That is a queue, and **level
order traversal** is nothing more than a queue applied to a tree.

## Why this matters in a job

Level order is **breadth-first search (BFS)** on a tree. BFS is the algorithm
that finds the fewest steps between two points, and you will use exactly this
code on graphs two lessons from now. In interviews, "print a binary tree level
by level" is a staple, and at least five other common questions (right side
view, left view, largest value in each row, average of each level, zigzag
order, minimum depth) are the same loop with one line changed. Learn the loop
once and you have all of them.

## A fire drill

When the fire alarm rings in a hostel, the warden clears floors from the top
down. She lists everyone on the top floor; as each person comes out, they tell
her who is in the rooms below them, and those names go to the **end** of her
list. She never goes down to the next floor until everyone on this floor is
out. Each name is dealt with in the order it was added: a queue.

::flow{numbered caption="One pass of the loop"}
  :::flow-step{label="Measure the level" icon="i-lucide-ruler" highlight}
  Everyone currently in the queue belongs to one level. Write down how many
  there are before touching anybody.
  :::
  :::flow-step{label="Take exactly that many" icon="i-lucide-arrow-up-from-line"}
  Poll each one, visit it.
  :::
  :::flow-step{label="Queue their children" icon="i-lucide-arrow-down-to-line"}
  Left child, then right child, to the back of the queue. They are the next
  level.
  :::
::

The first step is the one that makes the difference. Without it, you still
visit nodes in level order, but you cannot tell where one level ends and the
next begins.

## How it works

The same college chart as the last lesson, with the number of students under
each node.

```java [LevelOrder.java]
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.List;
import java.util.Queue;

public class LevelOrder {
  static class Node {
    String name;
    int students;
    Node left, right;
    Node(String name, int students) { this.name = name; this.students = students; }
  }

  static List<List<String>> byLevel(Node root) {
    List<List<String>> levels = new ArrayList<>();
    if (root == null) return levels;
    Queue<Node> queue = new ArrayDeque<>();
    queue.offer(root);
    while (!queue.isEmpty()) {
      int width = queue.size();                 // how many nodes are on THIS level
      List<String> level = new ArrayList<>();
      for (int i = 0; i < width; i++) {
        Node node = queue.poll();
        level.add(node.name);
        if (node.left != null) queue.offer(node.left);
        if (node.right != null) queue.offer(node.right);
      }
      levels.add(level);
    }
    return levels;
  }

  static List<String> rightView(Node root) {
    List<String> view = new ArrayList<>();
    for (List<String> level : byLevel(root)) view.add(level.get(level.size() - 1));
    return view;
  }

  static List<Integer> maxPerLevel(Node root) {
    List<Integer> result = new ArrayList<>();
    if (root == null) return result;
    Queue<Node> queue = new ArrayDeque<>();
    queue.offer(root);
    while (!queue.isEmpty()) {
      int width = queue.size(), best = Integer.MIN_VALUE;
      for (int i = 0; i < width; i++) {
        Node node = queue.poll();
        best = Math.max(best, node.students);
        if (node.left != null) queue.offer(node.left);
        if (node.right != null) queue.offer(node.right);
      }
      result.add(best);
    }
    return result;
  }

  public static void main(String[] args) {
    Node dean = new Node("Dean", 2400);
    dean.left = new Node("HOD-CSE", 960);
    dean.right = new Node("HOD-ECE", 720);
    dean.left.left = new Node("DSA", 180);
    dean.left.right = new Node("DBMS", 240);
    dean.right.right = new Node("Signals", 120);

    List<List<String>> levels = byLevel(dean);
    for (int i = 0; i < levels.size(); i++) {
      System.out.println("level " + i + ": " + levels.get(i));
    }
    System.out.println("right view:    " + rightView(dean));
    System.out.println("max per level: " + maxPerLevel(dean));
  }
}
```

```text [Output]
level 0: [Dean]
level 1: [HOD-CSE, HOD-ECE]
level 2: [DSA, DBMS, Signals]
right view:    [Dean, HOD-ECE, Signals]
max per level: [2400, 960, 240]
```

### The variants are one line each

| Question | Change to the loop |
| --- | --- |
| Level by level | Collect each level into its own list (above) |
| **Right side view** | Keep the **last** node of each level |
| Left side view | Keep the **first** node of each level (`i == 0`) |
| Largest value in each row | Track a max inside the level (above) |
| Average of each level | Track a sum and divide by `width` |
| **Zigzag** order | Reverse every second level's list before adding it |
| Minimum depth | Return the level number of the first leaf you poll |

Minimum depth is the one where BFS genuinely beats DFS: BFS stops at the first
leaf it meets, which is the shallowest, without exploring the deep branches at
all.

### Complexity

| | Time | Extra space |
| --- | --- | --- |
| Level order | O(n) | O(w), where w is the widest level |

On a complete tree the last level holds about half the nodes, so w is about
n / 2 and the space is O(n). Compare depth-first traversals, which need O(h):
for a wide, bushy tree DFS uses less memory; for a tall, thin one BFS does.

## Real use case

::real-life{title="Who hears first" source="A college notice system"}
An urgent notice goes out from the principal. It reaches the heads of
department first, then the faculty, then the class representatives, then the
students. "How many people are informed at each stage, and how many stages
until everybody knows?" is exactly level order traversal of the reporting
tree: the number of levels is the number of stages, and the width of each level
is the number of people reached at that stage.
::

The same loop, pointed at a graph instead of a tree, is how a social network
suggests "people you may know" at distance two, and how a campus map finds the
route with the fewest turns. You will write that in the graphs chapter.

## What confuses people here

- **Reading `queue.size()` inside the `for` condition.** `for (int i = 0; i <
  queue.size(); i++)` recomputes the size every iteration, and the size changes
  as you add children. Store it in `width` first.
- **Using a stack by mistake.** Replace the queue with a stack and you get a
  depth-first order. If your "level order" output looks like preorder, check
  which structure you declared.
- **Forgetting the empty tree.** Offering `null` onto an `ArrayDeque` throws
  `NullPointerException`. Return an empty list if `root == null`.
- **Right view is not "all right children".** In a tree where the rightmost
  node on a level is a left child, it still appears in the right view. Take
  the last node of each level, not the right pointer chain.

## Interview questions

::accordion
  :::accordion-item{label="Print a binary tree level by level." icon="i-lucide-message-circle"}
  A queue, seeded with the root. While it is not empty: read its size, poll that
  many nodes, add each to the current level, offer their children. O(n) time,
  O(w) space.
  :::
  :::accordion-item{label="Right side view of a binary tree." icon="i-lucide-message-circle"}
  Level order, keeping the last node polled on each level. A DFS alternative
  visits right before left and records the first node seen at each new depth.
  :::
  :::accordion-item{label="Zigzag level order." icon="i-lucide-message-circle"}
  Level order with a boolean that flips every level; when it is set, reverse
  the level's list (or add to the front of a `Deque`) before storing it.
  :::
  :::accordion-item{label="BFS or DFS for the minimum depth of a tree?" icon="i-lucide-message-circle"}
  BFS. It meets levels in order, so the first leaf it polls is at the minimum
  depth and it can stop immediately. DFS must explore every branch to be sure.
  :::
::
