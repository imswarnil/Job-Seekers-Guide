A tree is what you get when each item can point to more than one next item. The
dean has two heads of department under her; each head has courses under them. No
line can hold that shape, because "next" is no longer one thing.

## Why this matters in a job

Trees are the structure of things you use every day: folders on disk, the HTML
of every web page (the DOM), a company's reporting chain, the categories in a
course catalogue. `TreeMap` is a tree, a database index is a tree, and the
`PriorityQueue` at the end of this chapter is a tree stored in an array. In
product-company interviews, tree questions are the single largest group after
arrays, and nearly every one is a traversal with a small twist.

## The idea: a family chart

Draw the college's reporting chart. The **root** is the dean at the top. Each
person reports to exactly one person above them, their **parent**, and may have
people below them, their **children**. People with nobody below them are
**leaves**. A **binary tree** is the version where every node has at most two
children, called `left` and `right`.

The vocabulary, once, because interviewers use it without defining it:

| Word | Meaning |
| --- | --- |
| **Root** | The top node. The only node with no parent. |
| **Leaf** | A node with no children. |
| **Subtree** | A node and everything below it. Every child is the root of its own subtree. |
| **Depth** of a node | Edges from the root down to it. The root has depth 0. |
| **Height** of a tree | Nodes on the longest root-to-leaf path. Some books count edges instead, which is one less; say which you mean. |
| **Full / complete / perfect** | Every node has 0 or 2 children / every level filled except possibly the last, filled left to right / every level completely filled. |

The key sentence for the whole chapter: **every child is itself the root of a
smaller tree**. That is why nearly every tree algorithm is recursive. You solve
the problem for the left subtree, solve it for the right subtree, and combine.

## How it works

### Three depth-first orders

A **traversal** visits every node once. The three depth-first traversals all
go down the left side first; they differ only in **when you visit the node
itself** relative to its two subtrees.

| Traversal | Order | Where you meet it |
| --- | --- | --- |
| **Preorder** | self, left, right | Copying a tree; printing a folder listing with indentation |
| **Inorder** | left, self, right | On a binary search tree, gives the values **sorted** |
| **Postorder** | left, right, self | Deleting a tree (children before parent); adding up folder sizes |

A way to remember them: the prefix says where "self" goes. **Pre** is before
the children, **in** is in between, **post** is after.

```java [Traversals.java]
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;

public class Traversals {
  static class Node {
    String name;
    Node left, right;
    Node(String name) { this.name = name; }
  }

  static void preorder(Node node, List<String> out) {
    if (node == null) return;
    out.add(node.name);            // self
    preorder(node.left, out);      // left
    preorder(node.right, out);     // right
  }

  static void inorder(Node node, List<String> out) {
    if (node == null) return;
    inorder(node.left, out);
    out.add(node.name);
    inorder(node.right, out);
  }

  static void postorder(Node node, List<String> out) {
    if (node == null) return;
    postorder(node.left, out);
    postorder(node.right, out);
    out.add(node.name);
  }

  static List<String> inorderIterative(Node root) {
    List<String> out = new ArrayList<>();
    Deque<Node> stack = new ArrayDeque<>();
    Node current = root;
    while (current != null || !stack.isEmpty()) {
      while (current != null) {          // go as far left as possible
        stack.push(current);
        current = current.left;
      }
      current = stack.pop();             // nothing further left: visit
      out.add(current.name);
      current = current.right;           // then try the right subtree
    }
    return out;
  }

  static List<String> preorderIterative(Node root) {
    List<String> out = new ArrayList<>();
    if (root == null) return out;
    Deque<Node> stack = new ArrayDeque<>();
    stack.push(root);
    while (!stack.isEmpty()) {
      Node node = stack.pop();
      out.add(node.name);
      if (node.right != null) stack.push(node.right);   // right first,
      if (node.left != null) stack.push(node.left);     // so left is popped first
    }
    return out;
  }

  static int height(Node node) {
    if (node == null) return 0;
    return 1 + Math.max(height(node.left), height(node.right));
  }

  static int count(Node node) {
    if (node == null) return 0;
    return 1 + count(node.left) + count(node.right);
  }

  public static void main(String[] args) {
    Node dean = new Node("Dean");
    dean.left = new Node("HOD-CSE");
    dean.right = new Node("HOD-ECE");
    dean.left.left = new Node("DSA");
    dean.left.right = new Node("DBMS");
    dean.right.right = new Node("Signals");

    List<String> pre = new ArrayList<>(), in = new ArrayList<>(), post = new ArrayList<>();
    preorder(dean, pre);
    inorder(dean, in);
    postorder(dean, post);
    System.out.println("preorder:            " + pre);
    System.out.println("inorder:             " + in);
    System.out.println("postorder:           " + post);
    System.out.println("inorder, iterative:  " + inorderIterative(dean));
    System.out.println("preorder, iterative: " + preorderIterative(dean));
    System.out.println("height: " + height(dean) + ", nodes: " + count(dean));
  }
}
```

```text [Output]
inorder:             [DSA, HOD-CSE, DBMS, Dean, HOD-ECE, Signals]
postorder:           [DSA, DBMS, HOD-CSE, Signals, HOD-ECE, Dean]
inorder, iterative:  [DSA, HOD-CSE, DBMS, Dean, HOD-ECE, Signals]
preorder, iterative: [Dean, HOD-CSE, DSA, DBMS, HOD-ECE, Signals]
height: 3, nodes: 6
```

### Why the iterative versions need a stack

The recursive versions look like they use no data structure at all. They do:
the **call stack**. Each recursive call is a frame remembering "I still have to
do my right subtree". The iterative versions make that stack visible with an
`ArrayDeque`, exactly as the Stacks lesson promised.

::code-trace{caption="Iterative inorder: the shape interviewers ask you to write without recursion."}
```java [Traversals.java]
while (current != null || !stack.isEmpty()) {
  while (current != null) {
    stack.push(current);
    current = current.left;
  }
  current = stack.pop();
  out.add(current.name);
  current = current.right;
}
```

  :::code-trace-step{lines="2-5" caption="Dive left, pushing every node you pass. They are all waiting to be visited after their left subtree."}
  :::
  :::code-trace-step{lines="6-7" caption="Nothing further left. Pop the most recent node and visit it: its whole left subtree is done."}
  :::
  :::code-trace-step{lines="8" caption="Now do its right subtree, by the same rule. If there is none, current is null and the next loop pops the parent."}
  :::
::

In the iterative preorder, the right child is pushed **before** the left,
because a stack gives back the last thing pushed, and we want left first.

### Height and count, the recursive recipe

`height` and `count` show the recipe that solves most tree questions:

1. **Base case:** an empty tree (`null`) has height 0 and 0 nodes.
2. **Ask both children** for their answer.
3. **Combine:** height is `1 + max(left, right)`; count is `1 + left + right`.

Sum of marks, maximum value, number of leaves and "are these two trees
identical" are the same three steps with a different combine line.

### Complexity

| Operation | Time | Extra space |
| --- | --- | --- |
| Any traversal, recursive | O(n) | O(h), the height, for the call stack |
| Any traversal, iterative | O(n) | O(h) for the explicit stack |
| Height, count, sum | O(n) | O(h) |

h is between log n (a well-balanced tree) and n (a tree that is really a line,
each node having one child). "O(h)" is the precise answer; say both extremes.

## Real use case

Your file system is a tree, and "how much space does this folder use" is a
postorder traversal: you cannot total a folder until you have totalled every
subfolder inside it. The browser's DOM is a tree, and
`document.querySelectorAll` in the JavaScript track is a preorder walk that
collects matching nodes in document order. When a college portal renders a
nested menu (Departments → CSE → Semester 3 → Subjects), the code that draws
it with indentation is a preorder traversal carrying the depth.

## What confuses people here

- **Forgetting the `null` base case.** Every recursive tree method starts with
  `if (node == null) return ...`. Without it, the first leaf throws a
  `NullPointerException`.
- **Height in nodes or in edges.** A single node has height 1 in nodes and 0 in
  edges. Both are used. State your convention before you answer.
- **Pushing left before right in iterative preorder.** The stack reverses the
  order, so you get self, right, left. Push right first.
- **Inorder is "sorted".** Only on a binary search tree, which is two lessons
  away. On this college chart, inorder is a perfectly valid order with no
  special meaning.

## Interview questions

::accordion
  :::accordion-item{label="Write preorder, inorder and postorder. Which one is sorted?" icon="i-lucide-message-circle"}
  Three recursive methods that differ only in where `out.add(node)` sits. On a
  binary search tree, inorder visits the values in ascending order. Postorder
  is the one for deleting or freeing a tree, because children are processed
  before their parent.
  :::
  :::accordion-item{label="Inorder traversal without recursion." icon="i-lucide-message-circle"}
  An `ArrayDeque` as a stack and a `current` pointer: push and go left until
  `null`, pop and visit, then go right. Loop while `current != null ||
  !stack.isEmpty()`. O(n) time, O(h) space.
  :::
  :::accordion-item{label="Find the height (maximum depth) of a binary tree." icon="i-lucide-message-circle"}
  `return node == null ? 0 : 1 + Math.max(height(node.left),
  height(node.right));` O(n) time, since every node is visited once, and O(h)
  stack space.
  :::
  :::accordion-item{label="Check whether two trees are identical." icon="i-lucide-message-circle"}
  ```java
  static boolean same(Node a, Node b) {
    if (a == null || b == null) return a == b;       // both null, or not
    return a.name.equals(b.name) && same(a.left, b.left) && same(a.right, b.right);
  }
  ```
  The same recipe: base case, ask both children, combine with `&&`.
  :::
  :::accordion-item{label="Count the leaves." icon="i-lucide-message-circle"}
  Null gives 0; a node with no children gives 1; otherwise the sum of both
  subtrees' leaf counts. On the college chart it is 3: DSA, DBMS and Signals.
  :::
::
