The rule is this: for every node, everything in its left subtree is smaller and
everything in its right subtree is larger. With that one rule, finding a value
means comparing at the root and throwing away half the tree, then doing it
again. That is binary search, stored as a structure instead of run on an array.

## Why this matters in a job

Java's `TreeMap` and `TreeSet` are binary search trees (a self-balancing kind
called red-black). Every database index you meet in the DBMS track is a close
relative called a B-tree. In interviews, BST questions are the most common
tree questions after traversals: insert, search, delete, validate, find the
kth smallest, find the lowest common ancestor. They all rest on the one rule,
and on knowing that inorder traversal of a BST comes out sorted.

## A tree that is also a search

Think of a guessing game with marks. "Is it 55?" "Higher." "Is it 92?" "Lower."
"78?" "Yes." Each answer tells you which way to go, and you never look at the
other side. A **binary search tree (BST)** is that game written down once, so
every future search can play it.

The rule is about whole subtrees, not only direct children. 48 is in 55's left
subtree, so 48 must be smaller than 55 as well as larger than 41. That detail
is the trap in "validate a BST", below.

## How it works

Insert, search, delete, validate and inorder, on the marks above.

```java [MarksBST.java]
import java.util.ArrayList;
import java.util.List;

public class MarksBST {
  static class Node {
    int mark;
    Node left, right;
    Node(int mark) { this.mark = mark; }
  }

  static Node insert(Node node, int mark) {
    if (node == null) return new Node(mark);
    if (mark < node.mark)      node.left = insert(node.left, mark);
    else if (mark > node.mark) node.right = insert(node.right, mark);
    return node;                                   // duplicates ignored
  }

  static boolean search(Node node, int mark) {
    while (node != null) {
      if (mark == node.mark) return true;
      node = (mark < node.mark) ? node.left : node.right;
    }
    return false;
  }

  static Node delete(Node node, int mark) {
    if (node == null) return null;
    if (mark < node.mark) {
      node.left = delete(node.left, mark);
    } else if (mark > node.mark) {
      node.right = delete(node.right, mark);
    } else {
      if (node.left == null) return node.right;    // cases 1 and 2: no child, or one
      if (node.right == null) return node.left;
      Node successor = node.right;                 // case 3: two children
      while (successor.left != null) successor = successor.left;
      node.mark = successor.mark;                  // copy the successor up
      node.right = delete(node.right, successor.mark);
    }
    return node;
  }

  static void inorder(Node node, List<Integer> out) {
    if (node == null) return;
    inorder(node.left, out);
    out.add(node.mark);
    inorder(node.right, out);
  }

  static boolean isValid(Node node, long low, long high) {
    if (node == null) return true;
    if (node.mark <= low || node.mark >= high) return false;
    return isValid(node.left, low, node.mark) && isValid(node.right, node.mark, high);
  }

  static int height(Node node) {
    return node == null ? 0 : 1 + Math.max(height(node.left), height(node.right));
  }

  static String sorted(Node root) {
    List<Integer> out = new ArrayList<>();
    inorder(root, out);
    return out.toString();
  }

  public static void main(String[] args) {
    Node root = null;
    for (int mark : new int[]{ 55, 41, 92, 25, 48, 78, 99 }) root = insert(root, mark);

    System.out.println("inorder:      " + sorted(root));
    System.out.println("search 78:    " + search(root, 78));
    System.out.println("search 60:    " + search(root, 60));
    System.out.println("valid BST?    " + isValid(root, Long.MIN_VALUE, Long.MAX_VALUE));

    root = delete(root, 25);           // a leaf
    System.out.println("delete 25:    " + sorted(root));
    root = delete(root, 92);           // two children
    System.out.println("delete 92:    " + sorted(root) + "  root is " + root.mark);
    root = delete(root, 55);           // the root itself
    System.out.println("delete 55:    " + sorted(root) + "  root is " + root.mark);

    Node skewed = null;
    for (int mark : new int[]{ 25, 41, 48, 55, 78, 92, 99 }) skewed = insert(skewed, mark);
    Node balanced = null;
    for (int mark : new int[]{ 55, 41, 92, 25, 48, 78, 99 }) balanced = insert(balanced, mark);
    System.out.println("height, balanced order: " + height(balanced));
    System.out.println("height, sorted order:   " + height(skewed));
  }
}
```

```text [Output]
inorder:      [25, 41, 48, 55, 78, 92, 99]
search 78:    true
search 60:    false
valid BST?    true
delete 25:    [41, 48, 55, 78, 92, 99]
delete 92:    [41, 48, 55, 78, 99]  root is 55
delete 55:    [41, 48, 78, 99]  root is 78
height, balanced order: 3
height, sorted order:   7
```

### Insert and search

Both walk one path from the root: go left if smaller, right if larger. Insert
walks until it falls off the tree and puts the new node there. The recursive
insert returns the (possibly new) subtree root, and each caller reattaches it
with `node.left = insert(...)`. That pattern, "return the new subtree and let
the parent reattach it", is what makes delete manageable too.

### Delete: the three cases

::flow{numbered direction="vertical" caption="Deleting a node from a BST"}
  :::flow-step{label="No children (a leaf)" icon="i-lucide-leaf"}
  Remove it. Return `null` to the parent. Deleting 25 above.
  :::
  :::flow-step{label="One child" icon="i-lucide-corner-down-right"}
  Replace the node with its only child. Return that child to the parent.
  :::
  :::flow-step{label="Two children" icon="i-lucide-git-fork" highlight}
  Find the **inorder successor**: the smallest value in the right subtree (go
  right once, then left as far as possible). Copy its value into this node,
  then delete the successor from the right subtree, which is now case 1 or 2.
  Deleting 92 used 99; deleting 55 used 78.
  :::
::

The inorder successor works because it is the next value up in sorted order:
bigger than everything on the left, smaller than everything else on the right.
The inorder predecessor (largest on the left) works equally well.

### Complexity, and the catch

| Operation | Balanced | Skewed (a line) |
| --- | --- | --- |
| Search | **O(log n)** | O(n) |
| Insert | O(log n) | O(n) |
| Delete | O(log n) | O(n) |
| Inorder (sorted output) | O(n) | O(n) |

The last two lines of the output are the catch. The same seven marks, inserted
in sorted order, produce a tree of height 7 instead of 3: every node hangs off
the previous one's right.

::compare{caption="The same seven values, two insertion orders."}
  :::compare-side{label="Inserted 55, 41, 92, 25, 48, 78, 99" verdict="right"}
  Three levels. Any value found in at most three comparisons. **O(log n)**.
  :::
  :::compare-side{label="Inserted 25, 41, 48, 55, 78, 92, 99" verdict="wrong"}
  Seven levels, each node hanging off the previous one's right. Finding 99
  takes seven comparisons. **O(n)**, and it is a linked list wearing a costume.
  :::
::

Real data often arrives sorted (roll numbers are issued in order), which is why
nobody uses a plain BST in production. **Self-balancing** trees (red-black,
AVL, B-trees) rotate nodes on insert to keep the height logarithmic whatever
order the data arrives in.

::side-note{kind="go-deeper"}
Java's `TreeMap` is a red-black tree. Your database's index is a B-tree, the
same idea widened so each node fills a disk page and holds hundreds of keys.
You do not need to implement the rotations for a fresher interview. You do need
to say why balancing exists, which is the comparison above.
::

## Real use case

`TreeMap` answers range questions a `HashMap` cannot, because it keeps keys in
order:

```java [MarkBands.java]
import java.util.TreeMap;

public class MarkBands {
  public static void main(String[] args) {
    TreeMap<Integer, String> byMark = new TreeMap<>();
    byMark.put(55, "Asha");
    byMark.put(41, "Rahul");
    byMark.put(92, "Meera");
    byMark.put(78, "Imran");
    byMark.put(99, "Kavya");

    System.out.println("70 to 95:      " + byMark.subMap(70, true, 95, true));
    System.out.println("below 60:      " + byMark.floorEntry(59));
    System.out.println("at least 80:   " + byMark.ceilingKey(80));
    System.out.println("topper:        " + byMark.lastEntry());
  }
}
```

```text [Output]
70 to 95:      {78=Imran, 92=Meera}
below 60:      55=Asha
at least 80:   92
topper:        99=Kavya
```

Every one of those is O(log n), a walk down one path of the tree. "Which
students scored between 70 and 95" is the kind of question a hash map would
answer by scanning everything.

## What confuses people here

- **Validating by checking only children.** `left.mark < node.mark < right.mark`
  at every node is not enough: a 60 placed as the right child of 48 passes that
  check (60 is larger than 48) but breaks the rule, because 60 is in 55's left
  subtree. Pass the
  allowed range (`low`, `high`) down, as `isValid` does.
- **Integer bounds in validation.** Starting with `Integer.MIN_VALUE` fails a
  tree that genuinely contains `Integer.MIN_VALUE`. Use `long` bounds, or
  `null` for "no bound".
- **Duplicates.** Decide a policy (ignore, count, or always go right) and say
  it. Mine ignores them.
- **Forgetting to reattach.** Calling `insert(node.left, mark)` without
  assigning the result to `node.left` inserts into nothing when the child was
  `null`.

## Interview questions

::accordion
  :::accordion-item{label="Search and insert in a BST. What is the complexity?" icon="i-lucide-message-circle"}
  Walk one path, left if smaller and right if larger. O(h): O(log n) when
  balanced, O(n) when skewed, for example after inserting sorted data.
  :::
  :::accordion-item{label="Delete a node from a BST." icon="i-lucide-message-circle"}
  Leaf: remove. One child: replace with the child. Two children: copy the
  inorder successor's value (smallest in the right subtree) into the node, then
  delete the successor from the right subtree.
  :::
  :::accordion-item{label="Check whether a binary tree is a valid BST." icon="i-lucide-message-circle"}
  Recurse with an allowed range: the left child must lie in (low, node), the
  right in (node, high). Or do an inorder traversal and check every value is
  larger than the previous one. Both O(n).
  :::
  :::accordion-item{label="Find the kth smallest value in a BST." icon="i-lucide-message-circle"}
  Inorder traversal visits values in ascending order, so count as you visit and
  stop at the kth. O(h + k) with an iterative inorder that stops early.
  :::
  :::accordion-item{label="HashMap or TreeMap?" icon="i-lucide-message-circle"}
  `HashMap`: O(1) average, no order. `TreeMap`: O(log n), sorted keys, plus
  ranges (`subMap`), `floorKey`, `ceilingKey`, `firstKey`, `lastKey`. Choose
  `TreeMap` when you need order or ranges.
  :::
::
