The cheaper tree is a **heap**. It does not keep everything in order. It
promises one thing only: every parent is smaller than its children, so the
smallest value is always at the root. That weaker promise is cheaper to keep,
and it is enough whenever the question is "what is the most urgent item right
now?"

## Why this matters in a job

A heap is what sits under Java's `PriorityQueue`, and a priority queue is how
real systems decide what to do next: the job scheduler, the hospital triage
list, the "retry soonest first" queue. In interviews the heap unlocks a whole
family of problems in one move: **top k** (the k highest marks, the k most
frequent courses), **kth largest**, **merge k sorted lists** and **running
median**. When a question says "k", think heap before you think sort.

## A tournament ladder

Think of a knockout table-tennis tournament drawn as a tree. The winner of each
match moves up to face the winner of the next. The champion at the top has
beaten everyone, but nobody claims the two finalists' quarter-final opponents
are in any order. The ladder only guarantees that every player beat the ones
below them.

A **min-heap** is that ladder with "smaller wins": every parent is less than or
equal to its children. A **max-heap** is the reverse. Two rules together define
one:

1. **Heap order:** every parent beats its children.
2. **Shape:** the tree is **complete**, every level full except possibly the
   last, which fills left to right.

The shape rule is what lets a heap live in a plain array with no references at
all. Number the nodes level by level from 0, and for the node at index `i`:

| Relative | Index |
| --- | --- |
| Left child | `2i + 1` |
| Right child | `2i + 2` |
| Parent | `(i - 1) / 2` (integer division) |

## How it works

### By hand: sift up and sift down

**Insert:** put the new value at the end of the array (the next free spot in
the last level), then **sift up**: while it is smaller than its parent, swap
them. **Remove the top:** take the root, move the last element into the root,
then **sift down**: while it is larger than its smaller child, swap with that
child. Each is one walk along one root-to-leaf path, so O(log n).

```java [MarksHeap.java]
import java.util.Arrays;

public class MarksHeap {
  private int[] heap = new int[16];
  private int size = 0;

  void offer(int mark) {
    heap[size] = mark;
    int i = size++;
    while (i > 0 && heap[(i - 1) / 2] > heap[i]) {      // smaller than parent: swap up
      swap(i, (i - 1) / 2);
      i = (i - 1) / 2;
    }
  }

  int poll() {
    int smallest = heap[0];
    heap[0] = heap[--size];                              // last element to the root
    int i = 0;
    while (true) {                                       // sift it down
      int left = 2 * i + 1, right = 2 * i + 2, min = i;
      if (left < size && heap[left] < heap[min]) min = left;
      if (right < size && heap[right] < heap[min]) min = right;
      if (min == i) break;
      swap(i, min);
      i = min;
    }
    return smallest;
  }

  private void swap(int a, int b) { int t = heap[a]; heap[a] = heap[b]; heap[b] = t; }

  public static void main(String[] args) {
    MarksHeap h = new MarksHeap();
    for (int m : new int[]{ 67, 91, 45, 88, 73 }) {
      h.offer(m);
      System.out.println("offer " + m + " -> " + Arrays.toString(Arrays.copyOf(h.heap, h.size)));
    }
    System.out.println("poll -> " + h.poll() + ", heap now " + Arrays.toString(Arrays.copyOf(h.heap, h.size)));
    System.out.println("poll -> " + h.poll() + ", heap now " + Arrays.toString(Arrays.copyOf(h.heap, h.size)));
  }
}
```

```text [Output]
offer 67 -> [67]
offer 91 -> [67, 91]
offer 45 -> [45, 91, 67]
offer 88 -> [45, 88, 67, 91]
offer 73 -> [45, 73, 67, 91, 88]
poll -> 45, heap now [67, 73, 88, 91]
poll -> 67, heap now [73, 91, 88]
```

Follow `offer 45`: it lands at index 2, its parent (index 0) is 67, 45 is
smaller, swap. It is now the root. Follow the first `poll`: 45 leaves, the last
element 88 moves to the root, and its smaller child is 67 at index 2, so they
swap. Index 2 has no children left, so it stops. The array is never fully
sorted, and it never needs to be.

### In real Java: PriorityQueue

`PriorityQueue` is a min-heap by default. Pass `Collections.reverseOrder()` (or
any `Comparator`) for a max-heap.

```java [TopMarks.java]
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;
import java.util.PriorityQueue;

public class TopMarks {
  // The k highest marks, using a min-heap that never holds more than k.
  static List<Integer> topK(int[] marks, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();       // min-heap
    for (int mark : marks) {
      heap.offer(mark);
      if (heap.size() > k) heap.poll();                        // throw out the smallest
    }
    List<Integer> result = new ArrayList<>(heap);
    result.sort(Collections.reverseOrder());
    return result;
  }

  public static void main(String[] args) {
    int[] marks = { 67, 91, 45, 88, 73, 95, 52, 81 };

    PriorityQueue<Integer> minHeap = new PriorityQueue<>();
    PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
    for (int m : marks) { minHeap.offer(m); maxHeap.offer(m); }

    System.out.println("min-heap peek: " + minHeap.peek());
    System.out.println("max-heap peek: " + maxHeap.peek());
    System.out.println("min-heap array: " + minHeap);

    StringBuilder order = new StringBuilder("polled in order:");
    while (!maxHeap.isEmpty()) order.append(' ').append(maxHeap.poll());
    System.out.println(order);

    System.out.println("top 3: " + topK(marks, 3));
    System.out.println("3rd highest: " + topK(marks, 3).get(2));
  }
}
```

```text [Output]
min-heap peek: 45
max-heap peek: 95
min-heap array: [45, 73, 52, 81, 88, 95, 67, 91]
polled in order: 95 91 88 81 73 67 52 45
top 3: [95, 91, 88]
3rd highest: 88
```

Look at the third line. Printing a `PriorityQueue` shows the internal array,
which is heap-ordered, **not sorted**. Only repeated `poll` gives sorted order.

### Top k: why a min-heap for the highest marks

It sounds backwards and it is the point of the pattern. Keep a min-heap of at
most k marks. Its root is the **weakest of the current top k**. Each new mark
goes in; if the heap now holds k + 1, the smallest is thrown out. At the end,
the heap holds exactly the k largest, and its root is the kth largest.

::flow{caption="Top 3 of 67, 91, 45, 88, 73, 95 …"}

  Heap holds three. Root 45 is the weakest of the top three so far.
  :::
  :::flow-step{label="88 arrives" icon="i-lucide-arrow-down-to-line"}
  Four in the heap; poll the smallest, 45. Now 67, 88, 91.
  :::
  :::flow-step{label="73, then 95 arrive" icon="i-lucide-trophy" highlight}
  73 pushes out 67; 95 pushes out 73. Now 88, 91, 95. The root is always the
  bar a new mark must clear.

### Complexity

| Operation | Heap | Note |
| --- | --- | --- |
| `peek` | **O(1)** | The root |
| `offer` | O(log n) | Sift up one path |
| `poll` | O(log n) | Sift down one path |
| Build from n items with offers | O(n log n) | `new PriorityQueue<>(collection)` builds in O(n) |
| `contains`, `remove(Object)` | O(n) | A heap is not searchable |
| Top k of n | **O(n log k)**, O(k) space | Against O(n log n) to sort everything |
| Heap sort | O(n log n), O(1) extra | Not stable |

With 40,000 marks and k = 10, O(n log k) is about 40,000 × 3.3 steps against
40,000 × 15.3 for a full sort, and it only ever holds ten items in memory.

## Real use case

::real-life{title="The merit list without sorting the country" source="An entrance exam results team"}
An entrance exam with lakhs of candidates needs the top 500 for a counselling
round, and the scores arrive in batches from exam centres over a day. Sorting
everything again after every batch would be wasteful. A min-heap of size 500
takes each score in O(log 500) and at any moment its root is the current cutoff
score: the number every news channel wants by the evening.
::

Operating systems pick the next process with a priority queue (the Operating
Systems track calls it priority scheduling). Dijkstra's shortest path, at the
end of the graphs chapter, is a `PriorityQueue` of "closest place not yet
settled".

## What confuses people here

- **Heap the structure versus the JVM heap.** Unrelated. The JVM heap is the
  memory where objects live; this heap is a tree in an array. Same word,
  different things.
- **Printing a `PriorityQueue` and expecting sorted output.** Iteration order
  and `toString` follow the array, not priority. Poll repeatedly to get order.
- **Max-heap for "top k largest".** That works, but it holds all n items and
  costs O(n log n). The min-heap of size k is the answer they are looking for.
- **Mutating an object inside the queue.** Changing a student's mark after
  offering them does not re-sift; the heap is now silently wrong. Remove,
  change, re-offer.
- **Comparator overflow.** `(a, b) -> a - b` can overflow for large values.
  Use `Integer.compare(a, b)` or `Comparator.comparingInt(...)`.

## Interview questions

::accordion
  :::accordion-item{label="What is a heap and how is it stored?" icon="i-lucide-message-circle"}
  A complete binary tree where every parent is less than or equal to its
  children (min-heap) or greater than or equal (max-heap). It is stored in an
  array: children of `i` at `2i + 1` and `2i + 2`, parent at `(i - 1) / 2`.
  No references needed because the tree is complete.
  :::
  :::accordion-item{label="Find the kth largest element." icon="i-lucide-message-circle"}
  A min-heap of size k: offer each value, poll when the size exceeds k. The
  root at the end is the kth largest. O(n log k) time, O(k) space. Quickselect
  is O(n) on average if they push further.
  :::
  :::accordion-item{label="How do you make a max-heap with PriorityQueue?" icon="i-lucide-message-circle"}
  `new PriorityQueue<>(Collections.reverseOrder())`, or for objects
  `new PriorityQueue<>(Comparator.comparingInt(Student::getMarks).reversed())`.
  :::
  :::accordion-item{label="Top k most frequent courses chosen by students." icon="i-lucide-message-circle"}
  Count with a `HashMap<String, Integer>`, then keep a min-heap of size k
  ordered by count. O(n + m log k) where m is the number of distinct courses.
  :::
  :::accordion-item{label="Why is insert O(log n) in a priority queue but O(1) in a queue?" icon="i-lucide-message-circle"}
  An ordinary queue appends and cares only about arrival. A heap must restore
  heap order by sifting the new element up, one level per swap, and a complete
  tree has log n levels.
  :::
::
