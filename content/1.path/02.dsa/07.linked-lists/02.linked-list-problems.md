Reversing a linked list needs no new nodes at all. It needs three variables and
four lines in the right order, and once you can do it you can do most of the
linked list questions an interviewer has, because they are built from two
tricks: **turning arrows round** and **two pointers moving at different speeds**.

## Why this matters in a job

These five problems (reverse, middle, cycle, merge, remove from the end) are
the linked list round at most companies that ask DSA. Service company online
tests use the easy ones; product companies ask the same ones and then change a
detail to see whether you understood or memorised. None of them needs clever
mathematics. All of them punish you for losing a reference.

## Two tricks

**Turning arrows round.** Picture students in a line for fee payment, each
holding the shoulder of the student in front. To reverse the line without
anybody changing places, every student lets go and holds the shoulder of the
student *behind* instead. You walk down the line doing that one student at a
time, and you must remember who was in front before the hand lets go.

**Slow and fast pointers.** Two students walk down the corridor from the same
door. One takes one step at a time, the other takes two. When the fast one
reaches the far wall, the slow one is exactly halfway. And if the corridor were
secretly a circle, the fast one would lap the slow one and they would meet.
That single picture solves "find the middle" and "detect a cycle".

## How it works

All five in one program, on lists of roll numbers. The helper `build` uses a
**dummy node**: a fake node placed before the real head so that the first real
node needs no special case. It appears twice more below.

```java [ListProblems.java]
public class ListProblems {
  static class Node {
    int roll;
    Node next;
    Node(int roll) { this.roll = roll; }
  }

  static Node build(int... rolls) {
    Node dummy = new Node(0), tail = dummy;
    for (int r : rolls) { tail.next = new Node(r); tail = tail.next; }
    return dummy.next;
  }

  static String show(Node head) {
    StringBuilder sb = new StringBuilder();
    for (Node n = head; n != null; n = n.next) sb.append(n.roll).append(" -> ");
    return sb.append("null").toString();
  }

  static Node reverse(Node head) {
    Node prev = null, current = head;
    while (current != null) {
      Node next = current.next;   // 1. remember the rest
      current.next = prev;        // 2. turn this arrow round
      prev = current;             // 3. step prev forward
      current = next;             // 4. step current forward
    }
    return prev;
  }

  static Node reverseRecursive(Node head) {
    if (head == null || head.next == null) return head;
    Node newHead = reverseRecursive(head.next);
    head.next.next = head;
    head.next = null;
    return newHead;
  }

  static Node middle(Node head) {
    Node slow = head, fast = head;
    while (fast != null && fast.next != null) {
      slow = slow.next;
      fast = fast.next.next;
    }
    return slow;
  }

  static boolean hasCycle(Node head) {
    Node slow = head, fast = head;
    while (fast != null && fast.next != null) {
      slow = slow.next;
      fast = fast.next.next;
      if (slow == fast) return true;
    }
    return false;
  }

  static Node merge(Node a, Node b) {
    Node dummy = new Node(0), tail = dummy;
    while (a != null && b != null) {
      if (a.roll <= b.roll) { tail.next = a; a = a.next; }
      else                  { tail.next = b; b = b.next; }
      tail = tail.next;
    }
    tail.next = (a != null) ? a : b;
    return dummy.next;
  }

  static Node removeNthFromEnd(Node head, int n) {
    Node dummy = new Node(0);
    dummy.next = head;
    Node lead = dummy, lag = dummy;
    for (int i = 0; i <= n; i++) lead = lead.next;
    while (lead != null) { lead = lead.next; lag = lag.next; }
    lag.next = lag.next.next;
    return dummy.next;
  }

  public static void main(String[] args) {
    System.out.println("reverse:        " + show(reverse(build(101, 102, 103, 104))));
    System.out.println("reverse (rec):  " + show(reverseRecursive(build(101, 102, 103, 104))));
    System.out.println("middle of 5:    " + middle(build(101, 102, 103, 104, 105)).roll);
    System.out.println("middle of 4:    " + middle(build(101, 102, 103, 104)).roll);

    Node looped = build(101, 102, 103, 104);
    looped.next.next.next.next = looped.next;          // 104 points back at 102
    System.out.println("cycle?          " + hasCycle(looped));
    System.out.println("cycle (clean)?  " + hasCycle(build(101, 102, 103)));

    Node cse = build(101, 104, 107);
    Node ece = build(102, 103, 108, 110);
    System.out.println("merged:         " + show(merge(cse, ece)));
    System.out.println("drop 2nd last:  " + show(removeNthFromEnd(build(101, 102, 103, 104), 2)));
  }
}
```

```text [Output]
reverse (rec):  104 -> 103 -> 102 -> 101 -> null
middle of 5:    103
middle of 4:    103
cycle?          true
cycle (clean)?  false
merged:         101 -> 102 -> 103 -> 104 -> 107 -> 108 -> 110 -> null
drop 2nd last:  101 -> 102 -> 104 -> null
```

### The middle, and which middle

With five nodes, `fast` moves 0 → 2 → 4 and stops, `slow` moves 0 → 1 → 2: the
exact middle, 103. With four nodes there are two middles, 102 and 103. The loop
condition `fast != null && fast.next != null` returns the **second** one. If
the question wants the first, loop while `fast.next != null &&
fast.next.next != null`. Ask which one they want: that one question shows you
have thought about even lengths.

### Cycle detection

This is **Floyd's cycle detection**, often called tortoise and hare. If there
is no loop, `fast` reaches `null`. If there is a loop, both pointers end up
going round it; each step the gap between them shrinks by one, so `fast` must
land on `slow` within one lap. No `HashSet` of visited nodes needed, so the
extra space is O(1).

### Merge and remove from the end

`merge` is the merge step of merge sort done with references instead of an
extra array: compare the two heads, attach the smaller, move on. The dummy node
means the first attachment needs no `if (head == null)`.

`removeNthFromEnd` sends `lead` n + 1 steps ahead of `lag`, then walks both
until `lead` falls off the end. The gap means `lag` stops on the node **before**
the one to delete, which is exactly where you need to stand. One pass, no
counting the length first.

### Complexity

| Problem | Time | Extra space |
| --- | --- | --- |
| Reverse, iterative | O(n) | **O(1)** |
| Reverse, recursive | O(n) | O(n), one stack frame per node |
| Middle | O(n) | O(1) |
| Cycle (Floyd) | O(n) | O(1) |
| Cycle (`HashSet` of seen nodes) | O(n) | O(n) |
| Merge two sorted lists | O(n + m) | O(1) |
| Remove nth from end | O(n) | O(1) |

## Real use case

Merging two sorted chains without copying is how sorted results from two
places are combined everywhere: two sections' merit lists, each already sorted
by roll number, become one department list in a single pass. Databases do the
same with sorted runs when a sort does not fit in memory (the SQL track's
`ORDER BY` on a large table ends in exactly this kind of merge). And cycle
detection with two speeds is used well beyond lists, for example to detect that
a chain of "this student's mentor is that student" records loops back on
itself because of a data entry mistake.

::real-life{title="The report that never finished" source="A records team"}
A nightly job followed a chain of "replaced by" links between old and new
course codes to find each course's current code. Somebody entered CS301
replaced by CS401, and later CS401 replaced by CS301. The job walked the loop
forever and the report never arrived. The fix was two lines of slow and fast
pointers before trusting the chain, and an error that named the loop.
::

## What confuses people here

- **Returning the wrong variable after reversing.** When the loop ends,
  `current` is `null` and `head` is now the *last* node. The new head is
  `prev`.
- **The loop condition for fast.** `fast.next.next` throws if `fast.next` is
  `null`. Check `fast != null && fast.next != null`, in that order, every time.
- **Comparing values instead of nodes in cycle detection.** `slow == fast`
  compares references, which is what you want. Two different nodes can hold the
  same roll number; `slow.roll == fast.roll` would report cycles that are not
  there.
- **The recursive reverse on a long list.** It is elegant and it uses one stack
  frame per node. At 100,000 nodes it throws `StackOverflowError`. Give the
  iterative one first and mention the recursive one as an alternative.

::warning
If you draw nothing else in the interview, draw the list for these. Three boxes
and arrows on the whiteboard or in a comment, updated after each line, catch
the lost-reference bug before you write it. Interviewers read the drawing as
evidence that you reason rather than recite.
::

## Interview questions

::accordion
  :::accordion-item{label="Reverse a linked list. Iterative or recursive?" icon="i-lucide-message-circle"}
  Iterative: three pointers `prev`, `current`, `next`, O(n) time and O(1)
  space. Recursive: reverse the rest, then `head.next.next = head; head.next =
  null`, O(n) time and O(n) stack. Prefer iterative in production because the
  recursive one overflows the stack on long lists.
  :::
  :::accordion-item{label="Find the middle node in one pass." icon="i-lucide-message-circle"}
  Slow moves one, fast moves two; when fast reaches the end, slow is in the
  middle. Say which middle you return for an even length, and how to change the
  condition for the other.
  :::
  :::accordion-item{label="Detect a cycle. Can you do it in O(1) space?" icon="i-lucide-message-circle"}
  A `HashSet<Node>` of visited nodes works in O(n) space. Floyd's algorithm
  does it in O(1): if fast ever equals slow, there is a cycle. Follow-up: to
  find where the cycle starts, reset one pointer to the head and move both one
  step at a time; they meet at the start of the loop.
  :::
  :::accordion-item{label="Merge two sorted linked lists." icon="i-lucide-message-circle"}
  A dummy node and a `tail` pointer; attach the smaller head each time; when one
  list runs out, attach the rest of the other in one assignment. O(n + m) time,
  O(1) extra space because no nodes are created.
  :::
  :::accordion-item{label="Remove the nth node from the end in one pass." icon="i-lucide-message-circle"}
  Move a lead pointer n + 1 steps ahead of a lag pointer starting at a dummy
  node, then move both until lead is `null`; `lag.next` is the node to remove.
  The dummy handles the case where the head itself is removed.
  :::
::
