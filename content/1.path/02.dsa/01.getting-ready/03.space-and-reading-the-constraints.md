Memory is counted the same way as time: how much extra space does the code
need, and how does that grow with n. And the constraint line under every
problem, "1 ≤ n ≤ 10⁵", is the setter quietly telling you which complexity
will pass.

## Why this matters in a job

Because a program that runs fast but needs a copy of every student record for
every request runs out of memory in production, and "what is the space
complexity?" is the follow-up to "what is the time complexity?" in every live
round. And because in an online test, reading the constraints correctly is the
difference between spending 30 minutes on a solution that was always going to
time out and writing the right one first.

## Space is extra memory

Think of a teacher totalling marks. Doing it in her head with one running
number is constant space. Copying every mark onto a second sheet first, then
totalling, needs a sheet as long as the class. Same answer, different memory.

**Space complexity** counts the extra memory an algorithm uses as a function of
n. Most interviewers mean **auxiliary space**, which is the memory beyond the
input itself. The input array is already there; you are asked what you added.

| What the code allocates | Auxiliary space |
| --- | --- |
| A few variables (`total`, `i`, `max`) | O(1) |
| A copy of the array, or a `HashSet` of all elements | O(n) |
| An n × n table | O(n²) |
| Recursion n calls deep | O(n), for the call stack |
| Recursion that halves each call | O(log n) |

## How it works

Two ways to reverse the marks of a class. Same time, different space.

```java [ReverseSpace.java]
import java.util.Arrays;

public class ReverseSpace {
  // O(n) extra space: builds a second array
  static int[] reversedCopy(int[] marks) {
    int[] out = new int[marks.length];
    for (int i = 0; i < marks.length; i++) {
      out[i] = marks[marks.length - 1 - i];
    }
    return out;
  }

  // O(1) extra space: swaps in place with two indices
  static void reverseInPlace(int[] marks) {
    int left = 0, right = marks.length - 1;
    while (left < right) {
      int temp = marks[left];
      marks[left] = marks[right];
      marks[right] = temp;
      left++;
      right--;
    }
  }

  public static void main(String[] args) {
    int[] marks = {72, 91, 64, 85, 58};
    System.out.println("Copy:     " + Arrays.toString(reversedCopy(marks)));
    reverseInPlace(marks);
    System.out.println("In place: " + Arrays.toString(marks));
  }
}
```

```text [Output]
Copy:     [58, 85, 64, 91, 72]
In place: [58, 85, 64, 91, 72]
```

Both are O(n) time. The first is O(n) space, the second O(1). When an
interviewer says "can you do it in place?", this is what they mean.

### The space you do not see: the call stack

Every method call that has not returned yet keeps a **stack frame** in memory:
its parameters and local variables. A recursive method that goes n calls deep
holds n frames at once.

```java [StackDepth.java]
public class StackDepth {
  static int deepest = 0;

  static int sumMarks(int[] marks, int i, int depth) {
    deepest = Math.max(deepest, depth);
    if (i == marks.length) return 0;
    return marks[i] + sumMarks(marks, i + 1, depth + 1);
  }

  public static void main(String[] args) {
    int[] marks = {72, 91, 64, 85, 58};
    System.out.println("Total: " + sumMarks(marks, 0, 1));
    System.out.println("Frames on the stack at the deepest point: " + deepest);
  }
}
```

```text [Output]
Total: 370
Frames on the stack at the deepest point: 6
```

No array was allocated, and the space is still O(n). Recursion is never free
in memory, which is why the recursion chapter comes with a warning about
`StackOverflowError`.

## What log n actually means

**log₂ n** is the number of times you can halve n before you reach 1. That is
all it is.

```java [Halving.java]
public class Halving {
  public static void main(String[] args) {
    for (int n : new int[]{8, 1_000, 40_000, 1_000_000}) {
      int steps = 0;
      int remaining = n;
      while (remaining > 1) {
        remaining /= 2;
        steps++;
      }
      System.out.println(n + " students, halved " + steps + " times");
    }
  }
}
```

```text [Output]
8 students, halved 3 times
1000 students, halved 9 times
40000 students, halved 15 times
1000000 students, halved 19 times
```

A million becomes one in about 20 halvings. Any algorithm that throws away half
the remaining work each step is O(log n), and that is why binary search stays
fast on data of any size.

## Amortised: cheap on average

`ArrayList.add` is usually O(1), but when the internal array is full it
allocates a bigger one (1.5 times the size) and copies everything, which is
O(n). Because the size grows by a factor, those copies get rarer as the list
grows, and the average cost per `add`, across all of them, stays O(1). That
average over a sequence of operations is called **amortised** cost.

## Reading the constraints

An online judge runs your code against hidden inputs with a time limit of about
1–2 seconds. Java does roughly **10⁸ simple operations per second** on a typical
judge. Put n into your complexity and see whether it fits.

| If n is up to | Rough operation count | Complexity that passes | Typical technique |
| --- | --- | --- | --- |
| 10–12 | n! is about 4.8 × 10⁸ at 12 | O(n!) | All permutations |
| 20–25 | 2ⁿ is about a million at 20 | O(2ⁿ) | Subsets, backtracking |
| 500 | n³ is 1.25 × 10⁸ | O(n³) | Three nested loops, small DP |
| 5,000 | n² is 2.5 × 10⁷ | O(n²) | Nested loops, 2D DP |
| **10⁵ – 10⁶** | **n log n is about 2 × 10⁷** | **O(n log n) or O(n)** | **Sorting, hashing, two pointers, binary search** |
| 10⁹ and above | Cannot even read them all | O(log n) or O(1) | Binary search on the answer, maths |

The bold row is the one you will see most often. "n ≤ 10⁵" is the setter
saying: the nested loop you thought of first will time out, find something
better.

::tip
Read the constraints before the story. "1 ≤ n ≤ 20" in a problem about choosing
courses is a strong hint that trying every subset (2²⁰, about a million) is the
intended answer, and that you should not waste time looking for something
clever.
::

## Real use case

::real-life{title="The export that ran out of memory" source="A university results portal"}
A results export loaded every student's marks for every subject into a
`List<String>` of CSV lines, then wrote the list to a file. With 3,000 students
it worked. With 60,000 students and eight subjects each, the list needed more
memory than the server had, and the job died with `OutOfMemoryError`. The time
complexity was fine. The space was O(n) when it did not need to be: writing
each line as it was produced made it O(1) extra space, and the job has not
failed since.
::

## What confuses people here

- **Counting the input as extra space.** Reversing in place is O(1) auxiliary
  space even though the array is O(n). Say "auxiliary" and nobody argues.
- **Forgetting the call stack.** A recursive solution with no arrays is still
  O(depth) space.
- **Thinking O(log n) needs a base.** log₂, log₁₀, all differ by a constant,
  so Big-O does not care. It is written O(log n).
- **Treating 10⁸ as exact.** It is a rule of thumb. 3 × 10⁸ simple operations
  may pass, 10⁹ will not.

## Interview questions

::accordion
  :::accordion-item{label="What is the space complexity of a recursive sum over n marks?" icon="i-lucide-message-circle"}
  O(n), because n stack frames are alive at the deepest point, even though no
  array is allocated. An iterative loop with one `total` variable is O(1).
  :::

  :::accordion-item{label="Can you reverse this array in O(1) space?" icon="i-lucide-message-circle"}
  Yes, swap from both ends with two indices until they meet:

  ```java
  for (int l = 0, r = a.length - 1; l < r; l++, r--) {
    int t = a[l]; a[l] = a[r]; a[r] = t;
  }
  ```

  O(n) time, O(1) auxiliary space.
  :::

  :::accordion-item{label="What does amortised O(1) mean for ArrayList.add?" icon="i-lucide-message-circle"}
  Most adds are O(1). Occasionally the backing array is full, and that add
  copies everything into a larger array, which is O(n). Because capacity grows
  by a factor of 1.5, the copies become rarer, and averaged over n adds the
  cost per add is constant.
  :::

  :::accordion-item{label="n is up to 10^5. Will an O(n²) solution pass?" icon="i-lucide-message-circle"}
  No. n² is 10¹⁰ operations, about a hundred seconds at 10⁸ per second, against
  a limit of 1–2 seconds. You need O(n log n) or O(n), which usually means
  sorting, hashing, two pointers or a sliding window.
  :::

  :::accordion-item{label="Why is binary search O(log n)?" icon="i-lucide-message-circle"}
  Each comparison discards half of the remaining range. The number of times n
  can be halved before one element is left is log₂ n, about 20 for a million.
  :::
::
