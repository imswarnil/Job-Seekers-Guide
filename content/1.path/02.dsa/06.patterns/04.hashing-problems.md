The most asked question in the history of coding interviews is **two-sum**: find
two numbers in an array that add up to a target. With a `HashMap` it is one pass,
and the same move ("remember what I have seen, so I never look back") solves
every other problem on this page.

## Why this matters in a job

Because two-sum is so common that interviewers use it as a warm-up and judge you
on how fast and cleanly you get from the O(n²) answer to the O(n) one. Because
"count the frequency of each..." appears in online assessments at nearly every
service company I sat for. And because hashing is the most common answer to "can
you do better?" in the whole of DSA: when a brute force has an inner loop that
**searches** for something, a `HashMap` or `HashSet` usually replaces that loop
with one lookup.

## Remember, do not search

The two-pointer version of pair-sum needed a sorted array. Without sorting, the
brute force is: for every student, scan every other student for the partner.

The hashing idea is to walk the list once and keep a register of everyone you
have already passed. For each new student with marks `m`, you do not search for
a partner; you ask the register one question: "have I already seen someone with
`150 - m`?" A `HashMap` answers that in O(1).

::flow{numbered caption="The hashing move, for almost every problem on this page"}
  :::flow-step{label="Walk once" icon="i-lucide-footprints"}
  One loop over the input, left to right.
  :::
  :::flow-step{label="Ask the map" icon="i-lucide-search" highlight}
  Before storing the current element, ask whether the thing that would complete
  the answer is already in the map.
  :::
  :::flow-step{label="Then remember" icon="i-lucide-save"}
  Store the current element (and its index or count) for the elements still to
  come.
  :::
::

## How it works

### Two-sum

Return the indices of two students whose marks add up to the target. The marks
are **not** sorted.

```java [TwoSum.java]
import java.util.Arrays;
import java.util.HashMap;
import java.util.Map;

public class TwoSum {

  static int[] bruteForce(int[] marks, int target) {        // O(n²)
    for (int i = 0; i < marks.length; i++)
      for (int j = i + 1; j < marks.length; j++)
        if (marks[i] + marks[j] == target) return new int[]{i, j};
    return new int[0];
  }

  static int[] withMap(int[] marks, int target) {           // O(n)
    Map<Integer, Integer> seen = new HashMap<>();            // mark -> index
    for (int i = 0; i < marks.length; i++) {
      int need = target - marks[i];
      if (seen.containsKey(need)) {
        return new int[]{seen.get(need), i};
      }
      seen.put(marks[i], i);                                 // ask first, then store
    }
    return new int[0];
  }

  public static void main(String[] args) {
    int[] marks = {72, 35, 91, 60, 78, 48};
    System.out.println("Brute force: " + Arrays.toString(bruteForce(marks, 150)));
    System.out.println("HashMap:     " + Arrays.toString(withMap(marks, 150)));
    System.out.println("Target 80:   " + Arrays.toString(withMap(new int[]{40, 35, 75}, 80)));
  }
}
```

```text [Output]
Brute force: [0, 4]
HashMap:     [0, 4]
Target 80:   []
```

72 + 78 = 150, at indices 0 and 4. The third call shows the case that catches
people: a target of 80 with a 40 in the list. If you stored first and asked
second, the 40 would find **itself** and you would return `[0, 0]`. Asking
before storing is what guarantees two different students.

### Frequency counting

How many students got each grade? `merge` and `getOrDefault` are the two methods
you will use for this for the rest of your career.

```java [GradeCount.java]
import java.util.Map;
import java.util.TreeMap;

public class GradeCount {
  public static void main(String[] args) {
    String[] grades = {"B", "A", "C", "B", "A", "B", "F", "C", "B"};

    Map<String, Integer> count = new TreeMap<>();     // TreeMap: prints sorted
    for (String g : grades) {
      count.merge(g, 1, Integer::sum);                // add 1, or start at 1
    }
    System.out.println(count);

    String most = null;
    for (Map.Entry<String, Integer> e : count.entrySet()) {
      if (most == null || e.getValue() > count.get(most)) most = e.getKey();
    }
    System.out.println("Most common: " + most + " (" + count.get(most) + ")");
    System.out.println("Grade D: " + count.getOrDefault("D", 0));
  }
}
```

```text [Output]
{A=2, B=4, C=2, F=1}
Most common: B (4)
Grade D: 0
```

`count.merge(g, 1, Integer::sum)` reads as: put 1 if `g` is absent, otherwise
add 1 to what is there. It replaces the four-line `if (containsKey) ... else ...`
that every beginner writes.

### First non-repeating character

A classic online-assessment question: in a student's name, find the first
character that appears exactly once. Two passes: count, then walk the **string**
again in its original order.

```java [FirstUnique.java]
import java.util.HashMap;
import java.util.Map;

public class FirstUnique {

  static char firstUnique(String s) {
    Map<Character, Integer> count = new HashMap<>();
    for (char c : s.toCharArray()) {
      count.merge(c, 1, Integer::sum);
    }
    for (char c : s.toCharArray()) {          // the string, not the map
      if (count.get(c) == 1) return c;
    }
    return '_';                                // none
  }

  public static void main(String[] args) {
    System.out.println(firstUnique("aravindan"));
    System.out.println(firstUnique("swarnil"));
    System.out.println(firstUnique("abab"));
  }
}
```

```text [Output]
r
s
_
```

The second loop walks the string, not the map, because a `HashMap` has no order.
Iterating the map would find *a* character that appears once rather than the
*first* one. If you want to iterate the map instead, use a `LinkedHashMap`, which
keeps insertion order. Saying why is what turns a correct answer into a good one.

### Duplicates, with a set

"Has any roll number been registered twice?" and "list every duplicate" are the
`HashSet` version: `add` returns `false` when the element is already there.

```java [DuplicateRolls.java]
import java.util.LinkedHashSet;
import java.util.Set;

public class DuplicateRolls {
  public static void main(String[] args) {
    int[] registrations = {1003, 1019, 1007, 1019, 1042, 1003, 1019};
    Set<Integer> seen = new LinkedHashSet<>();
    Set<Integer> duplicates = new LinkedHashSet<>();
    for (int roll : registrations) {
      if (!seen.add(roll)) duplicates.add(roll);
    }
    System.out.println("Unique:     " + seen);
    System.out.println("Duplicates: " + duplicates);
  }
}
```

```text [Output]
Unique:     [1003, 1019, 1007, 1042]
Duplicates: [1019, 1003]
```

### Longest consecutive run of roll numbers

Given unsorted roll numbers present today, find the longest run of consecutive
numbers (a row of students sitting in order). Sorting gives O(n log n). With a
set: only start counting from a number whose predecessor is **absent**, because
only that number can begin a run.

```java [LongestRun.java]
import java.util.HashSet;
import java.util.Set;

public class LongestRun {

  static int longestRun(int[] rolls) {
    Set<Integer> present = new HashSet<>();
    for (int r : rolls) present.add(r);
    int best = 0;
    for (int r : present) {
      if (!present.contains(r - 1)) {             // r starts a run
        int length = 1;
        while (present.contains(r + length)) length++;
        best = Math.max(best, length);
      }
    }
    return best;
  }

  public static void main(String[] args) {
    int[] present = {1042, 1004, 1043, 1001, 1003, 1044, 1002, 1060};
    System.out.println("Longest run: " + longestRun(present));
  }
}
```

```text [Output]
Longest run: 4
```

1001, 1002, 1003, 1004. It looks like a loop inside a loop, but each number is
counted inside the `while` only once, as part of the run that starts before it,
so the total is O(n).

### Subarray sum equals k

How many stretches of consecutive days had fee collections summing to exactly k,
when some days have refunds (negative values)? The sliding window fails on
negatives. Prefix sums plus a map work: if the running total now is `sum`, and
some earlier running total was `sum - k`, then the days between them add up to k.

```java [SubarraySumK.java]
import java.util.HashMap;
import java.util.Map;

public class SubarraySumK {

  static int count(int[] daily, int k) {
    Map<Integer, Integer> seenSums = new HashMap<>();
    seenSums.put(0, 1);                         // the empty prefix
    int sum = 0, count = 0;
    for (int amount : daily) {
      sum += amount;
      count += seenSums.getOrDefault(sum - k, 0);
      seenSums.merge(sum, 1, Integer::sum);
    }
    return count;
  }

  public static void main(String[] args) {
    int[] daily = {3, 4, -2, 5, -3, 1, 2};      // thousands of rupees, refunds negative
    System.out.println("Stretches summing to 5: " + count(daily, 5));
  }
}
```

```text [Output]
Stretches summing to 5: 4
```

The `put(0, 1)` line is the one everyone forgets. Without it, a stretch that
starts on day one is never counted, because there is no "earlier" prefix for it.

### Complexity

| Problem | Brute force | With hashing | Extra space |
| --- | --- | --- | --- |
| Two-sum | O(n²) | **O(n)** | O(n) |
| Frequency of each value | O(n²) | **O(n)** | O(distinct values) |
| First non-repeating character | O(n²) | **O(n)** | O(alphabet) |
| Any duplicate | O(n²) | **O(n)** | O(n) |
| Longest consecutive run | O(n log n) sorted | **O(n)** | O(n) |
| Subarray sum equals k | O(n²) | **O(n)** | O(n) |

Every row trades memory for time. Say that trade out loud; interviewers
sometimes follow up with "and if memory were tight?", and the answer is to sort
and use two pointers, O(n log n) time with O(1) extra space.

## Real use case

**Joining two lists without a database.** A placement report needs each student's
name next to their offer. Offers come from one file, students from another. The
nested-loop join is O(n × m). Loading one side into a `HashMap` makes it O(n + m),
and this is exactly what a database does for a **hash join**.

```java [OfferReport.java]
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class OfferReport {

  record Student(String roll, String name) {}
  record Offer(String roll, String company, double lpa) {}

  public static void main(String[] args) {
    List<Student> students = List.of(
        new Student("1003", "Kabir"), new Student("1007", "Riya"), new Student("1019", "Meera"));
    List<Offer> offers = List.of(
        new Offer("1019", "Infosys", 3.6), new Offer("1003", "Accenture", 4.5));

    Map<String, String> nameByRoll = new HashMap<>();
    for (Student s : students) nameByRoll.put(s.roll(), s.name());   // build once

    for (Offer o : offers) {                                        // probe once each
      System.out.println(nameByRoll.get(o.roll()) + " -> " + o.company() + ", " + o.lpa() + " LPA");
    }
  }
}
```

```text [Output]
Meera -> Infosys, 3.6 LPA
Kabir -> Accenture, 4.5 LPA
```

## What confuses people here

**`Integer` comparison with `==`.** `seen.get(a) == seen.get(b)` compares two
`Integer` objects by reference. Java caches values from -128 to 127, so it
works in every test with small numbers and fails for index 128 and above.
Compare with `.equals`, or unbox into `int` first.

::warning{icon="i-lucide-alert-triangle"}
**Storing before checking in two-sum.** It makes one element pair with itself
whenever `target` is exactly twice a value. The test with `{72, 35, 91}` passes;
the interviewer's hidden test with a 75 and a target of 150 does not. Ask the map
first, store second.
::

::side-note{kind="performance"}
For counting lowercase letters, `int[26]` beats `HashMap<Character, Integer>`
comfortably: no hashing, no boxing, contiguous memory. Use the map when the keys
are not small integers (names, roll numbers, words). Choosing the array when it
fits, and saying why, is a small but real signal.
::

## Interview questions

::accordion
  :::accordion-item{label="1. Two-sum: brute force, then optimise" icon="i-lucide-message-circle"}
  Brute force: two loops, O(n²), O(1) space. Optimised: one pass with a map from
  value to index, asking for `target - x` before storing `x`, O(n) time and O(n)
  space. If the array is sorted, two pointers give O(n) time with O(1) space. Give
  all three, in that order.
  :::

  :::accordion-item{label="2. Check whether two strings are anagrams" icon="i-lucide-message-circle"}
  Count letters of the first up, the second down, and check every count is zero.
  O(n) with `int[26]` for lowercase letters, or a `HashMap` for any characters.
  Sorting both and comparing is O(n log n) and also acceptable as a first answer.
  :::

  :::accordion-item{label="3. Group students' names that are anagrams of each other" icon="i-lucide-message-circle"}
  The key is the sorted letters of each name; the value is the list of names
  with that key.

  ```java
  Map<String, List<String>> groups = new HashMap<>();
  for (String name : names) {
    char[] letters = name.toCharArray();
    Arrays.sort(letters);
    groups.computeIfAbsent(new String(letters), k -> new ArrayList<>()).add(name);
  }
  ```

  O(n × L log L) for n names of length L.
  :::

  :::accordion-item{label="4. Find the element that appears more than n/2 times" icon="i-lucide-message-circle"}
  A frequency map is O(n) time and O(n) space. The follow-up wants O(1) space:
  Boyer-Moore voting. Keep a candidate and a counter; same value increments,
  different decrements, zero means take the current value as the new candidate.
  The survivor is the majority when one is guaranteed.
  :::

  :::accordion-item{label="5. When is a HashMap the wrong tool?" icon="i-lucide-message-circle"}
  When the keys are small integers in a known range (use an array), when you need
  order or ranges (use `TreeMap`), when memory is tight and sorting is allowed
  (sort plus two pointers), and when the collection is tiny, where a linear scan
  is simpler and as fast.
  :::
::
