A window is a pair of pointers moving the same way, where everything between
them is the stretch you care about: seven consecutive days of attendance, or a
run of letters with no repeats. When the window slides one step, only two
elements change, so you update the answer in O(1) instead of recounting the
whole stretch.

## Why this matters in a job

Because "maximum sum of k consecutive elements", "longest substring without
repeating characters" and "smallest subarray with sum at least X" are some of the
most asked medium problems in product company rounds, and all three are the same
pattern. The brute force checks every stretch, O(n²) or worse; the window is
O(n). And the pattern is real: rolling seven-day averages on a dashboard are a
sliding window.

## The window on the attendance register

The class teacher wants the best week of attendance, meaning the seven
consecutive days with the most students present, over a 180-day term. The slow
way: for every starting day, add up seven days. That is 174 × 7 additions. The
window way: add up the first seven days once. To move the window forward one day,
**add the new day and subtract the day that fell off**. Two operations per step,
whatever the width.

Windows come in two kinds, and deciding which one you have is the first step.

| | Fixed-size window | Variable-size window |
| --- | --- | --- |
| The question says | "k consecutive", "every window of size k" | "longest", "shortest", "smallest subarray such that" |
| Right edge | moves every step | moves every step |
| Left edge | moves every step, k behind | moves only when the window breaks a rule |
| Example | best 7-day attendance | longest name stretch with no repeated letter |

## How it works

### Fixed size: the best k consecutive days

```java [BestWeek.java]
public class BestWeek {

  static int bestWindow(int[] present, int k) {
    int sum = 0;
    for (int i = 0; i < k; i++) sum += present[i];     // first window
    int best = sum, bestStart = 0;
    for (int right = k; right < present.length; right++) {
      sum += present[right] - present[right - k];      // add new, drop old
      if (sum > best) {
        best = sum;
        bestStart = right - k + 1;
      }
    }
    System.out.println("Best window starts on day " + (bestStart + 1));
    return best;
  }

  public static void main(String[] args) {
    int[] present = {42, 38, 45, 50, 31, 47, 49, 52, 40, 36};
    System.out.println("Most present in 3 days: " + bestWindow(present, 3));
  }
}
```

```text [Output]
Best window starts on day 6
Most present in 3 days: 148
```

Days 6, 7 and 8 had 47 + 49 + 52 = 148. One pass, one addition and one
subtraction per day.

### Variable size: the template

For a variable window, the right edge always moves forward one step and the left
edge catches up only when the window becomes invalid. Every variable-window
problem fits this shape:

::flow{numbered caption="The variable-window loop"}
  :::flow-step{label="Grow" icon="i-lucide-arrow-right"}
  Move `right` one step and add `a[right]` to whatever the window tracks.
  :::
  :::flow-step{label="Shrink while broken" icon="i-lucide-arrow-left" highlight}
  While the window breaks the rule, remove `a[left]` and move `left` forward.
  :::
  :::flow-step{label="Record" icon="i-lucide-check"}
  The window is valid now. Update the best length (or the best sum).
  :::
::

### Longest stretch with no repeated character

Given a student ID string, find the longest substring with no character
repeated. The window tracks which characters it holds; the rule is "no
duplicates".

```java [LongestUnique.java]
public class LongestUnique {

  static String longest(String s) {
    int[] count = new int[128];                 // ASCII counts inside the window
    int left = 0, bestLen = 0, bestStart = 0;
    for (int right = 0; right < s.length(); right++) {
      char c = s.charAt(right);
      count[c]++;                               // grow
      while (count[c] > 1) {                    // shrink while broken
        count[s.charAt(left)]--;
        left++;
      }
      if (right - left + 1 > bestLen) {         // record
        bestLen = right - left + 1;
        bestStart = left;
      }
    }
    return s.substring(bestStart, bestStart + bestLen);
  }

  public static void main(String[] args) {
    System.out.println(longest("abcabcbb"));
    System.out.println(longest("CSE2024CSE"));
    System.out.println(longest("aaaa"));
  }
}
```

```text [Output]
abc
024CSE
a
```

The middle one is worth checking by hand, because it is the kind of answer you
would guess wrong. "CSE20" is the first stretch without a repeat, five long. The
second "2" breaks it, so `left` moves past the first "2", and the window then
grows to "024CSE", six characters with none repeated (the first "C", "S" and "E"
have already left the window), and the string ends there. Whenever I write a
window, I check the answer against the rule rather than against what I expected.

### Variable size: shortest stretch reaching a target

The fee office wants the fewest consecutive days of collections that add up to
at least ₹50,000. Here the rule is flipped: the window is "good" when the sum is
large enough, and you shrink it while it stays good, to find the shortest.

```java [ShortestFees.java]
public class ShortestFees {

  static int shortest(int[] collected, int target) {
    int left = 0, sum = 0, best = Integer.MAX_VALUE;
    for (int right = 0; right < collected.length; right++) {
      sum += collected[right];
      while (sum >= target) {                   // good: try to make it shorter
        best = Math.min(best, right - left + 1);
        sum -= collected[left];
        left++;
      }
    }
    return best == Integer.MAX_VALUE ? 0 : best;
  }

  public static void main(String[] args) {
    int[] collected = {12000, 8000, 21000, 5000, 30000, 9000, 4000};   // rupees per day
    System.out.println("Fewest days for 50,000: " + shortest(collected, 50000));
    System.out.println("Fewest days for 2,00,000: " + shortest(collected, 200000));
  }
}
```

```text [Output]
Fewest days for 50,000: 3
Fewest days for 2,00,000: 0
```

Days 3 to 5 collected 21,000 + 5,000 + 30,000 = 56,000. The second call returns
0, meaning no stretch reaches the target, because the whole week only collected
89,000. Decide the "not possible" value with the interviewer before you code.

### Complexity

| Problem | Brute force | Window | Space |
| --- | --- | --- | --- |
| Best k consecutive | O(n × k) | **O(n)** | O(1) |
| Longest substring without repeats | O(n³) or O(n²) | **O(n)** | O(size of alphabet) |
| Shortest subarray with sum ≥ target | O(n²) | **O(n)** | O(1) |

The variable window looks like a loop inside a loop, but it is O(n): `left` only
ever moves forward, so across the whole run it moves at most n times in total.
Say that sentence when you give the complexity, because the nested `while`
makes interviewers ask.

## Real use case

**Rolling averages.** A placement dashboard shows a seven-day rolling average of
students attending mock interviews. Each day's number is a fixed window over the
last seven days.

```java [RollingAverage.java]
public class RollingAverage {
  public static void main(String[] args) {
    int[] attended = {20, 24, 18, 30, 26, 22, 28, 35, 31};
    int k = 7, sum = 0;
    for (int i = 0; i < attended.length; i++) {
      sum += attended[i];
      if (i >= k) sum -= attended[i - k];
      if (i >= k - 1) {
        System.out.printf("Day %d: %.1f%n", i + 1, sum / (double) k);
      }
    }
  }
}
```

```text [Output]
Day 7: 24.0
Day 8: 26.1
Day 9: 27.1
```

Metrics systems, rate limiters ("no more than 100 requests from one student in
any 60 seconds") and network protocols (the TCP sliding window you will meet in
the Computer Networks track) are all this idea.

## What confuses people here

**Using a window when values can be negative.** The "shrink while the sum is at
least the target" logic assumes adding an element never makes the sum smaller.
With negative numbers (marks deductions, refunds), shrinking can make the sum go
up, and the window gives wrong answers. For "subarray sum equals k" with
negatives, use prefix sums with a `HashMap`, which is in the hashing problems
lesson.

::warning{icon="i-lucide-alert-triangle"}
**Window length is `right - left + 1`, not `right - left`.** A window from index
3 to index 5 holds three elements. This single off-by-one is the most common bug
in window code, and it produces answers that are wrong by exactly one, which
look almost right.
::

## Interview questions

::accordion
  :::accordion-item{label="1. Why is the variable sliding window O(n) with a nested while loop?" icon="i-lucide-message-circle"}
  Each element is added once when `right` passes it and removed at most once
  when `left` passes it. Both pointers only move forward, so the total work is at
  most 2n steps, O(n), regardless of how the loops are nested.
  :::

  :::accordion-item{label="2. Maximum of every window of size k" icon="i-lucide-message-circle"}
  A running sum does not work for max, because you cannot "subtract" a maximum
  when it leaves. Use an `ArrayDeque` of indices kept in decreasing order of
  value: drop indices that fell out of the window from the front, drop smaller
  values from the back before adding. The front is always the maximum. O(n).
  This is the monotonic deque, a cousin of the monotonic stack in the stacks
  chapter.
  :::

  :::accordion-item{label="3. Count anagrams of a pattern in a text" icon="i-lucide-message-circle"}
  Fixed window of the pattern's length, with an `int[26]` count for the pattern
  and one for the window. Slide: increment the new letter, decrement the one that
  left, compare the two arrays (26 steps, constant). O(n × 26), which is O(n).
  :::

  :::accordion-item{label="4. How do you tell a window problem from a two-pointer problem?" icon="i-lucide-message-circle"}
  A window problem cares about everything **between** the pointers (a sum, a
  count of letters). An opposite-end two-pointer problem cares only about the two
  elements the pointers are **on**. "Contiguous", "consecutive", "substring" and
  "subarray" point to a window.
  :::
::
