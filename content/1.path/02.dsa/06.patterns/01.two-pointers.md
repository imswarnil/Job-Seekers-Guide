On a sorted list, one finger at the lowest mark and one at the highest can find
two marks adding up to 150 in a single pass, because every step tells you which
finger to move. That is the **two-pointer** pattern, and once you see it you
will find it in a fifth of all array questions.

## Why this matters in a job

Because the brute-force answer to "find a pair with this sum", "remove
duplicates in place" or "move all zeros to the end" is two nested loops, O(n²),
and the interviewer is waiting for you to say "two pointers" and make it O(n).
These problems appear in online assessments at service companies and as the
first problem of the first DSA round at product companies. They are also the
cheapest way to show you can reason about indices without an off-by-one.

## Two kinds of two pointers

::feature-list{columns="2"}
  :::feature{icon="i-lucide-arrow-right-left" title="Opposite ends, moving inwards"}
  `left` starts at 0, `right` at the end. Compare, then move one of them
  towards the other. Stops when they meet. Needs the array sorted, or a problem
  that is symmetric (reversing, palindromes).
  :::
  :::feature{icon="i-lucide-arrow-right" title="Same direction, slow and fast"}
  `fast` reads every element; `slow` marks where the next kept element should
  be written. Used for rearranging in place: removing duplicates, moving zeros,
  compacting a list.
  :::
::

The analogy for the first kind: two invigilators at opposite ends of a row of
benches, walking towards each other. Each step, one of them can rule out their
own bench for good. For the second kind: a clerk reading every form in a pile
(fast) while a second clerk stacks only the valid ones (slow).

## How it works

### Pair with a target sum, in a sorted array

Two students are to be paired for a project so that their marks add up to
exactly 150. The marks are sorted.

```java [PairSum.java]
public class PairSum {

  static int[] findPair(int[] sortedMarks, int target) {
    int left = 0, right = sortedMarks.length - 1;
    while (left < right) {
      int sum = sortedMarks[left] + sortedMarks[right];
      if (sum == target) return new int[]{left, right};
      if (sum < target) left++;          // need bigger: only left can grow it
      else right--;                      // need smaller: only right can shrink it
    }
    return null;
  }

  public static void main(String[] args) {
    int[] marks = {35, 48, 60, 72, 78, 88, 95};
    int[] pair = findPair(marks, 150);
    System.out.println("150: " + marks[pair[0]] + " + " + marks[pair[1]]);
    System.out.println("200: " + (findPair(marks, 200) == null ? "no pair" : "found"));
  }
}
```

```text [Output]
150: 72 + 78
200: no pair
```

Why it is safe to throw away an end: if `35 + 95` is too small, then 35 plus
anything else is even smaller, because 95 is the largest. So 35 can never be in
the answer. Every step removes one candidate permanently, so there are at most
n steps.

### Remove duplicates in place

A sorted list of roll numbers has duplicates because some students registered
twice. Remove them without a second array and return the new length.

```java [RemoveDuplicates.java]
import java.util.Arrays;

public class RemoveDuplicates {

  static int dedupe(int[] rolls) {
    if (rolls.length == 0) return 0;
    int slow = 0;                             // last kept position
    for (int fast = 1; fast < rolls.length; fast++) {
      if (rolls[fast] != rolls[slow]) {
        slow++;
        rolls[slow] = rolls[fast];            // keep it
      }
    }
    return slow + 1;
  }

  public static void main(String[] args) {
    int[] rolls = {1003, 1003, 1007, 1019, 1019, 1019, 1031};
    int length = dedupe(rolls);
    System.out.println("Unique: " + length);
    System.out.println(Arrays.toString(Arrays.copyOf(rolls, length)));
  }
}
```

```text [Output]
Unique: 4
[1003, 1007, 1019, 1031]
```

### Move absentees to the end

Attendance for a week, where 0 means absent. Move all the zeros to the end and
keep the order of the rest, in place.

```java [MoveZeros.java]
import java.util.Arrays;

public class MoveZeros {

  static void moveZeros(int[] hours) {
    int slow = 0;
    for (int fast = 0; fast < hours.length; fast++) {
      if (hours[fast] != 0) {
        int t = hours[slow]; hours[slow] = hours[fast]; hours[fast] = t;
        slow++;
      }
    }
  }

  public static void main(String[] args) {
    int[] hours = {6, 0, 5, 0, 0, 7, 4};
    moveZeros(hours);
    System.out.println(Arrays.toString(hours));
  }
}
```

```text [Output]
[6, 5, 7, 4, 0, 0, 0]
```

### The widest pair: container with most water

A classic that looks nothing like two pointers until you see it. Walls of
heights `h[i]` stand along a line; pick two to hold the most water between them.
Area is `min(h[left], h[right]) × (right - left)`. Always move the **shorter**
wall inwards, because the shorter wall limits the area and moving the taller one
can only make the width smaller without raising the limit.

```java [MostWater.java]
public class MostWater {

  static int maxArea(int[] h) {
    int left = 0, right = h.length - 1, best = 0;
    while (left < right) {
      int area = Math.min(h[left], h[right]) * (right - left);
      best = Math.max(best, area);
      if (h[left] < h[right]) left++;
      else right--;
    }
    return best;
  }

  public static void main(String[] args) {
    int[] heights = {1, 8, 6, 2, 5, 4, 8, 3, 7};
    System.out.println("Most water: " + maxArea(heights));
  }
}
```

```text [Output]
Most water: 49
```

### Complexity

| Problem | Brute force | Two pointers | Extra space |
| --- | --- | --- | --- |
| Pair with sum (sorted) | O(n²) | **O(n)** | O(1) |
| Remove duplicates (sorted) | O(n) with a set, O(n) space | **O(n)** | O(1) |
| Move zeros | O(n²) shifting | **O(n)** | O(1) |
| Container with most water | O(n²) | **O(n)** | O(1) |

If the array is unsorted, pair-sum costs O(n log n) to sort first. The hashing
lesson later in this chapter does it in O(n) without sorting, which is the
follow-up every interviewer asks.

## Real use case

**Merging two sorted lists is two pointers.** One pointer per list, take the
smaller, advance that one. You wrote it in merge sort. The same shape finds the
students who appear in both the hostel list and the scholarship list, when both
are sorted by roll number:

```java [BothLists.java]
import java.util.ArrayList;
import java.util.List;

public class BothLists {
  public static void main(String[] args) {
    int[] hostel = {1003, 1007, 1019, 1031, 1055};
    int[] scholarship = {1002, 1007, 1031, 1042, 1055, 1068};
    List<Integer> both = new ArrayList<>();
    int i = 0, j = 0;
    while (i < hostel.length && j < scholarship.length) {
      if (hostel[i] == scholarship[j]) { both.add(hostel[i]); i++; j++; }
      else if (hostel[i] < scholarship[j]) i++;
      else j++;
    }
    System.out.println("In both: " + both);
  }
}
```

```text [Output]
In both: [1007, 1031, 1055]
```

O(n + m), no extra structure. This is the same algorithm a database uses for a
**merge join** when both sides are sorted on the join column.

## What confuses people here

**Using opposite-end pointers on unsorted data.** The rule "sum too small, move
left" is only true because the array is sorted. On `{72, 35, 95, 48}` it skips
valid pairs and returns "no pair" with confidence.

::warning{icon="i-lucide-alert-triangle"}
**`left <= right` in pair-sum.** With `<=`, when both pointers meet on one
element, the code adds that element to itself. A student with 75 marks gets
paired with herself for a target of 150. Pairs need two different indices:
`left < right`.
::

::tip
To spot the pattern, look for these words: "sorted array", "pair", "triplet",
"in place", "without extra space", "reverse", "palindrome". Any one of them is a
strong hint to try two pointers before anything else.
::

## Interview questions

::accordion
  :::accordion-item{label="1. Three students whose marks add up to a target (3Sum)" icon="i-lucide-message-circle"}
  Sort, then fix each element `i` and run pair-sum with two pointers on the part
  after it, looking for `target - a[i]`. O(n²) instead of the brute force O(n³).
  Skip equal neighbours of `i`, `left` and `right` to avoid duplicate triplets,
  which is the part people forget.
  :::

  :::accordion-item{label="2. Check whether a roll-number string is a palindrome, ignoring non-letters" icon="i-lucide-message-circle"}
  Opposite-end pointers. Skip characters that are not letters or digits, compare
  the rest case-insensitively, stop when they cross.

  ```java
  static boolean isPalindrome(String s) {
    int l = 0, r = s.length() - 1;
    while (l < r) {
      if (!Character.isLetterOrDigit(s.charAt(l))) l++;
      else if (!Character.isLetterOrDigit(s.charAt(r))) r--;
      else if (Character.toLowerCase(s.charAt(l++)) != Character.toLowerCase(s.charAt(r--)))
        return false;
    }
    return true;
  }
  ```
  :::

  :::accordion-item{label="3. Why is it safe to move the shorter wall in container with most water?" icon="i-lucide-message-circle"}
  The area is capped by the shorter wall. Keeping the shorter wall and moving the
  taller one inwards makes the width smaller while the cap stays the same or
  drops, so no pair using the shorter wall and a closer partner can be better.
  That wall can be discarded, which is what makes one pass enough.
  :::

  :::accordion-item{label="4. Squares of a sorted array, still sorted" icon="i-lucide-message-circle"}
  Marks adjustments from -4 to 10 squared: the largest squares are at the two
  ends. Pointers at both ends, write the larger square into the result from the
  back. O(n), where squaring and sorting is O(n log n).
  :::
::
