Take it or leave it, under a limit. When every choice has two options and a
budget caps what you can take, one row of answers is not enough: you need a
table, with one axis for "which items have I considered" and one for "how much
budget is left".

This is the lesson where I stopped copying DP solutions and started drawing the
table on paper first. Draw it every time. The code writes itself from the
drawing.

## Why this matters in a job

The **0/1 knapsack** is the parent of a whole family of interview problems:
subset sum ("can these fees add up to exactly ₹50,000?"), partition into two
equal halves, target sum, coin change. The **longest common subsequence** (LCS)
is the parent of edit distance, which is how `git diff` and spelling suggestions
decide what changed. Know the two parents and you can derive most of the
children in the room.

## The knapsack, as a timetable problem

A student can take at most **7 credits** of electives this semester. Each
elective has a credit cost and a value to her (how useful it is for placements,
out of 10):

| Elective | Credits | Value |
| --- | --- | --- |
| Data Mining | 1 | 1 |
| Cloud Computing | 3 | 4 |
| Machine Learning | 4 | 5 |
| Cyber Security | 5 | 7 |

Each elective is taken whole or not at all (that is the "0/1"). Which
combination gives the most value within 7 credits?

Greedy thinking says "take the most valuable first": Cyber Security, value 7,
uses 5 credits, and with the 2 left only Data Mining fits. Total 8. But Cloud
Computing plus Machine Learning is exactly 7 credits and worth 9. Taking the
biggest thing first lost. We need a method that checks every combination without
trying all 2ⁿ of them.

### The state

`dp[i][c]` = the best value using only the **first i electives**, with **c
credits** available.

For each elective there are two choices:

- **Leave it**: the answer is whatever the first `i - 1` electives managed with
  the same credits, `dp[i - 1][c]`.
- **Take it** (only if it fits): its value plus the best the others can do with
  the credits that remain, `value + dp[i - 1][c - credits]`.

`dp[i][c]` is the larger of the two.

## How it works

```java [Electives.java]
public class Electives {
  public static void main(String[] args) {
    String[] names = {"Data Mining", "Cloud Computing", "Machine Learning", "Cyber Security"};
    int[] credits = {1, 3, 4, 5};
    int[] value = {1, 4, 5, 7};
    int limit = 7;

    int n = names.length;
    int[][] dp = new int[n + 1][limit + 1];      // row 0 and column 0 stay 0

    for (int i = 1; i <= n; i++) {
      for (int c = 0; c <= limit; c++) {
        int leave = dp[i - 1][c];
        int take = -1;
        if (credits[i - 1] <= c) {
          take = value[i - 1] + dp[i - 1][c - credits[i - 1]];
        }
        dp[i][c] = Math.max(leave, take);
      }
    }

    System.out.println("Best value within " + limit + " credits: " + dp[n][limit]);

    // Walk back through the table to see which electives were taken.
    int c = limit;
    for (int i = n; i >= 1; i--) {
      if (dp[i][c] != dp[i - 1][c]) {            // the value changed, so i was taken
        System.out.println("  take " + names[i - 1]);
        c -= credits[i - 1];
      }
    }
  }
}
```

```text [Output]
Best value within 7 credits: 9
  take Machine Learning
  take Cloud Computing
```

With 7 credits the answer is Cloud Computing plus Machine Learning (7 credits,
value 9), not Cyber Security plus Data Mining (6 credits, value 8). A greedy pick
of the most valuable elective first would have chosen Cyber Security and ended
with 8.

### Complexity

**O(n × W)** time and space, where n is the number of items and W the limit.
Every cell is filled once with constant work. Compare 2ⁿ for trying every
subset: 30 electives would be about a billion subsets, while the table with a
limit of 30 credits is 900 cells.

The space drops to **O(W)** with a single row filled from right to left, because
each cell only reads the previous row at the same or smaller credits.

## Longest common subsequence

A **subsequence** is what is left after deleting some characters without
reordering the rest. From `"CSE2019"`, `"C219"` is a subsequence; `"91"` is not,
because the order changed. (A **substring** must be continuous; a subsequence
need not be.)

The LCS of two strings is the longest subsequence they share. Compare two
students' submitted answer strings for a multiple-choice test, and the LCS tells
you how much of one appears, in order, in the other.

`dp[i][j]` = the LCS length of the first i characters of `a` and the first j of
`b`.

- If `a[i-1] == b[j-1]`, that character extends the answer: `dp[i-1][j-1] + 1`.
- Otherwise drop one character from either string and keep the better:
  `max(dp[i-1][j], dp[i][j-1])`.

```java [AnswerSheets.java]
public class AnswerSheets {
  static String lcs(String a, String b) {
    int[][] dp = new int[a.length() + 1][b.length() + 1];
    for (int i = 1; i <= a.length(); i++) {
      for (int j = 1; j <= b.length(); j++) {
        if (a.charAt(i - 1) == b.charAt(j - 1)) {
          dp[i][j] = dp[i - 1][j - 1] + 1;
        } else {
          dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
        }
      }
    }
    // Walk back from the bottom-right corner to rebuild the letters.
    StringBuilder shared = new StringBuilder();
    int i = a.length(), j = b.length();
    while (i > 0 && j > 0) {
      if (a.charAt(i - 1) == b.charAt(j - 1)) {
        shared.append(a.charAt(i - 1));
        i--; j--;
      } else if (dp[i - 1][j] >= dp[i][j - 1]) {
        i--;
      } else {
        j--;
      }
    }
    return shared.reverse().toString();
  }

  public static void main(String[] args) {
    String priya = "ABCBDAB";
    String rahul = "BDCABA";
    String shared = lcs(priya, rahul);
    System.out.println("Priya: " + priya);
    System.out.println("Rahul: " + rahul);
    System.out.println("Longest shared run of answers: " + shared + " (" + shared.length() + ")");
  }
}
```

```text [Output]
Priya: ABCBDAB
Rahul: BDCABA
Longest shared run of answers: BCBA (4)
```

There can be more than one LCS of the same length (`BDAB` is another here). The
length is unique; the letters are not. Say that if asked to "return the LCS".

### Complexity

**O(m × n)** time and space for strings of length m and n. Each cell reads three
neighbours.

## Real use case

::real-life{title="Why the diff shows what it shows" source="Every code review you will ever do"}
When you open a pull request and see green and red lines, the tool is solving a
longest common subsequence over lines rather than characters: the lines both
versions share, in order, are "unchanged", and everything else was added or
removed. The same family (edit distance) is how a student-search box suggests
"Rahul Sharma" when somebody types "Rahul Sarma".
::

## What confuses people here

::warning{icon="i-lucide-alert-triangle"}
**Off-by-one between the table and the arrays.** The table has an extra row and
column for "zero items" and "empty string", so row `i` describes item `i - 1`.
Every bug I made with knapsack was reading `credits[i]` where I meant
`credits[i - 1]`. Write the state sentence as a comment above the loop.
::

Two more traps:

- **Subsequence versus substring.** Longest common *substring* resets to 0 on a
  mismatch instead of taking the max. Ask which one the interviewer means.
- **0/1 versus unbounded knapsack.** If an item can be used any number of times
  (coin change), the "take" branch reads the *current* row. One index decides
  which problem you solved.

## Interview questions

::accordion
  :::accordion-item{label="Why not solve knapsack greedily by value per credit?" icon="i-lucide-message-circle"}
  Because items cannot be split. With a limit of 7, value per credit ranks Cyber
  Security (1.4) first, and after taking it the best that still fits is Data
  Mining, total 8. The table finds Cloud Computing plus Machine Learning, 9.
  Greedy by ratio is correct only for the fractional knapsack, where you can
  take part of an item.
  :::
  :::accordion-item{label="Can the fees add up to exactly the target? (subset sum)" icon="i-lucide-message-circle"}
  Knapsack with booleans instead of values:

  ```java
  static boolean canMake(int[] fees, int target) {
    boolean[] dp = new boolean[target + 1];
    dp[0] = true;                                  // zero is always possible
    for (int fee : fees)
      for (int t = target; t >= fee; t--)          // right to left: each fee once
        dp[t] = dp[t] || dp[t - fee];
    return dp[target];
  }
  // canMake(new int[]{12000, 18000, 20000}, 30000) → true
  ```
  :::
  :::accordion-item{label="What is the difference between LCS and edit distance?" icon="i-lucide-message-circle"}
  LCS counts what two strings share in order. Edit distance counts the minimum
  inserts, deletes and replacements to turn one into the other. Same shaped
  table, a different transition: on a mismatch edit distance takes
  `1 + min(replace, insert, delete)`.
  :::
  :::accordion-item{label="Reduce knapsack to O(W) space" icon="i-lucide-message-circle"}
  Keep one array and fill it from the largest capacity down, so every read of
  `dp[c - weight]` still sees the previous item's value:

  ```java
  int[] dp = new int[limit + 1];
  for (int i = 0; i < credits.length; i++)
    for (int c = limit; c >= credits[i]; c--)
      dp[c] = Math.max(dp[c], value[i] + dp[c - credits[i]]);
  ```
  :::
::

## Next

::callout{icon="i-lucide-arrow-right"}
Dynamic programming earns its answer by considering every choice and remembering
the results. Some problems let you skip all of that: take the best-looking
option at every step and never look back. Knowing when that shortcut is safe,
and when it quietly gives the wrong answer, is the whole skill.
::
