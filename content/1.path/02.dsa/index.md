You can write Java now: classes, collections, exceptions, a test or two. That
gets you through the technical questions about the language. It does not get
you through the coding round, where somebody hands you a problem you have never
seen and a clock.

I did not learn this properly the first time. At the institute in 2018 I learnt
enough Java to answer the walk-in interviewers, and the coding questions in the
written rounds were the part I guessed at. I learnt DSA properly years later,
at weekends, when I decided to switch jobs, and it is the single subject that
moved my salary most: from about 5 LPA to offers of 15.5 LPA and then 30+ LPA.
None of it was hard. It was a lot of small ideas stacked in the right order,
and this track is that order.

## How to use this track

Every lesson has a complete Java program and the output it really prints.
There is no Java runner in the browser, so type each one into your editor and
run it yourself. Typing it matters: most of what I learnt about these problems
I learnt from the version I got wrong.

::tip
Aim for two or three problems a day, every day, rather than ten on a Sunday.
Eight to ten weeks at that pace covers everything here and the fifty problems
at the end. Skip ahead to the patterns chapter if you have a test next week:
it pays back fastest.
::

::caution
This is the track people give up on, usually in recursion or dynamic
programming. The feeling of being stuck on a problem for forty minutes is not a
sign you are bad at this. It is what the work feels like, for everybody, and it
gets shorter.
::
