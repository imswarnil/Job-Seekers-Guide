**Backtracking** is recursion that makes a choice, explores everything that
follows from it, then undoes the choice and tries the next one. It is how you
list every subset of electives, every order of exam papers, every way to reach
a credit target. Three steps, the same in every problem: choose, explore,
unchoose.

## Why this matters in a job

Because "print all subsets", "print all permutations of a string" and
"combination sum" are standard medium questions in product-company rounds, and
N-Queens and Sudoku are the famous hard ones. Because the constraint "n ≤ 20"
in an online test is often a direct hint that backtracking is expected. At work
it appears less often by name, but the same search shows up in scheduling,
seat allotment and configuration tools that must try options until one fits.

## Walking a maze with chalk

Think of exploring the corridors of an unfamiliar college building for the
exam hall. At each junction you pick a corridor and mark it with chalk. If it
dead-ends, you walk back to the junction, rub out the mark, and try the next
corridor. You never try the same path twice, and you never give up on a
junction until every corridor from it has been tried.

That is the template:

::flow{numbered caption="The backtracking template. The third step is the one people forget."}
  :::flow-step{label="Choose" icon="i-lucide-mouse-pointer-click"}
  Add one option to the current partial answer.
  :::
  :::flow-step{label="Explore" icon="i-lucide-search" highlight}
  Recurse to make the remaining choices with that option in place.
  :::
  :::flow-step{label="Unchoose" icon="i-lucide-undo-2"}
  Remove the option, so the partial answer is exactly as it was, and try the next.
  :::
::

The possible choices form a **decision tree**. For subsets of three electives,
every elective is a yes-or-no decision, so the tree has 2³ = 8 leaves.

## How it works

### All subsets

A student may choose any combination of three electives. List every
combination, including choosing none.

```java [Subsets.java]
import java.util.*;

public class Subsets {
  static void subsets(String[] electives, int index, List<String> current,
                      List<List<String>> result) {
    if (index == electives.length) {           // every elective decided
      result.add(new ArrayList<>(current));    // save a COPY
      return;
    }
    // Option 1: skip this elective
    subsets(electives, index + 1, current, result);

    // Option 2: take it. Choose, explore, unchoose.
    current.add(electives[index]);
    subsets(electives, index + 1, current, result);
    current.remove(current.size() - 1);
  }

  public static void main(String[] args) {
    String[] electives = {"DS", "ML", "OS"};
    List<List<String>> result = new ArrayList<>();
    subsets(electives, 0, new ArrayList<>(), result);
    System.out.println(result.size() + " subsets");
    System.out.println(result);
  }
}
```

```text [Output]
8 subsets
[[], [OS], [ML], [ML, OS], [DS], [DS, OS], [DS, ML], [DS, ML, OS]]
```

::warning{icon="i-lucide-alert-triangle"}
`result.add(new ArrayList<>(current))`, not `result.add(current)`. There is only
one `current` list, and it is emptied by the unchoose steps. Adding the list
itself stores eight references to the same object, and at the end you print
eight empty lists. This is the most common backtracking bug by a distance.
::

### All permutations

Three exam papers, Maths, Physics and Chemistry, to be scheduled on three days.
Every order is a **permutation**. At each position, try every paper not yet
used.

```java [Permutations.java]
import java.util.*;

public class Permutations {
  static void permute(String[] papers, boolean[] used, List<String> current,
                      List<List<String>> result) {
    if (current.size() == papers.length) {
      result.add(new ArrayList<>(current));
      return;
    }
    for (int i = 0; i < papers.length; i++) {
      if (used[i]) continue;
      used[i] = true;                          // choose
      current.add(papers[i]);
      permute(papers, used, current, result);  // explore
      current.remove(current.size() - 1);      // unchoose
      used[i] = false;
    }
  }

  public static void main(String[] args) {
    String[] papers = {"Maths", "Physics", "Chemistry"};
    List<List<String>> result = new ArrayList<>();
    permute(papers, new boolean[papers.length], new ArrayList<>(), result);
    for (List<String> order : result) System.out.println(order);
  }
}
```

```text [Output]
[Maths, Physics, Chemistry]
[Maths, Chemistry, Physics]
[Physics, Maths, Chemistry]
[Physics, Chemistry, Maths]
[Chemistry, Maths, Physics]
[Chemistry, Physics, Maths]
```

### Combination sum, and pruning

A student needs exactly 10 credits from courses worth 2, 3, 5 and 7 credits,
where a course type may be taken more than once. List every combination.

**Pruning** means stopping a branch early when it cannot possibly succeed. Once
the running total passes 10, nothing further down that branch can come back to
10, so there is no point exploring it.

```java [CreditTarget.java]
import java.util.*;

public class CreditTarget {
  static void combine(int[] credits, int start, int remaining,
                      List<Integer> current, List<List<Integer>> result) {
    if (remaining == 0) {
      result.add(new ArrayList<>(current));
      return;
    }
    for (int i = start; i < credits.length; i++) {
      if (credits[i] > remaining) break;       // prune: sorted, so the rest are bigger
      current.add(credits[i]);
      combine(credits, i, remaining - credits[i], current, result);  // i, not i + 1: reuse allowed
      current.remove(current.size() - 1);
    }
  }

  public static void main(String[] args) {
    int[] credits = {2, 3, 5, 7};              // sorted, so the prune is valid
    List<List<Integer>> result = new ArrayList<>();
    combine(credits, 0, 10, new ArrayList<>(), result);
    System.out.println(result);
  }
}
```

```text [Output]
[[2, 2, 2, 2, 2], [2, 2, 3, 3], [2, 3, 5], [3, 7], [5, 5]]
```

Passing `start` rather than 0 is what stops `[2, 3, 5]` and `[3, 2, 5]` both
appearing: each combination is built in non-decreasing order only.

### Complexity

Backtracking is exponential by nature, because the number of answers is.

| Problem | Number of answers | Time |
| --- | --- | --- |
| Subsets of n | 2ⁿ | O(n × 2ⁿ), n to copy each |
| Permutations of n | n! | O(n × n!) |
| Combination sum | depends on the target | exponential, pruning helps in practice |

| n | 2ⁿ | n! |
| --- | --- | --- |
| 10 | 1,024 | 3,628,800 |
| 20 | 1,048,576 | about 2.4 × 10¹⁸ |

This is the constraints table from the first chapter, from the other side:
n ≤ 20 means 2ⁿ is expected, n ≤ 10 means n! is.

::side-note{kind="go-deeper"}
**N-Queens** places n queens on an n × n chessboard so none attack each other,
one row at a time, backtracking when a row has no safe column. **Sudoku** fills
empty cells the same way. Both are the template above with a validity check
before "choose". If you can write subsets and permutations cleanly, both are
reachable.
::

## Real use case

::real-life{title="Scheduling exams with no clashes" source="An examination cell"}
An exam cell has to place 12 papers into 6 slots so that no student sits two
papers in the same slot. A small tool tried papers slot by slot: place a paper,
check for clashes with papers already in that slot, recurse to the next paper,
and remove it if the rest could not be placed. For 12 papers it found a
clash-free timetable in under a second. Scheduling tools at scale use smarter
methods, but most of them still have a backtracking search at their core.
::

## What confuses people here

- **Forgetting to unchoose.** Without `current.remove(...)`, choices leak into
  sibling branches and the output is garbage.
- **Storing the list instead of a copy.** Covered in the warning above.
- **Duplicates in the answer.** For combinations, pass a `start` index so you
  never go backwards. For inputs with repeated values, sort first and skip
  `i > start && a[i] == a[i − 1]`.
- **Expecting it to be fast.** It is exhaustive. If n is 10⁵, backtracking is
  the wrong idea, however well it is pruned.

## Interview questions

::accordion
  :::accordion-item{label="Generate all subsets of a set." icon="i-lucide-message-circle"}
  For each element, recurse twice: once without it and once with it (choose,
  explore, unchoose). Save a copy at the leaf. 2ⁿ subsets, O(n × 2ⁿ) time. The
  bit-mask alternative loops `mask` from 0 to 2ⁿ − 1 and includes element `i`
  when bit `i` is set.
  :::

  :::accordion-item{label="Print all permutations of a string." icon="i-lucide-message-circle"}
  At each position try every unused character, marking it used before the
  recursive call and unused after. n! permutations. If the string has repeated
  characters, sort it and skip a character equal to the previous one whose
  previous copy is not in use, to avoid duplicates.
  :::

  :::accordion-item{label="What is the difference between recursion and backtracking?" icon="i-lucide-message-circle"}
  Backtracking is a use of recursion: it explores a tree of choices and undoes
  each choice after exploring it, so the shared state is restored for the next
  branch. Plain recursion, like factorial, has one path and nothing to undo.
  :::

  :::accordion-item{label="What is pruning, and why does it matter?" icon="i-lucide-message-circle"}
  Abandoning a branch as soon as it cannot lead to a valid answer, such as when
  the running total already exceeds the target. It does not change the
  worst-case Big-O, but it can cut the explored tree by orders of magnitude on
  real inputs.
  :::

  :::accordion-item{label="Why add new ArrayList<>(current) instead of current?" icon="i-lucide-message-circle"}
  `current` is one shared list that is changed throughout the search. Adding it
  directly stores a reference to that single object, which is empty by the time
  the search ends. A copy freezes the answer as it was at that leaf.
  :::
::
