The list got sorted by somebody comparing and swapping, and the three oldest
ways of doing that are the ones every fresher interview still asks you to write
on paper. They are slow, and understanding exactly why they are slow is what
makes the fast ones in the next two lessons make sense.

## Why this matters in a job

Because "write bubble sort" and "write insertion sort" are standard questions in
service company written rounds and in the first technical interview, often on
paper with no compiler. Because "which sort is best for nearly sorted data?" has
a specific answer (insertion sort). And because recognising a hand-written O(n²)
sort hiding in somebody's code, in a loop that runs on 40,000 records, is a real
skill in a real job.

## Three ways to sort a pile of answer sheets

You have a pile of answer sheets and you want them in order of marks.

::feature-list{columns="3"}
  :::feature{icon="i-lucide-arrow-down-up" title="Bubble sort"}
  Walk the pile, and every time two neighbours are the wrong way round, swap
  them. After one walk, the biggest has floated to the end. Walk again.
  :::
  :::feature{icon="i-lucide-mouse-pointer-click" title="Selection sort"}
  Scan the whole pile for the lowest mark, put it first. Scan the rest for the
  next lowest, put it second. Select, place, repeat.
  :::
  :::feature{icon="i-lucide-list-ordered" title="Insertion sort"}
  Pick up sheets one at a time and slide each into its place among the sheets
  you are already holding, the way you arrange playing cards.
  :::
::

## How it works

All three below sort the same six marks, so you can compare the passes.

### Bubble sort

::memory{kind="array" caption="Bubble sort: after each pass, the largest remaining value is in its final place."}
---

    cells: [{ value: 64 }, { value: 35 }, { value: 88 }, { value: 12 }, { value: 70 }, { value: 41 }]
  - label: "After pass 1: 88 has bubbled to the end"
    cells: [{ value: 35 }, { value: 64 }, { value: 12 }, { value: 70 }, { value: 41 }, { value: 88, state: "active" }]
  - label: "After pass 2: 70 is in place"
    cells: [{ value: 35 }, { value: 12 }, { value: 64 }, { value: 41 }, { value: 70, state: "active" }, { value: 88, state: "active" }]
---
::

```java [BubbleSort.java]
import java.util.Arrays;

public class BubbleSort {

  static void sort(int[] marks) {
    int n = marks.length;
    for (int pass = 0; pass < n - 1; pass++) {
      boolean swapped = false;
      for (int i = 0; i < n - 1 - pass; i++) {     // the last `pass` are done
        if (marks[i] > marks[i + 1]) {
          int temp = marks[i];
          marks[i] = marks[i + 1];
          marks[i + 1] = temp;
          swapped = true;
        }
      }
      System.out.println("After pass " + (pass + 1) + ": " + Arrays.toString(marks));
      if (!swapped) break;                         // already sorted: stop early
    }
  }

  public static void main(String[] args) {
    int[] marks = {64, 35, 88, 12, 70, 41};
    sort(marks);
  }
}
```

```text [Output]
After pass 1: [35, 64, 12, 70, 41, 88]
After pass 2: [35, 12, 64, 41, 70, 88]
After pass 3: [12, 35, 41, 64, 70, 88]
After pass 4: [12, 35, 41, 64, 70, 88]
```

Pass 4 made no swap, so the `swapped` flag stopped it early. Without that flag,
bubble sort does all five passes whatever the input. With it, an already sorted
list takes one pass, O(n). Mention the flag when you write it; it is the detail
that shows you understand the algorithm rather than remembering it.

### Selection sort

```java [SelectionSort.java]
import java.util.Arrays;

public class SelectionSort {

  static void sort(int[] marks) {
    int n = marks.length;
    for (int i = 0; i < n - 1; i++) {
      int minIndex = i;
      for (int j = i + 1; j < n; j++) {            // find the smallest in the rest
        if (marks[j] < marks[minIndex]) {
          minIndex = j;
        }
      }
      int temp = marks[i];                         // one swap per pass
      marks[i] = marks[minIndex];
      marks[minIndex] = temp;
      System.out.println("After pass " + (i + 1) + ": " + Arrays.toString(marks));
    }
  }

  public static void main(String[] args) {
    int[] marks = {64, 35, 88, 12, 70, 41};
    sort(marks);
  }
}
```

```text [Output]
After pass 1: [12, 35, 88, 64, 70, 41]
After pass 2: [12, 35, 88, 64, 70, 41]
After pass 3: [12, 35, 41, 64, 70, 88]
After pass 4: [12, 35, 41, 64, 70, 88]
After pass 5: [12, 35, 41, 64, 70, 88]
```

Selection sort always does every pass, even when nothing is left to do, because
it has no way to know the rest is sorted. Its one virtue is that it makes at
most n - 1 swaps. When a swap is expensive (moving physical files, writing to
flash memory that wears out), that matters. Almost nowhere else does it.

### Insertion sort

::memory{kind="array" caption="Insertion sort: the left part is always sorted. Each new value slides left until it fits."}
---

    cells: [{ value: 64, state: "active" }, { value: 35 }, { value: 88 }, { value: 12 }, { value: 70 }, { value: 41 }]
  - label: "35 slides before 64"
    cells: [{ value: 35, state: "active" }, { value: 64, state: "active" }, { value: 88 }, { value: 12 }, { value: 70 }, { value: 41 }]
  - label: "88 stays. 12 slides all the way to the front"
    cells: [{ value: 12, state: "active" }, { value: 35, state: "active" }, { value: 64, state: "active" }, { value: 88, state: "active" }, { value: 70 }, { value: 41 }]
---
::

```java [InsertionSort.java]
import java.util.Arrays;

public class InsertionSort {

  static void sort(int[] marks) {
    for (int i = 1; i < marks.length; i++) {
      int current = marks[i];
      int j = i - 1;
      while (j >= 0 && marks[j] > current) {       // shift bigger ones right
        marks[j + 1] = marks[j];
        j--;
      }
      marks[j + 1] = current;                      // drop it into the gap
      System.out.println("Inserted " + current + ": " + Arrays.toString(marks));
    }
  }

  public static void main(String[] args) {
    int[] marks = {64, 35, 88, 12, 70, 41};
    sort(marks);
  }
}
```

```text [Output]
Inserted 35: [35, 64, 88, 12, 70, 41]
Inserted 88: [35, 64, 88, 12, 70, 41]
Inserted 12: [12, 35, 64, 88, 70, 41]
Inserted 70: [12, 35, 64, 70, 88, 41]
Inserted 41: [12, 35, 41, 64, 70, 88]
```

Look at "Inserted 88": the `while` loop did not run at all, because 88 was
already bigger than everything before it. On a list that is already almost in
order, nearly every insertion looks like that, and insertion sort does close to
n steps in total. That is why it survives.

### Complexity

| Sort | Best | Average | Worst | Extra space | Stable? | Swaps |
| --- | --- | --- | --- | --- | --- | --- |
| Bubble (with flag) | O(n) | O(n²) | O(n²) | O(1) | Yes | Many |
| Selection | O(n²) | O(n²) | O(n²) | O(1) | **No** | At most n - 1 |
| Insertion | **O(n)** | O(n²) | O(n²) | O(1) | Yes | Many shifts |

Why n²: the outer loop runs n times and the inner loop up to n times, so up to
about n²/2 comparisons. For 40,000 applications that is about 800 million.
"Stable" means equal marks keep their original order; it gets a lesson of its
own at the end of this chapter.

## Real use case

You will not call any of these by name, but you use insertion sort every time
you call `Arrays.sort` on objects or `List.sort`. Java's sort for objects,
Timsort, cuts the list into short runs (32 to 64 elements) and sorts each run
with a form of insertion sort before merging them, because on 40 elements
insertion sort beats anything clever: no recursion, no extra array, no overhead.

```java [LateAdmissions.java]
import java.util.Arrays;

public class LateAdmissions {

  // The rank list is already sorted. Three late admissions are appended.
  // Insertion sort only has to move the three newcomers.
  public static void main(String[] args) {
    int[] ranks = {3, 8, 11, 15, 19, 24, 30, 36, 5, 17, 33};
    int shifts = 0;
    for (int i = 1; i < ranks.length; i++) {
      int current = ranks[i];
      int j = i - 1;
      while (j >= 0 && ranks[j] > current) {
        ranks[j + 1] = ranks[j];
        j--;
        shifts++;
      }
      ranks[j + 1] = current;
    }
    System.out.println(Arrays.toString(ranks));
    System.out.println("Shifts needed: " + shifts);
  }
}
```

```text [Output]
[3, 5, 8, 11, 15, 17, 19, 24, 30, 33, 36]
Shifts needed: 12
```

Twelve shifts for eleven elements. A selection sort on the same list would still do
55 comparisons, because it cannot tell that the list was nearly done.

## What confuses people here

**Off-by-one in the inner loop of bubble sort.** The inner loop goes to
`n - 1 - pass`, not `n`, because it compares `marks[i]` with `marks[i + 1]`.
Going to `n` reads past the end and throws `ArrayIndexOutOfBoundsException`.

::warning{icon="i-lucide-alert-triangle"}
**Selection sort is not stable**, and people assume it is because it is simple.
The long-distance swap can jump an element over an equal one. Sort `{70a, 70b,
40}` and the first pass swaps 70a with 40, giving `{40, 70b, 70a}`: the two 70s
have changed order. If the interviewer asks "which simple sort is unstable?",
this is the answer, with that example.
::

::side-note{kind="performance"}
All three sort **in place**, O(1) extra memory. That is their one real advantage
over merge sort, which needs a second array as big as the first. When memory is
tiny (a microcontroller in a lab instrument), in-place and simple can beat fast.
::

## Interview questions

::accordion
  :::accordion-item{label="1. Which sort would you use for a nearly sorted array?" icon="i-lucide-message-circle"}
  Insertion sort. Each element moves only as far as it is out of place, so with
  k elements out of position the work is about O(n × k), close to O(n) when k is
  small. That is also why Timsort uses it on short runs.
  :::

  :::accordion-item{label="2. What is the best-case complexity of bubble sort?" icon="i-lucide-message-circle"}
  O(n) with the `swapped` flag: one pass with no swaps proves the array is sorted.
  Without the flag it is O(n²) even on sorted input. Say which version you mean.
  :::

  :::accordion-item{label="3. Why is selection sort O(n²) even on sorted data?" icon="i-lucide-message-circle"}
  Because finding the minimum of the remaining part always scans all of it, and it
  never checks whether the rest is already in order. n + (n - 1) + ... + 1 is
  n(n + 1)/2 comparisons regardless of the input.
  :::

  :::accordion-item{label="4. How many swaps does selection sort make, at most?" icon="i-lucide-message-circle"}
  n - 1, one per pass. Bubble sort can make n(n - 1)/2 in the worst case (a
  reversed array). So when writes are expensive, selection sort is the one of the
  three to choose.
  :::

  :::accordion-item{label="5. Sort an array of 0s, 1s and 2s (absent / present / late) in one pass" icon="i-lucide-message-circle"}
  Not one of the three, and asked right after them: the Dutch national flag
  problem. Three pointers, O(n), O(1) space.

  ```java
  static void sort012(int[] a) {
    int low = 0, mid = 0, high = a.length - 1;
    while (mid <= high) {
      if (a[mid] == 0)      { int t = a[low]; a[low++] = a[mid]; a[mid++] = t; }
      else if (a[mid] == 1) { mid++; }
      else                  { int t = a[high]; a[high--] = a[mid]; a[mid] = t; }
    }
  }
  ```

  Note that `mid` does not advance after swapping with `high`, because the value
  that came back from the right has not been looked at yet.
  :::
::
