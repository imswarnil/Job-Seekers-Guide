The admissions office serves whoever arrived first. That is a **queue**: add at
the back, take from the front, and nobody jumps the line. Where a stack is
LIFO, a queue is **FIFO**, first in, first out.

## Why this matters in a job

Queues are the shape of most background work in real systems: emails waiting
to be sent, results waiting to be published, print jobs waiting for the
printer. In DSA they are the engine of **breadth-first search**, which you will
use for level order traversal of a tree in the next chapter and for shortest
paths in a graph after that. In interviews you will be asked the difference
between `offer` and `add`, to implement a **circular queue**, and to build a
queue out of two stacks.

## A counter with a line

Picture the fee counter on the first day of term. Students join at the back of
the line. The clerk always serves the student at the front. Two positions
matter, **front** (next to be served) and **rear** (where the next arrival
joins), and both ends move.

A **deque** (pronounced "deck", short for double-ended queue) lets you add and
remove at both ends. It is a stack and a queue in one, which is why Java's
`ArrayDeque` serves as both.

## How it works

### Queue and Deque in Java

`Queue` and `Deque` are interfaces; `ArrayDeque` is the class to use for both.
Each operation comes in two flavours: one that throws when it cannot do its
job, and one that returns a special value.

| Job | Throws on failure | Returns a value on failure |
| --- | --- | --- |
| Add at the back | `add(e)` | `offer(e)` returns `false` |
| Remove from the front | `remove()` | `poll()` returns `null` |
| Look at the front | `element()` | `peek()` returns `null` |

```java [ReviewQueue.java]
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.Queue;

public class ReviewQueue {
  public static void main(String[] args) {
    Queue<String> pending = new ArrayDeque<>();
    pending.offer("APP-0417");          // add at the back
    pending.offer("APP-0418");
    pending.offer("APP-0419");
    System.out.println("queue:     " + pending);
    System.out.println("peek:      " + pending.peek());
    System.out.println("poll:      " + pending.poll());
    System.out.println("poll:      " + pending.poll());
    System.out.println("queue:     " + pending);
    pending.poll();
    System.out.println("poll empty -> " + pending.poll());

    Deque<String> desk = new ArrayDeque<>();
    desk.offerLast("Riya");
    desk.offerLast("Karan");
    desk.offerFirst("Dean's nominee");   // jumps the line
    System.out.println("deque:     " + desk);
    System.out.println("pollLast:  " + desk.pollLast());
    System.out.println("pollFirst: " + desk.pollFirst());

    try {
      new ArrayDeque<String>().remove();
    } catch (Exception e) {
      System.out.println("remove on empty throws " + e.getClass().getSimpleName());
    }
  }
}
```

```text [Output]
queue:     [APP-0417, APP-0418, APP-0419]
peek:      APP-0417
poll:      APP-0417
poll:      APP-0418
queue:     [APP-0419]
poll empty -> null
deque:     [Dean's nominee, Riya, Karan]
pollLast:  Karan
pollFirst: Dean's nominee
remove on empty throws NoSuchElementException
```

::note
Prefer `offer`, `poll` and `peek`. On an empty queue they return `null` rather
than throwing, and on a bounded queue `offer` returns `false` when it is full.
That difference is the whole of your error handling, and interviewers
sometimes ask it to check whether you have read the interface or only used it.
One more trap: `ArrayDeque` does not accept `null` elements, precisely because
`null` is what `poll` returns to mean "empty".
::

### A circular queue on an array

Build a queue on a plain array the obvious way, with `front` moving right on
every poll, and you waste the slots behind it forever. After three polls the
first three seats are empty and unusable. The fix is to let the indexes **wrap
round** to 0 with the `%` operator, so the array behaves like a ring. Think of
exam hall seats arranged in a circle: when the last seat is taken, the next
student sits in the first seat, if it has been freed.

Keep a `size` counter alongside `front`. Then "full" is `size == capacity`,
"empty" is `size == 0`, and the rear is computed rather than stored.

```java [HallQueue.java]
public class HallQueue {
  private final int[] seats;
  private int front = 0;     // index of the next roll number to leave
  private int size = 0;

  HallQueue(int capacity) { seats = new int[capacity]; }

  boolean offer(int roll) {
    if (size == seats.length) return false;           // full
    int rear = (front + size) % seats.length;         // wrap round
    seats[rear] = roll;
    size++;
    return true;
  }

  Integer poll() {
    if (size == 0) return null;                       // empty
    int roll = seats[front];
    front = (front + 1) % seats.length;               // wrap round
    size--;
    return roll;
  }

  public static void main(String[] args) {
    HallQueue hall = new HallQueue(3);
    System.out.println(hall.offer(101) + " " + hall.offer(102) + " " + hall.offer(103));
    System.out.println("full, offer 104: " + hall.offer(104));
    System.out.println("poll: " + hall.poll() + ", poll: " + hall.poll());
    System.out.println("offer 104: " + hall.offer(104) + ", offer 105: " + hall.offer(105));
    System.out.println("front is now index " + hall.front);
    StringBuilder out = new StringBuilder("drain:");
    for (Integer r = hall.poll(); r != null; r = hall.poll()) out.append(' ').append(r);
    System.out.println(out);
    System.out.println("poll empty: " + hall.poll());
  }
}
```

```text [Output]
true true true
full, offer 104: false
poll: 101, poll: 102
offer 104: true, offer 105: true
front is now index 2
drain: 103 104 105
poll empty: null
```

104 and 105 went into slots 0 and 1, the seats that 101 and 102 freed, and
still came out after 103. That is the ring doing its job. `ArrayDeque` works
the same way inside, with one extra step: when the ring is full, it allocates a
bigger array and copies.

### A queue made of two stacks

A classic interview puzzle. Push arrivals onto an `in` stack. To take from the
front, pour `in` into an `out` stack (which reverses the order, putting the
oldest on top) but **only when `out` is empty**.

```java [TwoStackQueue.java]
import java.util.ArrayDeque;
import java.util.Deque;

public class TwoStackQueue {
  private final Deque<Integer> in = new ArrayDeque<>();
  private final Deque<Integer> out = new ArrayDeque<>();

  void offer(int roll) { in.push(roll); }

  Integer poll() {
    if (out.isEmpty()) {
      while (!in.isEmpty()) out.push(in.pop());   // reverse once, only when needed
    }
    return out.poll();
  }

  public static void main(String[] args) {
    TwoStackQueue q = new TwoStackQueue();
    q.offer(101); q.offer(102); q.offer(103);
    System.out.print(q.poll() + " ");
    q.offer(104);
    System.out.print(q.poll() + " " + q.poll() + " " + q.poll() + " ");
    System.out.println(q.poll());
  }
}
```

```text [Output]
101 102 103 104 null
```

### Complexity

| Operation | `ArrayDeque` | Circular array queue | Two-stack queue |
| --- | --- | --- | --- |
| offer | O(1) amortised | O(1) | O(1) |
| poll | O(1) | O(1) | O(1) **amortised**, O(n) worst single call |
| peek | O(1) | O(1) | O(1) amortised |
| Space | O(n) | O(capacity) | O(n) |

The two-stack queue is amortised O(1) because each element is moved from `in`
to `out` exactly once in its life, however many polls happen.

## Real use case

::real-life{title="Why background work is always a queue" source="Any system that sends email"}
Publishing semester results emails 40,000 students. Doing it inside the web
request means the registrar's browser waits four minutes and times out. So the
request writes 40,000 jobs into a queue and returns immediately, and a worker
takes them one at a time. Everything that follows, retries, rate limits,
seeing how far along it is, resuming after a crash, is possible because the
work is a queue. It is the most common architectural pattern you will meet.
::

A **priority queue** is the useful variant: not first in first out, but most
important out first. Java's `PriorityQueue` is a heap underneath, and it has
its own lesson at the end of the next chapter.

## What confuses people here

- **`add` and `offer` look identical.** On an unbounded `ArrayDeque` they
  behave the same. The difference shows on a bounded queue (`add` throws,
  `offer` returns `false`), and on empty queues for `remove` versus `poll`.
- **Using `LinkedList` as a queue.** It works, it is slower than `ArrayDeque`
  because of the cache, and it allows `null`, which makes `poll` returning
  `null` ambiguous.
- **Full versus empty in a circular queue.** Without a `size` counter, `front
  == rear` means both "empty" and "full". Keep a count, or leave one slot
  permanently unused. Say which you chose.
- **`Deque` method names.** `push`/`pop`/`peek` work at the **front** (stack
  style); `offer`/`poll` add at the back and remove at the front (queue style).
  Mixing them on one `ArrayDeque` gives you neither.

## Interview questions

::accordion
  :::accordion-item{label="Stack versus queue: give a real example of each." icon="i-lucide-message-circle"}
  Stack, LIFO: undo history, the call stack, the back button. Queue, FIFO: the
  fee counter, print jobs, emails waiting to be sent, BFS. Both are usually an
  array underneath; what differs is which end you remove from.
  :::
  :::accordion-item{label="Difference between offer/poll/peek and add/remove/element?" icon="i-lucide-message-circle"}
  Same jobs. The first set returns `false` or `null` on failure; the second set
  throws (`IllegalStateException` on a full bounded queue,
  `NoSuchElementException` on an empty one).
  :::
  :::accordion-item{label="Implement a circular queue. How do you tell full from empty?" icon="i-lucide-message-circle"}
  An array, a `front` index and a `size`. Rear is `(front + size) % capacity`.
  Poll moves `front` with `(front + 1) % capacity`. Full is `size ==
  capacity`, empty is `size == 0`. Without `size`, sacrifice one slot so that
  full is `(rear + 1) % capacity == front`.
  :::
  :::accordion-item{label="Implement a queue using two stacks. What is the complexity?" icon="i-lucide-message-circle"}
  Push onto `in`; to poll, if `out` is empty move everything from `in` to
  `out`, then pop `out`. Each element moves once, so offer and poll are
  amortised O(1), though a single poll can be O(n).
  :::
::
