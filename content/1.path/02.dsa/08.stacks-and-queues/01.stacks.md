Touch only one end of a list and you have a **stack**: the last thing you put
on is the first thing you take off. It sounds like a restriction, and it is.
The restriction is the point, because a great many problems behave exactly that
way, including checking that every bracket you open is closed in the right
order.

## Why this matters in a job

Stacks are everywhere without being named. Every method call you make pushes a
frame on the **call stack** (the Operating Systems track covers it) and every
return pops one; infinite recursion is a stack that never stops growing, which
is exactly what `StackOverflowError` means. Undo in an editor is a stack. The
browser's back button is a stack. In interviews, "balanced parentheses" is one
of the most-asked warm-up problems there is, and "next greater element" is the
problem that tells an interviewer whether you know the **monotonic stack**
pattern.

## A pile of answer sheets

At the end of an exam, the invigilator collects answer sheets into one pile on
the desk. The last sheet handed in sits on top, and when the evaluator starts
checking, the first sheet picked up is that last one. Nobody pulls a sheet out
of the middle of the pile.

That is **LIFO**: last in, first out. A stack has three operations, and all
three are O(1):

## How it works

A stack is an array plus one integer, `top`, which is the index of the top
element. Pushing increments it; popping decrements it. Nothing is ever shifted,
which is why both are O(1).

```java [MarksStack.java]
public class MarksStack {
  private final int[] data;
  private int top = -1;              // index of the top element; -1 means empty

  MarksStack(int capacity) { data = new int[capacity]; }

  void push(int mark) {
    if (top == data.length - 1) throw new IllegalStateException("stack overflow");
    data[++top] = mark;
  }

  int pop() {
    if (top == -1) throw new IllegalStateException("stack underflow");
    return data[top--];
  }

  int peek() {
    if (top == -1) throw new IllegalStateException("stack is empty");
    return data[top];
  }

  boolean isEmpty() { return top == -1; }
  int size() { return top + 1; }

  public static void main(String[] args) {
    MarksStack stack = new MarksStack(3);
    stack.push(78);
    stack.push(64);
    stack.push(91);
    System.out.println("peek: " + stack.peek() + ", size: " + stack.size());
    System.out.println("pop:  " + stack.pop());
    System.out.println("pop:  " + stack.pop());
    stack.push(55);
    System.out.println("pop:  " + stack.pop());
    System.out.println("pop:  " + stack.pop());
    System.out.println("empty? " + stack.isEmpty());
    try {
      stack.pop();
    } catch (IllegalStateException e) {
      System.out.println("error: " + e.getMessage());
    }
  }
}
```

```text [Output]
peek: 91, size: 3
pop:  91
pop:  64
pop:  55
pop:  78
empty? true
error: stack underflow
```

Two words to know: **overflow** is pushing onto a full stack, **underflow** is
popping an empty one. `data[++top]` increments first and then writes;
`data[top--]` reads first and then decrements. Mixing those two up is the most
common bug in this implementation.

You could equally build a stack on the linked list from the last chapter:
`push` is `addFirst`, `pop` removes the head. No capacity limit, one node per
item.

### The one to use in real Java

```java
Deque<Integer> stack = new ArrayDeque<>();
stack.push(78);          // top
stack.peek();            // 78
stack.pop();             // 78
```

::warning{icon="i-lucide-alert-triangle"}
Java has a class literally called `Stack`. Do not use it. It extends `Vector`,
so every method is synchronised, and you pay for thread safety you almost
never need. It also exposes indexed access (`get(i)`), which breaks the
restriction that makes a stack useful. The Java documentation itself recommends
`Deque`. Saying "`ArrayDeque`, not `Stack`, and here is why" in an interview is
a small, real signal.
::

### Problem 1: balanced brackets

Push every opening bracket. On a closing bracket, pop and check it is the
matching opener. At the end, the stack must be empty.

```java [Brackets.java]
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.Map;

public class Brackets {
  static boolean isBalanced(String text) {
    Deque<Character> open = new ArrayDeque<>();
    Map<Character, Character> pairs = Map.of(')', '(', ']', '[', '}', '{');

    for (char c : text.toCharArray()) {
      if (c == '(' || c == '[' || c == '{') {
        open.push(c);
      } else if (pairs.containsKey(c)) {
        if (open.isEmpty() || open.pop() != pairs.get(c)) {
          return false;                       // wrong closer, or nothing open
        }
      }
    }
    return open.isEmpty();                    // anything left open is unbalanced
  }

  public static void main(String[] args) {
    String[] timetable = { "{CSE[201](Mon)}", "{CSE[201)(Mon]}", "{CSE[201](Mon)", ")CSE(" };
    for (String t : timetable) {
      System.out.printf("%-18s -> %b%n", t, isBalanced(t));
    }
  }
}
```

```text [Output]
{CSE[201](Mon)}    -> true
{CSE[201)(Mon]}    -> false
{CSE[201](Mon)     -> false
)CSE(              -> false
```

The last two cases are the ones candidates miss. The third has every closer
matched, but a `{` is never closed, so returning `true` as soon as the loop
ends would be wrong. The fourth starts with a closer, so popping an empty stack
must be checked before it throws.

### Problem 2: next greater element

For each day's attendance in a lecture, find the next day with **higher**
attendance. The brute force checks every later day for every day: O(n²).

The stack version keeps the indexes of days still **waiting** for an answer.
When a bigger day arrives, it answers every waiting day that is smaller than
it, popping them off. The stack is always in decreasing order from bottom to
top, which is why it is called a **monotonic stack**.

```java [NextGreater.java]
import java.util.ArrayDeque;
import java.util.Arrays;
import java.util.Deque;

public class NextGreater {
  // For each day's attendance, the next day with HIGHER attendance, or -1.
  static int[] nextGreater(int[] attendance) {
    int[] answer = new int[attendance.length];
    Arrays.fill(answer, -1);
    Deque<Integer> waiting = new ArrayDeque<>();     // indexes still waiting for an answer

    for (int i = 0; i < attendance.length; i++) {
      while (!waiting.isEmpty() && attendance[waiting.peek()] < attendance[i]) {
        answer[waiting.pop()] = attendance[i];       // today answers them
      }
      waiting.push(i);
    }
    return answer;
  }

  public static void main(String[] args) {
    int[] attendance = { 42, 38, 51, 47, 45, 60, 33 };
    System.out.println("attendance:   " + Arrays.toString(attendance));
    System.out.println("next greater: " + Arrays.toString(nextGreater(attendance)));
  }
}
```

```text [Output]
attendance:   [42, 38, 51, 47, 45, 60, 33]
next greater: [51, 51, 60, 60, 60, -1, -1]
```

Walk it once by hand: 42 waits; 38 waits on top of it; 51 arrives and answers
both; 47 and 45 wait; 60 answers 45, 47 and 51; 33 waits. At the end, 60 and
33 are still waiting and keep their `-1`.

### Complexity

| | Time | Space |
| --- | --- | --- |
| push, pop, peek | O(1) | |
| Balanced brackets | O(n) | O(n) in the worst case (all openers) |
| Next greater, brute force | O(n²) | O(1) |
| Next greater, monotonic stack | **O(n)** | O(n) |

The monotonic stack is O(n) even though there is a `while` inside a `for`,
because every index is pushed exactly once and popped at most once. Counting
the total pushes and pops, rather than multiplying the loops, is the argument
interviewers want to hear.

## Real use case

::real-life{title="Undo, in any form" source="Every editor and admin screen"}
A marks-entry screen lets the lecturer undo. Every change (set Riya's mark to
78, set Karan's to 64) is pushed onto an undo stack. Undo pops the latest
change and reverses it. Redo is a second stack: undoing pushes the change onto
it, redoing pops it back. And the rule everybody forgets until they build it:
**a new change clears the redo stack**, because the future you could have
redone into no longer exists.
::

Compilers and IDEs use the bracket check to underline the unclosed `{` in your
code. Expression evaluators (a calculator, or a spreadsheet formula like
`=(A1+B1)*C1`) use two stacks, one for numbers and one for operators.

## What confuses people here

- **Stack the structure versus the call stack.** Same idea, different things.
  The call stack is the JVM's memory for method calls; your `ArrayDeque` lives
  on the heap. Recursion uses the call stack as a free stack, which is why any
  recursive depth-first algorithm can be rewritten with an explicit
  `ArrayDeque`.
- **`pop` on an empty `ArrayDeque`** throws `NoSuchElementException`. `poll`
  returns `null` instead. Check `isEmpty()` first.
- **Pushing values when you need indexes.** In next greater element, push the
  index, not the attendance. With the index you can both read the value and
  write the answer into the right slot.
- **Nested loop means O(n²).** Not always. Count how many times each element
  can be touched in total.

## Interview questions

::accordion
  :::accordion-item{label="Why ArrayDeque rather than Stack in Java?" icon="i-lucide-message-circle"}
  `Stack` extends `Vector`: synchronised methods you do not need, and indexed
  access that breaks the abstraction. `ArrayDeque` is unsynchronised, backed by
  a resizable array, O(1) at both ends, and the documentation recommends it.
  :::
  :::accordion-item{label="Check whether a string of brackets is balanced." icon="i-lucide-message-circle"}
  Push openers; on a closer, fail if the stack is empty or the popped opener
  does not match; at the end return `stack.isEmpty()`. Name both edge cases
  aloud: a closer with nothing open, and openers left over at the end.
  :::
  :::accordion-item{label="Implement a stack using an array. What happens when it is full?" icon="i-lucide-message-circle"}
  An array and a `top` index starting at -1. When full, either throw (a bounded
  stack) or allocate an array twice the size and copy, which makes push
  amortised O(1). That second answer is exactly how `ArrayDeque` grows.
  :::
  :::accordion-item{label="Design a stack that returns the minimum in O(1)." icon="i-lucide-message-circle"}
  Keep a second stack of minimums. On push, push `min(value, currentMin)` onto
  it too; on pop, pop both. The top of the second stack is always the minimum
  of everything currently in the first.

  ```java
  void push(int mark) {
    marks.push(mark);
    mins.push(mins.isEmpty() ? mark : Math.min(mark, mins.peek()));
  }
  int pop()    { mins.pop(); return marks.pop(); }
  int getMin() { return mins.peek(); }
  ```
  :::
  :::accordion-item{label="Why is next greater element O(n) with a nested loop?" icon="i-lucide-message-circle"}
  Each index is pushed once and popped at most once, so the inner `while` runs
  at most n times across the whole run, not n times per outer iteration. Total
  work is at most 2n operations.
  :::
::
