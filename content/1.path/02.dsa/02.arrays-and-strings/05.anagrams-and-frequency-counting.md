The counting trick is this: make an array of 26 zeros, one per letter, walk the
string, and add one to the slot for each letter you see. Two strings are
anagrams exactly when their 26 counts are identical. The same array answers
"most frequent letter", "first letter that appears once" and a long list of
other questions.

## Why this matters in a job

Because "check whether two strings are anagrams" is one of the most repeated
string questions in fresher tests, and because frequency counting is the core
of problems you will meet all through this track: sliding window, hashing,
top-k, and more. At work the same shape counts things all day: enrolments per
course, absences per student, complaints per hostel block.

## A tally sheet

Think of a teacher counting votes for class representative on the blackboard:
one column per candidate, one tick for each vote. At the end she does not
remember the order the votes came in, only the totals. That tally is a
**frequency count**: how many times each value occurred.

**Anagrams** are two words with exactly the same letters in the same quantities,
in any order: "listen" and "silent", "earth" and "heart". Their tally sheets
are identical.

The index of a lowercase letter in the array is `c - 'a'`. Characters in Java
are numbers underneath, so `'a' - 'a'` is 0, `'b' - 'a'` is 1, and `'z' - 'a'`
is 25.

## How it works

### Anagram check, two ways

```java [Anagram.java]
import java.util.Arrays;

public class Anagram {
  // O(n log n): sort both and compare
  static boolean bySorting(String a, String b) {
    if (a.length() != b.length()) return false;
    char[] x = a.toCharArray(), y = b.toCharArray();
    Arrays.sort(x);
    Arrays.sort(y);
    return Arrays.equals(x, y);
  }

  // O(n): one count array, up for a, down for b
  static boolean byCounting(String a, String b) {
    if (a.length() != b.length()) return false;
    int[] count = new int[26];
    for (int i = 0; i < a.length(); i++) {
      count[a.charAt(i) - 'a']++;
      count[b.charAt(i) - 'a']--;
    }
    for (int c : count) {
      if (c != 0) return false;
    }
    return true;
  }

  public static void main(String[] args) {
    System.out.println(bySorting("listen", "silent"));
    System.out.println(byCounting("listen", "silent"));
    System.out.println(byCounting("earth", "heart"));
    System.out.println(byCounting("rat", "car"));
    System.out.println(byCounting("aab", "abb"));
  }
}
```

```text [Output]
true
true
true
false
false
```

The last case, "aab" and "abb", has the same letters but not the same counts.
A solution that only checks "does every letter of a appear in b" says `true`,
and that is the classic wrong answer.

### Most frequent and first non-repeating character

Both come from one counting pass. For the first non-repeating one, the second
pass walks the **string**, not the count array, so "first" means first in the
string.

```java [CharCounts.java]
public class CharCounts {
  static char mostFrequent(String s) {
    int[] count = new int[26];
    for (char c : s.toCharArray()) count[c - 'a']++;
    int best = 0;
    for (int i = 1; i < 26; i++) {
      if (count[i] > count[best]) best = i;
    }
    return (char) ('a' + best);
  }

  static char firstUnique(String s) {
    int[] count = new int[26];
    for (char c : s.toCharArray()) count[c - 'a']++;
    for (char c : s.toCharArray()) {          // walk the string again, in order
      if (count[c - 'a'] == 1) return c;
    }
    return '_';                               // none
  }

  public static void main(String[] args) {
    System.out.println(mostFrequent("mississippi"));
    System.out.println(firstUnique("swarnil"));
    System.out.println(firstUnique("aabbcdc"));
    System.out.println(firstUnique("aabb"));
  }
}
```

```text [Output]
i
s
d
_
```

"mississippi" has four `i` and four `s`. The loop keeps the first of the ties,
`i`, because it only replaces `best` on a strictly larger count. Say which tie
rule you are using; interviewers ask.

### When the characters are not a–z: use a map

Names with capitals, digits in roll numbers, Unicode: the 26-slot trick breaks.
A `HashMap<Character, Integer>` counts anything, at the cost of hashing.

```java [MapCount.java]
import java.util.Map;
import java.util.TreeMap;

public class MapCount {
  public static void main(String[] args) {
    String roll = "2026CSE0184";
    Map<Character, Integer> count = new TreeMap<>();   // sorted keys for printing
    for (char c : roll.toCharArray()) {
      count.merge(c, 1, Integer::sum);                  // add 1, or start at 1
    }
    System.out.println(count);
  }
}
```

```text [Output]
{0=2, 1=1, 2=2, 4=1, 6=1, 8=1, C=1, E=1, S=1}
```

`merge(c, 1, Integer::sum)` means "put 1 if absent, otherwise add 1". It is the
one-line counting idiom in modern Java, and `getOrDefault(c, 0) + 1` is the
older equivalent. A `TreeMap` is used here only so the output is in a
predictable order.

### Group anagrams

Given a list of words, put anagrams together. Sort each word's letters to make
a **key**: every anagram of "listen" has the key "eilnst". Words with the same
key go in the same group.

```java [GroupAnagrams.java]
import java.util.*;

public class GroupAnagrams {
  public static void main(String[] args) {
    String[] words = {"listen", "earth", "silent", "heart", "enlist", "course"};
    Map<String, List<String>> groups = new LinkedHashMap<>();
    for (String w : words) {
      char[] c = w.toCharArray();
      Arrays.sort(c);
      String key = new String(c);
      groups.computeIfAbsent(key, k -> new ArrayList<>()).add(w);
    }
    System.out.println(groups.values());
  }
}
```

```text [Output]
[[listen, silent, enlist], [earth, heart], [course]]
```

### Complexity

| Task | Time | Extra space |
| --- | --- | --- |
| Anagram by sorting | O(n log n) | O(n) for the char arrays |
| Anagram by counting | **O(n)** | **O(1)**, always 26 slots |
| Most frequent, first unique | O(n) | O(1) |
| Counting with a `HashMap` | O(n) average | O(k), k distinct characters |
| Group m words of length up to L | O(m × L log L) | O(m × L) |

An `int[26]` is O(1) space because its size does not grow with the input.

## Real use case

::real-life{title="Seats left per course" source="A counselling round"}
During counselling, a college printed a live board of how many seats were taken
per course. Each allotment added one to its course. The first version searched
a list of allotments and counted each course separately, one pass per course,
for 40 courses on every refresh. The fix was a frequency count: one pass over
the allotments into a `Map<String, Integer>`, updated by one as each new
allotment arrived. It is this lesson's tally sheet with course codes instead of
letters.
::

## What confuses people here

- **Using `int[26]` on mixed-case input.** `'A' - 'a'` is −32, and the array
  index throws. Lower-case first, or use `int[128]` for ASCII, or a map.
- **Checking only that letters exist, not how many.** "aab" and "abb" pass that
  check and are not anagrams.
- **Walking the count array for "first unique".** That finds the
  alphabetically first unique letter, not the first in the string.
- **Iterating a `HashMap` and expecting order.** It has none. Use
  `LinkedHashMap` for insertion order or `TreeMap` for sorted order.

## Interview questions

::accordion
  :::accordion-item{label="Check whether two strings are anagrams in O(n)." icon="i-lucide-message-circle"}
  Compare lengths, then one `int[26]`: increment for the first string, decrement
  for the second, and check every slot is zero. O(n) time, O(1) space. Sorting
  both is simpler to write and O(n log n).
  :::

  :::accordion-item{label="Find the first non-repeating character." icon="i-lucide-message-circle"}
  Count all characters in one pass, then walk the string again and return the
  first character whose count is 1. Two O(n) passes, O(1) space for a fixed
  alphabet. With a `LinkedHashMap` you can walk the map instead, because it
  keeps insertion order.
  :::

  :::accordion-item{label="Why is an int[26] O(1) space?" icon="i-lucide-message-circle"}
  Because its size is fixed by the alphabet, not by the input. A string of
  10 or 10 million characters uses the same 26 counters.
  :::

  :::accordion-item{label="Group a list of words into anagram groups." icon="i-lucide-message-circle"}
  Use the sorted letters (or the 26 counts joined into a string) as a key in a
  `Map<String, List<String>>`, and add each word to its key's list.
  `computeIfAbsent` creates the list the first time. O(m × L log L) with sorted
  keys, O(m × L) with count keys.
  :::

  :::accordion-item{label="Is “Dormitory” an anagram of “dirty room”?" icon="i-lucide-message-circle"}
  Yes, if you ignore case and spaces, which you should ask about. Lower-case
  both, skip anything that is not a letter, then count. Asking the question
  before coding is worth as much as the code.
  :::
::
