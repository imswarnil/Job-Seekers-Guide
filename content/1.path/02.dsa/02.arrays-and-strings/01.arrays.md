The structure almost every algorithm runs on is the array, and the reason it is
fast is physical: its elements sit next to each other in memory. Everything an
array is good at, and everything it is bad at, comes from that one fact.

## Why this matters in a job

Because the first problem in most service-company coding tests is an array
problem: largest, second largest, reverse, rotate, remove duplicates. Because
product-company rounds build almost every pattern (two pointers, sliding
window, prefix sums, binary search) on top of arrays. And because at work, the
`ArrayList` is the collection you will use more than all the others put
together.

## An array is a row of lockers

Picture the lockers in a college corridor: numbered 0, 1, 2 and so on, all the
same size, side by side. To reach locker 4 you do not open lockers 0 to 3. You
walk to the start and count four lockers along.

An **array** is the same. A fixed number of elements of one type, stored
**contiguously** (next to each other, with no gaps), each one reached by its
**index**, starting at 0.

Because every element is the same size and they are adjacent, the machine finds
element 4 with one multiplication and one addition: `start + 4 × size`. That is
why **access by index is O(1)** and does not slow down as the array grows.

The cost is the other side of the same fact: there is no gap to insert into.

| Operation | Array / `ArrayList` | Why |
| --- | --- | --- |
| Read or write `a[i]` | **O(1)** | Arithmetic on the address |
| Traverse every element | O(n) | Visit each once |
| Search for a value (unsorted) | O(n) | Nothing tells you where it is |
| Add at the end (`ArrayList`) | O(1) amortised | Occasionally grows and copies |
| Insert or delete in the middle | O(n) | Everything after it shifts |

## How it works

The warm-up problems every test starts with, in one program: total, average,
largest, and the second largest distinct mark.

```java [MarksStats.java]
public class MarksStats {
  public static void main(String[] args) {
    int[] marks = {78, 64, 81, 55, 92, 70, 92};

    int total = 0;
    int largest = Integer.MIN_VALUE;
    int second = Integer.MIN_VALUE;

    for (int mark : marks) {
      total += mark;
      if (mark > largest) {
        second = largest;          // the old largest becomes second
        largest = mark;
      } else if (mark > second && mark != largest) {
        second = mark;
      }
    }

    double average = (double) total / marks.length;
    System.out.println("Total: " + total);
    System.out.printf("Average: %.2f%n", average);
    System.out.println("Largest: " + largest);
    System.out.println("Second largest: " + second);
  }
}
```

```text [Output]
Total: 532
Average: 76.00
Largest: 92
Second largest: 81
```

One pass, O(n) time, O(1) space. Two details are the ones interviewers watch:
starting from `Integer.MIN_VALUE` rather than 0 (so all-negative input works),
and `(double) total` before dividing, so the average is not cut down to an
integer.

### Reversing and rotating in place

Rotating the seating order of a row of students by k places to the right is a
classic. The neat O(1)-space answer is three reversals.

```java [Rotate.java]
import java.util.Arrays;

public class Rotate {
  static void reverse(int[] a, int left, int right) {
    while (left < right) {
      int temp = a[left];
      a[left] = a[right];
      a[right] = temp;
      left++;
      right--;
    }
  }

  static void rotateRight(int[] a, int k) {
    int n = a.length;
    k = k % n;                     // rotating by n is no rotation at all
    reverse(a, 0, n - 1);          // reverse the whole array
    reverse(a, 0, k - 1);          // reverse the first k
    reverse(a, k, n - 1);          // reverse the rest
  }

  public static void main(String[] args) {
    int[] rolls = {101, 102, 103, 104, 105, 106, 107};
    rotateRight(rolls, 3);
    System.out.println(Arrays.toString(rolls));

    int[] again = {101, 102, 103, 104, 105, 106, 107};
    rotateRight(again, 10);        // 10 % 7 = 3, same result
    System.out.println(Arrays.toString(again));
  }
}
```

```text [Output]
[105, 106, 107, 101, 102, 103, 104]
[105, 106, 107, 101, 102, 103, 104]
```

### Complexity

| Task | Time | Extra space |
| --- | --- | --- |
| Total, average, largest, second largest | O(n) | O(1) |
| Reverse in place | O(n) | O(1) |
| Rotate by k with three reversals | O(n) | O(1) |
| Rotate by k with a second array | O(n) | O(n) |
| Rotate by one, k times | O(n × k) | O(1) |

## `ArrayList`: an array that grows

A Java array has a fixed length. `ArrayList` wraps one and, when it is full,
allocates a new array 1.5 times larger and copies everything across. Most
`add` calls are O(1); the occasional one is O(n), and averaged across all of
them it works out to O(1), which is what **amortised** means.

```java [Growth.java]
import java.util.ArrayList;
import java.util.List;

public class Growth {
  public static void main(String[] args) {
    List<Integer> rolls = new ArrayList<>(40_000);   // capacity hint: no copies
    for (int i = 0; i < 5; i++) rolls.add(2026_0000 + i);

    rolls.add(2, 99);                                // O(n): shifts the rest
    System.out.println(rolls);
    System.out.println("rolls.get(3) = " + rolls.get(3));   // O(1)
    System.out.println("size = " + rolls.size());
  }
}
```

```text [Output]
[20260000, 20260001, 99, 20260002, 20260003, 20260004]
rolls.get(3) = 20260002
size = 6
```

::side-note{kind="performance"}
Arrays are fast twice over. O(1) access is the first reason. The second is the
processor cache: memory is read in blocks of about 64 bytes, so reading one
`int` brings the next fifteen along for free. Walking an array is mostly cache
hits. This is why an `ArrayList` usually beats structures with a better Big-O on
paper, which comes up again in the linked lists chapter.
::

## Real use case

::real-life{title="Attendance for a lecture" source="Any college attendance module"}
A lecture with 60 students is stored as a `boolean[] present = new boolean[60]`,
indexed by the student's position in the class list. Marking student 17 present
is `present[17] = true`, O(1). Counting attendance is one pass. The whole
lecture fits in 60 bytes and a report across 90 lectures is a 90 × 60 array
walked row by row. No map, no objects, and it is the fastest version possible
because the data is contiguous.
::

## What confuses people here

- **`length` versus `size()`.** Arrays have a field, `marks.length`. Lists have
  a method, `list.size()`. Strings have a method, `name.length()`.
- **Off by one.** The last index is `length - 1`. `for (int i = 0; i <= n; i++)`
  throws `ArrayIndexOutOfBoundsException` on the last step.
- **Starting max at 0.** Fine for marks, wrong for temperatures or profit and
  loss. Start at `Integer.MIN_VALUE` or at `a[0]`.
- **Rotating by k larger than n.** Without `k % n`, rotating 7 elements by 10
  reads past the end.
- **Printing an array.** `System.out.println(marks)` prints something like
  `[I@1b6d3586`. Use `Arrays.toString(marks)`.

## Interview questions

::accordion
  :::accordion-item{label="Find the second largest element in one pass." icon="i-lucide-message-circle"}
  Track `largest` and `second`. When a new value beats `largest`, the old
  largest moves to `second`. Otherwise, if it beats `second` and is not equal
  to `largest`, it becomes `second`. O(n) time, O(1) space. Sorting first works
  but is O(n log n) and gets duplicates wrong unless you are careful.
  :::

  :::accordion-item{label="Why is array access O(1)?" icon="i-lucide-message-circle"}
  Elements are the same size and stored contiguously, so the address of `a[i]`
  is `base + i × elementSize`, computed in one step without looking at any
  other element.
  :::

  :::accordion-item{label="Rotate an array by k in O(1) extra space." icon="i-lucide-message-circle"}
  Reduce k with `k % n`, then reverse the whole array, reverse the first k,
  reverse the remaining n − k. Three O(n) passes, no extra array. The program
  above is the full answer.
  :::

  :::accordion-item{label="Array versus ArrayList?" icon="i-lucide-message-circle"}
  An array has a fixed length, can hold primitives directly (`int[]`), and has
  no methods beyond `length`. An `ArrayList` grows automatically, holds objects
  only (so `Integer`, with boxing), and has `add`, `remove`, `contains`. Use an
  array when the size is known and performance matters; an `ArrayList` almost
  everywhere else.
  :::

  :::accordion-item{label="Move all zeros to the end, keeping the order of the rest." icon="i-lucide-message-circle"}
  Keep a write index. Copy every non-zero forward, then fill the tail with
  zeros. O(n), O(1).

  ```java
  int write = 0;
  for (int mark : marks) if (mark != 0) marks[write++] = mark;
  while (write < marks.length) marks[write++] = 0;
  ```
  :::
::
