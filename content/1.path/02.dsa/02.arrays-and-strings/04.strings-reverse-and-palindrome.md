A Java `String` is **immutable**: once it is made, no method changes it. Every
method that looks like it changes a string, `toUpperCase`, `replace`, `+`,
returns a new one and leaves the old one untouched. That rule decides how you
write every string algorithm in Java.

## Why this matters in a job

Because string questions are the other half of the first coding problem in
service-company tests: reverse a name, check a palindrome, count vowels, reverse
the words of a sentence. Because product companies build harder problems
(anagrams, longest palindromic substring, sliding window on characters) on the
same tools. And because the wrong way to build a string in a loop is one of the
most common slow-code bugs in real Java.

## A printed certificate

Think of a printed degree certificate. If the name is spelt wrong, nobody edits
the paper. The office prints a new certificate and the old one is thrown away.
A Java `String` works the same way: "changing" it means making a new one.

To work on the characters themselves, you use one of two editable tools:

| Tool | What it is | When to use it |
| --- | --- | --- |
| `char[]` | A plain array of characters, from `name.toCharArray()` | Swapping, sorting, counting, in-place algorithms |
| `StringBuilder` | A growable, editable buffer of characters | Building a result piece by piece |
| `String` | Immutable text | Reading, comparing, returning |

::warning{icon="i-lucide-alert-triangle"}
`result = result + c` inside a loop creates a new string and copies everything
built so far, every time. For a string of length n that is 1 + 2 + … + n
copies, O(n²). A `StringBuilder` appends in amortised O(1), so the same loop is
O(n).
::

## How it works

### Reverse a string

Three versions. The first is what most people write; the second is the fix; the
third is the two-pointer version interviewers like, because it works in place
on a character array.

```java [ReverseName.java]
public class ReverseName {
  static String reverseSlow(String s) {
    String result = "";
    for (int i = s.length() - 1; i >= 0; i--) {
      result += s.charAt(i);            // new String every iteration: O(n²)
    }
    return result;
  }

  static String reverseBuilder(String s) {
    StringBuilder sb = new StringBuilder(s.length());
    for (int i = s.length() - 1; i >= 0; i--) {
      sb.append(s.charAt(i));           // amortised O(1)
    }
    return sb.toString();
  }

  static String reverseTwoPointers(String s) {
    char[] c = s.toCharArray();
    int left = 0, right = c.length - 1;
    while (left < right) {
      char temp = c[left];
      c[left] = c[right];
      c[right] = temp;
      left++;
      right--;
    }
    return new String(c);
  }

  public static void main(String[] args) {
    String name = "Ananya Sharma";
    System.out.println(reverseSlow(name));
    System.out.println(reverseBuilder(name));
    System.out.println(reverseTwoPointers(name));
    System.out.println(new StringBuilder(name).reverse());
  }
}
```

```text [Output]
amrahS aynanA
amrahS aynanA
amrahS aynanA
amrahS aynanA
```

The last line is the library version, `StringBuilder.reverse()`. In an
interview, say it exists, then write one of the others, because the question is
testing whether you can.

### Reverse the words of a sentence

"Department of Computer Science" becomes "Science Computer of Department".
Split on spaces, then walk the words backwards.

```java [ReverseWords.java]
public class ReverseWords {
  static String reverseWords(String sentence) {
    String[] words = sentence.trim().split("\\s+");   // one or more spaces
    StringBuilder sb = new StringBuilder();
    for (int i = words.length - 1; i >= 0; i--) {
      sb.append(words[i]);
      if (i > 0) sb.append(' ');
    }
    return sb.toString();
  }

  public static void main(String[] args) {
    System.out.println(reverseWords("Department of Computer Science"));
    System.out.println("[" + reverseWords("   LNCT    Bhopal  ") + "]");
  }
}
```

```text [Output]
Science Computer of Department
[Bhopal LNCT]
```

The second call is the test case that catches people: leading, trailing and
repeated spaces. `trim()` removes the ends and the regular expression `\\s+`
treats any run of spaces as one separator.

## Palindromes

A **palindrome** reads the same forwards and backwards: "madam", "racecar",
roll number "12321". The efficient check never builds a reversed copy. Two
pointers start at the ends and walk inwards, comparing as they go.

The follow-up is always the same: "ignore case, spaces and punctuation". Skip
anything that is not a letter or digit, and compare lower-cased characters.

```java [Palindrome.java]
public class Palindrome {
  static boolean isPalindrome(String s) {
    int left = 0, right = s.length() - 1;
    while (left < right) {
      if (s.charAt(left) != s.charAt(right)) return false;
      left++;
      right--;
    }
    return true;
  }

  static boolean isPalindromeLoose(String s) {
    int left = 0, right = s.length() - 1;
    while (left < right) {
      char a = s.charAt(left), b = s.charAt(right);
      if (!Character.isLetterOrDigit(a)) { left++; continue; }
      if (!Character.isLetterOrDigit(b)) { right--; continue; }
      if (Character.toLowerCase(a) != Character.toLowerCase(b)) return false;
      left++;
      right--;
    }
    return true;
  }

  public static void main(String[] args) {
    System.out.println(isPalindrome("racecar"));
    System.out.println(isPalindrome("12321"));
    System.out.println(isPalindrome("Madam"));
    System.out.println(isPalindromeLoose("Madam"));
    System.out.println(isPalindromeLoose("Was it a car or a cat I saw?"));
    System.out.println(isPalindromeLoose("LNCT Bhopal"));
  }
}
```

```text [Output]
true
true
false
true
true
false
```

"Madam" fails the strict check because `M` and `m` are different characters.
That is the case to mention before the interviewer does.

### Complexity

| Task | Time | Extra space |
| --- | --- | --- |
| Reverse with `+=` in a loop | O(n²) | O(n) per copy |
| Reverse with `StringBuilder` or a `char[]` | O(n) | O(n), the result itself |
| Reverse the words | O(n) | O(n) |
| Palindrome with two pointers | O(n) | **O(1)** |
| Palindrome by comparing with a reversed copy | O(n) | O(n) |

## Real use case

::real-life{title="Cleaning up student names before matching" source="An admissions data import"}
An admissions office merged applications from two portals. The same student
appeared as "Ananya  Sharma", "ananya sharma" and " Ananya Sharma ". Matching
them needed exactly the tools in this lesson: `trim()`, collapsing repeated
spaces with `split("\\s+")` and a `StringBuilder`, and comparing
case-insensitively. The first version built the cleaned names with `+=` in a
loop over 80,000 rows and took minutes; switching to `StringBuilder` made it a
couple of seconds.
::

## What confuses people here

- **`==` versus `equals`.** `==` compares whether two references point to the
  same object; `equals` compares the characters. Always use `equals` for
  content, and `equalsIgnoreCase` when case should not matter.
- **Thinking `s.toUpperCase()` changes `s`.** It returns a new string. Without
  `s = s.toUpperCase()`, nothing happened.
- **`charAt` returns a `char`, not a `String`.** `'a'` and `"a"` are different
  types. `s.charAt(0) == 'a'` is correct; `s.charAt(0).equals("a")` does not
  compile.
- **`split(" ")` on multiple spaces** produces empty strings in the array. Use
  `split("\\s+")` after `trim()`.

## Interview questions

::accordion
  :::accordion-item{label="Why are Strings immutable in Java?" icon="i-lucide-message-circle"}
  Safety and sharing. The same string literal can be shared from the string
  pool by every part of a program, which is only safe if nobody can change it.
  Immutable strings are also thread-safe without locking, and their hash code
  can be cached, which makes them good `HashMap` keys. The cost is that every
  "modification" creates a new object.
  :::

  :::accordion-item{label="String, StringBuilder, StringBuffer: what is the difference?" icon="i-lucide-message-circle"}
  `String` is immutable. `StringBuilder` is mutable and not synchronised, so it
  is the fast choice in single-threaded code, which is nearly all code.
  `StringBuffer` is the older mutable version with every method synchronised,
  slower, and rarely needed today.
  :::

  :::accordion-item{label="Check whether a string is a palindrome without extra space." icon="i-lucide-message-circle"}
  Two indices from both ends moving inwards, returning false on the first
  mismatch. O(n) time, O(1) space. Then offer the version that skips
  non-alphanumeric characters and ignores case.
  :::

  :::accordion-item{label="Reverse the words in a sentence with irregular spaces." icon="i-lucide-message-circle"}
  `trim()`, `split("\\s+")`, then append the words from last to first with
  single spaces into a `StringBuilder`. O(n). The in-place version on a
  `char[]` is: reverse the whole array, then reverse each word.
  :::

  :::accordion-item{label="Count the vowels in a student's name." icon="i-lucide-message-circle"}
  ```java
  int count = 0;
  for (char c : name.toLowerCase().toCharArray()) {
    if ("aeiou".indexOf(c) >= 0) count++;
  }
  ```
  O(n). `indexOf` on a five-character string is a constant cost.
  :::
::
