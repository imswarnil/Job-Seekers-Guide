The extra array is called a **prefix sum**: at each position it stores the
total of everything up to that point. Build it once in O(n), and the total of
any range, roll 10 to roll 40 or roll 3 to roll 3,000, is a single subtraction.

## Why this matters in a job

Because dashboards, reports and analytics ask range questions all day: total
fees collected between two dates, attendance between week 3 and week 9, marks
from one roll number to another. And because in interviews, prefix sums are the
hidden step inside "subarray sum equals k", "equilibrium index", "range sum
query" and a long list of medium problems that look unrelated until you see it.

## Running totals on a scorecard

Think of a cricket scorecard that prints the team total after every over. If
you want to know how many runs were scored in overs 11 to 20, you do not add up
ten overs. You take the total after over 20 and subtract the total after over
10. That subtraction is the whole trick.

For an array `a`, define `prefix[i]` as the sum of the first `i` elements. So
`prefix[0] = 0` and `prefix[i + 1] = prefix[i] + a[i]`. Then the sum of
`a[left..right]` inclusive is:

::pull-quote
sum(left, right) = prefix[right + 1] − prefix[left]
::

Making `prefix` one longer than the input, with a 0 at the front, removes the
special case for ranges that start at index 0. It is the version to memorise.

## How it works

Attendance counts for ten lectures, and several range questions about them.

```java [RangeSum.java]
public class RangeSum {
  static int[] buildPrefix(int[] a) {
    int[] prefix = new int[a.length + 1];
    for (int i = 0; i < a.length; i++) {
      prefix[i + 1] = prefix[i] + a[i];
    }
    return prefix;
  }

  static int rangeSum(int[] prefix, int left, int right) {
    return prefix[right + 1] - prefix[left];
  }

  public static void main(String[] args) {
    int[] present = {52, 48, 55, 60, 41, 38, 57, 59, 50, 44};
    int[] prefix = buildPrefix(present);

    System.out.println("Lectures 0-9: " + rangeSum(prefix, 0, 9));
    System.out.println("Lectures 2-5: " + rangeSum(prefix, 2, 5));
    System.out.println("Lecture 7 only: " + rangeSum(prefix, 7, 7));
  }
}
```

```text [Output]
Lectures 0-9: 504
Lectures 2-5: 194
Lecture 7 only: 59
```

### Complexity

| Approach | Build | Each query | q queries on n elements |
| --- | --- | --- | --- |
| Loop over the range every time | none | O(n) | O(n × q) |
| Prefix sums | O(n) time, O(n) space | **O(1)** | **O(n + q)** |

With n = 10⁵ and q = 10⁵, that is 10¹⁰ operations against 2 × 10⁵. The first
times out; the second finishes before you blink.

## The equilibrium index

A common test question: find an index where the sum of everything to its left
equals the sum of everything to its right. Think of seating a class on two
benches so both benches carry the same total marks, with one student standing
in the middle.

With the total known, the right side is `total − leftSum − a[i]`. One pass.

```java [Equilibrium.java]
public class Equilibrium {
  static int equilibriumIndex(int[] a) {
    int total = 0;
    for (int x : a) total += x;

    int leftSum = 0;
    for (int i = 0; i < a.length; i++) {
      int rightSum = total - leftSum - a[i];
      if (leftSum == rightSum) return i;
      leftSum += a[i];
    }
    return -1;
  }

  public static void main(String[] args) {
    System.out.println(equilibriumIndex(new int[]{3, 4, 8, 1, 6}));
    System.out.println(equilibriumIndex(new int[]{1, 2, 3}));
  }
}
```

```text [Output]
2
-1
```

For `{3, 4, 8, 1, 6}`: left of index 2 is 3 + 4 = 7, right is 1 + 6 = 7. That
is O(n) time and O(1) space, because a running sum is a prefix sum you do not
store.

## Prefix sums in two dimensions

The same idea works on a grid: marks of students (rows) in subjects (columns).
`prefix[r][c]` stores the total of the rectangle from the top-left corner to
`(r − 1, c − 1)`. Any rectangle's total is then four lookups. You will not need
to write this in most service-company tests, but "range sum query 2D" is a
known medium problem, and it is the same subtraction with one more term.

```java [Grid.java]
public class Grid {
  public static void main(String[] args) {
    int[][] marks = {
      {70, 80, 65},
      {90, 85, 75},
      {60, 70, 95}
    };
    int rows = marks.length, cols = marks[0].length;
    int[][] p = new int[rows + 1][cols + 1];
    for (int r = 0; r < rows; r++)
      for (int c = 0; c < cols; c++)
        p[r + 1][c + 1] = marks[r][c] + p[r][c + 1] + p[r + 1][c] - p[r][c];

    // Students 1-2, subjects 1-2
    int r1 = 1, c1 = 1, r2 = 2, c2 = 2;
    int sum = p[r2 + 1][c2 + 1] - p[r1][c2 + 1] - p[r2 + 1][c1] + p[r1][c1];
    System.out.println("Rectangle total: " + sum);
  }
}
```

```text [Output]
Rectangle total: 325
```

That is 85 + 75 + 70 + 95 = 325, read from the table in four lookups.

## Real use case

::real-life{title="The fee collection report" source="A college accounts office"}
The accounts team wanted "total fees collected between any two dates this year"
on a dashboard with a date picker. The first version summed the day-wise rows
on every change of the picker. Storing a cumulative total per day, once a
night, turned every query into a subtraction of two numbers. It is the same
reason databases and spreadsheets keep running totals: the question is asked
far more often than the data changes.
::

## What confuses people here

- **Off by one in the formula.** With a prefix one longer than the input, it is
  `prefix[right + 1] − prefix[left]`. Draw the two arrays before you write it.
- **Overflow.** Summing 10⁵ values of up to 10⁹ overflows `int`. Use a
  `long[]` for the prefix when the constraints say values are large.
- **Using it when the data changes.** If a value is updated, every prefix after
  it changes, which is O(n) per update. For many updates and many queries, the
  answer is a Fenwick tree or a segment tree, which is beyond most fresher
  rounds but worth naming.

## Interview questions

::accordion
  :::accordion-item{label="Answer q range-sum queries on an array of n in better than O(n × q)." icon="i-lucide-message-circle"}
  Build a prefix array once in O(n); each query is `prefix[r + 1] − prefix[l]`
  in O(1). Total O(n + q) time, O(n) extra space.
  :::

  :::accordion-item{label="Find the equilibrium index." icon="i-lucide-message-circle"}
  Compute the total, then walk left to right keeping `leftSum`. At each `i`,
  the right sum is `total − leftSum − a[i]`. Return the first `i` where they are
  equal. O(n), O(1).
  :::

  :::accordion-item{label="Count subarrays whose sum equals k." icon="i-lucide-message-circle"}
  A subarray `a[i..j]` sums to k exactly when `prefix[j + 1] − prefix[i] = k`,
  that is, when an earlier prefix equals `current − k`. Keep a `HashMap` of how
  many times each prefix value has been seen:

  ```java
  Map<Integer, Integer> seen = new HashMap<>();
  seen.put(0, 1);
  int sum = 0, count = 0;
  for (int x : a) {
    sum += x;
    count += seen.getOrDefault(sum - k, 0);
    seen.merge(sum, 1, Integer::sum);
  }
  ```

  O(n) time, O(n) space. This works with negative numbers, where a sliding
  window does not. It comes back in the hashing lesson.
  :::

  :::accordion-item{label="Product of the array except self, without division." icon="i-lucide-message-circle"}
  The same idea with multiplication: a prefix product from the left and a
  suffix product from the right. `answer[i] = prefixProduct[i] ×
  suffixProduct[i + 1]`. O(n) time, and O(1) extra if you fill the answer array
  from the left and then multiply in a running suffix from the right.
  :::
::
