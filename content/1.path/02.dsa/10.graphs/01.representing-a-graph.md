A **graph** is a set of things and the connections between them, with no rules
about shape. A tree is a graph with strict rules (one parent each, no loops).
Take the rules away and you can describe a campus map, a friendship network or
the prerequisites between courses, all with the same two ideas.

## Why this matters in a job

Graphs are the model behind maps and routing, social networks, recommendation
("students who took DBMS also took…"), dependency managers such as Maven
resolving which library needs which, and build tools deciding what to compile
first. In interviews, graph questions are where product companies separate
candidates. They are rarely hard once the graph is stored well, and very hard
when it is not, so this lesson is only about storage.

## Places and paths

Look at a campus map. The **vertices** (also called **nodes**) are the places:
the gate, the library, the canteen, the CSE block, the hostel. The **edges**
are the paths between them. That is all a graph is.

Graphs come in a few flavours, and the question usually tells you which:

| Kind | Meaning | Example |
| --- | --- | --- |
| **Undirected** | An edge works both ways | A footpath between library and canteen |
| **Directed** | An edge has a direction, from → to | "Java must come before DSA" |
| **Weighted** | Each edge carries a number | The path is 400 metres long |
| **Unweighted** | Every edge counts the same | Only "connected or not" matters |
| **Cyclic / acyclic** | Whether you can walk in a loop back to the start | A directed acyclic graph (**DAG**) is what prerequisites must be |

Two more words: the **degree** of a vertex is how many edges touch it; in a
directed graph, **in-degree** counts arrows coming in and **out-degree** arrows
going out.

## How it works

Number the vertices 0 to n − 1 (keep a `String[]` for the names) and choose one
of two storages.

**Adjacency matrix:** an n × n grid of booleans (or weights). `matrix[i][j]` is
true when there is an edge from i to j. Instant to check one edge, but it uses
n² cells even when most are empty.

**Adjacency list:** for each vertex, a list of its neighbours. In Java, a
`List<List<Integer>>`. Uses space only for edges that exist.

```java [CampusGraph.java]
import java.util.ArrayList;
import java.util.List;

public class CampusGraph {
  public static void main(String[] args) {
    String[] place = { "Gate", "Library", "Canteen", "CSE Block", "Hostel" };
    int[][] paths = { {0, 1}, {0, 2}, {1, 3}, {2, 3}, {3, 4} };
    int n = place.length;

    // 1. Adjacency matrix: n x n booleans.
    boolean[][] matrix = new boolean[n][n];
    for (int[] p : paths) {
      matrix[p[0]][p[1]] = true;
      matrix[p[1]][p[0]] = true;        // undirected: both ways
    }

    // 2. Adjacency list: one list of neighbours per vertex.
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    for (int[] p : paths) {
      adj.get(p[0]).add(p[1]);
      adj.get(p[1]).add(p[0]);
    }

    System.out.println("Matrix:");
    for (int i = 0; i < n; i++) {
      StringBuilder row = new StringBuilder("  ");
      for (int j = 0; j < n; j++) row.append(matrix[i][j] ? 1 : 0).append(' ');
      System.out.println(row.toString().stripTrailing() + "   " + place[i]);
    }
    System.out.println("List:");
    for (int i = 0; i < n; i++) {
      System.out.println("  " + i + " " + place[i] + " -> " + adj.get(i) + "  (degree " + adj.get(i).size() + ")");
    }
    System.out.println("Library to Canteen directly? " + matrix[1][2]);
  }
}
```

```text [Output]
Matrix:
  0 1 1 0 0   Gate
  1 0 0 1 0   Library
  1 0 0 1 0   Canteen
  0 1 1 0 1   CSE Block
  0 0 0 1 0   Hostel
List:
  0 Gate -> [1, 2]  (degree 2)
  1 Library -> [0, 3]  (degree 2)
  2 Canteen -> [0, 3]  (degree 2)
  3 CSE Block -> [1, 2, 4]  (degree 3)
  4 Hostel -> [3]  (degree 1)
Library to Canteen directly? false
```

The matrix of an undirected graph is symmetric: row 1 column 3 matches row 3
column 1. Each undirected edge is stored twice in the list for the same reason.

### A directed graph: course prerequisites

With direction, add each edge **once**, from the course that must come first.
Counting in-degrees on the way tells you which courses have no prerequisites,
which is where any study plan must start (and where the next two lessons pick
up).

```java [Prerequisites.java]
import java.util.ArrayList;
import java.util.List;

public class Prerequisites {
  public static void main(String[] args) {
    String[] course = { "Java", "DSA", "DBMS", "SQL", "Spring" };
    // {a, b} means "a must be done before b": an arrow a -> b.
    int[][] before = { {0, 1}, {0, 2}, {2, 3}, {1, 4}, {3, 4} };

    List<List<Integer>> next = new ArrayList<>();
    for (int i = 0; i < course.length; i++) next.add(new ArrayList<>());
    int[] inDegree = new int[course.length];
    for (int[] e : before) {
      next.get(e[0]).add(e[1]);          // directed: one way only
      inDegree[e[1]]++;
    }

    for (int i = 0; i < course.length; i++) {
      List<String> unlocks = new ArrayList<>();
      for (int j : next.get(i)) unlocks.add(course[j]);
      System.out.printf("%-6s needs %d, unlocks %s%n", course[i], inDegree[i], unlocks);
    }
  }
}
```

```text [Output]
Java   needs 0, unlocks [DSA, DBMS]
DSA    needs 1, unlocks [Spring]
DBMS   needs 1, unlocks [SQL]
SQL    needs 1, unlocks [Spring]
Spring needs 2, unlocks []
```

For a weighted graph, store pairs instead of plain neighbours:
`List<List<int[]>>` where each `int[]` is `{neighbour, weight}`. The shortest
path lesson uses exactly that.

### Complexity: matrix or list

V is the number of vertices, E the number of edges.

| | Adjacency matrix | Adjacency list |
| --- | --- | --- |
| Space | O(V²) | **O(V + E)** |
| Is there an edge i → j? | **O(1)** | O(degree of i) |
| List all neighbours of i | O(V) | **O(degree of i)** |
| Add an edge | O(1) | O(1) |
| Good for | Small or **dense** graphs | Large, **sparse** graphs (almost every real one) |

A campus of 5,000 rooms with 20,000 corridors: a matrix needs 25 million cells;
a list needs about 45,000 entries. Real graphs are sparse, so the list is the
default. Use the matrix when V is small (a few hundred) or when the question
keeps asking "are these two connected?".

### Grids are graphs too

Many interview "graph" problems never mention a graph. A campus map drawn as a
grid of cells (`int[][]`, 1 for building, 0 for open ground) is a graph where
each cell is a vertex and its up, down, left and right neighbours are its
edges. You do not build an adjacency list for it: the neighbours are computed
from `(row ± 1, col)` and `(row, col ± 1)`. The next lesson counts buildings on
one.

## Real use case

::real-life{title="Which course can I take next?" source="A college registration system"}
Registration opens and a student asks which electives they are eligible for.
The system holds prerequisites as a directed graph: an adjacency list from each
course to the courses it unlocks, plus the in-degrees. A course is available
when every course pointing into it is in the student's completed set. Adding a
new course is appending to a list. Nobody draws the n × n grid of every course
against every other, because almost all of it would be empty.
::

## What confuses people here

- **Adding an undirected edge once.** Forget the reverse direction and half your
  walks fail to find paths that exist. Undirected: add both. Directed: add one.
- **Vertices as strings.** Interview inputs sometimes name vertices ("Library").
  Map each name to an index with a `HashMap<String, Integer>` first, or use a
  `Map<String, List<String>>` as the adjacency list. Do not mix the two.
- **Forgetting isolated vertices.** A vertex with no edges still needs its empty
  list, or `adj.get(i)` throws. Create all V lists before adding edges.
- **Thinking a tree is not a graph.** A tree is a connected, acyclic,
  undirected graph with V − 1 edges. Every graph algorithm works on trees.

## Interview questions

::accordion
  :::accordion-item{label="Adjacency matrix versus adjacency list?" icon="i-lucide-message-circle"}
  Matrix: O(V²) space, O(1) edge lookup, fine for small or dense graphs. List:
  O(V + E) space, fast neighbour iteration, the default for sparse graphs,
  which most real graphs are.
  :::
  :::accordion-item{label="How do you represent a weighted directed graph in Java?" icon="i-lucide-message-circle"}
  `List<List<int[]>> adj`, where `adj.get(u)` holds `{v, weight}` pairs for each
  edge u → v. Or a small `record Edge(int to, int weight)` and
  `List<List<Edge>>`, which reads better.
  :::
  :::accordion-item{label="What is the maximum number of edges in a graph with V vertices?" icon="i-lucide-message-circle"}
  Undirected, no self-loops: V(V − 1) / 2. Directed: V(V − 1). That is why a
  dense graph is O(V²) edges and a matrix is not wasteful for it.
  :::
  :::accordion-item{label="What is a DAG and where does it appear?" icon="i-lucide-message-circle"}
  A directed acyclic graph: arrows, and no way to follow them back to where you
  started. Course prerequisites, build dependencies and task scheduling must
  all be DAGs, and the order to do them in is a topological sort.
  :::
::
