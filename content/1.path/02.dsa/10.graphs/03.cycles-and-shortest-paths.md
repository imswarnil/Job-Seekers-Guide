A prerequisite loop is a **cycle** in a directed graph, and finding one is a
small change to the DFS you already have. Once you can prove there is no
cycle, you can put the courses in an order a student can actually follow, and
once you can walk in order, you can ask the question every map app answers:
what is the shortest way from here to there?

## Why this matters in a job

Cycle detection and ordering are how build tools (Maven, Gradle) decide what to
compile first and refuse circular dependencies, how spreadsheets reject a
formula that refers to itself, and how a scheduler runs jobs that depend on
other jobs. Shortest paths are maps, delivery routing, and network routing (the
Computer Networks track's routing protocols are shortest-path algorithms). In
interviews, "course schedule" (can all courses be finished? in what order?) is
one of the most common graph questions of all, and "network delay time" is
Dijkstra with a costume on.

## Three questions on one campus

::feature-list{columns="3"}
  :::feature{icon="i-lucide-refresh-cw" title="Is there a loop?"}

  :::

## How it works

### Detecting a cycle

**Undirected:** during DFS, if you meet a neighbour that is already visited and
it is **not the vertex you came from**, you have found a second way to reach
it, which means a loop. (The vertex you came from is always visited and always
a neighbour; ignoring it is the whole trick.)

**Directed:** "visited" is not enough. In the prerequisites below, DSA and DBMS
both lead to Spring, so Spring is reached twice, and that is not a cycle. A
cycle is an arrow back to a vertex **still on the current path**. So each
vertex gets one of three states: not started (0), on the current path (1),
finished (2). Reaching a 1 means a cycle.

```java [Cycles.java]
import java.util.ArrayList;
import java.util.List;

public class Cycles {
  static List<List<Integer>> build(int n, int[][] edges, boolean directed) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    for (int[] e : edges) {
      adj.get(e[0]).add(e[1]);
      if (!directed) adj.get(e[1]).add(e[0]);
    }
    return adj;
  }

  // Undirected: a visited neighbour that is not the one we came from closes a loop.
  static boolean undirectedHasCycle(List<List<Integer>> adj, int v, int parent, boolean[] visited) {
    visited[v] = true;
    for (int w : adj.get(v)) {
      if (!visited[w]) {
        if (undirectedHasCycle(adj, w, v, visited)) return true;
      } else if (w != parent) {
        return true;
      }
    }
    return false;
  }

  // Directed: 0 = not started, 1 = on the current path, 2 = finished.
  static boolean directedHasCycle(List<List<Integer>> adj, int v, int[] state) {
    state[v] = 1;
    for (int w : adj.get(v)) {
      if (state[w] == 1) return true;                         // back to our own path
      if (state[w] == 0 && directedHasCycle(adj, w, state)) return true;
    }
    state[v] = 2;
    return false;
  }

  static boolean anyDirectedCycle(List<List<Integer>> adj) {
    int[] state = new int[adj.size()];
    for (int v = 0; v < adj.size(); v++) {
      if (state[v] == 0 && directedHasCycle(adj, v, state)) return true;
    }
    return false;
  }

  public static void main(String[] args) {
    // Campus paths: Gate-Library-CSE Block-Canteen-Gate is a loop.
    int[][] paths = { {0, 1}, {1, 3}, {3, 2}, {2, 0}, {3, 4} };
    System.out.println("campus paths loop?     "
        + undirectedHasCycle(build(5, paths, false), 0, -1, new boolean[5]));
    int[][] tree = { {0, 1}, {0, 2}, {1, 3}, {3, 4} };
    System.out.println("tree-shaped paths?     "
        + undirectedHasCycle(build(5, tree, false), 0, -1, new boolean[5]));

    // 0 Java, 1 DSA, 2 DBMS, 3 SQL, 4 Spring
    int[][] sane = { {0, 1}, {0, 2}, {2, 3}, {1, 4}, {3, 4} };
    int[][] broken = { {0, 1}, {0, 2}, {2, 3}, {1, 4}, {3, 4}, {4, 2} };  // Spring before DBMS
    System.out.println("prerequisites sane?    " + !anyDirectedCycle(build(5, sane, true)));
    System.out.println("prerequisites broken?  " + anyDirectedCycle(build(5, broken, true)));
  }
}
```

```text [Output]
campus paths loop?     true
tree-shaped paths?     false
prerequisites sane?    true
prerequisites broken?  true
```

In the broken version, DBMS needs Spring, Spring needs SQL, and SQL needs DBMS.
The DFS goes Java → DSA → Spring → DBMS → SQL, all marked 1 as it goes, and
SQL's arrow points at Spring, which is still on the current path. A 1: cycle.

### Topological sort: a study plan

**Kahn's algorithm** is BFS on in-degrees. Start with every course that needs
nothing. Each time you "complete" a course, reduce the in-degree of everything
it unlocks; any course that drops to zero is now ready. If some courses never
reach zero, they are stuck in a cycle.

::flow{numbered caption="Kahn's algorithm on the prerequisites"}
  :::flow-step{label="Ready: Java" icon="i-lucide-play"}
  In-degree 0. Take it; DSA and DBMS drop to 0.
  :::
  :::flow-step{label="DSA, then DBMS" icon="i-lucide-list-checks"}
  DSA takes Spring from 2 to 1. DBMS takes SQL to 0.
  :::
  :::flow-step{label="SQL, then Spring" icon="i-lucide-check-check" highlight}
  SQL takes Spring to 0. All five placed, so there was no cycle.
  :::
::

```java [CourseOrder.java]
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.List;
import java.util.Queue;

public class CourseOrder {
  // Kahn's algorithm: repeatedly take a course with no prerequisites left.
  static List<String> order(String[] course, int[][] before) {
    int n = course.length;
    List<List<Integer>> next = new ArrayList<>();
    for (int i = 0; i < n; i++) next.add(new ArrayList<>());
    int[] inDegree = new int[n];
    for (int[] e : before) { next.get(e[0]).add(e[1]); inDegree[e[1]]++; }

    Queue<Integer> ready = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (inDegree[i] == 0) ready.offer(i);

    List<String> plan = new ArrayList<>();
    while (!ready.isEmpty()) {
      int c = ready.poll();
      plan.add(course[c]);
      for (int d : next.get(c)) {
        if (--inDegree[d] == 0) ready.offer(d);     // its last prerequisite is done
      }
    }
    if (plan.size() < n) return List.of("impossible: prerequisites form a cycle");
    return plan;
  }

  public static void main(String[] args) {
    String[] course = { "Java", "DSA", "DBMS", "SQL", "Spring" };
    int[][] sane = { {0, 1}, {0, 2}, {2, 3}, {1, 4}, {3, 4} };
    int[][] broken = { {0, 1}, {0, 2}, {2, 3}, {1, 4}, {3, 4}, {4, 2} };
    System.out.println(order(course, sane));
    System.out.println(order(course, broken));
  }
}
```

```text [Output]
[Java, DSA, DBMS, SQL, Spring]
[impossible: prerequisites form a cycle]
```

A graph can have many valid topological orders (DBMS before DSA would also be
fine). If the question wants one specific order, such as alphabetical among
ready courses, swap the queue for a `PriorityQueue`.

### Shortest paths: hops and metres

In an **unweighted** graph, BFS already finds the shortest path: it reaches
every vertex in order of distance, so the first time it reaches the target is
along a fewest-hops route. Record each vertex's `parent` as you discover it,
then walk the parents back from the target.

In a **weighted** graph, fewest hops is not fewest metres. **Dijkstra's
algorithm** replaces BFS's queue with a `PriorityQueue` ordered by distance so
far: always settle the closest place not yet settled, then see whether going
through it shortens the way to its neighbours (this check is called
**relaxing** an edge). It requires every weight to be zero or more.

```java [ShortestWalk.java]
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Collections;
import java.util.List;
import java.util.PriorityQueue;
import java.util.Queue;

public class ShortestWalk {
  static final String[] PLACE = { "Gate", "Library", "Canteen", "CSE Block", "Hostel" };

  // Unweighted: BFS. The first time a place is reached is the fewest hops.
  static List<String> fewestHops(List<List<Integer>> adj, int from, int to) {
    int[] parent = new int[adj.size()];
    Arrays.fill(parent, -1);
    boolean[] seen = new boolean[adj.size()];
    Queue<Integer> queue = new ArrayDeque<>();
    seen[from] = true;
    queue.offer(from);
    while (!queue.isEmpty()) {
      int v = queue.poll();
      if (v == to) break;
      for (int w : adj.get(v)) {
        if (!seen[w]) { seen[w] = true; parent[w] = v; queue.offer(w); }
      }
    }
    List<String> path = new ArrayList<>();
    for (int v = to; v != -1; v = parent[v]) path.add(PLACE[v]);
    Collections.reverse(path);
    return path;
  }

  // Weighted: Dijkstra. Always settle the closest unsettled place next.
  static int[] dijkstra(List<List<int[]>> adj, int from) {
    int[] dist = new int[adj.size()];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[from] = 0;
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));
    pq.offer(new int[]{ from, 0 });
    while (!pq.isEmpty()) {
      int[] top = pq.poll();
      int v = top[0], d = top[1];
      if (d > dist[v]) continue;                     // a stale, longer entry
      for (int[] edge : adj.get(v)) {
        int w = edge[0], metres = edge[1];
        if (dist[v] + metres < dist[w]) {
          dist[w] = dist[v] + metres;
          pq.offer(new int[]{ w, dist[w] });
        }
      }
    }
    return dist;
  }

  public static void main(String[] args) {
    int[][] paths = { {0, 1, 400}, {0, 2, 100}, {1, 3, 100}, {2, 3, 500}, {2, 1, 150}, {3, 4, 200} };
    List<List<Integer>> hops = new ArrayList<>();
    List<List<int[]>> metres = new ArrayList<>();
    for (int i = 0; i < PLACE.length; i++) { hops.add(new ArrayList<>()); metres.add(new ArrayList<>()); }
    for (int[] p : paths) {
      hops.get(p[0]).add(p[1]); hops.get(p[1]).add(p[0]);
      metres.get(p[0]).add(new int[]{ p[1], p[2] });
      metres.get(p[1]).add(new int[]{ p[0], p[2] });
    }

    System.out.println("fewest hops Gate -> Hostel: " + fewestHops(hops, 0, 4));
    int[] dist = dijkstra(metres, 0);
    for (int i = 0; i < PLACE.length; i++) {
      System.out.printf("%-10s %4d m%n", PLACE[i], dist[i]);
    }
  }
}
```

```text [Output]
fewest hops Gate -> Hostel: [Gate, Library, CSE Block, Hostel]
Gate          0 m
Library     250 m
Canteen     100 m
CSE Block   350 m
Hostel      550 m
```

Read those two answers together. BFS says Gate → Library → CSE Block → Hostel:
three paths, but 400 + 100 + 200 = 700 metres. Dijkstra finds 550 metres by
going Gate → Canteen → Library → CSE Block → Hostel: four paths, each short.
The direct path from the Gate to the Library is long, and only a weighted algorithm notices.

### Complexity

| Algorithm | Time | Space | Works when |
| --- | --- | --- | --- |
| Cycle detection (DFS) | O(V + E) | O(V) | Any graph |
| Topological sort (Kahn or DFS) | O(V + E) | O(V) | Directed, no cycle |
| Shortest path, BFS | O(V + E) | O(V) | Every edge weighs the same |
| Dijkstra with a binary heap | **O((V + E) log V)** | O(V + E) | No negative weights |
| Bellman-Ford | O(V × E) | O(V) | Negative weights allowed (named here, not taught) |

## Real use case

::real-life{title="The semester planner" source="A college academic office"}
Every semester the academic office loads 180 courses and their prerequisites
into a planner. Before publishing, it runs a topological sort. Twice in a year
somebody introduced a loop by adding "Advanced Java requires Spring" to a
catalogue that already said "Spring requires Advanced Java"; Kahn's algorithm
placed 178 of 180 courses and the two left over were exactly the loop, which
the error message named. Then the same order drives which courses are offered
in which semester.
::

Map applications run far more advanced versions of Dijkstra (with shortcuts and
precomputation), but the core idea, settle the nearest unsettled place and
relax its edges, is the one above.

## What confuses people here

- **Using the undirected cycle check on a directed graph.** "Already visited"
  wrongly reports a cycle when two courses share a later course. Directed
  graphs need the three states.
- **Using BFS on weighted edges.** It returns the fewest hops, which is not the
  shortest distance. Check whether the edges have weights before you choose.
- **Dijkstra with negative weights.** It can settle a place too early and never
  correct it. Negative edges need Bellman-Ford. Interviewers ask this as a
  follow-up.
- **Skipping the stale-entry check.** Java's `PriorityQueue` cannot lower an
  existing entry's priority, so Dijkstra offers a new entry and leaves the old
  one behind. `if (d > dist[v]) continue;` throws the old one away when it
  surfaces.
- **Overflow.** `dist[v] + metres` overflows if `dist[v]` is
  `Integer.MAX_VALUE`. It cannot happen here because only settled, finite
  distances are expanded, but it is worth saying out loud.

## Interview questions

::accordion
  :::accordion-item{label="Course schedule: can all courses be finished?" icon="i-lucide-message-circle"}
  Build a directed graph from prerequisite pairs and run Kahn's algorithm. If
  every course is placed, yes; if some are left with a non-zero in-degree,
  there is a cycle and the answer is no. O(V + E).
  :::
  :::accordion-item{label="Detect a cycle in a directed graph." icon="i-lucide-message-circle"}
  DFS with three states (unvisited, on the current path, finished). An edge to
  a vertex that is on the current path is a cycle. Or run Kahn's algorithm and
  check whether it placed every vertex.
  :::
  :::accordion-item{label="Detect a cycle in an undirected graph." icon="i-lucide-message-circle"}
  DFS carrying the parent: a visited neighbour that is not the parent means a
  cycle. Union-find is the alternative: an edge whose two ends are already in
  the same set closes a loop.
  :::
  :::accordion-item{label="Shortest path in an unweighted graph? In a weighted one?" icon="i-lucide-message-circle"}
  Unweighted: BFS, O(V + E), recording parents to rebuild the path. Weighted,
  non-negative: Dijkstra with a `PriorityQueue`, O((V + E) log V). Negative
  weights: Bellman-Ford.
  :::
  :::accordion-item{label="Why can't Dijkstra handle negative weights?" icon="i-lucide-message-circle"}
  It assumes that once the closest unsettled vertex is settled, no later path
  can be shorter, because every extra edge adds a non-negative amount. A
  negative edge breaks that, so a settled distance could later need to shrink,
  and Dijkstra never revisits it.
  :::
::
