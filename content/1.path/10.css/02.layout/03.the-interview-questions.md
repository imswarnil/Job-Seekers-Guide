CSS questions in an interview are narrow and predictable, and almost all of them
are really asking whether you can debug rather than whether you can style.

::accordion
  :::accordion-item{label="1. Explain the box model" icon="i-lucide-message-circle"}
  Content, padding, border, margin, outward. Then the part that makes it useful:
  by default `width` sets the **content** box, so a 300px element with 20px
  padding and a 2px border is 344px wide.

  `border-box` makes width mean the whole box, which is why essentially every
  codebase sets it globally in its first three lines.
  :::

  :::accordion-item{label="2. How does specificity work?" icon="i-lucide-message-circle"}
  Counted as ids, classes and elements, compared left to right, so any number in
  the first column beats any number in the second.

  Then the consequence, which is why modern conventions avoid ids in CSS: an id
  rule can only be overridden by another id rule, so one `#panel p` makes every
  future change to that element harder and is how a stylesheet ends up full of
  `!important`.
  :::

  :::accordion-item{label="3. Flexbox or Grid?" icon="i-lucide-message-circle"}
  One dimension against two. Flex for a row or column where the content decides
  the sizes; grid when you are defining rows and columns at once.

  Then the detail that shows use rather than reading:
  `repeat(auto-fill, minmax(18rem, 1fr))` is a responsive card grid with no media
  queries at all, and most real pages use grid for the page and flex inside each
  region.
  :::

  :::accordion-item{label="4. My style is not applying. What do you check?" icon="i-lucide-message-circle"}
  A sequence, and giving a sequence is the answer. Is the rule reaching the
  element at all — open the styles panel and look. Is it struck through, which
  means something more specific won and the tools name it. Is the box the size
  you think, which is usually `box-sizing`. Is the property even applicable —
  `width` on an inline element, `z-index` with no `position`, `margin: auto`
  with no width. None of those error; they are silently ignored.

  And what you do not do: reach for `!important`.
  :::

  :::accordion-item{label="5. How do you centre something?" icon="i-lucide-message-circle"}
  Sounds like a joke question and is a real one, because the answer dates you.
  `display: flex; align-items: center; justify-content: center` on the parent,
  or `display: grid; place-items: center`.

  The follow-up worth pre-empting: horizontally only, a block with a width takes
  `margin-inline: auto`. And it used to be genuinely hard, which is why it is
  still asked.
  :::

  :::accordion-item{label="6. How would you make this table work on a phone?" icon="i-lucide-message-circle"}
  The best CSS question, because there is no single right answer. Three options:
  horizontal scroll with the first column pinned by `position: sticky`; restyle
  rows as cards below a breakpoint; or show two columns and a details view.

  Name the cost of each: scrolling sideways is unpleasant and users miss it;
  cards make comparison impossible, which is usually the point of a table; fewer
  columns means somebody has to decide which two matter. And the accessibility
  note that almost nobody raises — `display: block` on a `tr` can lose the row
  and column relationships, so the card version needs testing with a screen
  reader.
  :::
::
