Before memory, the words. The three marked with a warning are the ones people
routinely swap in interviews.

| Term | In one line |
| --- | --- |
| **Process** | One running instance of a program, with its own memory, file descriptors, registers, identity and pid. |
| **Thread** | Another line of execution inside one process. Own stack and registers; shares the heap, the code and the file descriptors. |
| **Heap** | The shared part of a process's memory. Everything made with `new` lives here, and every thread can reach it. |
| **Stack** | Per thread. One frame per method call, holding parameters and local variables. Runs out → `StackOverflowError`. |
| **pid / ppid** | A process's number, and its parent's. Follow ppid up and you always reach 1. |
| **fork()** | Makes a copy of the calling process. Returns twice: `0` in the child, the child's pid in the parent. |
| **exec()** | Keeps the process, throws away its program and loads a different one. Same pid, new code. |
| **Ready** | Able to run, waiting for a processor. |
| **Blocked** | Waiting for something that is not a processor — disk, network, a keypress. Where most processes spend most of their lives. |
| **Context switch** | Saving one thread's registers and loading another's. A few microseconds, and the reason more threads is not always faster. |
| **Scheduler** | The kernel code that decides who runs next from the ready queue. |
| **Time slice / quantum** | How long a thread gets before the timer interrupt takes the processor back. |
| **Pre-emption** | The scheduler taking the processor away without the thread agreeing. This is why your code can be interrupted between any two instructions. |
| **Race condition** | ⚠️ A result that depends on the order two threads happened to be scheduled in. `x++` is the canonical example, because it is three instructions. |
| **Critical section** | The piece of code that only one thread may be inside at a time. |
| **Mutex / lock** | The thing that enforces a critical section. `synchronized` in Java. |
| **Atomic operation** | One that cannot be interrupted halfway. `AtomicInteger.incrementAndGet()` does read-add-write indivisibly. |
| **volatile** | ⚠️ Guarantees threads see each other's writes. Does **not** make read-add-write indivisible, so it does not fix `x++`. |
| **Deadlock** | Two threads each holding what the other wants. No error, no output, no processor use. |
| **Circular wait** | The fourth deadlock condition, and the one you break in practice by always taking locks in the same order. |
| **Thread pool** | A fixed set of reusable threads. Roughly the core count for processor-bound work; far more for work that waits. |
| **Concurrency** | ⚠️ Several things *in progress* at once. Possible on one core. |
| **Parallelism** | ⚠️ Several things *executing* at the same instant. Needs several cores. |
| **Thread dump** | A snapshot of every thread and what it is waiting on. `jstack <pid>` in Java, and it names deadlocks outright. |

## The three sentences to keep

::pull-quote
Threads share the heap and get their own stack. `x++` is three instructions. A
deadlock produces no error at all, which is why an idle processor on a hung
service is the clue.
::
