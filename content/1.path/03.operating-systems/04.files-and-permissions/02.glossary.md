The last of the vocabulary before the exercises.

## Memory

| Term | In one line |
| --- | --- |
| **Virtual address** | The address your program uses. Fake, and translated by hardware on every access. |
| **Physical address** | Where the data actually is in RAM. Your program never sees one. |
| **Page** | A fixed-size block of virtual memory, almost always 4 KB. The unit everything is handed out in. |
| **Frame** | A page-sized block of physical memory. A page maps to a frame, or to nothing. |
| **Page table** | The per-process map from pages to frames. Process isolation *is* this: A's table has no entry for B's frames. |
| **MMU** | The hardware that does the translation. Not software, which is why it is fast and why it cannot be bypassed. |
| **Page fault** | A memory access with no mapping. Traps into the kernel, which either fetches the page or kills the process. |
| **Minor fault** | Resolved without the disk. Cheap, and there are millions. |
| **Major fault** | Needs a disk read. Roughly 100,000× a normal access, and the number to watch. |
| **Swap** | Pages written to disk to free frames. A *consequence* of virtual memory, not the definition of it. |
| **Thrashing** | So much swapping that nothing else gets done. An unresponsive machine with an idle processor. |
| **Working set** | The pages a process actually needs right now. When the sum of everybody's working sets exceeds RAM, thrashing starts. |
| **RSS** | Resident set size: how much of a process is actually in RAM. The number in `ps` that means something. |
| **Virtual size** | How much a process *can* address. Usually far larger than RAM and not worth alarm. |
| **Heap** | The region a process allocates objects from. In Java, capped by `-Xmx` and garbage collected. |
| **Reachable** | Findable by following references from a root. The only thing garbage collection decides. |
| **Memory leak, in Java** | Something reachable that you have finished with. A `static Map` with no eviction is the classic. |
| **Metaspace** | Where the JVM keeps class definitions. Outside the heap, and it can exhaust separately. |

## Files and permissions

| Term | In one line |
| --- | --- |
| **File descriptor** | A small integer naming an open file within one process. 0 is stdin, 1 stdout, 2 stderr. |
| **inode** | The record holding a file's real metadata, owner, permissions, size, and where the blocks are. The name is *not* in it. |
| **Hard link** | A second name pointing at the same inode. Both are equally real; the file goes when the last one does. |
| **Symbolic link** | A small file containing a path. Breaks if the target moves, which a hard link does not. |
| **uid / gid** | The numbers the kernel actually checks. Names are for humans and live in a text file. |
| **root** | `uid=0`. Not a privileged name: a number the permission checks skip. |
| **rwx** | Read 4, write 2, execute 1, added per group of three. |
| **Owner, group, other** | The three sets of bits, checked in that order. **First match wins**, which is why an owner can be locked out of their own file. |
| **Execute, on a directory** | Permission to *traverse* it. Without it you cannot reach anything inside, whatever the file's own bits say. |
| **sudo** | Run one command as another user, after checking a file that says you may. Not "become an administrator". |
| **umask** | The bits removed from the permissions of every new file you create. Usually `022`, which is why new files are `644`. |

## The four that trip people up

::pull-quote
Swap is not virtual memory. RSS is not virtual size. A garbage-collected language
still leaks. And execute on a directory does not mean run it.
::
