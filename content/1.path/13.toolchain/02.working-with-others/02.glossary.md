Two chapters, in one page.

## The build

| Term | In one line |
| --- | --- |
| **Package manager** | Fetches somebody else's code and its dependencies. npm, pnpm, Maven, pip. |
| **Lock file** | Records the exact version **and checksum** of every package, including transitive ones. Commit it; never edit it. |
| **Transitive dependency** | A dependency of a dependency. One package can bring a thousand, and you are responsible for all of them. |
| **Semantic versioning** | `MAJOR.MINOR.PATCH`. Breaking, features, fixes. |
| **`^` and `~`** | Accept minor-and-patch, or patch only. Safe **because** the lock file pins the resolved version. |
| **Build tool** | Turns source into what ships. Vite, Maven, Gradle. |
| **Transpile** | Convert one language or version to another. TypeScript to JavaScript. |
| **Bundle** | Combine many modules into few files, so the browser makes fewer requests. |
| **Tree shaking** | Dropping code nothing imports. Why importing one function from a large library can cost almost nothing. |
| **Linter** | Finds likely mistakes and enforces style, so no human review is ever about a space. |
| **Typosquatting** | A package published under a near-miss name, with a post-install script. Read the name twice. |

## Working with other people

| Term | In one line |
| --- | --- |
| **Branch** | A line of work. One branch, one change, named for the change. |
| **Pull request** | An email to a reviewer. What and why first; detail underneath. |
| **Merge conflict** | Two branches changed the same lines. Rarer if you update from `main` regularly. |
| **Rebase** | Replay your commits on top of the latest `main`. Tidier history; never do it to a branch somebody else has. |
| **Squash merge** | Collapse a branch into one commit. Keeps `main` readable. |
| **Code review** | What is actually being assessed in your first months, and mostly about how you receive it. |
| **`nit:`** | A prefix marking a comment as optional. Without it every comment reads as blocking. |
| **CI** | A pipeline running on every push: it compiles, tests pass, the linter is happy, the artefact builds. |
| **A red build** | Gets fixed before anything else, or everybody starts ignoring the result and you have thrown the whole thing away. |
| **Artefact** | What the build produces. A jar, a container image, a folder of static files. |

## The four sentences to keep

::pull-quote
Commit the lock file and never delete it to make a build pass. Adding a
dependency is a decision with a cost that arrives later. A 2,000-line pull
request gets approved rather than reviewed. And CI does not find bugs, it
removes a category of conversation.
::
