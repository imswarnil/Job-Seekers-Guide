Four devices in one plastic case, then. Take the box on the wall of any PG in
BTM Layout apart in your head and you find a switch, a router, a wifi access
point and a modem. Each one works at a different layer, and knowing which is
the answer to one of the most common written-round questions there is.

## Why this matters in a job

"Difference between a hub, a switch and a router" appears in fresher written
tests and technical rounds year after year, because it checks whether the OSI
layers mean anything to you. At work it matters the day two machines on the same
office network can talk and a third on another network cannot: that is a routing
problem, not a cable problem.

## Three devices, three questions

Think of a college hostel.

- A **hub** is a warden who shouts every letter down the whole corridor. Every
  room hears every letter and each student checks whether it is theirs.
- A **switch** is a warden with a register of who lives in which room. Letters
  go only to the right door.
- A **router** is the college post office. It does not care about rooms; it
  decides which *city* a letter goes to next.

::compare{caption="Hub against switch: same job, one of them wastes everybody's time."}
  :::compare-side{label="Hub (layer 1)" verdict="wrong"}
  Repeats every incoming signal out of every other port. It cannot read an
  address. All devices share the bandwidth and collide with each other. Obsolete,
  and still asked about.
  :::
  :::compare-side{label="Switch (layer 2)" verdict="right"}
  Reads the destination **MAC address** in each frame and sends it out of the
  one port where that device lives. It learns which MAC is on which port by
  watching traffic, and keeps a table of them.
  :::
::

| Device | OSI layer | Reads | Job |
| --- | --- | --- | --- |
| Repeater | 1 Physical | Nothing, only signals | Boosts a weak signal over a long cable |
| Hub | 1 Physical | Nothing | Copies every signal to every port |
| Bridge | 2 Data link | MAC addresses | Joins two network segments, filters by MAC |
| Switch | 2 Data link | MAC addresses | A many-port bridge: sends each frame to one port |
| Router | 3 Network | IP addresses | Moves packets **between** networks, chooses the route |
| Gateway | Up to 7 | Anything | Joins networks that speak different protocols; in everyday use, "default gateway" means your router |
| Modem | 1 Physical | Nothing | Converts between your network's signals and the provider's line (fibre, cable, DSL) |
| Access point | 2 Data link | MAC addresses | A switch whose ports are radio |

## How it works

A switch keeps a **MAC address table**: which device is on which port. A router
keeps a **routing table**: which network lives in which direction. You cannot
see your switch's table from a laptop, but you can see your own routing table,
and it is short.

```bash [Terminal]
# macOS
netstat -rn -f inet | head -6
# Linux: ip route
# Windows: route print
```

```text [Output]
Routing tables

Internet:
Destination        Gateway            Flags               Netif Expire
default            192.168.1.1        UGScg                 en0
192.168.1          link#11            UCS                   en0
```

Read it as two rules. Anything for `192.168.1.x` is on my own network: send it
directly, and the switch inside the box delivers it by MAC address. **Anything
else** (`default`) goes to `192.168.1.1`, the router, which decides where it goes
next. Your laptop has no idea where Google is. It only knows who to hand the
packet to. Your addresses will differ; this output is from a home network.

`traceroute` shows every router a packet passes through on the way.

```bash [Terminal]
traceroute -m 5 google.com
```

```text [Output]
traceroute to google.com (142.250.183.46), 5 hops max, 52 byte packets
 1  192.168.1.1 (192.168.1.1)  2.1 ms  1.8 ms  1.9 ms
 2  10.24.0.1 (10.24.0.1)  6.4 ms  5.9 ms  6.2 ms
 3  * * *
 4  72.14.194.18 (72.14.194.18)  11.2 ms  10.8 ms  11.5 ms
 5  142.250.183.46 (142.250.183.46)  10.9 ms  11.1 ms  10.7 ms
```

Hop 1 is your own router. Hop 2 is your internet provider. Every numbered line
is a layer 3 device making a routing decision. The switch inside your box never
appears here, because a switch does not change the IP hop at all. (Illustrative
output: your hops and times will differ.)

## Real use case

In an office, the network team splits departments into separate networks so the
exam cell's machines are not on the same network as the student wifi. Two
machines on the same switch but in different networks cannot talk without going
through a router, and the router is where the rule lives.

```text [router-acl.txt]
# Allow the exam cell's network to reach the results server.
permit tcp 10.10.20.0/24 host 10.10.5.20 eq 443
# Deny the student wifi network from reaching it at all.
deny   ip  10.10.100.0/22 host 10.10.5.20
```

A developer meets this as "it works from my desk and not from the wifi". The
answer is almost never the code: it is a layer 3 rule on a router.

## What confuses people here

That a "router" at home is one device. It is a modem (talks to the provider's
line), a router (moves packets between your home network and the internet), a
switch (the four LAN ports) and a wifi access point, sold as one box. When an
interviewer asks "what does a router do", describe the layer 3 job only.

And that switches know IP addresses. A plain switch does not. It reads MAC
addresses only. ("Layer 3 switches" exist and route as well, but that is a
router built into a switch.)

## Interview questions

::accordion
  :::accordion-item{label="Difference between a hub, a switch and a router?" icon="i-lucide-message-circle"}
  A hub works at layer 1 and repeats every signal to every port. A switch works
  at layer 2, reads MAC addresses and sends each frame only to the port where the
  destination is. A router works at layer 3, reads IP addresses and moves packets
  between different networks, choosing a route.
  :::
  :::accordion-item{label="What is a default gateway?" icon="i-lucide-message-circle"}
  The router your machine hands every packet to when the destination is not on
  its own network. On a home network it is usually `192.168.1.1` or
  `192.168.0.1`. Without it you can reach machines on your own network and
  nothing on the internet.
  :::
  :::accordion-item{label="What is a collision domain and a broadcast domain?" icon="i-lucide-message-circle"}
  A collision domain is the set of devices whose signals can collide. Every port
  of a hub is one collision domain; each switch port is its own. A broadcast
  domain is the set of devices that receive a broadcast. A switch forwards
  broadcasts to every port, so it is one broadcast domain; a router does not
  forward them, so it separates broadcast domains.
  :::
  :::accordion-item{label="What does a modem do?" icon="i-lucide-message-circle"}
  It converts signals between your network and the provider's physical line
  (fibre, cable or telephone). Modulator and demodulator. It does not route and
  it does not read addresses.
  :::
::
