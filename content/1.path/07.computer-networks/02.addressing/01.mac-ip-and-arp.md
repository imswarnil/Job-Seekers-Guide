Every device has two addresses, and neither is spare. A MAC address says **who**
the device is. An IP address says **where** it is right now. The switch needs
the first, the router needs the second, and ARP is the protocol that connects
them.

## Why this matters in a job

"MAC address against IP address" is a standard written-round and interview
question, and ARP is the usual follow-up. At work you will meet it less directly:
the office network that only lets registered laptops on is filtering by MAC
address, and the "IP conflict" warning on somebody's machine is two devices
claiming the same IP.

## Name and hostel room

Your name stays the same whether you live in Bhopal or in a PG in BTM Layout.
Your postal address changes every time you move. A letter needs the address to
reach you; the person at the door needs your name to hand it to you.

- **MAC address** (Media Access Control): 48 bits, written as six pairs of hex
  digits like `3c:22:fb:4a:9e:01`. Burnt into the network card by the maker. The
  first half identifies the maker. It is used only on the **local** network, at
  layer 2.
- **IP address** (Internet Protocol): 32 bits for IPv4, written as four numbers
  like `192.168.1.23`. Given to you by the network you join, so it changes when
  you move from the PG wifi to the office. It is used end to end, at layer 3.

| | MAC address | IP address |
| --- | --- | --- |
| Layer | 2, data link | 3, network |
| Size | 48 bits | 32 bits (IPv4), 128 bits (IPv6) |
| Looks like | `3c:22:fb:4a:9e:01` | `192.168.1.23` |
| Assigned by | The manufacturer | The network (usually DHCP) |
| Changes when you move? | No | Yes |
| Used by | Switches | Routers |
| Reach | Only the local network | The whole internet |

## How it works

Your laptop wants to send a packet to `192.168.1.40`, another machine in the same
PG. It knows the IP address. But the switch only understands MAC addresses. So
the laptop asks, out loud, to everyone on the local network.

::flow{numbered direction="vertical" caption="ARP: Address Resolution Protocol. IP address in, MAC address out."}
  :::flow-step{label="Check the ARP cache" icon="i-lucide-database"}
  Has this laptop asked before? If yes, it uses the saved answer.
  :::
  :::flow-step{label="Broadcast the question" icon="i-lucide-megaphone" highlight}
  "Who has 192.168.1.40? Tell 192.168.1.23." Sent to MAC `ff:ff:ff:ff:ff:ff`,
  which every device on the network receives.
  :::
  :::flow-step{label="The owner replies, to you alone" icon="i-lucide-reply"}
  "192.168.1.40 is at a4:83:e7:11:2c:9d." The others ignore the question.
  :::
  :::flow-step{label="Cache it and send" icon="i-lucide-send"}
  The answer is kept for a few minutes. The frame goes out addressed to that MAC.
  :::
::

If the destination is on **another** network (a website, say), the laptop does
not ARP for the website. It ARPs for the **default gateway**, the router, and
sends the frame there. The IP address in the packet stays the website's; the MAC
address in the frame is the router's. At every router along the way, the MAC
addresses are replaced for the next hop and the IP addresses stay the same.

See both of your own addresses, and your ARP cache:

```bash [Terminal]
# macOS. On Linux: ip addr and ip neigh. On Windows: ipconfig /all and arp -a
ifconfig en0 | grep -E "ether|inet "
arp -a | head -3
```

```text [Output]
	ether 3c:22:fb:4a:9e:01
	inet 192.168.1.23 netmask 0xffffff00 broadcast 192.168.1.255
? (192.168.1.1) at 60:32:b1:7a:0c:44 on en0 ifscope [ethernet]
? (192.168.1.40) at a4:83:e7:11:2c:9d on en0 ifscope [ethernet]
? (192.168.1.255) at ff:ff:ff:ff:ff:ff on en0 ifscope [ethernet]
```

`ether` is your MAC. `inet` is your IP. The ARP table maps the IPs your laptop
has recently spoken to on to their MACs, and the first line is your router.
Your values will differ.

## Real use case

College and office networks often allow only registered devices. The network
team keeps a list of MAC addresses and the access point refuses the rest.

```text [allowed-devices.csv]
mac,owner,department
3c:22:fb:4a:9e:01,Faculty laptop 114,Computer Science
a4:83:e7:11:2c:9d,Exam cell printer,Examinations
```

It is a weak control, and worth saying so in an interview: most operating
systems let you change the MAC address your card announces in one command, so a
MAC filter keeps honest people honest and nothing more. Phones do it
deliberately now ("private wifi address"), which is why a college portal that
identifies students by MAC breaks every September.

## What confuses people here

That the MAC address travels across the internet. It does not. It is rewritten
at every router, so the server you reach never sees your laptop's MAC. It sees
your IP address (or, as the next lessons show, your router's public one).

And that ARP is needed on the internet. ARP only works inside one local network,
because its question is a broadcast and routers do not forward broadcasts.

## Interview questions

::accordion
  :::accordion-item{label="What is the difference between a MAC address and an IP address?" icon="i-lucide-message-circle"}
  A MAC address is a 48-bit hardware address set by the manufacturer, used at
  layer 2 inside one local network. An IP address is a 32-bit (IPv4) logical
  address given by the network, used at layer 3 to reach any machine anywhere.
  The MAC stays the same when you move; the IP changes.
  :::
  :::accordion-item{label="What is ARP and how does it work?" icon="i-lucide-message-circle"}
  Address Resolution Protocol finds the MAC address for an IP address on the
  local network. The sender broadcasts "who has this IP?", the owner replies with
  its MAC, and the answer is cached. For a destination on another network, the
  sender ARPs for the router instead.
  :::
  :::accordion-item{label="Why do we need both addresses?" icon="i-lucide-message-circle"}
  Because the two layers solve different problems. Switches deliver frames one
  hop at a time and need a fixed hardware address. Routers find a path across
  many networks and need an address that says which network you are on. An IP
  address has that structure; a MAC does not.
  :::
  :::accordion-item{label="What is RARP?" icon="i-lucide-message-circle"}
  Reverse ARP: a device that knows its MAC asks for its IP address. It is
  obsolete, replaced by DHCP, but it still turns up in written-round options.
  :::
::
