One server, three programs, and a packet that must reach exactly one of them.
The IP address gets it to the building. The **port** is the room number.

## Why this matters in a job

"Which port does HTTPS use?", "what is a socket?" and "what does port 22 do?"
are quick-fire interview questions. On your first week at work, "port 8080 is
already in use" will be one of the first errors you see, and knowing how to find
what is holding it takes ten seconds instead of a restart.

## An IP address is a machine. A port is a program.

A port is a 16-bit number, so 0 to 65535. A program **listens** on a port; the
operating system hands every packet arriving for that port to that program and
to nothing else.

Ports fall into three ranges:

- **0–1023, well-known.** Reserved for standard services. Binding to one needs
  administrator rights on most systems.
- **1024–49151, registered.** Used by known applications (MySQL, PostgreSQL).
- **49152–65535, dynamic or ephemeral.** Picked at random by your operating
  system for the **client** end of a connection.

The ports worth memorising:

| Port | Protocol | What listens |
| --- | --- | --- |
| 20, 21 | FTP | File transfer (21 control, 20 data) |
| 22 | SSH | Secure remote login to a server |
| 23 | Telnet | Old, unencrypted remote login |
| 25 | SMTP | Sending email between servers |
| 53 | DNS | Name lookups, mostly UDP |
| 67, 68 | DHCP | Address assignment (67 server, 68 client) |
| 80 | HTTP | The web, unencrypted |
| 110 | POP3 | Downloading email |
| 143 | IMAP | Reading email on the server |
| 443 | HTTPS | The web, encrypted |
| 3306 | MySQL | |
| 5432 | PostgreSQL | |
| 8080 | HTTP (alternative) | Development servers: above 1023, so no admin rights needed |

A **socket** is one end of a connection: an IP address plus a port, like
`10.0.4.12:5432`. A TCP connection is identified by **four** things: source IP,
source port, destination IP, destination port. That is how one web server on
port 443 can hold ten thousand connections at once: each one has a different
client address or client port.

## How it works

Here is a tiny server in Java that listens on a port, and what the operating
system says about it while it runs.

```java [RollCallServer.java]
import java.io.PrintWriter;
import java.net.ServerSocket;
import java.net.Socket;

public class RollCallServer {
    public static void main(String[] args) throws Exception {
        try (ServerSocket server = new ServerSocket(8080)) {
            System.out.println("Listening on port " + server.getLocalPort());
            try (Socket client = server.accept();
                 PrintWriter out = new PrintWriter(client.getOutputStream(), true)) {
                System.out.println("Connection from " + client.getRemoteSocketAddress());
                out.println("Attendance for CS-6A: 58 of 64 present");
            }
        }
    }
}
```

In a second terminal, connect with `nc` (netcat), then check who holds the port:

```bash [Terminal]
nc localhost 8080
lsof -i :8080          # run while the server is still waiting
```

```text [Output]
Listening on port 8080
Connection from /127.0.0.1:53412
```

```text [nc output]
Attendance for CS-6A: 58 of 64 present
```

```text [lsof output]
COMMAND   PID    USER   FD   TYPE  DEVICE SIZE/OFF NODE NAME
java    41872 swarnil   7u  IPv6  0x9a...      0t0  TCP *:http-alt (LISTEN)
```

`53412` is the ephemeral port your operating system picked for `nc`. `http-alt`
is the standard name for 8080. Start the server a second time while the first is
running and Java throws `java.net.BindException: Address already in use`,
because only one program may listen on a port.

## Real use case

The first-week error at every job: you stop a server by closing the terminal
window, it keeps running in the background, and the next start fails.

```bash [Terminal]
lsof -i :8080            # find the process holding the port
kill 41872               # stop it by its PID
# Windows: netstat -ano | findstr :8080, then taskkill /PID 41872 /F
```

And the one that matters for security. A database port open to the whole
internet is one of the most common serious misconfigurations there is. 5432 and
3306 should be reachable from the application servers only.

```text [firewall-rules.txt]
allow tcp 5432 from 10.0.1.0/24     # the web servers' subnet
deny  tcp 5432 from any
```

## What confuses people here

That a port is something physical. It is only a number in the TCP or UDP header
that the operating system uses to pick a program.

And that the **client** uses the same port as the server. It does not. Your
browser connects **to** port 443 **from** a random high port like 53412, and a
new tab gets another one.

## Interview questions

::accordion
  :::accordion-item{label="What is a port?" icon="i-lucide-message-circle"}
  A 16-bit number (0 to 65535) in the transport header that identifies which
  program on a machine should receive the data. The IP address finds the
  machine; the port finds the program.
  :::
  :::accordion-item{label="What is a socket?" icon="i-lucide-message-circle"}
  One endpoint of a connection: an IP address and a port together, such as
  `10.0.4.12:443`. A TCP connection is uniquely identified by the pair of
  sockets, that is source IP, source port, destination IP and destination port.
  :::
  :::accordion-item{label="Default ports for HTTP, HTTPS, SSH, FTP, DNS and SMTP?" icon="i-lucide-message-circle"}
  HTTP 80, HTTPS 443, SSH 22, FTP 21 (and 20 for data), DNS 53, SMTP 25.
  :::
  :::accordion-item{label="Why do development servers use 8080 or 3000 instead of 80?" icon="i-lucide-message-circle"}
  Ports below 1024 need administrator rights to bind on most systems. 8080 and
  3000 do not, so you can run a server without `sudo`.
  :::
  :::accordion-item{label="How can one server on port 443 handle thousands of clients?" icon="i-lucide-message-circle"}
  Because each connection is identified by all four values, not only the server
  port. Each client has a different IP or a different source port, so each
  connection is distinct.
  :::
::
