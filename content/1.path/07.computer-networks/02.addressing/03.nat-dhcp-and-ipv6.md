Every one of those laptops reaches Google through a trick at the router. The
router rewrites every outgoing packet so it appears to come from the building's
one public address, and remembers who asked so it can pass the reply back. That
trick is NAT, and it is the reason the internet did not run out of addresses in
the 2000s.

## Why this matters in a job

NAT, DHCP and IPv4 against IPv6 are each short, common interview questions, and
each has a one-line answer you should be able to give without thinking. At work
NAT explains a real problem: fifty students in one college hostel all appear to
a website as **one** IP address, so a rule like "block an address after ten
failed logins" locks out the whole hostel.

## Three problems, three fixes

::feature-list{columns="3"}
  :::feature{icon="i-lucide-users" title="NAT: too few addresses"}
  IPv4 has about 4.3 billion addresses and there are far more devices. NAT lets
  many private addresses share one public one.
  :::
  :::feature{icon="i-lucide-hand-helping" title="DHCP: nobody wants to type addresses"}
  When you join a network, a DHCP server hands your device an IP address, the
  subnet mask, the router's address and a DNS server. Automatically.
  :::
  :::feature{icon="i-lucide-infinity" title="IPv6: the real fix"}
  128-bit addresses. Enough for every device to have its own public address,
  which removes the need for NAT.
  :::
::

### NAT, the building receptionist

Network Address Translation. The PG has one landline number. Everybody's calls go
out from it, and the receptionist writes down who called whom, so when the reply
comes in she knows which room to put it through to.

### DHCP, four messages

Dynamic Host Configuration Protocol. Remember it as **DORA**.

::flow{numbered direction="horizontal" caption="The moment you join the PG wifi."}
  :::flow-step{label="Discover" icon="i-lucide-search"}
  The laptop broadcasts: "is there a DHCP server?"
  :::
  :::flow-step{label="Offer" icon="i-lucide-gift"}
  The router offers `192.168.1.23`.
  :::
  :::flow-step{label="Request" icon="i-lucide-hand"}
  The laptop asks to take that address.
  :::
  :::flow-step{label="Acknowledge" icon="i-lucide-check" highlight}
  Confirmed, with a **lease** time. The address is renewed before it runs out.
  :::
::

### IPv6

| | IPv4 | IPv6 |
| --- | --- | --- |
| Size | 32 bits | 128 bits |
| Addresses | About 4.3 billion | About 3.4 × 10^38 |
| Written as | `192.168.1.23` | `2401:4900:1c3a::5b2` (hex, colons) |
| NAT needed? | Usually | No, every device can have a public address |
| Configuration | DHCP or manual | Can configure itself (SLAAC), or DHCPv6 |
| Header | Variable, has a checksum | Fixed 40 bytes, simpler, no checksum |
| Loopback | `127.0.0.1` | `::1` |
| DNS record | `A` | `AAAA` |

The `::` in an IPv6 address means "a run of zeros here", allowed once per
address. Indian mobile networks moved to IPv6 early, so your phone on mobile data
very likely already has one.

## How it works

See what DHCP gave your laptop, then ask a public service which address the
world sees you as.

```bash [Terminal]
# macOS. On Linux: ip addr and cat /etc/resolv.conf. On Windows: ipconfig /all
ipconfig getpacket en0 | grep -E "yiaddr|router|domain_name_server|lease_time"
curl -s https://api.ipify.org; echo
```

```text [Output]
yiaddr = 192.168.1.23
lease_time (uint32): 0x15180
router (ip_mult): {192.168.1.1}
domain_name_server (ip_mult): {192.168.1.1}
49.207.51.118
```

`yiaddr` ("your IP address") is the private address DHCP leased to you.
`0x15180` is 86,400 seconds: a one-day lease. The last line is your **public**
address, the router's, as the internet sees it. The two are different, and that
difference is NAT. (Illustrative values; yours will differ.)

## Real use case

A college results site limits login attempts per IP address. On result day it
starts blocking whole hostels.

```java [LoginRateLimiter.java]
// Wrong for this college: every student behind the hostel router shares one IP.
String key = request.getRemoteAddr();              // 49.207.51.118 for 300 students

// Better: limit per account, and only use the address as a loose second signal.
String key = "login:" + form.getRollNumber();
```

The first version looks correct in testing, because the developer is one person
on one address. It fails the day 300 students behind one NAT try to log in at
10 am. Knowing that NAT exists is what makes you spot it in a code review.

## What confuses people here

- **NAT is not security.** It hides inside addresses as a side effect, but a
  firewall is what decides what is allowed in.
- **Your public address is not your laptop's address.** `ifconfig` shows the
  private one; websites see the router's.
- **DHCP does not only give an IP.** It also gives the mask, the default gateway
  and the DNS server. A laptop with an IP and no gateway reaches the local
  network and nothing else.

## Interview questions

::accordion
  :::accordion-item{label="What is NAT and why is it used?" icon="i-lucide-message-circle"}
  Network Address Translation rewrites private source addresses (and ports) to
  a public address as packets leave a network, and keeps a table to translate
  replies back. It lets many devices share one public IPv4 address, which
  stretched IPv4's 4.3 billion addresses much further.
  :::
  :::accordion-item{label="What is DHCP? Explain DORA." icon="i-lucide-message-circle"}
  Dynamic Host Configuration Protocol assigns IP configuration automatically:
  address, mask, default gateway, DNS server and a lease time. DORA is the
  exchange: Discover (client broadcasts), Offer (server proposes an address),
  Request (client accepts), Acknowledge (server confirms).
  :::
  :::accordion-item{label="Difference between IPv4 and IPv6?" icon="i-lucide-message-circle"}
  IPv4 addresses are 32 bits, about 4.3 billion, written as four decimals.
  IPv6 addresses are 128 bits, written as eight groups of hex, enough that NAT is
  unnecessary. IPv6 also has a simpler fixed header and can configure addresses
  itself.
  :::
  :::accordion-item{label="What is a static IP versus a dynamic IP?" icon="i-lucide-message-circle"}
  A static IP is set by hand and never changes; servers and printers use one so
  others can find them. A dynamic IP is leased by DHCP and can change; laptops
  and phones use one.
  :::
::
