The box stopped making sense because the program no longer had to be on your
machine. It could be on somebody else's, and you could reach it.

That one move created most of the jobs this course is aimed at.

## Why this matters in a job

Because it changed what "finished" means, and nobody tells beginners this.

Software in a box was finished when it shipped. Software on a server is never
finished: it is running, right now, and somebody is using it while you change it.
Every practice in the back half of this course — version control, tests,
deployments, monitoring, migrations — exists because of that sentence.

::compare{caption="The same bug, two eras."}
  :::compare-side{label="Boxed software, 1996" verdict="wrong"}
  A wrong fee calculation ships on a CD. The fix is version 4.1, next year, and
  every customer has to install it. So you test for months, and you are still
  wrong.
  :::
  :::compare-side{label="A web application, now" verdict="right"}
  A wrong fee calculation is fixed and live in twenty minutes. Which is a relief
  and a trap: it makes shipping something wrong cheap, so the discipline has to
  come from you rather than from the medium.
  :::
::

## What the browser actually did

It turned every machine in the world into a client for your program without
anybody installing anything.

::flow{numbered direction="vertical" caption="What happens when the registrar opens the admissions dashboard. Every one of these is a subject in this course."}
  :::flow-step{label="She types the address" icon="i-lucide-globe"}
  The name is turned into a number by DNS. That is the networks track.
  :::
  :::flow-step{label="Her browser asks your server for a page" icon="i-lucide-send"}
  Over HTTP, on a connection nobody can read in between. Networks again, then
  hosting.
  :::
  :::flow-step{label="Your code decides what to say" icon="i-lucide-server" highlight}
  Who is she, is she allowed, what does she need. Java, and later the backend
  tracks.
  :::
  :::flow-step{label="It asks the database" icon="i-lucide-database"}
  `SELECT` over applicants and applications. The SQL track, which is the one that
  most often decides whether you get the job.
  :::
  :::flow-step{label="The page is built and sent" icon="i-lucide-layout"}
  HTML for what it is, CSS for how it looks, JavaScript for what it does when she
  clicks.
  :::
  :::flow-step{label="She sees a number" icon="i-lucide-eye"}
  And if it is wrong, none of the six steps above told anybody.
  :::
::

That flow is, quite literally, the table of contents of this course. Everything
you are about to learn is one of those boxes.

## What confuses people here

Two things.

**"The browser is the front end and that is the easy part."** The browser is a
runtime for programs that run on a machine you do not control, over a network
that fails, for a person who will do things you did not anticipate. It is not the
easy part, it is a different hard part.

**"Web means simple websites."** The admissions system you will build in this
course is a real application. A bank's internet banking, a hospital's records
system and an airline's booking engine are all web applications. "Web" describes
how it is delivered, not how serious it is.

::side-note{kind="security"}
The moment your program is reachable by anybody with the address, it is reachable
by everybody with the address. Every security topic in this course — who can read
which student's marks, what happens to a password, what an injected query is —
exists because of this lesson and not before it.
::

## What you can do now

You can name the six things that happen between typing an address and seeing a
number, and you can point at the track in this course that teaches each one. That
is a genuinely good answer to "what do you know about how the web works", asked
of a fresher.

## Your turn

Open any website you use. Press F12, then look at the Network tab, then reload
the page. Count the requests. Write down the number.

Then answer: why is it that number and not one?

::accordion
  :::accordion-item{label="What you are looking at" icon="i-lucide-network"}
  The first request gets the HTML, which is a document that *refers to* other
  things: stylesheets, scripts, fonts, images, and usually several calls for data
  after the page is already on screen. So one address produces dozens of round
  trips, each of which can be slow or fail. Performance work, later in this
  course, is mostly about reducing that number or making it matter less.
  :::
::

   boxed software?
2. **An interviewer asks: "what happens when you type a URL and press enter?"**
   This is one of the most-asked questions in the industry. Give the six steps.

## The interview question this answers

**"What happens when you type a URL into a browser and press enter?"**

It is asked constantly because it is unbounded: you can answer it in thirty
seconds or forty minutes, and how far you go shows how deep you actually are.
The six steps above are a solid fresher answer. By the end of the networks track
you will be able to say DNS resolution, TCP handshake, TLS handshake, HTTP
request, server processing, response, parsing, and rendering, and mean all of it.
