| Term | In one line |
| --- | --- |
| **Declarative** | You describe the screen for a given state; React works out the difference. There are no transitions to forget. |
| **Component** | A function taking data and returning what the screen should look like. |
| **Props** | Data passed down. Read-only inside the child. |
| **State** | Data a component remembers between renders. Changing it re-renders. |
| **Lifting state** | Moving it to the nearest common parent when a sibling needs it. Not before: state at the top re-renders everything below. |
| **Derived state** | ⚠️ A value computed from other state. **Do not store it.** Two sources of truth will disagree. |
| **Immutability** | ⚠️ Replace, never mutate. React compares references, so `push` then `setState` changes nothing. |
| **Key** | ⚠️ Which item is which between renders. `key={index}` on a reorderable list moves somebody's typed input to another row. |
| **`useState`** | One piece of state. Prefer one `status` string over four booleans that can be in eight impossible combinations. |
| **`useEffect`** | ⚠️ For synchronising with something **outside** React. Not for computing values, not for click handlers. |
| **`useMemo` / `useCallback`** | Caching, for when profiling says you need it. Not by default. |
| **Custom hook** | A function starting with `use` that composes other hooks. How logic is shared between components. |
| **Controlled input** | Its value comes from state. The usual choice, and the reason a form stops working without JavaScript. |
| **Reconciliation** | React comparing the new description with the old one to work out the minimum change. |

## The four sentences to keep

::pull-quote
Describe the screen, do not sequence the transitions. Replace state, never
mutate it. Do not store what you can compute. And `useEffect` is for the world
outside React.
::
