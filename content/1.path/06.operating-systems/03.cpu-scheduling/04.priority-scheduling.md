Give each process a priority and always run the most important one that is
ready. That is **priority scheduling**, and it is what real operating systems are
built on. It also brings back the problem Round Robin fixed: a low-priority
process can wait forever.

## Why this matters in a job

Priority questions come in two forms: the Gantt chart (usually pre-emptive, to
make it interesting) and "what is starvation and how do you prevent it?", whose
answer, **ageing**, is one of the most reliably asked words in the whole
operating systems round. And the comparison table at the end of this lesson is
the thing to revise the night before.

## Most important first

Think of the college hospital's out-patient queue. Most people are seen in
order, but an accident case goes straight in, ahead of everyone, and if a second
emergency arrives while a routine patient is being seen, the doctor may stop and
take the emergency. On a busy day, the person with a mild cough might wait until
closing. That is priority scheduling, pre-emption and starvation in one queue.

The convention in this chapter: **a lower number means a higher priority**
(priority 1 runs first). Some textbooks use the opposite, so an exam question
will say which; always write it down before you start.

Same four processes, now with priorities: P1 (AT 0, BT 8, priority 2),
P2 (1, 4, 4), P3 (2, 9, 1), P4 (3, 5, 3).

### Non-pre-emptive priority

At 0 only P1 is there; it runs to 8 without interruption. At 8, the ready ones
are P2 (4), P3 (1), P4 (3): P3 goes first, then P4, then P2.

```text [Gantt chart, priority, non-pre-emptive]
|    P1    |     P3     |   P4   |  P2  |
0          8            17       22     26
```

| Process | AT | BT | Pri | CT | TAT | WT |
| --- | --- | --- | --- | --- | --- | --- |
| P1 | 0 | 8 | 2 | 8 | 8 | 0 |
| P2 | 1 | 4 | 4 | 26 | 25 | 21 |
| P3 | 2 | 9 | 1 | 17 | 15 | 6 |
| P4 | 3 | 5 | 3 | 22 | 19 | 14 |

Average waiting = 41 / 4 = **10.25 ms**.

### Pre-emptive priority

Now the scheduler checks whenever a process arrives. At 1, P2 (priority 4)
arrives: lower than P1 (2), P1 continues. At 2, P3 (priority 1) arrives: higher
than P1, so **P1 is pre-empted** with 6 left. P3 runs to 11. Then P1 (2) runs to
17, P4 (3) to 22, P2 (4) to 26.

```text [Gantt chart, priority, pre-emptive]
| P1 |     P3     |   P1   |   P4   |  P2  |
0    2            11       17       22     26
```

| Process | CT | TAT = CT - AT | WT = TAT - BT |
| --- | --- | --- | --- |
| P1 | 17 | 17 | 9 |
| P2 | 26 | 25 | 21 |
| P3 | 11 | 9 | 0 |
| P4 | 22 | 19 | 14 |

Average waiting = 44 / 4 = **11 ms**. P2, the lowest priority, waited 21 of its
25 ms. With a steady stream of higher-priority arrivals it would never run at
all.

### Starvation and ageing

**Starvation** (also called indefinite blocking) is a ready process that never
gets the processor because others are always preferred. **Ageing** is the fix:
the longer a process waits, the more its priority is raised, so eventually it is
the most important process in the queue and runs.

::flow{direction="horizontal" caption="Ageing: every 5 ms of waiting, the waiting process moves one step up."}
  :::flow-step{label="Waits at 4" icon="i-lucide-clock"}
  P2 arrives with the lowest priority.
  :::
  :::flow-step{label="Raised to 3" icon="i-lucide-arrow-up"}
  After 5 ms in the queue.
  :::
  :::flow-step{label="Raised to 2" icon="i-lucide-arrow-up"}
  After 10 ms.
  :::
  :::flow-step{label="Runs" icon="i-lucide-play" highlight}
  It now outranks newer arrivals, however many there are.
  :::

### Multilevel queues

Real systems combine the algorithms. A **multilevel queue** keeps separate ready
queues (say, interactive processes in one, batch jobs in another), each with its
own algorithm (Round Robin for interactive, FCFS for batch), and a priority
between the queues. A **multilevel feedback queue** also lets processes move
between queues: one that uses its whole slice is demoted (it looks like a long
batch job), one that waits too long is promoted (ageing). Most real schedulers
are variations of this.

## How it works

The shortest-first program from two lessons ago, with the choice changed from
"least time left" to "best priority":

```java [PriorityScheduler.java]
public class PriorityScheduler {
  public static void main(String[] args) {
    run(false);
    System.out.println();
    run(true);
  }

  static void run(boolean preemptive) {
    String[] name  = {"P1", "P2", "P3", "P4"};
    int[] arrival  = {0, 1, 2, 3};
    int[] burst    = {8, 4, 9, 5};
    int[] priority = {2, 4, 1, 3};                   // 1 is the highest
    int n = name.length;
    int[] left = burst.clone();
    int[] completion = new int[n];
    int time = 0, finished = 0, current = -1;
    StringBuilder gantt = new StringBuilder();
    String last = "";

    while (finished < n) {
      if (current == -1 || preemptive) {
        current = -1;
        for (int i = 0; i < n; i++) {
          boolean ready = arrival[i] <= time && left[i] > 0;
          if (ready && (current == -1 || priority[i] < priority[current])) current = i;
        }
      }
      if (current == -1) { time++; continue; }
      if (!name[current].equals(last)) {
        gantt.append(time).append(' ').append(name[current]).append(' ');
        last = name[current];
      }
      left[current]--;
      time++;
      if (left[current] == 0) { completion[current] = time; finished++; current = -1; }
    }
    gantt.append(time);

    System.out.println((preemptive ? "Pre-emptive" : "Non-pre-emptive") + "  Gantt: " + gantt);
    double totalWait = 0;
    for (int i = 0; i < n; i++) {
      int tat = completion[i] - arrival[i];
      totalWait += tat - burst[i];
      System.out.printf("%s  CT %2d  TAT %2d  WT %2d%n", name[i], completion[i], tat, tat - burst[i]);
    }
    System.out.printf("Average waiting: %.2f%n", totalWait / n);
  }
}
```

```text [Output]
Non-pre-emptive  Gantt: 0 P1 8 P3 17 P4 22 P2 26
P1  CT  8  TAT  8  WT  0
P2  CT 26  TAT 25  WT 21
P3  CT 17  TAT 15  WT  6
P4  CT 22  TAT 19  WT 14
Average waiting: 10.25

Pre-emptive  Gantt: 0 P1 2 P3 11 P1 17 P4 22 P2 26
P1  CT 17  TAT 17  WT  9
P2  CT 26  TAT 25  WT 21
P3  CT 11  TAT  9  WT  0
P4  CT 22  TAT 19  WT 14
Average waiting: 11.00
```

### All five, side by side

| Algorithm | Pre-emptive? | Avg waiting (this set) | Starvation? | Best for |
| --- | --- | --- | --- | --- |
| FCFS | No | 8.75 | No | Simple batch queues |
| SJF | No | 7.75 | Yes | Batch jobs with known lengths |
| SRTF | Yes | **6.50** | Yes | Minimum average wait, on paper |
| Round Robin (q = 4) | Yes | 11.75 | No | Interactive, time-sharing |
| Priority (non-pre-emptive) | No | 10.25 | Yes, unless ageing | Mixed importance |
| Priority (pre-emptive) | Yes | 11.00 | Yes, unless ageing | Real-time and real systems |

## Real use case

Every operating system exposes priorities. On Linux and macOS it is the **nice**
value, from -20 (most important) to 19 (least): the name is because a process
with a high nice value is being nice to everybody else.

```bash [Terminal]
# Run a big results export without slowing the rest of the server down.
nice -n 19 java -jar results-export.jar &

# See the nice value (NI) of running processes.
ps -o pid,ni,comm -p $!
```

```text [Output]
  PID  NI COMM
 9214  19 java
```

Java threads have priorities too (`Thread.setPriority`, 1 to 10), but the JVM
passes them to the operating system as hints and most systems largely ignore
them, which is a good detail to know if an interviewer asks you to "raise
the thread priority".

## What confuses people here

Which way the numbers go. In this chapter, and in Linux nice values, a smaller
number is more important. In Java's `Thread.setPriority`, 10 is the most
important. In exam questions it is whatever the question says. Read the question
twice before drawing anything.

A related trap is **priority inversion**: a high-priority process waits for a
lock held by a low-priority one, which cannot run because medium-priority
processes keep pre-empting it. The high-priority process is effectively stuck
behind the medium ones. The fix, **priority inheritance**, temporarily raises the
lock holder to the waiter's priority. It famously froze the Mars Pathfinder
lander's computer in 1997 until engineers turned inheritance on remotely.

## Interview questions

::accordion
  :::accordion-item{label="What is starvation and how do you prevent it?" icon="i-lucide-message-circle"}
  A ready process that never gets the processor because others are always
  chosen first (common with priority scheduling and SJF). Prevent it with
  **ageing**: gradually raise the priority of processes the longer they wait,
  until they are chosen.
  :::

  :::accordion-item{label="What is the difference between starvation and deadlock?" icon="i-lucide-message-circle"}
  In starvation the process could run and the system is making progress; it is
  never picked. In deadlock, a set of processes each wait for something
  another holds, and none of them can progress at all. Ageing fixes starvation;
  it does nothing for deadlock.
  :::

  :::accordion-item{label="What is a multilevel feedback queue?" icon="i-lucide-message-circle"}
  Several ready queues at different priorities, each with its own algorithm,
  where processes can move between them: a process that uses its full slice is
  moved down (it is processor-bound), one that waits too long is moved up
  (ageing). It approximates SJF without knowing burst times, and it is the basis
  of most real schedulers.
  :::

  :::accordion-item{label="What is priority inversion?" icon="i-lucide-message-circle"}
  A high-priority task waiting on a lock held by a low-priority task, while
  medium-priority tasks keep pre-empting the low one, so the high-priority task
  waits behind medium ones. Solved by priority inheritance: the lock holder
  temporarily runs at the waiter's priority.
  :::

  :::accordion-item{label="Compare FCFS, SJF, Round Robin and priority scheduling." icon="i-lucide-message-circle"}
  FCFS: simple, non-pre-emptive, convoy effect. SJF/SRTF: minimum average
  waiting time, needs burst times, can starve long jobs. Round Robin: fair, no
  starvation, good response, higher average waiting, quantum-sensitive.
  Priority: expresses importance, can starve, fixed with ageing. Give the
  numbers from one worked example if you have them.
  :::
::
