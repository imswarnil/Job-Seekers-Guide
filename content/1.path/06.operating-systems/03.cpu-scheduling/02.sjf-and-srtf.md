Run the shortest job available instead, and the average drops. That is
**shortest job first (SJF)**. Let it interrupt a running job when a shorter one
arrives, and it drops further: **shortest remaining time first (SRTF)**, which is
SJF made pre-emptive.

## Why this matters in a job

SRTF is the favourite of written rounds, because the pre-emption makes the Gantt
chart interesting and the arithmetic easy to get wrong. "Which algorithm gives
the minimum average waiting time?" is a one-line question with a one-word answer
(SJF, or SRTF if pre-emption is allowed), and the follow-up "so why does nobody
use it?" is where you earn the marks.

## Shortest first, and why it wins

Back at the photocopier. If the clerk serves the one-page students before the
thesis, five people wait a few seconds each and one person waits a bit longer.
Total waiting across the queue goes down, because every job that goes first
delays everybody behind it, and a short job delays them least.

The informal proof: swap a short job ahead of a long one. The long job now waits
an extra *short* burst, and the short job stops waiting a whole *long* burst. The
total waiting goes down every time you make that swap, so the order with every
short job ahead of every longer one has the minimum possible average waiting
time.

### SJF (non-pre-emptive), by hand

Same four processes as before: P1 (AT 0, BT 8), P2 (1, 4), P3 (2, 9), P4 (3, 5).

At time 0 only P1 has arrived, so it runs, and SJF does not interrupt it. At
time 8, P2, P3 and P4 are all waiting: pick the shortest, P2 (4). At 12, pick
between P3 (9) and P4 (5): P4. Then P3.

```text [Gantt chart, SJF]
|    P1    |  P2  |   P4   |     P3     |
0          8      12       17           26
```

| Process | AT | BT | CT | TAT | WT |
| --- | --- | --- | --- | --- | --- |
| P1 | 0 | 8 | 8 | 8 | 0 |
| P2 | 1 | 4 | 12 | 11 | 7 |
| P3 | 2 | 9 | 26 | 24 | 15 |
| P4 | 3 | 5 | 17 | 14 | 9 |

Average waiting = (0 + 7 + 15 + 9) / 4 = 31 / 4 = **7.75 ms** (FCFS was 8.75).

### SRTF (pre-emptive), by hand

Now the scheduler looks again **every time a process arrives**, and runs
whichever has the least time **remaining**.

::steps
### t = 0
Only P1 (remaining 8). P1 runs.

### t = 1
P2 arrives with 4. P1 has 7 left. 4 < 7, so **P1 is pre-empted** and P2 runs.

### t = 2
P3 arrives with 9. P2 has 3 left. P2 keeps running.

### t = 3
P4 arrives with 5. P2 has 2 left. P2 keeps running, and finishes at 5.

### t = 5
Remaining: P1 7, P3 9, P4 5. P4 runs to 10.

### t = 10
Remaining: P1 7, P3 9. P1 runs to 17, then P3 to 26.
::

```text [Gantt chart, SRTF]
|P1|  P2  |   P4   |     P1     |     P3     |
0  1      5        10           17           26
```

| Process | AT | BT | CT | TAT = CT - AT | WT = TAT - BT |
| --- | --- | --- | --- | --- | --- |
| P1 | 0 | 8 | 17 | 17 | 9 |
| P2 | 1 | 4 | 5 | 4 | 0 |
| P3 | 2 | 9 | 26 | 24 | 15 |
| P4 | 3 | 5 | 10 | 7 | 2 |

Average turnaround = 52 / 4 = **13 ms**. Average waiting = 26 / 4 = **6.5 ms**,
the lowest of any algorithm on this set.

::warning{icon="i-lucide-alert-triangle"}
P1's waiting time is 9, not 0, even though it started first. It ran for 1 ms,
waited from 1 to 10, then ran again. WT = TAT - BT handles that automatically,
which is why you compute it that way rather than trying to add up the gaps.
::

## How it works

One program for both. Every millisecond it picks the shortest remaining job;
with `preemptive` set to `false` it only picks when the processor is free.

```java [ShortestFirst.java]
public class ShortestFirst {
  public static void main(String[] args) {
    run(false);
    System.out.println();
    run(true);
  }

  static void run(boolean preemptive) {
    String[] name = {"P1", "P2", "P3", "P4"};
    int[] arrival = {0, 1, 2, 3};
    int[] burst   = {8, 4, 9, 5};
    int n = name.length;
    int[] left = burst.clone();
    int[] completion = new int[n];
    int time = 0, finished = 0, current = -1;
    StringBuilder gantt = new StringBuilder();
    String last = "";

    while (finished < n) {
      if (current == -1 || preemptive) {
        current = -1;
        for (int i = 0; i < n; i++) {
          boolean ready = arrival[i] <= time && left[i] > 0;
          if (ready && (current == -1 || left[i] < left[current])) current = i;
        }
      }
      if (current == -1) { time++; continue; }       // nobody has arrived: idle
      if (!name[current].equals(last)) {
        gantt.append(time).append(' ').append(name[current]).append(' ');
        last = name[current];
      }
      left[current]--;
      time++;
      if (left[current] == 0) {
        completion[current] = time;
        finished++;
        current = -1;
      }
    }
    gantt.append(time);

    System.out.println((preemptive ? "SRTF" : "SJF") + "  Gantt: " + gantt);
    double totalWait = 0;
    for (int i = 0; i < n; i++) {
      int tat = completion[i] - arrival[i];
      int wt = tat - burst[i];
      totalWait += wt;
      System.out.printf("%s  CT %2d  TAT %2d  WT %2d%n", name[i], completion[i], tat, wt);
    }
    System.out.printf("Average waiting: %.2f%n", totalWait / n);
  }
}
```

```text [Output]
SJF  Gantt: 0 P1 8 P2 12 P4 17 P3 26
P1  CT  8  TAT  8  WT  0
P2  CT 12  TAT 11  WT  7
P3  CT 26  TAT 24  WT 15
P4  CT 17  TAT 14  WT  9
Average waiting: 7.75

SRTF  Gantt: 0 P1 1 P2 5 P4 10 P1 17 P3 26
P1  CT 17  TAT 17  WT  9
P2  CT  5  TAT  4  WT  0
P3  CT 26  TAT 24  WT 15
P4  CT 10  TAT  7  WT  2
Average waiting: 6.50
```

## Real use case

The catch: **the scheduler does not know burst times.** A real operating system
cannot know how long a process will run before it runs. So pure SJF exists only
on paper. What real systems do is **predict** the next burst from past ones,
usually with an exponential average: next guess = a × last burst + (1 - a) ×
previous guess.

Where shortest-first appears for real is wherever the length *is* known in
advance. A college results service that generates marksheets in a queue can sort
the queue by page count:

```java [MarksheetQueue.java]
// Shortest job first: small departments' marksheets go out before the big ones.
PriorityQueue<MarksheetJob> queue =
    new PriorityQueue<>(Comparator.comparingInt(MarksheetJob::pageCount));

queue.add(new MarksheetJob("Mechanical", 1_200));
queue.add(new MarksheetJob("Library Science", 40));
queue.add(new MarksheetJob("Physics", 300));

while (!queue.isEmpty()) System.out.println(queue.poll().department());
```

```text [Output]
Library Science
Physics
Mechanical
```

## What confuses people here

**Starvation.** If short jobs keep arriving, a long job may never run under SJF
or SRTF: every time the scheduler looks, something shorter is waiting. The
average is excellent and one process waits forever. The fix is **ageing**, which
belongs to the priority lesson two lessons from now, and it is the answer to "so
why does nobody use SJF?" together with "nobody knows the burst times".

## Interview questions

::accordion
  :::accordion-item{label="Which scheduling algorithm gives the minimum average waiting time?" icon="i-lucide-message-circle"}
  SJF among non-pre-emptive algorithms, and SRTF (its pre-emptive version)
  overall, for a given set of processes. On this chapter's set: FCFS 8.75 ms,
  SJF 7.75 ms, SRTF 6.5 ms.
  :::

  :::accordion-item{label="Why is SJF not used directly in real operating systems?" icon="i-lucide-message-circle"}
  Two reasons. The burst time is not known in advance, so it has to be
  predicted (exponential averaging of past bursts). And long processes can
  starve if short ones keep arriving. Real schedulers use priorities with ageing
  and time slices instead.
  :::

  :::accordion-item{label="What is the difference between SJF and SRTF?" icon="i-lucide-message-circle"}
  SJF is non-pre-emptive: once a job starts it finishes. SRTF is pre-emptive:
  when a new process arrives with a shorter **remaining** time than the running
  one, the running one is interrupted. SRTF gives lower average waiting time but
  more context switches.
  :::

  :::accordion-item{label="Work SRTF for P1 (0, 8), P2 (1, 4), P3 (2, 9), P4 (3, 5)." icon="i-lucide-message-circle"}
  Gantt: P1 0-1, P2 1-5, P4 5-10, P1 10-17, P3 17-26. Waiting: P1 9, P2 0,
  P3 15, P4 2. Average 6.5 ms. Say out loud that you compute waiting as
  TAT - BT, which handles P1's split run correctly.
  :::
::

SRTF has the best average and a terrible property: a long job can wait forever,
and an interactive program might not respond for seconds. The fix every
time-sharing system uses is blunter and fairer: give everyone a turn of a fixed
length, and go round.
