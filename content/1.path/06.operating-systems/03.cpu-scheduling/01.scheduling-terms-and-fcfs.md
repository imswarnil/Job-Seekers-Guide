The scheduler chooses from the ready queue, and there are a handful of standard
ways to choose. Before any of them makes sense you need six words and two
formulas, and then the simplest scheduler of all: whoever arrived first goes
first.

## Why this matters in a job

Scheduling is the one operating systems topic that is asked **as arithmetic**.
A written round or a technical interviewer gives you four processes with arrival
and burst times and asks for the Gantt chart and the average waiting time. It
takes three minutes once you have done it a few times and is a disaster if you
have not. At work, the same ideas decide how a job queue, a thread pool or a
batch of nightly reports is ordered, and why one slow job can hold up everything
behind it.

## The words, then first come first served

Think of the one photocopier in the college office. Students arrive with
different amounts to copy. The clerk serves them in the order they arrived, and
one student with a 300-page thesis makes five students with one page each wait
twenty minutes. That is FCFS, and that unhappiness has a name, which we will get
to.

The terms every scheduling question uses:

| Term | Meaning | Formula |
| --- | --- | --- |
| **Arrival time (AT)** | When the process enters the ready queue | given |
| **Burst time (BT)** | How much processor time it needs | given |
| **Completion time (CT)** | When it finishes | read off the Gantt chart |
| **Turnaround time (TAT)** | Total time from arrival to finish | TAT = CT - AT |
| **Waiting time (WT)** | Time spent in the ready queue, not running | WT = TAT - BT |
| **Response time (RT)** | Time from arrival until it first gets the processor | RT = first start - AT |

And the two kinds of scheduler:

::compare{caption="The one property that decides which formulas and traps apply."}
  :::compare-side{label="Non-pre-emptive" verdict="neutral"}
  Once a process gets the processor, it keeps it until it finishes or blocks.
  FCFS, SJF and non-pre-emptive priority.
  :::
  :::compare-side{label="Pre-emptive" verdict="neutral"}
  The scheduler can take the processor away mid-burst: when a time slice ends or
  a more deserving process arrives. SRTF, Round Robin, pre-emptive priority.
  :::
::

What a good scheduler tries to do: keep **CPU utilisation** high, maximise
**throughput** (processes finished per second), and minimise turnaround,
waiting and response time. No algorithm wins all five, which is the point of
learning several.

### FCFS by hand

First come, first served: run them in arrival order, each to completion.

```text [Gantt chart, FCFS]
|    P1    |  P2  |     P3     |   P4   |
0          8      12           21       26
```

Now the table. Read CT off the chart, then TAT = CT - AT, then WT = TAT - BT.

| Process | AT | BT | CT | TAT = CT - AT | WT = TAT - BT |
| --- | --- | --- | --- | --- | --- |
| P1 | 0 | 8 | 8 | 8 - 0 = 8 | 8 - 8 = 0 |
| P2 | 1 | 4 | 12 | 12 - 1 = 11 | 11 - 4 = 7 |
| P3 | 2 | 9 | 21 | 21 - 2 = 19 | 19 - 9 = 10 |
| P4 | 3 | 5 | 26 | 26 - 3 = 23 | 23 - 5 = 18 |

Average turnaround = (8 + 11 + 19 + 23) / 4 = 61 / 4 = **15.25 ms**.
Average waiting = (0 + 7 + 10 + 18) / 4 = 35 / 4 = **8.75 ms**.

## How it works

The same calculation in Java, so you can check any answer you work by hand.
Change the arrays and run it again.

```java [Fcfs.java]
public class Fcfs {
  public static void main(String[] args) {
    String[] name  = {"P1", "P2", "P3", "P4"};
    int[] arrival  = {0, 1, 2, 3};             // must be sorted by arrival
    int[] burst    = {8, 4, 9, 5};

    int time = 0;
    double totalTat = 0, totalWait = 0;
    System.out.println("Job  AT  BT  CT  TAT  WT");
    for (int i = 0; i < name.length; i++) {
      time = Math.max(time, arrival[i]);       // processor may sit idle until it arrives
      time += burst[i];                        // runs to completion: non-pre-emptive
      int completion = time;
      int turnaround = completion - arrival[i];
      int waiting    = turnaround - burst[i];
      totalTat += turnaround;
      totalWait += waiting;
      System.out.printf("%-4s %2d  %2d  %2d  %3d  %2d%n",
          name[i], arrival[i], burst[i], completion, turnaround, waiting);
    }
    System.out.printf("Average turnaround: %.2f%n", totalTat / name.length);
    System.out.printf("Average waiting:    %.2f%n", totalWait / name.length);
  }
}
```

```text [Output]
Job  AT  BT  CT  TAT  WT
P1    0   8   8    8   0
P2    1   4  12   11   7
P3    2   9  21   19  10
P4    3   5  26   23  18
Average turnaround: 15.25
Average waiting:    8.75
```

The `Math.max` line matters: if the next process has not arrived yet, the
processor sits idle and the clock jumps forward. Forgetting idle time is the most
common arithmetic slip in written rounds.

### The convoy effect

FCFS has one famous weakness. When a long process arrives first, every short
process behind it waits the full length of the long one, like cars stuck behind
a lorry on a single-lane road. That is the **convoy effect**. Put P3 (burst 9)
first in the queue and the three short ones all wait at least 9 ms before
starting, even though they needed 17 ms between them.

## Real use case

Any plain queue is FCFS. A Java `ExecutorService` with one thread runs its tasks
in exactly the order they were submitted:

```java [NightlyJobs.java]
ExecutorService nightly = Executors.newSingleThreadExecutor();
nightly.submit(() -> exportAllResults());      // 40 minutes
nightly.submit(() -> sendFeeReminders());      // 30 seconds
nightly.submit(() -> refreshAttendanceView()); // 10 seconds
```

The reminders and the attendance view wait forty minutes behind the export: a
convoy. The usual fixes are the ideas in the rest of this chapter: run the short
jobs first, give each job a slice of time, or split into two queues with
different priorities.

## What confuses people here

Mixing up the three times. **Turnaround** is the whole stay, arrival to finish.
**Waiting** is only the time spent ready but not running. **Response** is only
the time until the first run. In a non-pre-emptive scheduler like FCFS, waiting
time and response time are the same number, because once a process starts it
never waits again. In a pre-emptive one they are not.

## Interview questions

::accordion
  :::accordion-item{label="Define turnaround time, waiting time and response time." icon="i-lucide-message-circle"}
  Turnaround = completion - arrival: the whole stay. Waiting = turnaround -
  burst: time ready but not running. Response = first start - arrival: how long
  until it first ran. Response matters most for interactive programs; turnaround
  for batch jobs.
  :::

  :::accordion-item{label="What is the difference between pre-emptive and non-pre-emptive scheduling?" icon="i-lucide-message-circle"}
  Non-pre-emptive: a process keeps the processor until it finishes or blocks
  (FCFS, SJF). Pre-emptive: the scheduler can take it away when a time slice ends
  or a higher-priority process arrives (Round Robin, SRTF). Every modern desktop
  and server operating system is pre-emptive, which is why a runaway loop in one
  program does not freeze the machine.
  :::

  :::accordion-item{label="What is the convoy effect?" icon="i-lucide-message-circle"}
  In FCFS, a long process at the front makes every short one behind it wait its
  whole burst, so average waiting time is high and devices sit idle while the
  short I/O-heavy processes queue. SJF and Round Robin both avoid it.
  :::

  :::accordion-item{label="What are the goals of CPU scheduling?" icon="i-lucide-message-circle"}
  High CPU utilisation and throughput; low turnaround, waiting and response
  time; and fairness, so nothing starves. They conflict: the order that minimises
  average waiting time (shortest first) is the one that can starve long jobs.
  :::

  :::accordion-item{label="What are the long-term, short-term and medium-term schedulers?" icon="i-lucide-message-circle"}
  The **long-term** scheduler decides which new jobs are admitted to memory
  (controls how many processes exist). The **short-term** (CPU) scheduler picks
  which ready process runs next, many times a second. The **medium-term**
  scheduler swaps processes out of memory and back in when memory is tight. When
  interviewers say "the scheduler" they mean the short-term one.
  :::
::
