Give everyone a turn of fixed length and go round. That is **Round Robin (RR)**:
each process runs for at most one **time quantum** (also called a time slice),
and if it has not finished it goes to the back of the ready queue. Nobody starves
and nobody waits long for a first turn, which is exactly what an interactive
machine needs.

## Why this matters in a job

Round Robin is the scheduling question interviewers ask most after FCFS, because
the queue order makes it easy to get wrong and it connects directly to real
systems: every time-sharing operating system is built on time slices, and "what
happens if the quantum is too small or too large" is a favourite follow-up.

## Taking turns

Think of the viva queue at the end of a lab exam. The examiner gives each student
four minutes. If you are not finished, you go to the back of the line and wait
for another turn. A student who needs two minutes is done in one visit; a
student who needs ten comes round three times. Nobody waits for one slow student
to finish completely.

The rules, precisely:

1. Processes wait in a first-in, first-out **ready queue**.
2. The one at the front runs for up to one quantum `q`.
3. If it finishes inside the quantum, it leaves and the next one starts at once.
4. If not, it is pre-empted and goes to the **back** of the queue.
5. **Tie rule:** if a new process arrives at the same moment a process is
   pre-empted, the new arrival joins the queue first. (State the convention you
   use in an exam; this is the common one.)

### Round Robin by hand, quantum 4

Same four processes: P1 (AT 0, BT 8), P2 (1, 4), P3 (2, 9), P4 (3, 5).

::steps
### 0 to 4: P1 runs
While it runs, P2, P3 and P4 arrive. Queue after it is pre-empted:
P2, P3, P4, **P1** (4 left).

### 4 to 8: P2 runs, finishes
P2 needed exactly 4. Queue: P3, P4, P1.

### 8 to 12: P3 runs
5 left. Queue: P4, P1, P3.

### 12 to 16: P4 runs
1 left. Queue: P1, P3, P4.

### 16 to 20: P1 runs, finishes
Queue: P3, P4.

### 20 to 24: P3 runs
1 left. Queue: P4, P3.

### 24 to 25: P4 finishes. 25 to 26: P3 finishes.
::

```text [Gantt chart, Round Robin, q = 4]
|  P1  |  P2  |  P3  |  P4  |  P1  |  P3  |P4|P3|
0      4      8      12     16     20     24 25 26
```

| Process | AT | BT | CT | TAT = CT - AT | WT = TAT - BT | RT = first start - AT |
| --- | --- | --- | --- | --- | --- | --- |
| P1 | 0 | 8 | 20 | 20 | 12 | 0 |
| P2 | 1 | 4 | 8 | 7 | 3 | 3 |
| P3 | 2 | 9 | 26 | 24 | 15 | 6 |
| P4 | 3 | 5 | 25 | 22 | 17 | 9 |

Average waiting = 47 / 4 = **11.75 ms**, worse than FCFS (8.75). Average
**response** = 18 / 4 = **4.5 ms**, far better than FCFS (8.75). That trade is
the whole point of Round Robin: nobody's first response is delayed by somebody
else's long job.

## How it works

A queue does all the work. `ArrayDeque` is Java's ordinary first-in, first-out
queue.

```java [RoundRobin.java]
import java.util.ArrayDeque;

public class RoundRobin {
  public static void main(String[] args) {
    String[] name = {"P1", "P2", "P3", "P4"};
    int[] arrival = {0, 1, 2, 3};                  // sorted by arrival
    int[] burst   = {8, 4, 9, 5};
    int quantum = 4, n = name.length;

    int[] left = burst.clone();
    int[] completion = new int[n];
    ArrayDeque<Integer> ready = new ArrayDeque<>();
    int time = 0, nextArrival = 0;
    StringBuilder gantt = new StringBuilder("Gantt: ");

    while (nextArrival < n && arrival[nextArrival] <= time) ready.add(nextArrival++);

    while (!ready.isEmpty()) {
      int p = ready.poll();
      int slice = Math.min(quantum, left[p]);
      gantt.append(time).append(' ').append(name[p]).append(' ');
      time += slice;
      left[p] -= slice;

      // New arrivals join the queue before the process that was pre-empted.
      while (nextArrival < n && arrival[nextArrival] <= time) ready.add(nextArrival++);

      if (left[p] > 0) ready.add(p);
      else completion[p] = time;

      if (ready.isEmpty() && nextArrival < n) {    // processor idle until next arrival
        time = arrival[nextArrival];
        ready.add(nextArrival++);
      }
    }
    System.out.println(gantt.append(time));

    double totalWait = 0;
    for (int i = 0; i < n; i++) {
      int tat = completion[i] - arrival[i];
      totalWait += tat - burst[i];
      System.out.printf("%s  CT %2d  TAT %2d  WT %2d%n", name[i], completion[i], tat, tat - burst[i]);
    }
    System.out.printf("Average waiting: %.2f%n", totalWait / n);
  }
}
```

```text [Output]
Gantt: 0 P1 4 P2 8 P3 12 P4 16 P1 20 P3 24 P4 25 P3 26
P1  CT 20  TAT 20  WT 12
P2  CT  8  TAT  7  WT  3
P3  CT 26  TAT 24  WT 15
P4  CT 25  TAT 22  WT 17
Average waiting: 11.75
```

Change `quantum` to 100 and run it again: the output becomes FCFS exactly,
because every process finishes inside its first slice.

### The size of the quantum

::compare{caption="The quantum is the one knob, and both extremes are bad."}
  :::compare-side{label="Too large" verdict="wrong"}
  Every process finishes in its first slice, so Round Robin **becomes FCFS**,
  convoy effect and all.
  :::
  :::compare-side{label="Too small" verdict="wrong"}
  The processor spends more time context switching than running anything. A
  quantum of 1 ms with a 0.1 ms switch wastes about 9% of the machine on
  switching alone.
  :::
::

The usual guidance: make the quantum longer than most processes' typical burst
(so most finish in one go), and much longer than a context switch. Real systems
use somewhere around 10 to 100 ms.

## Real use case

Linux's default scheduler is not textbook Round Robin, but it is built on the
same idea: every runnable process gets a share of the processor in turn, and
nobody gets it for long. Java's own `Thread.yield()` is a program volunteering
to end its slice early.

The same pattern appears in application code whenever many clients share one
worker. A college exam portal that has to grade uploaded answer sheets for
several courses at once can take a batch from each course in turn, so one course
with 3,000 uploads cannot hold every other course's results back:

```java [GradingWorker.java]
ArrayDeque<Course> courses = new ArrayDeque<>(coursesWithPendingSheets());
int batch = 50;                                    // the "quantum", in answer sheets

while (!courses.isEmpty()) {
  Course c = courses.poll();
  gradeNext(c, batch);                             // at most 50 sheets, then yield
  if (c.hasPendingSheets()) courses.add(c);        // back of the queue
}
```

## What confuses people here

The queue order at the moment of pre-emption. At time 4, P1's slice ends and
P2, P3 and P4 have already arrived. P1 goes **behind** them, not in front of
them. If a process arrives at exactly the instant another is pre-empted, the
arrival goes first under the usual convention. Most wrong RR answers are wrong
at exactly this step, so write the queue down after every slice, as in the steps
above.

## Interview questions

::accordion
  :::accordion-item{label="Explain Round Robin scheduling." icon="i-lucide-message-circle"}
  Pre-emptive FCFS with a time quantum. Each process runs for at most one
  quantum, then goes to the back of the ready queue if unfinished. No starvation,
  good response time, designed for time-sharing systems. Average waiting time is
  usually higher than SJF.
  :::

  :::accordion-item{label="What happens if the time quantum is very large or very small?" icon="i-lucide-message-circle"}
  Very large: it degenerates into FCFS. Very small: context-switch overhead
  dominates and throughput collapses. The quantum should be larger than most
  CPU bursts and much larger than the switch time.
  :::

  :::accordion-item{label="Why is Round Robin good for interactive systems?" icon="i-lucide-message-circle"}
  Because response time is bounded: with n processes and quantum q, no process
  waits more than (n - 1) × q for its next turn. On this chapter's set, average
  response time was 4.5 ms against 8.75 ms for FCFS.
  :::

  :::accordion-item{label="Can Round Robin cause starvation?" icon="i-lucide-message-circle"}
  No. Every process in the queue gets a turn within one full round. That is its
  main advantage over SJF, SRTF and plain priority scheduling.
  :::
::
