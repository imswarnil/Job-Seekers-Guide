Thirty-two questions, grouped the way an interviewer moves through the subject:
from "what is an operating system" to processes, scheduling, synchronisation,
deadlock, memory and files. Answer each one out loud before opening it. Aim for
under a minute: the definition in one sentence, then one example or consequence.

## Why this matters in a job

In a service-company technical round, operating systems is usually three to
five questions, and they are almost always from this list. In a product-company
round they are fewer but deeper, and the follow-up to each answer is "why?". The
answers below are written so the "why" is already in them.

## Interview questions

### The basics

::accordion
  :::accordion-item{label="1. What is an operating system? What are its functions?" icon="i-lucide-message-circle"}
  The program that runs other programs and manages the hardware for them. Four
  jobs: share the processor (scheduling), hand out memory, own the devices and
  files, and keep programs apart (protection). Example of the last: `permission
  denied` is the kernel refusing a request, not the command refusing you.
  :::

  :::accordion-item{label="2. What is the kernel, and what is the difference between user mode and kernel mode?" icon="i-lucide-message-circle"}
  The kernel is the core of the operating system, running in kernel mode where
  every instruction is allowed. Programs run in user mode, where instructions
  that touch hardware do not execute, so they must ask the kernel via system
  calls. It is a processor feature, which is why a crashing program cannot take
  down the machine.
  :::

  :::accordion-item{label="3. What is a system call? Give examples." icon="i-lucide-message-circle"}
  The mechanism by which a program requests a kernel service: a trap
  instruction switches to kernel mode, the kernel does the work and returns.
  `open`, `read`, `write`, `close`, `fork`, `exec`, `wait`, `exit`, `kill`. Each
  costs around a microsecond, which is why buffered I/O is so much faster.
  :::

  :::accordion-item{label="4. What types of operating systems are there?" icon="i-lucide-message-circle"}
  Batch (jobs run one after another, no interaction), multiprogramming (several
  in memory so the processor is never idle), time-sharing / multitasking
  (processes take turns fast enough to feel simultaneous), real-time (guaranteed
  response deadlines, as in medical or car systems), distributed and embedded.
  Linux, Windows and macOS are multitasking; Android and iOS are mobile systems.
  :::
::

### Processes and threads

::accordion
  :::accordion-item{label="5. What is the difference between a process and a thread?" icon="i-lucide-message-circle"}
  A process has its own memory, files and resources. Threads are units of
  execution within a process: each has its own stack, registers and program
  counter, and all share the heap, code and open files. Threads are cheaper to
  create and switch, and communicate through shared memory, which is why a
  shared mutable field is a race condition and one crashing thread kills the
  whole process.
  :::

  :::accordion-item{label="6. Draw the process state diagram." icon="i-lucide-message-circle"}
  New → ready (admitted), ready → running (dispatched), running → ready
  (pre-empted or time slice over), running → waiting (I/O or event request),
  waiting → ready (I/O done), running → terminated (exit). Waiting never goes
  straight to running.
  :::

  :::accordion-item{label="7. What is a PCB?" icon="i-lucide-message-circle"}
  Process control block: the kernel's data structure for one process, holding
  pid, state, program counter, registers, scheduling information, memory
  information, open files and accounting. It is what makes a context switch
  possible. Linux calls it `task_struct`.
  :::

  :::accordion-item{label="8. What is a context switch, and why is it overhead?" icon="i-lucide-message-circle"}
  Saving the running process's state to its PCB and loading another's. No
  useful work happens during it, and afterwards the caches and TLB are cold for
  the new process. That is why 2,000 threads on 8 cores run slower than 8.
  :::

  :::accordion-item{label="9. What are zombie and orphan processes?" icon="i-lucide-message-circle"}
  Zombie: finished, but the parent has not read its exit status with `wait`;
  only a process-table entry remains. Orphan: still running, but its parent has
  exited; it is adopted by process 1, which reaps it.
  :::
::

### CPU scheduling

::accordion
  :::accordion-item{label="10. Define turnaround time, waiting time and response time." icon="i-lucide-message-circle"}
  Turnaround = completion - arrival. Waiting = turnaround - burst. Response =
  first time on the processor - arrival. For non-pre-emptive algorithms waiting
  and response are equal.
  :::

  :::accordion-item{label="11. Explain FCFS, SJF, SRTF, Round Robin and priority scheduling." icon="i-lucide-message-circle"}
  FCFS: arrival order, non-pre-emptive, convoy effect. SJF: shortest burst
  first, non-pre-emptive, minimum average wait but needs burst times. SRTF:
  pre-emptive SJF on remaining time. Round Robin: fixed quantum in turn, fair,
  good response. Priority: most important first, can starve low priorities. On
  P1 (0, 8), P2 (1, 4), P3 (2, 9), P4 (3, 5): average waiting FCFS 8.75, SJF
  7.75, SRTF 6.5, RR (q = 4) 11.75 ms.
  :::

  :::accordion-item{label="12. What is the difference between pre-emptive and non-pre-emptive scheduling?" icon="i-lucide-message-circle"}
  Pre-emptive: the scheduler can take the processor away from a running process
  (time slice ends, higher priority arrives). Non-pre-emptive: a process keeps
  it until it finishes or blocks. Modern operating systems are pre-emptive.
  :::

  :::accordion-item{label="13. What is starvation and how is it solved?" icon="i-lucide-message-circle"}
  A process waiting indefinitely because others are always chosen first,
  typical of priority scheduling and SJF. Solved by ageing: gradually increase
  the priority of waiting processes.
  :::

  :::accordion-item{label="14. What happens if the Round Robin quantum is too large or too small?" icon="i-lucide-message-circle"}
  Too large: it becomes FCFS. Too small: most time goes on context switches.
  The quantum should be larger than a typical burst and much larger than the
  switch cost.
  :::
::

### Synchronisation

::accordion
  :::accordion-item{label="15. What is a race condition? Give an example." icon="i-lucide-message-circle"}
  When the result depends on the order threads run. `count++` is read, add,
  write; two threads can both read 4,100 and both write 4,101, losing one
  increment. Fix with a lock, an atomic, or by not sharing.
  :::

  :::accordion-item{label="16. What is the critical section problem? State its requirements." icon="i-lucide-message-circle"}
  Ensuring only one thread at a time runs the code that touches shared data.
  A solution must give mutual exclusion, progress (a free critical section is
  granted to a waiting thread without indefinite postponement) and bounded
  waiting (a limit on how often others overtake a waiter).
  :::

  :::accordion-item{label="17. What is a semaphore? Binary vs counting?" icon="i-lucide-message-circle"}
  An integer accessed only through atomic `wait` (P: decrement, block at zero)
  and `signal` (V: increment, wake a waiter). Binary: 0 or 1, one at a time.
  Counting: 0 to N, for N identical resources such as connections.
  :::

  :::accordion-item{label="18. What is the difference between a mutex and a semaphore?" icon="i-lucide-message-circle"}
  A mutex is a lock with ownership: only the thread that locked it unlocks it.
  A semaphore is a signalling counter with no owner: any thread may signal. Use
  a mutex to protect data, a semaphore to limit concurrency or to signal events.
  :::

  :::accordion-item{label="19. Solve producer-consumer with semaphores." icon="i-lucide-message-circle"}
  `empty = N`, `full = 0`, `mutex = 1`. Producer: wait(empty), wait(mutex), add,
  signal(mutex), signal(full). Consumer: wait(full), wait(mutex), remove,
  signal(mutex), signal(empty). Swapping the producer's two waits can deadlock
  when the buffer is full. In Java, `ArrayBlockingQueue` does all of this.
  :::
::

### Deadlock

::accordion
  :::accordion-item{label="20. What is a deadlock? What are the necessary conditions?" icon="i-lucide-message-circle"}
  A set of processes each waiting for a resource another holds, so none
  proceeds. Conditions (all four needed): mutual exclusion, hold and wait, no
  pre-emption, circular wait.
  :::

  :::accordion-item{label="21. How can deadlocks be handled?" icon="i-lucide-message-circle"}
  Prevention (break a condition, e.g. lock ordering for circular wait),
  avoidance (grant requests only into safe states: banker's algorithm),
  detection and recovery (find cycles, kill or roll back a victim, as databases
  do), or ignoring them (ostrich algorithm).
  :::

  :::accordion-item{label="22. Explain the banker's algorithm." icon="i-lucide-message-circle"}
  Each process declares a maximum. Need = Max - Allocation. A request is granted
  only if it is within Need and Available and, after pretending to grant it, a
  safe sequence still exists: repeatedly find a process whose Need fits in Work,
  add its Allocation to Work. Classic example with Available 3 3 2 gives the
  safe sequence P1, P3, P4, P0, P2.
  :::

  :::accordion-item{label="23. Deadlock vs starvation?" icon="i-lucide-message-circle"}
  Deadlock: circular waiting, no process in the set can ever proceed. Starvation:
  the system progresses but one process is always passed over. Ageing fixes
  starvation, not deadlock.
  :::
::

### Memory

::accordion
  :::accordion-item{label="24. What is paging? How is an address translated?" icon="i-lucide-message-circle"}
  Logical memory in fixed-size pages, physical memory in equal frames, a
  per-process page table mapping one to the other. Address = (page number,
  offset); physical = frame × page size + offset. With 1 KB pages and page 3 in
  frame 7, logical 3500 → page 3, offset 428 → 7 × 1024 + 428 = 7596.
  :::

  :::accordion-item{label="25. Internal vs external fragmentation? Paging vs segmentation?" icon="i-lucide-message-circle"}
  Internal: waste inside allocated blocks (paging's last page). External: free
  memory split into unusable holes (contiguous allocation, segmentation).
  Paging uses fixed invisible pages and removes external fragmentation;
  segmentation uses variable logical segments with base and limit.
  :::

  :::accordion-item{label="26. What is virtual memory? What is demand paging?" icon="i-lucide-message-circle"}
  Every address a program uses is virtual and translated by hardware through a
  per-process page table, giving isolation and address spaces larger than RAM.
  Demand paging loads a page only when it is first accessed, via a page fault.
  It is not "using the disk as RAM"; that is swap.
  :::

  :::accordion-item{label="27. What is a page fault, and what does the OS do?" icon="i-lucide-message-circle"}
  An access to a page not in memory. The MMU traps to the kernel, which checks
  the address is valid (else segmentation fault), finds a frame (evicting a
  page if needed), reads the page from disk, updates the page table, and
  restarts the instruction.
  :::

  :::accordion-item{label="28. Compare FIFO, LRU and Optimal. What is Belady's anomaly?" icon="i-lucide-message-circle"}
  FIFO evicts the oldest-loaded page, LRU the least recently used, Optimal the
  one not needed for the longest time (unimplementable, the benchmark). On 7, 0,
  1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2 with three frames: 10, 9 and 7 faults.
  Belady's anomaly: more frames, more faults, possible with FIFO (1, 2, 3, 4, 1,
  2, 5, 1, 2, 3, 4, 5 gives 9 faults with 3 frames and 10 with 4).
  :::

  :::accordion-item{label="29. What is thrashing, and how do you prevent it?" icon="i-lucide-message-circle"}
  The system spending more time paging than executing because working sets do
  not fit in memory; CPU use collapses while disk activity peaks. Prevent it by
  reducing the degree of multiprogramming, the working-set model, page-fault
  frequency control and local replacement; in code, by shrinking the working
  set (stream, do not load everything).
  :::
::

### Files

::accordion
  :::accordion-item{label="30. What is an inode? Hard link vs soft link?" icon="i-lucide-message-circle"}
  The record of a file: type, size, owner, permissions, timestamps, link count
  and data-block pointers, everything except the name. A hard link is another
  name for the same inode and survives deletion of the original name; a soft
  link is a file containing a path and dangles if the target goes.
  :::

  :::accordion-item{label="31. Explain contiguous, linked and indexed file allocation." icon="i-lucide-message-circle"}
  Contiguous: consecutive blocks, fast but external fragmentation and hard to
  grow. Linked: each block points to the next, no external fragmentation but
  slow random access (FAT keeps the links in a table). Indexed: an index block
  lists all blocks, fast random access; Unix inodes use direct and indirect
  pointers, about 4 TB maximum with 4 KB blocks.
  :::

  :::accordion-item{label="32. How do Linux file permissions work? What is chmod 755?" icon="i-lucide-message-circle"}
  Owner, group and other, each with read (4), write (2), execute (1), checked in
  that order with first match winning. 755 is rwx for the owner and r-x for
  everyone else. Execute on a directory means traverse. Fix access problems with
  `chown`, never `chmod 777`.
  :::
::

## Real use case

The best preparation I know is to record yourself. Pick five questions at
random, set a one-minute timer each, answer out loud into your phone, and listen
back. You will hear exactly where you hesitate. Do it every day for a week and
the operating systems round stops being the part you hope they skip.

## What confuses people here

Answering the question you prepared instead of the one asked. "What is the
difference between a process and a thread?" and "what does a thread share with
its process?" sound the same and want different emphasis. Listen to the last
few words of the question, and start your answer with them.
