Every variable in JavaScript starts with one of three words, and Java had only
the equivalent of two. The third one, `var`, is the oldest, the strangest, and
the reason for half the output-prediction questions you will be asked.

## Why this matters in a job

At work you will write `const` most of the time and `let` sometimes, and a code
reviewer will ask you to change any `let` that is never reassigned. You will
read `var` in older code, especially anything written before 2015. In an
interview, "what is the difference between `var`, `let` and `const`?" is close
to the first JavaScript question on every list, and the follow-ups (scope,
hoisting, the loop bug) all start here.

## Three labels on three kinds of box

Think of a hostel room with a name label on the door.

- `const` is a label that is **glued on**. It points at one thing forever. The
  thing itself can still be rearranged inside (a bed moved, a poster added), but
  the label cannot be moved to another room.
- `let` is a label that can be **peeled off and moved**, but only inside the
  corridor where it was put up. Leave the corridor and the label is not there.
- `var` is a label that can be moved, and that belongs to the **whole floor**,
  not the corridor. It leaks out of corridors, and it is visible from the
  staircase before anyone has written on it.

In real terms:

| | `var` | `let` | `const` |
| --- | --- | --- | --- |
| Scope | Function | Block `{ }` | Block `{ }` |
| Reassign | Yes | Yes | No |
| Redeclare in the same scope | Yes | No, a `SyntaxError` | No, a `SyntaxError` |
| Use before the line | `undefined` | `ReferenceError` | `ReferenceError` |
| Must be given a value | No | No | Yes |

**Scope** means the region of code where a name can be seen. A **block** is
anything between `{` and `}`: an `if`, a loop, or a bare pair of braces. A
**function scope** is the whole body of a function, however many blocks it
contains.

## How it works

```javascript [scope.js]
function checkAttendance() {
  if (true) {
    var fromVar = "visible outside the if";
    let fromLet = "only inside the if";
    const fromConst = "only inside the if";
  }
  console.log(fromVar);
  console.log(typeof fromLet);    // typeof does not throw for an unknown name
}
checkAttendance();

// Reassignment against mutation.
const student = { name: "Anita", marks: [78] };
student.marks.push(82);           // allowed: changing the object
console.log(student.marks.length);

try {
  student = { name: "Vikram" };   // not allowed: moving the label
} catch (error) {
  console.log(error.name + ": " + error.message);
}

// Using a let before its line.
try {
  console.log(course);
} catch (error) {
  console.log(error.name + ": " + error.message);
}
let course = "DBMS";

// var before its line is not an error, only undefined.
console.log(String(semester));
var semester = 5;
console.log(semester);
```

```text [Output]
visible outside the if
undefined
2
TypeError: Assignment to constant variable.
ReferenceError: Cannot access 'course' before initialization
undefined
5
```

The error messages are Chrome's wording; Firefox says the same thing in
different words.

Redeclaring is the one you cannot run, because it stops the whole file before a
single line executes:

```javascript [redeclare.js]
var seats = 60;
var seats = 30;        // fine with var: quietly overwrites

let intake = 60;
let intake = 30;       // SyntaxError: Identifier 'intake' has already been declared
```

## Real use case

In a real codebase the convention is short: **`const` by default, `let` when
you must reassign, never `var`.** Linters (tools that read your code and flag
problems, such as ESLint) enforce it with rules called `prefer-const` and
`no-var`. The reason is reading, not speed: when you see `const`, you know the
name means the same thing on line 200 as on line 3.

```javascript [attendance-report.js]
const PASS_ATTENDANCE = 75;                    // a constant nobody should change
const records = [92, 64, 81, 70, 88];          // the array itself is never replaced

let below = 0;                                 // a counter: it must be reassigned
for (const pct of records) {                   // const works here: a new binding each time
  if (pct < PASS_ATTENDANCE) below++;
}
console.log(`${below} of ${records.length} students are below ${PASS_ATTENDANCE}%`);

// If you need an object that genuinely cannot change, freeze it.
const rules = Object.freeze({ passMark: 40 });
rules.passMark = 30;                           // ignored (an error in strict mode)
console.log(rules.passMark);
```

```text [Output]
2 of 5 students are below 75%
40
```

## What confuses people here

That `const` means "constant value". It means **constant binding**: the name
cannot be pointed at something else. An object or array held in a `const` can
be changed freely. If you need the contents locked, that is `Object.freeze`,
and even that only freezes the top level.

The second trap: `for (const i = 0; i < 3; i++)` fails, because `i++`
reassigns. `for (const pct of records)` works, because each pass of a `for...of`
loop makes a fresh `pct`.

## Interview questions

::accordion
  :::accordion-item{label="What is the difference between var, let and const?" icon="i-lucide-message-circle"}
  Three differences, in the order to say them. **Scope:** `var` is function
  scoped, `let` and `const` are block scoped. **Reassignment:** `var` and `let`
  can be reassigned, `const` cannot. **Hoisting:** all three are hoisted, but
  `var` starts as `undefined` while `let` and `const` sit in the temporal dead
  zone and throw a `ReferenceError` if used early. Prove the scope one:

  ```javascript
  if (true) { var a = 1; let b = 2; }
  console.log(a);          // 1
  console.log(typeof b);   // "undefined": b does not exist out here
  ```
  :::

  :::accordion-item{label="Can you change an object declared with const?" icon="i-lucide-message-circle"}
  Yes. `const` stops reassignment of the variable, not changes to the object.
  `const s = { mark: 70 }; s.mark = 80;` works. `s = {}` throws
  `TypeError: Assignment to constant variable.` To stop changes to the object,
  use `Object.freeze(s)`, which is shallow: nested objects can still change.
  :::

  :::accordion-item{label="Why should you not use var?" icon="i-lucide-message-circle"}
  It ignores blocks, so a variable declared inside an `if` or a loop leaks into
  the whole function. It can be redeclared silently. It is `undefined` before
  its line instead of an error. And at the top level of a script it becomes a
  property of `window`. Each of those hides a bug that `let` would have
  reported.
  :::

  :::accordion-item{label="What does this print? var x = 1; { var x = 2; } console.log(x);" icon="i-lucide-message-circle"}
  `2`. The braces are a block, and `var` ignores blocks, so both lines refer to
  the same `x`. With `let` in both places it prints `1`, because the inner
  `let x` is a different variable that exists only inside the braces.
  :::
::
