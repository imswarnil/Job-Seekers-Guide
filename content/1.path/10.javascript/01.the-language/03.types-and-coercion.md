A variable has no type in JavaScript, but a **value** always does. `let score`
can hold anything; the thing it holds right now is a number, or a string, or
nothing. This lesson is the list of what it can be, and what happens when two
different kinds meet.

## Why this matters in a job

Because every value arriving from a form, a URL, a CSV file or an HTTP request
is a string, and JavaScript will happily add a string to a number without
complaining. The bug is a total of two fees that comes out as `"04500032000"`,
or a dashboard that shows `NaN` to a principal. In interviews, the
`typeof` table and "what does `"5" + 2` give?" are fixed questions, asked
because they check whether you know the rules or are guessing.

## Seven primitives and one everything-else

Think of the college office. Some things are single facts written on a slip:
a roll number, a name, yes or no. Other things are folders that hold many
slips. In JavaScript the slips are **primitives** and the folders are
**objects**.

A **primitive** is a single value that cannot be changed in place. There are
seven:

::feature-list{columns="2"}
  :::feature{icon="i-lucide-hash" title="number"}
  Every number, whole or decimal: `78`, `72.5`, `-3`. Also the special values
  `NaN` (not a number) and `Infinity`. There is no separate `int`.
  :::
  :::feature{icon="i-lucide-type" title="string"}
  Text, in single quotes, double quotes or backticks: `'Anita'`, `"CSE"`,
  `` `Roll ${roll}` ``.
  :::
  :::feature{icon="i-lucide-toggle-left" title="boolean"}
  `true` or `false`.
  :::
  :::feature{icon="i-lucide-circle-dashed" title="undefined"}
  "Never set". A variable declared without a value, a missing property, a
  missing argument.
  :::
  :::feature{icon="i-lucide-circle-off" title="null"}
  "Deliberately empty". Somebody set this on purpose to mean no value.
  :::
  :::feature{icon="i-lucide-binary" title="bigint and symbol"}
  `10n` for whole numbers too large for `number`, and `Symbol()` for unique
  keys. Rare in fresher work; know that they exist.
  :::
::

Everything that is not a primitive is an **object**: plain objects `{}`,
arrays `[]`, functions, dates. Objects are folders. They can be changed in
place, and two variables can point at the same one.

## How it works

`typeof` tells you the type of a value, as a string. Two of its answers are
famous for being wrong.

```javascript [types.js]
console.log(typeof 78, typeof "Anita", typeof true);
console.log(typeof undefined, typeof null);
console.log(typeof [78, 82], typeof { name: "Anita" }, typeof function () {});
console.log(typeof NaN, typeof 10n);
console.log(Array.isArray([78, 82]));

// Coercion: the language converting a type for you.
console.log("5" + 2, typeof ("5" + 2));   // + with a string joins
console.log("5" - 2);                     // - only means maths, so "5" becomes 5
console.log("5" * "2");
console.log(true + 1);                    // true becomes 1
console.log(String(Number("")));          // an empty string becomes 0
console.log(String(Number("12px")));      // cannot convert: NaN
console.log(parseInt("12px", 10));        // reads digits until it cannot

// NaN is the only value not equal to itself.
console.log(NaN === NaN);
console.log(Number.isNaN(Number("abc")));

// Primitives are copied. Objects are shared.
let mark = 78;
let copy = mark;
copy = 90;
console.log(mark);

const anita = { mark: 78 };
const alias = anita;
alias.mark = 90;
console.log(anita.mark);
```

```text [Output]
number string boolean
undefined object
object object function
number bigint
true
52 string
3
10
2
0
NaN
12
false
true
78
90
```

::runner{lang="javascript"}
```javascript
console.log(typeof 78, typeof "Anita", typeof true);
console.log(typeof undefined, typeof null);
console.log(typeof [78, 82], typeof function () {});
console.log("5" + 2, "5" - 2, "5" * "2", true + 1);
console.log(String(Number("")), String(Number("12px")), parseInt("12px", 10));
console.log(NaN === NaN, Number.isNaN(Number("abc")));
```
::

The two wrong-looking answers, explained:

- **`typeof null` is `"object"`.** This is a bug from the first version of
  JavaScript in 1995. Fixing it would break old websites, so it stays. To check
  for null, write `value === null`.
- **`typeof []` is `"object"`.** Arrays are objects. To check for an array,
  write `Array.isArray(value)`.

### The coercion rules you need

**Coercion** means the language converting a value from one type to another
without being asked. Three rules cover nearly every question:

::steps
### `+` with a string on either side joins

`"5" + 2` is `"52"`. `1 + 2 + "3"` is `"33"`, because it goes left to right:
`1 + 2` is 3 first, then `3 + "3"` joins.

### Every other maths operator converts to number

`-`, `*`, `/`, `%` and comparison with `<` or `>` against a number turn strings
into numbers. `"10" / "4"` is `2.5`.

### In an `if`, everything becomes true or false

The **falsy** values are `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`
and `NaN`. Everything else is **truthy**, including `"0"`, `"false"`, `[]` and
`{}`.
::

### null against undefined

| | `undefined` | `null` |
| --- | --- | --- |
| Means | Never set | Deliberately empty |
| Who produces it | The language | You, or an API |
| `typeof` | `"undefined"` | `"object"` (the bug) |
| In `JSON.stringify` | Property left out | Kept as `null` |
| As a number | `NaN` | `0` |

## Real use case

Reading a line of marks from a spreadsheet export, where a blank cell means
"not yet entered". The naive `Number(cell)` turns the blank into 0, which is a
real mark and a lie.

```javascript [import-marks.js]
const line = "Anita Rao,78,,92";
const cells = line.split(",");

const naive = cells.slice(1).map(cell => Number(cell));
console.log(JSON.stringify(naive));

// Blank means missing, so it becomes null, not 0.
const toMark = cell => (cell.trim() === "" ? null : Number(cell));
const marks = cells.slice(1).map(toMark);
console.log(JSON.stringify(marks));

const entered = marks.filter(m => m !== null);
const average = entered.reduce((sum, m) => sum + m, 0) / entered.length;
console.log(average);
```

```text [Output]
[78,0,92]
[78,null,92]
85
```

The naive version would have averaged to 56.67 and failed a student who had
not sat the paper yet. This is the zero-against-missing distinction from SQL's
`NULL` and Java's `Integer`, appearing again in a third language.

## What confuses people here

That `NaN` means "not a number" and yet `typeof NaN` is `"number"`. `NaN` is a
number value that means "the result of a calculation that failed", such as
`Number("abc")` or `0 / 0`. It poisons everything it touches (`NaN + 5` is
`NaN`) and it is not equal to itself, so `x === NaN` is always false. Use
`Number.isNaN(x)`. The older global `isNaN("abc")` converts first and returns
`true` for any string that is not a number, which is usually not what you meant.

## Interview questions

::accordion
  :::accordion-item{label="What are the data types in JavaScript?" icon="i-lucide-message-circle"}
  Seven primitives: `number`, `string`, `boolean`, `undefined`, `null`,
  `bigint`, `symbol`. And one non-primitive: `object`, which includes arrays,
  functions and dates. Primitives are copied by value; objects are shared by
  reference, so `const b = a; b.mark = 90;` changes `a.mark` too.
  :::

  :::accordion-item{label="Why is typeof null 'object'?" icon="i-lucide-message-circle"}
  A bug in the first implementation of JavaScript that was never fixed because
  fixing it would break existing websites. Check for null with `x === null`,
  and for arrays with `Array.isArray(x)`, because `typeof []` is `"object"` too.
  :::

  :::accordion-item{label="Difference between null and undefined?" icon="i-lucide-message-circle"}
  `undefined` means a value was never set: a declared variable with no value, a
  missing property, a missing argument. `null` is set on purpose to mean empty.
  `null == undefined` is `true`, `null === undefined` is `false`,
  `Number(null)` is `0` and `Number(undefined)` is `NaN`.
  :::

  :::accordion-item{label="What do these give? '5' + 2, '5' - 2, 1 + 2 + '3', '3' + 1 + 2" icon="i-lucide-message-circle"}
  `"52"`, `3`, `"33"`, `"312"`. `+` joins if either side is a string, and it
  works left to right, so `1 + 2` is added before the string arrives, while in
  `"3" + 1 + 2` the string arrives first and everything after it is joined.
  :::

  :::accordion-item{label="How do you check if a value is NaN?" icon="i-lucide-message-circle"}
  `Number.isNaN(x)`. Not `x === NaN`, which is always false because `NaN` is
  the only value not equal to itself. The global `isNaN` converts its argument
  first, so `isNaN("Anita")` is `true` while `Number.isNaN("Anita")` is `false`.
  :::
::
