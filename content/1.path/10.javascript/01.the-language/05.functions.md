In Java, a method lives inside a class and you call it. In JavaScript, a
function is a **value**, the same as a number or a string. You can put it in a
variable, pass it into another function, and return it from one. Most of what
looks strange in JavaScript code is that one idea being used.

## Why this matters in a job

Because almost every line of front-end code passes a function somewhere. A
click handler is a function handed to the browser. `marks.filter(m => m >= 40)`
hands a function to an array. A `setTimeout` takes a function to run later.
In interviews you will be asked the difference between a function declaration,
a function expression and an arrow function, what a callback is, and what a
higher-order function is, and all three answers are this lesson.

## A function is a recipe card you can hand over

In Java, a method is written on the wall of one kitchen. In JavaScript, a
function is a **recipe card**. You can keep it in a drawer (a variable), give
it to a colleague (pass it as an argument) so that they follow it at the right
moment, or write a new card and give it back (return it).

The words for that:

- **First-class functions**: functions are values, like any other.
- **Callback**: a function you pass to another function, for it to call later.
  "Call you back when it is time."
- **Higher-order function**: a function that takes a function as an argument,
  or returns one. `filter`, `map`, `addEventListener` and `setTimeout` are all
  higher-order functions.

## Syntax

Three ways to write a function, and they are nearly interchangeable:

```javascript [three-ways.js]
// 1. Function declaration: a statement with a name. Can be called above its line.
function grade(mark) {
  if (mark >= 75) return "Distinction";
  if (mark >= 60) return "First class";
  if (mark >= 40) return "Pass";
  return "Fail";
}

// 2. Function expression: a function stored in a variable.
const percentage = function (obtained, total) {
  return (obtained / total) * 100;
};

// 3. Arrow function: shorter. One expression means an automatic return.
const isPass = mark => mark >= 40;
const toResult = (name, mark) => ({ name, mark, pass: isPass(mark) });

console.log(grade(78), percentage(450, 600), isPass(38));
console.log(JSON.stringify(toResult("Anita", 78)));
```

```text [Output]
Distinction 75 false
{"name":"Anita","mark":78,"pass":true}
```

Two details in the arrow functions. With one parameter the brackets are
optional (`mark => ...`); with zero or two or more they are required
(`() => ...`, `(name, mark) => ...`). And returning an object needs round
brackets around it, or the braces are read as the function body.
`{ name, mark }` is shorthand for `{ name: name, mark: mark }`.

## How it works

Parameters got better than Java's. **Default parameters** fill in a value when
the caller leaves one out. **Rest parameters** (`...marks`) collect any number
of arguments into an array. **Spread** (`...array` in a call) does the opposite
and unpacks an array into separate arguments.

```javascript [parameters.js]
function totalFee(tuition, hostel = 0) {          // default parameter
  return tuition + hostel;
}
console.log(totalFee(45000), totalFee(45000, 30000));

function average(...marks) {                      // rest: marks is an array
  const sum = marks.reduce((total, m) => total + m, 0);
  return (sum / marks.length).toFixed(2);
}
console.log(average(78, 82, 91));

const semesterMarks = [78, 82, 91];
console.log(average(...semesterMarks));           // spread: unpack the array
console.log(Math.max(...semesterMarks));

// Passing a function in: a callback.
function applyToAll(marks, fn) {
  const results = [];
  for (const m of marks) results.push(fn(m));
  return results;
}
console.log(applyToAll([78, 35, 62], grade).join(", "));

// Returning a function: a function that makes checkers.
function atLeast(cutoff) {
  return mark => mark >= cutoff;
}
const eligibleForPlacement = atLeast(60);
console.log(eligibleForPlacement(62), eligibleForPlacement(58));

function grade(mark) {
  if (mark >= 75) return "Distinction";
  if (mark >= 60) return "First class";
  if (mark >= 40) return "Pass";
  return "Fail";
}
```

```text [Output]
45000 75000
83.67
83.67
91
Distinction, Fail, First class
true false
```

Notice `grade` is used before the line where it is written, and it works.
Declarations are **hoisted**, moved to the top of their scope before the code
runs. A function expression or an arrow function stored in `const` is not
usable before its line. The next chapter explains why.

::runner{lang="javascript"}
```javascript
const isPass = mark => mark >= 40;
const marks = [78, 35, 62, 40];

// A callback: filter calls isPass once for every mark.
console.log(marks.filter(isPass).join(", "));

// A function that returns a function.
const atLeast = cutoff => mark => mark >= cutoff;
const distinction = atLeast(75);
console.log(marks.filter(distinction).join(", "));

// Rest and spread.
const highest = (...all) => Math.max(...all);
console.log(highest(...marks));
```
::

### Arrow functions are not only shorter

| | Regular function | Arrow function |
| --- | --- | --- |
| Own `this` | Yes, set by how it is called | No, uses the surrounding one |
| `arguments` object | Yes | No, use rest parameters |
| Can be used with `new` | Yes | No |
| Hoisted when declared | Yes (declarations) | No |

The `this` row is the important one, and it gets a lesson of its own.

## Real use case

Sorting a list of students by any field. `sort` takes a **comparator**, a
callback that returns a negative number if `a` comes first, positive if `b`
does. Writing one comparator per field is repetitive, so real code writes a
function that **makes** comparators.

```javascript [sort-students.js]
const students = [
  { name: "Anita Rao",   mark: 78, attendance: 92 },
  { name: "Vikram Shah", mark: 64, attendance: 71 },
  { name: "Priya Nair",  mark: 91, attendance: 85 }
];

const byField = field => (a, b) => a[field] - b[field];     // returns a comparator

const byMark = [...students].sort(byField("mark"));          // copy, then sort
console.log(byMark.map(s => s.name).join(" < "));

const byAttendance = [...students].sort(byField("attendance"));
console.log(byAttendance.map(s => s.name).join(" < "));
```

```text [Output]
Vikram Shah < Anita Rao < Priya Nair
Vikram Shah < Priya Nair < Anita Rao
```

The same shape shows up everywhere once you notice it: a click handler passed
to `addEventListener`, a validation rule passed to a form library, a retry
function that takes the operation to retry.

## What confuses people here

**Braces turn off the automatic return.** `mark => mark >= 40` returns a
boolean. `mark => { mark >= 40 }` returns `undefined`, because with braces it is
an ordinary body and needs the word `return`. This is the most common arrow
function bug, and `marks.filter(m => { m >= 40 })` returns an empty array with
no error.

**Passing a function is not calling it.** `button.addEventListener("click",
save)` hands over the recipe card. `button.addEventListener("click", save())`
runs `save` immediately, once, and hands over whatever it returned, usually
`undefined`.

## Interview questions

::accordion
  :::accordion-item{label="Function declaration or function expression: what is the difference?" icon="i-lucide-message-circle"}
  A declaration (`function grade() {}`) is hoisted with its body, so you can
  call it before the line it is written on. An expression
  (`const grade = function () {}`) is a value assigned to a variable, and only
  exists after that line runs. Calling it earlier throws a `ReferenceError`
  with `const`/`let`, or a `TypeError: grade is not a function` with `var`.
  :::

  :::accordion-item{label="How is an arrow function different from a regular function?" icon="i-lucide-message-circle"}
  Shorter syntax with an implicit return for one expression, and four
  behaviours: no own `this` (it uses the surrounding scope's), no `arguments`
  object, cannot be called with `new`, and not hoisted. The `this` difference
  is why arrow functions are preferred for callbacks.
  :::

  :::accordion-item{label="What is a callback?" icon="i-lucide-message-circle"}
  A function passed to another function to be called later. `[78, 35].filter(m
  => m >= 40)` passes a callback that `filter` calls once for each item;
  `setTimeout(() => console.log("done"), 1000)` passes one the browser calls
  after a second.
  :::

  :::accordion-item{label="What is a higher-order function? Give an example." icon="i-lucide-message-circle"}
  A function that takes a function as an argument, returns one, or both.
  `map`, `filter` and `reduce` take one. This returns one:

  ```javascript
  const atLeast = cutoff => mark => mark >= cutoff;
  const pass = atLeast(40);
  console.log(pass(52));      // true
  ```
  :::

  :::accordion-item{label="Rest parameters and the spread operator look the same. What is the difference?" icon="i-lucide-message-circle"}
  Both are `...`, used in opposite places. In a function's **parameter list**
  it is rest, and gathers arguments into an array: `function avg(...marks)`.
  In a **call** or an array literal it is spread, and unpacks an array into
  items: `Math.max(...marks)`, `[...marks, 90]`.
  :::
::
