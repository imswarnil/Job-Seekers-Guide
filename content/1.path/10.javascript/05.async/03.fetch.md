`fetch` is the browser's built-in function for making an HTTP request, the
same GET and POST you met in the networks track, from JavaScript. It returns a
promise, so everything from the last two lessons applies. And it has one rule
that surprises almost everybody: it only rejects when the request could not be
made at all.

## Why this matters in a job

Because every page with live data calls `fetch` (or a library such as axios
that wraps it). The bugs are always the same few: an error page parsed as if it
were data, a button that stays disabled forever after one failure, a spinner
that never stops, two requests from a double click. Interviewers ask "how do
you call an API from JavaScript?", "does `fetch` throw on a 404?" and "how
would you handle errors and loading?", and the second question is where most
candidates slip.

## A letter and its reply

`fetch(url)` posts a letter. The promise it returns fulfils when a **reply
envelope** arrives: the status line and headers. You have not read the letter
inside yet; that is a second step, `response.json()`, which is also a promise
because the body may still be arriving.

And the rule: if a reply comes back at all, even one that says "404, no such
student" or "500, the server broke", the letter was delivered and `fetch`
**fulfils**. It only **rejects** when there is no reply at all: no internet, the
server's name does not exist, the request was blocked or cancelled. So there are
two kinds of failure, and you must check for both.

| What happened | `fetch` promise | `response.ok` | How you notice |
| --- | --- | --- | --- |
| 200 OK | fulfils | `true` | Read the body |
| 404 Not Found, 500 Server Error | **fulfils** | `false` | Check `response.ok` yourself |
| No network, bad host, CORS blocked | rejects | (no response) | `catch` |

`response.ok` is `true` for any status from 200 to 299.

## How it works

These examples call **JSONPlaceholder**, a free public test API that returns
fake data. Its users are not students, but it is real, so the output below is
what it actually returns.

```javascript [get.js]
async function getUser(id) {
  const response = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
  console.log(response.status, response.ok);

  if (!response.ok) {                               // 404 and 500 do NOT reject
    throw new Error(`Request failed with status ${response.status}`);
  }
  return response.json();                           // also a promise
}

(async () => {
  const user = await getUser(1);
  console.log(user.name, user.email);

  try {
    await getUser(9999);                            // no such user
  } catch (error) {
    console.log(error.message);
  }
})();
```

```text [Output]
200 true
Leanne Graham Sincere@april.biz
404 false
Request failed with status 404
```

Sending data is the same function with an options object: the method, a header
saying the body is JSON, and the body turned into a string.

```javascript [post.js]
(async () => {
  const response = await fetch("https://jsonplaceholder.typicode.com/posts", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      title: "Admission enquiry from Anita Rao",
      body: "B.Tech CSE, 2026 intake",
      userId: 1
    })
  });

  console.log(response.status);
  const created = await response.json();
  console.log(created.id, created.title);
})();
```

```text [Output]
201
101 Admission enquiry from Anita Rao
```

`201 Created` is the server saying it made something new. JSONPlaceholder
pretends to save it and always gives the new item id 101; a real server would
store it.

Paste either example into your browser's console (F12, then Console) to watch
the request appear in the Network tab.

## Real use case

The student list on a department page, the way a working developer writes it.
The URL `/api/students` belongs to an imaginary college server, so the output
here is illustrative rather than from a real run.

```javascript [load-students.js]
async function loadStudents(dept) {
  const status = document.querySelector("#status");
  const button = document.querySelector("#reload");

  button.disabled = true;                              // 1. no double request
  status.textContent = "Loading students…";            // 2. say something is happening

  const controller = new AbortController();            // 3. give up after 8 seconds
  const timer = setTimeout(() => controller.abort(), 8000);

  try {
    const response = await fetch(`/api/students?dept=${encodeURIComponent(dept)}`, {
      signal: controller.signal
    });

    if (!response.ok) {                                // 4. an HTTP error
      throw new Error(`The server answered ${response.status}`);
    }

    const students = await response.json();
    renderStudents(students);                          // 5. show what the SERVER sent
    status.textContent = `${students.length} students`;
  } catch (error) {
    status.textContent = error.name === "AbortError"
      ? "The server is taking too long. Try again."
      : `Could not load students. ${error.message}`;
  } finally {
    clearTimeout(timer);
    button.disabled = false;                           // 6. always usable again
  }
}
```

```text [Output]
Loading students…
62 students
```

(Illustrative: that is what `#status` shows for a department of 62. With the
network switched off in developer tools, it shows "Could not load students.
Failed to fetch".)

### CORS, in one paragraph

A page on `college.example` calling an API on `api.results.example` is a
**cross-origin** request. The browser sends it, but only lets your JavaScript
read the reply if the API's response includes a header allowing your origin
(`Access-Control-Allow-Origin`). If it does not, you see a CORS error in the
console and `fetch` rejects. It is fixed on the **server**, by adding that
header, never by changing your `fetch` call. JSONPlaceholder answers every
request with `Access-Control-Allow-Origin` set to whatever origin asked, which
is why the examples above work from any page.

## What confuses people here

**`fetch` does not reject on 404 or 500.** Check `response.ok`, every time.

**`response.json()` is a second promise.** `const data = response.json()`
without `await` gives you a promise, not the data.

**The body can be read once.** Calling `response.json()` and then
`response.text()` on the same response throws `TypeError: Body is unusable`,
because the body is a stream and it has been consumed.

**`fetch` sends no cookies to other origins by default.** Logged-in requests to
a different domain need `credentials: "include"`, and the server has to allow
that too.

## Interview questions

::accordion
  :::accordion-item{label="How do you make a GET and a POST request in JavaScript?" icon="i-lucide-message-circle"}
  ```javascript
  const res = await fetch("/api/students/42");
  if (!res.ok) throw new Error(res.status);
  const student = await res.json();

  await fetch("/api/enquiries", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ name: "Anita Rao", course: "CSE" })
  });
  ```
  :::

  :::accordion-item{label="Does fetch throw an error on a 404?" icon="i-lucide-message-circle"}
  No. `fetch` rejects only on a network failure (no connection, unknown host,
  CORS block, abort). A 404 or 500 is a successful request whose response
  says something went wrong, so the promise fulfils with `response.ok` set to
  `false`. You must check `response.ok` or `response.status` yourself.
  :::

  :::accordion-item{label="How do you add a timeout to fetch?" icon="i-lucide-message-circle"}
  With an `AbortController`: pass `controller.signal` in the options and call
  `controller.abort()` from a `setTimeout`. The `fetch` then rejects with an
  `AbortError`. Newer browsers also accept `signal: AbortSignal.timeout(8000)`
  directly.
  :::

  :::accordion-item{label="What is CORS?" icon="i-lucide-message-circle"}
  Cross-Origin Resource Sharing. By default a page may not read responses from
  a different origin (scheme, host or port). A server opts in by sending
  `Access-Control-Allow-Origin` with the allowed origin. For some requests, such
  as a POST with a JSON body, the browser first sends an `OPTIONS` "preflight"
  request to ask permission. It is configured on the server, not in the
  client.
  :::

  :::accordion-item{label="fetch or axios?" icon="i-lucide-message-circle"}
  `fetch` is built into every browser and Node.js 18 and later. axios is a
  library that adds conveniences: it rejects on 4xx and 5xx by default, parses
  JSON automatically, has timeouts and request interceptors. Knowing `fetch`
  properly, including its `response.ok` rule, is what an interviewer is
  checking.
  :::
::
