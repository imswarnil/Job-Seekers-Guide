In Java, a student record needs a class before it can exist. In JavaScript you
write the record down directly, with braces, and it is an **object**: a
collection of named values. Every example in the last lesson was one, and
nearly every piece of data a web page handles arrives as one.

## Why this matters in a job

Because data from a server arrives as JSON, becomes objects, and is read,
reshaped and copied all day. The two bugs this lesson prevents are real and
frequent: reading a property of something that is `undefined` (the page goes
blank with `Cannot read properties of undefined`), and changing a "copy" that
turns out to share its insides with the original. Interviewers ask about
destructuring, spread, shallow against deep copy and `JSON.stringify` directly,
and they use objects in every output question.

## A form with labelled boxes

An object is a filled-in form. Each box has a **label** (the **key**, always a
string or a symbol) and whatever is written in it (the **value**, any type at
all, including another form or a function). You read a box by its label.

```javascript [shape.js]
const student = {
  name: "Anita Rao",                    // key "name", value a string
  roll: "CSE042",
  marks: { dbms: 78, os: 82 },          // a value can be another object
  "fee status": "paid",                 // a key with a space needs quotes
  describe() {                          // a value can be a function: a method
    return this.name + " (" + this.roll + ")";
  }
};
```

Two ways to read a box. **Dot notation**, `student.name`, when you know the
label while writing the code. **Bracket notation**, `student["fee status"]` or
`student.marks[subject]`, when the label has a space or is held in a variable.

## How it works

```javascript [objects.js]
const student = {
  name: "Anita Rao",
  roll: "CSE042",
  marks: { dbms: 78, os: 82 },
  "fee status": "paid"
};

// Reading
const subject = "os";
console.log(student.name, student["fee status"], student.marks[subject]);

// Adding, changing, deleting
student.dept = "CSE";
student.roll = "CSE043";
delete student["fee status"];
console.log(Object.keys(student).join(", "));

// Reading safely: ?. stops at null or undefined instead of throwing
console.log(String(student.hostel?.room));
// ?? gives a fallback only for null or undefined
console.log(student.scholarship ?? "none");

// Keys, values, entries
console.log(Object.values(student.marks).join(", "));
for (const [paper, mark] of Object.entries(student.marks)) {
  console.log(`${paper}: ${mark}`);
}

// Destructuring: unpack boxes into variables
const { name, marks: { dbms }, city = "Bangalore" } = student;
console.log(name, dbms, city);

const [topper, , third] = ["Priya", "Anita", "Vikram"];
console.log(topper, third);
```

```text [Output]
Anita Rao paid 82
name, roll, marks, dept
undefined
none
78, 82
dbms: 78
os: 82
Anita Rao 78 Bangalore
Priya Vikram
```

The destructuring line does three things at once: takes `name`, reaches inside
`marks` for `dbms`, and gives `city` a **default** because `student` has no
`city`. The array version skips the second item with an empty slot.

### Copying: shallow against deep

`const b = a` does not copy an object. It makes a second name for the same one,
as the types lesson showed. To copy, you spread it into a new object. But
spread only copies the **top level**. Any object inside is still shared.

After `const copy = { ...student }`:

| Name | Outer object | Its `marks` |
| --- | --- | --- |
| `student` | object 1 | marks object M |
| `copy` | object 2, a new one | marks object M, **the same one** |

```javascript [copying.js]
const student = { name: "Anita Rao", marks: { dbms: 78, os: 82 } };

const shallow = { ...student };          // new outer object, SAME marks inside
shallow.name = "Changed";
shallow.marks.dbms = 10;
console.log(student.name, student.marks.dbms);

const deep = structuredClone(student);   // new objects all the way down
deep.marks.os = 0;
console.log(student.marks.os);

// Merging: later keys win
const updated = { ...student, name: "Anita R.", year: 3 };
console.log(JSON.stringify(updated));
```

```text [Output]
Anita Rao 10
82
{"name":"Anita R.","marks":{"dbms":10,"os":82},"year":3}
```

`name: "Anita R."` comes after the spread, so it wins, and it keeps its place
as the first key. Put it before the spread and the student's own `name`
overwrites it. That order question comes up in code review more often than you
would expect.

::runner{lang="javascript"}
```javascript
const student = { name: "Anita Rao", marks: { dbms: 78, os: 82 } };

const shallow = { ...student };
shallow.marks.dbms = 10;
console.log(student.marks.dbms);

const updated = { ...student, name: "Anita R.", year: 3 };
console.log(JSON.stringify(updated));

const reversed = { name: "Anita R.", ...student };
console.log(JSON.stringify(reversed));
```
::

### JSON

**JSON** (JavaScript Object Notation) is the text format servers and browsers
use to send data. It looks like an object literal, with stricter rules: keys in
double quotes, no functions, no `undefined`, no comments.

```javascript [json.js]
const record = {
  name: "Anita Rao",
  dob: new Date("2000-05-14"),
  remarks: undefined,
  mark: 78,
  describe() { return this.name; }
};

const text = JSON.stringify(record);
console.log(text);

const back = JSON.parse(text);
console.log(typeof back.dob, typeof back.describe);
```

```text [Output]
{"name":"Anita Rao","dob":"2000-05-14T00:00:00.000Z","mark":78}
string undefined
```

Three things were lost on the way through: `remarks` (undefined is dropped),
`describe` (functions are dropped), and the date, which became a string and
stays one after parsing. That is why a copy made with
`JSON.parse(JSON.stringify(x))` is a deep copy with holes in it, and
`structuredClone` is the better tool.

## Real use case

A server sends a student's result, and the page shows it. Real API data has
missing pieces, so every read is defensive, and the page keeps the original
untouched while it builds what it displays.

```javascript [result-card.js]
const response = '{"student":{"name":"Vikram Shah","roll":"ECE017"},' +
  '"marks":{"dbms":64,"os":null},"hostel":null}';

const data = JSON.parse(response);

const { student: { name, roll }, marks } = data;
const room = data.hostel?.room ?? "Day scholar";

const lines = Object.entries(marks).map(
  ([paper, mark]) => `${paper.toUpperCase()}: ${mark ?? "not entered"}`
);

console.log(`${name} (${roll}), ${room}`);
console.log(lines.join(" | "));
```

```text [Output]
Vikram Shah (ECE017), Day scholar
DBMS: 64 | OS: not entered
```

Without `?.` the `hostel` line throws, because `null.room` is an error, and the
whole result card fails to render because one student does not live in the
hostel.

## What confuses people here

**Spread is shallow.** `{ ...student }` copies the top level only. Change
something nested in the copy and the original changes too. Use
`structuredClone` when you need a real deep copy.

**`const` does not freeze.** A `const` object can have its properties changed;
only the variable cannot be pointed elsewhere.

**Order matters when merging.** In `{ ...defaults, ...overrides }` the later
one wins. Written the other way round, the defaults silently overwrite what you
meant to keep.

## Interview questions

::accordion
  :::accordion-item{label="Dot notation or bracket notation: when do you need brackets?" icon="i-lucide-message-circle"}
  When the key is held in a variable (`marks[subject]`), when it is not a
  valid identifier (`student["fee status"]`, `data["2024"]`), or when it is
  computed (`row["mark" + n]`). Otherwise dot notation is clearer.
  :::

  :::accordion-item{label="What is the difference between a shallow and a deep copy?" icon="i-lucide-message-circle"}
  A shallow copy (`{ ...obj }`, `Object.assign({}, obj)`) creates a new outer
  object but shares every nested object with the original. A deep copy
  (`structuredClone(obj)`) copies nested objects too. Prove it:
  `const c = { ...s }; c.marks.dbms = 10;` also changes `s.marks.dbms`.
  :::

  :::accordion-item{label="What is destructuring?" icon="i-lucide-message-circle"}
  Unpacking values from an object or array into variables in one statement.
  `const { name, city = "Bangalore" } = student;` takes `name` and gives `city`
  a default. `const [first, second] = toppers;` takes by position. It also
  works in function parameters: `function show({ name, roll }) {}`.
  :::

  :::accordion-item{label="What does JSON.stringify drop?" icon="i-lucide-message-circle"}
  Properties whose value is `undefined`, functions and symbols. Dates become
  ISO strings and do not turn back into dates with `JSON.parse`. `NaN` and
  `Infinity` become `null`. That is why `JSON.parse(JSON.stringify(x))` is an
  unreliable deep copy.
  :::

  :::accordion-item{label="What is optional chaining, and nullish coalescing?" icon="i-lucide-message-circle"}
  `a?.b` returns `undefined` instead of throwing when `a` is `null` or
  `undefined`. `a ?? b` returns `b` only when `a` is `null` or `undefined`,
  unlike `a || b`, which also replaces `0` and `""`. Together:
  `data.hostel?.room ?? "Day scholar"`.
  :::
::
