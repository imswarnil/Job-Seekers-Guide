JavaScript has `class`, `extends`, `constructor` and `super`, and they look
exactly like Java. They are a newer coat of paint, added in 2015, over an older
idea Java never had: an object can borrow methods directly from another object,
its **prototype**.

## Why this matters in a job

Because you will read and write classes in any sizeable codebase, and because
"explain prototypal inheritance" and "what is the prototype chain?" are
standard follow-ups after `this`. You do not need the internals. You need to
say, with an example, that methods are looked up through a chain of objects,
and that `class` is syntax over that chain. Modules come with it: every
real project splits code across files with `import` and `export`, and an
interviewer may ask the difference between a default and a named export.

## Asking up the chain

Imagine a new student who does not know the exam rules. She asks her class
representative. If the representative does not know, he asks the department
office. If the office does not know, it asks the university. The first one who
knows answers.

That is the **prototype chain**. Every object has a hidden link to another
object, its **prototype**. When you read a property the object does not have,
JavaScript follows the link and looks there, and then that object's
prototype, and so on until it finds the property or reaches `null` at the end.

A `class` sets that chain up for you:

::flow{direction="vertical" caption="Where anita.describe() is found"}
  :::flow-step{label="anita (the object itself)" icon="i-lucide-user"}
  Holds her own data: `name`, `roll`. No `describe` here.
  :::
  :::flow-step{label="Student.prototype" icon="i-lucide-graduation-cap" highlight}
  Holds the methods written in `class Student`. `describe` is found here.
  :::
  :::flow-step{label="CollegeMember.prototype" icon="i-lucide-building"}
  Methods from the parent class, reached through `extends`.
  :::
  :::flow-step{label="Object.prototype, then null" icon="i-lucide-circle-off"}
  `toString`, `hasOwnProperty`, and the end of the chain.
  :::
::

## How it works

```javascript [classes.js]
class CollegeMember {
  constructor(name) {
    this.name = name;
  }
  describe() {
    return `${this.name}, member of the college`;
  }
}

class Student extends CollegeMember {
  #feeDue = 0;                                  // # makes it private

  constructor(name, roll) {
    super(name);                                // run the parent's constructor first
    this.roll = roll;
  }
  describe() {                                  // override
    return `${super.describe()}, roll ${this.roll}`;
  }
  addFee(amount) { this.#feeDue += amount; }
  get feeDue() { return this.#feeDue; }         // read like a property
  static fromCsv(line) {                        // called on the class, not an object
    const [name, roll] = line.split(",");
    return new Student(name, roll);
  }
}

const anita = new Student("Anita Rao", "CSE042");
anita.addFee(45000);
console.log(anita.describe());
console.log(anita.feeDue);
console.log(Student.fromCsv("Vikram Shah,ECE017").describe());

// What is really underneath
console.log(typeof Student);
console.log(Object.getPrototypeOf(anita) === Student.prototype);
console.log(Object.getPrototypeOf(Student.prototype) === CollegeMember.prototype);
console.log(anita.hasOwnProperty("describe"), "describe" in anita);
console.log(anita instanceof CollegeMember);
```

```text [Output]
Anita Rao, member of the college, roll CSE042
45000
Vikram Shah, member of the college, roll ECE017
function
true
true
false true
true
```

`typeof Student` is `"function"`: a class is a special kind of function.
`describe` is not on `anita` herself (`hasOwnProperty` is `false`) but it is
reachable (`in` is `true`), because it lives on the prototype and is shared by
every student. A thousand students, one copy of each method.

The same chain, without the class syntax:

::runner{lang="javascript"}
```javascript
const department = {
  college: "LNCT",
  describe() { return this.name + " studies at " + this.college; }
};

// Object.create makes a new object whose prototype is department.
const anita = Object.create(department);
anita.name = "Anita Rao";

console.log(anita.describe());               // found on the prototype
console.log(anita.hasOwnProperty("college")); // not her own property
console.log(Object.getPrototypeOf(anita) === department);
```
::

### Modules

A **module** is a file with its own scope. Nothing inside it is visible
outside unless it is **exported**, and another file uses it by **importing**.

```javascript [grading.js]
export const PASS_MARK = 40;                        // a named export

export function grade(mark) {                       // another named export
  return mark >= 75 ? "Distinction" : mark >= PASS_MARK ? "Pass" : "Fail";
}

export default function average(marks) {            // the one default export
  return marks.reduce((s, m) => s + m, 0) / marks.length;
}
```

```javascript [report.js]
import average, { grade, PASS_MARK } from "./grading.js";

console.log(average([78, 64, 91]), grade(64), PASS_MARK);
```

```text [Output]
77.66666666666667 Pass 40
```

A file can have many **named** exports, imported with braces and the exact
name, and at most one **default** export, imported without braces under any
name you like. In the browser, a file that uses `import` must be loaded with
`<script type="module" src="report.js"></script>`, and it has to be served from
a web server rather than opened as a file, or the browser blocks the import.

## Real use case

A real front end is dozens of small modules: one for talking to the server,
one for formatting, one per screen. A class earns its place when many objects
share behaviour and each holds its own state, for example a register per
subject.

```javascript [attendance-register.js]
export class AttendanceRegister {
  #present = new Set();

  constructor(subject, strength) {
    this.subject = subject;
    this.strength = strength;
  }
  mark(roll) { this.#present.add(roll); }
  get percentage() {
    return Math.round((this.#present.size / this.strength) * 100);
  }
}
```

```javascript [main.js]
import { AttendanceRegister } from "./attendance-register.js";

const dbms = new AttendanceRegister("DBMS", 60);
["CSE001", "CSE002", "CSE001"].forEach(roll => dbms.mark(roll));
console.log(`${dbms.subject}: ${dbms.percentage}%`);
```

```text [Output]
DBMS: 3%
```

Marking `CSE001` twice counts once, because the `Set` holds unique values, and
nobody outside the class can reach `#present` to fake a number.

## What confuses people here

**`class` is not a new object model.** It is syntax over prototypes. Methods go
on the prototype and are shared; fields set in the constructor go on each
object.

**`__proto__` against `prototype`.** `Student.prototype` is the object that
students made with `new Student` will link to. `anita.__proto__` (properly,
`Object.getPrototypeOf(anita)`) is the object `anita` does link to. They are the
same object, reached from two directions.

**Forgetting `super()`.** In a subclass constructor you must call `super(...)`
before touching `this`, or you get `ReferenceError: Must call super constructor
in derived class before accessing 'this'`.

## Interview questions

::accordion
  :::accordion-item{label="What is prototypal inheritance?" icon="i-lucide-message-circle"}
  Every object has a link to another object, its prototype. When a property is
  not found on an object, JavaScript looks on its prototype, then that object's
  prototype, until it reaches `null`. That chain is how objects share methods.
  `const a = Object.create(dept); a.describe()` finds `describe` on `dept`.
  :::

  :::accordion-item{label="Are JavaScript classes the same as Java classes?" icon="i-lucide-message-circle"}
  They look the same and behave differently underneath. A JavaScript class is
  a function, and its methods live on a prototype object that instances link
  to. `typeof Student` is `"function"`. Private fields use `#name`, not the
  `private` keyword.
  :::

  :::accordion-item{label="Difference between a named and a default export?" icon="i-lucide-message-circle"}
  A module can have many named exports (`export function grade`), imported with
  braces and the same name (`import { grade } from "./grading.js"`), and one
  default export, imported without braces under any name
  (`import average from "./grading.js"`).
  :::

  :::accordion-item{label="What does super do?" icon="i-lucide-message-circle"}
  In a constructor, `super(args)` runs the parent class's constructor and must
  come before `this` is used. In a method, `super.describe()` calls the parent's
  version of a method you have overridden.
  :::
::
