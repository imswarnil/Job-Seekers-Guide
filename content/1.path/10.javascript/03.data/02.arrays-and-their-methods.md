A class of sixty is an array of sixty objects. In Java you would write a `for`
loop for every question you asked of it. In JavaScript you hand a small
function to an array method, and the method does the looping. This is where
the idea from the functions lesson (a function is a value) pays for itself.

## Why this matters in a job

Because most front-end and Node.js code is turning one array into another:
the students from the server into rows on screen, the rows into a filtered
list, the list into a total. A reviewer will expect `filter` and `map` rather
than a hand-written loop, and will catch you mutating an array that other code
was still reading. In interviews you will be asked the difference between
`map` and `forEach`, `slice` and `splice`, to write `reduce` for a sum or a
group-by, and what `[10, 9, 100].sort()` returns.

## A register you can ask questions of

An **array** is an ordered list, indexed from 0, that can hold any mix of
values and grows or shrinks as you go. Think of the attendance register:
students in order, and you keep asking it questions. Who failed? What are only
the names? What is the class average? Is anyone below 40? Each of those
questions has a method, and each method takes a small function that answers
it for **one** student.

The methods split into two families, and knowing which is which is half the
lesson:

| Changes the original (**mutating**) | Returns something new (**non-mutating**) |
| --- | --- |
| `push`, `pop`, `shift`, `unshift` | `map`, `filter`, `reduce` |
| `splice` | `slice`, `concat` |
| `sort`, `reverse` | `find`, `findIndex`, `some`, `every` |
| `fill` | `includes`, `indexOf`, `join` |

## How it works

### Adding and removing at the ends

```javascript [ends.js]
const queue = ["Anita", "Vikram"];

console.log(queue.push("Priya"));      // add at the end, returns the new length
console.log(queue.unshift("Rahul"));   // add at the start, returns the new length
console.log(queue.join(", "));
console.log(queue.pop());              // remove from the end, returns it
console.log(queue.shift());            // remove from the start, returns it
console.log(queue.join(", "));
```

```text [Output]
3
4
Rahul, Anita, Vikram, Priya
Priya
Rahul
Anita, Vikram
```

### slice against splice

```javascript [slice-splice.js]
const papers = ["Maths", "DBMS", "OS", "CN", "Java"];

console.log(papers.slice(1, 3).join(", "));   // copy index 1 up to (not including) 3
console.log(papers.length);                    // unchanged

const removed = papers.splice(1, 2);           // from index 1, remove 2
console.log(removed.join(", "), "|", papers.join(", "));

papers.splice(1, 0, "DSA");                    // from index 1, remove 0, insert DSA
console.log(papers.join(", "));
```

```text [Output]
DBMS, OS
5
DBMS, OS | Maths, CN, Java
Maths, DSA, CN, Java
```

`slice` is a photocopy of part of the register. `splice` is scissors and glue
on the original.

### The methods that take a function

```javascript [methods.js]
const students = [
  { name: "Anita",  dept: "CSE", mark: 78 },
  { name: "Vikram", dept: "ECE", mark: 35 },
  { name: "Priya",  dept: "CSE", mark: 91 },
  { name: "Rahul",  dept: "ME",  mark: 62 }
];

const names = students.map(s => s.name);                   // one out for each in
console.log(names.join(", "));

const cse = students.filter(s => s.dept === "CSE");        // keep those that pass
console.log(cse.map(s => s.name).join(", "));

const total = students.reduce((sum, s) => sum + s.mark, 0); // fold into one value
console.log(total, total / students.length);

console.log(students.find(s => s.mark > 80).name);          // first match, or undefined
console.log(students.findIndex(s => s.name === "Rahul"));    // its index, or -1
console.log(students.some(s => s.mark < 40));                // at least one?
console.log(students.every(s => s.mark >= 40));              // all of them?
console.log(names.includes("Priya"), names.indexOf("Meena"));

// reduce can build any shape: here, a count per department
const perDept = students.reduce((counts, s) => {
  counts[s.dept] = (counts[s.dept] ?? 0) + 1;
  return counts;
}, {});
console.log(JSON.stringify(perDept));

// Chaining: passed students, best first, names only
const merit = students
  .filter(s => s.mark >= 40)
  .sort((a, b) => b.mark - a.mark)
  .map(s => s.name);
console.log(merit.join(", "));
```

```text [Output]
Anita, Vikram, Priya, Rahul
Anita, Priya
266 66.5
Priya
3
true
false
true -1
{"CSE":2,"ECE":1,"ME":1}
Priya, Anita, Rahul
```


### The sort trap

```javascript [sort.js]
const marks = [78, 9, 100, 64];

console.log([...marks].sort().join(", "));               // default: compares as TEXT
console.log([...marks].sort((a, b) => a - b).join(", ")); // numbers, ascending
console.log([...marks].sort((a, b) => b - a).join(", ")); // numbers, descending
```

```text [Output]
100, 64, 78, 9
9, 64, 78, 100
100, 78, 64, 9
```

With no comparator, `sort` converts every item to a string and compares them
character by character. `"100"` starts with `"1"`, which comes before `"6"`,
`"7"` and `"9"`. The **comparator** `(a, b) => a - b` returns a negative number
when `a` should come first, so it sorts numerically. And note the `[...marks]`:
`sort` changes the original array, so the copy protects it.

::runner{lang="javascript"}
```javascript
const attendance = [92, 64, 100, 71, 8];

console.log(attendance.sort().join(", "));
console.log(attendance.join(", "));          // sort changed the original

const fixed = [92, 64, 100, 71, 8].sort((a, b) => a - b);
console.log(fixed.join(", "));

const below75 = fixed.filter(p => p < 75);
console.log(below75.length + " students below 75%");

const doubled = [1, 2, 3].forEach(n => n * 2);
console.log(String(doubled));               // forEach returns nothing
```

## Real use case

The results page for a department. The server sends raw records; the page
needs the pass percentage, the topper, and a sorted merit list, and must not
disturb the original data, because another part of the page is still using it.

```javascript [results-summary.js]
const results = [
  { roll: "CSE001", name: "Anita Rao",   mark: 78 },
  { roll: "CSE002", name: "Vikram Shah", mark: 35 },
  { roll: "CSE003", name: "Priya Nair",  mark: 91 },
  { roll: "CSE004", name: "Rahul Verma", mark: null },  // absent
  { roll: "CSE005", name: "Meena Iyer",  mark: 40 }
];

const appeared = results.filter(r => r.mark !== null);
const passed = appeared.filter(r => r.mark >= 40);
const passPct = Math.round((passed.length / appeared.length) * 100);

const topper = appeared.reduce((best, r) => (r.mark > best.mark ? r : best));

const meritList = [...passed]
  .sort((a, b) => b.mark - a.mark)
  .map((r, i) => `${i + 1}. ${r.name} (${r.mark})`);

console.log(`Appeared ${appeared.length}, passed ${passed.length}, ${passPct}%`);
console.log(`Topper: ${topper.name}`);
console.log(meritList.join("\n"));
console.log(results[0].name);          // the original order is untouched
```

```text [Output]
Appeared 4, passed 3, 75%
Topper: Priya Nair
1. Priya Nair (91)
2. Anita Rao (78)
3. Meena Iyer (40)
Anita Rao
```

Notice the absent student is removed **before** anything is counted. Counting
`null` as 0 would have made the pass percentage 60% and failed a student who
never sat the paper.

## What confuses people here

**`map` against `forEach`.** `map` returns a new array of what the callback
returned. `forEach` returns `undefined` and exists only for side effects, like
logging. Using `map` and ignoring its result, or using `forEach` and expecting
an array back, are both review comments.

**`find` against `filter`.** `find` returns the first matching **item** (or
`undefined`). `filter` returns an **array** of every match, possibly empty.

**`sort` and `reverse` mutate.** They change the array in place and also
return it, which makes it look as if they returned a copy. Newer browsers have
`toSorted()` and `toReversed()`, which do return copies.

**`reduce` without an initial value** uses the first item as the start. On an
empty array that throws `TypeError: Reduce of empty array with no initial
value`. Pass the initial value (`0`, `{}`, `[]`) every time unless you have a
reason not to.

## Interview questions

::accordion
  :::accordion-item{label="Difference between map and forEach?" icon="i-lucide-message-circle"}
  `map` builds and returns a new array from the callback's return values, and
  leaves the original alone. `forEach` runs the callback for each item and
  returns `undefined`. `[1, 2].map(n => n * 2)` is `[2, 4]`;
  `[1, 2].forEach(n => n * 2)` is `undefined`. Use `map` to transform, `forEach`
  for side effects.
  :::

  :::accordion-item{label="Difference between slice and splice?" icon="i-lucide-message-circle"}
  `slice(start, end)` returns a copy of part of the array and does not change
  it. `splice(start, deleteCount, ...items)` changes the original: it removes
  items, optionally inserts new ones, and returns the removed items.
  :::

  :::accordion-item{label="What does [10, 9, 100, 1].sort() return, and why?" icon="i-lucide-message-circle"}
  `[1, 10, 100, 9]`. Without a comparator, `sort` compares items as strings, so
  `"10"` and `"100"` come before `"9"`. Use `sort((a, b) => a - b)` for numbers.
  :::

  :::accordion-item{label="Write the sum of an array, and a count per group, with reduce." icon="i-lucide-message-circle"}
  ```javascript
  const total = marks.reduce((sum, m) => sum + m, 0);

  const perDept = students.reduce((acc, s) => {
    acc[s.dept] = (acc[s.dept] ?? 0) + 1;
    return acc;
  }, {});
  ```

  `reduce` calls the function with an accumulator and each item, and the
  accumulator becomes whatever the function returned. The second argument is
  the starting accumulator.
  :::

  :::accordion-item{label="How do you remove duplicates from an array?" icon="i-lucide-message-circle"}
  `[...new Set(array)]`. A `Set` keeps only unique values, and spreading it
  gives an array back. `[...new Set(["CSE", "ECE", "CSE"])]` is
  `["CSE", "ECE"]`. For objects, dedupe by a key with `filter` and `findIndex`
  or a `Map`.
  :::

  :::accordion-item{label="Difference between some and every?" icon="i-lucide-message-circle"}
  `some` returns `true` if the callback is true for at least one item, and stops
  at the first. `every` returns `true` only if it is true for all of them, and
  stops at the first false. On an empty array `some` is `false` and `every` is
  `true`.
  :::
