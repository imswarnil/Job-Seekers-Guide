The words are in the glossary; this page is the same material turned into the
questions you will actually hear. Every answer is short on purpose: say the
one-line answer, then prove it with a line of code, then stop. Interviewers
remember candidates who can do that.

## Why this matters in a job

Because a fresher web interview is mostly this page. The first round is often a
written or online test of output-prediction questions, and the technical round
goes through scope, closures, `this`, arrays and async in roughly that order.
The questions that repeat from company to company are not the clever ones.
They are `==` against `===`, hoisting, closures and the event loop, asked again
and again.

## How to use this page

Cover the answer, say yours out loud, then open it. For the output questions,
write your answer on paper before opening, and if you got it wrong, run it in
the browser console and find the rule you missed in its lesson.

## Interview questions

### The language

::accordion
  :::accordion-item{label="1. What is the difference between var, let and const?" icon="i-lucide-message-circle"}
  Scope: `var` is function scoped, `let` and `const` are block scoped.
  Reassignment: `const` cannot be reassigned. Hoisting: `var` is `undefined`
  before its line; `let` and `const` throw (the temporal dead zone).

  ```javascript
  if (true) { var a = 1; let b = 2; }
  console.log(a, typeof b);   // 1 "undefined"
  ```
  :::

  :::accordion-item{label="2. What are the data types in JavaScript?" icon="i-lucide-message-circle"}
  Seven primitives (number, string, boolean, undefined, null, bigint, symbol)
  and objects (including arrays and functions). `typeof null` is `"object"`
  (a historical bug) and `typeof []` is `"object"`, so use `Array.isArray`.
  :::

  :::accordion-item{label="3. Difference between == and ===?" icon="i-lucide-message-circle"}
  `===` compares type and value without conversion; `==` converts types first.
  `0 == ""` is `true`, `0 === ""` is `false`. Use `===`; the one idiomatic `==`
  is `x == null`, which matches both `null` and `undefined`.
  :::

  :::accordion-item{label="4. Difference between null and undefined?" icon="i-lucide-message-circle"}
  `undefined`: never set (missing property, argument, or value). `null`: set on
  purpose to mean empty. `Number(null)` is 0, `Number(undefined)` is `NaN`, and
  `JSON.stringify` drops `undefined` properties but keeps `null` ones.
  :::

  :::accordion-item{label="5. What are truthy and falsy values?" icon="i-lucide-message-circle"}
  Falsy: `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`. Everything
  else is truthy, including `"0"`, `"false"`, `[]` and `{}`. The real bug:
  `if (mark)` treats a mark of 0 as missing; write `if (mark != null)`.
  :::

  :::accordion-item{label="6. Difference between a function declaration, an expression and an arrow function?" icon="i-lucide-message-circle"}
  A declaration is hoisted with its body and can be called before its line. An
  expression is a value in a variable and exists only after that line. An
  arrow function is a shorter expression with no own `this`, no `arguments`,
  and cannot be used with `new`.
  :::

  :::accordion-item{label="7. What is a higher-order function? Give an example." icon="i-lucide-message-circle"}
  A function that takes or returns a function. `filter` takes one:
  `marks.filter(m => m >= 40)`. This returns one:
  `const atLeast = cutoff => mark => mark >= cutoff;`.
  :::
::

### Scope, closures and this

::accordion
  :::accordion-item{label="8. What is hoisting?" icon="i-lucide-message-circle"}
  Before a scope runs, its declarations are registered. Function declarations
  come with their bodies, `var` comes as `undefined`, `let`/`const`/`class`
  come uninitialised (using them throws). Assignments are never hoisted.

  ```javascript
  console.log(typeof grade, String(total));   // function undefined
  function grade() {}
  var total = 100;
  ```
  :::

  :::accordion-item{label="9. What is the temporal dead zone?" icon="i-lucide-message-circle"}
  The stretch of a scope before a `let` or `const` line. The variable exists
  and shadows any outer one, but touching it throws `ReferenceError: Cannot
  access 'x' before initialization`.
  :::

  :::accordion-item{label="10. What is a closure? Write one." icon="i-lucide-message-circle"}
  A function that keeps access to the variables of the scope where it was
  created, even after that scope has returned.

  ```javascript
  function counter() {
    let count = 0;
    return () => ++count;
  }
  const next = counter();
  console.log(next(), next());   // 1 2
  ```

  Uses: private state, function factories, event handlers, debounce.
  :::

  :::accordion-item{label="11. Write a debounce function." icon="i-lucide-message-circle"}
  ```javascript
  function debounce(fn, delay) {
    let timerId;
    return (...args) => {
      clearTimeout(timerId);
      timerId = setTimeout(() => fn(...args), delay);
    };
  }
  ```

  Each call cancels the previous timer, so `fn` runs once, `delay` ms after the
  calls stop. Used on search boxes so typing "Anita" sends one request, not five.
  :::

  :::accordion-item{label="12. What is this?" icon="i-lucide-message-circle"}
  In a regular function, decided by the call: the new object with `new`, the
  argument of `call`/`apply`/`bind`, the object before the dot in a method call,
  and `undefined` (strict) or `window` for a plain call. Arrow functions have no
  `this` and use the surrounding one.
  :::

  :::accordion-item{label="13. Difference between call, apply and bind?" icon="i-lucide-message-circle"}
  ```javascript
  function intro(greeting) { return greeting + ", " + this.name; }
  const s = { name: "Anita" };
  intro.call(s, "Hi");          // "Hi, Anita"   runs now, arguments listed
  intro.apply(s, ["Hello"]);    // "Hello, Anita" runs now, arguments in an array
  const later = intro.bind(s);  // a new function with this fixed; runs when called
  ```
  :::

  :::accordion-item{label="14. Why does a method lose this when passed as a callback, and how do you fix it?" icon="i-lucide-message-circle"}
  Whoever calls the callback calls it without your object before a dot, so
  `this` is not your object. `setTimeout(register.mark, 0)` loses it. Fix with
  an arrow, `setTimeout(() => register.mark(), 0)`, or
  `register.mark.bind(register)`.
  :::
::

### Objects and arrays

::accordion
  :::accordion-item{label="15. Shallow copy against deep copy?" icon="i-lucide-message-circle"}
  `{ ...obj }` copies the top level; nested objects are shared, so changing
  `copy.marks.dbms` changes the original too. `structuredClone(obj)` copies all
  the way down. `JSON.parse(JSON.stringify(obj))` also deep copies but drops
  functions and `undefined` and turns dates into strings.
  :::

  :::accordion-item{label="16. Difference between map, filter, reduce and forEach?" icon="i-lucide-message-circle"}
  `map` returns a new array with one result per item. `filter` returns a new
  array of the items that pass. `reduce` folds the array into one value.
  `forEach` returns `undefined` and is only for side effects.

  ```javascript
  const total = [78, 35, 91].reduce((sum, m) => sum + m, 0);   // 204
  ```
  :::

  :::accordion-item{label="17. How do you remove duplicates from an array?" icon="i-lucide-message-circle"}
  `[...new Set(["CSE", "ECE", "CSE"])]` gives `["CSE", "ECE"]`. A `Set` keeps
  unique values; spreading turns it back into an array.
  :::

  :::accordion-item{label="18. What is prototypal inheritance?" icon="i-lucide-message-circle"}
  Every object links to a prototype. A property not found on the object is
  looked up on its prototype, then that one's prototype, up to `null`. `class`
  and `extends` are syntax over this chain; methods live on the prototype and
  are shared by every instance.
  :::
::

### The DOM and events

::accordion
  :::accordion-item{label="19. What is the DOM?" icon="i-lucide-message-circle"}
  The tree of objects the browser builds from the HTML. JavaScript reads and
  changes it (`querySelector`, `textContent`, `classList`, `append`) and the
  browser redraws the page from it. It is not the HTML file.
  :::

  :::accordion-item{label="20. Difference between textContent and innerHTML?" icon="i-lucide-message-circle"}
  `textContent` sets plain text and never parses it. `innerHTML` parses
  markup, so setting it from user input lets an attacker run script (XSS). Use
  `textContent` for anything a user typed.
  :::

  :::accordion-item{label="21. What is event bubbling, and what is event delegation?" icon="i-lucide-message-circle"}
  Bubbling: after firing on its target, an event travels up through every
  ancestor. Delegation uses that: one listener on a parent, checking
  `event.target.closest(selector)`, handles all children, including ones added
  later.
  :::

  :::accordion-item{label="22. preventDefault against stopPropagation?" icon="i-lucide-message-circle"}
  `preventDefault` stops the browser's default action (a form submit reloading
  the page) but the event still bubbles. `stopPropagation` stops the bubbling
  but not the default action.
  :::
::

### Asynchronous JavaScript

::accordion
  :::accordion-item{label="23. What is a promise, and what are its states?" icon="i-lucide-message-circle"}
  An object for a value that arrives later. Pending, then settled exactly once
  as fulfilled (with a value, handled by `.then`) or rejected (with an error,
  handled by `.catch`).
  :::

  :::accordion-item{label="24. Promise.all against Promise.allSettled?" icon="i-lucide-message-circle"}
  `all` fulfils with every value in order, but rejects as soon as one rejects.
  `allSettled` always fulfils, with `{ status, value }` or `{ status, reason }`
  for each. Use `allSettled` when partial results are still worth showing.
  :::

  :::accordion-item{label="25. What does an async function return, and how do you handle its errors?" icon="i-lucide-message-circle"}
  Always a promise. `await` inside it throws when the awaited promise rejects,
  so `try`/`catch` handles errors:

  ```javascript
  async function load() {
    try {
      const res = await fetch("/api/students");
      if (!res.ok) throw new Error(res.status);
      return await res.json();
    } catch (error) {
      console.log("Could not load: " + error.message);
    }
  }
  ```
  :::

  :::accordion-item{label="26. Does fetch reject on a 404?" icon="i-lucide-message-circle"}
  No. It rejects only when no response arrives (network down, bad host, CORS,
  abort). A 404 or 500 fulfils with `response.ok === false`, so check it every
  time.
  :::

  :::accordion-item{label="27. Explain the event loop." icon="i-lucide-message-circle"}
  One thread runs your code. Timers, network and events are handled by the
  browser, which queues callbacks. Promise callbacks go in the microtask queue,
  timers and events in the task queue. The loop runs one task, then every
  microtask, then paints, then the next task. So: synchronous code, then
  microtasks, then macrotasks.
  :::
::

### What does it print?

Write your answer before opening each one. Every output below is from a real
run.

::accordion
  :::accordion-item{label="28. console.log(typeof typeof 1);" icon="i-lucide-terminal"}
  `string`. `typeof 1` is the string `"number"`, and `typeof` of any string is
  `"string"`.
  :::

  :::accordion-item{label="29. console.log([1, 2, 3] + [4, 5]);" icon="i-lucide-terminal"}
  `1,2,34,5`. `+` with objects converts both to strings: `"1,2,3"` and `"4,5"`,
  then joins them.
  :::

  :::accordion-item{label="30. console.log(0.1 + 0.2 === 0.3);" icon="i-lucide-terminal"}
  `false`. `0.1 + 0.2` is `0.30000000000000004`, because numbers are stored in
  binary floating point and 0.1 cannot be stored exactly. Compare money in paise
  as whole numbers, or check `Math.abs(a - b) < Number.EPSILON`.
  :::

  :::accordion-item{label="31. console.log(1 < 2 < 3, 3 > 2 > 1);" icon="i-lucide-terminal"}
  `true false`. Left to right: `1 < 2` is `true`, and `true < 3` is `1 < 3`,
  `true`. But `3 > 2` is `true`, and `true > 1` is `1 > 1`, `false`.
  :::

  :::accordion-item{label="32. for (var i = 0; i < 3; i++) setTimeout(() => console.log(i), 0);" icon="i-lucide-terminal"}
  `3`, `3`, `3`. One `i` for the whole loop, and the callbacks run after it has
  finished. With `let`: `0`, `1`, `2`.
  :::

  :::accordion-item{label="33. async function f() { console.log('A'); await null; console.log('B'); } f(); console.log('C');" icon="i-lucide-terminal"}
  `A`, `C`, `B`. An async function runs synchronously until its first `await`;
  the rest is queued as a microtask, which runs after the synchronous `C`.
  :::

  :::accordion-item{label="34. console.log(['10', '10', '10'].map(parseInt));" icon="i-lucide-terminal"}
  `[10, NaN, 2]`. `map` passes three arguments: the item, the index and the
  array. So it calls `parseInt("10", 0)` (base 0 means default, 10),
  `parseInt("10", 1)` (base 1 is invalid, `NaN`) and `parseInt("10", 2)`
  (binary 10 is 2). Write `.map(Number)` or `.map(s => parseInt(s, 10))`.
  :::

  :::accordion-item{label="35. const s = { dept: 'CSE', show() { return () => this.dept; } }; console.log(s.show()());" icon="i-lucide-terminal"}
  `CSE`. The arrow function takes `this` from `show`, and `show` was called as
  `s.show()`, so `this` is `s`.
  :::

  :::accordion-item{label="36. function f() { return, then a line break, then { ok: true }; } console.log(f());" icon="i-lucide-terminal"}
  `undefined`. JavaScript inserts a semicolon after a `return` followed by a
  line break (automatic semicolon insertion), so the function returns nothing
  and the object is never reached. Keep the opening brace on the same line as
  `return`.
  :::

  :::accordion-item{label="37. console.log(typeof NaN, [] == 0, null + 1, undefined + 1);" icon="i-lucide-terminal"}
  `number true 1 NaN`. `NaN` is a number value. `[]` becomes `""` becomes 0.
  `null` becomes 0 in maths; `undefined` becomes `NaN`.
  :::

  :::accordion-item{label="38. let x = 10; { let x = 20; } console.log(x);" icon="i-lucide-terminal"}
  `10`. The inner `let x` is a different variable that exists only inside the
  braces. With `var` in both places it would print `20`.
  :::

  :::accordion-item{label="39. const marks = [78, 82]; const copy = marks; copy.push(91); console.log(marks.length);" icon="i-lucide-terminal"}
  `3`. `copy` is not a copy; it is a second name for the same array. A real
  copy is `[...marks]`.
  :::
::

a minute each. The fastest way to prepare is this page plus the browser
console: for every one you miss, run it, change one thing, and run it again
until the rule is obvious.
