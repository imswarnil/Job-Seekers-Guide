Everything in the last two lessons followed one rule: where the code is written
decides what it can see. `this` breaks that rule. In a regular function, `this`
is decided by **how the function is called**, at the moment it is called, and
the same function can get a different `this` on every call.

## Why this matters in a job

Because "`this` is undefined" and "cannot read properties of undefined" are two
of the most common errors in front-end code, and nearly every one of them is a
method that was passed somewhere as a callback and lost its object. In
interviews, "explain `this`" is standard, and so is a snippet with a method, an
arrow function and a `setTimeout` and the question "what does each line print?"

## Who is holding the phone

In Java, `this` is always the object whose method is running. It is fixed.

In JavaScript, think of a function as a phone script that says "Hello, this is
**me** speaking". Who "me" is depends on who is holding the phone when the
script is read out. The department office reads it: "this is the CSE office".
The same script, read by the library: "this is the library". Somebody reads it
with no one's phone: nobody is "me".

The rules, in the order JavaScript checks them:

::steps
### Called with new

`new Student("Anita")`: `this` is the brand-new object being built.

### Called with call, apply or bind

`grade.call(anita)`: `this` is whatever you passed, `anita`.

### Called as a method, with a dot

`anita.introduce()`: `this` is the object before the dot, `anita`.

### Called plainly, with nothing before it

`introduce()`: `this` is `undefined` in strict mode (modules, classes), or the
global `window` object in an old-style script. Either way, not what you wanted.

### Arrow functions skip all of this

An arrow function has **no `this` of its own**. It uses the `this` of the
scope it was written in, following lexical scope like any other variable.
::

## How it works

```javascript [this.js]
function introduce(greeting) {
  return greeting + ", I am " + this.fullName;
}

const anita = { fullName: "Anita Rao", introduce };
const vikram = { fullName: "Vikram Shah" };

// Method call: this is the object before the dot.
console.log(anita.introduce("Hello"));

// call and apply: pass this explicitly. apply takes the arguments as an array.
console.log(introduce.call(vikram, "Hi"));
console.log(introduce.apply(vikram, ["Namaste"]));

// bind: returns a NEW function with this fixed forever.
const vikramIntro = introduce.bind(vikram);
console.log(vikramIntro("Good morning"));

// Losing it: the method is taken off the object, then called plainly.
const detached = anita.introduce;
console.log(detached("Hello"));

// Constructors: new makes a fresh object and sets this to it.
function Student(fullName, dept) {
  this.fullName = fullName;
  this.dept = dept;
}
const priya = new Student("Priya Nair", "ECE");
console.log(priya.fullName + ", " + priya.dept);
```

```text [Output]
Hello, I am Anita Rao
Hi, I am Vikram Shah
Namaste, I am Vikram Shah
Good morning, I am Vikram Shah
Hello, I am undefined
Priya Nair, ECE
```

`detached("Hello")` is a plain call. In an old-style script `this` is `window`,
which has no `fullName`, so you get `undefined`. In a module or a class it is
`undefined` itself, and the line throws instead.

### Arrow functions inside methods

This is where arrow functions earn their place.

```javascript [course.js]
const course = {
  title: "Operating Systems",
  students: ["Anita", "Vikram"],

  listWithArrow() {
    // The arrow has no this, so it uses listWithArrow's this: course.
    return this.students.map(name => name + " in " + this.title);
  },

  listWithFunction() {
    // A regular function called by map, plainly: this is lost.
    return this.students.map(function (name) {
      return name + " in " + this.title;
    });
  }
};

console.log(course.listWithArrow().join("; "));
console.log(course.listWithFunction().join("; "));
```

```text [Output]
Anita in Operating Systems; Vikram in Operating Systems
Anita in undefined; Vikram in undefined
```

::runner{lang="javascript"}
```javascript
class AttendanceRegister {
  constructor(subject) {
    this.subject = subject;
    this.present = 0;
  }
  mark() {
    this.present++;
    return this.subject + ": " + this.present;
  }
}

const dbms = new AttendanceRegister("DBMS");
console.log(dbms.mark());

// Taken off the object. Classes are strict, so this is undefined.
const mark = dbms.mark;
try {
  mark();
} catch (error) {
  console.log(error.name + ": " + error.message);
}

// bind fixes it.
const boundMark = dbms.mark.bind(dbms);
console.log(boundMark());
```
::

```text [Output]
DBMS: 1
TypeError: Cannot read properties of undefined (reading 'present')
DBMS: 2
```

## Real use case

The everyday version is a method handed to the browser as a callback. The
browser calls it plainly, or with `this` set to the clicked element, and the
object is gone.

```javascript [register-page.js]
class AttendanceRegister {
  constructor(subject, button) {
    this.subject = subject;
    this.present = 0;

    // Bug: the browser calls mark with this = the button, not the register.
    // button.addEventListener("click", this.mark);

    // Fix 1: an arrow function, so this stays the register.
    button.addEventListener("click", () => this.mark());

    // Fix 2: bind once in the constructor.
    // button.addEventListener("click", this.mark.bind(this));
  }

  mark() {
    this.present++;
    console.log(`${this.subject}: ${this.present} present`);
  }
}
```

```text [Output]
DBMS: 1 present
DBMS: 2 present
```

(That output is what two clicks on the button print with either fix. With the
buggy line, each click prints `undefined: NaN present`, because `this` is the
button, which has no `subject` and no `present`.)

The same thing happens with `setTimeout(register.mark, 1000)`, and the same two
fixes apply.

## What confuses people here

**An arrow function as an object's method.** `const course = { title: "OS",
show: () => this.title }` does **not** give `"OS"`. The arrow takes `this` from
where the object literal is written, which is the outer scope, not the object.
Use arrows **inside** methods, and ordinary method syntax **for** methods.

**bind cannot be re-bound.** `f.bind(a).bind(b)` still has `this` as `a`. The
first `bind` wins, and arrow functions ignore `bind` entirely.

## Interview questions

::accordion
  :::accordion-item{label="What is this in JavaScript?" icon="i-lucide-message-circle"}
  A reference decided by how a regular function is called. With `new`, the new
  object. With `call`/`apply`/`bind`, the object you passed. As a method
  (`obj.fn()`), the object before the dot. As a plain call, `undefined` in
  strict mode or `window` otherwise. Arrow functions have no `this` and use the
  surrounding scope's.
  :::

  :::accordion-item{label="Difference between call, apply and bind?" icon="i-lucide-message-circle"}
  All three set `this`. `call` runs the function now with arguments listed:
  `fn.call(obj, a, b)`. `apply` runs it now with arguments in an array:
  `fn.apply(obj, [a, b])`. `bind` does not run it; it returns a new function
  with `this` (and optionally some arguments) fixed: `const g = fn.bind(obj)`.
  :::

  :::accordion-item{label="Why does a method lose this when passed as a callback?" icon="i-lucide-message-circle"}
  Because `this` is decided by the call, and whoever calls the callback (the
  browser, `setTimeout`, `map`) calls it plainly, without your object before a
  dot. `setTimeout(reg.mark, 0)` passes only the function. Fix with
  `setTimeout(() => reg.mark(), 0)` or `setTimeout(reg.mark.bind(reg), 0)`.
  :::

  :::accordion-item{label="What does this print? const o = { n: 'CSE', a: () => this.n, b() { return this.n; } }; console.log(o.b(), o.a());" icon="i-lucide-message-circle"}
  `CSE undefined`. `b` is a regular method called with a dot, so `this` is
  `o`. `a` is an arrow function, so its `this` is the one outside the object
  literal (the global scope), which has no `n`. In a module the outer `this`
  is `undefined`, so `o.a()` throws instead.
  :::

  :::accordion-item{label="What is this inside an event handler?" icon="i-lucide-message-circle"}
  With a regular function passed to `addEventListener`, `this` is the element
  the listener is attached to (the same as `event.currentTarget`). With an
  arrow function, it is whatever `this` was where the arrow was written. Using
  `event.currentTarget` is clearer than relying on either.
  :::
::
