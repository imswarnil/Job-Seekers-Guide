A recorded lecture, a campus map from another site, and your own data tucked
into an element for JavaScript to read later. These are the three things HTML
embeds, and each has one detail interviewers like to ask about.

## Why this matters in a job

Before HTML5, video on a web page needed a plug-in called Flash, which crashed,
drained batteries and was eventually removed from every browser. `<video>` and
`<audio>` replaced it. Iframes are how YouTube videos, Google Maps and payment
pages are embedded, and they come with security settings you are expected to
know. `data-*` attributes are everywhere in real front-end code. "What are data
attributes?" and "what is an iframe, and is it safe?" are standard fresher
questions.

## Three ways of putting something inside a page

Think of a college seminar hall. Some things are the hall's own: the projector
and speakers (**video and audio**). Some things are a window into another room
entirely, controlled by whoever is in that room (**an iframe**). And some are the
sticky notes the organiser puts on each chair, meant for staff and not the
audience (**data attributes**).

## How it works

### Video and audio

```html [lecture.html]
<video controls width="640" height="360"
       poster="/lectures/os-week3.jpg" preload="metadata">
  <source src="/lectures/os-week3.webm" type="video/webm">
  <source src="/lectures/os-week3.mp4"  type="video/mp4">
  <track kind="captions" src="/lectures/os-week3.en.vtt"
         srclang="en" label="English" default>
  Your browser cannot play this video.
  <a href="/lectures/os-week3.mp4">Download it instead</a>.
</video>

<audio controls src="/podcasts/placement-tips.mp3"></audio>
```

- `controls` shows play, pause, volume and the timeline. Leave it out and the
  user has no way to play the video.
- Several `<source>` elements: the browser plays the **first format it
  supports**.
- `<track kind="captions">` adds subtitles from a WebVTT file. Captions are an
  accessibility requirement for anybody who cannot hear the audio, and are used
  by many people who can (on a bus, in a library).
- `poster` is the image shown before playing. `preload="metadata"` fetches only
  the length and dimensions, not the whole file.
- `autoplay` only works when combined with `muted` in modern browsers, because
  pages that shouted at people were blocked.

### Iframes

An `<iframe>` (inline frame) displays **another whole web page** inside a
rectangle of yours.

```html [campus.html]
<iframe
  src="https://www.youtube-nocookie.com/embed/VIDEO_ID"
  title="Campus tour, 2026"
  width="560" height="315"
  loading="lazy"
  allow="fullscreen"
  sandbox="allow-scripts allow-same-origin">
</iframe>
```

- `title` is required for accessibility: it is what a screen reader announces
  for the frame.
- `sandbox` restricts what the embedded page can do. With `sandbox=""` and no
  values, it cannot run scripts, submit forms, or open pop-ups. You add back
  only what it needs.
- `loading="lazy"` delays loading until it is near the screen, which matters
  because each iframe is a full page load.

The other direction matters too. A site can refuse to be framed with the HTTP
header `X-Frame-Options: DENY` or a Content Security Policy
`frame-ancestors` rule. Banks do this to prevent **clickjacking**, where an
attacker frames the real page invisibly on top of a harmless-looking button.

### Data attributes

Any attribute that starts with `data-` is yours. The browser ignores it, and
JavaScript reads it through `element.dataset`.

::runner{lang="html"}
```html
<ul>
  <li data-roll-no="CS21001" data-cgpa="8.4">Anita Rao</li>
  <li data-roll-no="CS21002" data-cgpa="7.1">Vikram Shah</li>
</ul>
<p id="out"></p>
<script>
  const first = document.querySelector('li');
  document.getElementById('out').textContent =
    first.dataset.rollNo + ' has a CGPA of ' + first.dataset.cgpa;
</script>
```
::

```text [Rendered]
• Anita Rao
• Vikram Shah
CS21001 has a CGPA of 8.4
```

`data-roll-no` becomes `dataset.rollNo`: the hyphenated name is converted to
camelCase. Every value comes back as a **string**, so `"8.4"` needs
`Number(...)` before arithmetic.

## Real use case

A results table where each "View" button knows which student it belongs to,
without a global variable or a hidden input:

```html [results.html]
<tr>
  <td>Anita Rao</td><td>78</td>
  <td><button type="button" data-student-id="4211">View marksheet</button></td>
</tr>
```

```javascript [results.js]
document.querySelector('table').addEventListener('click', (event) => {
  const button = event.target.closest('button[data-student-id]');
  if (!button) return;
  openMarksheet(button.dataset.studentId);   // "4211"
});
```

One listener on the table handles every button, because each button carries its
own id. You will see this pattern again in the JavaScript track, where it is
called event delegation. Testing tools use the same idea: `data-testid="submit"`
gives automated tests a hook that does not break when the CSS classes change.

## What confuses people here

- **Data attributes are not private.** Anybody can read them with view source.
  Never put a password, token or anything secret in one.
- **Data attributes are not for styling state that has a real attribute.** A
  disabled button is `disabled`, not `data-disabled="true"`.
- **An iframe is not a way to include part of your own page.** It loads a
  complete separate document, with its own styles and scripts, which is slow.
- **`autoplay` without `muted` silently does nothing** in Chrome and Safari,
  which looks like a bug in your code.

## Interview questions

::accordion
  :::accordion-item{label="What are data attributes, and how do you read them?" icon="i-lucide-message-circle"}
  Custom attributes starting with `data-`, used to store extra information on an
  element. Read them with `element.dataset.name`, where `data-student-id`
  becomes `dataset.studentId`, or with `getAttribute('data-student-id')`. The
  value is always a string.
  :::
  :::accordion-item{label="What is an iframe, and what are its risks?" icon="i-lucide-message-circle"}
  An element that embeds another HTML page inside the current one. Risks: the
  embedded page may run scripts, so use `sandbox`; and your own page can be
  framed by an attacker for clickjacking, which you prevent with
  `X-Frame-Options` or CSP `frame-ancestors`. Always give it a `title`.
  :::
  :::accordion-item{label="Why can a video have several source elements?" icon="i-lucide-message-circle"}
  Browsers support different formats. The browser tries each `<source>` in
  order and plays the first whose `type` it can handle.
  :::
  :::accordion-item{label="Why does my video not autoplay?" icon="i-lucide-message-circle"}
  Browsers block autoplay with sound. Add `muted` (and `playsinline` for iOS)
  and it will autoplay.
  :::
::
