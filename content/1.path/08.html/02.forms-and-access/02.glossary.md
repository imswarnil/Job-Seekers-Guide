Two chapters of HTML, in one page of words.

## Structure

| Term | In one line |
| --- | --- |
| **Semantic element** | One whose name says what it *is*: `<nav>`, `<table>`, `<button>`. Not `<div>`. |
| **Landmark** | `header`, `nav`, `main`, `aside`, `footer`. How a screen reader user navigates a page without reading it. |
| **`<main>`** | The unique content of this page. Exactly one per page. |
| **Heading outline** | `h1` to `h6` as a tree, not as sizes. Skipping a level breaks it; size is CSS. |
| **`lang`** | On `<html>`. Decides which voice a screen reader uses. One attribute, and most pages omit it. |
| **`alt`** | What the image *conveys*, not what it depicts. `alt=""` means "decorative, skip it" and is different from omitting it. |
| **`scope`** | On a `<th>`. Tells a screen reader which cells a heading governs, so a number is read as "Score, 78". |
| **Link or button** | A link goes somewhere; a button does something. If opening it in a new tab makes sense, it is a link. |
| **`data-*`** | Your own attributes, readable from JavaScript as `element.dataset`. |

## Forms

| Term | In one line |
| --- | --- |
| **`label` + `for`** | Not a caption. It makes the label part of the tap target and is what a screen reader announces. |
| **`type`** | `email`, `tel`, `number`, `date`. Decides the keyboard that appears on a phone. |
| **`inputmode`** | Refines the keyboard without changing validation. `numeric` for a percentage. |
| **`autocomplete`** | Lets the browser fill what it already knows, correctly spelled. Omitting it is the most common unforced error in forms. |
| **`aria-describedby`** | Ties hint or error text to a field, so it is announced with the label. |
| **`aria-invalid`** | Marks a field as failing, so assistive technology says so. |
| **`fieldset` / `legend`** | Groups fields and names the group. Essential for radio buttons, where the question *is* the legend. |
| **`required`** | Browser-level validation. A kindness to an honest user, never a rule. |
| **Progressive enhancement** | It works without JavaScript, and is better with it. A real `<form>` gets this free. |

## Accessibility

| Term | In one line |
| --- | --- |
| **Screen reader** | Software that reads a page aloud. VoiceOver on macOS, NVDA on Windows, both free. |
| **Focus order** | The order Tab moves through controls. Follows the DOM, which is why source order matters. |
| **Focus visible** | The outline showing where you are. Removing it without a replacement makes a page unusable by keyboard. |
| **WCAG** | The standard. AA is what most organisations are held to and what a client will ask about. |
| **Contrast ratio** | 4.5:1 for body text at AA. Placeholder text usually fails it, which is one reason it is not a label. |
| **ARIA** | Attributes that add meaning HTML cannot express. The first rule of ARIA is to use the right element instead. |

## The three sentences to keep

::pull-quote
The right element is not a style choice: `<div onclick>` cannot be reached by
keyboard, so the feature does not exist for that person. `alt` carries the
information, not the picture. And a front-end check is a kindness, never a rule.
::
