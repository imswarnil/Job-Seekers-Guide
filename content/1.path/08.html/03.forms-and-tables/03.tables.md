A merit list, a results sheet, an exam timetable. Once a college has collected
data, it publishes some of it back as rows and columns, and that is the one job
the HTML table is for.

## Why this matters in a job

Admin screens, reports and dashboards are full of tables, and so are interview
tasks ("build a timetable in HTML" is a classic machine-round exercise at
training institutes and in walk-ins). Interviewers ask about `colspan` and
`rowspan`, the difference between `th` and `td`, and, as a trap, whether you
would use a table to lay out a page. The answer to the last one is no, and you
need to say why.

## A table is a grid with headings

Think of the printed exam timetable on a college notice board. Across the top:
the days. Down the side: the time slots. Each cell is the paper at that time on
that day. You read any cell by looking up to its column heading and across to
its row heading. An HTML table writes those relationships down, so a screen
reader can do the same looking up and across out loud.

The elements:

- `<table>` the whole thing; `<caption>` its title.
- `<thead>`, `<tbody>`, `<tfoot>` the header rows, the body rows, the summary
  rows.
- `<tr>` a table row.
- `<th>` a header cell; `<td>` a data cell.
- `scope="col"` or `scope="row"` on a `th` says which cells it heads.
- `colspan="2"` makes a cell span two columns; `rowspan="2"` two rows.

## How it works

::runner{lang="html"}
```html
<table border="1" cellpadding="6">
  <caption>End-semester timetable, B.Tech CSE, semester 3</caption>
  <thead>
    <tr>
      <th scope="col">Time</th>
      <th scope="col">Monday</th>
      <th scope="col">Tuesday</th>
      <th scope="col">Wednesday</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">10:00–13:00</th>
      <td>Operating Systems</td>
      <td>Computer Networks</td>
      <td rowspan="2">DBMS practical (10:00–17:00)</td>
    </tr>
    <tr>
      <th scope="row">14:00–17:00</th>
      <td colspan="2">Seminar: placement preparation</td>
    </tr>
  </tbody>
  <tfoot>
    <tr>
      <td colspan="4">Report 30 minutes early with your hall ticket.</td>
    </tr>
  </tfoot>
</table>
```
::

```text [Rendered]
            End-semester timetable, B.Tech CSE, semester 3
+-------------+-------------------+-------------------+-------------------+
| Time        | Monday            | Tuesday           | Wednesday         |
+-------------+-------------------+-------------------+-------------------+
| 10:00–13:00 | Operating Systems | Computer Networks | DBMS practical    |
+-------------+---------------------------------------+ (10:00–17:00)     |
| 14:00–17:00 | Seminar: placement preparation        |                   |
+-------------+---------------------------------------+-------------------+
| Report 30 minutes early with your hall ticket.                          |
+-------------------------------------------------------------------------+
```

Count the cells in each row. Row one has four. Row two has only **two**
written, because the `colspan="2"` cell takes two columns and the Wednesday
column is still occupied by the `rowspan="2"` cell from the row above. Getting
that count wrong is the most common table bug: an extra cell pushes out past
the edge of the grid.

## Real use case

A marks report in an admin screen, with the details that make it usable:

```html [marks-report.html]
<table>
  <caption>Semester 3 marks, computer science (60 students)</caption>
  <thead>
    <tr>
      <th scope="col">Roll no.</th>
      <th scope="col">Student</th>
      <th scope="col">OS</th>
      <th scope="col">CN</th>
      <th scope="col">Total</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>CS21001</td>
      <th scope="row">Anita Rao</th>
      <td>78</td><td>84</td><td>162</td>
    </tr>
  </tbody>
  <tfoot>
    <tr>
      <th scope="row" colspan="2">Class average</th>
      <td>71.5</td><td>74.2</td><td>145.7</td>
    </tr>
  </tfoot>
</table>
```

```text [A screen reader, on the cell 84]
"Anita Rao. CN, 84."
```

The student's name is a row header (`th scope="row"`), so every cell in that
row is announced with the name, and the subject heading above it. Without
`scope` and `th`, the user hears "84" and must remember which column and row
they are in, across 60 rows. On wide tables, teams also wrap the table in a
container with horizontal scrolling so it does not break a phone layout.

::warning{icon="i-lucide-alert-triangle"}
**Never use a table for page layout.** Before CSS could do columns, whole sites
were built as one big table, and some old college sites still are. A screen
reader then announces "table, 3 columns" for the page itself and reads every
section as a cell. It cannot reflow on a phone, and the markup is hard to
change. Layout is CSS's job: flexbox and grid, in the next track.
::

## What confuses people here

- **`th` is not "bold `td`".** It is a header, and screen readers use it. Bold
  text comes from default styling, which you can change.
- **`thead` and `tbody` are optional in the source, but the browser adds
  `tbody` anyway.** A CSS selector like `table > tr` then matches nothing,
  because the DOM is `table > tbody > tr`.
- **`caption` versus a heading above the table.** A heading is fine for the page
  outline; `caption` is what is announced as the table's name. Use `caption`,
  and a heading too if the table starts a section.
- **The `border` and `cellpadding` attributes** in the runner above are old
  presentational HTML, used there so the grid is visible without CSS. In real
  code, borders and padding are CSS.

## Interview questions

::accordion
  :::accordion-item{label="Difference between th and td?" icon="i-lucide-message-circle"}
  `th` is a header cell and `td` a data cell. `th` carries meaning (screen
  readers announce it with the data) and, with `scope`, says whether it heads a
  column or a row. Default styling makes `th` bold and centred.
  :::
  :::accordion-item{label="What do colspan and rowspan do?" icon="i-lucide-message-circle"}
  `colspan="n"` makes a cell stretch across n columns; `rowspan="n"` down n
  rows. The cells they cover must be left out of the markup, or the row gets
  too many cells.
  :::
  :::accordion-item{label="Why should you not use tables for layout?" icon="i-lucide-message-circle"}
  They mean "tabular data", so screen readers announce the layout as a data
  table; they cannot reflow for small screens; they mix structure with
  presentation; and they are heavy to maintain. Use CSS flexbox or grid.
  :::
  :::accordion-item{label="What are thead, tbody and tfoot for?" icon="i-lucide-message-circle"}
  They group header, body and footer rows. They help screen readers, let CSS
  style each part, let the header repeat on every printed page, and let a long
  body scroll while the header stays in place.
  :::
  :::accordion-item{label="What does the scope attribute do?" icon="i-lucide-message-circle"}
  On a `th`, `scope="col"` or `scope="row"` tells assistive technology which
  cells that header describes, so each data cell is announced with its heading.
  :::
::
