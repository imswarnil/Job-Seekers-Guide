of words, which is the page to read on the morning of a walk-in.

## Why this matters in a job

An interviewer rarely asks "define `scope`". They ask a question that assumes
you know the word, and your answer falls apart if you do not. Every term below
came up in this track, and most of them come up in interviews.

## The document

| Term | In one line |
| --- | --- |
| **HTML** | HyperText Markup Language. Describes what each piece of a page *is*, not how it looks. |
| **Doctype** | `<!doctype html>`. Switches the browser into standards mode. Not an element. |
| **Quirks mode** | What the browser falls back to without a doctype: imitating 1990s browsers. |
| **Tag** | The text in angle brackets, `<p>` or `</p>`. |
| **Element** | Opening tag, content and closing tag together; a node in the tree. |
| **Attribute** | `name="value"` on an opening tag: `href`, `id`, `class`, `lang`. |
| **Void element** | Has no content and no closing tag: `br`, `img`, `input`, `meta`, `link`, `hr`. |
| **DOM** | The Document Object Model: the tree of elements the browser builds from the HTML. What JavaScript and developer tools see. |
| **Block element** | Starts on a new line, takes the full width: `div`, `p`, `h1`, `ul`. |
| **Inline element** | Flows inside text, only as wide as its content: `span`, `a`, `strong`. |
| **`div` / `span`** | The generic block and inline containers, with no meaning. |

## Content and semantics

| Term | In one line |
| --- | --- |
| **Semantic element** | One whose name says what it is: `nav`, `table`, `button`. |
| **Heading outline** | `h1` to `h6` as a tree, not sizes. One `h1`, no skipped levels. |
| **Landmark** | A region a screen reader can jump to: `header`, `nav`, `main`, `aside`, `footer`. |
| **`main`** | The unique content of the page. One visible per page. |
| **`article`** | Self-contained content that makes sense on its own. |
| **`section`** | A themed part of something, normally with a heading. |
| **`aside`** | Related but not central content: a sidebar. |
| **`figure` / `figcaption`** | An illustration or chart and its caption. |
| **`alt`** | The text alternative for an image. `alt=""` means decorative. |
| **Absolute URL** | Includes scheme and host: `https://college.example/fees`. |
| **Relative URL** | Resolved against the current page: `/fees`, `fees`, `../fees`. |
| **`rel="noopener"`** | Stops a page opened with `target="_blank"` controlling yours. |
| **Layout shift** | Content jumping as late images load; prevented by `width` and `height`. |
| **`iframe`** | Embeds a whole other page in a rectangle of yours. |
| **`sandbox`** | Restricts what an iframe's page may do. |
| **Clickjacking** | Framing a real page invisibly to trick clicks; blocked by `X-Frame-Options`. |
| **`data-*`** | Your own attributes, read in JavaScript as `element.dataset`. Always strings, never secret. |

## Forms and tables

| Term | In one line |
| --- | --- |
| **`action` / `method`** | Where the form is sent, and how (GET or POST). |
| **GET** | Values in the URL. For searching and filtering. |
| **POST** | Values in the body. For creating, logging in, paying, uploading. |
| **`name`** | The key a value is sent under. No `name`, not sent. |
| **`label for`** | Ties a label to an input's `id`: clickable, and announced by screen readers. |
| **`fieldset` / `legend`** | Groups fields and names the group. |
| **`enctype="multipart/form-data"`** | Required to upload files. |
| **Button types** | `submit` (the default in a form), `reset`, `button`. |
| **Built-in validation** | `required`, `min`, `max`, `step`, `minlength`, `maxlength`, `pattern`, and the input type. |
| **`novalidate`** | Turns off the browser's validation for a form. |
| **`autocomplete`** | Lets the browser fill known values correctly. |
| **`th` / `td`** | Header cell and data cell. |
| **`scope`** | On `th`: which cells it heads, `col` or `row`. |
| **`colspan` / `rowspan`** | A cell stretching across columns or down rows. |
| **`caption`** | The table's name, announced by screen readers. |

## Accessibility and the head

| Term | In one line |
| --- | --- |
| **Accessibility (a11y)** | A page usable by people with disabilities. |
| **Screen reader** | Reads the page aloud: NVDA, VoiceOver, TalkBack. |
| **WCAG** | The accessibility standard. AA is the usual target. |
| **Contrast ratio** | 4.5:1 for normal text at AA. |
| **Focus / focus ring** | Which element receives keys, and the outline showing it. |
| **`tabindex`** | `0` into the tab order, `-1` script-only, positive values avoided. |
| **ARIA** | Attributes that add meaning HTML cannot. Native HTML first. |
| **`aria-label`** | A name for an element with no visible text. |
| **`aria-describedby`** | Ties hint or error text to a field. |
| **`charset`** | How to decode the bytes. `utf-8`, early in the head. |
| **Viewport meta** | Makes a phone use its own width instead of pretending to be a desktop. |
| **Open Graph** | `og:` meta tags that build link previews. |
| **`defer`** | Download in parallel, run after parsing, in order. |
| **`async`** | Download in parallel, run as soon as ready, any order. |
| **localStorage** | About 5 MB per site, until cleared, never sent to the server. |
| **sessionStorage** | Same, but one tab, cleared when it closes. |
| **Cookie** | About 4 KB, sent with every request; `HttpOnly`, `Secure`, `SameSite`. |

## The pairs people confuse

::feature-list{columns="2"}
  :::feature{icon="i-lucide-git-compare" title="head and header"}
  `head` is information about the document, never shown. `header` is a visible
  banner on the page or in an article.
  :::
  :::feature{icon="i-lucide-git-compare" title="id and name"}
  `id` is for the page and unique. `name` is what the server receives.
  :::
  :::feature{icon="i-lucide-git-compare" title="section and article"}
  A section is a titled part of something. An article stands on its own.
  :::
  :::feature{icon="i-lucide-git-compare" title="strong and b"}
  `strong` means important. `b` only looks bold.
  :::
  :::feature{icon="i-lucide-git-compare" title="defer and async"}
  `defer` waits for parsing and keeps order. `async` runs whenever it arrives.
  :::
  :::feature{icon="i-lucide-git-compare" title="alt missing and alt empty"}
  Missing: the file name is read aloud. Empty: the image is skipped on purpose.
  :::
::

## Real use case

When I was preparing in BTM, the thing that helped most before an interview was
reading a list like this aloud and stopping at every term I could not explain in
one sentence. Those were the ones I went back to. Do the same: any term here you
cannot say in one breath, return to the lesson it came from.

## Interview questions

::accordion
  :::accordion-item{label="Explain the difference between head and header in one sentence." icon="i-lucide-message-circle"}
  `head` holds information about the document (title, meta, stylesheets) and is
  never shown; `header` is visible introductory content at the top of the page or
  of an article.
  :::
  :::accordion-item{label="What is a void element? Give three." icon="i-lucide-message-circle"}
  An element with no content and no closing tag: `img`, `input`, `br`.
  :::
  :::accordion-item{label="Which three storage options does the browser give a page?" icon="i-lucide-message-circle"}
  localStorage, sessionStorage and cookies (plus IndexedDB for larger data).
  :::
::
