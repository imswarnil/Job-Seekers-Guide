The glossary gave you the words. These are the questions built from them, in
roughly the order an interviewer reaches for them: structure first, then
semantics, forms, accessibility and the head.

## Why this matters in a job

In a fresher web round, HTML questions are fast. An interviewer can ask six in
five minutes, and each answer tells them whether you learned the tags or learned
what the tags are for. A short, confident answer with one example beats a long
recitation every time. Read each question, answer it aloud before opening it,
then compare.

## Interview questions

### The document

::accordion
  :::accordion-item{label="1. What is HTML? Is it a programming language?" icon="i-lucide-message-circle"}
  HyperText Markup Language: it describes the structure and meaning of a
  document. It is a markup language, not a programming language, because it has
  no logic (no variables, conditions or loops). Structure is HTML, appearance is
  CSS, behaviour is JavaScript.
  :::
  :::accordion-item{label="2. What does the doctype do?" icon="i-lucide-message-circle"}
  `<!doctype html>` puts the browser in standards mode. Without it, the browser
  uses quirks mode and imitates old browsers, which changes layout behaviour.
  :::
  :::accordion-item{label="3. Tag, element and attribute: the difference?" icon="i-lucide-message-circle"}
  ```html
  <a href="/faculty">Faculty</a>
  ```
  `<a>` and `</a>` are tags. The whole line is an element. `href="/faculty"` is
  an attribute.
  :::
  :::accordion-item{label="4. Block versus inline elements?" icon="i-lucide-message-circle"}
  Block elements start on a new line and fill the width (`div`, `p`, `h1`,
  `ul`). Inline elements flow in text and are as wide as their content (`span`,
  `a`, `strong`). A plain inline element ignores `width` and `height`.
  :::
  :::accordion-item{label="5. What is the DOM, and how is it different from the HTML source?" icon="i-lucide-message-circle"}
  The tree of objects the browser builds from the HTML. It can differ from the
  source because the parser fixes errors (closing a `p` before a `div`, adding
  `tbody`) and JavaScript changes it after load.
  :::
::

### Semantics and content

::accordion
  :::accordion-item{label="6. What is semantic HTML and why use it?" icon="i-lucide-message-circle"}
  Elements whose names describe their content. It serves screen readers
  (structure and landmarks), keyboards (native focus and activation), search
  engines (meaning) and developers (readable, stable selectors). Example:
  `<div class="button">` cannot be reached with Tab; `<button>` can.
  :::
  :::accordion-item{label="7. Difference between div, section and article?" icon="i-lucide-message-circle"}
  `div` has no meaning and is for layout and styling. `section` is a themed
  part of something, normally with a heading. `article` is self-contained and
  would make sense on its own, like a notice or a comment.
  :::
  :::accordion-item{label="8. Name the HTML5 semantic elements." icon="i-lucide-message-circle"}
  `header`, `nav`, `main`, `article`, `section`, `aside`, `footer`, `figure`,
  `figcaption`, `time`, `mark`, `details`, `summary`.
  :::
  :::accordion-item{label="9. What is the alt attribute for, and when is it empty?" icon="i-lucide-message-circle"}
  The text alternative for an image, read by screen readers and shown if the
  image fails. It describes what the image conveys. `alt=""` marks a decorative
  image to skip; a missing `alt` makes screen readers read the file name.
  :::
  :::accordion-item{label="10. strong versus b, em versus i?" icon="i-lucide-message-circle"}
  `strong` (importance) and `em` (stress) carry meaning; `b` and `i` are only
  visual. They look the same by default.
  :::
  :::accordion-item{label="11. Why add rel=noopener to target=_blank links?" icon="i-lucide-message-circle"}
  The opened page could otherwise use `window.opener` to redirect your tab to a
  fake page (tabnabbing). Modern browsers imply it, but it is still expected.
  ```html
  <a href="https://results.college.example" target="_blank" rel="noopener noreferrer">Results</a>
  ```
  :::
  :::accordion-item{label="12. What are data attributes?" icon="i-lucide-message-circle"}
  Custom `data-*` attributes for your own values, read with `dataset`:
  ```html
  <li data-roll-no="CS21001">Anita Rao</li>
  <script>
    console.log(document.querySelector('li').dataset.rollNo); // "CS21001"
  </script>
  ```
  Always strings, never for secrets.
  :::
  :::accordion-item{label="13. What is an iframe, and how do you make it safer?" icon="i-lucide-message-circle"}
  An element that embeds another page. Add a `title`, `sandbox` to limit what
  it can do, and `loading="lazy"`. To stop your own site being framed, send
  `X-Frame-Options: DENY` or CSP `frame-ancestors`.
  :::
::

### Forms and tables

::accordion
  :::accordion-item{label="14. GET versus POST?" icon="i-lucide-message-circle"}
  GET puts data in the URL: visible, bookmarkable, cacheable, limited in size,
  for reading. POST puts it in the body: not in the URL or history, any size,
  files allowed, for changing things. Neither is secure without HTTPS.
  :::
  :::accordion-item{label="15. id versus name on an input?" icon="i-lucide-message-circle"}
  `id` is unique in the page and used by `label for`, CSS and JavaScript. `name`
  is the key the value is submitted under; inputs without a `name` are not sent.
  :::
  :::accordion-item{label="16. Name ten input types." icon="i-lucide-message-circle"}
  `text`, `email`, `password`, `number`, `date`, `tel`, `url`, `checkbox`,
  `radio`, `file`, `range`, `search`, `color`, `hidden`, `time`. Mention that the
  type changes the phone keyboard and the built-in validation.
  :::
  :::accordion-item{label="17. What are the button types, and which is the default?" icon="i-lucide-message-circle"}
  `submit`, `reset`, `button`. Inside a form a `<button>` with no type is
  `submit`.
  :::
  :::accordion-item{label="18. How do you validate a form without JavaScript? Is that enough?" icon="i-lucide-message-circle"}
  ```html
  <input name="marks" type="number" min="0" max="100" required>
  <input name="phone" type="tel" pattern="[6-9][0-9]{9}" required>
  ```
  It is not enough: anybody can bypass the browser, so the server must validate
  again.
  :::
  :::accordion-item{label="19. What do colspan and rowspan do?" icon="i-lucide-message-circle"}
  Make a cell span several columns or rows. The covered cells must be omitted
  from the markup.
  :::
  :::accordion-item{label="20. Why not use tables for layout?" icon="i-lucide-message-circle"}
  Tables mean tabular data, so screen readers announce the layout as data; they
  do not reflow on phones; and they mix structure with presentation. Use CSS
  flexbox or grid.
  :::
::

### Accessibility, the head and storage

::accordion
  :::accordion-item{label="21. How do you make a web page accessible?" icon="i-lucide-message-circle"}
  Semantic elements, `lang` on `html`, alt text, labels on every input, a heading
  outline and landmarks, full keyboard support with visible focus, 4.5:1 contrast,
  captions, ARIA only where HTML cannot. Then test with the keyboard and a screen
  reader, because automated tools catch only part of it.
  :::
  :::accordion-item{label="22. What is ARIA, and when would you use it?" icon="i-lucide-message-circle"}
  Attributes that give assistive technology information HTML cannot express,
  such as `aria-expanded` on a toggle or `aria-label` on an icon-only button.
  Use native HTML first; wrong ARIA is worse than none.
  :::
  :::accordion-item{label="23. What does the viewport meta tag do?" icon="i-lucide-message-circle"}
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1">
  ```
  Tells mobile browsers to lay the page out at the device's width without
  zooming out. Without it, a phone shows a shrunken desktop layout.
  :::
  :::accordion-item{label="24. Script loading: normal, defer, async?" icon="i-lucide-message-circle"}
  A normal script blocks parsing while it downloads and runs. `defer` downloads
  in parallel and runs after parsing, in order. `async` downloads in parallel
  and runs as soon as it arrives, in any order.
  :::
  :::accordion-item{label="25. localStorage, sessionStorage and cookies?" icon="i-lucide-message-circle"}
  localStorage: about 5 MB, persists until cleared, shared across tabs, never
  sent to the server. sessionStorage: same size, one tab, cleared when it
  closes. Cookies: about 4 KB, expiry date, sent with every request, can be
  `HttpOnly`. A login session belongs in an `HttpOnly`, `Secure` cookie.
  :::
::

## Real use case

The way I would use this page: pick five questions at random each morning, say
the answer aloud in under thirty seconds, and only then open it. In walk-ins the
interviewer is often seeing a hundred people that day. An answer that starts with
the point and ends with one example is the one they remember.
