The admission form lost everything when the connection dropped at eleven at
night. The browser has three places to keep small amounts of data for a page,
and choosing between them is a question you will be asked in almost every web
interview.

## Why this matters in a job

Saving a form draft, remembering the dark theme, keeping a user logged in: each
needs data to survive a reload, and each belongs in a different place. The wrong
choice either loses data or leaks it. "Difference between localStorage,
sessionStorage and cookies" is a standard fresher question, usually right after
the HTML round turns to "and what does the browser give you?".

## Three drawers

Think of three places to leave a note at the college. A note in **your own
locker** stays until you clear it (localStorage). A note on **the desk in the
exam hall** is gone when that session ends and the hall is cleared
(sessionStorage). A note **pinned to your ID card** is shown to the clerk every
time you go to the counter, whether they asked or not (a cookie).

| | localStorage | sessionStorage | Cookie |
| --- | --- | --- | --- |
| Lasts | Until cleared by code or the user | Until the tab closes | Until its expiry date, or the browser closes if none |
| Shared across tabs | Yes, same site | No, one tab only | Yes, same site |
| Size | About 5 MB per site | About 5 MB per site | About 4 KB each |
| Sent to the server | Never | Never | **With every request** to that site |
| Read by | JavaScript only | JavaScript only | Server, and JavaScript unless `HttpOnly` |

## How it works

::runner{lang="html"}
```html
<label for="why">Why this college?</label><br>
<textarea id="why" rows="3" cols="40"></textarea>
<p id="status"></p>
<script>
  const box = document.getElementById('why');
  const status = document.getElementById('status');

  // Restore the draft, if there is one
  const saved = localStorage.getItem('application-draft-why');
  if (saved) {
    box.value = saved;
    status.textContent = 'Draft restored (' + saved.length + ' characters).';
  }

  // Save on every change
  box.addEventListener('input', () => {
    localStorage.setItem('application-draft-why', box.value);
    status.textContent = 'Draft saved.';
  });

  // sessionStorage: this tab only
  const visits = Number(sessionStorage.getItem('visits') || 0) + 1;
  sessionStorage.setItem('visits', visits);
  status.textContent += ' Visits in this tab: ' + visits;
</script>
```
::

```text [Output, after typing, then pressing Run again]
Draft restored (54 characters). Visits in this tab: 2
```

The API is the same for both storages: `setItem(key, value)`,
`getItem(key)`, `removeItem(key)`, `clear()`. **Values are always strings.**
To store an object, convert it:

```javascript [draft.js]
const draft = { fullName: 'Anita Rao', programmeId: 1, marks: 78.5 };
localStorage.setItem('draft', JSON.stringify(draft));

const back = JSON.parse(localStorage.getItem('draft'));
console.log(back.marks + 1);
```

```text [Output]
79.5
```

Cookies are set by the server in a response header, and the browser sends them
back on every request:

```text [Set by the server after login]
Set-Cookie: session_id=8f3a91c2; Path=/; HttpOnly; Secure; SameSite=Lax; Max-Age=3600
```

- `HttpOnly`: JavaScript cannot read it, so a malicious script cannot steal it.
- `Secure`: only sent over HTTPS.
- `SameSite=Lax`: not sent on most cross-site requests, which blocks a class of
  attack called CSRF.
- `Max-Age=3600`: expires in an hour.

## Real use case

This is how the three are used on a real college portal:

- **Login session:** a cookie with `HttpOnly; Secure; SameSite`, holding only a
  random session id. The server looks up who that is.
- **The admission form draft:** localStorage, saved as the applicant types, and
  removed with `removeItem` after a successful submit.
- **A multi-step fee payment wizard:** sessionStorage, so opening the portal in a
  second tab does not share half-finished steps, and closing the tab abandons
  them.
- **Theme and language preference:** localStorage.

::warning{icon="i-lucide-alert-triangle"}
Never keep a password, a card number, or a long-lived login token in
localStorage or sessionStorage. Any script running on the page, including one
injected by an attacker through an XSS bug or a compromised third-party library,
can read all of it. An `HttpOnly` cookie is out of JavaScript's reach.
::

## What confuses people here

- **"sessionStorage lasts for the login session."** No: it lasts for the
  **tab**. It survives a reload and is lost when the tab closes, whatever the
  login state.
- **localStorage is not a database.** It is small, synchronous (it blocks while
  reading) and stores only strings. For large data in the browser there is
  IndexedDB.
- **Storage is per origin.** `https://college.example` and
  `https://portal.college.example` have separate localStorage.
- **Private browsing** may give you empty storage or clear it at the end, so code
  should not assume it is there.

## Interview questions

::accordion
  :::accordion-item{label="Difference between localStorage, sessionStorage and cookies?" icon="i-lucide-message-circle"}
  localStorage persists until cleared, is shared across tabs of the same origin,
  holds about 5 MB and is never sent to the server. sessionStorage is the same
  but per tab and cleared when the tab closes. Cookies are about 4 KB, have an
  expiry, are sent with every request to their domain, and can be made
  `HttpOnly` so JavaScript cannot read them.
  :::
  :::accordion-item{label="Where would you store a login token, and why?" icon="i-lucide-message-circle"}
  In an `HttpOnly`, `Secure`, `SameSite` cookie, because script cannot read it,
  so an XSS bug cannot steal it. localStorage is readable by any script on the
  page.
  :::
  :::accordion-item{label="How do you store an object in localStorage?" icon="i-lucide-message-circle"}
  `localStorage.setItem('key', JSON.stringify(obj))`, and read it with
  `JSON.parse(localStorage.getItem('key'))`. Storage holds only strings.
  :::
  :::accordion-item{label="What do HttpOnly, Secure and SameSite mean on a cookie?" icon="i-lucide-message-circle"}
  `HttpOnly`: not readable by JavaScript. `Secure`: only sent over HTTPS.
  `SameSite`: controls whether it is sent on cross-site requests (`Strict`,
  `Lax`, `None`), protecting against CSRF.
  :::
::
