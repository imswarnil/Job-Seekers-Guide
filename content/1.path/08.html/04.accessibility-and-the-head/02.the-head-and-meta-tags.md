Everything so far has lived in the `<body>`. The `<head>` is never displayed,
and it decides the tab title, how the page behaves on a phone, what WhatsApp
shows when somebody shares the link, and when your scripts run.

## Why this matters in a job

The viewport tag alone is the difference between a page that works on a phone
and one that shows a tiny desktop page you have to pinch. The title and
description are what Google shows in its results. A script in the wrong place
makes the page blank for a second on a slow connection. In interviews, "what does
the viewport meta tag do?" and "defer versus async?" are two of the most asked
HTML questions for freshers, and the second is asked again in the JavaScript
round.

## The head is the cover of a file

Think of the cover sheet on a student's file in the college office: name, roll
number, department, what language the documents are in, which other files to
fetch alongside it. Nobody reads the cover sheet for the content, and everybody
relies on it. The `<head>` is that cover sheet for a page.

## How it works

```html [notice.html]
<!doctype html>
<html lang="en">
<head>
  <!-- 1. How to decode the bytes. First, within the first 1024 bytes. -->
  <meta charset="utf-8">

  <!-- 2. Behave like a phone-sized page on a phone -->
  <meta name="viewport" content="width=device-width, initial-scale=1">

  <!-- 3. The tab title, the bookmark name, the search result headline -->
  <title>Semester 3 results published · LNCT Computer Science</title>

  <!-- 4. The snippet under the headline in search results -->
  <meta name="description"
        content="Semester 3 results for B.Tech computer science are on the portal from 10 am Monday.">

  <!-- 5. Link previews in WhatsApp, LinkedIn, Slack (Open Graph) -->
  <meta property="og:title" content="Semester 3 results published">
  <meta property="og:description" content="Results are on the portal from 10 am Monday.">
  <meta property="og:image" content="https://college.example/og/results.png">
  <meta property="og:url" content="https://college.example/notices/sem3-results">

  <!-- 6. Resources the page needs -->
  <link rel="stylesheet" href="/css/site.css">
  <link rel="icon" href="/favicon.svg" type="image/svg+xml">
  <link rel="canonical" href="https://college.example/notices/sem3-results">

  <!-- 7. Scripts that do not block the page -->
  <script src="/js/notices.js" defer></script>
  <script src="https://analytics.example/a.js" async></script>
</head>
<body>
  <h1>Semester 3 results published</h1>
</body>
</html>
```

```text [Where each one shows up]
Browser tab:        [icon] Semester 3 results published · LNCT Computer Science
Google result:      Semester 3 results published · LNCT Computer Science
                    Semester 3 results for B.Tech computer science are on the portal...
WhatsApp preview:   [results.png]  Semester 3 results published
                    Results are on the portal from 10 am Monday.
On a phone:         Text at a readable size, page as wide as the screen.
```

### The viewport

Phones pretend to be about 980 pixels wide unless told otherwise, then shrink
the page to fit, so text becomes unreadable. `width=device-width` says "the page
is as wide as the device", and `initial-scale=1` says "do not zoom". Without this
line, none of the responsive CSS in the next track works on a phone.

::warning{icon="i-lucide-alert-triangle"}
Never add `user-scalable=no` or `maximum-scale=1`. They stop people zooming,
which is how low-vision users read. It is a WCAG failure and some old templates
still ship it.
::

### Scripts: normal, defer and async

The browser parses HTML top to bottom. A plain `<script src>` **stops** parsing
while the script downloads and runs, so everything below it waits.

::compare{caption="Three ways to load a script."}
  :::compare-side{label="script (no attribute)" verdict="wrong"}
  Parsing stops, the script downloads, runs, then parsing resumes. In the head,
  the user sees a blank page until it finishes, and the script cannot find
  elements further down.
  :::
  :::compare-side{label="defer" verdict="right"}
  Downloads in parallel while parsing continues; runs **after** the document is
  parsed, **in order**. The right default for your own scripts.
  :::
::

::compare{caption="And the third."}
  :::compare-side{label="async" verdict="neutral"}
  Downloads in parallel; runs **as soon as it arrives**, pausing parsing
  briefly, in **no guaranteed order**. For independent scripts such as
  analytics.
  :::
  :::compare-side{label="Rule of thumb" verdict="neutral"}
  Depends on the DOM or on another script: `defer`. Depends on nothing and
  nothing depends on it: `async`. The old habit of putting scripts at the end of
  the body works too, but starts the download later.
  :::
::

## Real use case

Every production site has a head like the one above, usually generated by a
framework or template. A frequent support ticket: "when we share the admissions
page on WhatsApp, the preview shows the college logo from 2019 and the wrong
title". The fix is in the Open Graph tags, and the check is a debugger tool such
as LinkedIn's Post Inspector or Facebook's Sharing Debugger, which fetches the
page and shows which `og:` tags it found. Another: a page that shows unstyled
content for half a second. The stylesheet was loaded by JavaScript instead of a
`<link rel="stylesheet">` in the head.

## What confuses people here

- **`<title>` is not the `<h1>`.** The title is for the tab and search results
  and can include the site name; the `h1` is the heading on the page.
- **Meta keywords do nothing.** `<meta name="keywords">` has been ignored by
  Google for over a decade. Interviewers sometimes ask to check you know.
- **`defer` and `async` only apply to external scripts** (with `src`). On an
  inline script they are ignored.
- **The charset must come early.** If it arrives after the browser has already
  guessed the encoding, the browser may re-read the page.

## Interview questions

::accordion
  :::accordion-item{label="What does the viewport meta tag do?" icon="i-lucide-message-circle"}
  `<meta name="viewport" content="width=device-width, initial-scale=1">` tells
  mobile browsers to use the device's width as the page width and not to zoom
  out. Without it, phones render a roughly 980px desktop layout shrunk down, and
  media queries do not behave as expected.
  :::
  :::accordion-item{label="Difference between defer and async?" icon="i-lucide-message-circle"}
  Both download without blocking parsing. `defer` runs after the HTML is fully
  parsed, in document order. `async` runs as soon as it downloads, in any order.
  Use `defer` for scripts that touch the DOM or depend on each other, `async`
  for independent ones like analytics.
  :::
  :::accordion-item{label="Name the meta tags you would put on every page." icon="i-lucide-message-circle"}
  `charset="utf-8"`, the viewport, a `description`, and Open Graph tags
  (`og:title`, `og:description`, `og:image`, `og:url`) if the page is shared. Plus
  a `<title>`, which is an element rather than a meta tag.
  :::
  :::accordion-item{label="What is Open Graph?" icon="i-lucide-message-circle"}
  A set of `meta property="og:..."` tags that social apps read to build a link
  preview: title, description, image and URL.
  :::
  :::accordion-item{label="Why put the stylesheet in the head and scripts with defer?" icon="i-lucide-message-circle"}
  The stylesheet in the head means the first paint is already styled, avoiding a
  flash of unstyled content. `defer` means scripts do not block parsing and run
  once the DOM exists.
  :::
::
