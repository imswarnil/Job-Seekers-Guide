Line one of every HTML document is `<!doctype html>`, and most people who type
it cannot say what it does. This lesson walks through a complete document from
that first line, and then follows the browser as it reads it.

## Why this matters in a job

Every page you will ever debug is a document with this shape, and the browser's
developer tools show you the **parsed** version of it, not the file you wrote.
If you do not know the difference, you will spend an hour looking for a tag that
the browser quietly moved. In interviews, "what is the doctype for?", "difference
between a tag and an element" and "block versus inline" are warm-up questions.
Getting them wrong early sets the tone for the rest of the round.

## A document is a tree

Think of a college's organisation chart. The university at the top, faculties
under it, departments under each faculty, and students under each department.
Every box has exactly one parent. An HTML document is the same shape: the
`<html>` element at the top, `<head>` and `<body>` under it, and everything else
nested inside those.

::flow{direction="vertical" caption="The skeleton every page shares."}
  :::flow-step{label="The doctype" icon="i-lucide-file-code"}
  Not an element. An instruction to the browser: use standards mode.
  :::
  :::flow-step{label="The html element" icon="i-lucide-box"}
  The root. Every other element sits inside it. `lang` sets the language.
  :::
  :::flow-step{label="The head" icon="i-lucide-settings" highlight}
  Information about the page: character set, title, stylesheets, scripts. Not
  displayed.
  :::
  :::flow-step{label="The body" icon="i-lucide-layout"}
  Everything the reader sees.
  :::
::

Three words people use interchangeably and should not:

::feature-list{columns="3"}
  :::feature{icon="i-lucide-tag" title="Tag"}
  The text in angle brackets: `<p>` is an opening tag, `</p>` a closing tag.
  :::
  :::feature{icon="i-lucide-box" title="Element"}
  The opening tag, the closing tag and everything between them. The thing in
  the tree.
  :::
  :::feature{icon="i-lucide-settings-2" title="Attribute"}
  Extra information on the opening tag, as `name="value"`: `href`, `id`,
  `class`, `lang`.
  :::
::

Some elements have no content and no closing tag. They are called **void
elements**: `<br>`, `<img>`, `<input>`, `<meta>`, `<link>`, `<hr>`. Writing
`<br/>` with a slash is allowed but does nothing in HTML.

## How it works

Here is a complete, valid page for a department. Every line is there for a
reason.

```html [department.html]
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Computer Science · LNCT</title>
  </head>
  <body>
    <h1>Department of Computer Science</h1>
    <p>Head of department: <strong>Dr Meera Iyer</strong></p>
    <p>Intake this year: <span id="seats">120</span> seats.</p>
    <ul>
      <li>B.Tech Computer Science</li>
      <li>M.Tech Data Science</li>
    </ul>
  </body>
</html>
```

```text [Rendered]
Department of Computer Science          (large, bold heading on its own line)
Head of department: Dr Meera Iyer       ("Dr Meera Iyer" in bold, same line)
Intake this year: 120 seats.
  • B.Tech Computer Science
  • M.Tech Data Science
Browser tab reads: Computer Science · LNCT
```

What the browser does with that file, in order:

::flow{numbered direction="vertical" caption="From bytes to pixels."}
  :::flow-step{label="Bytes to characters" icon="i-lucide-binary"}
  `charset="utf-8"` says how to decode the bytes. Without it, "₹" or "é" can turn
  into garbage.
  :::
  :::flow-step{label="Characters to tokens" icon="i-lucide-scissors"}
  The parser recognises start tags, end tags, attributes and text.
  :::
  :::flow-step{label="Tokens to the DOM" icon="i-lucide-network" highlight}
  The Document Object Model: the tree of elements in memory. This is what
  JavaScript reads and changes, and what developer tools show you.
  :::
  :::flow-step{label="DOM plus CSS to layout" icon="i-lucide-ruler"}
  Styles are applied and every box gets a size and a position.
  :::
  :::flow-step{label="Paint" icon="i-lucide-paintbrush"}
  Pixels on the screen.
  :::
::

The parser is **forgiving**. It never refuses a page. If you forget `</p>` or
put a `<div>` inside a `<p>`, it fixes the tree its own way, and the DOM stops
matching your file. That is the source of many "my CSS selector does not match"
afternoons.

### Block and inline

Every element has a default display behaviour.

- **Block** elements start on a new line and take the full width available:
  `<div>`, `<p>`, `<h1>`–`<h6>`, `<ul>`, `<li>`, `<table>`, `<form>`,
  `<section>`.
- **Inline** elements sit inside a line of text and are only as wide as their
  content: `<span>`, `<a>`, `<strong>`, `<em>`, `<img>`, `<label>`, `<input>`.

::runner{lang="html"}
```html
<p>Block: this paragraph takes the full width.</p>
<div style="background:#eee">So does this div.</div>
<span style="background:#fde68a">Inline span</span>
<a href="#">inline link</a>
<strong>inline bold</strong>
```
::

```text [Rendered]
Block: this paragraph takes the full width.
So does this div.                         (grey band across the whole width)
Inline span inline link inline bold       (all three on one line)
```

`<div>` and `<span>` are the two **generic** containers: a block with no
meaning, and an inline piece with no meaning. You use them when nothing more
specific fits, mostly as hooks for CSS.

## Real use case

The first thing a front-end developer does with a bug report ("the heading is
in the wrong place") is open developer tools, the Elements panel, and read the
**DOM**, not the source file. Here is a real kind of bug that only makes sense
once you know the parser rewrites the tree:

```html [notice.html]
<p>
  Exam timetable
  <div class="table-wrap">...</div>
</p>
```

```text [The DOM the browser actually builds]
<p> Exam timetable </p>
<div class="table-wrap">...</div>
<p></p>
```

A `<p>` cannot contain a block like `<div>`, so the parser closes the paragraph
early and leaves an empty one after. A CSS rule written as `p .table-wrap` now
matches nothing. The fix is to use the right element (a `<section>` or `<div>`
instead of the `<p>`), not to fight the selector.

## What confuses people here

- **The doctype is not an HTML tag.** It is a switch. Leave it out and the
  browser enters **quirks mode**, imitating browsers from the late 1990s, and
  your layout sizes change in ways that look like CSS bugs.
- **"View source" and the Elements panel show different things.** View source
  is the file as sent. The Elements panel is the DOM after parsing and after any
  JavaScript has run.
- **`<head>` and `<header>` are unrelated.** `<head>` is information about the
  document. `<header>` is a visible banner on the page.
- **HTML is not case-sensitive for tag names**, so `<P>` works, but everybody
  writes lower case and so should you.

## Interview questions

::accordion
  :::accordion-item{label="What does the doctype do?" icon="i-lucide-message-circle"}
  It tells the browser to render in standards mode. Without it the browser uses
  quirks mode, emulating old browsers, which changes how the box model and some
  layout calculations work. It is not an element and has no closing tag.
  :::
  :::accordion-item{label="Difference between a tag, an element and an attribute?" icon="i-lucide-message-circle"}
  A tag is the text in angle brackets (`<a>`, `</a>`). An element is the whole
  thing: opening tag, content and closing tag. An attribute is a name and value
  on the opening tag that configures the element, such as
  `<a href="/faculty">`.
  :::
  :::accordion-item{label="What is the DOM?" icon="i-lucide-message-circle"}
  The Document Object Model: the tree of objects the browser builds in memory
  from the HTML. JavaScript reads and changes the DOM, not the file, and the
  developer tools show the DOM. It can differ from the source because the
  parser fixes errors and scripts change it.
  :::
  :::accordion-item{label="Block versus inline elements?" icon="i-lucide-message-circle"}
  A block element starts on a new line and takes the full available width
  (`div`, `p`, `h1`, `ul`). An inline element flows within text and is only as
  wide as its content (`span`, `a`, `strong`). Width and height do not apply to
  a plain inline element; CSS `display` can change either.
  :::
  :::accordion-item{label="What are void elements? Name some." icon="i-lucide-message-circle"}
  Elements that cannot have content and so have no closing tag: `br`, `hr`,
  `img`, `input`, `meta`, `link`. The trailing slash in `<br />` is optional in
  HTML.
  :::
::
