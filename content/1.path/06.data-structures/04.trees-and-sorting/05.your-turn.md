A number you produced beats a number you read. Every exercise here ends with a
figure to write down, and several of them are worth quoting in an interview.

::note
Run each timing three times and take the middle. A first run in Java includes
class loading and the JIT compiler warming up, and it will be misleadingly slow.
::

## 1. Watch the quadratic

```java [Quadratic.java]
import java.util.*;

public class Quadratic {
  public static void main(String[] args) {
    for (int n : new int[]{1_000, 5_000, 20_000, 40_000}) {
      List<Long> ids = new ArrayList<>();
      for (long i = 0; i < n; i++) ids.add(i % (n / 2));   // half are duplicates

      long start = System.nanoTime();
      Set<Long> nested = new HashSet<>();
      for (int i = 0; i < ids.size(); i++)
        for (int j = i + 1; j < ids.size(); j++)
          if (ids.get(i).equals(ids.get(j))) nested.add(ids.get(i));
      long nestedMs = (System.nanoTime() - start) / 1_000_000;

      start = System.nanoTime();
      Set<Long> seen = new HashSet<>(), fast = new HashSet<>();
      for (Long id : ids) if (!seen.add(id)) fast.add(id);
      long fastMs = (System.nanoTime() - start) / 1_000_000;

      System.out.printf("n=%,7d   nested %,6d ms   set %,4d ms%n", n, nestedMs, fastMs);
    }
  }
}
```

**Write down the four nested times.** Check that doubling n roughly quadruples
it. That relationship, seen once with your own numbers, is what makes O(n²) stop
being notation.

## 2. Measure the cache

```java [Cache.java]
import java.util.*;

public class Cache {
  public static void main(String[] args) {
    int n = 5_000_000;
    List<Integer> arrayList = new ArrayList<>(n);
    List<Integer> linkedList = new LinkedList<>();
    for (int i = 0; i < n; i++) { arrayList.add(i); linkedList.add(i); }

    for (int run = 0; run < 3; run++) {
      System.out.printf("ArrayList  %5d ms%n", time(arrayList));
      System.out.printf("LinkedList %5d ms%n", time(linkedList));
    }
  }

  static long time(List<Integer> list) {
    long start = System.nanoTime(), total = 0;
    for (int v : list) total += v;
    return (System.nanoTime() - start) / 1_000_000 + (total == -1 ? 1 : 0);
  }
}
```

**Write down the ratio.** Both are O(n). Mine was about ten to one on the third
run. That gap is entirely contiguity and cache lines, and it is the best answer
to "when would you use a LinkedList".

## 3. Break a HashMap on purpose

```java [BadHash.java]
import java.util.*;

public class BadHash {
  record Good(String roll) { }                       // records get a real hashCode

  static class Bad {
    final String roll;
    Bad(String roll) { this.roll = roll; }
    @Override public boolean equals(Object o) {
      return o instanceof Bad b && roll.equals(b.roll);
    }
    @Override public int hashCode() { return 1; }    // legal, and catastrophic
  }

  public static void main(String[] args) {
    int n = 50_000;
    Map<Good, Integer> good = new HashMap<>();
    Map<Bad, Integer> bad = new HashMap<>();

    long t = System.nanoTime();
    for (int i = 0; i < n; i++) good.put(new Good("2026CSE" + i), i);
    System.out.printf("good hash  %,6d ms%n", (System.nanoTime() - t) / 1_000_000);

    t = System.nanoTime();
    for (int i = 0; i < n; i++) bad.put(new Bad("2026CSE" + i), i);
    System.out.printf("hashCode()=1  %,6d ms%n", (System.nanoTime() - t) / 1_000_000);
  }
}
```

`hashCode() { return 1; }` is **legal**: it satisfies the contract, because equal
objects do return equal hashes. It also puts all fifty thousand entries in one
bucket.

**Write down both times.** This is the O(1)-becomes-O(n) case, demonstrated, and
it is a very good thing to have actually seen.

## 4. Break the contract instead

```java [Contract.java]
import java.util.*;

public class Contract {
  static class Applicant {
    final String roll;
    Applicant(String roll) { this.roll = roll; }
    @Override public boolean equals(Object o) {
      return o instanceof Applicant a && roll.equals(a.roll);
    }
    // hashCode deliberately not overridden
  }

  public static void main(String[] args) {
    Map<Applicant, Integer> scores = new HashMap<>();
    Applicant a = new Applicant("2026CSE0184");
    scores.put(a, 78);

    System.out.println("same object:  " + scores.get(a));
    System.out.println("equal object: " + scores.get(new Applicant("2026CSE0184")));
    System.out.println("are they equal? " + a.equals(new Applicant("2026CSE0184")));
  }
}
```

**Write down the three lines of output.** Two objects that report themselves
equal, and the map finds one and not the other. Then add `hashCode` and run it
again.

## 5. Prove stability matters

```java [Stability.java]
import java.util.*;
import static java.util.Comparator.comparing;

public class Stability {
  record App(String name, int score, int dayReceived) { }

  public static void main(String[] args) {
    List<App> apps = new ArrayList<>(List.of(
        new App("Anita",  78, 3), new App("Vikram", 78, 1),
        new App("Priya",  81, 2), new App("Rahul",  78, 2)));

    apps.sort(comparing(App::dayReceived));                  // first, by date
    apps.sort(comparing(App::score).reversed());             // then, by score
    apps.forEach(a -> System.out.println(a.name() + " " + a.score()));
  }
}
```

**Write down the order of the three applicants on 78.** Then predict what it
would be if `List.sort` were unstable, and say why that would make a cutoff at
position two indefensible to a parent.

## 6. Talk yourself out of sorting

Forty thousand applications; you need the top ten by score.

Write three versions and time each: sort the whole list and take ten; a bounded
`PriorityQueue` of size ten; and a single pass tracking ten manually.

::accordion
  :::accordion-item{label="What you should find, and the answer that is not in the code" icon="i-lucide-lightbulb"}
  The priority queue wins, and the margin is smaller than people expect at
  40,000 — a few milliseconds. It becomes decisive at ten million, where sorting
  needs the whole list in memory and the queue needs ten elements.

  **The answer that is not in the code:** if those applications are in a
  database, none of the three is right. `ORDER BY score DESC LIMIT 10` with an
  index on `score` reads ten index entries and stops, and never loads 40,000
  rows into your application at all.

  That is the shape of a genuinely good interview answer to this question:
  choose the structure, then notice the question was one layer too low.
  :::
::

## The card to keep

| If the problem says | Reach for |
| --- | --- |
| "by index", "in order", "iterate" | `ArrayList` |
| "last in, first out", "undo", "matching brackets", "depth-first" | `ArrayDeque` as a stack |
| "first in, first out", "queue of work", "breadth-first", "shortest path" | `ArrayDeque` as a queue |
| "top k", "highest priority first", "merge sorted streams" | `PriorityQueue` |
| "have I seen this", "unique", "duplicates" | `HashSet` |
| "look up by id", "count occurrences", "group by" | `HashMap` |
| "between x and y", "in sorted order", "next largest" | `TreeMap` |
| "already sorted", "find the boundary" | Binary search |
| "every pair", "compare all with all" | Stop. This is O(n²) and usually avoidable with a map. |
