Joins put two tables side by side, matching rows across. Sometimes you need the
opposite: two results stacked on top of each other, such as this year's toppers
and last year's in one list. That is what the **set operations** do.

## Why this matters in a job

Data that belongs together often lives in separate tables or separate queries:
current students and alumni, this semester's results and an archive table, two
campuses' registers. Combining them is `UNION`. "Who is in both lists?" is
`INTERSECT`, and "who is in the first but not the second?" is `EXCEPT`. In
interviews, "what is the difference between `UNION` and `UNION ALL`?" is asked
almost as often as `WHERE` against `HAVING`.

## Two lists on one sheet of paper

Picture two printed lists: the students who applied for the Infosys drive and
the students who applied for the TCS drive.

::feature-list{columns="2"}
  :::feature{icon="i-lucide-layers" title="UNION"}
  Everyone who applied to either drive, **each name once**.
  :::
  :::feature{icon="i-lucide-copy" title="UNION ALL"}
  Both lists pasted one under the other, duplicates kept.
  :::
  :::feature{icon="i-lucide-merge" title="INTERSECT"}
  Only the names on **both** lists.
  :::
  :::feature{icon="i-lucide-minus" title="EXCEPT"}
  Names on the first list that are **not** on the second.
  :::
::

::compare{caption="Joins add columns. Set operations add rows."}
  :::compare-side{label="JOIN" verdict="right"}
  Widens the result: each output row has columns from both tables.
  :::
  :::compare-side{label="UNION" verdict="right"}
  Lengthens the result: the rows of the second query go under the rows of the
  first, in the same columns.
  :::
::

## Syntax

```sql [set-syntax.sql]
SELECT col1, col2 FROM table_a
UNION | UNION ALL | INTERSECT | EXCEPT
SELECT col1, col2 FROM table_b
ORDER BY col1;          -- once, at the very end
```

Two rules the queries must follow:

1. The **same number of columns**, in the same order.
2. **Compatible types** in each position (a number under a number, text under
   text). The column names of the result come from the first query.

::runner{lang="sql"}
```sql [drives.sql]
CREATE TABLE InfosysDrive (student_id INTEGER, full_name TEXT);
INSERT INTO InfosysDrive VALUES (1, 'Anita Rao'), (2, 'Rahul Verma'), (3, 'Priya Nair');

CREATE TABLE TcsDrive (student_id INTEGER, full_name TEXT);
INSERT INTO TcsDrive VALUES (3, 'Priya Nair'), (4, 'Arjun Mehta'), (1, 'Anita Rao');

SELECT 'UNION' AS op, COUNT(*) AS n_rows FROM
  (SELECT student_id FROM InfosysDrive UNION SELECT student_id FROM TcsDrive);

SELECT 'UNION ALL' AS op, COUNT(*) AS n_rows FROM
  (SELECT student_id FROM InfosysDrive UNION ALL SELECT student_id FROM TcsDrive);

-- Applied to either: each student once.
SELECT full_name FROM InfosysDrive
UNION
SELECT full_name FROM TcsDrive
ORDER BY full_name;
```
::

```text [Output]
op     n_rows
-----  ------
UNION  4

op         n_rows
---------  ------
UNION ALL  6

full_name
-----------
Anita Rao
Arjun Mehta
Priya Nair
Rahul Verma
```

::runner{lang="sql"}
```sql [intersect-except.sql]
CREATE TABLE InfosysDrive (student_id INTEGER, full_name TEXT);
INSERT INTO InfosysDrive VALUES (1, 'Anita Rao'), (2, 'Rahul Verma'), (3, 'Priya Nair');
CREATE TABLE TcsDrive (student_id INTEGER, full_name TEXT);
INSERT INTO TcsDrive VALUES (3, 'Priya Nair'), (4, 'Arjun Mehta'), (1, 'Anita Rao');

-- Applied to both drives.
SELECT full_name FROM InfosysDrive
INTERSECT
SELECT full_name FROM TcsDrive;

-- Applied to Infosys but not TCS.
SELECT full_name FROM InfosysDrive
EXCEPT
SELECT full_name FROM TcsDrive;
```
::

```text [Output]
full_name
----------
Anita Rao
Priya Nair

full_name
-----------
Rahul Verma
```

| Database | "In A but not B" |
| --- | --- |
| PostgreSQL, SQL Server, SQLite, MySQL 8.0.31+ | `EXCEPT` |
| Oracle | `MINUS` (Oracle 21c also accepts `EXCEPT`) |
| Older MySQL | Neither: use `NOT EXISTS` or a `LEFT JOIN ... IS NULL` |

## UNION against UNION ALL

`UNION` removes duplicate rows, and to do that it has to sort or hash the whole
result. `UNION ALL` keeps every row and does no extra work.

::compare{caption="Which one to reach for."}
  :::compare-side{label="UNION" verdict="right"}
  When the same row may appear in both and you want it once: a list of
  distinct people.
  :::
  :::compare-side{label="UNION ALL" verdict="right"}
  When the parts cannot overlap, or duplicates are meaningful (counting
  payments from two tables). Faster, because it skips the duplicate check.
  :::
::

::warning{icon="i-lucide-alert-triangle"}
`UNION` removes duplicates you may need. Two genuine fee payments of ₹42,500 by
the same student on the same day, stacked from two campus tables with `UNION`,
become one payment, and the total is ₹42,500 short. When you are going to add
things up, use `UNION ALL`.
::

## Real use case

The college moved to a new system in 2024. Older results are in an
`ExamResultArchive` table; newer ones in `ExamResult`. The controller of
examinations wants one list of every result for a student's transcript, labelled
by source, newest first:

::runner{lang="sql"}
```sql [transcript.sql]
CREATE TABLE ExamResultArchive (student_id INTEGER, course_code TEXT, marks INTEGER, exam_date TEXT);
INSERT INTO ExamResultArchive VALUES
  (1, 'MA101', 74, '2023-05-12'), (1, 'CS101', 81, '2023-11-20'), (2, 'CS101', 58, '2023-11-20');

CREATE TABLE ExamResult (student_id INTEGER, course_code TEXT, marks INTEGER, exam_date TEXT);
INSERT INTO ExamResult VALUES
  (1, 'CS201', 87, '2024-11-20'), (1, 'CS202', 72, '2025-05-02'), (2, 'CS201', 64, '2024-11-20');

SELECT course_code, marks, exam_date, 'archive' AS source
FROM   ExamResultArchive WHERE student_id = 1
UNION ALL
SELECT course_code, marks, exam_date, 'current'
FROM   ExamResult        WHERE student_id = 1
ORDER BY exam_date DESC;
```
::

```text [Output]
course_code  marks  exam_date   source
-----------  -----  ----------  -------
CS202        72     2025-05-02  current
CS201        87     2024-11-20  current
CS101        81     2023-11-20  archive
MA101        74     2023-05-12  archive
```

`UNION ALL`, because a result cannot be in both tables and the check would be
wasted work. The literal `'archive'` / `'current'` column tells the reader
where each row came from, which is a small habit that saves a lot of confusion.

This is also how a **full outer join is written in MySQL**, which has none:

```sql [full-join-mysql.sql]
-- MySQL 8
SELECT s.full_name, d.name FROM Student s LEFT  JOIN Department d ON d.department_id = s.department_id
UNION
SELECT s.full_name, d.name FROM Student s RIGHT JOIN Department d ON d.department_id = s.department_id;
```

```text [Output (MySQL 8, on the joins lesson's data)]
+-------------+------------+
| full_name   | name       |
+-------------+------------+
| Anita Rao   | CSE        |
| Rahul Verma | ECE        |
| Priya Nair  | CSE        |
| Arjun Mehta | NULL       |
| NULL        | Mechanical |
| NULL        | Civil      |
+-------------+------------+
```

## What confuses people here

- **`ORDER BY` goes once, at the end**, and sorts the combined result. An
  `ORDER BY` in the middle, on the first query, is an error in most databases.
- **Column names come from the first query.** In the transcript above, the
  second query's `'current'` has no alias and it does not matter.
- **Mismatched columns are not always an error.** `SELECT student_id, marks
  UNION SELECT marks, student_id` runs happily and mixes ids with marks. Line the
  columns up by eye.
- **Set operations compare whole rows.** `INTERSECT` on `(student_id,
  full_name)` treats "3, Priya Nair" and "3, Priya  Nair" (two spaces) as
  different rows.
- **Set operations treat `NULL`s as equal to each other**, unlike `=`. Two rows
  that are both `(NULL, 'Civil')` count as duplicates for `UNION`.

## Interview questions

::accordion
  :::accordion-item{label="What is the difference between UNION and UNION ALL?" icon="i-lucide-message-circle"}
  `UNION` removes duplicate rows from the combined result; `UNION ALL` keeps
  them. `UNION ALL` is faster because it skips the duplicate check. On the drive
  lists above: `UNION` gave 4 students, `UNION ALL` gave 6 rows. Use `UNION ALL`
  when the parts cannot overlap or when duplicates must be counted.
  :::
  :::accordion-item{label="What rules must queries follow to be combined with UNION?" icon="i-lucide-message-circle"}
  The same number of columns, in the same order, with compatible types. The
  result takes its column names from the first query, and a single `ORDER BY`
  goes at the end.
  :::
  :::accordion-item{label="What is the difference between UNION and JOIN?" icon="i-lucide-message-circle"}
  A join combines columns from two tables into wider rows by matching them on
  a condition. `UNION` combines rows from two queries into a longer result with
  the same columns. Join is side by side; union is one under the other.
  :::
  :::accordion-item{label="How do you find rows in one table but not in another?" icon="i-lucide-message-circle"}
  `EXCEPT` (`MINUS` in Oracle), `NOT EXISTS`, or `LEFT JOIN ... WHERE right.key
  IS NULL`. Mention that `NOT IN` is the one to avoid when the other table can
  contain `NULL`s.
  :::
  :::accordion-item{label="What does INTERSECT do?" icon="i-lucide-message-circle"}
  Returns rows present in both results, without duplicates. On the drive lists
  above, Anita Rao and Priya Nair, the two who applied to both. The same answer
  can be written with `EXISTS` or an inner join plus `DISTINCT`.
  :::
::
