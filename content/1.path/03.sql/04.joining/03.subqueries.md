"Students who scored above the average" needs the average before it can compare
anything to it. You could run one query, write the number down, and type it
into a second. A **subquery** does both in one statement: the inner query
answers first, and the outer query uses its answer.

## Why this matters in a job

Real questions come in layers: "courses whose average is above the college
average", "students who have paid less than the full fee", "the department with
the most placements". Each is a question built on another question. In
interviews, subqueries are how the classic "second highest marks" is usually
solved first, and "subquery or join?" is a common follow-up.

## A question that depends on another question

Think of how you would answer "who scored above the class average?" by hand.
First you work out the average: 70. Then you go down the list and pick everyone
above 70. Two steps, and the second uses the answer of the first. A subquery
writes the first step in brackets, exactly where its answer is needed:

```sql [the-idea.sql]
SELECT full_name FROM ExamResult
WHERE  marks > (SELECT AVG(marks) FROM ExamResult);
--              └──────── step 1: answers 70 ───────┘
```

::feature-list{columns="2"}
  :::feature{icon="i-lucide-dot" title="Scalar subquery"}
  Returns one value (one row, one column). Used anywhere a single value can go:
  `marks > (SELECT AVG(marks) ...)`.
  :::
  :::feature{icon="i-lucide-list" title="List subquery"}
  Returns one column, many rows. Used with `IN` / `NOT IN`:
  `student_id IN (SELECT student_id FROM Placement)`.
  :::
  :::feature{icon="i-lucide-table" title="Table subquery (derived table)"}
  Returns rows and columns. Used in `FROM`, as if it were a table, and must
  have an alias.
  :::
  :::feature{icon="i-lucide-repeat" title="Correlated subquery"}
  Refers to the outer query's row, so it runs once per row. The next lesson.
  :::
::

The data for every example:

```sql [subquery-data.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER);

INSERT INTO ExamResult VALUES
  (1, 1, 101, 87), (2, 2, 101, 64), (3, 3, 101, 91),
  (4, 4, 101, 45), (5, 5, 101, 78), (6, 6, 101, 55);
```

### A scalar subquery in WHERE

::runner{lang="sql"}
```sql [above-average.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER);
INSERT INTO Student VALUES
  (1, 'Anita Rao', 1), (2, 'Rahul Verma', 2), (3, 'Priya Nair', 1),
  (4, 'Arjun Mehta', 3), (5, 'Sneha Iyer', 1), (6, 'Karan Patel', 2);
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, student_id INTEGER, course_id INTEGER, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 1, 101, 87), (2, 2, 101, 64), (3, 3, 101, 91),
  (4, 4, 101, 45), (5, 5, 101, 78), (6, 6, 101, 55);

SELECT student_id, marks
FROM   ExamResult
WHERE  marks > (SELECT AVG(marks) FROM ExamResult)
ORDER BY marks DESC;

-- The student with the highest marks.
SELECT student_id, marks
FROM   ExamResult
WHERE  marks = (SELECT MAX(marks) FROM ExamResult);
```
::

```text [Output]
student_id  marks
----------  -----
3           91
1           87
5           78

student_id  marks
----------  -----
3           91
```

### A list subquery with IN

::runner{lang="sql"}
```sql [in-subquery.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER);
INSERT INTO Student VALUES
  (1, 'Anita Rao', 1), (2, 'Rahul Verma', 2), (3, 'Priya Nair', 1),
  (4, 'Arjun Mehta', 3), (5, 'Sneha Iyer', 1), (6, 'Karan Patel', 2);
CREATE TABLE Placement (placement_id INTEGER PRIMARY KEY, student_id INTEGER, company TEXT, package_lpa REAL);
INSERT INTO Placement VALUES (1, 1, 'Infosys', 3.6), (2, 3, 'Accenture', 4.5), (3, 5, 'TCS', 3.4);

-- Placed students.
SELECT full_name FROM Student
WHERE  student_id IN (SELECT student_id FROM Placement);

-- Students placed with a package above 4 LPA.
SELECT full_name FROM Student
WHERE  student_id IN (SELECT student_id FROM Placement WHERE package_lpa > 4);
```
::

```text [Output]
full_name
----------
Anita Rao
Priya Nair
Sneha Iyer

full_name
----------
Priya Nair
```

### A derived table in FROM

A subquery in `FROM` produces a temporary table that the outer query reads.
It must have an alias.

::runner{lang="sql"}
```sql [derived-table.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER);
INSERT INTO Student VALUES
  (1, 'Anita Rao', 1), (2, 'Rahul Verma', 2), (3, 'Priya Nair', 1),
  (4, 'Arjun Mehta', 3), (5, 'Sneha Iyer', 1), (6, 'Karan Patel', 2);
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, student_id INTEGER, course_id INTEGER, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 1, 101, 87), (2, 2, 101, 64), (3, 3, 101, 91),
  (4, 4, 101, 45), (5, 5, 101, 78), (6, 6, 101, 55);

-- Average marks per department, then only departments above 60.
SELECT dept.department_id, dept.average
FROM  (SELECT s.department_id, ROUND(AVG(r.marks), 1) AS average
       FROM   ExamResult r JOIN Student s ON s.student_id = r.student_id
       GROUP BY s.department_id) AS dept
WHERE  dept.average > 60;
```
::

```text [Output]
department_id  average
-------------  -------
1              85.3
```

You could write that one with `HAVING` instead. Derived tables earn their place
when you need to aggregate twice, such as "the average of the department
averages", which `HAVING` cannot express.

### A subquery in SELECT

::runner{lang="sql"}
```sql [subquery-in-select.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, student_id INTEGER, course_id INTEGER, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 1, 101, 87), (2, 2, 101, 64), (3, 3, 101, 91),
  (4, 4, 101, 45), (5, 5, 101, 78), (6, 6, 101, 55);

SELECT student_id,
       marks,
       marks - (SELECT ROUND(AVG(marks), 1) FROM ExamResult) AS above_average_by
FROM   ExamResult
ORDER BY above_average_by DESC;
```
::

```text [Output]
student_id  marks  above_average_by
----------  -----  ----------------
3           91     21.0
1           87     17.0
5           78     8.0
2           64     -6.0
6           55     -15.0
4           45     -25.0
```

## WITH: the readable way to write a subquery

A **common table expression** (CTE) gives a subquery a name, written before the
main query. It does the same thing as a derived table and reads top to bottom,
like steps in a recipe:

::runner{lang="sql"}
```sql [cte.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER);
INSERT INTO Student VALUES
  (1, 'Anita Rao', 1), (2, 'Rahul Verma', 2), (3, 'Priya Nair', 1),
  (4, 'Arjun Mehta', 3), (5, 'Sneha Iyer', 1), (6, 'Karan Patel', 2);
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, student_id INTEGER, course_id INTEGER, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 1, 101, 87), (2, 2, 101, 64), (3, 3, 101, 91),
  (4, 4, 101, 45), (5, 5, 101, 78), (6, 6, 101, 55);

WITH dept_average AS (
  SELECT s.department_id, AVG(r.marks) AS average
  FROM   ExamResult r JOIN Student s ON s.student_id = r.student_id
  GROUP BY s.department_id
)
SELECT ROUND(AVG(average), 2) AS average_of_department_averages,
       (SELECT ROUND(AVG(marks), 2) FROM ExamResult) AS average_of_students
FROM   dept_average;
```
::

```text [Output]
average_of_department_averages  average_of_students
------------------------------  -------------------
63.28                           70.0
```

Two different "averages", and a report that does not say which one it shows
is wrong for someone. `WITH` is supported by MySQL 8, PostgreSQL, Oracle, SQL
Server and SQLite. On MySQL 5.7 and older it does not exist, which you may meet
on older systems.

## Real use case

The placement cell asks: "Which students scored above their batch average but
have not been placed yet?" It is two questions (the average, and who is placed)
feeding a third, and `WITH` lets each step have a name:

::runner{lang="sql"}
```sql [above-average-unplaced.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER);
INSERT INTO Student VALUES
  (1, 'Anita Rao', 1), (2, 'Rahul Verma', 2), (3, 'Priya Nair', 1),
  (4, 'Arjun Mehta', 3), (5, 'Sneha Iyer', 1), (6, 'Karan Patel', 2);
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, student_id INTEGER, course_id INTEGER, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 1, 101, 87), (2, 2, 101, 64), (3, 3, 101, 91),
  (4, 4, 101, 45), (5, 5, 101, 78), (6, 6, 101, 55);
CREATE TABLE Placement (placement_id INTEGER PRIMARY KEY, student_id INTEGER, company TEXT, package_lpa REAL);
INSERT INTO Placement VALUES (1, 1, 'Infosys', 3.6), (2, 3, 'Accenture', 4.5);

WITH batch AS (
  SELECT AVG(marks) AS average FROM ExamResult
),
placed AS (
  SELECT student_id FROM Placement
)
SELECT s.full_name, r.marks
FROM   ExamResult r
JOIN   Student s ON s.student_id = r.student_id
WHERE  r.marks > (SELECT average FROM batch)
  AND  r.student_id NOT IN (SELECT student_id FROM placed WHERE student_id IS NOT NULL)
ORDER BY r.marks DESC;
```
::

```text [Output]
full_name   marks
----------  -----
Sneha Iyer  78
```

Sneha is the one the placement cell should call first. The `IS NOT NULL` inside
the `NOT IN` is the NULL lesson's trap, handled on purpose.

## Subquery or join?

::compare{caption="The same question, two ways. Both are correct."}
  :::compare-side{label="Subquery" verdict="right"}
  `SELECT full_name FROM Student WHERE student_id IN (SELECT student_id FROM Placement);`

  Reads like the question. Returns each student once, even if they had two
  offers.
  :::
  :::compare-side{label="Join" verdict="right"}
  `SELECT DISTINCT s.full_name FROM Student s JOIN Placement p ON p.student_id = s.student_id;`

  Needs `DISTINCT`, or a student with two offers appears twice. Lets you show
  columns from `Placement` too.
  :::
::

Modern databases usually turn both into the same plan, so choose the one that
reads more clearly. Use a join when you need columns from both tables; use a
subquery with `IN` or `EXISTS` when you only need to test membership.

## What confuses people here

- **"Subquery returns more than one row."** A scalar subquery must return one
  value. `WHERE marks = (SELECT marks FROM ExamResult WHERE course_id = 101)`
  fails in MySQL and PostgreSQL if the course has several results. Use `IN`, or
  an aggregate such as `MAX`. (SQLite quietly takes the first row, which hides
  the bug.)
- **A derived table needs an alias.** `FROM (SELECT ...)` without `AS name` is
  an error in MySQL and PostgreSQL.
- **A scalar subquery that finds nothing returns `NULL`**, and `marks > NULL`
  is never true, so the whole query returns nothing.
- **The inner query cannot see the outer query's aliases**, unless it is a
  correlated subquery, which is the next lesson.

## Interview questions

::accordion
  :::accordion-item{label="What is a subquery? What types are there?" icon="i-lucide-message-circle"}
  A query nested inside another. By what it returns: scalar (one value), row,
  list (one column, used with `IN`) and table (used in `FROM`). By how it runs:
  non-correlated (runs once) and correlated (refers to the outer row, runs once
  per row).
  :::
  :::accordion-item{label="Find students who scored above the average." icon="i-lucide-message-circle"}
  `SELECT student_id, marks FROM ExamResult WHERE marks > (SELECT AVG(marks) FROM ExamResult);`
  On the six results above (average 70), students 3, 1 and 5.
  :::
  :::accordion-item{label="What is the difference between a subquery and a join?" icon="i-lucide-message-circle"}
  A join combines rows from tables so you can show columns from both; a subquery
  computes a value or list the outer query uses. Many queries can be written
  either way and optimisers often plan them the same. Joins can duplicate rows
  (a student with two offers); `IN` and `EXISTS` subqueries do not.
  :::
  :::accordion-item{label="What is a CTE, and why use one?" icon="i-lucide-message-circle"}
  A common table expression: a named subquery written with `WITH name AS (...)`
  before the main query. It makes multi-step logic readable, can be referred to
  more than once, and can be recursive (`WITH RECURSIVE`) for hierarchies such as
  a reporting chain.
  :::
  :::accordion-item{label="Find the department with the most students." icon="i-lucide-message-circle"}
  ```sql [top-department.sql]
  SELECT department_id, COUNT(*) AS students
  FROM   Student
  GROUP BY department_id
  HAVING COUNT(*) = (SELECT MAX(c) FROM (SELECT COUNT(*) AS c
                                         FROM Student GROUP BY department_id) AS counts);
  ```

  ```text [Output (on the six students above)]
  department_id  students
  -------------  --------
  1              3
  ```
  Unlike `ORDER BY students DESC LIMIT 1`, this returns every department that
  ties for first, which is usually what was asked.
  :::
::
