Between the queries, the SQL round asks theory questions, and the first is
almost always a vocabulary test: "What is DDL? What is DML? Give examples." It
is easy marks if you can sort every command you have learned so far into the
right family, and say one thing about each family that shows you understand it.

## Why this matters in a job

The families are not only an exam classification. They decide real behaviour:
DDL changes the structure and, in MySQL and Oracle, commits immediately and
cannot be rolled back; DCL decides who can do what, which is how a college keeps
fee data away from the placement agency; TCL is how several writes become one.
Knowing which family a command is in tells you how careful to be with it.

## Five families, sorted by what they touch

Think of the college library. Building shelves, adding a new section or knocking
one down is **DDL**: it changes the structure. Putting books on shelves, moving
them and removing them is **DML**: it changes the contents. Looking up a book is
**DQL**. Handing out library cards and deciding who may enter the reference room
is **DCL**. And "these five books are issued together or not at all" is **TCL**.

::feature-list{columns="2"}
  :::feature{icon="i-lucide-hammer" title="DDL: Data Definition Language"}
  The structure. `CREATE`, `ALTER`, `DROP`, `TRUNCATE`, `RENAME`, `COMMENT`.
  :::
  :::feature{icon="i-lucide-pencil" title="DML: Data Manipulation Language"}
  The rows. `INSERT`, `UPDATE`, `DELETE`, `MERGE`.
  :::
  :::feature{icon="i-lucide-search" title="DQL: Data Query Language"}
  Reading. `SELECT`. Many books put it inside DML; either answer is accepted if
  you say which convention you use.
  :::
  :::feature{icon="i-lucide-key-round" title="DCL: Data Control Language"}
  Permissions. `GRANT`, `REVOKE`.
  :::
  :::feature{icon="i-lucide-arrow-left-right" title="TCL: Transaction Control Language"}
  Transactions. `COMMIT`, `ROLLBACK`, `SAVEPOINT`, `SET TRANSACTION`.
  :::
::

| Family | Commands | Changes | Can be rolled back? |
| --- | --- | --- | --- |
| DDL | `CREATE`, `ALTER`, `DROP`, `TRUNCATE`, `RENAME` | Structure (tables, views, indexes) | MySQL, Oracle: **no**, auto-commits. PostgreSQL, SQL Server, SQLite: mostly yes |
| DML | `INSERT`, `UPDATE`, `DELETE`, `MERGE` | Rows | Yes, inside a transaction |
| DQL | `SELECT` | Nothing | Nothing to roll back |
| DCL | `GRANT`, `REVOKE` | Permissions | Usually auto-commits |
| TCL | `COMMIT`, `ROLLBACK`, `SAVEPOINT` | Controls the transaction itself | They are the rollback |

## How it works

One runner, one command from each family that SQLite supports, labelled:

::runner{lang="sql"}
```sql [every-family.sql]
-- DDL: create the structure.
CREATE TABLE Course (course_id INTEGER PRIMARY KEY, code TEXT NOT NULL, credits INTEGER);
ALTER TABLE Course ADD COLUMN title TEXT;

-- TCL: start a unit of work.
BEGIN;

-- DML: change the rows.
INSERT INTO Course (course_id, code, credits, title) VALUES
  (101, 'CS201', 4, 'Data Structures'), (102, 'CS202', 3, 'DBMS'), (103, 'MA201', 4, 'Discrete Maths');
UPDATE Course SET credits = 4 WHERE code = 'CS202';
DELETE FROM Course WHERE code = 'MA201';

-- TCL: keep it.
COMMIT;

-- DQL: read it.
SELECT course_id, code, title, credits FROM Course;
```
::

```text [Output]
course_id  code   title            credits
---------  -----  ---------------  -------
101        CS201  Data Structures  4
102        CS202  DBMS             4
```

### DCL: GRANT and REVOKE

SQLite is a single file with no users, so it has no `GRANT`. In MySQL,
PostgreSQL, Oracle and SQL Server, this is how access is given and taken away:

```sql [grants.sql]
-- MySQL 8
CREATE USER 'placement_agency'@'%' IDENTIFIED BY '••••••••';

GRANT SELECT ON college.placement_eligible TO 'placement_agency'@'%';   -- read one view
GRANT SELECT, INSERT, UPDATE ON college.ExamResult TO 'exam_cell'@'%'; -- write results

REVOKE INSERT, UPDATE ON college.ExamResult FROM 'exam_cell'@'%';      -- after results are frozen

SHOW GRANTS FOR 'exam_cell'@'%';
```

```text [Output (MySQL 8, illustrative)]
+-----------------------------------------------------------------+
| Grants for exam_cell@%                                          |
+-----------------------------------------------------------------+
| GRANT USAGE ON *.* TO `exam_cell`@`%`                           |
| GRANT SELECT ON `college`.`ExamResult` TO `exam_cell`@`%`       |
+-----------------------------------------------------------------+
```

`WITH GRANT OPTION` lets the receiver pass the permission on to others, which is
usually a bad idea and a good thing to mention.

## Real use case

The most practical consequence of the families is the one that has caught out
people in every company: in MySQL, **DDL commits whatever transaction is open**.

```sql [ddl-commits.sql]
-- MySQL 8
START TRANSACTION;
DELETE FROM ExamResult WHERE course_id = 102;   -- DML, inside the transaction
CREATE INDEX idx_marks ON ExamResult (marks);   -- DDL: implicitly COMMITs the DELETE
ROLLBACK;                                       -- too late
SELECT COUNT(*) FROM ExamResult WHERE course_id = 102;
```

```text [Output (MySQL 8, illustrative)]
+----------+
| COUNT(*) |
+----------+
|        0 |
+----------+
```

The `ROLLBACK` did nothing, because the `CREATE INDEX` had already committed the
`DELETE`. PostgreSQL and SQLite handle DDL inside transactions, so the same
script there restores the rows:

::runner{lang="sql"}
```sql [ddl-in-transaction-sqlite.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, course_id INTEGER, marks INTEGER);
INSERT INTO ExamResult VALUES (1, 101, 87), (2, 102, 72), (3, 102, 64);

BEGIN;
DELETE FROM ExamResult WHERE course_id = 102;
CREATE INDEX idx_marks ON ExamResult (marks);
ROLLBACK;

SELECT COUNT(*) AS course_102_results FROM ExamResult WHERE course_id = 102;
```
::

```text [Output]
course_102_results
------------------
2
```

The rule to carry into any job: never mix structure changes and data changes in
one manual session on a live database, whichever database it is.

## What confuses people here

- **`TRUNCATE` is DDL, not DML**, even though it removes rows. It works by
  resetting the table's storage rather than deleting rows one by one, which is
  why it is fast and why, in MySQL and Oracle, it cannot be rolled back. The next
  lesson is all about this.
- **`SELECT` is DQL or DML** depending on the book. Say "`SELECT` is sometimes
  classed as DQL" and you are right either way.
- **`MERGE`** (Oracle, SQL Server) is DML: insert or update in one statement, the
  upsert from the INSERT, UPDATE and DELETE lesson.
- **`COMMIT` is not DCL.** "Control" in DCL means access control. Transaction
  control is TCL.

## Interview questions

::accordion
  :::accordion-item{label="What are DDL, DML, DCL and TCL? Give examples." icon="i-lucide-message-circle"}
  DDL defines structure: `CREATE`, `ALTER`, `DROP`, `TRUNCATE`. DML changes rows:
  `INSERT`, `UPDATE`, `DELETE`. DCL controls access: `GRANT`, `REVOKE`. TCL
  controls transactions: `COMMIT`, `ROLLBACK`, `SAVEPOINT`. `SELECT` is DQL, or
  part of DML in some books.
  :::
  :::accordion-item{label="Is TRUNCATE DDL or DML? Why?" icon="i-lucide-message-circle"}
  DDL. It deallocates the table's data pages instead of deleting rows one at a
  time, so it does not fire row triggers, cannot take a `WHERE`, resets identity
  counters, and in MySQL and Oracle commits implicitly.
  :::
  :::accordion-item{label="Can DDL statements be rolled back?" icon="i-lucide-message-circle"}
  Depends on the database. MySQL and Oracle commit implicitly before and after
  DDL, so no. PostgreSQL, SQL Server and SQLite support transactional DDL for
  most statements, so yes. On SQLite above, the `ROLLBACK` restored both deleted
  rows.
  :::
  :::accordion-item{label="What is the difference between GRANT and REVOKE?" icon="i-lucide-message-circle"}
  `GRANT` gives a user or role a privilege on an object
  (`GRANT SELECT ON ExamResult TO exam_cell`); `REVOKE` takes it away. Grant the
  least privilege needed, and prefer granting on a view to granting on a table.
  :::
  :::accordion-item{label="Which SQL commands auto-commit?" icon="i-lucide-message-circle"}
  In autocommit mode, every statement. Inside an explicit transaction, DDL
  (`CREATE`, `ALTER`, `DROP`, `TRUNCATE`) and DCL still commit implicitly in
  MySQL and Oracle. DML waits for `COMMIT`.
  :::
::
