You now have every tool the SQL round uses. The round itself asks the same
handful of questions in almost every company, and the first is nearly always
"find the second highest salary". In this guide the table is marks, not
salaries. The logic is identical.

## Why this matters in a job

It is asked because it tests four things in one line: subqueries, sorting and
limiting, `DISTINCT`, and whether you think about ties. I was asked a version of
it in more walk-ins than any other SQL question, usually on paper, usually with
"now the Nth" as the follow-up. At work it appears as "the runner-up", "the
second-latest payment", and "the third most popular course".

## What "second highest" really means

Marks in a course: 91, 87, 87, 78, 64. What is the second highest?

::compare{caption="Two readings of the same question. Ask which one is meant."}
  :::compare-side{label="The second row" verdict="wrong"}
  Sort descending and take row 2: **87**. But row 3 is also 87, so "second" and
  "third" are the same mark, and the answer to "third highest" would be 87 as
  well.
  :::
  :::compare-side{label="The second distinct value" verdict="right"}
  Distinct marks are 91, 87, 78, 64. The second highest is **87**, the third is
  **78**. This is what "second highest salary" means in almost every interview.
  :::
::

Say this out loud before writing anything: "I'll treat it as the second highest
**distinct** mark, so ties don't shift the answer." That one sentence is what
most candidates leave out.

## How it works: four solutions

Every solution below runs against the same data:

```sql [marks.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, student_id INTEGER, full_name TEXT, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 1, 'Priya Nair',  91), (2, 2, 'Anita Rao',   87), (3, 3, 'Arjun Mehta', 87),
  (4, 4, 'Sneha Iyer',  78), (5, 5, 'Rahul Verma', 64), (6, 6, 'Karan Patel', NULL);
```

### 1. MAX below the MAX

The highest mark that is less than the highest mark:

::runner{lang="sql"}
```sql [second-with-max.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, student_id INTEGER, full_name TEXT, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 1, 'Priya Nair',  91), (2, 2, 'Anita Rao',   87), (3, 3, 'Arjun Mehta', 87),
  (4, 4, 'Sneha Iyer',  78), (5, 5, 'Rahul Verma', 64), (6, 6, 'Karan Patel', NULL);

SELECT MAX(marks) AS second_highest
FROM   ExamResult
WHERE  marks < (SELECT MAX(marks) FROM ExamResult);
```
::

```text [Output]
second_highest
--------------
87
```

Works on every database ever made, handles ties naturally, and ignores `NULL`.
It does not generalise: the third highest needs a subquery inside a subquery,
and the Nth needs N levels.

### 2. DISTINCT, ORDER BY, LIMIT and OFFSET

Skip N − 1 distinct values and take one:

::runner{lang="sql"}
```sql [nth-with-offset.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, student_id INTEGER, full_name TEXT, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 1, 'Priya Nair',  91), (2, 2, 'Anita Rao',   87), (3, 3, 'Arjun Mehta', 87),
  (4, 4, 'Sneha Iyer',  78), (5, 5, 'Rahul Verma', 64), (6, 6, 'Karan Patel', NULL);

-- 2nd highest: skip 1.
SELECT DISTINCT marks AS second_highest
FROM   ExamResult
WHERE  marks IS NOT NULL
ORDER BY marks DESC
LIMIT 1 OFFSET 1;

-- 3rd highest: skip 2.
SELECT DISTINCT marks AS third_highest
FROM   ExamResult
WHERE  marks IS NOT NULL
ORDER BY marks DESC
LIMIT 1 OFFSET 2;
```
::

```text [Output]
second_highest
--------------
87

third_highest
-------------
78
```

Without `DISTINCT`, `OFFSET 2` would land on Arjun's 87 and call it the third
highest. With it, the answer is 78. In SQL Server the same idea is `ORDER BY
marks DESC OFFSET 2 ROWS FETCH NEXT 1 ROWS ONLY`.

### 3. DENSE_RANK

The cleanest general answer, and the one that returns the **students** as well as
the mark:

::runner{lang="sql"}
```sql [nth-with-dense-rank.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, student_id INTEGER, full_name TEXT, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 1, 'Priya Nair',  91), (2, 2, 'Anita Rao',   87), (3, 3, 'Arjun Mehta', 87),
  (4, 4, 'Sneha Iyer',  78), (5, 5, 'Rahul Verma', 64), (6, 6, 'Karan Patel', NULL);

WITH ranked AS (
  SELECT full_name, marks,
         DENSE_RANK() OVER (ORDER BY marks DESC) AS rnk
  FROM   ExamResult
  WHERE  marks IS NOT NULL
)
SELECT full_name, marks
FROM   ranked
WHERE  rnk = 2;
```
::

```text [Output]
full_name    marks
-----------  -----
Anita Rao    87
Arjun Mehta  87
```

Change `rnk = 2` to `rnk = N` and it answers the Nth. It returns both students on
87, which is usually right: "who came second?" has two answers. `DENSE_RANK`,
not `RANK`: with `RANK` the marks go 1, 2, 2, 4, so there is no rank 3 at all
and "third highest" returns nothing.

### 4. A correlated COUNT

The classic textbook answer, from before window functions existed: a mark is the
Nth highest if exactly N − 1 distinct marks are above it.

::runner{lang="sql"}
```sql [nth-with-correlated-count.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, student_id INTEGER, full_name TEXT, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 1, 'Priya Nair',  91), (2, 2, 'Anita Rao',   87), (3, 3, 'Arjun Mehta', 87),
  (4, 4, 'Sneha Iyer',  78), (5, 5, 'Rahul Verma', 64), (6, 6, 'Karan Patel', NULL);

-- N = 3: exactly 2 distinct marks are higher.
SELECT DISTINCT e.marks AS third_highest
FROM   ExamResult e
WHERE  2 = (SELECT COUNT(DISTINCT x.marks)
            FROM   ExamResult x
            WHERE  x.marks > e.marks);
```
::

```text [Output]
third_highest
-------------
78
```

It works everywhere, including MySQL 5.7, and it is slow on large tables
because the inner count runs for every row. Knowing it exists, and why it is
slow, is worth more than writing it.

## Real use case

The college awards a runner-up prize in every course. The rule: the second
highest distinct mark in that course, and every student who got it. That is the
DENSE_RANK solution with `PARTITION BY`, because it needs the Nth highest
**per group**:

::runner{lang="sql"}
```sql [runner-up-per-course.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, full_name TEXT, course_code TEXT, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 'Priya Nair', 'CS201', 91), (2, 'Anita Rao', 'CS201', 87), (3, 'Arjun Mehta', 'CS201', 87),
  (4, 'Sneha Iyer', 'CS201', 78), (5, 'Anita Rao', 'CS202', 72), (6, 'Priya Nair', 'CS202', 88),
  (7, 'Rahul Verma', 'CS202', 72), (8, 'Karan Patel', 'CS202', 69);

WITH ranked AS (
  SELECT course_code, full_name, marks,
         DENSE_RANK() OVER (PARTITION BY course_code ORDER BY marks DESC) AS rnk
  FROM   ExamResult
  WHERE  marks IS NOT NULL
)
SELECT course_code, full_name, marks
FROM   ranked
WHERE  rnk = 2
ORDER BY course_code, full_name;
```
::

```text [Output]
course_code  full_name    marks
-----------  -----------  -----
CS201        Anita Rao    87
CS201        Arjun Mehta  87
CS202        Anita Rao    72
CS202        Rahul Verma  72
```

Two prizes in each course, because two students tied in each. The prize rule
said "every student who got it", and the query says the same thing.

## What confuses people here

- **When there is no second highest.** If every student scored 87, solution 1
  returns one row with `NULL`, solution 2 returns no rows, and solution 3 returns
  no rows. Some interviewers ask for `NULL` specifically ("return null if there
  is no second highest"); wrap it as `SELECT (SELECT DISTINCT marks ... LIMIT 1
  OFFSET 1) AS second_highest;` to always get one row.
- **`ORDER BY marks DESC LIMIT 1 OFFSET 1` without `DISTINCT`** is the most
  common wrong answer. It returns the second row, not the second value.
- **`TOP` and `ROWNUM`.** SQL Server writes `SELECT TOP 1 ... ORDER BY`; old
  Oracle applies `ROWNUM` before `ORDER BY`, so `WHERE ROWNUM = 2` returns
  nothing at all (the first row is rejected, so there is never a row 2). If an
  interviewer names a database, use its syntax, or say you would use
  `DENSE_RANK`, which works on all of them.
- **`NULL` marks.** `MAX` ignores them, `ORDER BY ... DESC` puts them first in
  some databases and last in others. Filter `WHERE marks IS NOT NULL` and you
  never have to remember which.

## Interview questions

::accordion
  :::accordion-item{label="Find the second highest marks." icon="i-lucide-message-circle"}
  `SELECT MAX(marks) FROM ExamResult WHERE marks < (SELECT MAX(marks) FROM ExamResult);`
  Then offer the general version with `DENSE_RANK` before they ask for it, and
  say you are treating it as the second highest distinct value.
  :::
  :::accordion-item{label="Find the Nth highest marks." icon="i-lucide-message-circle"}
  `DENSE_RANK() OVER (ORDER BY marks DESC)` in a CTE, then `WHERE rnk = N`. Or
  `SELECT DISTINCT marks ... ORDER BY marks DESC LIMIT 1 OFFSET N-1`. Both are
  shown above with their output (N = 3 gives 78).
  :::
  :::accordion-item{label="What is wrong with ORDER BY marks DESC LIMIT 1 OFFSET 1?" icon="i-lucide-message-circle"}
  It returns the second **row**, not the second **distinct value**. With 91, 87,
  87, it correctly returns 87 for second, but `OFFSET 2` also returns 87 for
  third. Add `DISTINCT`.
  :::
  :::accordion-item{label="Why DENSE_RANK and not RANK for the Nth highest?" icon="i-lucide-message-circle"}
  `RANK` leaves gaps after ties (1, 2, 2, 4), so `rank = 3` finds nothing.
  `DENSE_RANK` has no gaps (1, 2, 2, 3), so rank N is always the Nth distinct
  value.
  :::
  :::accordion-item{label="Find the second highest marks in each course." icon="i-lucide-message-circle"}
  Add `PARTITION BY course_code` to the `DENSE_RANK`, and keep `rnk = 2`. The
  runner-up query and its output are in "Real use case" above.
  :::
::
