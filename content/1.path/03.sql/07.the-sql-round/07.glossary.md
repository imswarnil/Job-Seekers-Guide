## The clause order, which explains most errors

```text [Clause order]
Written:    SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT
Evaluated:  FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
```

That one difference explains why an alias fails in `WHERE` and works in
`ORDER BY`, why a condition on `COUNT(*)` belongs in `HAVING`, and why a window
function cannot appear in `WHERE`.

## First tables

| Term | In one line |
| --- | --- |
| **Data** | Raw facts: "87", "Anita Rao". |
| **Database** | An organised collection of related data. |
| **DBMS** | The software that stores a database and controls every read and write (MySQL, Oracle). |
| **RDBMS** | A DBMS that stores data as related tables. |
| **SQL** | The declarative language for defining, changing and asking about relational data. |
| **Table, row, column** | Relation, tuple, attribute in the theory. A row is one thing; a column is one kind of fact. |
| **Primary key** | A column (or set) that is unique and never `NULL`, so every row can be named. |
| **Data type** | What a column holds and refuses: `INTEGER`, `DECIMAL(p, s)`, `VARCHAR(n)`, `DATE`. |
| **`CHAR` vs `VARCHAR`** | Fixed length, padded with spaces, against variable length up to n. |
| **`DECIMAL`** | Exact decimal. The type for money. `FLOAT` is approximate and never for money. |
| **`CREATE TABLE`** | Makes an empty table with named, typed columns. |
| **`ALTER TABLE`** | Changes a table: add, rename or drop a column. |
| **`INSERT`** | Adds rows. Always name the columns. |
| **`UPDATE`** | Changes rows. Without `WHERE`, every row. |
| **`DELETE`** | Removes rows. Without `WHERE`, every row. |
| **Soft delete** | Marking a row as removed (`status = 'LEFT'`) instead of deleting it. |
| **Upsert** | Insert, or update if the key exists: `ON CONFLICT`, `ON DUPLICATE KEY UPDATE`, `MERGE`. |

## Asking

| Term | In one line |
| --- | --- |
| **`SELECT`** | Which columns. Name them; `SELECT *` changes silently when a column is added. |
| **Alias (`AS`)** | A temporary name for a column or table in one query. |
| **`WHERE`** | Which rows, before any grouping. Cannot see an aggregate. |
| **`AND`, `OR`, `NOT`** | `NOT` binds first, then `AND`, then `OR`. Write brackets when they meet. |
| **`ORDER BY`** | Sorts. End on something unique or the order is not reproducible. |
| **`ASC` / `DESC`** | Ascending (default) or descending. |
| **`LIMIT` / `OFFSET`** | Keep n rows, after skipping m. `TOP` in SQL Server, `FETCH FIRST` in the standard. |
| **`DISTINCT`** | Removes duplicate result rows, across all selected columns. Often hides a join bug. |
| **`LIKE`** | Pattern match: `%` any run, `_` exactly one character. A leading `%` cannot use an index. |
| **`IN` / `NOT IN`** | Any of a list. `NOT IN` with a `NULL` in the list returns nothing. |
| **`BETWEEN`** | Inclusive at both ends. For dates with times, use `>= start AND < next_start`. |
| **`NULL`** | Unknown or missing. Not zero, not an empty string. |
| **Three-valued logic** | `TRUE`, `FALSE`, `UNKNOWN`. Only `TRUE` rows come back. |
| **`IS NULL`** | The only way to test for `NULL`. `= NULL` never matches. |
| **`COALESCE(a, b)`** | The first non-`NULL` argument. A default is a decision, not formatting. |
| **`NULLIF(a, b)`** | `NULL` if equal. `x / NULLIF(y, 0)` avoids division by zero. |

## Summarising

| Term | In one line |
| --- | --- |
| **Aggregate function** | Many rows in, one value out: `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`. |
| **`COUNT(*)`** | Rows. Same as `COUNT(1)`. |
| **`COUNT(col)`** | Non-`NULL` values in `col`. |
| **`COUNT(DISTINCT col)`** | Different non-`NULL` values. Events against people. |
| **Aggregates and `NULL`** | Every aggregate except `COUNT(*)` skips `NULL`. `SUM` of no rows is `NULL`. |
| **`GROUP BY`** | One output row per group. Every selected column must be grouped or aggregated. |
| **`HAVING`** | Filters groups, after grouping. Can use aggregates. |
| **Conditional aggregation** | `SUM(CASE WHEN ... THEN 1 ELSE 0 END)`: count only some rows in each group. |

## Joining

| Term | In one line |
| --- | --- |
| **Join condition** | The rule that matches rows across tables: `ON s.department_id = d.department_id`. |
| **`INNER JOIN`** | Only rows with a partner on both sides. Silently drops the rest. |
| **`LEFT JOIN`** | Every left row; `NULL`s where there is no match. |
| **`RIGHT JOIN`** | Every right row. A `LEFT JOIN` with the tables swapped. |
| **`FULL OUTER JOIN`** | Everything from both sides. Not in MySQL: `LEFT JOIN UNION RIGHT JOIN`. |
| **Anti-join** | Rows with no match: `LEFT JOIN ... WHERE right.key IS NULL`, or `NOT EXISTS`. |
| **Fan-out** | Joining to several matching rows multiplies rows, and every `SUM` and `COUNT` with them. |
| **Self join** | A table joined to itself with two aliases: faculty and their head. |
| **`CROSS JOIN`** | Every row with every row: the Cartesian product, m × n rows. |
| **`NATURAL JOIN` / `USING`** | Join on same-named columns. `USING` is fine; `NATURAL` is fragile. |
| **Subquery** | A query inside a query. Scalar (one value), list (with `IN`), or table (in `FROM`). |
| **Derived table** | A subquery in `FROM`, used like a table. Needs an alias. |
| **CTE (`WITH`)** | A named subquery written before the main query. The readable form. |
| **Correlated subquery** | Refers to the outer row, so it is evaluated per row. |
| **`EXISTS` / `NOT EXISTS`** | Is there at least one matching row. Safe with `NULL`s. |
| **`UNION`** | Stack two results, removing duplicates. |
| **`UNION ALL`** | Stack two results, keeping duplicates. Faster. |
| **`INTERSECT`** | Rows in both results. |
| **`EXCEPT` / `MINUS`** | Rows in the first result but not the second. `MINUS` in Oracle. |

## Design and safety

| Term | In one line |
| --- | --- |
| **Constraint** | A rule the database enforces on every write. |
| **`NOT NULL`** | The column must have a value. |
| **`UNIQUE`** | No two rows share the value. Allows `NULL`. Many per table. |
| **`PRIMARY KEY`** | Unique and not `NULL`. One per table. The row's identity. |
| **`FOREIGN KEY`** | The value must exist in another table's key. Referential integrity. |
| **`ON DELETE CASCADE`** | Deleting the parent deletes the children. `SET NULL` clears them; the default blocks. |
| **`CHECK`** | The value must pass a condition. Passes on `NULL`. |
| **`DEFAULT`** | The value used when none is given. |
| **Composite key** | A key made of several columns; only the combination is unique. |
| **View** | A stored query used like a table. Stores no rows; always current. |
| **Materialised view** | A stored result. Fast, stale until refreshed. |
| **Index** | A sorted structure over columns that lets the database find rows without scanning. |
| **Full table scan** | Reading every row. `SCAN` in SQLite's plan. |
| **Composite index** | An index on several columns, sorted by the first, then the next. |
| **Leftmost-prefix rule** | A composite index helps only queries that filter on its leading column(s). |
| **`EXPLAIN`** | Shows the plan: whether an index is used (`SEARCH`) or not (`SCAN`). |
| **Transaction** | Several statements that succeed or fail as one. |
| **`BEGIN` / `COMMIT` / `ROLLBACK`** | Start, keep, discard. |
| **`SAVEPOINT`** | A marker to roll back to without abandoning the whole transaction. |
| **Autocommit** | Every statement commits on its own. The default in most tools. |
| **ACID** | Atomicity, Consistency, Isolation, Durability. The DBMS track in detail. |

## Analysing

| Term | In one line |
| --- | --- |
| **Window function** | A value computed over related rows, returned for every row. `OVER (...)`. |
| **`PARTITION BY`** | Splits rows into windows without collapsing them. |
| **`ROW_NUMBER`** | 1, 2, 3, 4. Always unique. |
| **`RANK`** | 1, 2, 2, 4. Ties share, then a gap. |
| **`DENSE_RANK`** | 1, 2, 2, 3. Ties share, no gap. The one for Nth highest. |
| **Running total** | `SUM(x) OVER (ORDER BY date)`. |
| **`LAG` / `LEAD`** | The value from the previous / next row in the window. |
| **`FIRST_VALUE` / `LAST_VALUE`** | First / last value in the frame. `LAST_VALUE` needs a widened frame. |
| **`NTILE(n)`** | Splits ordered rows into n nearly equal bands. |
| **Frame** | Which rows around the current one a window function sees: `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW`. |
| **`CASE`** | SQL's if-then-else. The first true `WHEN` wins; no match and no `ELSE` is `NULL`. |
| **Pivot** | Rows into columns, usually with `SUM(CASE ...)` per category. |

## The SQL round

| Term | In one line |
| --- | --- |
| **Nth highest** | `DENSE_RANK() ... WHERE rnk = N`, or `DISTINCT ... LIMIT 1 OFFSET N-1`. |
| **Duplicates** | `GROUP BY cols HAVING COUNT(*) > 1`. Delete with `NOT IN (SELECT MIN(id) ...)`. |
| **Top N per group** | `ROW_NUMBER() OVER (PARTITION BY ...)` in a CTE, `WHERE rn <= N` outside. |
| **DDL** | Structure: `CREATE`, `ALTER`, `DROP`, `TRUNCATE`. Auto-commits in MySQL and Oracle. |
| **DML** | Rows: `INSERT`, `UPDATE`, `DELETE`, `MERGE`. |
| **DQL** | `SELECT`. Part of DML in some books. |
| **DCL** | Access: `GRANT`, `REVOKE`. |
| **TCL** | Transactions: `COMMIT`, `ROLLBACK`, `SAVEPOINT`. |
| **`TRUNCATE`** | Removes all rows at once. DDL, no `WHERE`, resets identity. No rollback in MySQL, Oracle. |
| **`DROP`** | Removes the table itself, with its structure. |

## The pairs people confuse

These are what an interviewer probes, because a memorised answer falls apart on
the follow-up.

::accordion
  :::accordion-item{label="WHERE against HAVING" icon="i-lucide-git-compare"}
  `WHERE` removes rows before grouping and cannot use aggregates. `HAVING`
  removes groups after grouping and can.
  :::
  :::accordion-item{label="COUNT(*) against COUNT(column)" icon="i-lucide-git-compare"}
  Rows, against non-`NULL` values in that column.
  :::
  :::accordion-item{label="INNER JOIN against LEFT JOIN" icon="i-lucide-git-compare"}
  Matches only, against every left row with `NULL`s where there is no match. A
  right-table condition in `WHERE` quietly turns a `LEFT JOIN` into an inner one.
  :::
  :::accordion-item{label="UNION against UNION ALL" icon="i-lucide-git-compare"}
  Duplicates removed (slower), against duplicates kept (faster).
  :::
  :::accordion-item{label="Primary key against unique key" icon="i-lucide-git-compare"}
  One per table and never `NULL`, against many per table and `NULL` allowed.
  :::
  :::accordion-item{label="RANK against DENSE_RANK against ROW_NUMBER" icon="i-lucide-git-compare"}
  1, 2, 2, 4 against 1, 2, 2, 3 against 1, 2, 3, 4.
  :::
  :::accordion-item{label="DELETE against TRUNCATE against DROP" icon="i-lucide-git-compare"}
  Some or all rows, rollback-able DML; all rows, DDL, resets identity; the whole
  table.
  :::
  :::accordion-item{label="NOT IN against NOT EXISTS" icon="i-lucide-git-compare"}
  `NOT IN` returns nothing if the list holds a `NULL`; `NOT EXISTS` is safe.
  :::
  :::accordion-item{label="View against table" icon="i-lucide-git-compare"}
  A stored query with no rows of its own, against stored rows.
  :::
  :::accordion-item{label="Subquery against join" icon="i-lucide-git-compare"}
  A value or list for the outer query, against wider rows from both tables.
  Joins can duplicate rows; `IN` and `EXISTS` cannot.
  :::
::
