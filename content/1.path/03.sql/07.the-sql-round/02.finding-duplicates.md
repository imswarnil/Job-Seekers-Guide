The second most asked question in the SQL round is shorter than the first, and
you will meet it for real in your first month: "this table has duplicate
students. Find them, then delete the extras without deleting the originals."

## Why this matters in a job

Duplicates arrive from everywhere: an admission form submitted twice, an import
run twice, a spreadsheet merged with a copy of itself. They double-count fees,
send two hall tickets to one student, and break every "one row per student"
report. In interviews the question comes in three steps, and interviewers often
stop you after each one: find the duplicate values, show the duplicate rows,
delete all but one.

## What counts as a duplicate

A duplicate is decided by **the columns that should be unique**, not by the
whole row. Two rows for Anita Rao with different `student_id`s are not
identical rows (the ids differ), but they are the same student if the email is
the same. So the first step is always to say which columns define "the same":
here, `email`.

::flow{numbered direction="vertical" caption="The three steps an interviewer walks you through."}
  :::flow-step{label="Find the duplicated values" icon="i-lucide-search"}
  GROUP BY email HAVING COUNT(*) > 1.
  :::
  :::flow-step{label="Show every duplicate row" icon="i-lucide-rows-3"}
  Join back, or use COUNT(*) OVER.
  :::
  :::flow-step{label="Delete all but one" icon="i-lucide-trash-2" highlight}
  Keep the lowest id per email, delete the rest.
  :::
  :::flow-step{label="Stop it happening again" icon="i-lucide-shield"}
  A UNIQUE constraint on email.
  :::
::

## How it works

```sql [students.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, email TEXT, city TEXT);
INSERT INTO Student VALUES
  (1, 'Anita Rao',    'anita@college.edu',  'Bhopal'),
  (2, 'Rahul Verma',  'rahul@college.edu',  'Patna'),
  (3, 'Anita Rao',    'anita@college.edu',  'Bhopal'),
  (4, 'Priya Nair',   'priya@college.edu',  'Bangalore'),
  (5, 'Rahul Verma',  'rahul@college.edu',  'Patna'),
  (6, 'Anita Rao',    'anita@college.edu',  'Indore');
```

### Step 1: which values are duplicated

::runner{lang="sql"}
```sql [find-duplicate-emails.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, email TEXT, city TEXT);
INSERT INTO Student VALUES
  (1, 'Anita Rao', 'anita@college.edu', 'Bhopal'), (2, 'Rahul Verma', 'rahul@college.edu', 'Patna'),
  (3, 'Anita Rao', 'anita@college.edu', 'Bhopal'), (4, 'Priya Nair', 'priya@college.edu', 'Bangalore'),
  (5, 'Rahul Verma', 'rahul@college.edu', 'Patna'), (6, 'Anita Rao', 'anita@college.edu', 'Indore');

SELECT email, COUNT(*) AS copies
FROM   Student
GROUP BY email
HAVING COUNT(*) > 1;
```
::

```text [Output]
email              copies
-----------------  ------
anita@college.edu  3
rahul@college.edu  2
```

This is the answer to "find duplicates" in its short form, and the one to write
first. It is `GROUP BY` and `HAVING` from the summarising chapter, nothing more.

### Step 2: every duplicate row, not only the value

The interviewer's follow-up: "Show me the actual rows." Two ways:

::runner{lang="sql"}
```sql [show-duplicate-rows.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, email TEXT, city TEXT);
INSERT INTO Student VALUES
  (1, 'Anita Rao', 'anita@college.edu', 'Bhopal'), (2, 'Rahul Verma', 'rahul@college.edu', 'Patna'),
  (3, 'Anita Rao', 'anita@college.edu', 'Bhopal'), (4, 'Priya Nair', 'priya@college.edu', 'Bangalore'),
  (5, 'Rahul Verma', 'rahul@college.edu', 'Patna'), (6, 'Anita Rao', 'anita@college.edu', 'Indore');

-- With a subquery.
SELECT * FROM Student
WHERE  email IN (SELECT email FROM Student GROUP BY email HAVING COUNT(*) > 1)
ORDER BY email, student_id;

-- With a window function: every row, with how many copies it has.
SELECT student_id, email, city,
       COUNT(*) OVER (PARTITION BY email) AS copies
FROM   Student
ORDER BY email, student_id;
```
::

```text [Output]
student_id  full_name    email              city
----------  -----------  -----------------  ------
1           Anita Rao    anita@college.edu  Bhopal
3           Anita Rao    anita@college.edu  Bhopal
6           Anita Rao    anita@college.edu  Indore
2           Rahul Verma  rahul@college.edu  Patna
5           Rahul Verma  rahul@college.edu  Patna

student_id  email              city       copies
----------  -----------------  ---------  ------
1           anita@college.edu  Bhopal     3
3           anita@college.edu  Bhopal     3
6           anita@college.edu  Indore     3
4           priya@college.edu  Bangalore  1
2           rahul@college.edu  Patna      2
5           rahul@college.edu  Patna      2
```

Notice student 6: same email, **different city**. It might be a genuine update
(Anita moved to Indore) rather than a copy. Before deleting anything, look at
what differs between the copies; the query tells you they are duplicates by
email, not that the extra rows are worthless.

### Step 3: delete all but one

::warning{icon="i-lucide-alert-triangle"}
This is a `DELETE` driven by a subquery, the most dangerous shape there is. Run
it as a `SELECT` first, inside `BEGIN`, check the count, then `COMMIT`. Get the
subquery wrong and it deletes the originals too.
::

Keep the lowest `student_id` for each email and delete the rest:

::runner{lang="sql"}
```sql [delete-duplicates.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, email TEXT, city TEXT);
INSERT INTO Student VALUES
  (1, 'Anita Rao', 'anita@college.edu', 'Bhopal'), (2, 'Rahul Verma', 'rahul@college.edu', 'Patna'),
  (3, 'Anita Rao', 'anita@college.edu', 'Bhopal'), (4, 'Priya Nair', 'priya@college.edu', 'Bangalore'),
  (5, 'Rahul Verma', 'rahul@college.edu', 'Patna'), (6, 'Anita Rao', 'anita@college.edu', 'Indore');

BEGIN;

-- Look first: the rows that WILL be deleted.
SELECT * FROM Student
WHERE  student_id NOT IN (SELECT MIN(student_id) FROM Student GROUP BY email);

DELETE FROM Student
WHERE  student_id NOT IN (SELECT MIN(student_id) FROM Student GROUP BY email);

SELECT changes() AS deleted;
COMMIT;

SELECT * FROM Student ORDER BY student_id;
```
::

```text [Output]
student_id  full_name    email              city
----------  -----------  -----------------  ------
3           Anita Rao    anita@college.edu  Bhopal
5           Rahul Verma  rahul@college.edu  Patna
6           Anita Rao    anita@college.edu  Indore

deleted
-------
3

student_id  full_name    email              city
----------  -----------  -----------------  ---------
1           Anita Rao    anita@college.edu  Bhopal
2           Rahul Verma  rahul@college.edu  Patna
4           Priya Nair   priya@college.edu  Bangalore
```

The same with `ROW_NUMBER`, which lets you choose **which** copy to keep (here,
the most recent id instead of the oldest):

::runner{lang="sql"}
```sql [delete-with-row-number.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, email TEXT, city TEXT);
INSERT INTO Student VALUES
  (1, 'Anita Rao', 'anita@college.edu', 'Bhopal'), (2, 'Rahul Verma', 'rahul@college.edu', 'Patna'),
  (3, 'Anita Rao', 'anita@college.edu', 'Bhopal'), (4, 'Priya Nair', 'priya@college.edu', 'Bangalore'),
  (5, 'Rahul Verma', 'rahul@college.edu', 'Patna'), (6, 'Anita Rao', 'anita@college.edu', 'Indore');

DELETE FROM Student
WHERE  student_id IN (
  SELECT student_id FROM (
    SELECT student_id,
           ROW_NUMBER() OVER (PARTITION BY email ORDER BY student_id DESC) AS rn
    FROM   Student
  ) AS numbered
  WHERE rn > 1
);

SELECT * FROM Student ORDER BY student_id;
```
::

```text [Output]
student_id  full_name    email              city
----------  -----------  -----------------  ---------
4           Priya Nair   priya@college.edu  Bangalore
5           Rahul Verma  rahul@college.edu  Patna
6           Anita Rao    anita@college.edu  Indore
```

Anita's Indore row survived this time, because the newest copy was kept. Which
copy is "right" is a business decision; the query only carries it out.

::note
MySQL refuses `DELETE FROM Student WHERE student_id IN (SELECT ... FROM
Student ...)` with error 1093 ("You can't specify target table for update in
FROM clause"). The usual fix is to wrap the subquery one level deeper, as the
`ROW_NUMBER` version above does, or to use a self join:
`DELETE s1 FROM Student s1 JOIN Student s2 ON s1.email = s2.email AND s1.student_id > s2.student_id;`
::

## Real use case

The admissions office imported the same batch of fee payments twice. A duplicate
payment is the same student, amount and date. Find how much money is
double-counted, remove the extra copies, and then add a constraint so a second
import is refused instead of silently accepted:

::runner{lang="sql"}
```sql [duplicate-payments.sql]
CREATE TABLE FeePayment (payment_id INTEGER PRIMARY KEY, student_id INTEGER, amount INTEGER, paid_on TEXT);
INSERT INTO FeePayment VALUES
  (1, 1, 42500, '2025-07-14'), (2, 2, 42500, '2025-07-15'), (3, 3, 21250, '2025-07-15'),
  (4, 1, 42500, '2025-07-14'), (5, 2, 42500, '2025-07-15'), (6, 3, 21250, '2025-08-01');

-- How much is counted twice?
SELECT COUNT(*) - 1 AS extra_copies, (COUNT(*) - 1) * amount AS overstated, student_id, amount, paid_on
FROM   FeePayment
GROUP BY student_id, amount, paid_on
HAVING COUNT(*) > 1;

DELETE FROM FeePayment
WHERE  payment_id NOT IN (SELECT MIN(payment_id) FROM FeePayment
                          GROUP BY student_id, amount, paid_on);

CREATE UNIQUE INDEX uq_payment ON FeePayment (student_id, amount, paid_on);

SELECT SUM(amount) AS total_collected FROM FeePayment;
```
::

```text [Output]
extra_copies  overstated  student_id  amount  paid_on
------------  ----------  ----------  ------  ----------
1             42500       1           42500   2025-07-14
1             42500       2           42500   2025-07-15

total_collected
---------------
127500
```

Student 3's two payments are on different dates, so they are two real
instalments and both stay. The unique index is the last step and the most
important one: after it, running the same import again fails loudly instead of
doubling the money a third time.

## What confuses people here

- **`DISTINCT` does not remove duplicates from the table.** It hides them from
  one query's result. The table still has them, and the next report counts them.
- **`NOT IN` with a subquery that could return `NULL`.** `MIN(student_id)` never
  returns `NULL` here because `student_id` is a primary key. If the key column
  could be `NULL`, use `NOT EXISTS`.
- **Duplicates by which columns?** "Same name" is not "same student": two
  different students can both be called Rahul Verma. Match on something that
  genuinely identifies a person (email, roll number, Aadhaar-style id), and
  confirm with whoever owns the data.
- **Case and spaces.** `'Anita@College.edu'` and `'anita@college.edu '` are
  different strings. Group on `LOWER(TRIM(email))` to catch them.

## Interview questions

::accordion
  :::accordion-item{label="How do you find duplicate records in a table?" icon="i-lucide-message-circle"}
  `SELECT email, COUNT(*) FROM Student GROUP BY email HAVING COUNT(*) > 1;`
  Group by the columns that should be unique; any group with more than one row
  is duplicated. On the data above: anita@college.edu 3, rahul@college.edu 2.
  :::
  :::accordion-item{label="How do you delete duplicates but keep one?" icon="i-lucide-message-circle"}
  `DELETE FROM Student WHERE student_id NOT IN (SELECT MIN(student_id) FROM Student GROUP BY email);`
  keeps the lowest id per email. Or number the copies with
  `ROW_NUMBER() OVER (PARTITION BY email ORDER BY student_id)` and delete
  `rn > 1`. Say you would run it as a `SELECT` inside a transaction first.
  :::
  :::accordion-item{label="How do you delete duplicates when the table has no primary key?" icon="i-lucide-message-circle"}
  Copy the distinct rows into a new table, then swap: `CREATE TABLE s2 AS
  SELECT DISTINCT * FROM Student;`, drop the old table and rename. Or use a
  hidden row identifier: `ROWID` in SQLite and Oracle, `ctid` in PostgreSQL.
  :::
  :::accordion-item{label="How do you prevent duplicates?" icon="i-lucide-message-circle"}
  A `UNIQUE` constraint (or unique index) on the identifying columns, so the
  database refuses the second insert. Application checks alone are not enough:
  two requests at the same moment can both pass the check.
  :::
  :::accordion-item{label="Find students enrolled in the same course more than once." icon="i-lucide-message-circle"}
  `SELECT student_id, course_id, COUNT(*) FROM Enrolment GROUP BY student_id,
  course_id HAVING COUNT(*) > 1;` Duplicates across several columns are the same
  query with more columns in `GROUP BY`.
  :::
::
