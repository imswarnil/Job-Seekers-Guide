"The highest-paid in each department" was top 1 per group. Change it to "the top
three students in each course, with ties handled properly" and it becomes the
hardest of the classic questions, because `GROUP BY` can give you the top
**value** per group but not the top **rows**.

## Why this matters in a job

"Top 5 products per region", "latest 3 payments per student", "best result per
course": top N per group is one of the most common real reporting requests, and
it is where people who only know `GROUP BY` get stuck. In interviews it is the
question that separates candidates who know window functions from those who do
not, and the follow-up is always about ties.

## Why GROUP BY cannot do it

`SELECT course_id, MAX(marks) FROM ExamResult GROUP BY course_id` gives the top
mark per course. It cannot give the top three marks, and it cannot tell you
**who** got them, because a group collapses to one row. You need to keep every
row, number the rows within each course, and then keep the first N. That is
exactly what a window function does.

::flow{numbered direction="vertical" caption="The shape of every top N per group answer."}
  :::flow-step{label="Partition" icon="i-lucide-layers"}
  One window per course: PARTITION BY course_id.
  :::
  :::flow-step{label="Order and number" icon="i-lucide-list-ordered" highlight}
  Highest marks first, numbered 1, 2, 3 within each course.
  :::
  :::flow-step{label="Filter outside" icon="i-lucide-filter"}
  In a CTE, then WHERE rn <= 3 in the outer query.
  :::
::

## How it works

```sql [results.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, full_name TEXT, course_code TEXT, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 'Priya Nair',  'CS201', 91), (2, 'Anita Rao',   'CS201', 87), (3, 'Arjun Mehta', 'CS201', 87),
  (4, 'Sneha Iyer',  'CS201', 78), (5, 'Rahul Verma', 'CS201', 64),
  (6, 'Karan Patel', 'CS202', 88), (7, 'Anita Rao',   'CS202', 72), (8, 'Priya Nair',  'CS202', 69),
  (9, 'Divya Menon', 'CS202', 69), (10, 'Rohit Kumar','CS202', 55);
```

### ROW_NUMBER: exactly N per group

::runner{lang="sql"}
```sql [top3-row-number.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, full_name TEXT, course_code TEXT, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 'Priya Nair', 'CS201', 91), (2, 'Anita Rao', 'CS201', 87), (3, 'Arjun Mehta', 'CS201', 87),
  (4, 'Sneha Iyer', 'CS201', 78), (5, 'Rahul Verma', 'CS201', 64),
  (6, 'Karan Patel', 'CS202', 88), (7, 'Anita Rao', 'CS202', 72), (8, 'Priya Nair', 'CS202', 69),
  (9, 'Divya Menon', 'CS202', 69), (10, 'Rohit Kumar', 'CS202', 55);

WITH ranked AS (
  SELECT course_code, full_name, marks,
         ROW_NUMBER() OVER (PARTITION BY course_code
                            ORDER BY marks DESC, full_name) AS rn
  FROM   ExamResult
)
SELECT course_code, rn, full_name, marks
FROM   ranked
WHERE  rn <= 3
ORDER BY course_code, rn;
```
::

```text [Output]
course_code  rn  full_name    marks
-----------  --  -----------  -----
CS201        1   Priya Nair   91
CS201        2   Anita Rao    87
CS201        3   Arjun Mehta  87
CS202        1   Karan Patel  88
CS202        2   Anita Rao    72
CS202        3   Divya Menon  69
```

Exactly three per course. In CS202, Priya and Divya are tied on 69 for third
place and only Divya is listed, because the tie-break (`full_name`)
alphabetically put her first. That may be fine (three interview slots, strictly)
or unfair (a prize for "the top three marks"). The query is honest about the
rule because the rule is written in its `ORDER BY`.

### DENSE_RANK: everyone in the top N marks

::runner{lang="sql"}
```sql [top3-dense-rank.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, full_name TEXT, course_code TEXT, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 'Priya Nair', 'CS201', 91), (2, 'Anita Rao', 'CS201', 87), (3, 'Arjun Mehta', 'CS201', 87),
  (4, 'Sneha Iyer', 'CS201', 78), (5, 'Rahul Verma', 'CS201', 64),
  (6, 'Karan Patel', 'CS202', 88), (7, 'Anita Rao', 'CS202', 72), (8, 'Priya Nair', 'CS202', 69),
  (9, 'Divya Menon', 'CS202', 69), (10, 'Rohit Kumar', 'CS202', 55);

WITH ranked AS (
  SELECT course_code, full_name, marks,
         DENSE_RANK() OVER (PARTITION BY course_code ORDER BY marks DESC) AS rnk
  FROM   ExamResult
)
SELECT course_code, rnk, full_name, marks
FROM   ranked
WHERE  rnk <= 3
ORDER BY course_code, rnk, full_name;
```
::

```text [Output]
course_code  rnk  full_name    marks
-----------  ---  -----------  -----
CS201        1    Priya Nair   91
CS201        2    Anita Rao    87
CS201        2    Arjun Mehta  87
CS201        3    Sneha Iyer   78
CS202        1    Karan Patel  88
CS202        2    Anita Rao    72
CS202        3    Divya Menon  69
CS202        3    Priya Nair   69
```

CS201 now returns four students (the three highest distinct marks are 91, 87 and
78, and two students share 87). CS202 returns four (88, 72 and the two on 69).

::compare{caption="Choose by what the result is for."}
  :::compare-side{label="ROW_NUMBER" verdict="right"}
  Exactly N rows per group, ties broken by a rule you write. Three interview
  slots per course, the latest three payments per student.
  :::
  :::compare-side{label="DENSE_RANK (or RANK)" verdict="right"}
  Everyone whose marks are in the top N, however many that is. Prizes, merit
  lists, anything where a tie must not be decided by alphabet. `RANK` gives
  "top 3 positions" (1, 2, 2 then stop); `DENSE_RANK` gives "top 3 marks".
  :::
::

### Without window functions: a correlated count

The version that works on MySQL 5.7 and in exams that do not allow window
functions: a row is in the top 3 of its course if fewer than 3 students in the
same course scored higher.

::runner{lang="sql"}
```sql [top3-correlated.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, full_name TEXT, course_code TEXT, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 'Priya Nair', 'CS201', 91), (2, 'Anita Rao', 'CS201', 87), (3, 'Arjun Mehta', 'CS201', 87),
  (4, 'Sneha Iyer', 'CS201', 78), (5, 'Rahul Verma', 'CS201', 64),
  (6, 'Karan Patel', 'CS202', 88), (7, 'Anita Rao', 'CS202', 72), (8, 'Priya Nair', 'CS202', 69),
  (9, 'Divya Menon', 'CS202', 69), (10, 'Rohit Kumar', 'CS202', 55);

SELECT e.course_code, e.full_name, e.marks
FROM   ExamResult e
WHERE  (SELECT COUNT(*) FROM ExamResult x
        WHERE  x.course_code = e.course_code AND x.marks > e.marks) < 3
ORDER BY e.course_code, e.marks DESC, e.full_name;
```
::

```text [Output]
course_code  full_name    marks
-----------  -----------  -----
CS201        Priya Nair   91
CS201        Anita Rao    87
CS201        Arjun Mehta  87
CS202        Karan Patel  88
CS202        Anita Rao    72
CS202        Divya Menon  69
CS202        Priya Nair   69
```

This behaves like `RANK`: in CS202, two students scored above the 69s, so both
69s qualify. Correct, and slow on large tables, because the count runs once per
row.

### Top 1 only: MAX joined back

For the single best per group, the oldest trick still works everywhere:
compute the maximum per group, then join back to find who has it.

::runner{lang="sql"}
```sql [top1-max-join.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, full_name TEXT, course_code TEXT, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 'Priya Nair', 'CS201', 91), (2, 'Anita Rao', 'CS201', 87), (3, 'Arjun Mehta', 'CS201', 87),
  (4, 'Sneha Iyer', 'CS201', 78), (5, 'Rahul Verma', 'CS201', 64),
  (6, 'Karan Patel', 'CS202', 88), (7, 'Anita Rao', 'CS202', 72), (8, 'Priya Nair', 'CS202', 69),
  (9, 'Divya Menon', 'CS202', 69), (10, 'Rohit Kumar', 'CS202', 55);

SELECT e.course_code, e.full_name, e.marks
FROM   ExamResult e
JOIN  (SELECT course_code, MAX(marks) AS top_marks
       FROM   ExamResult GROUP BY course_code) m
  ON   m.course_code = e.course_code AND m.top_marks = e.marks
ORDER BY e.course_code;
```
::

```text [Output]
course_code  full_name    marks
-----------  -----------  -----
CS201        Priya Nair   91
CS202        Karan Patel  88
```

## Real use case

Two more questions from the same family come up constantly. The first: "the
department with the highest average marks". The second: "students with no
result at all". Both use tools from earlier chapters, and both have a trap:

::runner{lang="sql"}
```sql [two-favourites.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, department TEXT);
INSERT INTO Student VALUES
  (1, 'Anita Rao', 'CSE'), (2, 'Rahul Verma', 'ECE'), (3, 'Priya Nair', 'CSE'),
  (4, 'Arjun Mehta', 'Mechanical'), (5, 'Karan Patel', 'ECE'), (6, 'Meera Joshi', 'Civil');
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, student_id INTEGER, marks INTEGER);
INSERT INTO ExamResult VALUES (1, 1, 87), (2, 2, 64), (3, 3, 91), (4, 4, 70), (5, 5, 92), (6, 1, 72);

-- Department(s) with the highest average, ties included.
WITH dept AS (
  SELECT s.department, ROUND(AVG(r.marks), 2) AS average
  FROM   ExamResult r JOIN Student s ON s.student_id = r.student_id
  GROUP BY s.department
)
SELECT department, average FROM dept
WHERE  average = (SELECT MAX(average) FROM dept);

-- Students with no result at all.
SELECT s.full_name, s.department
FROM   Student s
WHERE  NOT EXISTS (SELECT 1 FROM ExamResult r WHERE r.student_id = s.student_id);
```
::

```text [Output]
department  average
----------  -------
CSE         83.33

full_name    department
-----------  ----------
Meera Joshi  Civil
```

The first trap: `ORDER BY average DESC LIMIT 1` returns one department even when
two tie for first. The second: a `NOT IN` version breaks if any result has a
`NULL` `student_id`, which is why this is `NOT EXISTS`.

## What confuses people here

- **Filtering on the window function in the same query.** `WHERE ROW_NUMBER()
  OVER (...) <= 3` is an error: window functions are computed after `WHERE`.
  Rank in a CTE or subquery, filter outside.
- **Forgetting `PARTITION BY`** gives the top 3 of the whole table, not of each
  course. The query runs and the answer looks plausible.
- **Groups with fewer than N rows** return what they have. A course with two
  students returns two rows for "top 3", which is correct.
- **`ROW_NUMBER` without a tie-break** in the `ORDER BY` is not reproducible:
  which of two 69s is "third" can change between runs. Always end the window's
  `ORDER BY` on something unique if you use `ROW_NUMBER`.

## Interview questions

::accordion
  :::accordion-item{label="Find the top 3 students in each course." icon="i-lucide-message-circle"}
  `ROW_NUMBER() OVER (PARTITION BY course_code ORDER BY marks DESC, full_name)`
  in a CTE, then `WHERE rn <= 3`. Then ask, or state, how ties should be
  handled, and switch to `DENSE_RANK` if everyone on a tied mark should appear.
  :::
  :::accordion-item{label="Why can't you do this with GROUP BY?" icon="i-lucide-message-circle"}
  `GROUP BY` collapses each course to one row, so it can return the top value
  (`MAX`) but not the rows behind it, and not the top three. Window functions
  keep every row and number them within each group.
  :::
  :::accordion-item{label="How would you do it in MySQL 5.7, without window functions?" icon="i-lucide-message-circle"}
  A correlated subquery: keep a row if fewer than 3 rows in the same course have
  higher marks. Correct, including ties, and slow on large tables because the
  count runs once per row. For top 1, join to a `GROUP BY ... MAX()` derived
  table.
  :::
  :::accordion-item{label="Find the latest payment for each student." icon="i-lucide-message-circle"}
  The same pattern with a date:
  `ROW_NUMBER() OVER (PARTITION BY student_id ORDER BY paid_on DESC, payment_id DESC)`
  and `WHERE rn = 1`. The correlated `MAX(paid_on)` version is in the correlated
  subqueries lesson.
  :::
  :::accordion-item{label="Find the department with the highest average marks." icon="i-lucide-message-circle"}
  Average per department in a CTE, then `WHERE average = (SELECT MAX(average) FROM dept)`,
  which keeps ties. On the data above it is CSE, with 83.33.
  :::
::
