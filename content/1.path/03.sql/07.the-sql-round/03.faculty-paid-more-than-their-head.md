The third classic checks whether you can join a table to itself under pressure.
In most companies it is "find employees who earn more than their manager". In
this guide it is faculty who earn more than the head they report to, and the
self join lesson already built the mechanism. This lesson is the question, and
the four follow-ups that come after it.

## Why this matters in a job

Any table that points at itself (reporting lines, a course and its
prerequisite, a category and its parent) needs this pattern, and real HR and
academic systems are full of them. In interviews it is asked because the naive
attempt fails in an instructive way: people try `WHERE salary > manager_salary`
on one table and discover there is no such column, and the interviewer watches
whether they reach for a second alias.

## Two fingers on one register

The `Faculty` table has `reports_to`, holding the `faculty_id` of the person's
head. To compare a faculty member with their head, you need **both rows on one
line**. A self join puts them there: alias `f` for the faculty member, alias `h`
for the head, matched by `h.faculty_id = f.reports_to`. After that, comparing
salaries is an ordinary `WHERE`.

## How it works

```sql [faculty.sql]
CREATE TABLE Department (department_id INTEGER PRIMARY KEY, name TEXT);
INSERT INTO Department VALUES (1, 'CSE'), (2, 'ECE'), (3, 'Mechanical');

CREATE TABLE Faculty (faculty_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER,
                      salary INTEGER, reports_to INTEGER);
INSERT INTO Faculty VALUES
  (1, 'Dr. Meera Joshi', 1, 150000, NULL),
  (2, 'Vikram Singh',    1,  95000, 1),
  (3, 'Rohit Kumar',     1,  82000, 1),
  (4, 'Anjali Desai',    1, 155000, 1),
  (5, 'Dr. Suresh Rao',  2, 140000, NULL),
  (6, 'Divya Menon',     2, 145000, 5),
  (7, 'Kavita Sharma',   2,  78000, 5),
  (8, 'Dr. Nitin Gupta', 3, 130000, NULL),
  (9, 'Farhan Ali',      3,  90000, NULL);    -- reporting line not yet entered
```

### The question

::runner{lang="sql"}
```sql [earns-more-than-head.sql]
CREATE TABLE Faculty (faculty_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER, salary INTEGER, reports_to INTEGER);
INSERT INTO Faculty VALUES
  (1, 'Dr. Meera Joshi', 1, 150000, NULL), (2, 'Vikram Singh', 1, 95000, 1),
  (3, 'Rohit Kumar', 1, 82000, 1), (4, 'Anjali Desai', 1, 155000, 1),
  (5, 'Dr. Suresh Rao', 2, 140000, NULL), (6, 'Divya Menon', 2, 145000, 5),
  (7, 'Kavita Sharma', 2, 78000, 5), (8, 'Dr. Nitin Gupta', 3, 130000, NULL),
  (9, 'Farhan Ali', 3, 90000, NULL);

SELECT f.full_name AS faculty, f.salary,
       h.full_name AS head,    h.salary AS head_salary
FROM   Faculty f
JOIN   Faculty h ON h.faculty_id = f.reports_to
WHERE  f.salary > h.salary;
```
::

```text [Output]
faculty       salary  head             head_salary
------------  ------  ---------------  -----------
Anjali Desai  155000  Dr. Meera Joshi  150000
Divya Menon   145000  Dr. Suresh Rao   140000
```

That is the whole answer, and on a whiteboard it is four lines. Say, while
writing it, "I join the table to itself: `f` is the faculty member and `h` is
their head". The interviewer is listening for that sentence.

The same question as a correlated subquery, which some interviewers ask for as
a second way:

::runner{lang="sql"}
```sql [earns-more-correlated.sql]
CREATE TABLE Faculty (faculty_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER, salary INTEGER, reports_to INTEGER);
INSERT INTO Faculty VALUES
  (1, 'Dr. Meera Joshi', 1, 150000, NULL), (2, 'Vikram Singh', 1, 95000, 1),
  (3, 'Rohit Kumar', 1, 82000, 1), (4, 'Anjali Desai', 1, 155000, 1),
  (5, 'Dr. Suresh Rao', 2, 140000, NULL), (6, 'Divya Menon', 2, 145000, 5),
  (7, 'Kavita Sharma', 2, 78000, 5), (8, 'Dr. Nitin Gupta', 3, 130000, NULL),
  (9, 'Farhan Ali', 3, 90000, NULL);

SELECT f.full_name, f.salary
FROM   Faculty f
WHERE  f.salary > (SELECT h.salary FROM Faculty h WHERE h.faculty_id = f.reports_to);
```
::

```text [Output]
full_name     salary
------------  ------
Anjali Desai  155000
Divya Menon   145000
```

## The four follow-ups

### 1. Faculty with no head recorded

"Who has no one above them?" Heads have `reports_to = NULL`, and so does Farhan,
whose reporting line was never entered. Telling them apart is the interesting
part:

::runner{lang="sql"}
```sql [no-head.sql]
CREATE TABLE Faculty (faculty_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER, salary INTEGER, reports_to INTEGER);
INSERT INTO Faculty VALUES
  (1, 'Dr. Meera Joshi', 1, 150000, NULL), (2, 'Vikram Singh', 1, 95000, 1),
  (3, 'Rohit Kumar', 1, 82000, 1), (4, 'Anjali Desai', 1, 155000, 1),
  (5, 'Dr. Suresh Rao', 2, 140000, NULL), (6, 'Divya Menon', 2, 145000, 5),
  (7, 'Kavita Sharma', 2, 78000, 5), (8, 'Dr. Nitin Gupta', 3, 130000, NULL),
  (9, 'Farhan Ali', 3, 90000, NULL);

-- Nobody above them, AND nobody reports to them either: a data problem, not a head.
SELECT f.full_name
FROM   Faculty f
WHERE  f.reports_to IS NULL
  AND  NOT EXISTS (SELECT 1 FROM Faculty x WHERE x.reports_to = f.faculty_id);
```
::

```text [Output]
full_name
---------------
Dr. Nitin Gupta
Farhan Ali
```

Dr. Nitin Gupta also has nobody reporting to him in this data, so he appears
too. The query found two rows to check, which is exactly what a data-quality
query should do: it does not decide, it points.

### 2. Heads with the most people reporting to them

::runner{lang="sql"}
```sql [most-reports.sql]
CREATE TABLE Faculty (faculty_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER, salary INTEGER, reports_to INTEGER);
INSERT INTO Faculty VALUES
  (1, 'Dr. Meera Joshi', 1, 150000, NULL), (2, 'Vikram Singh', 1, 95000, 1),
  (3, 'Rohit Kumar', 1, 82000, 1), (4, 'Anjali Desai', 1, 155000, 1),
  (5, 'Dr. Suresh Rao', 2, 140000, NULL), (6, 'Divya Menon', 2, 145000, 5),
  (7, 'Kavita Sharma', 2, 78000, 5), (8, 'Dr. Nitin Gupta', 3, 130000, NULL),
  (9, 'Farhan Ali', 3, 90000, NULL);

SELECT h.full_name AS head, COUNT(f.faculty_id) AS reports
FROM   Faculty h
LEFT JOIN Faculty f ON f.reports_to = h.faculty_id
WHERE  h.reports_to IS NULL
GROUP BY h.faculty_id, h.full_name
ORDER BY reports DESC;
```
::

```text [Output]
head             reports
---------------  -------
Dr. Meera Joshi  3
Dr. Suresh Rao   2
Dr. Nitin Gupta  0
Farhan Ali       0
```

`LEFT JOIN` and `COUNT(f.faculty_id)`, so a head with nobody reporting shows 0
rather than disappearing (the joins lesson's rule). Farhan shows up here too,
because the query treats anyone with no `reports_to` as a head, which is the
data problem from follow-up 1 showing itself again.

### 3. Faculty earning more than their department's average

A different comparison: not with one other row, but with an aggregate of the
row's own group. That is a correlated subquery, or a window function:

::runner{lang="sql"}
```sql [above-dept-average.sql]
CREATE TABLE Faculty (faculty_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER, salary INTEGER, reports_to INTEGER);
INSERT INTO Faculty VALUES
  (1, 'Dr. Meera Joshi', 1, 150000, NULL), (2, 'Vikram Singh', 1, 95000, 1),
  (3, 'Rohit Kumar', 1, 82000, 1), (4, 'Anjali Desai', 1, 155000, 1),
  (5, 'Dr. Suresh Rao', 2, 140000, NULL), (6, 'Divya Menon', 2, 145000, 5),
  (7, 'Kavita Sharma', 2, 78000, 5), (8, 'Dr. Nitin Gupta', 3, 130000, NULL),
  (9, 'Farhan Ali', 3, 90000, NULL);

WITH f AS (
  SELECT full_name, department_id, salary,
         AVG(salary) OVER (PARTITION BY department_id) AS dept_avg
  FROM   Faculty
)
SELECT full_name, department_id, salary, ROUND(dept_avg) AS dept_avg
FROM   f
WHERE  salary > dept_avg
ORDER BY department_id, salary DESC;
```
::

```text [Output]
full_name        department_id  salary  dept_avg
---------------  -------------  ------  --------
Anjali Desai     1              155000  120500.0
Dr. Meera Joshi  1              150000  120500.0
Divya Menon      2              145000  121000.0
Dr. Suresh Rao   2              140000  121000.0
Dr. Nitin Gupta  3              130000  110000.0
```

### 4. The highest-paid faculty member in each department

::runner{lang="sql"}
```sql [highest-per-department.sql]
CREATE TABLE Department (department_id INTEGER PRIMARY KEY, name TEXT);
INSERT INTO Department VALUES (1, 'CSE'), (2, 'ECE'), (3, 'Mechanical');
CREATE TABLE Faculty (faculty_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER, salary INTEGER, reports_to INTEGER);
INSERT INTO Faculty VALUES
  (1, 'Dr. Meera Joshi', 1, 150000, NULL), (2, 'Vikram Singh', 1, 95000, 1),
  (3, 'Rohit Kumar', 1, 82000, 1), (4, 'Anjali Desai', 1, 155000, 1),
  (5, 'Dr. Suresh Rao', 2, 140000, NULL), (6, 'Divya Menon', 2, 145000, 5),
  (7, 'Kavita Sharma', 2, 78000, 5), (8, 'Dr. Nitin Gupta', 3, 130000, NULL),
  (9, 'Farhan Ali', 3, 90000, NULL);

SELECT d.name AS department, f.full_name, f.salary
FROM   Faculty f
JOIN   Department d ON d.department_id = f.department_id
WHERE  f.salary = (SELECT MAX(x.salary) FROM Faculty x WHERE x.department_id = f.department_id)
ORDER BY d.name;
```
::

```text [Output]
department  full_name        salary
----------  ---------------  ------
CSE         Anjali Desai     155000
ECE         Divya Menon      145000
Mechanical  Dr. Nitin Gupta  130000
```

This is "top 1 per group", and the next lesson is entirely about its general
form.

## Real use case

A college's HR office runs a pay-equity check every year before appraisals:
anyone paid more than the person they report to is flagged, with the gap, so
the committee can confirm it is deliberate (a senior professor reporting to a
younger head, for example) rather than a data-entry error. The production
version is the interview answer with a join to `Department` and a computed gap:

::runner{lang="sql"}
```sql [pay-equity-check.sql]
CREATE TABLE Department (department_id INTEGER PRIMARY KEY, name TEXT);
INSERT INTO Department VALUES (1, 'CSE'), (2, 'ECE'), (3, 'Mechanical');
CREATE TABLE Faculty (faculty_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER, salary INTEGER, reports_to INTEGER);
INSERT INTO Faculty VALUES
  (1, 'Dr. Meera Joshi', 1, 150000, NULL), (2, 'Vikram Singh', 1, 95000, 1),
  (3, 'Rohit Kumar', 1, 82000, 1), (4, 'Anjali Desai', 1, 155000, 1),
  (5, 'Dr. Suresh Rao', 2, 140000, NULL), (6, 'Divya Menon', 2, 145000, 5),
  (7, 'Kavita Sharma', 2, 78000, 5), (8, 'Dr. Nitin Gupta', 3, 130000, NULL),
  (9, 'Farhan Ali', 3, 90000, NULL);

SELECT d.name              AS department,
       f.full_name         AS faculty,
       h.full_name         AS head,
       f.salary - h.salary AS paid_above_head
FROM   Faculty f
JOIN   Faculty h    ON h.faculty_id    = f.reports_to
JOIN   Department d ON d.department_id = f.department_id
WHERE  f.salary > h.salary
ORDER BY paid_above_head DESC;
```
::

```text [Output]
department  faculty       head             paid_above_head
----------  ------------  ---------------  ---------------
CSE         Anjali Desai  Dr. Meera Joshi  5000
ECE         Divya Menon   Dr. Suresh Rao   5000
```

## What confuses people here

- **Which alias is which.** Write the `ON` as `h.faculty_id = f.reports_to` and
  read it aloud: "the head's id is the faculty member's reports_to". Swap them
  (`f.faculty_id = h.reports_to`) and you get each head's reports instead, and
  the salary comparison flips meaning.
- **Inner join drops the heads**, whose `reports_to` is `NULL`. For "earns more
  than their head" that is correct: a head has no head to out-earn. For a full
  listing of everyone with their head's name, use `LEFT JOIN`.
- **`reports_to` pointing at a missing row.** If a head leaves and is deleted,
  their reports' `reports_to` points at nothing. A foreign key from `reports_to`
  to `faculty_id` prevents this, and it is a good point to mention.
- **Going further up.** "Everyone above Vikram, all the way to the principal"
  needs a recursive CTE (`WITH RECURSIVE`), because the number of levels is not
  fixed. Knowing its name is enough at fresher level.

## Interview questions

::accordion
  :::accordion-item{label="Find faculty who earn more than their head (employees earning more than their manager)." icon="i-lucide-message-circle"}
  `SELECT f.full_name FROM Faculty f JOIN Faculty h ON h.faculty_id = f.reports_to WHERE f.salary > h.salary;`
  On the data above: Anjali Desai and Divya Menon.
  :::
  :::accordion-item{label="Can you write it without a join?" icon="i-lucide-message-circle"}
  Yes, with a correlated subquery:
  `WHERE f.salary > (SELECT h.salary FROM Faculty h WHERE h.faculty_id = f.reports_to)`.
  Same result. The join version is usually preferred because it can show the
  head's name too.
  :::
  :::accordion-item{label="List every faculty member with their head's name, including heads." icon="i-lucide-message-circle"}
  `LEFT JOIN Faculty h ON h.faculty_id = f.reports_to`, with
  `COALESCE(h.full_name, '(head)')` for the ones with nobody above. The self join
  lesson has the query and its output.
  :::
  :::accordion-item{label="Find the heads who have no one reporting to them." icon="i-lucide-message-circle"}
  `WHERE h.reports_to IS NULL AND NOT EXISTS (SELECT 1 FROM Faculty f WHERE f.reports_to = h.faculty_id)`.
  On this data it returns Dr. Nitin Gupta and Farhan Ali, and the honest answer
  adds that Farhan is probably missing data, not a head.
  :::
  :::accordion-item{label="Find faculty who earn more than their department's average." icon="i-lucide-message-circle"}
  `AVG(salary) OVER (PARTITION BY department_id)` in a CTE and `WHERE salary >
  dept_avg`, or a correlated subquery on `department_id`. Shown above: Dr. Meera
  Joshi and Anjali Desai in CSE, Dr. Suresh Rao and Divya Menon in ECE, Dr.
  Nitin Gupta in Mechanical.
  :::
::
