Questions answered is half the round. The other half is writing a query cold, on
a schema you have not seen, with a number that has to be right. Twelve problems,
from warm-up to the kind that ends interviews. Attempt each one in the runner
before opening the answer. Getting one wrong here costs nothing.

## 1. Warm-up: the CSE list

Every CSE student's name and city, alphabetically, with "Not given" where the
city is missing. Use the department's **name**, not its id.

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  ```sql [e1.sql]
  SELECT s.full_name, COALESCE(s.city, 'Not given') AS city
  FROM   Student s JOIN Department d ON d.department_id = s.department_id
  WHERE  d.name = 'CSE'
  ORDER BY s.full_name;
  ```

  ```text [Output]
  full_name   city
  ----------  ---------
  Anita Rao   Bhopal
  Priya Nair  Bangalore
  Sneha Iyer  Indore
  ```
  A beginner writes `WHERE department_id = 1`. It works today and breaks the day
  someone renumbers departments; filtering on the name says what you mean.
  :::
::

## 2. The count that is too high

This is supposed to show students per department, including departments with
none. It says Civil has one student. Why, and what is the fix?

```sql [e2-broken.sql]
SELECT d.name, COUNT(*) AS students
FROM   Department d LEFT JOIN Student s ON s.department_id = d.department_id
GROUP BY d.name;
```

```text [Output]
name        students
----------  --------
CSE         3
Civil       1
ECE         3
Mechanical  1
```

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  The `LEFT JOIN` keeps Civil with one row of `NULL`s, and `COUNT(*)` counts that
  row. Count a column from the right-hand table, which is `NULL` there:

  ```sql [e2.sql]
  SELECT d.name, COUNT(s.student_id) AS students
  FROM   Department d LEFT JOIN Student s ON s.department_id = d.department_id
  GROUP BY d.name
  ORDER BY students DESC, d.name;
  ```

  ```text [Output]
  name        students
  ----------  --------
  CSE         3
  ECE         3
  Mechanical  1
  Civil       0
  ```
  It is quiet because 1 is a believable number. Nobody investigates a 1.
  :::
::

## 3. The pass percentage

The pass mark is 40. What percentage of students who **sat** CS202 passed? One
query, one number, to one decimal place.

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  First version that works:

  ```sql [e3-first.sql]
  SELECT 100 * SUM(CASE WHEN marks >= 40 THEN 1 ELSE 0 END) / COUNT(marks) AS pass_pct
  FROM   ExamResult WHERE course_code = 'CS202';
  ```

  ```text [Output]
  pass_pct
  --------
  80
  ```
  It prints 80, which happens to be right only because this data divides
  evenly. `100 * 4 / 5` is integer division; with 2 passes out of 3 it would say
  66, not 66.7. The version an experienced developer writes:

  ```sql [e3.sql]
  SELECT ROUND(100.0 * SUM(CASE WHEN marks >= 40 THEN 1 ELSE 0 END) / COUNT(marks), 1) AS pass_pct,
         COUNT(marks) AS sat
  FROM   ExamResult WHERE course_code = 'CS202';
  ```

  ```text [Output]
  pass_pct  sat
  --------  ---
  80.0      5
  ```
  `100.0` forces decimal arithmetic, and showing `sat` next to the percentage
  means nobody can misread what it is a percentage of.
  :::
::

## 4. The November total that is short

The accounts office wants fees collected in November 2025. This query returns
₹42,500. The bank statement says ₹85,000. Find the missing money.

```sql [e4-broken.sql]
SELECT SUM(amount) AS november FROM FeePayment
WHERE  paid_on BETWEEN '2025-11-01' AND '2025-11-30';
```

```text [Output]
november
--------
42500
```

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  Payment 5 was at `'2025-11-30 16:45:00'`, which is after `'2025-11-30'`, so
  `BETWEEN` excludes it. Use a half-open range:

  ```sql [e4.sql]
  SELECT SUM(amount) AS november FROM FeePayment
  WHERE  paid_on >= '2025-11-01' AND paid_on < '2025-12-01';
  ```

  ```text [Output]
  november
  --------
  85000
  ```
  :::
::

## 5. Nobody unplaced?

"Students not yet placed" returns nobody. There are clearly unplaced students.
Why? Write the correct query.

```sql [e5-broken.sql]
SELECT full_name FROM Student
WHERE  student_id NOT IN (SELECT student_id FROM Placement);
```

```text [Output]
(no rows)
```

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  The TCS placement has a `NULL` `student_id`, and `NOT IN` with a `NULL` in the
  list is never true. Use `NOT EXISTS`:

  ```sql [e5.sql]
  SELECT s.full_name FROM Student s
  WHERE  NOT EXISTS (SELECT 1 FROM Placement p WHERE p.student_id = s.student_id)
  ORDER BY s.full_name;
  ```

  ```text [Output]
  full_name
  -----------
  Arjun Mehta
  Divya Menon
  Karan Patel
  Rahul Verma
  Sneha Iyer
  ```
  And then tell somebody that a placement with no student is a data problem: a
  `NOT NULL` and a foreign key on `Placement.student_id` would have refused it.
  :::
::

## 6. Fees paid per student, without the fan-out

Each student's total fees paid and number of attendance records, one row per
student, for students who have paid anything. Check Anita's number by hand
before trusting yours.

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  The first attempt joins both tables and sums:

  ```sql [e6-wrong.sql]
  SELECT s.full_name, SUM(f.amount) AS paid, COUNT(a.class_date) AS attendance_rows
  FROM   Student s
  JOIN   FeePayment f ON f.student_id = s.student_id
  LEFT JOIN Attendance a ON a.student_id = s.student_id
  GROUP BY s.full_name ORDER BY s.full_name;
  ```

  ```text [Output]
  full_name    paid    attendance_rows
  -----------  ------  ---------------
  Anita Rao    170000  4
  Divya Menon  21250   0
  Priya Nair   170000  2
  Rahul Verma  85000   2
  Sneha Iyer   85000   2
  ```
  Anita paid ₹85,000 (two payments), not ₹1,70,000; her two payments times her
  two attendance rows made four rows. Aggregate each table first:

  ```sql [e6.sql]
  SELECT s.full_name, f.paid, COALESCE(a.attendance_rows, 0) AS attendance_rows
  FROM   Student s
  JOIN  (SELECT student_id, SUM(amount) AS paid FROM FeePayment GROUP BY student_id) f
         ON f.student_id = s.student_id
  LEFT JOIN (SELECT student_id, COUNT(*) AS attendance_rows FROM Attendance GROUP BY student_id) a
         ON a.student_id = s.student_id
  ORDER BY s.full_name;
  ```

  ```text [Output]
  full_name    paid   attendance_rows
  -----------  -----  ---------------
  Anita Rao    85000  2
  Divya Menon  21250  0
  Priya Nair   85000  2
  Rahul Verma  42500  2
  Sneha Iyer   42500  2
  ```
  :::

## 7. Detained students

Attendance below 75% means detention. List every student with at least one
attendance record, their percentage, and "Detained" or "Eligible".

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  ```sql [e7.sql]
  SELECT s.full_name,
         ROUND(100.0 * SUM(a.present) / COUNT(*), 1) AS attendance_pct,
         CASE WHEN 100.0 * SUM(a.present) / COUNT(*) < 75 THEN 'Detained' ELSE 'Eligible' END AS status
  FROM   Attendance a JOIN Student s ON s.student_id = a.student_id
  GROUP BY s.student_id, s.full_name
  ORDER BY attendance_pct;
  ```

  ```text [Output]
  full_name    attendance_pct  status
  -----------  --------------  --------
  Sneha Iyer   0.0             Detained
  Rahul Verma  50.0            Detained
  Anita Rao    100.0           Eligible
  Priya Nair   100.0           Eligible
  ```
  `SUM(present)` works because `present` is 1 or 0. The `CASE` repeats the
  expression rather than the alias, which is portable to every database.
  :::
::

## 8. The second highest in CS201

The second highest **distinct** mark in CS201, and every student who got it.

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  ```sql [e8.sql]
  WITH r AS (
    SELECT s.full_name, e.marks,
           DENSE_RANK() OVER (ORDER BY e.marks DESC) AS rnk
    FROM   ExamResult e JOIN Student s ON s.student_id = e.student_id
    WHERE  e.course_code = 'CS201' AND e.marks IS NOT NULL
  )
  SELECT full_name, marks FROM r WHERE rnk = 2;
  ```

  ```text [Output]
  full_name    marks
  -----------  -----
  Anita Rao    87
  Arjun Mehta  87
  ```
  A beginner's `ORDER BY marks DESC LIMIT 1 OFFSET 1` returns only one of the
  two students on 87.
  :::
::

## 9. The duplicate email

Two students share an email. Find them, then write the `DELETE` that would keep
the lower `student_id`, and say why you would **not** run it here.

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  ```sql [e9.sql]
  SELECT student_id, full_name, email FROM Student
  WHERE  email IN (SELECT email FROM Student GROUP BY email HAVING COUNT(*) > 1)
  ORDER BY student_id;
  ```

  ```text [Output]
  student_id  full_name    email
  ----------  -----------  -----------------
  3           Priya Nair   priya@college.edu
  7           Divya Menon  priya@college.edu
  ```
  The delete would be `DELETE FROM Student WHERE student_id NOT IN (SELECT
  MIN(student_id) FROM Student GROUP BY email);`. But look at the rows: Priya Nair
  and Divya Menon are **different people** with one mistyped email. Deleting
  Divya would also orphan her fee payment and exam result. The right fix is to
  correct her email, then add a `UNIQUE` constraint. Knowing when not to run the
  delete is the point of this exercise.
  :::
::

## 10. Top two per course

The top two students in each course by marks, ties included.

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  ```sql [e10.sql]
  WITH r AS (
    SELECT e.course_code, s.full_name, e.marks,
           DENSE_RANK() OVER (PARTITION BY e.course_code ORDER BY e.marks DESC) AS rnk
    FROM   ExamResult e JOIN Student s ON s.student_id = e.student_id
    WHERE  e.marks IS NOT NULL
  )
  SELECT course_code, rnk, full_name, marks FROM r
  WHERE  rnk <= 2
  ORDER BY course_code, rnk, full_name;
  ```

  ```text [Output]
  course_code  rnk  full_name    marks
  -----------  ---  -----------  -----
  CS201        1    Priya Nair   91
  CS201        2    Anita Rao    87
  CS201        2    Arjun Mehta  87
  CS202        1    Divya Menon  81
  CS202        2    Anita Rao    72
  CS202        2    Priya Nair   72
  ```
  Three rows per course, not two, because two students share second place in
  each. If exactly two per course were required, `ROW_NUMBER` with a
  stated tie-break is the answer, and you should say which rule you chose.
  :::
::

## 11. Above their own department's average

Students whose CS201 marks are above the CS201 average **of their own
department**.

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  ```sql [e11.sql]
  WITH cs201 AS (
    SELECT s.full_name, s.department_id, e.marks,
           AVG(e.marks) OVER (PARTITION BY s.department_id) AS dept_avg
    FROM   ExamResult e JOIN Student s ON s.student_id = e.student_id
    WHERE  e.course_code = 'CS201' AND e.marks IS NOT NULL
  )
  SELECT full_name, department_id, marks, ROUND(dept_avg, 1) AS dept_avg
  FROM   cs201 WHERE marks > dept_avg
  ORDER BY department_id, marks DESC;
  ```

  ```text [Output]
  full_name   department_id  marks  dept_avg
  ----------  -------------  -----  --------
  Priya Nair  1              91     85.3
  Anita Rao   1              87     85.3
  ```
  The correlated-subquery version gives the same rows. Arjun (Mechanical) and
  Rahul (ECE) are the only CS201 results in their departments, so they equal
  their own average and are not above it.
  :::
::

## 12. The one-page report

In one query: for each department, the number of students, how many have paid
any fee, the total collected, and how many are placed. Every department must
appear, even with zeros.

::accordion
  :::accordion-item{label="Answer" icon="i-lucide-check"}
  ```sql [e12.sql]
  WITH paid AS (SELECT student_id, SUM(amount) AS amount FROM FeePayment GROUP BY student_id),
       placed AS (SELECT DISTINCT student_id FROM Placement WHERE student_id IS NOT NULL)
  SELECT d.name,
         COUNT(s.student_id)              AS students,
         COUNT(p.student_id)              AS paid_any,
         COALESCE(SUM(p.amount), 0)       AS collected,
         COUNT(pl.student_id)             AS placed
  FROM   Department d
  LEFT JOIN Student s  ON s.department_id = d.department_id
  LEFT JOIN paid p     ON p.student_id    = s.student_id
  LEFT JOIN placed pl  ON pl.student_id   = s.student_id
  GROUP BY d.department_id, d.name
  ORDER BY d.department_id;
  ```

  ```text [Output]
  name        students  paid_any  collected  placed
  ----------  --------  --------  ---------  ------
  CSE         3         3         212500     2
  ECE         3         2         63750      0
  Mechanical  1         0         0          0
  Civil       0         0         0          0
  ```
  Every rule from the track is in it: `LEFT JOIN` so empty departments stay,
  `COUNT(column)` so they show 0, pre-aggregated fees so nothing fans out,
  `DISTINCT` and `IS NOT NULL` on placements, and `COALESCE` on a `SUM` that
  would otherwise be `NULL`. Check the total against `SELECT SUM(amount) FROM
  FeePayment` before you hand it over: both should say ₹2,76,250.
  :::

## The cheat sheet

Everything the track used, one line each.

| You want | Write |
| --- | --- |
| Some columns, some rows | `SELECT a, b FROM t WHERE ...` |
| Sorted, top n | `ORDER BY x DESC, id LIMIT n` |
| Unique values | `SELECT DISTINCT x` / `COUNT(DISTINCT x)` |
| Pattern, list, range | `LIKE 'A%'`, `IN (...)`, `>= start AND < end` |
| Missing values | `IS NULL`, `COALESCE(x, default)`, `NULLIF(y, 0)` |
| One number | `COUNT(*)`, `SUM`, `AVG`, `MIN`, `MAX` |
| One number per group | `GROUP BY g`, filter groups with `HAVING` |
| Count some rows per group | `SUM(CASE WHEN ... THEN 1 ELSE 0 END)` |
| Columns from two tables | `JOIN ... ON` (keep unmatched: `LEFT JOIN`) |
| Rows with no match | `NOT EXISTS (SELECT 1 ... )` |
| A table and itself | `FROM t a JOIN t b ON b.id = a.parent_id` |
| An answer that needs an answer | Subquery, or `WITH name AS (...)` |
| Stack two results | `UNION ALL` (or `UNION` to de-duplicate) |
| Refuse bad data | `NOT NULL`, `UNIQUE`, `CHECK`, `FOREIGN KEY` |
| Save a query | `CREATE VIEW v AS SELECT ...` |
| Make a lookup fast | `CREATE INDEX i ON t (col)`, check with `EXPLAIN` |
| Several writes as one | `BEGIN; ... COMMIT;` or `ROLLBACK;` |
| Rank within groups | `DENSE_RANK() OVER (PARTITION BY g ORDER BY x DESC)` |
| Compare with previous row | `LAG(x) OVER (PARTITION BY g ORDER BY d)` |
| Labels from numbers | `CASE WHEN ... THEN ... ELSE ... END` |
| Nth highest | `DENSE_RANK` then `WHERE rnk = N` |
| Duplicates | `GROUP BY cols HAVING COUNT(*) > 1` |
