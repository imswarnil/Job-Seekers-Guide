The report is full of numbers and the principal wants words: grade A, B or C
from the marks, "detained" beside anyone under 75% attendance. `CASE` is SQL's
if-then-else, and it works anywhere a value can go.

## Why this matters in a job

Every report turns numbers into categories: grades, pass and fail, fee status,
"high", "medium" and "low". `CASE` inside `SUM` or `COUNT` also turns rows into
columns (a pivot), which is how one query produces a summary table with a
column per status. In interviews, "convert marks into grades" is a common
written question, and "count passes and fails per course in one query" is the
follow-up that checks you know the `SUM(CASE ...)` pattern.

## The grading rule, written as SQL

Your college's grading rule is already a `CASE` written on paper: "90 and above
is O, 75 and above is A, 60 and above is B, 40 and above is C, otherwise F". The
important words are "and above": the rules are checked **in order**, and the
**first** one that is true wins. A student with 92 is also above 75 and 60, but
they get O because that rule comes first.

::flow{numbered direction="vertical" caption="How CASE picks a result for marks = 78."}
  :::flow-step{label="WHEN marks >= 90 THEN 'O'" icon="i-lucide-x"}
  False. Try the next.
  :::
  :::flow-step{label="WHEN marks >= 75 THEN 'A'" icon="i-lucide-check" highlight}
  True. The result is 'A', and the rest are never checked.
  :::
  :::flow-step{label="ELSE 'F'" icon="i-lucide-minus"}
  Only used when no WHEN is true.
  :::
::

## Syntax

Two forms. The **searched** form tests any condition and is the one you will use
most. The **simple** form compares one expression with a list of values.

```sql [case-syntax.sql]
-- Searched CASE
CASE
  WHEN condition1 THEN result1
  WHEN condition2 THEN result2
  ELSE default_result
END

-- Simple CASE
CASE expression
  WHEN value1 THEN result1
  WHEN value2 THEN result2
  ELSE default_result
END
```

::runner{lang="sql"}
```sql [grades.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 'Anita Rao', 1, 92), (2, 'Rahul Verma', 2, 64), (3, 'Priya Nair', 1, 78),
  (4, 'Arjun Mehta', 3, 38), (5, 'Sneha Iyer', 1, 45), (6, 'Karan Patel', 2, NULL);

SELECT full_name, marks,
       CASE
         WHEN marks >= 90 THEN 'O'
         WHEN marks >= 75 THEN 'A'
         WHEN marks >= 60 THEN 'B'
         WHEN marks >= 40 THEN 'C'
         WHEN marks IS NULL THEN 'Absent'
         ELSE 'F'
       END AS grade,
       CASE department_id          -- simple CASE
         WHEN 1 THEN 'CSE'
         WHEN 2 THEN 'ECE'
         ELSE 'Other'
       END AS department
FROM   ExamResult
ORDER BY marks DESC;
```
::

```text [Output]
full_name    marks  grade   department
-----------  -----  ------  ----------
Anita Rao    92     O       CSE
Priya Nair   78     A       CSE
Rahul Verma  64     B       ECE
Sneha Iyer   45     C       CSE
Arjun Mehta  38     F       Other
Karan Patel  NULL   Absent  ECE
```

Karan's `NULL` marks would fail every `>=` comparison (each is `UNKNOWN`), so
without the `IS NULL` branch he would have fallen through to `ELSE 'F'`: an
absent student recorded as failed. Put the `NULL` check in on purpose.

## CASE inside aggregates: turning rows into columns

`CASE` returns 1 for the rows you want to count and 0 for the rest; `SUM` adds
them up. One query, one row per course, one column per category:

::runner{lang="sql"}
```sql [pass-fail-per-course.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, student_id INTEGER, course_id INTEGER, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 1, 101, 92), (2, 2, 101, 64), (3, 3, 101, 38), (4, 4, 101, NULL),
  (5, 1, 102, 78), (6, 2, 102, 35), (7, 3, 102, 31), (8, 4, 102, 55);

SELECT course_id,
       COUNT(*)                                          AS students,
       SUM(CASE WHEN marks >= 40 THEN 1 ELSE 0 END)      AS passed,
       SUM(CASE WHEN marks <  40 THEN 1 ELSE 0 END)      AS failed,
       SUM(CASE WHEN marks IS NULL THEN 1 ELSE 0 END)    AS absent,
       ROUND(100.0 * SUM(CASE WHEN marks >= 40 THEN 1 ELSE 0 END)
             / COUNT(marks), 1)                          AS pass_pct
FROM   ExamResult
GROUP BY course_id;
```
::

```text [Output]
course_id  students  passed  failed  absent  pass_pct
---------  --------  ------  ------  ------  --------
101        4         2       1       1       66.7
102        4         2       2       0       50.0
```

Passed, failed and absent add up to the total, because the `NULL` branch is
counted on purpose, and the pass percentage is over students who sat the exam
(`COUNT(marks)`), not over everyone. PostgreSQL and SQLite also accept
`COUNT(*) FILTER (WHERE marks >= 40)`, which says the same thing.

## CASE in ORDER BY and UPDATE

::runner{lang="sql"}
```sql [case-order-update.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, fee_status TEXT, attendance_pct REAL, remark TEXT);
INSERT INTO Student VALUES
  (1, 'Anita Rao', 'PAID', 92, NULL), (2, 'Rahul Verma', 'OVERDUE', 68, NULL),
  (3, 'Priya Nair', 'PARTIAL', 81, NULL), (4, 'Arjun Mehta', 'OVERDUE', 74.5, NULL);

-- A custom sort order: overdue first, then partial, then paid.
SELECT full_name, fee_status FROM Student
ORDER BY CASE fee_status WHEN 'OVERDUE' THEN 1 WHEN 'PARTIAL' THEN 2 ELSE 3 END,
         full_name;

-- Set a different value per row in one UPDATE.
UPDATE Student
SET    remark = CASE WHEN attendance_pct < 75 THEN 'Detained' ELSE 'Eligible' END;

SELECT full_name, attendance_pct, remark FROM Student;
```
::

```text [Output]
full_name    fee_status
-----------  ----------
Arjun Mehta  OVERDUE
Rahul Verma  OVERDUE
Priya Nair   PARTIAL
Anita Rao    PAID

full_name    attendance_pct  remark
-----------  --------------  --------
Anita Rao    92.0            Eligible
Rahul Verma  68.0            Detained
Priya Nair   81.0            Eligible
Arjun Mehta  74.5            Detained
```

One `UPDATE` with a `CASE` replaces two `UPDATE`s with opposite `WHERE`s, and
cannot leave half the rows done if something fails between them.

## Real use case

The examination controller's end-of-semester sheet has one line per department,
with the number of students in each grade band. It is `GROUP BY` for the rows
and `CASE` for the columns, the pivot shape almost every summary report takes:

::runner{lang="sql"}
```sql [grade-distribution.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, department TEXT, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 'CSE', 92), (2, 'CSE', 78), (3, 'CSE', 45), (4, 'CSE', 81), (5, 'CSE', 38),
  (6, 'ECE', 64), (7, 'ECE', 91), (8, 'ECE', 55), (9, 'ECE', 72),
  (10, 'Mechanical', 38), (11, 'Mechanical', 61);

SELECT department,
       SUM(CASE WHEN marks >= 90                THEN 1 ELSE 0 END) AS o_grade,
       SUM(CASE WHEN marks >= 75 AND marks < 90 THEN 1 ELSE 0 END) AS a_grade,
       SUM(CASE WHEN marks >= 60 AND marks < 75 THEN 1 ELSE 0 END) AS b_grade,
       SUM(CASE WHEN marks >= 40 AND marks < 60 THEN 1 ELSE 0 END) AS c_grade,
       SUM(CASE WHEN marks < 40                 THEN 1 ELSE 0 END) AS failed
FROM   ExamResult
GROUP BY department
ORDER BY department;
```
::

```text [Output]
department  o_grade  a_grade  b_grade  c_grade  failed
----------  -------  -------  -------  -------  ------
CSE         1        2        0        1        1
ECE         1        0        2        1        0
Mechanical  0        0        1        0        1
```

In the reporting work I did at Twilio, this "rows into columns" step was exactly
where the business rules hid (which deals count as won, which count as late), so
it is worth being able to write it by hand and read it in someone else's query.

## What confuses people here

- **Order of `WHEN`s matters.** Put `WHEN marks >= 40 THEN 'C'` first and every
  student above 40 gets C. The first true branch wins; the rest are skipped.
- **No `ELSE` means `NULL`.** If nothing matches and there is no `ELSE`, the
  result is `NULL`, which then vanishes from counts and comparisons.
- **The simple form cannot test `NULL`.** `CASE marks WHEN NULL THEN ...` never
  matches, because it is `marks = NULL`. Use the searched form with `IS NULL`.
- **Every branch should return the same type.** Mixing `'A'` and `0` works in
  SQLite and MySQL and fails in PostgreSQL.
- **`CASE` is an expression, not a statement.** It produces a value inside a
  query. Procedural `IF ... THEN` blocks belong to stored procedures, which are a
  different topic.

## Interview questions

::accordion
  :::accordion-item{label="Write a query to assign grades from marks." icon="i-lucide-message-circle"}
  A searched `CASE` with conditions in descending order and an explicit `NULL`
  branch: `CASE WHEN marks >= 90 THEN 'O' WHEN marks >= 75 THEN 'A' ... WHEN
  marks IS NULL THEN 'Absent' ELSE 'F' END`. The full query and its output are in
  the Syntax section above.
  :::
  :::accordion-item{label="Count passed and failed students per course in one query." icon="i-lucide-message-circle"}
  `SUM(CASE WHEN marks >= 40 THEN 1 ELSE 0 END)` and the same for `< 40`,
  grouped by `course_id`. Mention that `NULL` marks fall into neither, so count
  them separately if the totals must add up.
  :::
  :::accordion-item{label="Simple CASE vs searched CASE?" icon="i-lucide-message-circle"}
  Simple `CASE x WHEN 1 THEN ...` compares one expression with values for
  equality. Searched `CASE WHEN condition THEN ...` evaluates any condition, so
  it handles ranges and `IS NULL`. Every simple `CASE` can be rewritten as a
  searched one, not the other way round.
  :::
  :::accordion-item{label="What happens if no WHEN matches and there is no ELSE?" icon="i-lucide-message-circle"}
  The `CASE` returns `NULL`.
  :::
  :::accordion-item{label="How do you swap two values in a column in one UPDATE?" icon="i-lucide-message-circle"}
  A classic: swap every 'M' and 'F', or here every 'ODD' and 'EVEN' semester
  label.
  ```sql [swap.sql]
  CREATE TABLE Enrolment (student_id INTEGER, semester TEXT);
  INSERT INTO Enrolment VALUES (1, 'ODD'), (2, 'EVEN'), (3, 'ODD');

  UPDATE Enrolment
  SET    semester = CASE semester WHEN 'ODD' THEN 'EVEN' WHEN 'EVEN' THEN 'ODD' END;

  SELECT * FROM Enrolment;
  ```

  ```text [Output]
  student_id  semester
  ----------  --------
  1           EVEN
  2           ODD
  3           EVEN
  ```
  One statement, so no row is swapped twice.
  :::
::
