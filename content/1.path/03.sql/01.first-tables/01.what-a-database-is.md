At the end of DSA your Java program could hold a thousand students in an
`ArrayList` and find any one of them through a `HashMap` in a single step. Then
the program stopped, and every one of those students was gone. This lesson is
about where data goes so that it outlives the program.

## Why this matters in a job

Every company you will interview at keeps its data in a database: the college
you graduated from keeps marks in one, your bank keeps your balance in one, and
the startup that hires you will keep its customers in one. Your Java code comes
and goes; the database is the thing that has to be right.

In the walk-ins I went to in 2018, the SQL part of the technical round often
opened with the easiest question of the day: "What is a database? What is a
DBMS? What is the difference between a DBMS and an RDBMS?" It is easy, and a
surprising number of people answer it vaguely. Answer it crisply and the rest
of the round starts on a good note.

## Data, a database, a DBMS

Think of the exam cell of your college.

::flow{direction="horizontal" caption="Four words that interviewers expect you to separate."}
  :::flow-step{label="Data" icon="i-lucide-file-digit"}
  Raw facts: "Anita Rao", "CSE", "87".
  :::
  :::flow-step{label="Database" icon="i-lucide-archive"}
  An organised collection of related data: every student and every mark.
  :::
  :::flow-step{label="DBMS" icon="i-lucide-server" highlight}
  The software that stores it, guards it and answers questions about it.
  :::
  :::flow-step{label="SQL" icon="i-lucide-terminal"}
  The language you use to talk to that software.
  :::
::

- **Data** is raw facts. "87" on its own means nothing.
- **Information** is data with meaning: "Anita Rao scored 87 in Data Structures".
- A **database** is an organised collection of related data, stored so it can
  be found again. The exam cell's register is a database, even on paper.
- A **DBMS** (database management system) is the software that stores the
  database on disk and controls every read and write: who may see what, what
  happens when two people change the same row, what happens when the power goes.
  MySQL, PostgreSQL, Oracle, SQL Server and SQLite are all DBMSs.
- An **RDBMS** (relational DBMS) is a DBMS that stores data in **tables** that
  relate to each other through shared values. Every DBMS named above is
  relational.
- **SQL** (Structured Query Language, said "sequel" or "S-Q-L", both are fine)
  is the language you use to create tables, put data in, and ask questions.

## A table, a row, a column

A relational database stores data in tables. A table looks like a spreadsheet,
but it is stricter, and the strictness is the point.

| student_id | full_name | city | department |
| --- | --- | --- | --- |
| 1 | Anita Rao | Bhopal | CSE |
| 2 | Rahul Verma | Patna | ECE |
| 3 | Priya Nair | Bangalore | CSE |

- A **column** (also called a field or attribute) is one kind of fact, with a
  name and a type. `city` holds text, and only text.
- A **row** (also called a record or tuple) is one thing: one student.
- A **primary key** is a column whose value is different for every row, so
  each row can be named exactly. Here it is `student_id`. Two students can both
  be called Rahul Verma; they cannot both be student 2.

::note
You will meet two sets of words for the same things: table, row, column
(everyday SQL) and relation, tuple, attribute (the theory, in the DBMS track).
Interviewers use both. They mean the same thing.
::

## How it works

You send the DBMS a SQL statement, it does the work, and it sends back either a
result table or a message. Three statements are enough to see the whole cycle:
`CREATE TABLE` makes an empty table, `INSERT` puts rows in, `SELECT` asks a
question.

::runner{lang="sql"}
```sql [first-table.sql]
CREATE TABLE Student (
  student_id  INTEGER PRIMARY KEY,
  full_name   TEXT,
  city        TEXT,
  department  TEXT
);

INSERT INTO Student VALUES (1, 'Anita Rao',   'Bhopal',    'CSE');
INSERT INTO Student VALUES (2, 'Rahul Verma', 'Patna',     'ECE');
INSERT INTO Student VALUES (3, 'Priya Nair',  'Bangalore', 'CSE');

SELECT full_name, city
FROM   Student
WHERE  department = 'CSE';
```
::

```text [Output]
full_name   city
----------  ---------
Anita Rao   Bhopal
Priya Nair  Bangalore
```

Read the `SELECT` out loud and it is nearly English: "select the full name and
city from Student where the department is CSE". That readability is deliberate,
and it is why SQL has lasted since the 1970s.

::tip
Press Run, then change `'CSE'` to `'ECE'` and run it again. The runner builds a
fresh, empty database every time, which is why every example in this track
creates its own tables first. Nothing you do here can break anything.
::

## The databases you will hear about

| DBMS | Where you meet it | Cost |
| --- | --- | --- |
| **MySQL** | Most Indian startups and service companies, and most institute courses | Free (open source) |
| **PostgreSQL** | Product companies and newer startups | Free (open source) |
| **Oracle** | Banks, large enterprises, many service-company projects | Paid |
| **SQL Server** | Companies built on Microsoft tools | Paid, with a free edition |
| **SQLite** | Inside phones, browsers and apps; the runner on this site | Free, a single file |

The SQL in this track is standard SQL that runs on all of them. Where one of
them differs (the way you limit rows, the way you delete everything), the lesson
says which.

## Real use case

A college's exam cell needs to publish the list of CSE students from Bhopal
before a scholarship deadline. Without a database, somebody opens a register or
a spreadsheet and copies names by hand. With one, it is a single question, and
the answer is right every time it is asked:

::runner{lang="sql"}
```sql [scholarship-list.sql]
CREATE TABLE Student (
  student_id  INTEGER PRIMARY KEY,
  full_name   TEXT,
  city        TEXT,
  department  TEXT
);

INSERT INTO Student VALUES
  (1, 'Anita Rao',    'Bhopal',    'CSE'),
  (2, 'Rahul Verma',  'Patna',     'ECE'),
  (3, 'Priya Nair',   'Bangalore', 'CSE'),
  (4, 'Arjun Mehta',  'Bhopal',    'CSE'),
  (5, 'Sneha Iyer',   'Bhopal',    'Civil');

SELECT student_id, full_name
FROM   Student
WHERE  department = 'CSE' AND city = 'Bhopal';
```
::

```text [Output]
student_id  full_name
----------  -----------
1           Anita Rao
4           Arjun Mehta
```

At Accenture I worked on Salesforce, which keeps a company's customers and
deals in a database behind its screens. Every report a manager looked at was a
query like this one underneath, written in SOQL, Salesforce's own dialect of
SQL. Different product, same idea.

## What confuses people here

::compare{caption="Two things beginners mix up in the first week."}
  :::compare-side{label="What people think" verdict="wrong"}
  "SQL is a database." "MySQL is a language."
  :::
  :::compare-side{label="What is true" verdict="right"}
  SQL is the **language**. MySQL is a **DBMS**, a piece of software that
  understands SQL. You write SQL; MySQL runs it.
  :::
::

- **A spreadsheet is not a database.** It lets you type anything in any cell,
  it has no idea two people are editing it, and it cannot answer "which
  department has the most students with a backlog" without you building the
  answer by hand. The first lesson of the DBMS track is entirely about this.
- **SQL keywords are not case-sensitive.** `select` and `SELECT` are the same.
  Writing keywords in capitals is a convention that makes queries easier to
  read, and every example here follows it. The **values** inside quotes can be
  case-sensitive, depending on the database.
- **Text goes in single quotes.** `'CSE'`, never `"CSE"`. Double quotes mean a
  column or table name in standard SQL.

## Interview questions

::accordion
  :::accordion-item{label="What is a database, and what is a DBMS?" icon="i-lucide-message-circle"}
  A database is an organised collection of related data. A DBMS is the software
  that stores that data and controls access to it: it runs queries, enforces
  rules, handles many users at once and recovers after a crash. MySQL and Oracle
  are DBMSs; the college's student records are a database.
  :::
  :::accordion-item{label="What is the difference between a DBMS and an RDBMS?" icon="i-lucide-message-circle"}
  An RDBMS is a DBMS that stores data as related tables and enforces the
  relationships between them with keys. Every RDBMS is a DBMS; not every DBMS is
  relational (a document store such as MongoDB is not). In practice, "the
  database" at almost every job is an RDBMS.
  :::
  :::accordion-item{label="What is SQL? Is it a programming language?" icon="i-lucide-message-circle"}
  SQL is a declarative query language: you describe the result you want and the
  database decides how to get it. It is not a general-purpose programming
  language like Java. `SELECT full_name FROM Student WHERE city = 'Bhopal'` says
  what, never how.
  :::
  :::accordion-item{label="What is a primary key, in one line?" icon="i-lucide-message-circle"}
  A column (or set of columns) whose value is unique and never empty for every
  row, so every row can be identified exactly. `student_id` is the primary key
  of `Student`.
  :::
  :::accordion-item{label="Name some popular RDBMSs." icon="i-lucide-message-circle"}
  MySQL, PostgreSQL, Oracle, Microsoft SQL Server and SQLite. Say which one you
  practised on, and that the SQL you know is standard enough to move between
  them.
  :::
::
