One number for the whole table was the last lesson. The head of department
wants one number per course, and the principal wants one per department.
`GROUP BY` is how rows become one answer per group.

## Why this matters in a job

Every report, dashboard and analytics question is a `GROUP BY` underneath:
students per department, fees per month, average marks per course, placements
per company. At Twilio almost every query I wrote for the GTM team ended in a
`GROUP BY`. In interviews, "what is the difference between `WHERE` and
`HAVING`?" is close to a certainty, and "find departments with more than N
students" is the query that tests it.

## Sorting answer sheets into piles

Picture the exam cell on result day with a stack of answer sheets. Somebody
sorts them into piles, one pile per course. Then, for each pile, they count the
sheets and work out the average. `GROUP BY course_id` is making the piles. The
aggregate functions are what you do to each pile. One pile becomes one row of
output.

::flow{direction="horizontal" caption="Seven rows in, two piles, two rows out."}
  :::flow-step{label="Rows" icon="i-lucide-rows-3"}
  Seven results, mixed courses.
  :::
  :::flow-step{label="GROUP BY course_id" icon="i-lucide-layers" highlight}
  Pile 101 (four sheets), pile 102 (three sheets).
  :::
  :::flow-step{label="Aggregate each pile" icon="i-lucide-sigma"}
  COUNT, AVG, MAX per pile.
  :::
  :::flow-step{label="One row per pile" icon="i-lucide-table"}
  Two rows.
  :::
::

## Syntax

```sql [group-by-syntax.sql]
SELECT   group_column, AGGREGATE(col)
FROM     table_name
WHERE    row_condition          -- removes rows, before grouping
GROUP BY group_column
HAVING   group_condition        -- removes groups, after grouping
ORDER BY ...;
```

::runner{lang="sql"}
```sql [per-course.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, student_id INTEGER, course_id INTEGER, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 1, 101, 87), (2, 2, 101, 64), (3, 3, 101, 91), (4, 4, 101, 35),
  (5, 1, 102, 72), (6, 2, 102, 38), (7, 3, 102, 91);

SELECT   course_id,
         COUNT(*)              AS students,
         ROUND(AVG(marks), 1)  AS average,
         MAX(marks)            AS highest
FROM     ExamResult
GROUP BY course_id;
```
::

```text [Output]
course_id  students  average  highest
---------  --------  -------  -------
101        4         69.3     91
102        3         67.0     91
```

## The one rule

**Every column in `SELECT` must either be in `GROUP BY` or be inside an
aggregate function.**

The reason is what a group is. Course 101's pile has four students in it. If
you ask for `student_id` next to `COUNT(*)`, which of the four do you mean?
There is no answer, so standard SQL refuses:

```sql [illegal.sql]
-- PostgreSQL
SELECT course_id, student_id, COUNT(*)
FROM   ExamResult
GROUP BY course_id;
```

```text [Output (PostgreSQL 16)]
ERROR:  column "examresult.student_id" must appear in the GROUP BY clause
        or be used in an aggregate function
```

::warning{icon="i-lucide-alert-triangle"}
SQLite, and MySQL with its old default settings, **accept** that query and
return the `student_id` from some row in each group. It looks like an answer and
it is not one. Never rely on it; in an interview, state the rule.
::

## WHERE against HAVING

Both filter. They filter different things at different times, and the
evaluation order from the "SELECT and WHERE" lesson explains everything:

::compare{caption="Rows before grouping, groups after."}
  :::compare-side{label="WHERE" verdict="right"}
  Removes **rows**, before `GROUP BY`. Cannot see an aggregate.
  `WHERE marks IS NOT NULL` keeps absentees out of every pile.
  :::
  :::compare-side{label="HAVING" verdict="right"}
  Removes **groups**, after `GROUP BY`. Can use aggregates.
  `HAVING AVG(marks) < 60` keeps only the courses doing badly.
  :::
::

::runner{lang="sql"}
```sql [where-and-having.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER, admission_year INTEGER);
INSERT INTO Student VALUES
  (1, 'Anita Rao', 1, 2024), (2, 'Rahul Verma', 2, 2024), (3, 'Priya Nair', 1, 2025),
  (4, 'Arjun Mehta', 3, 2024), (5, 'Sneha Iyer', 1, 2024), (6, 'Karan Patel', 2, 2024),
  (7, 'Divya Menon', 1, 2024), (8, 'Rohit Kumar', 2, 2025);

-- Departments with more than 2 students admitted in 2024.
SELECT   department_id, COUNT(*) AS students_2024
FROM     Student
WHERE    admission_year = 2024        -- rows: only 2024 admissions
GROUP BY department_id
HAVING   COUNT(*) > 2                 -- groups: only big enough departments
ORDER BY students_2024 DESC;
```
::

```text [Output]
department_id  students_2024
-------------  -------------
1              3
```

Trying to put the count in `WHERE` fails, because at the time `WHERE` runs
there are no groups and no counts:

::runner{lang="sql"}
```sql [aggregate-in-where.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, department_id INTEGER);
INSERT INTO Student VALUES (1, 1), (2, 2), (3, 1);

SELECT department_id FROM Student
WHERE  COUNT(*) > 1
GROUP BY department_id;
```
::

```text [Output]
Error: misuse of aggregate: COUNT()
```

::tip
A condition that could go in either (`department_id = 1`, say) belongs in
`WHERE`: it removes rows before grouping, so there is less to group. Being able
to say why is exactly what the interviewer is checking.
::

## Grouping by more than one column

One group per **combination** that actually occurs:

::runner{lang="sql"}
```sql [two-columns.sql]
CREATE TABLE Student (student_id INTEGER PRIMARY KEY, full_name TEXT, department_id INTEGER, admission_year INTEGER);
INSERT INTO Student VALUES
  (1, 'Anita Rao', 1, 2024), (2, 'Rahul Verma', 2, 2024), (3, 'Priya Nair', 1, 2025),
  (4, 'Arjun Mehta', 3, 2024), (5, 'Sneha Iyer', 1, 2024), (6, 'Karan Patel', 2, 2024),
  (7, 'Divya Menon', 1, 2024), (8, 'Rohit Kumar', 2, 2025);

SELECT   department_id, admission_year, COUNT(*) AS students
FROM     Student
GROUP BY department_id, admission_year
ORDER BY department_id, admission_year;
```
::

```text [Output]
department_id  admission_year  students
-------------  --------------  --------
1              2024            3
1              2025            1
2              2024            2
2              2025            1
3              2024            1
```

Department 3 has no 2025 row at all, rather than a row with 0. A report that
expects every department in every year will be missing lines; the joins chapter
shows how to fill them in.

## Real use case

The principal's monthly review has a slide titled "courses that need attention":
every course where the average is below 60 or more than a quarter of students
failed. It needs `WHERE` (ignore absentees), `GROUP BY` (per course), conditional
counting and `HAVING`:

::runner{lang="sql"}
```sql [courses-needing-attention.sql]
CREATE TABLE ExamResult (result_id INTEGER PRIMARY KEY, student_id INTEGER, course_id INTEGER, marks INTEGER);
INSERT INTO ExamResult VALUES
  (1, 1, 101, 87), (2, 2, 101, 64), (3, 3, 101, 91), (4, 4, 101, 35),
  (5, 1, 102, 72), (6, 2, 102, 38), (7, 3, 102, 51), (8, 4, 102, 33),
  (9, 1, 103, 58), (10, 2, 103, 55), (11, 3, 103, NULL), (12, 4, 103, 61);

SELECT   course_id,
         COUNT(*)                                          AS sat,
         ROUND(AVG(marks), 1)                              AS average,
         SUM(CASE WHEN marks < 40 THEN 1 ELSE 0 END)       AS failed
FROM     ExamResult
WHERE    marks IS NOT NULL
GROUP BY course_id
HAVING   AVG(marks) < 60
     OR  SUM(CASE WHEN marks < 40 THEN 1 ELSE 0 END) * 4 > COUNT(*)
ORDER BY average;
```
::

```text [Output]
course_id  sat  average  failed
---------  ---  -------  ------
102        4    48.5     2
103        3    58.0     0
```

Course 101 is not on the slide: one fail in four is exactly a quarter, not more.
The `SUM(CASE WHEN ... THEN 1 ELSE 0 END)` pattern counts only the rows that meet
a condition; `CASE` has its own lesson later in this track.

## What confuses people here

- **`GROUP BY` does not sort.** It used to in some old MySQL versions, and
  people came to rely on it. If you want an order, write `ORDER BY`.
- **An alias in `HAVING`.** `HAVING students > 2` works in MySQL and SQLite and
  fails in PostgreSQL and SQL Server, because `SELECT` runs after `HAVING`.
  Repeat the aggregate to be safe.
- **`NULL` forms its own group.** Students with no department all land in one
  group labelled `NULL`.
- **`COUNT(*)` in a group counts rows in that pile**, including rows where the
  column you care about is `NULL`. Use `COUNT(marks)` to count marked papers.

## Interview questions

::accordion
  :::accordion-item{label="What is the difference between WHERE and HAVING?" icon="i-lucide-message-circle"}
  `WHERE` filters rows before grouping and cannot use aggregates. `HAVING`
  filters groups after grouping and can. Then explain it from the evaluation
  order (`FROM`, `WHERE`, `GROUP BY`, `HAVING`, `SELECT`), and add that a
  condition that could go in either belongs in `WHERE`, because it reduces the
  rows before the grouping work.
  :::
  :::accordion-item{label="Find departments with more than 2 students." icon="i-lucide-message-circle"}
  ```sql [big-departments.sql]
  SELECT department_id, COUNT(*) AS students
  FROM   Student
  GROUP BY department_id
  HAVING COUNT(*) > 2;
  ```

  ```text [Output (on the eight students above)]
  department_id  students
  -------------  --------
  1              4
  2              3
  ```
  :::
  :::accordion-item{label="Why must non-aggregated columns appear in GROUP BY?" icon="i-lucide-message-circle"}
  Because each output row is a group, and a group has many values for any
  column that is not grouped. "The student_id of course 101" has four possible
  answers. Either group by it, or say which one you want with an aggregate such
  as `MAX(student_id)`.
  :::
  :::accordion-item{label="Can you use HAVING without GROUP BY?" icon="i-lucide-message-circle"}
  Yes: the whole table is then one group.
  `SELECT COUNT(*) FROM Student HAVING COUNT(*) > 5` returns the count only if
  there are more than five students, otherwise no row at all. Rare, and a good
  follow-up to know.
  :::
  :::accordion-item{label="Count the students admitted each year, per department." icon="i-lucide-message-circle"}
  `GROUP BY department_id, admission_year`: one row per combination that
  exists. The output is shown in "Grouping by more than one column" above.
  :::
::
