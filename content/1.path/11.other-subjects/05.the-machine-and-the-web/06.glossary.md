## How software gets made

| Word | Means |
| --- | --- |
| **SDLC** | Software Development Life Cycle: requirements, design, implementation, testing, deployment, maintenance |
| **SRS** | Software Requirements Specification, the document that states what the system must do |
| **Waterfall** | Each SDLC phase once, in order, no going back |
| **V-model** | Waterfall with a matching test level planned for each build phase |
| **Iterative / incremental** | Improve the same piece in rounds / add new pieces one at a time |
| **Spiral** | Iterative loops, each starting with risk analysis |
| **Agile** | Values for delivering working software in small increments and welcoming change |
| **Scrum** | A framework for Agile: three roles, five events, three artefacts |
| **Product Owner** | Owns and orders the product backlog; decides what is built |
| **Scrum Master** | Facilitates the process and removes blockers; not a manager |
| **Sprint** | A fixed time box, usually two weeks, ending in a working increment |
| **Product / sprint backlog** | All wanted work in order / the part committed to this sprint |
| **User story** | "As a …, I want …, so that …", with acceptance criteria |
| **Story point** | A relative estimate of effort, not hours |
| **Velocity** | Points completed per sprint, averaged, used to forecast |
| **Stand-up** | The 15-minute daily sync: yesterday, today, blockers |
| **Retrospective** | The team's review of its own process at the end of a sprint |
| **Definition of Done** | The checklist every item must meet to count as finished |
| **Kanban** | A flow-based method with a board and work-in-progress limits, no sprints |
| **Jira** | Atlassian's tool for tracking stories and bugs on a board |

## Testing

| Word | Means |
| --- | --- |
| **Unit / integration / system / UAT** | One component / components together / the whole system / the users accept it |
| **Functional / non-functional** | What it does / how well: performance, security, usability |
| **Smoke test** | Broad, shallow check that a new build is testable at all |
| **Sanity test** | Narrow check that one fix or change works |
| **Regression test** | Rerun existing tests to check nothing that worked is broken |
| **Retesting** | Rerun the failed test to confirm the bug is fixed |
| **Black box / white box** | Test without seeing the code / with knowledge of it |
| **STLC** | Software Testing Life Cycle: analysis, planning, design, environment, execution, closure |
| **RTM** | Requirement traceability matrix, linking requirements to test cases |
| **Test case / scenario / script** | Detailed steps and data / one-line what to test / automated code |
| **Severity / priority** | How badly it hurts / how soon to fix |
| **Boundary value analysis** | Test at and around the edges of a range |
| **Equivalence partitioning** | Test one value from each group that behaves the same |
| **Verification / validation** | Building it right (reviews) / building the right thing (running it) |

## Git and GitHub

| Word | Means |
| --- | --- |
| **Version control** | A system that records every change so any version can be recovered |
| **Repository** | A folder whose history Git tracks, stored in `.git` |
| **Commit** | A saved snapshot with a message, author and hash |
| **Staging area** | Where `git add` puts changes chosen for the next commit |
| **Branch** | A movable pointer to a commit; a separate line of work |
| **HEAD** | Where you are now |
| **Merge / fast-forward** | Combine branches / move the pointer when nothing diverged |
| **Merge conflict** | Both branches changed the same lines; you choose |
| **Rebase** | Replay commits on top of another branch, rewriting them |
| **Remote / origin** | A copy elsewhere / the conventional name for it |
| **Push / fetch / pull** | Send commits / download without merging / download and merge |
| **Pull request** | A proposal to merge a branch, with review |
| **Fork / clone** | Your copy on GitHub / a copy on your machine |
| **.gitignore** | Patterns Git should not track |
| **Revert / reset** | Undo with a new commit / move the branch back |
| **Stash** | Put uncommitted changes aside |
| **Reflog** | The record of where HEAD has been, for recovery |

## Linux

| Word | Means |
| --- | --- |
| **Shell** | The program that reads your commands and runs them (bash, zsh) |
| **Root (`/`) / root user** | The top of the file tree / the administrator account |
| **Absolute / relative path** | From `/` / from where you are |
| **Permissions `rwx`** | Read (4), write (2), execute (1), for owner, group, others |
| **`chmod` / `chown` / `sudo`** | Change permissions / change owner / run as root |
| **Pipe `\|`** | Send one command's output into the next |
| **Redirect `>` / `>>`** | Write output to a file / append to it |
| **Process / PID** | A running program / its number |
| **SIGTERM / SIGKILL** | Please stop (`kill`) / stop now (`kill -9`) |

## The machine and the web

| Word | Means |
| --- | --- |
| **Cloud computing** | Renting computing over the internet, paid by use |
| **IaaS / PaaS / SaaS** | Rent machines / rent a platform for your code / use finished software |
| **Region / availability zone** | A geographic area / an isolated data centre inside it |
| **Scalability / elasticity** | Can grow / grows and shrinks automatically |
| **DNS** | Translates a domain name into an IP address |
| **TCP / TLS** | Reliable connection / encryption layer for HTTPS |
| **HTTP status code** | 2xx worked, 3xx moved, 4xx client error, 5xx server error |
| **Compiler / interpreter** | Translates all first / translates and runs line by line |
| **Bytecode / JVM / JIT** | Java's portable instructions / the machine that runs them / compiling hot code at runtime |
| **CPU / ALU / control unit** | The processor / its arithmetic part / its coordinating part |
| **Register / cache / RAM** | Fastest slots in the CPU / fast memory near it / main memory |
| **Volatile** | Loses contents without power |
| **Bit / byte** | One binary digit / eight bits |
| **Two's complement** | Negative numbers as inverted bits plus one |

## The pairs people confuse

::accordion
  :::accordion-item{label="Smoke versus sanity"}
  Smoke is broad and on a new build ("can we test this at all?"). Sanity is
  narrow and on one change ("does this fix work?").
  :::
  :::accordion-item{label="Regression versus retesting"}
  Retesting checks the bug is fixed. Regression checks nothing else broke.
  :::
  :::accordion-item{label="git reset versus git revert"}
  Reset rewrites history by moving the branch back. Revert adds a new commit
  that undoes an old one, and is the only safe choice for pushed commits.
  :::
  :::accordion-item{label="git fetch versus git pull"}
  Fetch downloads and changes nothing you are working on. Pull fetches and
  merges.
  :::
  :::accordion-item{label="Severity versus priority"}
  Severity is impact on the system; priority is urgency of the fix. A misspelt
  university name is low severity, high priority.
  :::
  :::accordion-item{label="401 versus 403"}
  401: not authenticated, log in. 403: authenticated, not allowed.
  :::
::
