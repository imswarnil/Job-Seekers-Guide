Eight problems, one from each corner of the track, and none of them is a drill.
Do them at a keyboard where a keyboard helps (a Linux or macOS terminal, or Git
Bash on Windows), on paper where the written round would make you. Only open an
answer after you have written your own.

::warning{icon="i-lucide-alert-triangle"}
Problems 1 and 2 run Git and shell commands. Do them in a fresh practice folder
(`mkdir ~/practice && cd ~/practice`), never inside a repository or folder you
care about. Problem 1 uses `reset`, which can delete uncommitted work.
::

## The problems

::steps
### 1. The commit on the wrong branch
You are on `main`, you have made two commits for ticket STU-231 that should have
been on a branch, and you have **not pushed**. `git log --oneline -3` shows:

```text [Output]
e41b2a0 (HEAD -> main) Show attendance percentage in red below 75
b77c019 Add attendance percentage card
9b2e4d1 (origin/main) Add DBMS attendance for 22CS041
```

Get both commits onto `feature/STU-231` and put `main` back where the remote is,
without losing anything. Then say what you would do instead if you **had**
pushed.

### 2. One line, one answer
Using `results.csv` from the Linux chapter (make it yourself, 20 rows or more),
write **one pipeline** that prints the three subjects with the most failures,
most first, with their counts.

### 3. This bug report was bounced
"Results page broken on phone. Please fix ASAP." Rewrite it so a developer can
reproduce it without asking you a single question. Invent the details you
need, but make every field specific.

### 4. Smoke, sanity, or regression?
For each, say which kind of testing it is: (a) a new build arrives and you check
login, dashboard and payment pages open; (b) after a fix to hall-ticket
download, you check that one flow in five minutes; (c) overnight, 600 automated
tests run across the portal after the fix.

### 5. The forecast
A team finished 16, 24 and 20 points in its last three two-week sprints. The PO
wants 150 points of work done before semester registration opens in 14 weeks.
Is that realistic? What would you say in the planning meeting?

### 6. The permissions puzzle
`ls -l` shows `-rw-r--r-- priya faculty publish.sh`. Priya cannot run it, and the
faculty group should be able to run it but not edit it. Others must have no
access. Give the one `chmod` command in numbers, and the permission string it
produces.

### 7. The written round, eight minutes
On paper, no calculator: (a) 183 to binary; (b) `0x7E` to decimal; (c)
`101110` binary to octal and hex; (d) `1101 + 0111` in binary; (e) -12 in 8-bit
two's complement.

### 8. The URL, in order
Put these in the order they happen: HTTP response received; TLS handshake; DNS
lookup; browser builds the DOM; TCP handshake; database queried; HTTP request
sent. Then say which step a "certificate not valid" warning comes from.
::

## Answers

::accordion
  :::accordion-item{label="1. The commit on the wrong branch" icon="i-lucide-check"}
  ```bash [Terminal]
  git status                        # confirm nothing uncommitted
  git branch feature/STU-231        # new label at e41b2a0, keeps both commits
  git reset --hard origin/main      # main back to 9b2e4d1
  git switch feature/STU-231
  git log --oneline -3
  ```

  ```text [Output]
  e41b2a0 (HEAD -> feature/STU-231) Show attendance percentage in red below 75
  b77c019 Add attendance percentage card
  9b2e4d1 (origin/main, main) Add DBMS attendance for 22CS041
  ```

  The branch is created *before* the reset, so the commits always have a label
  pointing at them. If you had pushed, do not reset: create the branch the same
  way, then `git revert` the two commits on `main` and push, so nobody's history
  is rewritten.
  :::
  :::accordion-item{label="2. One line, one answer" icon="i-lucide-check"}
  ```bash [Terminal]
  grep FAIL results.csv | cut -d, -f2 | sort | uniq -c | sort -rn | head -n 3
  ```

  ```text [Output]
        7 DBMS
        4 OS
        2 CN
  ```

  (Counts depend on your file.) The beginner version forgets the first `sort`,
  so `uniq -c` counts runs of neighbouring lines and the numbers are silently
  wrong, with no error.
  :::
  :::accordion-item{label="3. This bug report was bounced" icon="i-lucide-check"}
  ```text [BUG report]
  Title       : Marks table cut off on screens narrower than 400px (results page)
  Environment : Production, results.university.ac.in, Android 14, Chrome 128,
                Pixel 6a (412 px wide), also on iPhone SE Safari
  Severity    : Medium     Priority : High (results published today)
  Steps       : 1. Open results.university.ac.in on a phone
                2. Log in as 22CS041
                3. Open Semester 5 results
  Expected    : All 6 subjects visible; table scrolls sideways if needed
  Actual      : Only 4 columns visible, Marks and Result columns cut off,
                no horizontal scroll
  Attachments : screenshot-pixel.png, screenshot-iphone.png
  ```
  Priority is high even though nothing crashes, because every student is
  opening this page today.
  :::
  :::accordion-item{label="4. Smoke, sanity, or regression?" icon="i-lucide-check"}
  (a) Smoke: broad and shallow on a new build. (b) Sanity: narrow, on one
  change. (c) Regression: the wide suite, checking nothing that worked is now
  broken. Checking that the original hall-ticket bug is gone would be
  retesting.
  :::
  :::accordion-item{label="5. The forecast" icon="i-lucide-check"}
  Average velocity (16 + 24 + 20) / 3 = 20 points per sprint. 14 weeks is 7
  two-week sprints, so about 140 points. 150 is slightly beyond the forecast,
  with no room for bugs or new work. In planning: "At our current velocity we
  will finish about 140. Which 10 points can move after registration opens?"
  Negotiating scope with the PO, not promising to work weekends, is the Agile
  answer.
  :::
  :::accordion-item{label="6. The permissions puzzle" icon="i-lucide-check"}
  `chmod 750 publish.sh` gives `-rwxr-x---`. Owner 7 (read, write, execute),
  group 5 (read, execute, no write), others 0. The common wrong answer, `755`,
  lets everyone else read and run it.
  :::
  :::accordion-item{label="7. The written round, eight minutes" icon="i-lucide-check"}
  ```text [Working]
  (a) 183 = 128 + 32 + 16 + 4 + 2 + 1       = 1011 0111
  (b) 0x7E = 7 × 16 + 14 = 112 + 14         = 126
  (c) 101110 → octal: 101 110 = 5 6         = 56 (octal)
             → hex:   0010 1110 = 2 E        = 0x2E   (check: 46 both ways)
  (d)   1101 (13)
      + 0111 ( 7)
      = 10100 (20)
  (e) 12 = 0000 1100 → flip 1111 0011 → +1 = 1111 0100
  ```
  :::
  :::accordion-item{label="8. The URL, in order" icon="i-lucide-check"}
  DNS lookup, TCP handshake, TLS handshake, HTTP request sent, database queried,
  HTTP response received, browser builds the DOM. A certificate warning comes
  from the TLS handshake: the browser could not verify the server's identity.
  :::
::
