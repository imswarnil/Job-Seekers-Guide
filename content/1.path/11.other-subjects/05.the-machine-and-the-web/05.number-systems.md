156 in binary is `10011100`, and in hexadecimal it is `9C`. By the end of this
lesson you can get there in under a minute, on paper, which is what the written
round asks.

## Why this matters in a job

Written rounds at TCS, Infosys, Wipro, Capgemini and others still carry
questions like "convert 0x2F to decimal" or "what is 1011 + 0110 in binary".
They are two free marks for anyone who has practised and a trap for anyone who
has not. At work, hex is everywhere: colours in CSS (`#1E40AF`), memory
addresses in stack traces, Git commit IDs (`9b2e4d1`), file permissions in octal
(`chmod 755`).

## Place value, analogy first

You already know one number system perfectly. In decimal, **base 10**, 347 means
3 hundreds, 4 tens, 7 ones: each place is worth ten times the one to its right.
Every other base works the same way, with a different multiplier.

| System | Base | Digits | Place values (right to left) | Written |
| --- | --- | --- | --- | --- |
| Binary | 2 | 0, 1 | 1, 2, 4, 8, 16, 32, 64, 128 | `10011100₂` or `0b10011100` |
| Octal | 8 | 0–7 | 1, 8, 64, 512 | `234₈` or `0o234` |
| Decimal | 10 | 0–9 | 1, 10, 100, 1000 | `156` |
| Hexadecimal | 16 | 0–9, A–F (A=10 … F=15) | 1, 16, 256, 4096 | `9C₁₆` or `0x9C` |

Why binary? A circuit is either on or off, and two states are the most reliable
thing to build billions of. Why hex? One hex digit is exactly four binary digits,
so it is binary written short.

## How it works

### Any base to decimal: multiply by place values

```text [10011100 (binary) to decimal]
Places :  128  64  32  16   8   4   2   1
Bits   :    1   0   0   1   1   1   0   0
Sum    :  128        + 16 + 8 + 4          = 156
```

```text [0x2F to decimal]
2 × 16  =  32
F × 1   =  15
          ----
            47
```

### Decimal to any base: divide repeatedly, read remainders upwards

::code-trace{caption="156 to binary. Divide by 2, keep the remainder, stop at zero, read from the bottom."}
```text [Repeated division]
156 ÷ 2 = 78  remainder 0
 78 ÷ 2 = 39  remainder 0
 39 ÷ 2 = 19  remainder 1
 19 ÷ 2 =  9  remainder 1
  9 ÷ 2 =  4  remainder 1
  4 ÷ 2 =  2  remainder 0
  2 ÷ 2 =  1  remainder 0
  1 ÷ 2 =  0  remainder 1
Read upwards: 10011100
```

  :::code-trace-step{lines="1-2" caption="The first remainder is the rightmost bit, the ones place."}
  :::
  :::code-trace-step{lines="3-8" caption="Keep dividing the quotient until it reaches zero."}
  :::
  :::code-trace-step{lines="9" caption="Read the remainders from bottom to top. Check: 128 + 16 + 8 + 4 = 156."}
  :::
::

The same method works for any base: divide by 8 for octal, by 16 for hex.

```text [156 to hexadecimal]
156 ÷ 16 = 9  remainder 12 (C)
  9 ÷ 16 = 0  remainder 9
Read upwards: 9C
```

### The shortcut: binary and hex through groups of four

Because 16 = 2⁴, each hex digit is exactly four bits. Group from the right.

```text [Binary to hex and back]
1001 1100            →   9  C    →  0x9C
0x3A7  →  0011 1010 0111   →   1110100111 (leading zeros dropped)
```

For octal it is groups of **three** (8 = 2³): `010 011 100` is `2 3 4`, so
156 = `234₈`.

::tip
Memorise the powers of two up to 1024 (1, 2, 4, 8, 16, 32, 64, 128, 256, 512,
1024) and the hex digits A=10 to F=15. With those two lists every conversion in a
written round becomes addition.
::

### Binary addition

Four rules: 0+0=0, 0+1=1, 1+1=10 (write 0, carry 1), 1+1+1=11 (write 1, carry 1).

```text [1011 + 0110]
  carry  1 1 1
         1 0 1 1      (11)
       + 0 1 1 0      ( 6)
       ---------
       1 0 0 0 1      (17)
```

### Bits and bytes

A **bit** is one binary digit. A **byte** is 8 bits, enough for 256 values
(0 to 255), which is why a colour channel in `#1E40AF` runs from `00` to `FF`.
1 KB is 1,024 bytes, 1 MB is 1,024 KB, and so on (storage manufacturers use
1,000, which is why a "1 TB" drive shows as about 931 GB).

### Negative numbers: two's complement

Computers store negative integers in **two's complement**: invert every bit and
add one.

```text [-6 in 8 bits]
 6   =  0000 0110
flip =  1111 1001
 +1  =  1111 1010   =  -6
```

The leftmost bit becomes a sign bit, and an 8-bit value runs from -128 to 127.
This is why a Java `byte` holds -128 to 127 and why `Integer.MAX_VALUE + 1`
becomes a large negative number.

```java [Overflow.java]
public class Overflow {
    public static void main(String[] args) {
        System.out.println(Integer.toBinaryString(156));
        System.out.println(Integer.toHexString(156));
        System.out.println(Integer.parseInt("2F", 16));
        System.out.println(Integer.MAX_VALUE + 1);
    }
}
```

```text [Output]
10011100
9c
47
-2147483648
```

## Real use case

::real-life{title="Hex you will read in your first month" source="Everyday work"}
A CSS colour `#1E40AF` is three bytes: red `1E` (30), green `40` (64), blue `AF`
(175). A Java stack trace prints an object as `Student@1b6d3586`, the hash in
hex. A Git commit is 40 hex characters, of which you type the first seven.
`chmod 755` is octal, one digit per three permission bits. None of these need
arithmetic at work, but all of them make sense only if you know what the digits
are.
::

## What confuses people here

- **Reading the remainders downwards.** The first remainder is the *last* digit.
  Always check by converting back.
- **Grouping from the left.** Groups of four (or three) start from the right; pad
  the leftmost group with zeros.
- **`10` means different numbers.** Two in binary, eight in octal, sixteen in hex.
  Always know the base.
- **Signed and unsigned.** `1111 1010` is 250 unsigned and -6 in two's
  complement. The bits do not say which; the type does.

## Interview questions

::accordion
  :::accordion-item{label="Convert 45 to binary, octal and hex."}
  Binary by repeated division: 101101 (32+8+4+1). Octal, groups of three from
  the right: 101 101 = 55. Hex, groups of four: 0010 1101 = 2D. Check:
  2×16 + 13 = 45.
  :::
  :::accordion-item{label="Convert 0xFF to decimal and binary."}
  F×16 + F = 15×16 + 15 = 255. Binary: 1111 1111. The largest value one byte
  holds.
  :::
  :::accordion-item{label="Why do computers use binary?"}
  Electronic circuits reliably represent two states (on and off, high and low
  voltage). Two states are easier to build, distinguish and keep error-free than
  ten.
  :::
  :::accordion-item{label="What is two's complement, and why is it used?"}
  A way to represent signed integers: a negative number is the bitwise inverse of
  its magnitude plus one. It gives one representation of zero and lets the same
  addition circuit handle positive and negative numbers.
  :::
  :::accordion-item{label="How many values can n bits represent?"}
  2ⁿ. So 8 bits: 256 values (0–255 unsigned, -128 to 127 signed). 32 bits: about
  4.29 billion.
  :::
::
