**The cloud is somebody else's computers, rented over the internet, by the
hour.** Everything else in this lesson is detail on top of that sentence.

## Why this matters in a job

Almost every company you join runs at least part of its systems on AWS, Azure or
Google Cloud, and job descriptions for freshers increasingly say "exposure to
cloud is a plus". In interviews the fresher-level questions are about awareness:
"what is cloud computing?", "IaaS, PaaS, SaaS with examples", "name some AWS
services". Nobody expects you to design a cloud architecture. They do expect you
not to confuse SaaS with a website.

## The cloud, analogy first

A student arriving in Bangalore has three choices for a place to live. Buy a
flat: you own it, you fix everything, it costs lakhs up front. Rent an empty
flat: somebody else owns the building, you bring the furniture and cook. Stay in
a PG: bed, food and Wi-Fi included, you bring only yourself. I chose the third
in BTM Layout, and for the same reason most companies rent computing: pay
monthly, leave when you want, let somebody else fix the plumbing.

::compare{caption="Owning servers versus renting them."}
  :::compare-side{label="On-premises" verdict="neutral"}
  Buy servers, a room, cooling, power backup, staff. Months to add capacity.
  Paid for even when idle.
  :::
  :::compare-side{label="Cloud" verdict="neutral"}
  Rent servers in minutes, pay per hour or per request, add or remove capacity
  as load changes. The provider handles the hardware.
  :::
::

## How it works: IaaS, PaaS, SaaS

The three models differ in **how much the provider manages for you**.

| Model | You manage | Provider manages | Example | The PG analogy |
| --- | --- | --- | --- | --- |
| **IaaS**, Infrastructure as a Service | Operating system, runtime, your application, data | Hardware, network, virtualisation | AWS EC2, Azure Virtual Machines, Google Compute Engine | Empty rented flat |
| **PaaS**, Platform as a Service | Your application and data | Everything underneath, including OS and runtime | Heroku, Google App Engine, Azure App Service, Salesforce Platform | Furnished flat, kitchen ready |
| **SaaS**, Software as a Service | Only your use of it and your data | The whole application | Gmail, Microsoft 365, Zoom, Salesforce CRM | PG: everything included |

::real-life{title="Salesforce is two of these at once" source="My work since Accenture"}
Salesforce is sold as **SaaS** (a sales team logs in and uses the CRM) and as
**PaaS** (developers like me write code and build apps on the Salesforce
Platform without ever touching a server). That distinction is a good one to use
in an interview because it shows you understand the models rather than a list of
examples.
::

### The three providers

| Idea | AWS (Amazon) | Azure (Microsoft) | Google Cloud (GCP) |
| --- | --- | --- | --- |
| Virtual machine | EC2 | Virtual Machines | Compute Engine |
| File / object storage | S3 | Blob Storage | Cloud Storage |
| Managed relational database | RDS | Azure SQL Database | Cloud SQL |
| Run code without servers | Lambda | Azure Functions | Cloud Functions |

AWS has the largest market share, Azure is strong wherever companies already use
Microsoft, and GCP is strong in data and machine learning.

### Regions and availability zones

A **region** is a geographic area with its own data centres, such as AWS
`ap-south-1` in **Mumbai** (there is also one in Hyderabad). Each region has
several **availability zones**: separate data centres with their own power and
network, a few kilometres apart. Running an application in two zones means one
building losing power does not take it down. Choosing a region close to your
users (Mumbai for students in India) means faster pages, and some data must stay
in the country by law.

### Words that come with it

::feature-list{columns="2"}
  :::feature{icon="i-lucide-scaling" title="Scalability"}
  Adding capacity when load grows. **Vertical**: a bigger machine. **Horizontal**:
  more machines.
  :::
  :::feature{icon="i-lucide-activity" title="Elasticity"}
  Adding and removing capacity automatically, for results day, then shrinking
  back.
  :::
  :::feature{icon="i-lucide-indian-rupee" title="Pay as you go"}
  Billed for what you use, per hour or per request.
  :::
  :::feature{icon="i-lucide-cloud-cog" title="Public, private, hybrid"}
  Shared provider cloud, a cloud run for one organisation, or a mix of both.
  :::
::

## Real use case

A university's results site gets 2,000 visitors on a normal day and 3,00,000 in
the hour results are published. On its own servers it would have to buy for the
peak and sit idle 364 days a year. On the cloud, an **auto-scaling group** starts
extra machines when CPU passes 70% and removes them when traffic falls, and the
bill covers only that hour.

## What confuses people here

- **SaaS is not "any website".** It is software you use on subscription without
  installing or managing it.
- **Serverless still has servers.** You do not manage them; the provider runs
  your code on demand and bills per request.
- **The cloud is not automatically cheaper.** A machine left running all year
  can cost more than owning one. It is flexible, not free.
- **Awareness is enough for a fresher.** Certifications (AWS Cloud Practitioner,
  Azure AZ-900) are nice to have, not a requirement to get hired.

## Interview questions

::accordion
  :::accordion-item{label="What is cloud computing?"}
  Delivering computing resources (servers, storage, databases, software) over
  the internet on demand, paid for by use, instead of owning and running them
  yourself.
  :::
  :::accordion-item{label="Explain IaaS, PaaS and SaaS with an example each."}
  IaaS: rent virtual machines and manage the OS yourself (AWS EC2). PaaS: deploy
  your code, the platform manages the OS and runtime (Heroku, Google App Engine).
  SaaS: use a finished application over the internet (Gmail, Zoom).
  :::
  :::accordion-item{label="Name some AWS services."}
  EC2 (virtual machines), S3 (object storage), RDS (managed databases), Lambda
  (serverless functions), IAM (users and permissions), CloudWatch (monitoring).
  :::
  :::accordion-item{label="What is a region and an availability zone?"}
  A region is a geographic location with several data centres (Mumbai,
  ap-south-1). An availability zone is one or more isolated data centres inside a
  region. Deploying across zones gives fault tolerance.
  :::
  :::accordion-item{label="Scalability versus elasticity?"}
  Scalability is the ability to handle more load by adding resources. Elasticity
  is doing that automatically, both up and down, as demand changes.
  :::
::
