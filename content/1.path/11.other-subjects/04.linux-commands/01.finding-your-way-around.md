Linux is an operating system, and on a server there is no desktop to click: you
talk to it by typing commands into a **shell**, the program that reads what you
type and runs it. Everything in this chapter works the same in the macOS
terminal and in Git Bash or WSL on Windows.

## Why this matters in a job

Most servers in the world run Linux. Your application's logs, its config files
and the process running it all live on one, and in your first months somebody
will ask you to "SSH in and check the logs". Service-company interviews for
freshers routinely include "name ten Linux commands you know" or "how do you see
the last 100 lines of a file". Testers are asked it as often as developers.

## One tree

Windows has drives, `C:\` and `D:\`. Linux has one tree, starting at `/` (the
**root**). Think of a university: one campus, departments inside it, classrooms
inside those. Every file has one address from the gate inwards.

::feature-list{columns="2"}
  :::feature{icon="i-lucide-home" title="/home/priya"}
  Your **home directory**, written `~` for short. Where your own files live.
  :::
  :::feature{icon="i-lucide-settings" title="/etc"}
  System configuration files.
  :::
  :::feature{icon="i-lucide-scroll-text" title="/var/log"}
  Log files. Where you go when something breaks.
  :::
  :::feature{icon="i-lucide-package" title="/usr/bin, /bin"}
  The programs themselves. `ls` is a file in here.
  :::
::

A **path** is an address. **Absolute** starts from `/`
(`/home/priya/results/sem5.csv`). **Relative** starts from where you are
(`results/sem5.csv`). `.` means "here", `..` means "one level up".

## How it works

```bash [Terminal]
pwd
ls
ls -la
```

```text [Output]
/home/priya
results  notes.txt
total 16
drwxr-xr-x  4 priya priya 4096 Sep 29 10:02 .
drwxr-xr-x  5 root  root  4096 Sep  1 09:00 ..
-rw-r--r--  1 priya priya  220 Sep  1 09:00 .bashrc
-rw-r--r--  1 priya priya   88 Sep 29 09:55 notes.txt
drwxr-xr-x  2 priya priya 4096 Sep 29 10:02 results
```

`pwd` prints the working directory. `ls` lists it. `-l` gives the long format,
`-a` shows hidden files (names starting with `.`). The first column is
permissions, the subject of the next lesson.

```bash [Terminal]
cd results
mkdir -p sem5/cse
touch sem5/cse/marks.csv
cd ..
cp results/sem5/cse/marks.csv backup-marks.csv
mv backup-marks.csv marks-backup.csv
ls
```

```text [Output]
marks-backup.csv  notes.txt  results
```

| Command | Does |
| --- | --- |
| `cd dir` / `cd ..` / `cd ~` / `cd -` | Go into, up one, home, back to the previous directory |
| `mkdir -p a/b/c` | Make directories, including missing parents |
| `touch file` | Create an empty file (or update its timestamp) |
| `cp src dest` / `cp -r dir dest` | Copy a file / a directory |
| `mv src dest` | Move, and also rename |
| `rm file` / `rm -r dir` | Delete a file / a directory and everything in it |

### Reading files

```bash [Terminal]
cat results/sem5/cse/marks.csv
head -n 3 /var/log/syslog
tail -n 2 app.log
tail -f app.log
```

```text [Output]
RollNo,Subject,Marks
22CS041,DBMS,78
22CS042,DBMS,64
Sep 29 10:01:02 portal systemd[1]: Started Daily apt download.
Sep 29 10:01:05 portal CRON[2231]: (root) CMD (backup.sh)
Sep 29 10:01:07 portal kernel: [ 91.2] eth0: link up
2026-09-29 10:14:22 INFO  Fee payment saved for 22CS041
2026-09-29 10:14:25 ERROR Receipt service timed out after 30000 ms
```

`cat` prints a whole file. `less` pages through a large one (`q` to quit, `/`
to search). `head` and `tail` show the first or last lines. `tail -f` keeps
following the file as new lines arrive, which is how you watch a live log;
`Ctrl+C` stops it.

::warning{icon="i-lucide-alert-triangle"}
`rm` has no recycle bin. `rm -r` deletes a directory and everything inside it,
and `rm -rf` does so without asking, even for protected files. Before any
`rm -r`, run `pwd` and `ls` on the exact path you are about to delete. A space in
the wrong place (`rm -rf / tmp/old` instead of `rm -rf /tmp/old`) is the classic
way to wipe a machine.
::

## Real use case

The request "check why fee payment failed at 10:14" is, on a server:

```bash [Terminal]
cd /var/log/portal
ls -lt | head -n 3
tail -n 200 app.log | less
```

`ls -lt` sorts by modification time, newest first, so the log that was written
to most recently is at the top.

## What confuses people here

- **`command not found`** usually means a typing mistake or a program that is
  not installed, not that you are in the wrong place.
- **`No such file or directory`** means the path is wrong. Check `pwd`, and
  remember Linux is **case-sensitive**: `Marks.csv` and `marks.csv` are two
  files.
- **Spaces in names** need quotes: `cd "Semester 5"`. Most people avoid spaces
  in file names for this reason.
- **`mv` is rename.** There is no separate rename command.

## Interview questions

::accordion
  :::accordion-item{label="How do you see the last 100 lines of a log file, and follow it live?"}
  `tail -n 100 app.log` for the last 100 lines, `tail -f app.log` to keep
  printing new lines as they are written. `Ctrl+C` to stop.
  :::
  :::accordion-item{label="Absolute versus relative path?"}
  An absolute path starts from the root `/` and is the same wherever you are
  (`/var/log/app.log`). A relative path starts from the current directory
  (`logs/app.log`, `../notes.txt`).
  :::
  :::accordion-item{label="How do you rename a file in Linux?"}
  With `mv old-name new-name`. Moving and renaming are the same operation.
  :::
  :::accordion-item{label="What is the difference between rm, rm -r and rm -rf?"}
  `rm` deletes files. `-r` deletes directories recursively with their contents.
  `-f` forces it without prompting and ignores missing files. None of them go to
  a recycle bin.
  :::
  :::accordion-item{label="Name ten Linux commands you use."}
  `pwd`, `ls`, `cd`, `mkdir`, `cp`, `mv`, `rm`, `cat`, `tail`, `grep`, `find`,
  `chmod`, `ps`, `kill`. Then give one real use: "`tail -f` on the application
  log while I reproduce a bug."
  :::
::
