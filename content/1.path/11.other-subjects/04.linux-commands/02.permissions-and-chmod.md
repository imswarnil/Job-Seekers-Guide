`Permission denied` is the operating system telling you that *you*, as this
user, are not allowed to do *that* to *this* file. Every file carries its own
rules, and they fit in ten characters.

## Why this matters in a job

A deployment script that will not run, a log file your application cannot write
to, a private key that SSH refuses to use because it is "too open". All three are
permissions, and all three happen in a first job. "What does `chmod 755` mean?"
is one of the most asked Linux interview questions, and it has one right answer.

## Who may do what

Think of a university's result register. The **owner** (the exam controller) can
read and edit it. The **group** (heads of department) can read it. **Others**
(students) cannot open it at all. Linux gives every file exactly this: one owner,
one group, and everybody else, each with three possible rights.

::feature-list{columns="3"}
  :::feature{icon="i-lucide-eye" title="r, read (4)"}
  File: see its contents. Directory: list what is inside.
  :::
  :::feature{icon="i-lucide-pencil" title="w, write (2)"}
  File: change it. Directory: create, delete or rename files in it.
  :::
  :::feature{icon="i-lucide-play" title="x, execute (1)"}
  File: run it as a program. Directory: enter it with `cd`.
  :::
::

## How it works

```bash [Terminal]
ls -l
```

```text [Output]
-rwxr-xr-- 1 priya faculty 1204 Sep 29 11:00 publish-results.sh
-rw-r----- 1 priya faculty 8830 Sep 29 10:58 sem5-marks.csv
drwxr-x--- 2 priya faculty 4096 Sep 29 10:40 answer-scripts
```

Read `-rwxr-xr--` in four parts:

| Part | Characters | Means |
| --- | --- | --- |
| Type | `-` | Regular file (`d` directory, `l` link) |
| Owner (u) | `rwx` | priya can read, write, execute |
| Group (g) | `r-x` | faculty members can read and execute |
| Others (o) | `r--` | everyone else can only read |

### chmod with numbers

Add the values: r = 4, w = 2, x = 1. One digit each for owner, group, others.

```text [Worked example]
rwx = 4+2+1 = 7
r-x = 4+0+1 = 5
r-- = 4+0+0 = 4      →  rwxr-xr--  =  754

755 = rwx r-x r-x   scripts and directories everyone may run or enter
644 = rw- r-- r--   ordinary files: owner edits, everyone reads
600 = rw- --- ---   private files: SSH keys, .env
```

```bash [Terminal]
./publish-results.sh
chmod 755 publish-results.sh
./publish-results.sh
```

```text [Output]
bash: ./publish-results.sh: Permission denied
Results published for 214 students.
```

### chmod with letters

```bash [Terminal]
chmod u+x publish-results.sh   # owner gets execute
chmod go-w sem5-marks.csv      # group and others lose write
chmod o= sem5-marks.csv        # others get nothing
```

`u` user (owner), `g` group, `o` others, `a` all; `+` add, `-` remove, `=` set
exactly.

### Owner, and sudo

`chown` changes the owner: `sudo chown priya:faculty sem5-marks.csv`.
**`sudo`** runs one command as the **root** user, the administrator who can
change anything. You will type your own password, and the command then has no
restrictions at all.

::caution
Two habits to avoid. `chmod 777` "to make the error go away" lets every user on
the machine change or replace the file, which is a security hole, not a fix.
And putting `sudo` in front of a command because it failed hides the real
problem and can create root-owned files your application cannot touch later.
Find out which user needs which right, and give exactly that.
::

## Real use case

```bash [Terminal]
ssh -i portal-key.pem ubuntu@10.0.4.21
```

```text [Output]
WARNING: UNPROTECTED PRIVATE KEY FILE!
Permissions 0644 for 'portal-key.pem' are too open.
It is required that your private key files are NOT accessible by others.
```

The fix is `chmod 600 portal-key.pem`. Every developer meets this message in
their first cloud task.

## What confuses people here

- **Execute on a directory** means "may enter it", not "may run it". Without
  `x` on a directory you cannot `cd` into it even if you can read it.
- **Deleting a file depends on the directory's permissions**, not the file's.
  Write on the directory lets you delete files in it.
- **Root ignores permissions.** That is why `sudo` is powerful and why it is
  dangerous.
- **The digits are in order u, g, o.** 750 and 057 are very different files.

## Interview questions

::accordion
  :::accordion-item{label="What does chmod 755 mean?"}
  Owner read, write, execute (7 = 4+2+1); group read and execute (5 = 4+1);
  others read and execute (5). Written `rwxr-xr-x`. Typical for scripts and
  directories.
  :::
  :::accordion-item{label="What is the difference between chmod and chown?"}
  `chmod` changes a file's permissions (what the owner, group and others can do).
  `chown` changes who the owner and group are.
  :::
  :::accordion-item{label="What is sudo, and who is root?"}
  Root is the superuser account with unrestricted access. `sudo` runs a single
  command with root's privileges after checking you are allowed to, and logs it.
  :::
  :::accordion-item{label="Why is chmod 777 a bad idea?"}
  It lets every user on the system read, modify and execute the file. Anyone, or
  any compromised process, can replace a script with their own code. Give the
  smallest permission that works.
  :::
::
