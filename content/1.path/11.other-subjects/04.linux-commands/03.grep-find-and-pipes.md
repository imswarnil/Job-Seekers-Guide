Two different searches: **`grep`** looks *inside* files for a line of text,
**`find`** looks *for* files by name, size or age. And the **pipe**, `|`, sends
one command's output into the next, which is where Linux stops being a list of
commands and becomes a language.

## Why this matters in a job

The first real production issue you help with will start with "grep the logs
for that student's roll number". Support and testing roles use `grep` many times
a day. In interviews: "how do you search for a word in a file?", "how do you find
all `.log` files larger than 100 MB?", "what does a pipe do?".

## The idea: small tools, joined

Think of an exam results office. One clerk pulls every answer sheet for DBMS
(`grep`), the next sorts them by roll number (`sort`), the next removes
duplicates (`uniq`), the last counts them (`wc`). None of them does much; passed
hand to hand, they answer a real question. The pipe is the hand-off.

## How it works

The file used below:

```text [results.csv]
RollNo,Subject,Marks,Result
22CS041,DBMS,78,PASS
22CS042,DBMS,34,FAIL
22CS043,OS,81,PASS
22CS042,OS,39,FAIL
22CS044,DBMS,34,FAIL
```

### grep

```bash [Terminal]
grep FAIL results.csv
grep -c FAIL results.csv
grep -i "dbms" results.csv | grep -v PASS
grep -n "22CS042" results.csv
```

```text [Output]
22CS042,DBMS,34,FAIL
22CS042,OS,39,FAIL
22CS044,DBMS,34,FAIL
3
22CS042,DBMS,34,FAIL
22CS044,DBMS,34,FAIL
3:22CS042,DBMS,34,FAIL
5:22CS042,OS,39,FAIL
```

| Flag | Means |
| --- | --- |
| `-i` | ignore case |
| `-v` | invert: lines that do **not** match |
| `-c` | count matching lines |
| `-n` | show line numbers |
| `-r` | search every file in a directory, recursively |
| `-l` | print only the names of files that match |

### Pipes

```bash [Terminal]
grep FAIL results.csv | cut -d, -f1 | sort | uniq -c | sort -rn
```

```text [Output]
      2 22CS042
      1 22CS044
```

::code-trace{caption="Which students failed, and how many subjects each."}
```bash [Pipeline]
grep FAIL results.csv
cut -d, -f1
sort
uniq -c
sort -rn
```

  :::code-trace-step{lines="1" caption="Keep only the failing lines."}
  :::
  :::code-trace-step{lines="2" caption="Split each line on commas and keep field 1, the roll number."}
  :::

  :::

### Redirection

```bash [Terminal]
grep FAIL results.csv > failures.txt     # write output to a file (overwrites)
grep FAIL old.csv >> failures.txt        # append to the end
wc -l failures.txt
```

```text [Output]
5 failures.txt
```

::warning{icon="i-lucide-alert-triangle"}
A single `>` empties the file before writing, with no question asked. Typing
`>` when you meant `>>` has wiped many a log and many a CSV. When in doubt, write
to a new file name.
::

### find

```bash [Terminal]
find . -name "*.csv"
find /var/log -name "*.log" -size +100M
find . -name "*.tmp" -mtime +7
```

```text [Output]
./results.csv
./archive/sem4-results.csv
/var/log/portal/app.log
./cache/upload-1182.tmp
```

`-name` matches a pattern (quote it), `-size +100M` is bigger than 100 MB,
`-mtime +7` is modified more than seven days ago, `-type f` or `-type d` limits
to files or directories.

## Real use case

"How many fee payments failed today, and for which reason?"

```bash [Terminal]
grep "2026-09-29" app.log | grep ERROR | grep -o "Fee payment failed: [A-Z_]*" | sort | uniq -c
```

```text [Output]
     41 Fee payment failed: BANK_TIMEOUT
      3 Fee payment failed: INVALID_UPI_ID
```

One line, on a 400,000-line log, answered in under a second. `-o` prints only the
matching part of each line.

## What confuses people here

- **grep versus find.** grep searches contents; find searches names and
  attributes. "Find the file containing X" is `grep -rl "X" .`.
- **`uniq` without `sort`** only removes duplicates that are next to each other,
  so it gives wrong counts on unsorted input and no error.
- **Quote your patterns.** `find . -name *.csv` without quotes lets the shell
  expand `*.csv` first and gives confusing results.
- **Pipe versus redirect.** `|` sends output to another *command*; `>` sends it
  to a *file*.

## Interview questions

::accordion
  :::accordion-item{label="How do you search for a word in all files in a directory?"}
  `grep -r "word" .` for matching lines with file names, `grep -rl "word" .` for
  only the file names, `-i` to ignore case.
  :::
  :::accordion-item{label="What is a pipe?"}
  The `|` operator connects the standard output of one command to the standard
  input of the next, so small commands combine: `grep ERROR app.log | wc -l`
  counts error lines.
  :::
  :::accordion-item{label="How do you find files larger than 100 MB?"}
  `find / -type f -size +100M`, usually with a starting directory narrower than
  `/`, such as `/var/log`.
  :::
  :::accordion-item{label="Difference between > and >>?"}
  `>` redirects output to a file, overwriting it. `>>` appends to the end.
  :::
  :::accordion-item{label="How do you count lines in a file?"}
  `wc -l file`. `wc -w` counts words, `wc -c` bytes.
  :::
::
