Every running program is a **process**, and each one has a number, its **PID**
(process ID). Find the PID and you can inspect it, slow it down, or stop it.
The operating systems track explained what a process is; this is how you see
them.

## Why this matters in a job

"The server is slow", "port 8080 is already in use", "the report job has been
running for three hours". Each one ends with you finding a process and deciding
what to do with it. Interviewers ask "how do you find and kill a process?" and
"what is the difference between `kill` and `kill -9`?" in almost every Linux
round.

## Processes, analogy first

A university library issues every borrower a token number. The librarian can
look up who holds which token, how long they have been inside, and ask them to
leave. The kernel is the librarian, the PID is the token, and `kill` is the
request to leave, politely or not.

## How it works

### Seeing processes

```bash [Terminal]
ps aux | grep java
```

```text [Output]
priya   2231  4.1 12.6 3985412 1034220 ?  Sl  09:02  3:11 java -jar fee-service.jar
priya   5120 97.8  8.2 3721004  671200 ?  Rl  11:40 42:05 java -jar report-job.jar
priya   5391  0.0  0.0    6432     720 pts/0 S+ 12:22  0:00 grep java
```

Columns that matter: `PID` (second), `%CPU`, `%MEM`, and the command at the end.
PID 5120 is using 97.8% of a processor. The last line is the `grep` itself.

```bash [Terminal]
top
```

```text [Output]
top - 12:23:01 up 12 days,  2 users,  load average: 3.92, 3.40, 2.15
Tasks: 188 total,   2 running, 186 sleeping
%Cpu(s): 96.1 us,  2.0 sy,  0.0 ni,  1.9 id
MiB Mem :   7856.2 total,    412.5 free,   6120.3 used

  PID USER   %CPU %MEM   TIME+  COMMAND
 5120 priya  97.8  8.2  42:05.1 java
 2231 priya   4.1 12.6   3:11.4 java
```

`top` refreshes every few seconds, busiest first. `q` quits. `htop` is a friendlier
version, when installed.

### Stopping a process

```bash [Terminal]
kill 5120
ps -p 5120
```

```text [Output]
    PID TTY          TIME CMD
```

`kill` sends a **signal**. By default it is **SIGTERM** (15): "please finish up
and exit", which lets the program close files and database connections cleanly.
`kill -9` sends **SIGKILL**: the kernel ends it immediately, no clean-up.

::warning{icon="i-lucide-alert-triangle"}
Use `kill -9` only after a plain `kill` has been ignored for a while. A process
killed with `-9` cannot finish writing what it was writing, so a half-saved
file or a half-finished batch of fee records is possible. And check the PID
twice: killing the wrong one on a shared server takes down somebody else's
service.
::

### Port already in use

```bash [Terminal]
lsof -i :8080
```

```text [Output]
COMMAND  PID  USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
java    2231 priya   45u  IPv6  51231      0t0  TCP *:8080 (LISTEN)
```

Now you know which process holds the port, and can decide whether to stop it.

### Background, disk and memory

```bash [Terminal]
./nightly-report.sh &        # run in the background, prompt returns
jobs                         # background jobs of this shell
df -h                        # disk space per file system
free -h                      # memory
```

```text [Output]
[1] 6012
[1]+  Running                 ./nightly-report.sh &
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        50G   47G  3.0G  94% /
               total        used        free      shared  buff/cache   available
Mem:           7.7Gi       6.0Gi       412Mi        12Mi       1.3Gi       1.4Gi
```

A disk at 94% is the next outage. `du -sh /var/log/*` shows which folders are
using it.

## Real use case

::real-life{title="The three-hour report" source="A support ticket, any company"}
A nightly job that normally takes ten minutes has run for three hours and the
portal is slow. `top` shows it at 98% CPU. You do not kill it straight away: you
check with whoever owns it, because stopping it half way might leave the report
table half filled. You `kill` (not `kill -9`), confirm it exited, and note the
PID and time in the ticket. That order, look, ask, stop cleanly, record, is the
whole skill.
::

## What confuses people here

- **`kill` does not always kill.** It sends SIGTERM, which a program may catch
  and handle, or ignore if it is stuck.
- **A process versus a program.** The program is the file on disk; a process is
  one running instance of it. Two terminals running `java` are two processes.
- **`ps` is a snapshot, `top` is live.**
- **Load average** is the number of processes wanting the CPU, averaged over 1,
  5 and 15 minutes. Compare it to the number of CPU cores.

## Interview questions

::accordion
  :::accordion-item{label="How do you find and kill a process?"}
  `ps aux | grep name` (or `pgrep name`) to find its PID, then `kill PID`. If it
  ignores that, `kill -9 PID`. `pkill name` kills by name.
  :::
  :::accordion-item{label="kill versus kill -9?"}
  `kill` sends SIGTERM (15), asking the process to exit; it can clean up or even
  ignore it. `kill -9` sends SIGKILL, which the process cannot catch: the kernel
  ends it immediately with no clean-up.
  :::
  :::accordion-item{label="How do you check which process is using a port?"}
  `lsof -i :8080`, or `ss -ltnp | grep 8080` (older systems: `netstat -tulnp`).
  :::
  :::accordion-item{label="How do you check disk space and memory?"}
  `df -h` for disk space per file system, `du -sh folder` for one folder's size,
  `free -h` for memory.
  :::
  :::accordion-item{label="What does & do at the end of a command?"}
  Runs it in the background so the prompt returns immediately. `jobs` lists
  background jobs, `fg` brings one back. It still stops if you log out, unless
  started with `nohup`.
  :::
::
