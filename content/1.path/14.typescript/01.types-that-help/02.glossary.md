| Term | In one line |
| --- | --- |
| **Structural typing** | Two types are compatible if their *shapes* match. Java compares names; TypeScript compares members. |
| **`interface` / `type`** | Both describe a shape. `interface` can be reopened and extended; `type` can be a union. Use either, consistently. |
| **Union** | `'A' \| 'B' \| 'C'`. A closed set the compiler checks and your editor autocompletes. The feature to reach for first. |
| **Narrowing** | Proving to the compiler which member of a union you have, with `typeof`, `in` or a check. |
| **Generic** | `Page<T>`. The same idea as Java's. |
| **Utility types** | `Omit`, `Partial`, `Pick`, `Required`, `Record`. Derive one type from another rather than writing it twice. |
| **`unknown`** | Safe. You must narrow it before using it. |
| **`any`** | ⚠️ Switches off checking for everything it touches, and spreads outward through return values. |
| **`as`** | ⚠️ An assertion, not a conversion. Tells the compiler to stop checking. Occasionally right, usually somebody silencing an error. |
| **Type erasure** | Types are checked and then **deleted**. Nothing exists at run time. |
| **`strict`** | What makes null checking real. Without it, `string` silently includes `null`. Turn it on day one. |
| **`noUncheckedIndexedAccess`** | Makes `array[0]` have type `T \| undefined`, which is true and which nobody enables. |
| **Schema validation** | Zod or similar. Parse at the boundary, and derive the type from the schema so the two cannot drift. |

## The one sentence to keep

::pull-quote
Inside your program a type is a guarantee. At the edge, HTTP, a form, storage:
it is a claim you made about somebody else's data, and a claim needs checking.
::
