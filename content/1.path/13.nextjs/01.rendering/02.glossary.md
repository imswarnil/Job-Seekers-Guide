| Term | In one line |
| --- | --- |
| **CSR** | Client-side rendering. The browser gets an empty div and builds the page. Blank until JavaScript loads, and a second round trip for the data. |
| **SSR** | Server-side rendering. HTML arrives with content in it, on the first response. |
| **SSG** | Built once at deploy time. Fastest possible, and only for pages that do not change per request. |
| **ISR** | Static, regenerated in the background after an interval. Static speed with fresher data. |
| **Hydration** | React attaching to server-rendered HTML to make it interactive. Between arrival and hydration the page looks ready and is not. |
| **Server component** | The default. Runs only on the server, can query the database directly, and **its code is never sent to the browser**. |
| **Client component** | `'use client'`. Needed for state, effects, event handlers and browser APIs. Its code **is** downloaded. |
| **`'use client'`** | ⚠️ A **boundary**, not a file. Everything imported below it becomes client code, which is how a codebase loses the benefit. |
| **Server action** | `'use server'`. A function on the server called from a form. Works without JavaScript, upgraded when it loads. |
| **`revalidatePath`** | Marks a page's cached data stale after a mutation. |
| **`force-dynamic`** | Never cache this page. |
| **Streaming** | Sending HTML in pieces so the fast parts appear while the slow parts are still loading. |
| **Edge / Node runtime** | Where it executes. Edge is closer to the user and cannot do everything Node can. |

## The two sentences to keep

::pull-quote
Default to the server and opt into the client for a reason you can name. And
`'use client'` in a layout turns the whole application back into a client
application.
::
